# Wi-Fi 시뮬레이터 실습 — 보드 없이 PC 시뮬레이터에 연결하기

**90분 동안 `SmartIO`를 PC에서 돌리는 BLEuno 시뮬레이터에 Wi-Fi(TCP)로 연결하고, 보드와 같은 명령·응답을 주고받는다.**
대상은 12주차 2일차 이후의 `SmartIO`다. 앱 코드는 네 곳만 바꾼다. 그 가운데 bleuno 두 파일(2-1)은 내 프로젝트에 이미 있으면 건너뛴다. 나머지 코드(검색 목록·`connect`·`send`·`onMessage`)는 그대로 쓴다.
시뮬레이터 실행 방법·화면·포트·방화벽은 `tools/bleuno-sim`의 [README](../../tools/bleuno-sim/README.md)에 있다. 명령·응답 규약은 [bleuno README 2절](../bleuno/README.md#2-명령과-응답)과 같다. 다른 점은 연결 직후 먼저 오는 `hello` 줄(4번), `about`의 `app`·`version`(`BLEuno-SIM`·`1.0.5_sim`), 6번 [시뮬레이터와 Fake·보드의 차이](#시뮬레이터와-fake보드의-차이)에 모은 것이다.
표는 '예상' 칸을 먼저 채우고, 실행한 뒤 '실제' 칸과 나머지 칸을 채운다. 표는 스스로 점검하는 것이라 제출하지 않는다.
**(예상)** 표시는 빌드·실행해 보지 않고 코드나 문서로 짐작해 적은 것이라, 기기에서 조금 다르게 보일 수 있다.

Fake(`useFake = true`)는 앱 안에서 응답을 흉내 낸다. 이 실습은 앱 밖의 프로그램과 실제로 소켓 통신을 한다. 주차 실습의 관찰표·캡처·제출은 지금처럼 Fake 또는 실보드 기준이다. 이 실습은 그것을 대신하지 않는다.

## 주차별 적용 범위

내 `SmartIO`가 어느 주차까지 왔는지에 따라 할 수 있는 단계가 다르다. **이 주차까지 했다면 여기까지** 한다.

| 내 SmartIO | 할 단계 |
|---|---|
| 12주차 1일차까지 | 대상이 아니다. 목록 줄을 눌러 연결하는 코드(38번)가 없다. 12주차 2일차를 먼저 끝낸다 |
| 12주차 2일차 | 1~4, 8 |
| 13주차 | 위 + 5 (LED 켜기·끄기) |
| 14주차 1일차 | 위 + 5의 번호 검사·오류 표시·밝기 확장 |
| 14주차 2일차 이후 | 위 + 6, 7 (2-4에서 14주차 2일차 판 리스너를 넣는다) |

이 문서는 같은 PC에서 돌리는 Android 에뮬레이터를 기준으로 쓴다. 실기기나 공유기·학교 Wi-Fi에서 다르게 보일 수 있는 곳에는 (예상)을 붙였다. (예상)이 없는 Logcat 줄은 API 31 에뮬레이터에서 옮긴 것이라, 수업 기준 에뮬레이터(API 33 이상)에서는 글자가 조금 다를 수 있다.

## 90분 시간표

| 시간 | 할 일 | 남길 것 |
|---|---|---|
| 0–10분 | 1번: [README](../../tools/bleuno-sim/README.md)대로 시뮬레이터를 실행하고, 시뮬레이터 창에 LED 4개와 `연결 수: 0`이 보이는지 본다 | 시뮬레이터 시작 출력 |
| 10–25분 | 2번: 바꿀 곳을 넣고 빌드한다. 2-1은 `bleuno` 패키지의 파일이 9개면 건너뛴다 | 빌드 성공 |
| 25–35분 | 3·4번: [검색] → 목록 줄 탭 → `준비됨` → [해제] | 캡처 1 |
| 35–48분 | 5번(13주차 이후): LED 켜기·끄기·밝기를 시뮬레이터 화면에서 본다 | 캡처 2 |
| 48–62분 | 6번(14주차 2일차 이후): 온습도 받기, 화면 슬라이더, [입력 버튼], [중지] 뒤 기다리기 | 캡처 3 |
| 62–76분 | 7번(14주차 2일차 이후): [연결 끊기] → `끊김` → [재연결], LED와 Switch 비교, Ctrl+C | LED와 Switch를 비교한 한 문장 |
| 76–86분 | 8번: 주소 직접 입력과 잘못된 주소 | 막혔을 때 표에 있는 문구 하나 |
| 86–90분 | 9번 확인, 캡처 정리, 제출 | 제출물 |

- 12주차 2일차까지만 한 사람은 35분부터 8번으로 간다. 8번을 마치면 [먼저 끝났다면](#먼저-끝났다면)을 한다.
- 13주차 또는 14주차 1일차까지 한 사람은 48분부터 8번으로 간다. 8번을 마치면 [먼저 끝났다면](#먼저-끝났다면)을 한다.
- 늦으면 7번 5·6단계(Ctrl+C)와 (더 해 볼 것)은 건너뛰고 76분에 8번으로 간다.
- 끝나면 `useTcp`를 `false`로, `useFake`를 원래 값(`true`)으로 되돌린다. 주차 실습과 제출은 그 상태로 한다.
- Windows에서 방화벽 창의 [액세스 허용]을 눌렀거나 방화벽 규칙을 만들거나 바꿨다면 README [7절](../../tools/bleuno-sim/README.md#7-windows-방화벽)대로 지운다. [액세스 허용]을 눌렀거나 7절의 네 줄을 실행했으면 시뮬레이터를 끄기 전에 **Python 규칙 지우기**를 하고, 포트 규칙을 만들었으면 관리자 권한 PowerShell에서 `Remove-NetFirewallRule` 두 줄을 실행한다. 관리자 권한이 없으면 조교에게 묻는다.
- 2-4의 [주소로 연결]은 시뮬레이터 연습용이다. Fake·실보드에서는 누르지 않고 목록 줄로 연결한다. Fake는 어떤 글자를 넣어도 `준비됨`이 되고, 14주차 2일차 이후 판은 넣은 글자를 [재연결] 주소로 저장하므로 실보드에서 [재연결]이 되지 않을 것이다(예상).
- 2-2~2-4에서 넣은 코드는 실습이 끝나도 그대로 둔다(`useTcp = false`면 `createTcp()`는 불리지 않는다). 14주차 2일차 따라하기에서 `activity_main.xml`을 예제 파일 전체로 바꾸면 2-4의 주소 칸과 버튼이 없어져 [주소로 연결] 리스너가 빌드되지 않는다. 그때는 2-4의 레이아웃을 다시 넣거나 리스너를 지운다.

## 1. 준비

1. **시뮬레이터**: Python 3.10 이상과 pygame-ce를 준비하고, `tools/bleuno-sim` 폴더에서 README [3. 실행과 끝내기](../../tools/bleuno-sim/README.md#3-실행과-끝내기)대로 PC에서 실행한다. README 3절은 학번 뒤 4자리로 이름을 붙여 실행한다(`py sim.py --name ESP32_BLE_0423`). 옵션은 모두 생략할 수 있으므로, 혼자 에뮬레이터로 연습할 때는 이름 없이 `py sim.py`로 실행해도 된다. 같은 Wi-Fi에서 여럿이 실기기로 할 때는 README [9. 수업에서 여럿이 쓸 때](../../tools/bleuno-sim/README.md#9-수업에서-여럿이-쓸-때)대로 꼭 이름을 붙인다. 명령 포트는 `8266`, 검색 포트는 `8267`, 화면은 별도 시뮬레이터 창이며, `8080`은 HTTP API 포트다. 시작 메시지 가운데 이 실습에서 보는 줄은 아래 세 줄이다. 전체는 README [4. 시작 메시지와 로그](../../tools/bleuno-sim/README.md#4-시작-메시지와-로그)에 있다.

```text
에뮬레이터에서는 10.0.2.2:8266
HTTP API: http://127.0.0.1:8080/state
[14:02:11] 시작: TCP 8266, UDP 8267, HTTP 8080
```

마지막 줄의 시각은 실행할 때마다 다르다. 이 줄이 보이면 앱에서 붙어도 된다.

이 문서는 이름 없이 실행했을 때의 기본 이름 `ESP32_BLE_SIM1`로 적는다. 이름을 붙여 실행했으면 목록 줄, Logcat의 `UDP 받음:`·`onFound:`·`첫 줄 받음` 줄, 시뮬레이터 터미널, 캡처에서 `ESP32_BLE_SIM1` 자리에 내가 붙인 이름이 나올 것이다(예상).

2. **어디서 실행하나**: 앱을 에뮬레이터에서 돌리면 PC 주소는 `10.0.2.2`다. 실기기에서 돌리면 시뮬레이터 시작 메시지의 `이 PC의 IPv4 주소` 줄에 찍힌 주소(예: `192.168.0.10`)를 쓴다. 자세한 것은 README [6. 앱에서 붙을 주소](../../tools/bleuno-sim/README.md#6-앱에서-붙을-주소)와 [7. Windows 방화벽](../../tools/bleuno-sim/README.md#7-windows-방화벽)에 있다.

| 앱을 실행하는 곳 | 시뮬레이터 주소 |
|---|---|
| 같은 PC의 에뮬레이터 | `10.0.2.2:8266` |
| PC와 같은 Wi-Fi의 실기기 | `PC의 IPv4:8266` (예: `192.168.0.10:8266`) |

3. **에뮬레이터 블루투스**: [검색] 코드는 2번(바꿀 곳 4가지)에서 바꾸지 않으므로 권한·블루투스 확인(12주차 25번)이 그대로 돈다. TCP에는 블루투스가 필요 없지만, 블루투스가 꺼져 있거나 권한이 없으면 12주차처럼 켜기 창이나 권한 창이 먼저 뜰 것이다(예상). 허용하고 [검색]을 다시 누른다. 8번의 [주소로 연결]은 이 확인을 거치지 않는다.
4. **12주차 2일차 이후의 `SmartIO` 프로젝트**. 없으면 해당 주차 완성본(`examples/`)으로 시작한다.

## 2. 바꿀 곳 4가지

2-2~2-4(인터넷 권한, `useTcp`, 주소 직접 입력)는 주차 예제에 없는 코드다. 이 실습을 할 때만 내 프로젝트에 넣는다. 2-1의 두 파일은 12~15주차 예제와 [bleuno/src](../bleuno/src)에 이미 들어 있으므로, 내 프로젝트에 없을 때만 넣는다. 새로 넣는 덩어리(Manifest 권한, 주소 입력 레이아웃, [주소로 연결] 리스너)의 주석에는 주석 번호 대신 `(Wi-Fi 시뮬레이터)` 꼬리표를 붙인다.

### 2-1. bleuno 폴더에 두 파일

Project 창에서 내 `bleuno` 패키지(`com.example.smartio.bleuno`)의 파일을 센다. `TcpBleunoClient.kt`가 이미 있으면(파일 9개) 이 단계는 건너뛴다. 12~15주차 예제(`examples/`)로 시작했거나 [bleuno/src](../bleuno/src)의 9개 파일을 붙여 넣은 프로젝트가 그렇다. 8개뿐이면 두 파일을 넣는다.

1. [bleuno/src](../bleuno/src)의 `TcpBleunoClient.kt`를 내 프로젝트의 `bleuno` 패키지에 붙여 넣는다.
2. 같은 폴더의 `Bleuno.kt`로 내 `Bleuno.kt`를 바꾼다. 새 판은 맨 아래에 함수 하나가 더해진 것이다. 파일이 9개인 프로젝트의 `Bleuno.kt`에는 이 함수가 이미 있다.

```kotlin
    // PC에서 돌리는 시뮬레이터(tools/bleuno-sim)에 Wi-Fi(TCP)로 연결하는 클라이언트를 만든다.
    // 보드와 블루투스 없이 같은 명령·응답으로 연습한다. 만든 객체는 client에 보관한 뒤 그대로 돌려준다.
    fun createTcp(): BleunoClient {
        val created: BleunoClient = TcpBleunoClient()
        client = created
        return created
    }
```

- 두 파일은 꼭 함께 넣는다. `Bleuno.kt`만 바꾸면 `Bleuno.kt`에서 `Unresolved reference 'TcpBleunoClient'.`가 난다.
- 두 파일이 있어도 `createTcp()`를 부르지 않으면 앱은 전과 같다. 부르는 곳은 2-3에서 바꾸는 한 줄뿐이다.

### 2-2. AndroidManifest.xml에 INTERNET 권한

`<application` **위**에 두 줄을 넣는다. 일반 권한이라 실행 중에 허락받지 않는다.

```xml
    <!-- (Wi-Fi 시뮬레이터) tools/bleuno-sim에 TCP로 연결하는 권한. 일반 권한이라 실행 중 허락은 필요 없다. -->
    <uses-permission android:name="android.permission.INTERNET" />
```

### 2-3. MainActivity.kt에서 클라이언트 고르기

1. 클래스 변수 자리의 `useFake` 한 줄을 두 줄로 바꾼다.

바꾸기 전:

```kotlin
    private val useFake = true
```

바꾼 뒤:

```kotlin
    private val useFake = false
    private val useTcp = true   // PC 시뮬레이터(tools/bleuno-sim)에 Wi-Fi로 연결하려면 true. 이때 useFake는 false로 둔다.
```

2. `onCreate`의 24번(client 받기) 한 줄을 바꾼다.

바꾸기 전:

```kotlin
        client = Bleuno.client ?: Bleuno.create(this, useFake)
```

바꾼 뒤:

```kotlin
        client = Bleuno.client ?: if (useTcp) Bleuno.createTcp() else Bleuno.create(this, useFake)
```

- **`useTcp = true`이면 `useFake`는 반드시 `false`로 둔다.** 14주차 2일차 이후의 55번 [끊김 시험]은 `useFake = true`일 때만 보이고, 누르면 client를 `FakeBleunoClient`로 보고(`as`) `simulateLost()`를 부른다. 둘 다 `true`로 두고 [끊김 시험]을 누르면 앱이 닫힌다(Logcat 줄은 [막혔을 때](#막혔을-때)에 있다). 끊김 연습은 시뮬레이터 화면의 [연결 끊기]로 한다(7번).
- `useFake = false`이므로 14주차 2일차 이후 판에서도 [끊김 시험]은 보이지 않는다.

### 2-4. 주소 직접 입력 한 줄

검색이 안 되는 Wi-Fi에서도 연결할 수 있게 주소 칸과 버튼을 둔다.

1. `strings.xml`의 `</resources>` 위에 두 줄을 넣는다.

```xml
    <string name="address_hint">주소 (예: 10.0.2.2:8266)</string>
    <string name="connect_address">주소로 연결</string>
```

2. `activity_main.xml`의 `deviceList`(검색 목록) **아래**에 넣는다.

```xml
    <!-- (Wi-Fi 시뮬레이터) 주소 직접 입력: "IP:포트"를 넣고 [주소로 연결] -->
    <LinearLayout
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"
        android:layout_marginTop="8dp"
        android:orientation="horizontal">

        <EditText
            android:id="@+id/addressEdit"
            android:layout_width="220dp"
            android:layout_height="wrap_content"
            android:hint="@string/address_hint"
            android:inputType="text" />

        <Button
            android:id="@+id/addressButton"
            android:layout_width="wrap_content"
            android:layout_height="wrap_content"
            android:layout_marginStart="8dp"
            android:text="@string/connect_address" />

    </LinearLayout>
```

3. `MainActivity.kt`의 `onCreate` 안, `// 19.` 목록 줄 리스너를 닫는 `}` **아래**에 넣는다. 내 주차에 맞는 판 하나만 넣는다.

12주차 2일차·13주차·14주차 1일차:


14주차 2일차 이후: 12주차 판에 세 줄을 더한다. 43번과 같은 저장 두 줄은 47번 [재연결]이 이 주소로 다시 연결하게 하고, `startConnectTimeout()`(49번)은 목록 줄과 같은 10초 연결 제한을 건다.

4. 빌드한다. Build 창에 빨간 줄이 없으면 다음으로 간다.

- 두 판 모두 맨 앞의 `binding.deviceNameEdit.setText(address)`가 주소 칸의 글자를 장치 이름 칸에도 넣는다(19번 목록 줄과 같은 틀). 39번 [제어 화면]은 이 칸의 글자를 제목으로 들고 간다. 이 줄을 빼면 [주소로 연결] 뒤 제어 화면 제목이 어떻게 될지 **예상만** 적는다(빼지 않는다). 힌트: 이 줄 말고 코드가 장치 이름 칸을 채우는 곳은 목록 줄을 누를 때(19번)뿐이다. 21번은 저장해 둔 이름을 이 칸이 아니라 `마지막 장치:` 글자로 보여 준다.
- 두 판 모두 `client.connect(address)` 앞에서 `client.stopScan()`을 부른다(38번 목록 줄과 같다). 검색 중에 [주소로 연결]을 눌러도 5초 검색이 끝날 때 29번이 상태 글자를 `검색 완료 · 장치 수: N`으로 덮어쓰지 않게 하려는 것이다.
- 14주차 2일차 판의 `startConnectTimeout()`은 50번 함수다. 앞서 걸린 10초 예약을 먼저 취소하고 새로 걸므로, 앞 연결(예: 꺼진 시뮬레이터에 누른 [재연결])의 예약이 새 연결을 끊지 않는다.

### 시뮬레이터와 Fake·보드의 차이

`dht11` 값, 입력 이벤트, 연결·해제 때 LED, 빈 줄을 Fake·실제 보드·시뮬레이터가 어떻게 다루는지 아래 표에 모았다. 시뮬레이터는 `dht11` 값과 입력 이벤트가 둘과 다르고, LED와 빈 줄은 보드에 맞추었다. 실제 보드 칸은 펌웨어 소스(bleuno `1.0.5_dev`) 기준이다.

| 항목 | Fake (`useFake = true`) | 실제 보드 (펌웨어 소스 기준) | 시뮬레이터 |
|---|---|---|---|
| `dht11` 응답 값 | `[24.5,40.0]` → `[25.0,41.0]` → `[25.5,42.0]` 반복 | 센서가 잰 값 | 시뮬레이터 창의 온도·습도 슬라이더 값. 움직이면 다음 응답부터 바뀐다 |
| 입력 이벤트 `{"event":"input",…}` | `준비됨`이면 10초마다 저절로 온다 | 보내는 코드가 없다 | 화면의 [입력 버튼]을 누를 때만 온다. 누를 때마다 `value`가 1, 0, 1, …로 바뀌고, 시뮬레이터를 켠 뒤부터 센다 |
| 연결·해제 때 LED | LED 상태를 두지 않는다 | 앱이 연결되면 외부 LED를 모두 끄고, 연결이 끊기면 LED와 밝기(`pwm`)를 모두 0으로 한다([bleuno README 1절](../bleuno/README.md#1-보드)) | 보드처럼 앱이 붙을 때(`hello`를 보내기 전)와 연결이 끝날 때(앱의 [해제], 화면의 [연결 끊기] 등) LED 4개를 모두 0으로 한다. 여러 앱이 붙어 있으면 한 앱이 붙거나 끊겨도 모두 꺼진다 |
| 빈 줄(앱의 `send("")`가 보내는 `\n` 한 줄) | `send()`가 걸러서 답이 없다 | 길이 0인 명령을 건너뛰어 답이 없다 | 길이 0인 줄에 답하지 않는다 |

- 앱의 LED Switch·밝기 막대는 앱이 보낸 명령만 기억한다. 시뮬레이터나 보드가 스스로 LED를 꺼도 앱 화면은 바뀌지 않는다.
- 공백만 있는 줄에는 시뮬레이터가 `{"result":"fail","ms":"need command"}`로, 보드는 `unknown command`로 답한다(펌웨어 소스 기준). Fake는 공백만 있는 줄도 걸러 답하지 않는다(코드 기준). 12~15주차 예제 화면으로는 빈 줄이나 공백만 있는 줄을 보낼 수 없다. 명령은 제어 화면에서만 나가고, LED 번호 칸이 비면 보내기 전에 Toast로 막는다.
- 시뮬레이터는 상태를 저장하지 않는다. 끄고 다시 실행하면 LED는 모두 0, 온도·습도는 처음 값(24.5 °C·40.0 %)이다. `value`도 처음부터 셀 것이다(예상).

## 7. 끊김과 재연결 (14주차 2일차 이후)

명령은 제어 화면에서만 나간다(12~15주차 예제에서 `send()`를 부르는 곳은 `ControlActivity`뿐이다). 제어 화면에는 [재연결]이 없으므로, 제어 화면에서 끊기면 [뒤로]를 먼저 누른다.

1. `준비됨` → [제어 화면] → LED 번호 `0` → Switch를 켠다. 14주차 1일차 확장을 했으면 `LED 0 밝기` 막대를 오른쪽 끝까지 끌었다 놓는다. 표 2 첫 줄을 채운다.
2. 제어 화면에 있는 채로 시뮬레이터 화면의 [연결 끊기]를 누른다. 이 화면에서 표 1 첫 줄과 표 2 둘째 줄을 채운다.
3. [뒤로]를 누른다. 연결 화면에서 [재연결]을 누른다.
4. `준비됨`이 되면 [제어 화면]을 다시 연다. 표 2 셋째 줄을 채운 뒤 [뒤로]를 누른다.
5. 연결 화면이 `준비됨`인 채로 시뮬레이터 터미널에서 Ctrl+C로 시뮬레이터를 끈다. 꺼진 채로 [재연결]을 한 번 눌러 본다.
6. 시뮬레이터를 다시 실행하고 [재연결]을 누른다.

## 8. 주소 직접 입력

1. [해제]로 `연결 안 됨`을 만든다.
2. 주소 칸(`주소 (예: 10.0.2.2:8266)`)에 `10.0.2.2:8266`(실기기면 `PC의 IPv4:8266`)을 넣고 [주소로 연결]을 누른다(표의 첫 줄). `준비됨`이 되면 [제어 화면]을 열어 제목을 적고 [뒤로]를 누른다.
3. 표의 예상 칸은 실행하기 전에, 막혔을 때 표를 보기 전에 모두 채운다. 그다음 표의 둘째 줄부터 차례로 주소를 넣어 [주소로 연결]을 누른다. 앞 줄이 끝난 상태에서 다음 줄을 넣는다. 끝나면 올바른 주소로 다시 [주소로 연결]을 누른다.

| 주소 칸 | 예상 상태 글자 | 실제 상태 글자 | Toast | Logcat `tag:TCP` 새 줄 |
|---|---|---|---|---|
| `10.0.2.2:8266` |  |  |  |  |
| [해제] 뒤 `10.0.2.2` (포트 없음) |  |  |  |  |
| `준비됨`에서 (빈 칸) |  |  |  |  |
| `준비됨`에서 `10.0.2.2:99999` |  |  |  |  |
| `:8266` (IP 없음) |  |  |  |  |
| `abc` |  |  |  |  |
| `10.0.2.2:8080` |  |  |  |  |
| (더 해 볼 것) `10.0.2.99:8266` |  |  |  |  |

- 연결에 실패하면 상태는 `끊김`이 된다. 14주차 2일차 이후 판은 이때 끊김 Toast(46번)도 띄운다. 12주차 2일차·13주차·14주차 1일차 판에는 끊김 Toast와 [재연결]이 없다. 빈 칸일 때의 Toast `주소를 입력하세요 (예: 10.0.2.2:8266)`는 2-4의 두 판 리스너에 모두 있다.
- 2번에서 적은 제어 화면 제목을, 목록 줄로 연결한 뒤 [제어 화면]을 열었을 때의 제목과 비교한다. 두 제목이 어디서 왔는지 19번 목록 줄 리스너와 2-4 리스너가 장치 이름 칸에 넣는 글자를 찾아 한 문장 적는다.
- **주소 칸에는 이름이 아니라 IP를 넣는다.** 연결 3초 제한은 IP를 넣었을 때 기준이다. `abc`처럼 이름을 넣으면 앱이 그 이름을 IP로 바꾸는 동안에는 이 3초 제한이 걸리지 않는다.
- `:8266`처럼 `:` 앞의 IP를 빼면 앱이 왜 연결하지 않는지 `TcpBleunoClient.kt`의 `connect()` 주석에서 찾아 한 문장 적는다.
- `8080`은 시뮬레이터의 **HTTP API 포트**다. 명령 포트는 `8266`이다. `8080`에 붙으면 `서비스 확인 중`에서 무엇을 기다리게 되는지 생각해 예상을 적는다.
- `준비됨`에서 `10.0.2.2:99999`를 넣었을 때 지금 연결이 어떻게 되는지 시뮬레이터 터미널의 새 줄로 확인한다.
- 14주차 2일차 이후 판은 [주소로 연결]을 누르는 순간 연결 결과와 상관없이 주소를 저장한다(2-4의 저장 두 줄). 잘못된 주소를 넣었으면 [재연결]도 그 주소로 간다. **주소를 고친 뒤에는 [재연결]이 아니라 [주소로 연결]을 다시 누른다.**
- 실기기에서 검색 목록이 비면 이 방법으로 연결한다. 공유기의 AP 격리(같은 Wi-Fi 기기끼리 통신을 막는 설정)나 학교 Wi-Fi는 검색(UDP)과 연결(TCP)을 모두 막을 수 있다(예상). 직접 입력으로도 연결되지 않으면 README [10. 막혔을 때](../../tools/bleuno-sim/README.md#10-막혔을-때)를 보고 에뮬레이터로 한다.

## 9. 오늘 확인할 것

- [ ] [검색] 뒤 목록에 `ESP32_BLE_SIM1 (10.0.2.2:8266)`(이름을 붙여 실행했으면 그 이름)이 한 줄 보인다.
- [ ] 목록 줄을 누르면 `연결 중` → `서비스 확인 중` → `준비됨`이 되고, 시뮬레이터 `연결 수`가 1이 된다. [해제]하면 `연결 안 됨`과 `연결 수: 0`.
- [ ] (13주차 이후) Switch를 켜면 시뮬레이터 LED 0이 `255`가 된다.
- [ ] (14주차 2일차 이후) 입력 이력에 `[24.5,40.0]`, 슬라이더를 바꾼 값, [입력 버튼]의 `입력=` 줄이 쌓인다.
- [ ] (14주차 2일차 이후) [연결 끊기] → `끊김` + Toast + [재연결] → `준비됨`. [재연결] 뒤 시뮬레이터 LED와 앱 Switch를 비교하고 까닭을 적었다.
- [ ] [주소로 연결]로 `준비됨`이 되고, 잘못된 주소에서도 앱이 멈추지 않는다.
- [ ] 내 주차까지의 캡처(1~3)를 찍었다(앱 화면은 세로).
- [ ] `useTcp = false`, `useFake = true`로 되돌렸다.
- [ ] (Windows에서 방화벽 창의 [액세스 허용]을 눌렀거나 방화벽 규칙을 만들거나 바꿨다면) README 7절대로 지웠다. 관리자 권한이 없으면 조교에게 맡겼다.

| `준비됨`이 된 뒤 상태 글자가 `검색 완료 · 장치 수: 1`로 바뀌고 [검색]이 켜진다. [해제]·[제어 화면]도 켜져 있다 (14주차 2일차 이후) | `끊김`에서 [검색]을 누르고, 5초 검색이 끝나기 전에 [재연결]을 눌렀다. 검색이 끝날 때 29번이 상태 글자를 덮어쓴 것이고 연결은 `준비됨` 그대로다([제어 화면]은 `상태: 준비됨`). 14주차 2일차 예제의 원래 동작이다. [검색]을 눌렀다면 [중지]를 누르거나 검색이 끝난 뒤에 [재연결]을 누른다 |
| (예상) [재연결]을 누르면 Toast `마지막 주소가 없습니다. [검색]부터 하세요` (14주차 2일차 이후) | 14주차 2일차 프로젝트에 12주차 판 리스너(저장 두 줄이 없는 것)를 넣고 [주소로 연결]로만 연결했다. 2-4의 14주차 2일차 판으로 바꾼다 |
| [해제] 뒤 `disconnect: socket.close() → 연결 안 됨`, `지난 연결 스레드 끝남: java.net.SocketException: Socket closed` | 오류가 아니다. [해제]로 스스로 닫은 연결의 스레드가 끝났다는 줄이다 |
| (예상) [검색] 목록이 늘 비고 [주소로 연결]도 곧 `끊김`. Logcat에 `UDP 검색 중 오류:`나 `connect/read 오류:` 줄 | Manifest에 INTERNET 줄이 없다. 2-2를 한다 |
| [끊김 시험]을 누르자 앱이 닫히고 홈 화면이 나온다(오류 창 없음). Logcat(태그 `AndroidRuntime`) `FATAL EXCEPTION: main`, `java.lang.ClassCastException: com.example.smartio.bleuno.TcpBleunoClient cannot be cast to com.example.smartio.bleuno.FakeBleunoClient` | `useFake`와 `useTcp`를 둘 다 `true`로 두었다. `useFake = false`로 한다(2-3). 이 줄은 태그가 `TCP`가 아니므로 필터에서 `tag:TCP`를 빼고 본다. 그 아래 `at …MainActivity.kt:` 뒤의 줄 번호는 파일마다 다르다 |
| 켜 둔 LED가 시뮬레이터 화면에서 저절로 모두 꺼졌다. 앱의 Switch는 켜진 모양 그대로다 | 앱의 상태 글자를 본다. `준비됨` 그대로면 다른 연결(다른 사람의 앱, 같은 PC의 다른 프로그램)이 내 시뮬레이터에 붙었거나 끊긴 것이다. 시뮬레이터는 그때 LED를 모두 끈다([시뮬레이터와 Fake·보드의 차이](#시뮬레이터와-fake보드의-차이)). 터미널에 내 앱이 아닌 `[주소:포트]`의 `연결`·`해제` 줄이 찍혔는지 보고, Switch를 껐다 켜서 다시 켠다. `끊김`이면 화면의 [연결 끊기]나 Ctrl+C로 내 연결이 끊긴 것이고, Switch로는 다시 켤 수 없다. 위 `EOF: 상대가 연결을 닫음` 줄대로 [뒤로]를 누르고 다시 연결한 뒤(14주차 2일차 이후는 [재연결], 13주차·14주차 1일차는 목록 줄) [제어 화면]에서 LED 번호를 넣고 켠다 |
| 입력 이력에 `입력=` 줄이 저절로 생기지 않는다. `dht11` 값이 Fake 예시와 다르다. 시뮬레이터를 다시 켰더니 LED·온습도가 처음 값이다 | 앱 문제가 아니다. [시뮬레이터와 Fake·보드의 차이](#시뮬레이터와-fake보드의-차이)를 본다 |
| 입력 이력 시각이 PC 시계와 9시간 다르다 | 에뮬레이터 시간대가 GMT다. 앱 문제가 아니다 |

시뮬레이터 쪽에서는 시뮬레이터 터미널의 로그를 본다. 연결되면 `[127.0.0.1:포트] 연결 (1개)`, 끊기면 `해제 (0개)`, 명령마다 `[127.0.0.1:포트] on 0 → {"result":"ok","ms":"led(s) on"}` 같은 줄이 찍힌다. 줄 앞에는 `[시:분:초]`가 붙고, 포트 번호는 매번 다르다(에뮬레이터에서 붙으면 `127.0.0.1`로 보인다). 시뮬레이터 쪽 증상은 README [10. 막혔을 때](../../tools/bleuno-sim/README.md#10-막혔을-때)에 있다.
한 번에 한 곳만 바꾸고 다시 실행한다. 해결되지 않으면 오류 문구·Logcat·시뮬레이터 터미널이 보이는 화면을 그대로 보여 주고 도움을 받는다.
앱 문제인지 연결 문제인지 모르겠으면 `useTcp = false`, `useFake = true`로 같은 동작을 해 본다. Fake에서 되면 주소·시뮬레이터·네트워크를, Fake에서도 안 되면 내 코드를 본다.

## 제출

이 실습은 선택 실습이다. 제출 여부와 위치는 수업 공지를 따른다. 내라고 하면 아래를 낸다.

1. **캡처 1**: 검색 목록에 `ESP32_BLE_SIM1 (10.0.2.2:8266)`(이름을 붙여 실행했으면 그 이름)이 보이고 상태 글자가 `준비됨`인 세로 연결 화면(4번 3단계)
2. **캡처 2** (13주차 이후): LED 0을 켠 직후의 앱 명령 로그와, LED 0이 켜진 시뮬레이터 창
3. **캡처 3** (14주차 2일차 이후): 입력 이력에 온습도 2줄 이상과 `입력=` 줄이 보이는 제어 화면
4. **막혔을 때 한 줄**: 8번에서 일부러 넣은 잘못된 주소 하나와 그때 Logcat `tag:TCP` 줄, 그 줄이 무슨 뜻인지 한 문장
5. **`MainActivity.kt`**: 2번에서 바꾼 곳을 넣은 파일

캡처에 계정·알림 내용이 보이지 않게 한다. PC의 IP가 캡처에 들어가도 되는지는 수업 공지를 따른다.

## 먼저 끝났다면

- (12·13주차·14주차 1일차) 연결 화면이 `준비됨`인 채로 시뮬레이터 화면의 [연결 끊기]를 누른다. 연결 화면의 상태 글자와 켜진 버튼을 적고, 다시 연결하려면 무엇을 눌러야 하는지 적는다.
- 시뮬레이터를 Ctrl+C로 끈 채 [검색]을 누르고, 5초 뒤 상태 글자와 Logcat `stopScan:` 줄을 본다. 끝나면 시뮬레이터를 다시 실행한다.
- 시뮬레이터를 Ctrl+C로 끄고 학번 이름으로 다시 실행한다(README [9. 수업에서 여럿이 쓸 때](../../tools/bleuno-sim/README.md#9-수업에서-여럿이-쓸-때), 예: `py sim.py --name ESP32_BLE_0423`). [검색]을 눌러 목록 줄과 Logcat `onFound:` 줄의 이름을 본다.
- (13주차 이후) LED 번호를 바꿔 가며 LED 두 개 이상을 켠 뒤 [전체 끄기]를 누른다. 시뮬레이터 터미널에 찍힌 명령과 LED 4개의 숫자, 앱의 Switch 모양을 본다.
- 내 주차에 해당하는 7번·8번의 (더 해 볼 것)을 한다.

추가 과제는 선택 사항이다.
