# 중간고사: 혼자 60분, 제출한 파일로 채점

7주차까지 SmartIO에서 한 일을 **작은 앱 하나**로 다시 만듭니다.
새 문법은 없습니다. 2~7주에 쓴 코드를 **혼자, 시간 안에** 씁니다.

```text
Rehearsal
카운트다운 중
남은 초: 3
[시작] [취소]      ← 회전해도 그대로 이어진다
```

---

# 1일차 — 시험 범위·채점표와 공개 리허설

`30분 설명 → 60분 리허설`

1. 시험 범위와 채점표 20점
2. 제출본 기준: 저장 후 다시 실행
3. 60분 시간 예산
4. 리허설 starter의 TODO 다섯 곳

---

## 1일차 · 0–5분 — 이번 주 두 날과 시험 범위

| 날 | 30분 | 60분 |
|---|---|---|
| 1일차 | 범위·채점표·시간 예산 | **공개 리허설** (점수 없음) |
| 2일차 | 절차·허용 자료·장애 대체 | **본시험** (20점) |

- 범위는 **2~7주**입니다. 버튼·ViewBinding·`isEnabled` / 회전 / 코루틴 / ViewModel·StateFlow
- 본시험은 오늘 리허설과 **같은 모양**입니다. 화면 이름·문구·세부 요구만 다릅니다.
- 두 축: ① 버튼 → 코루틴(delay·취소·오류) ② 회전해도 이어지기(ViewModel + StateFlow)

---

## 1일차 · 5–12분 ① — 채점표 20점 공개

| 항목 | 점수 | 이렇게 확인합니다 |
|---|---:|---|
| UI·이벤트 | 5 | 누르면 동작, 상태에 맞게 켜지고 꺼짐, 글자 |
| 생명주기·복원 | 5 | 진행 중에 **회전**해도 글자·숫자·버튼이 이어짐 |
| 코루틴 delay·취소·오류 | 5 | 1초마다 줄어듦, [취소] 뒤 멈춤, 실패해도 안 꺼짐 |
| StateFlow collect | 3 | 값은 ViewModel에, 화면은 `collect { }`에서 |
| 실행·제출 | 2 | 제출 파일이 빌드·실행됨, 파일·캡처를 시간 안에 |

채점은 **앱을 실행해 보고** 합니다. 코드 길이는 점수가 아닙니다.
세부 기준: [rubric.md](rubric.md)

---

## 1일차 · 5–12분 ② — 항목마다 코드 어디를 보나

```kotlin
private val viewModel: RehearsalViewModel by viewModels()  // 복원
job = viewModelScope.launch {                              // 코루틴
    for (i in 5 downTo 1) {
        _seconds.value = i                                 // StateFlow
        delay(1000)
    }
}
viewModel.seconds.collect { seconds ->                     // collect
    binding.timeText.text = "남은 초: $seconds"            // UI
}
```

- 한 원인으로 여러 곳이 틀리면 **한 번만** 뺍니다.
- 빌드가 안 되면 실행해 볼 것이 없습니다. 모르는 TODO는 **비워 둔 채** 빌드되게 둡니다.

---

## 1일차 · 12–17분 — 제출본 기준: 저장 후 다시 실행

```text
고치기 → 저장(Ctrl+S) → Run ▶ 다시 → 점검표 확인 → 두 파일 제출
```

- 채점자는 **제출한 파일**을 같은 starter에 넣어 실행합니다. 내 에뮬레이터 화면이 아닙니다.
- 제출: `MainActivity.kt`, `○○ViewModel.kt`, 문항이 지정한 캡처
- `activity_main.xml`·`strings.xml`은 고치지 않습니다. 고쳐도 채점에는 starter 원본이 쓰입니다.
- 마지막으로 고친 뒤 **한 번 더 실행**하지 않은 코드는 확인되지 않은 코드입니다.

---

## 1일차 · 17–22분 — 60분 시간 예산

| 시간 | 할 일 |
|---|---|
| 0–5분 | starter 열고 실행, 문항과 TODO 읽기 |
| 5–25분 | ViewModel 쪽 TODO (코루틴·취소) |
| 25–40분 | 화면 쪽 TODO (버튼·collect) |
| 40–50분 | 점검표: 시작·완료·취소·회전 |
| 50–55분 | 저장 → 다시 실행 |
| 55–60분 | 파일 두 개와 캡처 제출 |

25분에 ViewModel이 안 끝나도 **화면 쪽으로 넘어갑니다**. 점수는 동작한 만큼입니다.

---

## 1일차 · 22–27분 — 리허설 starter 둘러보기

| TODO | 파일 · 자리 | 할 일 |
|---|---|---|
| (1) | `RehearsalViewModel.kt` `startCountdown()` | 막음 + `launch` + 5→1 + 완료 |
| (2) | `RehearsalViewModel.kt` `cancelCountdown()` | `job?.cancel()` + 취소됨 |
| (3) | `MainActivity.kt` 1·2번 리스너 | ViewModel 함수 부르기 |
| (4) | `MainActivity.kt` 3번 틀 `collect` | 글자 + 버튼 켜기·끄기 |
| (5) | `MainActivity.kt` 4번 틀 `collect` | `남은 초: 3` |

이미 들어 있는 것: 의존성, XML, import, `by viewModels()`, `_state`·`state`, `repeatOnLifecycle` 틀.
**값을 만드는 쪽(ViewModel) → 받는 쪽(화면)** 순서로 채웁니다.

# 2일차 — 시험 안내와 본시험

`30분 안내 → 60분 본시험`

1. 리허설에서 자주 막힌 곳
2. 시험 순서, 허용 자료, 장애가 나면
3. 모두 함께 PC 점검(내 Rehearsal 실행)

---

## 2일차 · 0–5분 — 리허설에서 자주 막힌 곳

| 증상 | 원인 |
|---|---|
| `Unresolved reference 'seconds초'.` | `"$seconds초"` — `$변수` 바로 뒤에 한글 |
| [취소]가 켜지지 않는다 (예상) | 비교 글자가 `"카운트다운 중"`과 다르다 |
| [취소] 뒤에도 숫자가 준다 | `job = viewModelScope.launch {`로 보관하지 않았다 |
| 회전하면 `대기 중`으로 돌아간다 (예상) | `by viewModels()` 대신 직접 만들었다 |

빌드는 되는데 틀린 것은 **실행해서 눌러 봐야** 보입니다. 그래서 점검표가 있습니다.

---

## 2일차 · 5–12분 — 시험 순서

```text
0–5분    starter 받기 → File › Open → Sync → Run ▶ → 첫 화면 확인
5–25분   ViewModel 쪽 TODO
25–40분  화면 쪽 TODO
40–50분  점검표: 시작·완료·취소·회전 (실패가 있으면 실패도)
50–55분  저장 → 다시 실행
55–60분  제출: MainActivity.kt, ○○ViewModel.kt, 캡처
```

- 문항지와 starter는 시험 시작 때 받습니다.
- 문구가 이해되지 않으면 손을 듭니다. 답은 **모두에게 같은 공지**로 합니다.
- 자세한 절차: [exam_structure.md](exam_structure.md)

## 2일차 · 12–17분 — 허용 자료와 금지 행동

| 허용 | 금지 |
|---|---|
| 이 과목 공개 교재(2~8주, examples 포함) | 생성형 AI (브라우저·Android Studio 모두) |
| 내가 만든 `SmartIO` 프로젝트 열어 보기 | 메신저·메일·클라우드로 코드 주고받기 |
| Android Developers·Kotlin 공식 문서 | 다른 사람과 대화, 휴대폰 |
| 자동 완성, Alt+Enter, Logcat | 검색 사이트·블로그·질문 사이트 |

시험 공지가 이 표와 다르면 **공지가 우선**합니다.

---

## 2일차 · 17–22분 — 장애가 나면

| 상황 | 이렇게 |
|---|---|
| 에뮬레이터가 안 켜짐·멈춤 | 손 들기 → Cold Boot → 안 되면 예비 PC로 |
| 고치기 전부터 Sync·빌드 실패 | 손 들기 → starter 다시 받기 |
| PC가 멈춤 | 손 들기 → 다시 켜고 열기 (평소에 Ctrl+S) |
| LMS에 올라가지 않음 | 손 들기 → 조교 USB에 복사, 시각 기록 |

- 조교가 **시각·증상·조치**를 적고, 잃은 시간만큼 기록을 근거로 연장합니다.
- 빨간 줄·빌드 오류처럼 **내 코드 때문**인 것은 장애가 아닙니다.

---

## 2일차 · 22–27분 — PC 점검: 내 Rehearsal 실행

1. 어제 만든 `Rehearsal` 프로젝트를 엽니다.
2. 아래쪽 진행 표시(Sync)가 끝나면 Run ▶을 누릅니다.
3. 에뮬레이터에 `Rehearsal` 화면이 뜨고 Logcat 창이 열리는지 봅니다.

```text
☐ Sync 끝남   ☐ 에뮬레이터 켜짐   ☐ Run 성공   ☐ Logcat 보임
```

여기서 안 되는 PC는 **시험 전에** 자리를 옮깁니다. 에뮬레이터는 켜 둔 채로 시작합니다.
