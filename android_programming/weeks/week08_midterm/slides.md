# 중간고사: 수업에서 한 것을 혼자 다시

1~7주 실습에서 **실제로 제출한 것**을 한 문제씩 모은 문제 은행으로 연습하고, 같은 문제를 값만 바꿔 시험을 봅니다.
새 문법은 없습니다. 수업에서 쓴 `StudentCard` 프로젝트에서 **혼자, 시간 안에** 다시 만듭니다.

```text
내 정보
이름: 홍길동
3
[-1] [초기화] [+1]      ← 회전해도 3 이 남는다
```

- 해답은 없고 문제마다 **확인할 것**과 **힌트**가 있습니다.
- 답안은 고친 코드 + 에뮬레이터 캡처 + 설명 1~2문장입니다.

2. 문제 은행 일곱 문제, 문제 하나 읽는 법

## 1일차 · 0–5분 — 이번 주 두 날과 범위

| 날 | 30분 | 60분 |
|---|---|---|
| 1일차 | 문제 은행·읽는 법·확인하는 법·채점표 | **연습** (점수 없음) |
| 2일차 | 규칙(분반 공지)·답안에 넣을 것·PC 점검 | **중간고사** (20점) |

- 범위는 1~7주 가운데 **수업에서 나간 주차까지**입니다. 어디까지인지는 공지에 적습니다.
- 시험 문제는 은행 문제와 **같은 문제, 값만 다른 것**입니다. 글자·id·숫자·키 이름이 바뀝니다.
- 수업에서 한 것: Kotlin 출력, LinearLayout 화면, `findViewById`, 버튼 카운터, 회전해도 남는 `count`.

## 1일차 · 5–12분 ② — 문제 하나 읽는 법: a03_name_button

[a03 문제 문장](examples/a03_name_button/README.md) — 모든 문제가 같은 순서다

```text
할 일          XML 에서 할 것(View·id·글자) → Kotlin 에서 할 것(findViewById·리스너·변수)
확인할 것      화면·Logcat 으로 스스로 맞춰 보는 목록. 해답 대신이다
힌트           막혔을 때. 시험의 설명 물음이 이 내용이다
이 문제의 값   시험에서 바뀌는 값 — nameText · 홍길동 · countText · 0 · plusButton · +1 · 3
설명 물음      시험에서 1~2문장으로 답할 것
```

- `id`·글자·숫자는 문제 문장에서 **복사해 붙입니다.** 한 글자 다르면 `Unresolved reference`.
- 확인할 것 예: 처음 `이름: 홍길동`·`0`, `+1` 세 번 → `3`, Logcat 에 빨간 줄 없음.

## 1일차 · 12–17분 — 확인하는 법: 실행·캡처·Logcat

```text
저장(Ctrl+S) → Run ▶ → 화면에서 확인할 것을 하나씩 → 요구한 상태를 캡처
Logcat 탭 → 필터 칸에 태그(Life) → 그 줄만 보인다
회전 → 에뮬레이터 창 옆 도구 막대의 회전 버튼
```

- 캡처는 에뮬레이터 창 옆 카메라 버튼, 또는 Win+Shift+S / ⌘+Shift+4.
- 디자인 미리보기(Split)는 배치 확인용입니다. 캡처는 **실행된 화면**이어야 합니다.
- 빨간 줄은 첫 줄부터 읽습니다. [막혔을 때](lab.md#막혔을-때) 표에 자주 나오는 줄이 있습니다.

**확인할 것은 화면과 Logcat 으로 보는 결과다. 결과가 같으면 코드 모양은 달라도 된다.**

## 1일차 · 17–22분 — 채점표 20점: 동작·코드·설명

| 보는 것 | 비율 | 어떻게 |
|---|---:|---|
| 동작(확인할 것) | 약 60% | 캡처와 코드에서 항목마다 |
| 코드 | 약 20% | 붙인 XML·Kotlin 이 캡처와 맞고 요소가 들어 있다 |
| 설명 | 약 20% | 설명 물음에 자기 말로 1~2문장 |

- 문제가 2개면 10점씩, 4개면 5점씩. 어느 쪽인지는 공지에.
- 한 원인은 한 번만 뺍니다. 실행 안 되는 줄은 `//` 로 막고 실행되는 상태를 캡처 → 원래 코드와 오류는 답안에.
- 세부 기준: [rubric.md](rubric.md)

`30분 안내 → 본시험(공지한 시간)`

---

## 2일차 · 0–5분 — 연습에서 자주 막힌 곳

| 증상 | 원인 |
|---|---|
| `Unresolved reference 'nameText'.` | XML 의 `@+id/` 뒤 이름과 다르다 |
| `Unresolved reference 'name님'.` | `$변수` 바로 뒤에 한글 — `"${name}님"` |
| 버튼을 눌러도 숫자가 안 바뀐다 | `countText.text = "$count"` 를 빠뜨렸다 |
| 회전하면 `0` 으로 돌아간다 | `putInt`·`getInt` 키가 다르거나 `count` 가 `onCreate` 안에 있다 |

빌드는 되는데 틀린 것은 **실행해서 눌러 봐야** 보입니다. 그래서 확인할 것이 있습니다.

---

## 2일차 · 5–12분 — 시험 규칙: 분반 공지가 정한다

```text
문항   은행 문제를 값만 바꿔 2~4문제      시간   30~60분 (시작·끝 시각은 공지)
범위   수업에서 나간 주차까지            제출   LMS 답안 칸 — 코드 · 캡처 · 설명
```

- 볼 수 있는 것(교재·내 프로젝트·공식 문서)과 AI 도구 허용 여부는 공지를 따릅니다.
- 문제끼리 이어지지 않습니다. **오래 막히면 다음 문제로.**
- 다 못 했어도 코드·캡처·시도한 것을 냅니다. 부분 점수가 있습니다.
- 질문은 문구·제출 방법·장애만. 답은 **모두에게 같은 공지**로 합니다.
- 자세한 절차: [exam_structure.md](exam_structure.md)

---

## 2일차 · 12–17분 — 문제 읽는 순서: 값이 어디가 다른지

```text
은행 a03    nameText · 홍길동 · countText 0 · plusButton +1 · 세 번 → 3
시험 문제   nameText · 김민지 · countText 10 · plusButton +2 · 세 번 → 16   ← 값만 다르다
```

1. 처음 3분은 읽기만. "이 문제의 값"에서 은행과 다른 값에 표시합니다.
2. XML → Kotlin → 저장·실행 → 확인할 것 → 캡처. 1일차와 같은 순서입니다.
3. 맞지 않는 항목은 그 항목이 가리키는 할 일로 돌아갑니다.

**값은 복사해 붙인다. id 한 글자가 다르면 빨간 줄이다.**

---

## 2일차 · 17–22분 — 답안에 넣을 것: 코드·캡처·설명

```text
① 코드    activity_main.xml · MainActivity.kt 전체 선택 → 복사 → 답안 칸에 붙이기
② 캡처    요구한 상태의 에뮬레이터 화면 (회전·Logcat 을 요구하면 그 화면까지)
③ 설명    설명 물음에 자기 말로 1~2문장 (힌트에 있는 수준)
```

- 설명 예: "회전하면 Activity 가 없어지고 새로 만들어져서 `count = 0` 이 다시 실행된다."
- 빌드가 안 되는 줄은 `//` 로 막고 실행되는 상태를 캡처합니다. 원래 코드와 오류 메시지는 답안에 적습니다.
- 마지막으로 고친 뒤 **저장 → Run ▶ → 확인할 것**을 한 번 더 합니다.

**동작·코드·설명 세 가지가 문제마다 있어야 한다.**

---

## 2일차 · 22–27분 — PC 점검: 프로젝트 실행과 에뮬레이터

1. `StudentCard` 프로젝트를 엽니다.
2. 아래쪽 진행 표시(Sync)가 끝나면 Run ▶ 을 누릅니다.
3. 에뮬레이터에 화면이 뜨고 Logcat 창이 열리는지 봅니다. LMS 답안 칸도 열어 둡니다.

```text
☐ Sync 끝남   ☐ 에뮬레이터 켜짐   ☐ Run 성공   ☐ Logcat 보임   ☐ LMS 답안 칸 열림
```

여기서 안 되는 PC 는 **시험 전에** 자리를 옮깁니다. 에뮬레이터는 켜 둔 채로 시작합니다.
