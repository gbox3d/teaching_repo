# 중간 개인 실기 — 공개 운영 구조

이 문서는 공개 가능한 공통 구조다. 실제 시험 문구, 고유 입력값, fixture, 정답·부분답, 자동/숨은 testcase와 학생 정보는 별도 비공개 공간에서 관리한다.

## 평가 범위

| 영역 | 확인 역량 |
|---|---|
| Kotlin/XML UI | View binding, event, 상태별 표현, 기본 접근성 |
| lifecycle/ViewModel | 화면 재생성과 상태 소유권, View 참조 안전성 |
| coroutine | UI 응답성, scope, 취소, 예상된 오류 처리 |
| Flow | 읽기 전용 StateFlow, 단방향 상태, lifecycle-aware collect |
| 검증·설명 | normal·boundary·failure 재현, 로그와 선택 근거 |

세부 문항별 포함 깊이는 시험 전 공식 공지로 확정한다.

## 권장 2일 운영

### 1일차: 공개 리허설

- 30분: 공개 구조·rubric·시간 관리 설명
- 60분: 실제 시험과 다른 중립 동형 연습

### 2일차: 검증 안내와 평가

- 30분: 공정한 공통 환경·제출·장애 처리 안내
- 60분: 별도 비공개 시험 패킷의 개인 실기 또는 기관 일정에 따른 공개 검증 리허설

실제 시험 시간이 60분과 다르면 설명 시간과 평가 시간을 분리해 LMS에 사전 공지한다.

## 비공개 시험 패킷 체크

1. 실제 요구사항과 관찰 가능한 완료 조건
2. 동일 release/checksum의 중립 starter
3. 필요한 fixture와 사용 허가
4. 제출 경로·파일명·마감 시각
5. 참고 자료·네트워크·AI 도구 허용 범위
6. 장비/IDE/제출 장애의 기록과 대체 제출 절차
7. 채점자용 정답 기준과 비공개 testcase

## 학생 산출물의 공개 구조

- 지정 source 파일 또는 저장소 revision
- 실행 대상과 마지막 commit id
- 요구된 normal·boundary·failure 상태
- 짧은 구현 설명과 검증 증거

구체 파일명·기능·입력값은 실제 시험 공지의 `TBD`다.

## 감독 시작 전 체크

- 기준 프로젝트가 모든 시험 PC/기준 기기에서 실행된다.
- dependency cache와 에뮬레이터/실기기 상태를 확인한다.
- starter에 답안, 이전 학생 코드·식별자, 실제 점수가 없다.
- 제출 시스템에 테스트 업로드·재다운로드를 수행한다.
- 동일한 공지·시간·장애 대응 절차를 모든 응시자에게 적용한다.
- 장애 발생 시 시각·증상·대체 제출을 공식 기록한다.

## 공정성과 보안 경계

- 구현 답에 해당하는 개별 힌트는 제공하지 않는다.
- 환경/문구 설명은 모든 학생에게 같은 수준으로 공지한다.
- 추가 시간과 대체 평가는 대학 규정 및 공식 기록을 따른다.
- 공개 Git 저장소에 학생 코드, 이름, 학번, 점수, 이의신청 기록을 올리지 않는다.
- 실제 문제나 fixture를 이 폴더의 공개 연습과 섞지 않는다.
