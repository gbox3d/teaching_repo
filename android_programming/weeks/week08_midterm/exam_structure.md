# 중간고사(개인 실기) — 시험 운영 안내

이 문서는 학생과 감독자가 함께 보는 공개 운영 안내다. 본시험 문항·starter·정답은 이 저장소에 없고 시험 시작 때 배포한다.
허용 자료·제출 위치·마감 처리는 이 문서가 기본이며, 시험 공지(LMS)가 이 문서와 다르면 **공지가 우선**한다.

## 시험 범위와 문항 모양

본시험은 1일차 리허설과 **같은 모양**이다. 화면 이름·문구·초 수·세부 요구만 바뀐다. 문항은 아래 두 축으로 만든다.

| 축 | 요구 | 쓰는 코드(배운 주) |
|---|---|---|
| ① 코루틴 | 버튼을 누르면 1초씩 기다리며 숫자를 줄이고, [취소]로 멈추고, 실패하는 일이 있으면 앱이 꺼지지 않게 받는다 | `viewModelScope.launch`(7주), `for … downTo`·`delay`·`Job`·`cancel()`·`try/catch`(6주) |
| ② 회전 유지 | 진행 중에 화면을 돌려도 글자·숫자·버튼 상태가 이어진다 | `by viewModels()`·`MutableStateFlow`·`repeatOnLifecycle` 틀 안의 `collect`(7주), `isEnabled`(5주) |

starter에 **미리 들어 있는 것**: `build.gradle.kts`(의존성), `activity_main.xml`, `strings.xml`, ViewBinding 틀, `by viewModels()` 줄, `MutableStateFlow`/`StateFlow` 선언, `repeatOnLifecycle` 틀, 필요한 import. 가짜로 실패하는 함수가 필요하면 완성된 채로 들어 있다.

범위 밖: BroadcastReceiver, 권한, ListView, SharedPreferences, BLE(10주 이후).

## 시험 날 순서

| 때 | 학생 | 감독(강의자·조교) |
|---|---|---|
| 설명 30분 | 절차·허용 자료·장애 대체 안내를 듣는다. 1일차 `Rehearsal` 프로젝트를 열어 실행해 PC를 점검한다 | 실행이 안 되는 PC를 찾아 자리를 옮긴다 |
| 시작 | 휴대폰을 가방에 넣는다. 브라우저에는 허용 자료 탭만 남긴다 | 문항지와 starter를 배포하고 시작 시각을 칠판에 적는다 |
| 0–5분 | starter를 열고(File › Open) Sync가 끝나면 Run ▶, 첫 화면 확인 | starter가 열리지 않는 학생을 먼저 돕는다(장애 기록) |
| 5–25분 | ViewModel 쪽 TODO | 순회. 구현 힌트는 주지 않는다 |
| 25–40분 | 화면 쪽 TODO | 순회. 구현 힌트는 주지 않는다 |
| 40–50분 | 점검표: 시작·완료·취소·회전(문항에 실패가 있으면 실패도) | 순회 |
| 50–55분 | 저장 → 다시 실행 | "5분 남음" 공지 |
| 55–60분 | 파일 두 개와 캡처를 제출한다 | "제출 시간" 공지, 제출 확인 |
| 끝 | 편집을 멈춘다 | 장애 기록지를 모아 연장 대상을 확정한다 |

문항 문구가 이해되지 않으면 손을 든다. 답은 개인에게만 하지 않고 **모두에게 같은 내용으로** 공지한다.

## 제출

| 항목 | 내용 |
|---|---|
| 파일 | starter에 있는 `MainActivity.kt`와 `○○ViewModel.kt` 두 개. 파일 이름을 바꾸지 않는다 |
| 캡처 | 문항이 지정한 화면(예: 진행 중에 회전한 화면, 취소한 화면). 에뮬레이터 창의 카메라 모양 버튼(Take Screenshot)으로 찍는다 |
| 위치·마감 | 시험 공지의 LMS 제출 칸. 60분이 끝나는 시각까지 |
| 파일 찾기 | Project 창에서 파일 우클릭 › **Open In › Explorer**(맥 **Finder**). 폴더는 `app/src/main/java/com/example/…/` |

**제출본 기준**: 채점자는 제출한 두 파일을 같은 starter 프로젝트에 넣어 빌드·실행하고 채점한다. 내 에뮬레이터에 떠 있던 화면이 아니라 제출한 파일이 채점 대상이다.

- `activity_main.xml`·`strings.xml`은 문항이 따로 요구하지 않으면 고치지 않는다. 고쳐도 채점에는 starter 원본이 쓰인다.
- 마지막으로 고친 뒤 **저장(Ctrl+S, 맥 ⌘+S) → Run ▶ 다시 실행 → 점검표**를 한 번 더 한다. 다시 실행하지 않은 코드는 확인되지 않은 코드다.
- 빌드가 되지 않으면 실행해서 볼 수 있는 것이 없다. 끝내지 못한 TODO는 빨간 줄을 남기지 말고 비워 둔 채(또는 그 줄 앞에 `//`를 붙여) 빌드되는 상태로 제출한다.

## 장애가 나면

**먼저 손을 든다.** 조교가 장애 기록지에 시각·증상·조치를 적는다. 장애로 잃은 시간은 기록을 근거로 연장한다.
빨간 줄, 빌드 오류, 앱이 꺼지는 것처럼 **내 코드 때문에 생긴 문제는 장애가 아니다.**

| 상황 | 대체 절차 |
|---|---|
| 에뮬레이터가 켜지지 않거나 멈춘다 | Device Manager에서 그 기기의 ⋮ › **Cold Boot Now**. 5분 안에 안 되면 예비 PC로 자리를 옮기고, 작성 중인 두 파일은 조교 USB로 옮긴다 |
| 코드를 고치기 전부터 Sync·빌드가 실패한다 | starter 배포본 문제일 수 있다. 조교가 USB의 starter 복사본을 다시 주거나 자리를 옮긴다 |
| PC가 멈추거나 꺼진다 | 다시 켜고 프로젝트를 연다. 평소에 자주 저장해 둔다. 되살리지 못한 부분은 기록하고 연장한다 |
| 에뮬레이터 장애로 캡처를 찍지 못한다 | 파일만 제출하고 기록지에 "캡처 불가(장애)"를 남긴다. 채점자가 제출 파일을 실행해 확인한다 |
| LMS에 올라가지 않는다 | 조교 USB에 `학번_파일이름`으로 복사하고 기록지에 시각을 적는다. 이 복사본을 제출본으로 인정한다 |
| 몸이 아프거나 급한 일이 생긴다 | 감독자에게 알린다. 처리는 대학 규정을 따른다 |

## 시작 전 점검(강의자·조교)

- [ ] 본시험 starter를 실습실 Android Studio의 New Project 템플릿과 같은 AGP·Gradle 버전으로 만들었고, 그 버전을 적어 두었다(AGP ______ / Gradle ______).
- [ ] 시험 전날 모든 시험 PC에서 같은 설정의 starter 껍데기(문항 없는 프로젝트 폴더)를 File › Open → Sync해 Gradle 캐시를 채웠다. Sync가 실패한 PC는 좌석표에 표시했다.
- [ ] 본시험 starter를 네트워크 없이 빌드해 보았고, USB 복사본과 예비 PC가 준비되어 있다.
- [ ] 2일차 설명 22–27분에 학생마다 자기 `Rehearsal` 프로젝트가 실행된다(PC·에뮬레이터·Android Studio 점검). 본시험 starter의 Sync는 이 점검이 아니라 전날 껍데기 Sync로 확인한다.
- [ ] starter에 정답 코드, 이전 학생 코드·이름이 들어 있지 않다.
- [ ] LMS 제출 칸에 시험 파일을 올리고 내려받아 보았다.
- [ ] 시험 PC의 Android Studio AI 도우미가 로그인되어 있지 않다.
- [ ] 장애 기록지, 시작·종료 시각을 적을 칠판, "5분 남음" 공지 담당이 정해져 있다.
- [ ] 같은 공지·시간·장애 대체 절차를 모든 학생에게 적용한다.

## 공정성과 공개 범위

- 구현 답에 해당하는 개별 힌트는 주지 않는다. 문구·환경 설명은 모두에게 같은 수준으로 공지한다.
- 연장과 대체 제출은 장애 기록지에 적힌 것만 인정한다.
- 공개 저장소에는 본시험 문항·starter·정답, 학생 코드·이름·학번·점수를 올리지 않는다.
- 빌드가 되지 않는 제출의 처리(구현 시도 흔적이 있을 때 기본점수를 줄지)는 [채점표](rubric.md#빌드가-되지-않는-제출)에 적고 시험 전에 공지한다.
