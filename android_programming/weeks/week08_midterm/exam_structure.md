# 중간고사(개인 실기) — 시험 운영 안내

이 문서는 학생과 감독자가 함께 보는 공개 운영 안내다. 시험에 내는 문제의 값과 해답은 이 저장소에 없다.
시간·문항 수·허용 자료·제출 방법은 **분반 공지가 정한다.** 이 문서와 공지가 다르면 **공지가 우선**한다.

|---|---|

| 형식 | 개인 실기. [문제 은행](examples/README.md)의 문제를 **값만 바꿔** 2~4문제 낸다 |
| 범위 | 1~7주 가운데 **수업에서 나간 주차까지**([README 이번 주 범위](README.md#이번-주-범위)). 어디까지인지는 공지에 적는다 |

## 시험 문제 — 문제 은행에서, 값만 바꿔

- 1~7주 실습 제출을 한 문제씩으로 정리한 문제 은행이 공개돼 있다. 문제마다 할 일·확인할 것·힌트·이 문제의 값·설명 물음이 있고, 해답은 공개하지 않는다.
- 시험 문제는 은행 문제와 **같은 문제를 값만 바꾼 것**이다. 문장·할 일·확인하는 방법은 같고, "이 문제의 값" 표의 값(글자·id·숫자·키 이름)만 다르다. 은행에 보이는 값이 시험에 그대로 나오지 않는다.
- 설명 물음은 그 문제의 힌트에 있는 내용이다. 예: `id` 와 `R.id` 의 연결, `var` 인 이유, 회전할 때 Activity 가 다시 만들어지는 것, `?.`·`?:` 의 뜻.
- 문제끼리 이어지지 않는다. 이어서 하는 모양(a03 → a05)이어도 앞 문제가 안 됐으면 그 상태에서 다음 문제를 시작해도 된다.

## 시험 날 순서

| 때 | 학생 | 감독(강의자·조교) |
|---|---|---|
| 설명 30분 | 공지(규칙·시간·제출)를 듣는다. `StudentCard` 를 열어 실행해 PC 를 점검한다 | 실행이 안 되는 PC 를 찾아 자리를 옮긴다 |
| 시작 | 공지대로 브라우저 탭을 정리한다 | 문제를 공개하고 시작 시각을 적는다 |
| 0–3분 | 문제를 읽고 "이 문제의 값"이 은행과 다른 곳을 표시한다 | 문구 질문을 받아 **모두에게 같은 내용으로** 공지한다 |
| 풀기 | XML → Kotlin → 저장·실행 → 확인할 것 → 캡처 → 설명. 오래 막히면 다음 문제로 | 순회. 구현 힌트는 주지 않는다 |
| 끝 5분 전 | 문제마다 코드·캡처·설명이 있는지 보고 제출한다 | "5분 남음"·"제출 시간" 공지, 제출 확인 |
| 끝 | 편집을 멈춘다 | 장애 기록지를 모아 연장 대상을 확정한다 |

## 제출

| 항목 | 내용 |
|---|---|
| 코드 | 고친 `activity_main.xml` 과 `MainActivity.kt`. Android Studio 에서 전체 선택 → 복사 → 답안 칸에 붙인다 |
| 캡처 | 문제가 요구한 상태의 에뮬레이터 화면(예: `3` 이 보이는 화면, 회전한 가로 화면, `Life` 로 필터한 Logcat) |
| 설명 | 문제의 설명 물음에 자기 말로 1~2문장 |
| 위치·마감 | 공지한 LMS 답안 칸. 공지한 시각까지 |

- 빌드가 되지 않으면 실행해서 볼 것이 없다. 안 되는 줄은 앞에 `//` 를 붙여 **실행되는 상태**로 캡처를 찍고, 원래 쓰려던 코드와 오류 메시지는 답안에 적는다. 시도와 설명은 부분 점수가 있다.
- 마지막으로 고친 뒤 **저장 → Run ▶ 다시 실행 → 확인할 것**을 한 번 더 한다. 다시 실행하지 않은 코드는 확인되지 않은 코드다.

## 장애가 나면

**먼저 손을 든다.** 감독이 장애 기록지에 시각·증상·조치를 적는다. 장애로 잃은 시간은 기록을 근거로 연장한다.
빨간 줄, 빌드 오류, 앱이 꺼지는 것처럼 **내 코드 때문에 생긴 문제는 장애가 아니다.**

| 상황 | 대체 절차 |
|---|---|
| 에뮬레이터가 켜지지 않거나 멈춘다 | Device Manager 에서 그 기기의 ⋮ › **Cold Boot Now**. 5분 안에 안 되면 예비 PC 로 자리를 옮긴다. 두 파일은 USB 나 LMS 임시 저장으로 옮긴다 |
| 코드를 고치기 전부터 Sync·빌드가 실패한다 | 새 Empty Views Activity 프로젝트를 만들어 이어 간다. 감독이 시각을 기록한다 |
| PC 가 멈추거나 꺼진다 | 다시 켜고 프로젝트를 연다. 평소에 자주 저장해 둔다. 되살리지 못한 부분은 기록하고 연장한다 |
| 에뮬레이터 장애로 캡처를 찍지 못한다 | 코드만 제출하고 기록지에 "캡처 불가(장애)"를 남긴다. 채점자가 코드로 확인한다 |
| LMS 에 올라가지 않는다 | 감독 USB 에 `학번_파일이름` 으로 복사하고 기록지에 시각을 적는다. 이 복사본을 제출본으로 인정한다 |
| 몸이 아프거나 급한 일이 생긴다 | 감독자에게 알린다. 처리는 대학 규정을 따른다 |

## 시작 전 점검(강의자·조교)

- [ ] 공지에 날짜·시각·문항 수·범위(어느 주차까지)·허용 자료·AI 허용 여부·제출 방법을 적었다.
- [ ] 실습실 PC 마다 Android Studio 와 에뮬레이터가 켜지고 `StudentCard` 가 실행된다. 안 되는 PC 는 좌석표에 표시했다.
- [ ] LMS 답안 칸에 코드 붙이기와 이미지 넣기가 된다. 안 되면 과제로 받는 대안을 준비했다.
- [ ] 시험 PC 의 Android Studio AI 도우미 상태가 공지와 맞다.
- [ ] 장애 기록지, 시작·종료 시각을 적을 칠판, "5분 남음" 공지 담당이 정해져 있다.
- [ ] 같은 공지·시간·장애 대체 절차를 모든 학생에게 적용한다.

## 공정성과 공개 범위

- 구현 답에 해당하는 개별 힌트는 주지 않는다. 문구·환경 설명은 모두에게 같은 수준으로 공지한다.
- 연장과 대체 제출은 장애 기록지에 적힌 것만 인정한다.
- 공개 저장소에는 시험 문제의 값·해답, 학생 코드·이름·학번·점수를 올리지 않는다.
- 빌드가 되지 않는 제출의 처리(시도 흔적이 있을 때의 부분 점수)는 [채점표](rubric.md#빌드가-되지-않는-제출)에 적었다.
