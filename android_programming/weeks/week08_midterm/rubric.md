# 중간 개인 실기 공개 채점표 — 20점

이 rubric은 공개 가능한 공통 역량 기준이다. 학기별 실제 문항·부분점수 매핑과 비공개 testcase는 별도 시험 패킷에서 관리한다.

| 영역 | 배점 | 충족 기준 |
|---|---:|---|
| Kotlin/XML UI·event | 4 | 지정 View가 의미 있게 배치되고 event가 정확한 대상과 상태 변경을 유발함 |
| lifecycle·ViewModel | 4 | 상태 소유권이 분명하고 회전/복귀 및 Fragment View 수명에서 안전함 |
| coroutine | 4 | UI를 blocking하지 않고 scope·취소·예상 오류를 요구에 맞게 처리함 |
| Flow·단방향 UI 상태 | 4 | 읽기 전용 StateFlow, 배타적 상태, `repeatOnLifecycle(STARTED)` 수집과 일관된 render |
| 경계·실패 처리 | 2 | 문항이 요구한 boundary/failure와 복구 경로를 재현함 |
| 검증·설명·제출 | 2 | 실행 가능한 제출본, normal/boundary/failure 증거와 선택 근거가 일치함 |
| 합계 | **20** | |

## 수준 판단

### 완전 충족

요구 동작을 독립적으로 재현할 수 있고 상태·수명·오류 경계가 일관된다. 제출 revision, 실행 결과와 설명이 일치한다.

### 부분 충족

실행 가능한 핵심 경로가 있으나 특정 회전, 연속 event, empty/오류 또는 복구 경로에서 실패한다. 코드 존재만이 아니라 실제 관찰 가능한 부분 결과가 있어야 한다.

### 미충족

지정 앱이 실행되지 않거나 요구와 무관하며, 채점 가능한 source/revision 또는 본인 설명 근거가 없다.

## 채점 원칙

- 같은 근본 원인으로 여러 증상이 생기면 중복 감점 여부와 근거를 기록한다.
- 각 영역 점수는 해당 배점을 넘지 않는다.
- UI 미세 취향과 기능/접근성 실패를 같은 수준으로 취급하지 않는다.
- 시스템/장비/제출 장애와 학생 구현 오류를 기록상 구분한다.
- 실제 문항의 hidden testcase나 정답을 학생 공개 피드백에 노출하지 않는다.
