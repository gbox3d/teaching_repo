# 중간고사 채점표 — 20점

본시험과 1일차 리허설 자기 채점에 같은 표를 쓴다. 채점은 **제출한 파일을 starter에 넣어 실행해 보고** 한다([제출본 기준](exam_structure.md#제출)).
코드 모양이 교재와 달라도 요구한 동작이 보이면 점수를 준다. StateFlow collect 항목만 코드를 읽어 확인한다.

## 항목과 배점

| 항목 | 배점 | 이렇게 확인한다 | 리허설 코드에서 볼 곳 |
|---|---:|---|---|
| UI·이벤트 | 5 | 버튼을 누르면 동작한다. 상태에 맞게 버튼이 켜지고 꺼진다. 글자가 문항 문구와 같다 | `MainActivity.kt` 리스너 34~41행, `collect` 안 `if/else` 49~55행, `"남은 초: $seconds"` 64행 |
| 생명주기·복원 | 5 | 진행 중에 **회전**해도 글자·숫자·버튼이 이어진다. 끝난 뒤 회전하거나 홈에서 돌아와도 그대로다 | `RehearsalViewModel` 13행, `by viewModels()` 20행 |
| 코루틴 delay·취소·오류 | 5 | 1초마다 줄고 기다리는 동안 화면이 멈추지 않는다. [취소] 뒤 더 줄지 않는다. 실패해도 앱이 꺼지지 않는다 | `viewModelScope.launch`·`delay` 30~40행, `job?.cancel()` 45행 |
| StateFlow collect | 3 | 값은 ViewModel의 `MutableStateFlow`에 넣고, 화면은 `repeatOnLifecycle` 틀 안의 `collect { }`에서 바꾼다 | `RehearsalViewModel.kt` 16~19행, `MainActivity.kt` 44~58·61~67행 |
| 실행·제출 | 2 | 제출 파일이 starter에서 빌드·실행된다. 지정한 파일과 캡처를 시간 안에 냈다 | — |
| 합계 | **20** | | |

## 항목별 세부 기준

### UI·이벤트 (5)

| 기준 | 점수 |
|---|---:|
| 시작 버튼을 누르면 진행이 시작된다 | 1 |
| [취소]를 누르면 취소 문구가 보인다 | 1 |
| 진행 중에는 시작 버튼이 꺼지고 [취소]가 켜진다 | 1 |
| 진행 중이 아닐 때는 시작 버튼이 켜지고 [취소]가 꺼진다(문항에 다른 단계가 있으면 그 규칙까지) | 1 |
| 상태 문구와 `남은 초: 3` 모양의 글자가 문항과 같다 | 1 |

### 생명주기·복원 (5)

| 기준 | 점수 |
|---|---:|
| 진행 중에 회전: 상태 글자가 그대로다 | 1 |
| 진행 중에 회전: 숫자가 처음부터가 아니라 이어서 줄어든다 | 1 |
| 진행 중에 회전: 버튼 켜짐·꺼짐이 그대로다 | 1 |
| 끝난 뒤(완료·취소) 회전해도 그 화면이 그대로다 | 1 |
| 홈으로 나갔다가 돌아와도 최신 상태가 보인다 | 1 |

### 코루틴 delay·취소·오류 (5)

| 기준 | 점수 |
|---|---:|
| 숫자가 1초 간격으로 줄고, 기다리는 동안 화면이 멈추지 않는다 | 2 |
| [취소] 뒤 숫자가 더 줄지 않고 완료 문구로 덮이지 않는다 | 2 |
| 오류: 실패하는 경우에도 앱이 꺼지지 않고 실패 문구가 보인다 | 1 |

리허설처럼 문항에 실패가 없으면 마지막 1점도 화면 동작으로 본다. "완료 뒤 다시 시작하면 처음 숫자부터 다시 세고 두 번째도 완료 문구로 끝난다"(리허설: `완료` 뒤 다시 [시작]하면 `남은 초: 5`부터 다시 세고 두 번째도 `완료`로 끝난다).

### StateFlow collect (3)

| 기준 | 점수 |
|---|---:|
| 상태와 남은 초를 ViewModel의 `MutableStateFlow`에 넣고, 화면은 읽기 전용 `StateFlow`만 쓴다 | 1 |
| 상태 글자와 버튼을 `repeatOnLifecycle` 틀 안의 `collect { }`에서 바꾼다 | 1 |
| 남은 초를 `collect { }`에서 바꾼다 | 1 |

리스너 안에서 `binding.…`을 직접 바꿔 같은 화면을 만들었다면 그 칸은 0점이다(동작 점수는 다른 항목에서 따로 준다).

### 실행·제출 (2)

| 기준 | 점수 |
|---|---:|
| 제출한 두 파일을 starter에 넣으면 빌드되고 실행된다 | 1 |
| 지정한 파일 이름과 캡처를 마감 안에 냈다 | 1 |

## 채점 원칙

- **한 원인은 한 번만** 뺀다. 예: `by viewModels()` 대신 ViewModel을 직접 만들어 회전하면 처음으로 돌아가는 경우, 생명주기·복원에서만 빼고 UI·이벤트의 버튼 규칙은 회전 전 동작으로 판단한다.
- 동작으로 판단한다. 코드가 길거나 짧은 것, 주석, 변수 이름은 점수와 관계없다.
- 실패가 절반 확률로 나는 문항은 채점자가 실패와 성공이 한 번씩 나올 때까지 반복해 본다.
- 장애 기록지에 적힌 장비·제출 문제와 학생 코드의 문제를 구분해 기록한다.
- 각 항목 점수는 그 항목 배점을 넘지 않는다.

## 채점 순서(채점자)

1. starter 원본을 복사하고 제출한 `MainActivity.kt`, `○○ViewModel.kt`로 바꾼다.
2. Run ▶. 빌드가 실패하면 첫 오류 줄을 기록하고 [빌드가 되지 않는 제출](#빌드가-되지-않는-제출)로 간다.
3. 앱 시작 화면 → 시작 → 끝까지 기다리기 → 다시 시작 → 중간에 [취소] → 몇 초 기다리기 → 다시 시작 → 중간에 회전 → 끝까지 → 끝난 뒤 회전 → 홈으로 나갔다 돌아오기 순서로 누른다. 실패가 있는 문항은 실패·성공이 한 번씩 나올 때까지 반복한다.
4. 두 코드 파일에서 `MutableStateFlow`와 `collect { }` 위치를 확인한다.
5. 아래 기록 양식을 채운다.
