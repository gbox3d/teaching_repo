# 내 방의 온습도와 호출 확인

14주차 · RoomControl

연결 화면에서 연결한다.
제어 화면에서 방의 상태를 확인한다.

책상 조명 → 실내 온습도 → 호출 이력

---

# 1일차 수업 흐름

설명·시연 30분 + 실습 60분

1. 연결과 조명 확인
2. 온습도 확인 버튼
3. 응답을 화면에 표시
4. 슬라이더 변경 후 다시 확인

---

# 1일차 · 0~5분: 연결 후 제어 화면

PC: WlEno 실행

WlEno와 같은 PC의 에뮬레이터: `10.0.2.2:8266`
다른 PC의 에뮬레이터·실기기: WlEno 실행 PC의 LAN IPv4 + `:8266`

연결 화면 코드는 그대로 사용한다.

---

# 1일차 · 5~10분: 방의 센서값 요청

[온습도 확인] → `dht11` → 응답 → 화면 표시

```kotlin
binding.sensorButton.setOnClickListener {
    send("dht11")
}
```

한 번 누르면 한 번 요청한다.

---

# 1일차 · 10~18분: 응답에서 두 값 읽기

```json
{"result":"ok","value":"[24.5,40.0]"}
```

`value`는 배열을 담은 문자열이다.

```kotlin
val values = JSONArray(WlenoMessage.value(line) ?: return)
val temperature = values.getDouble(0)
val humidity = values.getDouble(1)
```

---

# 1일차 · 18~25분: 단위와 표시 시점

온도: 24.5 °C / 습도: 40.0 %

시뮬레이터 슬라이더를 움직여도 앱 값은 그대로다.
[온습도 확인]을 다시 누르면 새 값이 보인다.

센서 숫자를 고정 문자열로 넣지 않는다.

---

# 1일차 · 25~30분: 실행 확인

| 조작 | 앱 결과 |
|---|---|
| 온습도 확인 | 현재 값 표시 |
| 슬라이더 변경 | 이전 값 유지 |
| 다시 확인 | 변경된 값 표시 |

실습: 버튼과 표시 자리 추가 → 수신 처리 → 전후 캡처

---

# 2일차 · 0~8분: 호출은 시뮬레이터에서 시작

WlEno의 [입력 버튼]을 방의 호출 버튼으로 사용한다.

```json
{"event":"input","index":0,"value":1}
```

앱의 요청 없이 이벤트가 도착한다.
다시 누르면 `value`가 0으로 바뀐다.

---

# 2일차 · 8~16분: 입력과 응답 구분

```kotlin
if (WlenoMessage.event(line) == "input") {
    showInput(line)
    return@onMessage
}
```

입력 이벤트를 먼저 분류한다.
온습도 응답을 호출 이력에 넣지 않는다.

---

# 2일차 · 16~23분: 호출 이력 표시

입력 번호 0 · 값 1
입력 번호 0 · 값 0

입력 한 번에 한 줄을 추가한다.
이 제어 화면의 최근 20건만 표시한다.
새 제어 화면에서는 새 이력으로 시작한다.

---

# 2일차 · 23~30분: 연결이 끊겼을 때

시뮬레이터 [연결 끊기] → 제어 버튼 비활성

[연결 화면] → 다시 연결 → 제어 재개

배경 전환·회전에서도 연결을 닫는다.
연결되지 않은 동안의 호출은 나중에 재생되지 않는다.

---

# 실습 제출

- 온습도 전후 화면
- 호출 이력 두 줄
- `ControlActivity.kt`와 `activity_control.xml`
- 버튼 요청과 외부 입력의 차이 한 문장

통신 라이브러리와 연결 화면을 새로 구현하지 않는다.
