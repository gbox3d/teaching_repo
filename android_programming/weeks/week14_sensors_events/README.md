# 14주차: 내 방의 온습도와 호출 확인

`RoomControl` 앱에서 방의 상태를 확인한다. 연결 화면에서 WlEno에 연결한 뒤 제어 화면에서 책상 조명을 조작하고, 실내 온습도를 읽으며, 시뮬레이터의 호출 버튼 입력을 확인한다.

## 학습 목표

- [온습도 확인] 버튼을 누르면 시뮬레이터의 온도와 습도를 화면에 표시한다.
- 슬라이더를 바꾼 뒤 다시 확인하여 값이 갱신되는 시점을 관찰한다.
- 시뮬레이터의 [입력 버튼]을 누르면 앱의 호출 이력에 한 줄을 추가한다.
- 연결이 끊기면 제어를 중지하고 연결 화면에서 다시 연결한다.

## 준비와 시작점

13주차 [완성 예제](../week13_room_control_project/examples/day1/) 또는 이 주차 [예제](examples/README.md)를 사용한다. 프로젝트 이름은 `RoomControl`, package는 `com.example.roomcontrol`이다. 공통 연결 코드는 [WlEno 안내](../../../tools/wleno/android/README.md)대로 한 번만 넣는다.

PC에서 `tools/wleno`로 이동하여 `uv run main`을 실행한다. WlEno와 같은 PC의 에뮬레이터는 `10.0.2.2:8266`, 다른 PC의 에뮬레이터와 실기기는 `WlEno 실행 PC의 LAN IPv4:8266`을 입력한다. [주소와 방화벽 조건](../../iot_sim/lab.md#2-앱에-넣을-주소-결정)을 확인한다.

## 2일 수업 흐름

| 일차 | 설명·시연 30분 | 실습 60분 | 결과물 |
|---|---|---|---|
| 1일차 | 연결 화면 → 제어 화면, 온습도 요청과 표시 | 버튼 연결, 값 표시, 시뮬레이터 값 변경 후 재확인 | 온습도 전후 화면 |
| 2일차 | 앱의 요청과 외부 입력의 차이, 호출 이력 | 입력 이벤트 표시, 연결 해제 후 다시 연결 | 호출 이력과 재연결 화면 |

소켓·스레드·UDP 검색 구현은 제공 코드다. 수업에서는 제어 버튼과 수신 결과를 화면에 연결하는 데 집중한다. 센서 반복 읽기는 이번 주 필수 과제에 넣지 않는다.

## 완료 기준

- [ ] 제어 화면에서 책상 조명을 켜고 끌 수 있다.
- [ ] [온습도 확인]을 누르면 시뮬레이터 값과 같은 온도·습도가 나온다.
- [ ] 슬라이더 변경만으로 앱 값은 바뀌지 않으며, 버튼을 다시 눌러 갱신한다.
- [ ] [입력 버튼]을 두 번 누르면 호출 이력이 두 줄 생긴다.
- [ ] 연결이 끊긴 동안 제어 버튼이 꺼지고, 다시 연결한 뒤 동작한다.
