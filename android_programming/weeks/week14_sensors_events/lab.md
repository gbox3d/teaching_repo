| 시간 | 할 일 | 확인 |
|---|---|---|
| 0~10분 | WlEno 시작, 앱 연결, 책상 조명 확인 | 제어 화면과 LED 0 |
| 10~25분 | 온습도 버튼과 표시 자리 추가 | 버튼을 눌러 `dht11` 전송 |

| 50~60분 | 관찰표 기록, 캡처 정리 | 아래 제출물 |

| 순서 | WlEno 온도·습도 | 앱 온도·습도 |
|---|---|---|

## 2일차 실습 60분

| 시간 | 할 일 | 확인 |
|---|---|---|
| 0~10분 | 1일차 앱 실행, 연결 | 온습도 읽기 |
| 10~25분 | 호출 이력 TextView와 목록 추가 | 초기 글자 |
| 25~40분 | 입력 이벤트 분기와 이력 추가 | 입력 두 번, 두 줄 |
| 40~50분 | 연결 끊기, 다시 연결 | 끊김 동안 제어 중단 |
| 50~60분 | 요청과 입력 비교, 제출 | 코드와 캡처 |

앱의 [온습도 확인]을 누를 때와 시뮬레이터 [입력 버튼]을 누를 때 수신하는 줄을 비교한다. `result`와 `event` 중 어느 키로 구분했는지 적는다.

## 문제 해결

| 증상 | 확인 |
|---|---|
| 연결 화면에 계속 머문다 | 시뮬레이터 실행 여부, IP와 TCP 8266 확인 |
| 온습도 버튼을 눌러도 값이 없다 | `dht11` 철자, `onMessage`의 `showSensor` 호출 확인 |
| 응답 형식 안내가 나온다 | `value`를 먼저 문자열로 꺼낸 뒤 `JSONArray`로 읽는지 확인 |
| 호출이 일반 응답으로 표시된다 | `event == "input"` 분기를 명령 응답보다 먼저 배치 |
| `pin`을 읽다가 오류가 난다 | 입력 키를 `index`로 수정 |
| 앱에 없는 동안의 호출이 보이지 않는다 | 연결이 닫혀 수신하지 않은 이벤트다. 다시 연결한 뒤 새로 누른다 |

## 제출

1. `ControlActivity.kt`, `activity_control.xml`.
2. WlEno 값과 앱 온습도를 함께 볼 수 있는 캡처.
3. 호출 이력 두 줄이 보이는 캡처.
4. 버튼 요청과 호출 이벤트의 차이를 설명한 한 문장.

## 먼저 끝났다면

호출 값 1과 0을 서로 다른 안내 글자로 표시한다. 숫자 0이 연결 오류를 뜻하지 않음을 설명한다. 이번 실습에서는 반복 요청이나 데이터베이스를 추가하지 않는다.
