# 14주차 따라하기: 실내 상태 표시

## 1일차: 온습도 확인

### 1. 연결과 책상 조명 확인

1. `tools/wleno`에서 `uv run main`을 실행한다.
2. Android Studio에서 `RoomControl`을 실행한다.
3. [실행 위치에 맞는 주소](../../iot_sim/lab.md#2-앱에-넣을-주소-결정)를 입력하고 [제어 시작]을 누른다. WlEno와 같은 PC의 에뮬레이터 주소는 `10.0.2.2:8266`이다.
4. 제어 화면이 열리면 책상 조명을 켰다가 끈다. WlEno의 LED 0이 앱의 책상 조명에 해당한다.

연결되지 않으면 새 기능을 붙이기 전에 [11주차 연결 실습](../week11_lan_connection/lab.md)을 확인한다. 이번 주에도 연결 화면 코드는 그대로 사용한다.

### 2. 온습도 표시 자리 추가

`activity_control.xml`에 버튼 `sensorButton`과 TextView `sensorText`를 넣는다. 버튼은 `온습도 확인`, 초기 글자는 `실내 온습도: 확인 전`으로 둔다. 배치는 [day1 완성 화면](examples/day1/activity_control.xml)과 대조한다.

화면에 제목과 버튼이 보이는지 먼저 실행해 확인한다. 온도·습도 값은 버튼을 누른 뒤 채운다.

### 3. 버튼을 명령에 연결

`ControlActivity.onCreate`에서 `sensorButton`의 클릭 리스너를 등록한다. 리스너는 기존 `send("dht11")`를 호출한다. 공통 클라이언트가 명령 끝에 줄바꿈을 붙이므로 직접 넣지 않는다.

연결 상태를 화면에 반영하는 기존 collect 블록에 `sensorButton.isEnabled = ready`를 넣는다. 연결이 끊기면 온습도 요청 버튼도 꺼져야 한다.

### 4. 수신한 온습도 표시

시뮬레이터의 응답은 다음 형태다. 숫자는 화면 슬라이더 설정에 따라 달라진다.

```json
{"result":"ok","value":"[24.5,40.0]"}
```

`value`는 JSON 배열을 담은 문자열이다. `WlenoMessage.value(line)`로 문자열을 꺼내고, `JSONArray`로 읽어 0번을 온도, 1번을 습도로 사용한다. [day1 ControlActivity](examples/day1/ControlActivity.kt)의 `showSensor` 함수를 붙이고 `onMessage`에서 성공 응답에 `value`가 있을 때 호출한다.

응답 처리는 기존 오류 처리 안에 둔다. 배열 길이가 2가 아니거나 숫자를 읽을 수 없으면 앱을 종료하지 않고 안내를 표시한다. 코드를 외우기보다 버튼 → 요청 → 값 표시 순서를 설명한다.

### 5. 값이 바뀌는 시점 관찰

[온습도 확인]을 눌러 값을 기록한다. WlEno의 온도·습도 슬라이더를 움직인 뒤 앱을 본다. 앱 값은 아직 이전 값이다. 버튼을 다시 누르면 변경한 값이 나타난다. 이는 1회 요청 방식이기 때문이다.

## 2일차: 호출 이력

### 6. 호출 버튼을 방의 입력으로 정하기

WlEno의 [입력 버튼]을 방에서 누르는 호출 버튼으로 사용한다. 앱에서 먼저 명령을 보내지 않아도 연결된 앱으로 입력 이벤트가 전송된다.

```json
{"event":"input","index":0,"value":1}
```

다시 누르면 `value`가 0으로 바뀐다. 다음 입력은 다시 1이다. 입력 번호 키는 `index`이며, 시뮬레이터에서 입력 번호는 0이다.

### 7. 호출 이력 자리와 수신 처리 추가

`activity_control.xml`에 `inputText`를 추가한다. `ControlActivity`에 `inputHistory` 목록과 `showInput` 함수를 넣는다. 완성 내용은 [day2 코드](examples/day2/ControlActivity.kt)에 있다.

`onMessage`에서 `event`가 `input`인지 먼저 검사한다. 호출 이벤트이면 이력에 추가하고 이 콜백 처리를 끝낸다. 일반 명령 응답 처리는 뒤에 둔다. 입력 이벤트에는 `result`가 없으므로 명령 성공 여부로 분류하면 호출을 놓친다.

### 8. 호출 두 번과 온습도 요청 비교

시뮬레이터 [입력 버튼]을 두 번 누른다. 호출 이력이 두 줄 생기고 값은 1과 0으로 번갈아 나온다. 이어서 앱의 [온습도 확인]을 누른다. 온습도는 갱신되지만 호출 이력은 늘어나지 않는다.

이력은 이 제어 화면에서 받은 최근 20건만 보관한다. 다른 화면으로 나가거나 화면을 회전하여 새 제어 화면을 열면 이력은 새로 시작한다. 파일 저장은 이번 주 범위에 넣지 않는다.

### 9. 연결 중단과 복귀

시뮬레이터의 [연결 끊기]를 누른다. 앱의 제어 버튼이 꺼지는지 확인한다. [연결 화면]으로 돌아가 같은 주소로 연결한 뒤 온습도와 호출을 다시 확인한다.

앱을 배경으로 보내거나 회전하면 제어 화면의 `onStop`에서 연결을 닫는다. 복귀 후에는 연결 화면에서 다시 연결한다. 연결되지 않은 동안 발생한 호출은 나중에 재생되지 않는다.
