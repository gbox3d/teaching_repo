# 14주차 2차 과제 채점표 — 발표 12 + 레포트 8 = 20점

필수 기능과 제출 방법은 [과제 안내](project_brief.md)에 있다. 이 채점표는 발표 전에 공개하며, 평가자는 아래 기록 양식에 근거를 적는다.
팀 운영 여부와 팀원 점수 적용은 수업 공지를 따른다. 팀이어도 **코드 설명은 한 사람씩** 하고 학생별로 기록한다.

## 배점 검산

| 구분 | 배점 |
|---|---|

| 레포트 | 8 |
| **합계** | **20** |

## 발표 — 12점

| 항목 | 배점 | 만점 | 부분 점수 | 0점 |
|---|---|---|---|---|
| 연결 흐름 | 3 | 권한 안내(`권한 OK` 또는 AlertDialog) → 검색 목록 `ESP32_BLE…` → 줄 탭 → `연결 중`·`서비스 확인 중`·`준비됨` 상태 표시 → [해제]로 `연결 안 됨`까지 막힘 없이 동작한다 | 2: 한 부분이 빠진다(권한 안내를 보이지 못함, [해제] 없음, 중간 상태가 보이지 않음 등) / 1: `준비됨`까지는 가지만 두 부분 이상 빠진다 | `준비됨`까지 가지 못한다 |
| 출력 제어와 명령 규약 | 2 | 제어 화면에서 출력을 하나 이상 규약대로(`on 3`, `off -1` 등) 보내고 응답 `{"result":"ok",…}`이 로그에 보인다(실보드면 LED가 바뀐다) | 1: 명령은 나가지만 응답이 보이지 않는다 / 규약과 다른 명령으로 `fail`이 난다 / 허용되지 않는 번호를 막지 않는다 | 출력 제어가 없거나 명령이 나가지 않는다 |
| 입력 수신과 입력 이력 | 2 | [온습도 받기 시작] → 입력 이력에 시각이 붙은 `[온도,습도]` 줄이 3줄 이상 쌓이고 [중지]로 멈춘다(Fake는 입력 이벤트 3줄도 인정) | 1: 1~2줄만 보인다 / 시각이 없다 / [중지]로 멈추지 않는다 / 입력 이벤트가 숫자 한 줄로 들어간다 | 입력이 화면에 보이지 않는다 |
| 끊김·재연결·시간 제한 | 2 | 끊김(실보드 전원 끄기 또는 [끊김 시험]) → 안내 Toast와 [재연결] → `준비됨`을 시연하고, 연결 시간 초과 안내를 시연이나 레포트 캡처로 보인다 | 1: 끊김 안내·[재연결]과 시간 초과 안내 중 하나만 된다 / [재연결]이 `준비됨`까지 가지 못한다 | 끊겨도 안내와 재시도가 없다 |
| 코드 설명(개인 구술) | 3 | 질문을 받고 해당 파일과 줄을 스스로 찾아 가리키며, 그 줄이 하는 일을 맞게 한 문장으로 말한다 | 2: 줄은 찾지만 설명이 틀리거나 빠진다 / 1: 평가자가 파일을 알려 준 뒤에야 줄을 찾는다 | 줄을 찾지 못하고 설명하지 못한다 |
| 소계 | **12** | | | |

- 시연은 3분에서 멈춘다. 3분 안에 보이지 않은 장면은 레포트 캡처로 판단하되 **해당 항목 최대 절반**까지만 준다(조교 장애 기록이 있으면 만점까지).
- 연결 시간 초과는 가짜 보드에서 저절로 나오지 않으므로 레포트 캡처로 보여도 절반 제한을 두지 않는다.
- Fake와 실보드는 같은 기준으로 본다. 실보드 시연을 필수로 할지는 수업 공지를 따른다.
- 질문은 평가자가 시연에서 보인 장면 중에서 고른다. 예: [중지]로 반복이 멈추는 까닭 / 입력 이벤트와 온습도 응답을 가르는 순서 / 이력 한 줄에서 시각을 꺼내는 줄 / [재연결]이 보이게 되는 줄 / 10초가 넘으면 알리는 줄 / Toast를 collect 안에 바로 쓰지 않은 까닭.
- 화면만 보여 주고 질문에 줄을 가리키지 못하면 코드 설명 항목을 충족한 것으로 보지 않는다.

## 레포트 — 8점

| 항목 | 배점 | 만점 | 부분 점수 | 0점 |
|---|---|---|---|---|
| 실행 방법과 시연 절차 | 2 | Fake/실보드 여부와 `useFake` 값, 누르는 것 → 보이는 것 순서의 2~3분 시연 절차, 고친 파일 목록이 있고, 절차대로 누르면 같은 화면이 나온다 | 1: 셋 중 하나가 빠지거나 절차가 실제 앱과 다르다 | 없다 |
| 필수 기능 캡처와 코드 위치 | 3 | 일곱 칸(권한 안내·장치 목록·준비됨·출력 제어·입력 수신·끊김+[재연결]·시간 초과)의 캡처가 모두 있고, 칸마다 코드 파일과 줄 번호가 제출 소스와 맞다 | 2: 한두 칸의 캡처가 빠지거나 코드 위치가 틀리다 / 1: 세 칸 이상 빠지거나, 캡처는 있지만 코드 위치가 하나도 없다 | 캡처가 없다 |
| Logcat 근거 | 1 | `tag:BLE` 캡처 한 묶음과, 앱이 보낸 줄과 보드가 보낸 줄을 맞게 구분한 설명이 있다 | 0.5: 캡처만 있고 구분 설명이 없거나 틀리다 | 없다 |
| 오류 해결 기록 | 1 | 오류 메시지 원문(또는 증상과 Logcat 줄), 원인, 고친 방법이 한 건 이상 맞게 적혀 있다 | 0.5: 셋 중 하나가 빠진다 | 없다 |
| 확인 환경과 알려진 한계 | 1 | 확인한 기기·방법(Fake/실보드), 알고 있는 한계, 장애가 있었다면 그 기록이 사실대로 있다 | 0.5: 환경만 있고 한계가 없다 | 없다 |
| 소계 | **8** | | | |

## 공통 판단

- 같은 원인으로 여러 항목이 깎이면 가장 가까운 항목 하나에서만 뺀다. 예: 입력 이력 어댑터를 붙이지 않아 제어 화면에서 앱이 멈추면 입력 수신에서만 빼고, 출력 제어는 멈추기 전 화면으로 본다.
- 장비 장애(조교 기록이 있는 것)와 내 코드 때문에 생긴 문제를 나눈다. 판단 절차는 [과제 안내의 실물 장비가 안 될 때](project_brief.md#실물-장비가-안-될-때--앱과-장비-나누기)를 따른다. Fake에서 필수 기능이 되면 장비 장애로 보고, 실보드로 못 보인 장면은 Fake 시연으로 만점까지 인정한다.
- (시험용) [끊김 시험] 버튼과 `as FakeBleunoClient` 줄은 채점하지 않는다. 넣지 않은 경우 Fake 끊김은 레포트의 실보드 캡처나 코드 설명으로 본다.
- 본인이 더한 기능(선택)은 점수에 더하거나 빼지 않는다.
- 제출 소스로 빌드되지 않으면 발표 때 보인 화면과 제출물이 같은지 확인할 수 없다. 이때 처리(재제출 허용 여부)는 수업 공지를 따른다.
- 공개 저장소에는 학생 이름·학번·점수·제출물을 올리지 않는다.

## 0점 또는 인정하지 않는 증거

- 펌웨어를 고치거나 올린 결과를 Android 앱 구현 대신 낸 것
- 다른 학생(팀)의 시연 영상·캡처·Logcat을 자기 것으로 낸 것
- 실보드로 하지 않은 장면을 실보드 캡처라고 적은 것(Fake 캡처는 Fake라고 적으면 인정한다)
- 소스·실행 방법이 없어 무엇을 만들었는지 확인할 수 없는 것

표절·부정행위·지각 제출의 처리는 이 채점표가 아니라 대학 규정과 수업 공지를 따른다.
