> **COURSE_POLICY_TBD:** 개인/2인 팀 제출 단위와 공유·차등 점수 적용 방식은 공식 수업 공지로 확정한다. 아래 개인 구술 증거는 어느 정책에서도 학생별로 기록한다.

## 발표 — 12점

| 항목 | 배점 | 충족 증거 |
|---|---:|---|
| 핵심 연결 시나리오 | 3 | 버전 인식 권한, 제한 시간 scan, Connecting/Discovering, 필수 계약 뒤 Ready를 재현한다. |
| 출력·입력 통합 | 3 | Ready에서 출력 제어와 입력 notification/currentness를 같은 앱에서 재현하고 확인 가능 범위를 정확히 말한다. |
| 실패·복구 | 2 | disconnect 또는 timeout을 주입하고 출력 금지·입력 stale·사용자 복구·새 상태 확인까지 보인다. |
| 상태·구조 설명 | 2 | `UI → ViewModel/use case → BLE abstraction → transport`와 전체 상태 기계를 코드·로그에 연결해 설명한다. |
| 개인 구술 증거 | 2 | 각 학생이 지정 상태 예측, 코드 흐름, 장애 원인·복구 질문에 직접 답한다. |
| **발표 소계** | **12** |  |

### 발표 부분점수 원칙

- 실물 장비가 강의자 확인 하에 고장난 경우, fake 재현과 앱 진단 증거로 해당 앱 역량을 확인하되 물리 관찰을 꾸며 쓰지 않는다.
- 화면만 보여주고 상태·로그·복구 설명이 없으면 해당 설명 항목을 충족한 것으로 보지 않는다.
- 팀이 허용되더라도 개인 구술 2점은 학생별 증거를 기록한다. 최종 점수 반영 방식은 `COURSE_POLICY_TBD`다.

## 0점 또는 미충족 증거 예

- firmware 코딩·빌드·플래싱 결과를 Android 구현 대신 제출
- 임의 UUID·GPIO·payload를 실제 계약이라고 주장
- 다른 학생/팀의 시연이나 로그를 본인 증거로 제출
- 실행 가능한 최소 안내, source, 식별 가능한 제출 근거가 없음

학사 정책상 표절·부정행위·지각 제출 처리는 이 기술 루브릭이 아니라 공식 강의/LMS 공지를 따른다.
