# 기말고사: 혼자 60분 구현, 보드 앞에서 시연

2~14주에 만든 **Smart I/O Controller**의 세 기능을 혼자 다시 씁니다.
새 문법은 없습니다. 1일차는 **공개 리허설**, 2일차는 **본시험**입니다.

```text
권한 확인  [권한 확인] → 요청 창 → 권한 OK / 권한이 필요합니다 창
LED 토글   on 3 → 응답: {"result":"ok","ms":"led(s) on"}
시간 제한  10초 뒤에도 연결 중 → 연결 시간이 초과되었습니다
```

구현 15점은 Fake로 실행해 채점하고, 시연 5점은 **실보드 앞에서** 봅니다.

---

# 1일차 — 범위·채점표·starter와 공개 리허설

`30분 설명 → 60분 리허설`

1. 기말 범위(2~14주)와 두 날
2. 채점표 20점: 구현 15 + 시연 5
3. starter 구조: 화면 / 제공 `bleuno/` / 상수
4. 리허설 세 기능과 TODO 아홉 곳

---

## 1일차 · 0–5분 — 이번 주 두 날과 기말 범위

| 날 | 30분 | 60분 |
|---|---|---|
| 1일차 | 범위·채점표·starter | **공개 리허설** (점수 없음) |
| 2일차 | 절차·보드 배부·시연 순서 | **본시험** 구현 + 개인 시연·구술 (20점) |

- 범위는 **2~14주**입니다. 화면·이벤트 / 회전 / 코루틴 / StateFlow / 권한·저장 / BLE 명령·응답
- 본시험은 오늘 리허설과 **같은 모양**입니다. 문구·숫자·세부 요구만 다릅니다.
- 세 기능: ① 권한 확인 흐름 ② LED 번호 토글과 응답 표시 ③ 연결 시간 제한 안내
- 기말 20% = 구현 15 + 시연 5. 주차별 실습 점수 대상은 아닙니다.

---

## 1일차 · 5–12분 ① — 구현 15점: Fake로 실행해 채점

| 항목 | 점수 | 이렇게 확인합니다 |
|---|---:|---|
| UI·이벤트 | 3 | 빈 칸 Toast, 보낸 직후 0.3초 막기, 문구가 문항과 같음 |
| 상태 보존·StateFlow | 3 | 상태 글자·버튼, 회전해도 그대로, 연결 중 회전 뒤 시간 제한 |
| 코루틴 timeout·취소·오류 | 3 | 시간 초과 안내·끊기, 준비됨이면 조용히, `Job` 보관·취소 |
| 권한·SharedPreferences | 3 | 권한 OK·요청 창, 거절 창·설정 화면, 마지막 장치 |
| `send`·`onMessage`·재연결 | 3 | `on 3` 전송, 응답 줄·오류 표시, 허용 번호·[재연결] |

채점자는 **제출한 두 파일**을 starter에 넣고 `useFake = true`로 실행합니다.
starter에 이미 있던 기능(S1·S2·P3)도 제출본에서 **그대로 동작해야** 점수가 됩니다. starter를 그대로 내면 이 셋만 받습니다.
세부 기준: [rubric.md](rubric.md)

---

## 1일차 · 5–12분 ② — 시연 5점과 기본점수 5점

| 시연 | 점수 | 보드 앞에서 |
|---|---:|---|
| 출력 제어 | 2 | 명령으로 LED 켜기·끄기, 로그의 응답 줄 보여 주기 |
| 입력 수신 | 2 | `dht11` 입력 이력 2줄, [중지]로 멈추기 |
| 구술 | 1 | "이 콜백은 언제 불리나" 한 문항 |

- **기본점수**: 구현 점수가 5점보다 낮아도 TODO 자리에 **구현 시도 흔적**이 있으면 구현 5점입니다.
- 빌드가 안 되는 제출도 같습니다. TODO 주석만 남긴 것은 흔적이 아닙니다.
- 그래도 **빌드되는 제출**이 점수를 더 받습니다. 모르는 곳은 비워 둔 채 빌드되게 둡니다.

## 1일차 · 12–18분 — starter 구조: 화면 / 제공 bleuno / 상수

```text
com.example.smartio
├─ MainActivity.kt      화면: 연결  (TODO(1) 권한 · TODO(3) 시간 제한)
├─ ControlActivity.kt   화면: 제어  (TODO(2) LED 토글 · 응답)
├─ ContactsReader.kt    제공 (11주)
└─ bleuno/              제공 8개: Bleuno · BleunoClient · BleunoMessage · ConnState …
res/layout   activity_main.xml · activity_control.xml     (고치지 않음)
res/values   strings.xml · colors.xml(log_ok · log_error)  상수
```

- 14주 최종 앱에서 **아홉 곳의 본문만** 비웠습니다. 검색·연결·끊김·[재연결]·온습도·마지막 장치는 완성되어 있습니다.
- 상수: `ConnState` 다섯 상태, `strings.xml`, `colors.xml`. 새 id·새 파일은 없습니다.

## 1일차 · 18–25분 ① — 리허설 세 기능과 TODO 아홉 곳

| TODO | 파일 · 자리(주석 번호) | 할 일 |
|---|---|---|
| (1) 네 곳 | `MainActivity` 13번 `hasBlePermissions()` · 14번 `showPermissionDialog()` · `permissionLauncher` 결과 · 12번 [권한 확인] | `for`로 권한 확인, 거절 창, 결과 받기, 요청 |
| (2) 세 곳 | `ControlActivity` 12번 `isAllowedIndex()` · 2번 LED Switch · 8번 응답 가지 | 허용 번호, `send`, 응답 로그·오류 표시 |
| (3) 두 곳 | `MainActivity` 50번 `startConnectTimeout()` · 51번 `waitConnectTimeout()` | `Job` 보관, 10초 뒤 안내·끊기 |

채우는 순서: **불리는 함수 → 부르는 곳.** 한 곳 채울 때마다 빌드됩니다.
힌트는 starter 안에 있습니다: 40번 `showLocationDialog()`, 7번 [전체 끄기], 52번 `listOf(…).contains(…)`.

## 1일차 · 18–25분 ② — starter에서 지키는 세 가지

1. **회색 import를 지우지 않습니다.** `Uri`·`delay`(연결 화면), `AlertDialog`·`ContextCompat`(제어 화면)는 TODO를 채우면 씁니다.
2. **`return true` / `return false` 줄을 남깁니다.** TODO 주석만 지우고 그 **위에** 씁니다.
3. **시간 초과는 숫자를 잠시 줄여 봅니다.** Fake는 2초 만에 `준비됨`이라 10초 안내가 안 뜨는 게 정상입니다.

```text
MainActivity.kt:478:9 Unresolved reference 'delay'.     ← 1을 어기면
MainActivity.kt:398:5 Missing return statement.         ← 2를 어기면
```

`delay(10000)` → `delay(1000)`으로 확인하고 **꼭 되돌립니다.**

# 2일차 — 시험 안내·보드 배부와 본시험

`30분 안내 → 60분 본시험(구현 + 시연)`

1. 리허설에서 자주 막힌 곳
2. 시험 순서, 허용 자료, 장애가 나면
3. 보드 배부와 실기기 점검, 시연 순서와 구술

---

## 2일차 · 0–5분 — 리허설에서 자주 막힌 곳

| 증상 | 원인 |
|---|---|
| `Missing return statement.` | TODO 주석과 함께 `return true` 줄까지 지웠다 |
| `Unresolved reference 'delay'.` | 회색 import가 자동 정리로 지워졌다 → Alt+Enter |
| `Suspend function 'suspend fun waitConnectTimeout(): Unit' should be called only from a coroutine or another suspend function.` | `lifecycleScope.launch { }` 없이 불렀다 |
| 빈 칸에서 Switch를 누르면 앱이 멈춘다 | `toInt()`를 빈 칸 검사보다 먼저 했다 |
| 빨간 `응답: {"result":"fail","ms":"unknown command"}` | `"on$index"` — 띄어쓰기가 빠졌다 |

빌드는 되는데 틀린 것은 **눌러 봐야** 보입니다. 그래서 점검표가 있습니다.

---

## 2일차 · 5–10분 — 시험 순서와 제출본 기준

```text
0–5분    starter 열기 → Sync → Run ▶ (에뮬레이터, Fake) → 문항지·TODO 읽기
5–20분   기능 1          20–35분  기능 2          35–45분  기능 3
45–52분  점검표 (시간 초과는 숫자를 잠시 줄여 보고 되돌리기)
52–55분  저장 → 다시 실행
55–60분  제출: MainActivity.kt, ControlActivity.kt
```

- 채점자는 **제출한 두 파일**을 배포 starter에 넣어 실행합니다. XML·`strings.xml`은 고치지 않습니다.
- 시연 차례(5–55분)가 오면 손을 멈추고 시연합니다. 3분은 모두 똑같이 쓰므로 마감은 모두 60분입니다(장애로 넘긴 몫만 연장).
- 문구가 이해되지 않으면 손을 듭니다. 답은 **모두에게 같은 공지**로 합니다.

## 2일차 · 10–15분 ① — 허용 자료와 금지 행동

| 허용 | 금지 |
|---|---|
| 이 과목 공개 교재(2~15주, examples·리허설 완성본 포함) | 생성형 AI (브라우저·Android Studio 모두) |
| 내가 만든 `SmartIO` 프로젝트 열어 보기 | 메신저·메일·클라우드로 코드 주고받기 |
| Android Developers·Kotlin 공식 문서 | 다른 사람과 대화, 휴대폰(시연 기기는 시연 때만) |
| 자동 완성, Alt+Enter, Logcat | 검색 사이트·블로그·질문 사이트 |

시험 공지가 이 표와 다르면 **공지가 우선**합니다.

## 2일차 · 10–15분 ② — 장애가 나면

| 상황 | 이렇게 |
|---|---|
| 에뮬레이터·PC가 멈춤 | 손 들기 → Cold Boot 또는 예비 PC, 시각 기록 |
| 고치기 전부터 Sync·빌드 실패 | 손 들기 → starter 다시 받기 |
| 보드가 파랑 깜빡임이 아님·검색 안 됨 | 손 들기 → 강의자 확인 뒤 보드 교환 또는 Fake 시연 |
| LMS에 올라가지 않음 | 손 들기 → 조교 USB에 복사, 시각 기록 |

- 조교가 **시각·증상·조치**를 적고, 잃은 시간은 기록을 근거로 연장합니다.
- 빨간 줄·빌드 오류·앱이 멈추는 것처럼 **내 코드 때문**인 것은 장애가 아닙니다.
- 펌웨어는 고치지도, 다시 올리지도 않습니다.

---

## 2일차 · 15–22분 — 보드 배부와 실기기 점검

1. 좌석표대로 보드와 (필요하면) 대여 기기를 받습니다. 보드에 붙은 `ESP32_BLE…` 이름을 적어 둡니다.
2. 1일차 `SmartIO`에서 `useFake = false`로 바꾸고 **실기기**에 Run ▶ → [권한 확인] → 허용.
   리허설 TODO(1)·(2)를 못 끝냈으면 먼저 두 파일을 `rehearsal_solution`으로 바꿉니다.
3. [검색] → **내 보드 이름** 줄 탭 → `준비됨` → [제어 화면] → `0` + Switch → LED 0 켜짐.
4. [온습도 받기 시작] → 입력 이력 2줄 → [중지]. 이 앱은 기기에 **그대로 둡니다**(시연용).
5. `useFake = true`로 되돌리고 Run 대상을 에뮬레이터로 돌립니다.

```text
☐ 기기 인식   ☐ 권한 OK   ☐ 내 보드 준비됨   ☐ LED 켜짐   ☐ 이력 2줄
```

안 되는 자리는 **시험 전에** 보드·기기를 바꿉니다.
22분까지 못 끝낸 자리는 본시험 0–5분에 조교와 이어서 하고, 시연은 맨 뒤 차례입니다.

---

## 2일차 · 22–27분 — 시연 순서와 구술 한 문항

`T_demo = ceil(N / E) × D ≤ 50분` (N 인원, E 평가자 수, D 한 사람 시연 분)
시연 구간은 본시험 5–55분입니다. 예: D = 3분, E = 2명이면 N ≤ 32명. 넘으면 평가자를 늘립니다.
시연 D분은 모두 똑같이 한 번 쓰므로 제출 마감은 모두 60분입니다. 장애로 D분을 넘긴 몫만 60분 뒤 이어서 합니다.

| 순서 | 할 일 (D = 3분) |
|---|---|
| ① 30초 | 시연 기기 앱 → [검색] → 내 보드 → `준비됨` → [제어 화면] |
| ② 1분 | 출력 제어: LED 켜기·끄기, 로그의 응답 줄 가리키기 |
| ③ 1분 | 입력 수신: [온습도 받기 시작] → 2줄 → [중지] |
| ④ 30초 | 구술: 평가자가 가리킨 콜백이 **언제 불리는지** 한 문장 |

좌석표 순서대로 평가자가 자리로 갑니다. 순서는 칠판과 LMS에 공지합니다.

---

## 2일차 · 27–30분 — 본시험 시작

[2일차 실습](lab.md#2일차--본시험-60분) · [따라하기](walkthrough.md#2일차)

1. 휴대폰은 가방에(시연 기기는 앱 화면만 켜 둠), 브라우저에는 허용 자료 탭만 남깁니다.
2. 문항지와 starter를 받으면 시각을 봅니다. 0–5분은 열고 실행하기입니다.
3. 마지막 5분은 제출 시간입니다. 편집은 그 전에 끝냅니다.

**설명 합계: 5+5+5+7+5+3 = 30분**
