# 15주차 실습: 기말 리허설과 시연

## 1일차 리허설 60분

| 시간 | 할 일 |
|---|---|
| 0~10분 | 시작 코드 실행, LAN 연결, 제어 화면 확인 |
| 10~25분 | TODO 1 책상 조명 켜기·끄기 |
| 25~40분 | TODO 2 온습도 표시 |
| 40~50분 | TODO 3 호출 이력 |
| 50~60분 | 자기 점검, 완성본 비교, 수정 |

## 자기 점검

| 조작 | 예상 결과 | 확인 |
|---|---|---|
| 주소 입력 후 연결 | 제어 화면 표시 |  |
| 책상 조명 켜기·끄기 | LED 0 상태 변경 |  |
| 온습도 확인 | 시뮬레이터 값 표시 |  |
| 슬라이더 변경 후 다시 확인 | 변경한 값으로 갱신 |  |
| 입력 버튼 두 번 | 호출 이력 두 줄 |  |
| 온습도 확인 | 호출 이력은 그대로 |  |
| 시뮬레이터 연결 끊기 | 제어 버튼 비활성 |  |
| 연결 화면에서 다시 연결 | 제어 가능 |  |

실행이 되지 않으면 Android Studio Build 창의 첫 오류부터 확인한다. `ActivityControlBinding` 오류는 XML의 id와 `binding` 이름을 비교한다. 연결 문제는 11주차 절차대로 확인하며 TCP·UDP 코드를 직접 수정하지 않는다.

## 2일차 평가 60분

| 시간 | 진행 |
|---|---|
| 0~5분 | 시작 코드와 문항 확인 |
| 5~50분 | 구현, 순회 시연과 구술 |
| 50~60분 | 최종 실행과 코드 제출 |

시연은 연결 → 책상 조명 → 온습도 → 호출 순서로 진행한다. 제어 동작 한 곳의 실행 시점을 설명한다. 평가는 [기말 채점표](rubric.md)를 따른다.

장비·LAN 장애가 생기면 강의자가 기록하고 같은 PC의 에뮬레이터와 WlEno로 재확인한다. 장비 장애와 구현 오류를 구분한다. 학기별 시간 연장과 제출 경로는 시험 공지를 따른다.

## 제출

기말 실습에서는 수정한 `ControlActivity.kt`와 `activity_control.xml`을 제출한다. 연결 코드 변경이 문항에 없다면 `MainActivity.kt`를 고칠 필요가 없다. 제출 직전에 두 파일을 저장하고 앱을 한 번 실행한다.

프로젝트 최종 제출물은 [13주차 과제 안내](../week13_room_control_project/project_brief.md)를 따른다. 학생 이름·학번·점수·시연 기록은 공개 저장소에 올리지 않는다.
