# 기말 개인 실기 Rubric — 총 20점

## 배점 검산

| 구분 | 배점 |
|---|---:|
| 구현 | 15 |
| 시연 | 5 |
| **합계** | **20** |

이 공개 rubric은 평가 차원을 설명한다. 실제 prompt, 정답, 비공개 평가 사례는 포함하지 않는다.

## 구현 — 15점

| 항목 | 배점 | 공개 충족 기준 |
|---|---:|---|
| 요구·UI 상태 구현 | 3 | 당일 요구의 입력·출력·XML View·UiState를 일관되게 구현한다. |
| lifecycle·비동기·component 경계 | 3 | 지정된 lifecycle/coroutine/Flow 또는 Android component/data 경계를 안전하게 사용한다. |
| BLE abstraction·상태 기계 | 4 | 제공 abstraction으로 요구된 BLE 경로와 `Idle → ... → Ready → Disconnected/Error` 상태를 구현한다. |
| validation·실패·검증 | 3 | 정상·경계·실패를 재현하고 오류 뒤 안전 상태와 복구 행동을 보인다. |
| 코드·제출 무결성 | 2 | 지정 범위의 최소 변경, 읽을 수 있는 책임 분리, 최종 source/SHA/제출 증거가 일치한다. |
| **구현 소계** | **15** |  |

실제 prompt는 위 다섯 차원을 모두 평가할 수 있는 과업·증거 지점을 제공한다. 고정 배점 `3 + 3 + 4 + 3 + 2`를 적용하며 `N/A` 처리나 다른 항목으로의 재배점은 하지 않는다.

### 구현 기본점수 floor

먼저 다섯 항목을 분석적으로 채점해 `analyticSubtotal`(0~15점)을 구한다. 시험 제출본에서 당일 요구와 연결되는 식별 가능한 in-scope 구현 시도 증거(source/diff/실행·테스트 기록 중 하나 이상)가 확인될 때만 다음 식을 한 번 적용한다.

```text
implementationScore = min(15, max(analyticSubtotal, 5))
```

식별 가능한 in-scope 시도 증거가 없으면 floor를 적용하지 않고 `implementationScore = analyticSubtotal`로 둔다. floor는 구현 점수에만 적용하며 15점을 넘길 수 없고, 시연 5점은 아래 기준으로 별도 채점한다. 채점자는 적용 여부와 연결한 요구 ID·근거 위치를 기록한다.

## 시연 — 5점

| 항목 | 배점 | 공개 충족 기준 |
|---|---:|---|
| 실행·검증 | 2 | 최종 제출본에서 요구된 정상과 실패/경계 경로를 재현하고 화면·상태·로그를 연결한다. |
| 코드·상태 설명 | 2 | event, 함수/경계, state, render 또는 transport 흐름을 개인 언어로 설명한다. |
| 현장 진단·후속 질문 | 1 | 관찰 근거로 다음 진단 또는 공지 범위의 짧은 후속 질문에 답한다. |
| **시연 소계** | **5** |  |

## 부분점수 증거 원칙

- 실행되지 않는 경우에도 구현 시도, 정확한 상태 예측, 진단 근거를 항목별로 먼저 채점한 뒤 위 floor의 증거 조건과 식을 적용한다.
- 정상 화면만 있고 코드·상태 흐름을 개인이 설명하지 못하면 시연 설명 점수를 충족한 것으로 보지 않는다.
- 강의자가 확인한 장비 장애는 앱 증거와 장비 증거를 분리해 기록하며 물리 동작을 추정하지 않는다.
- 부정행위·지각·재평가 처리는 이 기술 rubric이 아니라 공식 학사/시험 공지를 따른다.
