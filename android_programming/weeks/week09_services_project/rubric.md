# 9주차 1차 과제 채점표 — 발표 5 + 레포트 5 = 10점

주제 (a)/(b)와 제출 방법은 [과제 안내](project_brief.md)에 있다. 이 채점표는 발표 전에 공개하며, 평가자는 아래 기록 양식에 근거를 적는다.
팀 운영 여부와 팀원 점수 적용은 수업 공지를 따른다. 팀이어도 **코드 설명은 한 사람씩** 한다.

## 발표 — 5점

| 항목 | 배점 | 만점 | 부분 점수 | 0점 |
|---|---|---|---|---|
| 정상 흐름 | 1.5 | 처음부터 끝까지 막힘 없이 동작한다. (a) 장치 이름 → 카운트다운 → `준비됨` → 제어 화면 명령 로그와 본인 기능 / (b) 앱의 주 흐름과 `fakeRequest()` 성공 결과 | 1.0: 흐름은 되지만 한 부분이 빠진다(본인 기능 없음, 제어 화면 이동 안 됨, (b)에서 `fakeRequest()`를 부르지 않음 등) / 0.5: 앱은 실행되지만 흐름의 절반 이상이 동작하지 않는다 | 앱이 실행되지 않는다 |
| 실패·재시도 | 1 | 실패 문구와 [다시 시도]가 보이고, 다시 시도해 성공까지 간다. 앱이 꺼지지 않는다 | 0.5: 실패 문구는 보이지만 [다시 시도]가 없거나 동작하지 않는다 / 확률을 고정해 실패가 나오지 않아 레포트 캡처로 대신했다 | 실패할 때 앱이 꺼진다, 또는 실패 처리가 없다 |
| 회전 유지 | 1 | 진행 중(`연결 중… 3`, `요청 중…`)이나 실패 화면에서 돌려도 글자·숫자·버튼이 그대로다 | 0.5: 글자는 남지만 버튼·[다시 시도]·숫자 중 하나가 처음 모양으로 돌아간다 | 돌리면 처음 문구로 돌아간다 |
| 코드 설명(개인 구술) | 1.5 | 질문을 받고 해당 파일과 줄을 스스로 찾아 가리키며, 그 줄이 하는 일을 맞게 한 문장으로 말한다 | 1.0: 줄은 찾지만 설명이 틀리거나 빠진다 / 0.5: 평가자가 파일을 알려 준 뒤에야 줄을 찾는다 | 줄을 찾지 못하고 설명하지 못한다 |
| 소계 | **5** | | | |

- 시연은 2분에서 멈춘다. 2분 안에 보이지 않은 장면은 레포트 캡처로 판단하되 **해당 항목 최대 절반**까지만 준다(장애 기록이 있거나 아래 실패 확률 예외면 만점까지).
- 실패 확률 예외: 확률을 고정하지 않았는데 세 번 눌러도 실패가 나오지 않는 것은 학생 탓이 아니다(세 번 모두 성공할 확률 1/8). 질문 시간에 한 번 더 눌러 실패와 [다시 시도]가 나오면 만점이다. 그래도 나오지 않으면 레포트의 실패 캡처를 보여 주고 `catch` 줄을 가리키면 만점이다.
- 가짜 연결·`fakeRequest()`의 확률을 발표용으로 고정해 성공이나 실패 한쪽만 나오면, 나오지 않은 쪽 항목은 부분 점수로 본다.
- 질문은 평가자가 고른다. 예: 회전해도 상태가 남는 이유 / 실패해도 앱이 꺼지지 않는 이유 / [다시 시도]가 보이게 되는 줄 / 중복 시작을 막는 줄 / 본인 기능의 줄.

## 레포트 — 5점

| 항목 | 배점 | 만점 | 부분 점수 | 0점 |
|---|---|---|---|---|
| 실행 방법과 파일 목록 | 1 | 레포트대로 누르면 같은 화면이 나오고, 만들거나 고친 파일이 모두 한 줄 설명과 함께 있다 | 0.5: 둘 중 하나가 빠지거나 실제 소스와 다르다 | 둘 다 없다 |
| 채점 축 캡처와 코드 위치 | 2 | 정상 흐름·실패와 [다시 시도]·회전(세로·가로 두 장) 세 칸의 캡처가 모두 있고, 칸마다 코드 파일과 줄 번호가 제출 소스와 맞다 | 1.5: 세 칸 중 한 칸의 캡처가 빠지거나 코드 위치가 틀리다 / 1.0: 두 칸이 빠지거나, 캡처는 다 있지만 코드 위치가 하나도 없다 / 0.5: 캡처가 한 칸만 있다 | 캡처가 없다 |
| 본인 기능 설명 | 1 | (a) 본인 기능이 무엇이고 어느 파일·줄인지, 무엇을 써서 만들었는지(배운 주) / (b) `fakeRequest()`를 부르는 곳, `try/catch`, [다시 시도]가 보이게 되는 줄 | 0.5: 기능 이름만 있고 코드 위치가 없다 | 없다 |
| 오류 해결 기록 | 1 | 오류 메시지 원문(또는 증상), 원인, 고친 방법이 한 건 이상 맞게 적혀 있다 | 0.5: 셋 중 하나가 빠진다 | 없다 |
| 소계 | **5** | | | |

## 공통 판단

- 같은 원인으로 여러 항목이 깎이면 가장 가까운 항목 하나에서만 뺀다. 예: 실패할 때 앱이 꺼지면 실패·재시도에서만 빼고, 회전 유지는 성공 쪽 화면으로 본다.
- 장비 장애(조교 기록이 있는 것)와 내 코드 때문에 생긴 문제를 나눈다. 장애로 못 보인 장면은 레포트 캡처로 만점까지 인정한다.
- 제출 소스로 빌드되지 않으면 발표 때 보인 화면과 제출물이 같은지 확인할 수 없다. 이때 처리(재제출 허용 여부)는 수업 공지를 따른다.
- Service·Fragment·Notification을 넣었는지는 점수에 더하거나 빼지 않는다.
- 공개 저장소에는 학생 이름·학번·점수·제출물을 올리지 않는다.
