# 9주차 1차 과제 채점표 — 총 10점

개인/팀 운영 방식은 **과목 운영 정책 `TBD`**다. 어느 방식이든 발표 중 개인 코드 설명·장애 대응과 레포트의 개인 commit/작업 근거를 확인한다. 명시적 팀원/제출 근거가 없는 결과를 자동 공유하지 않는다.

## 발표 — 5점

| 항목 | 배점 | 충족 기준 |
|---|---:|---|
| normal 동작 | 1.5 | 같은 revision에서 event→비동기 상태→Ready/Success를 재현함 |
| boundary·failure 복구 | 1.5 | empty/중복/회전 중 하나와 오류/timeout→retry를 재현함 |
| 구조·Service 선택 | 1.0 | 단방향 흐름과 scope/lifecycle, Service 사용/미사용 근거를 정확히 설명함 |
| 개인 설명·대응 | 1.0 | 본인 코드 위치를 설명하고 질문/시연 장애에 근거 있게 대응함 |
| 소계 | **5.0** | |

## 레포트 — 5점

| 항목 | 배점 | 충족 기준 |
|---|---:|---|
| 요구 추적·실행 재현 | 1.5 | 요구→파일/함수→증거와 실행 절차가 일치함 |
| 상태·수명 설계 | 1.0 | UI 상태, ViewModel/coroutine/collector 수명을 그림과 근거로 설명함 |
| test 증거 | 1.5 | normal·boundary·failure의 입력, 기대, 실제, 복구를 기록함 |
| revision·개인 근거 | 1.0 | commit과 제출물이 일치하고 개인 설명/기여 위치가 확인됨 |
| 소계 | **5.0** | |

## 총점

| 구분 | 점수 |
|---|---:|
| 발표 | 5 |
| 레포트 | 5 |
| **합계** | **10** |

## 공통 판단

- 완전 충족: 독립 재현 가능하고 실행·설명·증거가 일치한다.
- 부분 충족: 핵심 일부가 실제 실행되지만 특정 상태/수명/복구 또는 증거가 빠진다.
- 미충족: 실행·설명 가능한 결과가 없거나 요구와 무관하다.
- 같은 근본 원인의 중복 감점 여부를 기록하고 항목 최대 배점을 넘기지 않는다.
- 시스템/장비 장애와 구현 오류를 구분한다.
- ESP32-C3 펌웨어 작업은 채점하지 않는다.
