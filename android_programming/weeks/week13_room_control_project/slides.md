# 내 방 제어 시나리오와 계획안

13주차

1일차: 공부 준비·취침 준비·외출 점검

2일차: 현재 앱 시연과 계획안 발표

새 통신 API는 추가하지 않는다.

---

# 1일차 · 0~5분 · 이번 주 시작 화면

책상·침대 조명 선택, 켜기·끄기, 밝기 적용.

12주차 RoomControl 화면을 사용한다.

독립 앱이므로 10주차 이전 프로젝트는 필요하지 않다.

처음 시작하면 제공 완성본과 공통 설정을 사용한다.

---

# 1일차 · 5~10분 · 공부 준비

1. 책상 조명을 선택한다.
2. 밝기를 최대로 적용한다.
3. 침대 조명을 선택한다.
4. 조명을 끈다.

확인: LED 0 밝음, LED 1 꺼짐.

---

# 1일차 · 10~15분 · 취침 준비

1. 책상 조명을 선택하고 끈다.
2. 침대 조명을 선택한다.
3. 밝기를 낮춰 적용한다.

확인: LED 0 꺼짐, LED 1 어두움.

슬라이더 이동 뒤 [밝기 적용]을 누른다.

---

# 1일차 · 15~19분 · 외출

[방 조명 모두 끄기]

```text
off -1
```

선택한 조명과 관계없이 모든 LED가 꺼진다.

앱의 완료 표시와 WlEno 창을 함께 확인한다.

---

# 1일차 · 19~23분 · 명령과 응답 설명

```text
선택: 책상 조명
보냄: pwm 0 128
받음: {"result":"ok","ms":"pwm set"}
표시: 조명 설정 완료
```

명령을 만드는 줄과 응답을 표시하는 줄을 찾는다.

---

# 1일차 · 23~27분 · 동료 점검

친구에게 상황별 조작 순서만 전달한다.

같은 조명 상태를 만들 수 있는지 확인한다.

버튼 이름이 다르면 설명을 실제 화면에 맞춘다.

결과가 다르면 선택 조명과 전송 명령부터 비교한다.

---

# 1일차 · 27~30분 · 실습 결과

60분 동안 상황별 조작과 결과를 확인한다.

- 공부 준비 캡처
- 취침 준비 캡처
- 외출 동작 확인
- 코드 두 곳 설명

새 기능 추가보다 현재 기능의 재현에 집중한다.

---

# 2일차 · 0~5분 · 완성할 앱

연결 화면: 주소 확인과 제어 시작.

제어 화면: 조명 선택과 밝기.

14주차 추가: 실내 온습도와 호출 표시.

시뮬레이터와 에뮬레이터만으로 모든 필수 기능을 보인다.

---

# 2일차 · 5~10분 · 계획안 1쪽

- 앱 목적과 두 화면
- 현재 동작하는 조명 기능
- 추가할 온습도·호출 표시
- 버튼과 명령의 대응
- 남은 일정과 실행 환경

발표용 슬라이드는 필요하지 않다.

---

# 2일차 · 10~14분 · UI와 명령

| UI | 명령 또는 입력 |
|---|---|
| 책상 켜기 | on 0 |
| 침대 끄기 | off 1 |
| 책상 중간 밝기 | pwm 0 128 |
| 방 조명 모두 끄기 | off -1 |
| 온습도 확인 | dht11 |
| 호출 표시 | 시뮬레이터 입력 버튼 |

---

# 2일차 · 14~18분 · 남은 일정

| 시점 | 할 일 |
|---|---|
| 14주차 | 실내 온습도와 호출 표시 |
| 15주차 전 | 실행 순서와 캡처 정리 |
| 15주차 | 완성 앱과 보고서 제출 |

입력 기능이 아직 없어도 계획안을 발표할 수 있다.

---

# 2일차 · 18~22분 · 3분 발표

첫 1분: 연결하고 조명을 제어한다.

다음 1분: 남은 기능과 일정을 설명한다.

마지막 1분: 코드 설명과 질문.

20명 기준 60분이며 실제 순서는 수업 공지를 따른다.

---

# 2일차 · 22~26분 · 평가 기준

| 구분 | 배점 |
|---|---|
| 계획안과 현재 앱 발표 | 10 |
| 최종 기능 시연 | 12 |
| 실행 보고서 | 8 |

실물 보드, UDP 검색, 전화번호부는 평가하지 않는다.

---

# 2일차 · 26~30분 · 제출 준비

계획안에는 현재 기능과 추가할 기능을 구분한다.

발표 뒤 받은 의견 한 가지를 기록한다.

최종 제출: 앱 소스, 기능 캡처 3장, 실행 보고서.

계정·비밀번호·실제 연락처는 넣지 않는다.

---

연결 화면과 조명 제어는 그대로 사용한다.
