# 과제 안내 · 내 방 제어 앱 완성

이번 과제는 독립 앱 `RoomControl`(앱 이름 `내 방 제어`)을 완성하는 작업이다. 실제 조명 대신 PC의 WlEno를 사용한다. 연결 화면에서 제어 화면을 열고 방의 조명과 입력 상태를 확인하는 흐름으로 구성한다.

| 시점 | 제출·발표 | 배점 |
|---|---|---|
| 13주차 2일차 | 계획안 1쪽과 현재 앱 시연 | 10 |
| 15주차 | 앱 소스·캡처·실행 보고서 | 20 |

개인 과제를 기준으로 한다. 팀 허용 여부, 제출 위치, 마감과 발표 순서는 수업 공지가 우선한다. 기말 실기와 과제 점수는 별도다.

## 최종 앱의 필수 기능

| 기능 | 확인 장면 |
|---|---|
| 연결 화면에서 제어 시작 | LAN 주소로 연결한 뒤 제어 화면 열림 |
| 조명 제어 | 선택한 책상·침대 조명 켜기·끄기·밝기 적용 |
| 제어 결과 | 응답을 받은 뒤 완료 표시, 원본 응답 확인 |
| 실내 온습도 | [온습도 확인]으로 WlEno의 현재 값 표시 |
| 호출 표시 | WlEno의 입력 버튼을 누르면 앱에 호출 표시 |
| 종료와 재사용 | 연결 화면으로 돌아간 뒤 다시 제어 시작 |

11~13주차의 연결·조명 제어에 14주차 입력 표시를 추가한다. TCP 소켓, UDP 검색, 자동 재연결, 실제 BLE 보드, 전화번호부 접근은 필수 구현에 포함하지 않는다. 에뮬레이터와 같은 PC의 WlEno만으로 만점을 받을 수 있다.

## 계획안 1쪽

다음 내용을 A4 한 장 또는 화면 한 장에 적는다.

- 앱 소개: 내 방에서 어떤 조명과 상태를 확인하는지 한 문장.
- 화면 구성: 연결 화면과 제어 화면을 간단히 그린다.
- 현재 동작: 책상·침대 조명과 밝기 중 지금 되는 기능.
- 추가할 동작: 실내 온습도와 호출 표시의 위치, 확인 버튼.
- 명령: `on 0`, `off 1`, `pwm 0 128`, `off -1`, `dht11` 중 사용할 명령과 대응 UI.
- 일정: 14주차 입력 표시, 15주차 점검·제출 준비.
- 실행 환경: 에뮬레이터 또는 휴대전화, 연결 주소, 네트워크 장애 시 같은 PC의 에뮬레이터 사용.

명령 목록은 [WlEno 안내](../../../tools/wleno/README.md)와 비교한다. 13주차에 아직 구현하지 않은 입력 기능은 계획으로 설명하면 된다.

## 발표 방법

1분 동안 연결과 조명 제어를 보인다. 다음 1분에는 추가할 기능과 일정을 설명한다. 마지막 1분에는 질문에 답하고 코드 한 곳을 가리킨다. 발표용 슬라이드는 필요하지 않다.

## 최종 제출물

앱 소스 프로젝트, 기능 캡처 3장, 실행 보고서를 제출한다. 보고서는 2~3쪽을 기준으로 하며 분반 공지가 있으면 따른다.

| 제출물 | 포함할 내용 |
|---|---|
| 소스 | Gradle 설정, `app/src`, `app/libs/wleno-android-0.1.0.aar` 포함. 앱 빌드 산출물·로컬 SDK 경로·인증정보 제외 |
| 캡처 1 | 제어 화면과 조명 설정 결과 |
| 캡처 2 | WlEno와 앱의 같은 온습도 값 |
| 캡처 3 | WlEno 입력 버튼 뒤 앱의 호출 표시 |
| 보고서 | 실행 환경, 시뮬레이터 시작 명령, 앱 연결 주소, 2~3분 시연 순서, 수정 파일과 코드 설명, 해결한 문제 또는 알려진 제한 |

시연 순서는 연결 → 책상 조명 켜기 → 밝기 적용 → 온습도 확인 → 입력 버튼 누르기 → 연결 화면으로 돌아가기 순으로 작성할 수 있다. 제출물의 화면 문구가 다르면 실제 앱의 문구로 적는다.

소스만으로 실행할 수 있어야 한다. 네트워크 비밀번호, 계정, 실제 연락처, 다른 학생 정보는 제출물에 넣지 않는다. 공개 저장소에는 학생 제출물과 점수를 올리지 않는다.
