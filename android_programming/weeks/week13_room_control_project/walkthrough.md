# 13주차 따라하기 · 내 방 제어 점검

[1일차 예제](examples/README.md)는 12주차의 조명 선택·밝기 기능을 유지한다. 동작하는 학생은 코드를 다시 복사하지 않고 점검과 계획안 작성에 집중한다. 처음 시작하는 학생도 [공통 설정](../../../tools/wleno/android/README.md)으로 독립 RoomControl 프로젝트를 만들 수 있다.

## 1일차

### 1. 제어 화면 열기

PC에서 WlEno를 시작한다. 앱에서 주소를 확인하고 [제어 시작]을 누른다. WlEno와 같은 PC의 에뮬레이터는 `10.0.2.2:8266`, 다른 PC의 에뮬레이터와 실기기는 `WlEno 실행 PC의 LAN IPv4:8266`을 사용한다. [주소와 방화벽 조건](../../iot_sim/lab.md#2-앱에-넣을-주소-결정)을 확인한다.

### 2. 상황별 제어 순서 작성

| 상황 | 조작 순서 | 확인 |
|---|---|---|
| 공부 준비 | 책상 선택 → 밝기 최대 → 적용 → 침대 선택 → 끄기 | LED 0 밝음, LED 1 꺼짐 |
| 취침 준비 | 책상 선택 → 끄기 → 침대 선택 → 밝기 낮춤 → 적용 | LED 0 꺼짐, LED 1 어두움 |
| 외출 | 방 조명 모두 끄기 | 모든 LED 꺼짐 |

슬라이더는 [밝기 적용]을 눌렀을 때 반영된다. `off -1`의 `-1`은 전체 LED를 뜻한다. 사용자는 [방 조명 모두 끄기] 버튼으로 이 동작을 수행한다.

### 3. 응답으로 완료 확인

버튼을 누르면 큰 글자가 `응답 대기 중`으로 바뀌고, 응답의 `result`가 `ok`이면 `조명 설정 완료`가 된다. 아래 작은 글자에는 실제 전송과 원본 JSON이 남는다. 완료 글자가 바뀌는 코드와 LED 선택을 번호로 바꾸는 코드를 각각 찾아 설명한다.

### 4. 친구가 재현하기

친구에게 공부 준비 순서만 전달한다. 코드 설명 없이 같은 조명 상태가 만들어지는지 확인한다. 설명이 부족하면 버튼 이름과 순서를 고친다. 새 기능을 늘리기보다 조작과 결과가 일치하는지 확인한다.

### 5. 수업 종료 동작

[연결 화면]을 누르면 연결을 해제한다. 다시 제어하려면 [제어 시작]을 누른다. 시뮬레이터는 연결과 해제 때 LED를 초기화한다. 연결을 다시 한 뒤 조명이 꺼져 있어도 정상이다.

## 2일차

### 6. 계획안 작성

[과제 안내](project_brief.md)의 양식을 사용한다. 지금 되는 조명 제어와 14주차에 추가할 실내 온습도·호출 표시를 나누어 적는다. 연결 클래스나 UDP 검색을 새로 구현하는 계획은 필요하지 않다.

### 7. 3분 발표

첫 1분은 연결과 조명 제어를 보여 준다. 다음 1분은 추가할 입력 기능과 일정을 설명한다. 마지막 1분은 코드 설명과 질문이다. 아직 배우지 않은 입력 기능이 없다는 사실로 계획안 점수를 깎지 않는다.

### 8. 피드백 반영

발표에서 받은 수정 의견 한 가지를 계획안에 적는다. 다음 주에는 본인 앱 또는 13주차 완성본의 제어 화면에 입력 표시를 추가한다. 제출물에 계정이나 네트워크 비밀번호를 넣지 않는다.
