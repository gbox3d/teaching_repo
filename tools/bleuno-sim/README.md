# bleuno-sim — 보드 없이 Wi-Fi로 연습하는 BLEuno 시뮬레이터

`sim.py`는 PC에서 돌리는 가짜 BLEuno 보드다. 보드와 같은 명령을 받아 같은 모양의 JSON 한 줄로 답하고, LED·온도·습도·입력 버튼을 따로 뜨는 창(시뮬레이터 화면)에 보여 준다.
앱과는 블루투스 대신 Wi-Fi(TCP)로 주고받으므로, 보드가 없어도 12주차 2일차 이후의 `SmartIO`로 검색·연결을, 13주차 이후 판으로는 명령·응답까지 에뮬레이터나 실기기에서 연습할 수 있다. 주차마다 할 수 있는 단계는 [실습 안내](../../android_programming/iot_sim/lab.md)의 '주차별 적용 범위' 표에 있다.
앱이 아닌 프로그램(AI 에이전트, 시험 스크립트)도 같은 TCP 명령으로 보드 대신 쓸 수 있다([11절](#11-다른-프로그램에서-쓰기)).
이 문서는 시뮬레이터만 다룬다. 앱에서 바꿀 곳과 90분 실습 순서는 [실습 안내](../../android_programming/iot_sim/lab.md)에, 보드의 명령 규약은 [bleuno README](../../android_programming/bleuno/README.md)에 있다.

## 1. 시뮬레이터가 대신하는 것

시뮬레이터는 **보드와 블루투스**를 대신한다. 앱이 보내는 명령과 받는 JSON의 모양은 보드와 같다.
앱 쪽에서 바꿀 곳(클라이언트를 `TcpBleunoClient`로 만들기, 인터넷 권한)은 [실습 안내](../../android_programming/iot_sim/lab.md)를 따른다.
아래 표의 '실제 보드' 칸과 이 문서에서 '펌웨어 소스 기준'이라고 적은 보드 동작은 bleuno 펌웨어(`1.0.5_dev`) 소스를 읽고 적은 것이다. 실제 보드로는 확인하지 못했다.

| 항목 | 실제 보드 (펌웨어 소스 기준) | Fake (`useFake = true`) | 시뮬레이터 |
|---|---|---|---|
| 앱 쪽 클래스 | `RealBleunoClient` | `FakeBleunoClient` | `TcpBleunoClient` |
| 연결 | 블루투스(BLE) | 없음. 앱 안에서 흉내 낸다 | Wi-Fi(TCP 8266) |
| [검색]에 나오는 이름 | `ESP32_BLE` + 칩 ID | `ESP32_BLE_FAKE1`, `ESP32_BLE_FAKE2` | `--name`으로 준 이름(기본 `ESP32_BLE_SIM1`) |
| LED | 보드의 LED | 보이지 않는다 | 화면의 원 4개 |
| `dht11` 값 | 센서가 잰 값 | `[24.5,40.0]` → `[25.0,41.0]` → `[25.5,42.0]` 반복 | 화면 슬라이더 값 |
| 입력 이벤트 | 지금 펌웨어에는 없다 | 10초마다 저절로 | 화면의 [입력 버튼]을 누를 때만 |
| `끊김` 만들기 | 보드 전원 끄기 | `simulateLost()` | 화면의 [연결 끊기], 또는 시뮬레이터 끄기. 앱의 [끊김 시험] 버튼은 `useFake = false`라 보이지 않는다 |
| `about`의 `app`·`version` | `BLEuno`·`1.0.5_dev` | `BLEuno`·`1.0.5_dev` | `BLEuno-SIM`·`1.0.5_sim` |
| 앱이 연결·해제될 때 LED | 모두 꺼진다 | LED 상태가 없다 | 모두 꺼진다 |
| 빈 줄(길이 0) | 답하지 않는다 | 답하지 않는다 | 답하지 않는다 |
| 공백만 있는 줄(예: 띄어쓰기 하나) | `unknown command`로 답한다 | 답하지 않는다 | `need command`로 답한다 |

**결정된 사항**: 보드·Fake와 다르게 두기로 정한 것과, 보드에 맞춘 것이다.

- `dht11`은 화면 슬라이더 값을 준다. Fake는 세 값을 돌려 가며 주므로, 14주차 2일차의 Fake 실행 예시와 값이 다르다. 슬라이더를 움직이면 다음 `dht11`부터 값이 바뀐다.
- 입력 이벤트는 화면의 [입력 버튼]을 누를 때만 보낸다(Fake는 10초마다). 14주차 2일차 따라하기에서 Fake의 10초 입력 이벤트를 기다리는 곳(1단계 5번, 5단계 4번의 '가만히 둔다', 6단계 8·9번, 13단계 표)은 시뮬레이터에서는 [입력 버튼]을 누른다. 참고로 보드 펌웨어에도 입력 이벤트를 보내는 코드가 없다(`ble.cpp`에서 `notify()`를 부르는 곳은 `onWrite` 안의 명령 응답뿐이다).
- LED는 보드처럼 앱이 연결될 때와 연결이 끝날 때 모두 꺼진다(보드 쪽은 펌웨어 소스 기준). 보드에는 앱이 하나만 붙지만 시뮬레이터에는 여럿이 붙을 수 있다. 그래서 여러 앱이 붙어 있을 때 한 앱이 새로 붙거나 끊겨도 LED가 모두 꺼진다.
- 길이 0인 줄(빈 줄)에는 보드처럼 답하지 않는다(보드 쪽은 펌웨어 소스 기준).

시뮬레이터는 포트 세 개를 연다. 화면은 포트가 아니라 시뮬레이터가 띄우는 창이다.

| 포트 | 쓰는 쪽 | 하는 일 |
|---|---|---|
| TCP 8266 | 앱 | 명령 한 줄을 보내고 JSON 한 줄을 받는다 |
| UDP 8267 | 앱의 [검색] | `bleuno?`를 보내면 이름과 TCP 포트가 돌아온다 |
| TCP 8080 | 이 PC의 다른 프로그램 | 상태 읽기와 화면 조작(HTTP API, [11절](#11-다른-프로그램에서-쓰기)). 앱은 쓰지 않는다 |

## 2. 준비

- **Python 3.10 이상과 pygame-ce.** 화면을 pygame-ce로 그린다. 처음 한 번 아래 표의 명령으로 설치한다.
- 이 폴더의 `sim.py` 한 파일. Windows와 macOS에서 같은 파일을 쓴다.
- 에뮬레이터로 연습하면 에뮬레이터를 띄운 PC에서, 실기기로 연습하면 휴대폰과 같은 Wi-Fi에 붙은 PC에서 실행한다.

터미널에서 Python 버전부터 확인한다.

| 운영체제 | 버전 확인 | 설치(처음 한 번) | 실행 |
|---|---|---|---|
| Windows | `py --version` (안 되면 `python --version`) | `py -m pip install pygame-ce` | `py sim.py` 또는 `python sim.py` |
| macOS | `python3 --version` | `python3 -m pip install pygame-ce` | `python3 sim.py` |

`Python 3.12.13`처럼 3.10 이상이 나오면 된다. 명령을 찾지 못한다는 글이 나오면 [10. 막혔을 때](#10-막혔을-때)의 첫 두 줄을 본다.

- 설치는 실행할 때와 같은 명령으로 한다. `py sim.py`로 실행하면 `py -m pip`, `python sim.py`로 실행하면 `python -m pip`이다. Python이 여럿 깔린 PC에서 다른 Python에 설치하면 실행할 때 `pygame-ce 를 불러오지 못했다`가 나온다.
- `pygame`(이름에 `-ce`가 없는 원래 판)이 깔려 있으면 먼저 같은 방법으로 지운다(`py -m pip uninstall pygame`, macOS는 `python3 -m pip uninstall pygame`). 둘 다 `pygame`이라는 이름으로 깔리므로 함께 둘 수 없다. 원래 판의 마지막 버전(2.6.1)에는 Python 3.14용 설치 파일이 없다.
- 화면 없이 돌릴 때는 `--no-window`를 붙인다([3절](#3-실행과-끝내기)). 이때는 pygame-ce가 없어도 되고 Python 3.9 이상이면 된다.

## 3. 실행과 끝내기

터미널에서 `sim.py`가 있는 폴더로 옮긴 뒤 이름을 붙여 실행한다. 이름 규칙은 [9절](#9-수업에서-여럿이-쓸-때)에 있다.

```powershell
cd 내려받은_폴더\tools\bleuno-sim
py sim.py --name ESP32_BLE_0423
```

macOS에서는 이렇게 한다.

```bash
cd 내려받은_폴더/tools/bleuno-sim
python3 sim.py --name ESP32_BLE_0423
```

터미널에 시작 메시지가 찍힌 뒤 시뮬레이터 창이 따로 뜬다([5절](#5-시뮬레이터-화면)).
옵션은 모두 생략할 수 있다. `py sim.py -h`(macOS는 `python3 sim.py -h`)로 같은 목록을 볼 수 있다.

| 옵션 | 기본값 | 뜻 |
|---|---|---|
| `--name` | `ESP32_BLE_SIM1` | 장치 이름. [검색] 답, 연결 직후의 hello 줄, 화면 제목에 쓰인다 |
| `--tcp` | `8266` | 명령 포트. 앱이 붙는 곳 |
| `--udp` | `8267` | 검색 포트. 앱의 [검색]이 `bleuno?`를 보내는 곳 |
| `--http` | `8080` | HTTP API 포트([11절](#11-다른-프로그램에서-쓰기)) |
| `--bind` | `0.0.0.0` | TCP·UDP를 받을 주소. `0.0.0.0`은 이 PC의 모든 네트워크다 |
| `--http-bind` | `127.0.0.1` | HTTP API를 받을 주소. 기본값이면 이 PC에서만 열린다 |
| `--no-window` | (없음) | 시뮬레이터 창 없이 돌린다. pygame-ce가 없어도 된다. 끝낼 때는 Ctrl+C |

포트는 바꾸지 않는 것이 기본이다. 바꾸면 이렇게 된다.

- `--http`: 8080을 다른 프로그램이 쓰고 있을 때만 `--http 8081`처럼 바꾼다. HTTP API 주소만 달라진다.
- `--tcp`: [검색] 답에 바뀐 포트가 들어간다. 주소를 직접 넣을 때도 `IP:바꾼 포트`로 쓴다.
- `--udp`: 앱은 8267로만 묻는다. 바꾸면 [검색]에 나오지 않으므로 주소를 직접 넣는다.

**끝내기**: 시뮬레이터 창을 닫거나, 시뮬레이터를 돌리는 터미널에서 Ctrl+C(macOS는 control+C)를 누른다. 붙어 있던 앱마다 `해제` 줄이 찍히고, 마지막 줄에 `종료`가 찍힌 뒤 프롬프트로 돌아온다.
붙어 있던 앱은 연결이 끊겨 `끊김`이 된다. 끈 뒤 바로 다시 실행해도 같은 포트로 뜬다.
Windows에서 방화벽 창의 [액세스 허용]을 눌렀거나 [7절](#7-windows-방화벽)의 네 줄로 규칙을 바꿨다면, 수업이 끝나 마지막으로 끄기 전에 7절의 **Python 규칙 지우기**를 한다.

## 4. 시작 메시지와 로그

`py sim.py --name ESP32_BLE_0423`을 실행하면 아래처럼 나온다. IP 주소와 시각은 PC마다 다르다.

```text
=== BLEuno 시뮬레이터 (ESP32_BLE_0423) ===
명령(TCP) 포트 8266, 검색(UDP) 포트 8267, 바인드 0.0.0.0
이 PC의 IPv4 주소(실기기용, 앞의 것부터): 192.168.0.10, 100.80.1.2(VPN?)
에뮬레이터에서는 10.0.2.2:8266
HTTP API: http://127.0.0.1:8080/state
Windows 방화벽 창이 뜨면 [액세스 허용]을 누른다. 안 뜨면 포트 8266·8267을 인바운드로 허용한다.
끝내려면 시뮬레이터 창을 닫거나 Ctrl+C
[14:02:11] 시작: TCP 8266, UDP 8267, HTTP 8080
```

`--no-window`로 실행하면 `끝내려면` 줄이 `끝내려면 Ctrl+C`로 나온다. 나머지는 같다.

| 줄 | 읽는 법 |
|---|---|
| `=== BLEuno 시뮬레이터 (ESP32_BLE_0423) ===` | `--name`으로 준 이름. [검색] 목록에 이 이름이 나온다 |
| `명령(TCP) 포트 8266, 검색(UDP) 포트 8267, 바인드 0.0.0.0` | 앱이 붙는 포트, [검색] 포트, 받는 주소 |
| `이 PC의 IPv4 주소(실기기용, 앞의 것부터): …` | 실기기의 주소 칸에 넣을 IP. 인터넷으로 나가는 어댑터(노트북은 보통 Wi-Fi)의 주소를 맨 앞에 두고, 그 뒤에 사설 주소(`192.168.…`, `10.…`, `172.16.…`~`172.31.…`)를 둔다. WSL·Hyper-V·VirtualBox 같은 가상 어댑터의 주소도 사설 주소라 표시 없이 섞일 수 있다. `(VPN?)`·`(자동 할당)`이 붙은 주소는 맨 뒤에 두며, 쓰지 않는다 |
| `에뮬레이터에서는 10.0.2.2:8266` | 에뮬레이터의 주소 칸에 넣을 값 |
| `HTTP API: http://127.0.0.1:8080/state` | 다른 프로그램이 상태를 읽는 주소([11절](#11-다른-프로그램에서-쓰기)). 앱은 이 주소를 쓰지 않는다 |
| `주의: 이름이 ESP32_BLE 로 시작하지 않으면 12~15주차 예제의 [검색] 목록에 나오지 않는다.` | 이름이 `ESP32_BLE`로 시작하지 않을 때만 `HTTP API:` 줄 아래에 나온다 |
| `Windows 방화벽 창이 뜨면 …` | [7절](#7-windows-방화벽). macOS에서도 이 줄은 찍힌다 |
| `[14:02:11] 시작: TCP 8266, UDP 8267, HTTP 8080` | 세 포트를 모두 열었다. 이 줄이 보이면 앱에서 붙어도 된다. 시뮬레이터 창은 이 줄 다음에 뜬다 |

그 뒤로는 일이 생길 때마다 시각과 함께 한 줄씩 찍힌다. 같은 줄이 화면의 `최근 명령 로그`에도 나온다. `[시:분:초]`가 없는 줄(시작 안내와 마지막 `종료`)은 터미널에만 찍힌다.

| 로그 줄(예) | 뜻 |
|---|---|
| `[14:02:58] [192.168.0.31:51234] bleuno? → {"name":"ESP32_BLE_0423","port":8266}` | 앱의 [검색]에 답했다. 대괄호 안은 물어 온 쪽의 IP와 포트 |
| `[14:03:05] [192.168.0.31:40122] 연결 (1개)` | 앱이 붙었다. 괄호 안은 지금 연결 수 |
| `[14:03:07] [192.168.0.31:40122] on 0 → {"result":"ok","ms":"led(s) on"}` | 받은 명령 → 보낸 응답 |
| `[14:03:20] [화면] 입력 버튼 → {"event":"input","index":0,"value":1} (1개에 전송)` | 화면에서 [입력 버튼]을 눌렀다. 괄호 안은 이벤트를 받은 연결 수. HTTP API로 누르면 `[화면]` 대신 `[API]`가 붙는다 |
| `[14:03:31] [화면] 연결 끊기 (1개)` | 화면에서 [연결 끊기]를 눌렀다. HTTP API로 누르면 `[API]`가 붙는다 |
| `[14:03:31] [192.168.0.31:40122] 해제 (0개)` | 연결이 끝났다. 괄호 안은 남은 연결 수 |
| `종료` | 시뮬레이터가 꺼졌다(터미널에만 찍힌다) |

연결 직후 보내는 hello 줄과 화면의 슬라이더 조작은 로그에 남지 않는다. 빈 줄(길이 0)은 답도 로그도 없다. 공백만 있는 줄은 `need command` 응답과 함께 찍히고, `→` 앞의 명령 자리가 비어 있다.

## 5. 시뮬레이터 화면

시작 메시지 뒤에 `BLEuno 시뮬레이터 — 이름` 창이 뜬다. 창은 1초에 30번 시뮬레이터의 상태를 다시 그린다. 왼쪽에 LED·온습도·버튼이, 오른쪽에 로그가 있다.

| 부분 | 보이는 것 | 하는 일 |
|---|---|---|
| 제목 | `BLEuno 시뮬레이터 — ESP32_BLE_0423` | `--name` 확인 |
| 안내 줄 | `TCP 8266 · UDP 8267 · [검색]에 나오지 않으면 앱의 주소 칸에 직접 입력하세요. …` | 앱에 넣을 주소([6절](#6-앱에서-붙을-주소)) |
| `LED (인덱스 0~3, 밝기 0~255)` | 원 4개(LED 0~3)와 그 아래 밝기 숫자. 0이면 회색, 밝을수록 진한 빨강이고 둘레가 번진다 | `on`·`off`·`pwm`의 결과. 앱이 붙거나 끊기면 모두 꺼진다 |
| 내장 LED | 작은 점과 `내장 LED: 꺼짐`. `blink`를 받으면 점이 파랗게 깜빡이고 `내장 LED: 깜빡임` | `blink`·`stopblk`의 결과. 보드는 앱이 연결된 동안 `blink`를 받아도 깜빡이지 않는다(펌웨어 소스 기준) |
| `DHT11 (dht11 명령이 읽어 가는 값)` | 온도(-10~50 °C)·습도(0~100 %) 슬라이더와 그 값. 처음 값은 24.5 °C·40.0 % | 막대를 누르거나 손잡이를 끌면 곧바로 바뀌고, 다음 `dht11` 응답에 소수 첫째 자리로 들어간다. 마우스로는 약 0.2 °C·0.3 % 간격으로 움직인다 |
| [입력 버튼] | 버튼 | 연결된 모든 앱에 입력 이벤트 한 줄을 보낸다([8절](#8-명령과-응답)) |
| [연결 끊기] | 빨간 글자 버튼 | 붙어 있는 앱의 연결을 모두 끊는다. 앱은 `끊김`이 되고 LED는 모두 꺼진다(재연결 연습용) |
| `연결 수:` | 숫자 | 지금 붙어 있는 앱 수 |
| `최근 명령 로그` | 오른쪽 검은 칸 | 터미널 로그의 최근 줄. 칸에는 17행까지 들어가고, 긴 줄은 칸 폭에서 접으므로 그보다 적은 줄이 보일 수 있다. 칸에 다 들어가지 않으면 최근 줄만 보인다. 한 줄이 300자를 넘으면 300자까지만 보이고, 제어 문자와 글꼴에 없는 글자(이모지 등)는 `?`로 보인다(터미널에는 그대로 찍힌다) |

- 시뮬레이터 창은 시뮬레이터를 실행한 PC에만 뜬다. 다른 사람은 내 화면의 버튼을 누를 수 없다.
- 창을 닫으면 시뮬레이터가 끝난다. 터미널에서 Ctrl+C를 누른 것과 같다.
- Windows에서 창 제목 줄을 마우스로 누르고 있는 동안(창을 끌어 옮길 때)에는 앱의 명령과 [검색]에 답하지 않는다. 손을 떼면 이어서 답한다. 앱이 연결하는 동안 3초 넘게 누르고 있으면 앱은 `끊김`이 된다.
- HTTP API로 슬라이더 범위 밖의 값(예: 온도 100)을 넣으면 손잡이는 끝에 머물고 숫자는 넣은 값을 보인다. 100만이 넘는 값은 `1e+07 °C`처럼 줄여 보인다.
- 한글이 네모로 보이면 [10절](#10-막혔을-때)을 본다.

## 6. 앱에서 붙을 주소

| 앱을 돌리는 곳 | 주소 칸에 넣을 값 | 조건 |
|---|---|---|
| 에뮬레이터 | `10.0.2.2:8266` | 시뮬레이터와 에뮬레이터가 같은 PC. 에뮬레이터 안에서 `10.0.2.2`는 그 PC를 가리킨다 |
| 실기기 | `PC의 IPv4:8266` (예: `192.168.0.10:8266`) | 휴대폰과 PC가 같은 Wi-Fi. Windows는 방화벽 허용([7절](#7-windows-방화벽)) |

[검색]을 쓰면 주소를 몰라도 찾을 수 있다.

1. 앱이 UDP 8267로 `bleuno?`를 보낸다. 같은 Wi-Fi 전체(브로드캐스트)와 `10.0.2.2`(에뮬레이터를 띄운 PC) 두 곳이다.
2. 시뮬레이터는 물어 온 쪽에 `{"name":"ESP32_BLE_0423","port":8266}`로 답하고, 터미널에 `bleuno? →` 줄을 찍는다.
3. 앱 목록에 `ESP32_BLE_0423 (192.168.0.10:8266)`처럼 이름과 `IP:포트`가 들어간다.

[검색]에 나오지 않으면 주소 칸(`주소 (예: 10.0.2.2:8266)`)에 직접 넣고 [주소로 연결]을 누른다. 이 칸과 버튼은 [실습 안내](../../android_programming/iot_sim/lab.md) 2-4에서 앱에 더한다. 어느 쪽이든 붙는 곳은 TCP 8266이다.

## 7. Windows 방화벽

실기기는 Wi-Fi를 거쳐 PC로 들어오므로, 방화벽이 막으면 [검색]도 연결도 되지 않는다.

**창이 뜨면**: 시뮬레이터를 처음 실행할 때 Python의 네트워크 접근을 허용할지 묻는 창이 뜨면 **[액세스 허용]을 누른다**.
창에 `개인`·`공용` 네트워크 체크 칸이 있으면 둘 다 체크한다. 체크하지 않은 종류의 네트워크에서는 계속 막힌다. 이 허용은 그 Python의 TCP와 UDP에 함께, 포트를 가리지 않고 적용된다. 수업이 끝나면 시뮬레이터를 끄기 전에 아래 **Python 규칙 지우기**를 따른다.

**지금 Wi-Fi의 종류 보기**: PowerShell에서 `Get-NetConnectionProfile | Format-Table InterfaceAlias, NetworkCategory`를 실행한다. `InterfaceAlias`가 `Wi-Fi`인 줄의 `NetworkCategory`를 본다. `Public`이 공용, `Private`이 개인이다. VPN처럼 연결이 둘 이상이면 줄이 여러 개 나온다.

**창이 뜨지 않았는데 실기기가 붙지 않으면**: PowerShell을 **관리자 권한으로 실행**해 포트 두 개를 연다.

```powershell
New-NetFirewallRule -DisplayName "BLEuno SIM TCP 8266" -Direction Inbound -Protocol TCP -LocalPort 8266 -Action Allow
New-NetFirewallRule -DisplayName "BLEuno SIM UDP 8267" -Direction Inbound -Protocol UDP -LocalPort 8267 -Action Allow
```

수업이 끝나면 관리자 권한 PowerShell에서 지운다.

```powershell
Remove-NetFirewallRule -DisplayName "BLEuno SIM TCP 8266"
Remove-NetFirewallRule -DisplayName "BLEuno SIM UDP 8267"
```

**포트를 열어도 실기기가 붙지 않거나, 창에서 [취소]를 눌렀거나, 관리자가 아닌 계정이라면**: Windows가 그 Python을 막는 규칙을 남겼을 수 있다. 관리자가 아닌 계정에서는 창에서 무엇을 눌러도 막는 규칙이 생길 수 있다. 막는 규칙은 위의 허용 규칙보다 앞서므로, 포트를 열어도 실기기가 붙지 않는다.
시뮬레이터를 켜 둔 채로 PowerShell 창을 하나 더 관리자 권한으로 열어 아래 네 줄을 실행한다. `--tcp`로 포트를 바꿨으면 첫 줄의 8266을 그 번호로 바꾼다.

1. 첫 줄은 시뮬레이터를 돌리는 Python(8266 포트를 연 Python)의 경로를 `$py`에 담는다. 시뮬레이터가 꺼져 있으면 오류가 난다.
2. 둘째 줄은 그 경로를 보여 준다. 경로가 나오지 않으면 나머지 줄은 아무것도 바꾸지 않는다. 시뮬레이터가 켜져 있는지 보고 첫 줄부터 다시 실행한다. 그래도 나오지 않으면 조교에게 묻는다.
3. 셋째 줄은 그 Python의 규칙을 보여 준다.
4. 넷째 줄은 그 가운데 `Action`이 `Block`인 규칙을 허용으로 바꾼다. 네 줄을 다 실행해도 실기기가 붙지 않으면 위의 포트 규칙을 만들고, 그래도 붙지 않으면 조교에게 묻는다.

```powershell
$py = (Get-Process -Id (Get-NetTCPConnection -LocalPort 8266 -State Listen).OwningProcess | Where-Object Name -like 'python*').Path
$py
Get-NetFirewallApplicationFilter | Where-Object Program -eq $py | Get-NetFirewallRule | Format-Table DisplayName, Action, Profile
Get-NetFirewallApplicationFilter | Where-Object Program -eq $py | Get-NetFirewallRule | Where-Object Action -eq Block | Set-NetFirewallRule -Action Allow
```

**Python 규칙 지우기**: [액세스 허용]으로 생긴 규칙이나 위에서 허용으로 바꾼 규칙이 남아 있으면, 그 Python으로 돌리는 다른 프로그램도 허용한 종류의 네트워크에서 들어오는 연결을 받는다. 수업이 끝나면 시뮬레이터를 끄기 전에(이미 껐으면 처음과 같은 명령으로 다시 켠다) PowerShell 창을 하나 더 관리자 권한으로 열어 아래 세 줄을 실행한다. 첫 두 줄은 위와 같다. 둘째 줄에 경로가 나오지 않으면 아무것도 지워지지 않는다. 셋째 줄은 그 Python의 규칙을 모두 지운다. 수업 전부터 있던 그 Python의 규칙(다른 수업에서 허용해 둔 것 등)도 함께 지워진다. 다음에 시뮬레이터를 실행할 때 창이 다시 뜨면 [액세스 허용]을 누른다.

```powershell
$py = (Get-Process -Id (Get-NetTCPConnection -LocalPort 8266 -State Listen).OwningProcess | Where-Object Name -like 'python*').Path
$py
Get-NetFirewallApplicationFilter | Where-Object Program -eq $py | Get-NetFirewallRule | Remove-NetFirewallRule
```

관리자 권한이 없는 PC면 조교에게 묻는다. 조교는 포트 규칙만 만들지 말고 위의 네 줄로 막는 규칙도 확인한다. macOS에서 들어오는 연결을 허용할지 묻는 창이 뜨면 [허용]을 누른다.

## 8. 명령과 응답

한 줄이 명령 하나다(끝에 `\n`. 앱의 `send`가 붙인다). 응답은 JSON 한 줄이고, 명령을 보낸 앱에만 간다.
응답 글자는 Fake와 같다. 다른 것은 `dht11` 값(화면 슬라이더), `about`의 `app`·`version`, 공백만 있는 줄이다([1절](#1-시뮬레이터가-대신하는-것)의 표와 결정된 사항). 빈 줄(길이 0)에는 보드·Fake처럼 답하지 않는다. 공백만 있는 줄에는 `need command`로 답한다. 보드는 `unknown command`로 답하고, Fake는 `send()`에서 걸러 보내지 않으므로 답이 없다. 띄어쓰기 자리에 탭이나 전각 공백(U+3000) 같은 다른 공백 글자를 넣으면 시뮬레이터는 띄어쓰기로 읽는다. 보드는 반각 띄어쓰기로만 나누므로, 명령 이름 바로 뒤에 다른 공백 글자를 쓰면 `unknown command`로 답한다. 줄 맨 앞에 띄어쓰기가 있으면 시뮬레이터와 Fake는 지우고 읽지만, 보드는 `unknown command`로 답한다. 이 문단의 보드 동작은 모두 펌웨어 소스 기준이다.

| 보내는 명령 | 받는 응답 | 화면 |
|---|---|---|
| `on N` / `on N N …` | `{"result":"ok","ms":"led(s) on"}` | 그 LED 밝기 255 |
| `on -1` | `{"result":"ok","ms":"led(s) on"}` | 4개 모두 255 |
| `on` (번호 없음) | `{"result":"err","ms":"need pin index"}` | 그대로 |
| `off N` / `off -1` | `{"result":"ok","ms":"led(s) off"}` | 그 LED(또는 모두) 밝기 0 |
| `off` (번호 없음) | `{"result":"err","ms":"need pin index"}` | 그대로 |
| `pwm N V` (N은 0~3, V는 0~255) | `{"result":"ok","ms":"pwm set"}` | LED N 밝기 V |
| `pwm -1 V` | `{"result":"ok","ms":"pwm set"}` | 4개 모두 밝기 V |
| `pwm 4 10`, `pwm 9 100` (N이 3보다 큼) | `{"result":"err","ms":"pwm pin index error"}` | 그대로 |
| `pwm 0 300`, `pwm 0 -1` (V가 0~255 밖) | `{"result":"err","ms":"pwm value range 0~255"}` | 그대로 |
| `pwm 0`, `pwm` (값이 모자람) | `{"result":"err","ms":"need pin index and pwm value"}` | 그대로 |
| `dht11` | `{"result":"ok","value":"[24.5,40.0]"}` | 슬라이더 값(온도, 습도) |
| `about` | `{"result":"ok","os":"cronos-v1","app":"BLEuno-SIM","version":"1.0.5_sim","author":"gbox3d","chipid":1234567890}` | — |
| `blink` / `stopblk` | `{"result":"ok","ms":"led blink"}` / `{"result":"ok","ms":"led stop blink"}` | 내장 LED 깜빡임 / 꺼짐 |
| 빈 줄(길이 0) | 답하지 않는다 | — |
| 공백만 있는 줄 | `{"result":"fail","ms":"need command"}` | — |
| 그 밖의 글자(`hello`, 대문자 `ON 0` 등) | `{"result":"fail","ms":"unknown command"}` | — |

범위 밖이나 잘못된 값은 이렇게 처리한다.

- `on 9`처럼 0~3 밖의 번호는 무시하고 `ok`를 준다. `on 1 9`는 LED 1만 켠다. 실제 보드는 `on`·`off`의 번호를 검사하지 않으므로(펌웨어 소스 기준), 앱이 보내기 전에 `0~3` 또는 `-1`인지 검사한다([bleuno README](../../android_programming/bleuno/README.md) 2절).
- `on`·`off`에서 `-1`이 아닌 음수(`on -2`)는 범위 밖 번호처럼 무시하고 `ok`를 준다. `pwm`은 음수 번호를 모두 4개 전체로 처리한다(`pwm -3 10`은 4개 모두 밝기 10).
- 번호가 음수면 `pwm`은 밝기 값을 검사하지 않는다. `pwm -1 300`은 `ok`이고 4개 모두 255가 된다.
- 번호나 값이 정수가 아니면 0으로 읽는다. `on abc`는 LED 0을 켜고, `pwm 2 abc`는 LED 2를 끈다. 소수(`pwm 0 127.5`), 밑줄이 든 수(`1_0`), 32비트 정수 범위를 넘는 수(`99999999999`)도 0이다. Fake(`toIntOrNull()`)와 같은 규칙이다.
- 명령은 소문자만 안다. `ON 0`은 `unknown command`다.

시뮬레이터가 먼저 보내는 줄도 있다.

| 언제 | 시뮬레이터가 보내는 줄 | 받는 곳 |
|---|---|---|
| 연결 직후 한 번 | `{"event":"hello","name":"ESP32_BLE_0423","app":"BLEuno-SIM"}` | 붙은 앱. 앱은 이 줄을 받으면 `준비됨`이 되고, 이 줄은 `onMessage`로 넘기지 않는다 |
| 화면의 [입력 버튼]을 누를 때 | `{"event":"input","index":0,"value":1}`. 누를 때마다 `value`가 1, 0, 1, …로 바뀐다 | 연결된 모든 앱 |
| UDP 8267로 `bleuno?`가 올 때 | `{"name":"ESP32_BLE_0423","port":8266}` | 물어 온 쪽 |

- 입력 이벤트는 Fake처럼 10초마다 오지 않는다. [입력 버튼]을 누를 때만 온다. 14주차 2일차 따라하기에서 Fake의 10초 입력 이벤트를 기다리는 곳(1단계 5번, 5단계 4번의 '가만히 둔다', 6단계 8·9번, 13단계 표)은 시뮬레이터에서는 [입력 버튼]을 누른다.
- `value`는 시뮬레이터를 켠 뒤부터 센다. 아무도 연결되지 않았을 때 누른 것도 세므로, 앱이 받는 첫 이벤트가 `"value":0`일 수 있다.
- UDP 8267은 앞뒤 공백·줄바꿈을 뺀 글자가 `bleuno?`일 때만 답한다.

## 9. 수업에서 여럿이 쓸 때

같은 Wi-Fi에서 여러 명이 시뮬레이터를 켜면, 실기기의 [검색] 한 번에 반 전체의 시뮬레이터가 답할 것이다(예상). 그래서 각자 이름을 다르게 붙인다.

```powershell
py sim.py --name ESP32_BLE_0423
```

- 이름은 `ESP32_BLE_` 뒤에 **학번 뒤 4자리**를 붙인다. 학번이 20260423이면 `ESP32_BLE_0423`이다.
- `ESP32_BLE`로 시작해야 한다. 12~15주차 예제는 [검색] 결과를 `name.startsWith("ESP32_BLE")`로 거르므로 다른 이름은 목록에 들어가지 않는다. 대소문자도 같아야 한다. 이름이 맞지 않으면 시작 메시지에 `주의:` 줄이 나온다.
- 뒤 4자리가 같은 사람이 있으면 이니셜을 더 붙인다(예: `ESP32_BLE_0423_KM`).
- 목록에서 **내 이름**을 누른다. 남의 시뮬레이터를 누르면 그 사람 화면의 LED가 켜지고 그 사람 터미널에 내 명령이 찍힌다. 내 터미널에 `연결 (1개)` 줄이 찍혔는지 본다.
- 시뮬레이터 창은 내 PC에만 뜨고 HTTP API(8080)도 기본값으로 이 PC에서만 열리므로, 다른 사람이 내 화면의 버튼을 누를 수 없다. 수업 중에는 `--http-bind 0.0.0.0`을 쓰지 않는다.
- 학교 Wi-Fi가 기기끼리의 통신을 막아 두었으면(AP 격리) 실기기로는 [검색]도 연결도 되지 않는다. 이때는 에뮬레이터로 한다.

| 잘 되다가 앱이 `끊김` | 터미널의 마지막 두 줄을 본다. `[화면] 연결 끊기 (1개)` 다음에 `해제 (0개)`가 있으면 화면에서 [연결 끊기]를 누른 것이다. 맨 끝이 `종료`면 시뮬레이터가 꺼진 것이니 다시 켠다. 어느 경우든 앱에서 다시 연결한다 |
| 켜 둔 LED가 저절로 모두 꺼졌다 | 앱이 새로 붙었거나 연결이 끊긴 것이다. 시뮬레이터는 그때 LED를 모두 끈다([1절](#1-시뮬레이터가-대신하는-것)의 결정된 사항). 터미널에 `연결`·`해제` 줄이 찍혔는지 본다 |
| 응답은 `ok`인데 내 화면의 LED가 그대로다 | 다른 사람 시뮬레이터에 붙었을 수 있다. 내 터미널에 그 명령 줄이 찍혔는지 본다. `on 9`처럼 범위 밖 번호는 `ok`여도 아무것도 바뀌지 않는다 |
| 시뮬레이터 창이 보이지 않는다 | 터미널의 끝부분(마지막 서너 줄)을 본다. `pygame-ce 를 불러오지 못했다`, `시뮬레이터 창을 열 수 없다`, `포트를 열 수 없다` 가운데 하나가 있으면 그 줄을 이 표에서 찾는다. 셋 다 없고 마지막 줄이 `종료`가 아니면 시뮬레이터는 돌고 있다. 창이 다른 창 뒤에 있으니 작업 표시줄에서 찾는다 |
| 시뮬레이터 창이 저절로 닫혔다 | 시뮬레이터가 끝났다. 터미널의 `종료` 앞 줄을 본다 |
| 실기기에 넣을 IP를 모르겠다 | `이 PC의 IPv4 주소` 줄의 맨 앞 주소부터 넣어 본다. `(VPN?)`·`(자동 할당)`이 붙은 주소는 쓰지 않는다. `(자동 할당)`이 붙은 주소는 그 어댑터가 주소를 받지 못한 것이다. 앞 주소로 안 되거나 `(찾지 못함. ipconfig 로 확인)`이 나오면, Windows는 `ipconfig`의 `무선 LAN 어댑터 Wi-Fi:` 아래 `IPv4 주소`(영문 화면은 `IPv4 Address`)를, macOS는 `ipconfig getifaddr en0`의 결과를 쓴다 |
| 목록에 모르는 이름이 많다 | 같은 Wi-Fi의 다른 학생 시뮬레이터다. 내 이름을 고른다 |

오류 번호와 글자(`[WinError 10048] 각 소켓 주소…`, TCP는 `[Errno 10048] …`)는 Windows 언어나 운영체제에 따라 다르게 나온다. `포트를 열 수 없다`가 들어간 앞부분은 같다.
한 번에 한 곳만 바꾸고 다시 해 본다. 그래도 안 되면 터미널과 앱 화면을 그대로 보여 주고 도움을 받는다.

## 11. 다른 프로그램에서 쓰기

앱 대신 다른 프로그램(AI 에이전트, 시험 스크립트, 다른 언어의 클라이언트)이 시뮬레이터를 보드처럼 쓸 수 있다. 수업에는 필요 없다.

**명령(TCP 8266)**은 앱과 같다. 붙으면 hello 줄이 먼저 온다. 그다음 명령 한 줄(`\n`으로 끝)을 보내고 JSON 한 줄을 받는다. [입력 버튼]의 이벤트 줄은 아무 때나 끼어들므로, 받은 줄에 `event` 키가 있으면 응답이 아니라 이벤트로 다룬다.

```python
import json
import socket

with socket.create_connection(("127.0.0.1", 8266)) as s:
    f = s.makefile("rw", encoding="utf-8", newline="\n")
    print(json.loads(f.readline()))            # {"event":"hello",...}
    for cmd in ("on 0", "pwm 1 128", "dht11"):
        f.write(cmd + "\n")
        f.flush()
        reply = json.loads(f.readline())
        while "event" in reply:                # 입력 이벤트는 건너뛰고 응답을 기다린다
            reply = json.loads(f.readline())
        print(cmd, "→", reply)
```

HTTP API(8080)는 화면에서 하는 일을 프로그램으로 한다. 기본값으로 이 PC에서만 열린다.

| 요청 | 본문 | 응답 | 하는 일 |
|---|---|---|---|
| `GET /state` | 없음 | `{"leds":[255,128,0,0],"blink":false,"temperature":24.5,"humidity":40.0,"clients":1,"log":[…]}` | LED 밝기, 내장 LED 깜빡임, 온습도, 연결 수, 최근 로그 20줄 |
| `POST /set` | `{"temperature":30.5,"humidity":55}` (하나만 보내도 된다) | `{"result":"ok"}` | 슬라이더를 움직인 것과 같다. 값은 JSON 숫자만 받는다. 문자열(`"30"`)·`true`·NaN·Infinity·실수로 바꿀 수 없는 큰 수는 400이고 아무것도 바뀌지 않는다 |
| `POST /input` | 없음 | `{"result":"ok"}` | [입력 버튼]을 누른 것과 같다. 로그에는 `[API]`로 남는다 |
| `POST /drop` | 없음 | `{"result":"ok"}` | [연결 끊기]를 누른 것과 같다 |

그 밖의 주소는 404이고 본문은 `{"result":"fail","ms":"not found"}`다.

- `--http-bind 0.0.0.0`을 주면 같은 네트워크의 다른 기기에서도 HTTP API가 열린다. 그러면 누구나 [입력 버튼]·[연결 끊기]와 같은 일을 할 수 있다. Windows에서는 시뮬레이터를 돌리는 Python을 허용하는 규칙(방화벽 창의 [액세스 허용]으로 생기거나 7절의 네 줄로 바꾼 것)이 있을 때만 열린다. [7절](#7-windows-방화벽)의 포트 규칙만 만들었다면 8080은 막혀 있다. 이때도 시작 메시지의 `HTTP API:` 줄은 `http://127.0.0.1:8080/state`로 나온다.
- 화면이 없는 컴퓨터(원격 서버, 모니터 없이 도는 Linux 장비)에서는 `--no-window`로 실행한다. pygame-ce 없이 표준 라이브러리만 쓴다.
- uv를 쓰면 `uv run sim.py`로 실행할 수 있다. `sim.py` 머리의 `# /// script` 부분에 적은 pygame-ce를 uv가 받아 쓴다.
