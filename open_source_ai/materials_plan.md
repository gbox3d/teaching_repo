## 1. 목적과 범위

수업계획서의 4개 챕터·15주 구조를 기준으로 학생용 교재와 교수자용 강의 교안을
체계적으로 제작한다. 두 자료는 같은 학습목표와 실습을 공유하되 용도에 따라
내용을 분리한다.

- **교재**: 개념 설명, 따라 하기 실습, 확인문제, 과제 준비를 위한 학생용 자료
- **강의 교안**: 시간 배분, 설명 포인트, 시연 절차, 질문, 오류 대응을 포함한 교수자용 자료
- **실습 자료**: 시작 코드, 완성 예시, 데이터, 실행 명령과 검증 절차
- **평가 자료**: 4개 종합과제 안내서·루브릭과 수시·기말평가 출제 기준

오늘은 제작 계획만 수립한다. 교재 본문, 슬라이드, 실습 코드와 평가 문항은
후속 작업에서 작성한다.

## 2. 단일 기준과 문서 관계

| 문서·자료 | 역할 | 관리 원칙 |
|---|---|---|
| [`README.md`](README.md) | 공용 교재 진입점 | 공용 범위와 학교 적용 문서를 연결 |
| 해당 학교 수업계획서 (학교 저장소에서 관리) | 최초 적용 강좌 수업계획서 | 주차, 평가비율, 과제 시점의 단일 기준 |
| `materials_plan.md` | 제작 순서와 품질 기준 | 교재·교안 제작 진행상태 관리 |
| 교재 원고 | 학생용 개념·실습 자료 | 주차별 문서를 챕터 단위로 묶어 배포 |
| 강의 교안 | 교수자용 수업 진행 자료 | 교재를 복제하지 않고 페이지·실습 ID로 참조 |
| 실습 저장소 | 실행 가능한 예제와 과제 시작점 | 학생용 시작본과 교수자용 해설본 분리 |
| 참고자료 색인 | 출처·버전·라이선스 기록 | 공식 문서를 우선하고 중복 링크 제거 |

모든 콘텐츠에는 `C{챕터}-W{주차}` 형식의 ID를 사용한다. 예를 들어
1장 4주차 자료는 `C1-W04`로 표기하여 교재, 교안, 실습과 평가표에서 같은 ID로
상호 참조한다.

## 3. 예정 폴더 구조

실제 폴더와 파일은 콘텐츠 제작을 시작할 때 생성한다.

```text
materials/
├─ textbook/                 # 학생용 교재 원고
│  ├─ chapter-01/
│  ├─ chapter-02/
│  ├─ chapter-03/
│  └─ chapter-04/
├─ slides/                   # 주차별 강의 슬라이드 원본
├─ instructor-notes/         # 교수자용 진행안·시연·오류 대응
├─ labs/
│  ├─ starter/               # 학생 배포용
│  └─ solution/              # 교수자 해설용
├─ assessments/              # 과제 안내·루브릭·평가 기준
├─ assets/                   # 공용 그림·표·화면 캡처
└─ references/
   └─ index.md               # 출처·버전·라이선스 색인
```

## 4. 챕터별 제작 범위

| 챕터 | 주차 | 교재 핵심 범위 | 실습·시연 | 완료 관문 |
|---|---:|---|---|---|
| 1장. 오픈소스 협업과 로컬 AI 기초 | 1~4주 | OSS 생태계, Git/GitHub, 라이선스, 재현 가능한 Python 환경, Ollama | 협업 저장소 구성, 로컬 모델 실행, REST API 호출 | 1차 과제 패키지와 실행 검증 |

## 5. 주차별 자료 구성 표준

각 주차는 아래 항목을 한 세트로 작성한다.

### 학생용 교재

1. 학습목표 3~5개
2. 선수지식과 핵심 용어
3. 개념 설명과 구조도
4. 단계별 실습
5. 실행 결과와 검증 방법
6. 자주 발생하는 오류와 해결 단서
7. 확인문제와 자기점검
8. 다음 주차 또는 종합과제 연결
9. 출처, 버전, 라이선스

### 교수자용 강의 교안

1. 수업 전 준비사항과 환경 점검
2. 구간별 시간 배분
3. 반드시 설명할 핵심 메시지
4. 라이브 코딩·시연 스크립트
5. 학생 질문과 토론 프롬프트
6. 중간 이해도 확인 지점
7. GPU·네트워크 장애 시 대체 진행안
8. 과제 안내 및 다음 시간 예고

### 실습 자료

- Windows·NVIDIA RTX 4070 환경을 기본 검증 대상으로 한다.
- GPU를 사용할 수 없을 때 실행 가능한 소형 모델 또는 CPU 대체 경로를 둔다.
- 설치 명령, 의존성 버전, 예상 실행시간과 VRAM 사용량을 기록한다.
- API 키와 비밀정보는 예제에 포함하지 않고 `.env.example` 형식만 제공한다.
- 학생용 시작본과 해설·완성본을 분리한다.

## 6. 과제·평가 연계

과제는 매주 만들지 않고 각 챕터가 끝나는 시점에만 배치한다.

| 주차 | 종합과제 | 교재·교안에서 준비할 항목 | 배점 |
|---:|---|---|---:|
| 4주 | 협업 저장소·Ollama 로컬 API | 1장 실습 체크리스트, 제출 형식, 기본 루브릭 | 5% |
| 8주 | 라이선스 분석·RAG 미니프로젝트 | 출처·라이선스 표, RAG 품질 점검표, 수시평가 범위 | 5% |
| 12주 | PEFT/LoRA 실험·AI 서비스 베타 | 실험 기록 양식, 성능·자원 비교표, 서비스 검증표 | 10% |
| 15주 | 최종 오픈소스 릴리스 패키지 | 릴리스 체크리스트, 발표 기준, 최종 루브릭 | 10% |

과제가 없는 11개 주차에는 별도 제출물을 만들지 않는다. 해당 주차의 실습 결과는
다음 챕터 종합과제를 완성하기 위한 누적 작업으로만 활용한다.

## 7. 제작 단계

| 단계 | 작업 | 종료 조건 |
|---|---|---|
| 0. 기준 확정 | 템플릿, 콘텐츠 ID, 개발환경, 참고자료 색인 형식 확정 | 예시 주차 1개에 대한 구조 검토 |
| 1. 1장 제작 | 1~4주 교재·교안·실습·1차 과제 작성 | 새 PC와 RTX 4070에서 전체 실습 재현 |
| 2. 2장 제작 | 5~8주 자료와 2차 과제·수시평가 기준 작성 | 모델·데이터 출처와 라이선스 검토 |
| 3. 3장 제작 | 9~12주 자료와 3차 과제 작성 | 학습·추론 시간과 VRAM 사용량 검증 |
| 4. 4장 제작 | 13~15주 자료와 4차 과제·기말평가 기준 작성 | 릴리스·발표 전체 흐름 모의 실행 |
| 5. 통합 검수 | 용어, 링크, 코드, 난이도, 배점, 접근성 점검 | 15주 자료 색인과 배포본 확정 |

상세 일정은 대학 학사일정과 실제 개강일을 확인한 뒤 역산한다. 우선순위는
`1장 → 2장 → 3장 → 4장`으로 하며, 각 장은 실제 수업 최소 2주 전에 배포 가능한
상태로 만드는 것을 목표로 한다.

## 8. 품질 검수 기준

- [ ] 15개 주차가 각각 하나의 콘텐츠 ID로 색인되어 있다.
- [ ] 교재와 교안이 동일 내용을 중복 서술하지 않고 상호 참조한다.
- [ ] 4개 과제가 4·8·12·15주차에만 연결되어 있다.
- [ ] 명령과 코드는 깨끗한 Windows 환경에서 처음부터 재현된다.
- [ ] RTX 4070 실습의 모델 크기, 실행시간과 VRAM 기준이 현실적이다.
- [ ] 외부 코드·모델·데이터에 출처, 버전과 라이선스가 기록되어 있다.
- [ ] 링크와 화면 캡처는 제작 시점의 공식 문서를 기준으로 최신성을 확인했다.
- [ ] 실패 사례와 GPU·네트워크 장애 대체안이 교수자 교안에 포함되어 있다.
- [ ] 학생용 시작본에 정답, 토큰, 개인정보와 비밀정보가 포함되지 않는다.
- [ ] 평가 루브릭의 항목과 배점 합계가 수업계획서와 일치한다.
