## 1. 목적과 범위

수업계획서의 4개 챕터·15주 구조를 기준으로 학생용 교재와 교수자용 강의 교안을
체계적으로 제작한다. 두 자료는 같은 학습목표와 실습을 공유하되 용도에 따라
내용을 분리한다.

- **교재**: 개념 설명, 따라 하기 실습, 확인문제, 과제 준비를 위한 학생용 자료
- **강의 교안**: 시간 배분, 설명 포인트, 시연 절차, 질문, 오류 대응을 포함한 교수자용 자료
- **실습 자료**: 시작 코드, 완성 예시, 데이터, 실행 명령과 검증 절차
- **평가 자료**: 4개 종합과제 안내서·루브릭과 수시·기말평가 출제 기준

15주 초판(교재·슬라이드·실습·예제·평가 문서와 비공개 대본·해답)은 작성을 마쳤다.
남은 일은 환경 기준표 확정, 기준 PC 실측과 비공개 평가 패킷 작성이다.

콘텐츠 ID는 주차 폴더 이름(`weekNN_slug`)이다. 교재, 대본, 실습과 평가표는 모두 같은 폴더 이름으로 서로를 참조한다.

## 3. 폴더 구조

초안의 `materials/` 챕터 단위 구조 대신, 다른 과목과 같은 **주차 폴더 구조**를 채택했다.
학생용 교재·슬라이드·실습·예제·평가 문서는 공개 저장소에, 강의 대본과 실습 해답은 비공개 저장소의 같은 주차 폴더에 둔다.

```text
open_source_ai/
├─ README.md                 # 진입점
├─ materials_plan.md         # 이 문서
├─ ta_setup_guide.md         # 조교 설치 목록
└─ weeks/
   ├─ README.md              # 운영 기준·주차 목록·검증용 기본값
   └─ weekNN_slug/
      ├─ README.md           # 학습 질문·목표·3블록 흐름·완료 기준
      ├─ slides.md           # Marp 원고 (20분 × 3)
      ├─ lab.md              # 실습 문제 (30분 × 3)
      ├─ walkthrough.md      # 1·3·4·7·10·12주차
      ├─ examples/           # uv 프로젝트·템플릿
      └─ 평가 문서            # 4·8·9·12·15주차

(비공개) teaching_materials_private/open_source_ai/weeks/weekNN_slug/
      ├─ lecture_script.md   # 20분 × 3 강의 대본
      └─ lab_solution.md     # 실습 해답
```

콘텐츠 ID `C{챕터}-W{주차}`는 주차 폴더 이름(`weekNN_*`)으로 대체한다.

## 5. 주차별 자료 구성 표준

각 주차는 아래 항목을 한 세트로 작성한다.

### 학생용 교재

1. 학습목표 3~5개
2. 선수지식과 핵심 용어
3. 개념 설명과 구조도
4. 단계별 실습
5. 실행 결과와 검증 방법
6. 자주 발생하는 오류와 해결 단서
7. 확인문제와 자기점검
8. 다음 주차 또는 종합과제 연결
9. 출처, 버전, 라이선스

### 교수자용 강의 교안

1. 수업 전 준비사항과 환경 점검
2. 구간별 시간 배분
3. 반드시 설명할 핵심 메시지
4. 라이브 코딩·시연 스크립트
5. 학생 질문과 토론 프롬프트
6. 중간 이해도 확인 지점
7. GPU·네트워크 장애 시 대체 진행안
8. 과제 안내 및 다음 시간 예고

### 실습 자료

- Windows·NVIDIA RTX 4070 환경을 기본 검증 대상으로 한다.
- GPU를 사용할 수 없을 때 실행 가능한 소형 모델 또는 CPU 대체 경로를 둔다.
- 설치 명령, 의존성 버전, 예상 실행시간과 VRAM 사용량을 기록한다.
- API 키와 비밀정보는 예제에 포함하지 않고 `.env.example` 형식만 제공한다.
- 학생용 시작본과 해설·완성본을 분리한다.

## 6. 과제·평가 연계

| 8주 | 라이선스 분석·RAG 미니프로젝트 | [`weeks/week08_midterm/assignment_brief.md`](weeks/week08_midterm/assignment_brief.md), 실기평가 구조·루브릭 |

각 루브릭은 100점 상대 배점이다. 실제 성적 비율과 마감은 학교 운영 문서가 정한다.

과제가 없는 11개 주차에는 별도 제출물을 만들지 않는다. 해당 주차의 실습 결과는
다음 챕터 종합과제를 완성하기 위한 누적 작업으로만 활용한다.

상세 일정은 대학 학사일정과 실제 개강일을 확인한 뒤 역산한다. 우선순위는
`1장 → 2장 → 3장 → 4장`으로 하며, 각 장은 실제 수업 최소 2주 전에 배포 가능한
상태로 만드는 것을 목표로 한다.

## 8. 품질 검수 기준

- [ ] 15개 주차가 각각 하나의 콘텐츠 ID로 색인되어 있다.
- [ ] 교재와 교안이 동일 내용을 중복 서술하지 않고 상호 참조한다.
- [ ] 4개 과제가 4·8·12·15주차에만 연결되어 있다.
- [ ] 명령과 코드는 깨끗한 Windows 환경에서 처음부터 재현된다.
- [ ] RTX 4070 실습의 모델 크기, 실행시간과 VRAM 기준이 현실적이다.
- [ ] 외부 코드·모델·데이터에 출처, 버전과 라이선스가 기록되어 있다.
- [ ] 링크와 화면 캡처는 제작 시점의 공식 문서를 기준으로 최신성을 확인했다.
- [ ] 실패 사례와 GPU·네트워크 장애 대체안이 교수자 교안에 포함되어 있다.
- [ ] 학생용 시작본에 정답, 토큰, 개인정보와 비밀정보가 포함되지 않는다.
- [ ] 평가 루브릭의 항목과 배점 합계가 수업계획서와 일치한다.

## 9. 다음 작업 시작점

15주 초판은 [`weeks/README.md`](weeks/README.md)에서 시작한다. 개강 전에 남은 작업은 다음과 같다.

1. 환경 기준표에서 Python·uv·Ollama·PyTorch·CUDA·모델 ID·양자화 값을 확정한다.
2. 기준 PC(RTX 4070)에서 각 주차 `examples/`의 `uv lock`을 생성해 커밋하고, 4·6·7·10·11·12주차의 실행시간·VRAM 실측값을 README 기록 칸에 채운다.
3. 8주차 실기평가의 비공개 패킷(문항·fixture·정답)과 15주차 기말 검증 패킷을 비공개 저장소에 작성한다.
4. 강의 대본을 낭독 리허설해 20분 분량을 조정하고, 학교 운영 문서에 실제 배점·마감·분반 정보를 연결한다.
