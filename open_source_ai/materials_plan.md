## 1. 목적과 범위

수업계획서의 4개 챕터·15주 구조를 기준으로 학생용 교재와 교수자용 강의 교안을
제작한다. 두 자료는 같은 학습목표와 실습을 공유하되 용도에 따라
내용을 분리한다.

- **교재**: 개념 설명, 따라 하기 실습, 확인문제, 과제 준비를 위한 학생용 자료
- **강의 교안**: 시간 배분, 설명 포인트, 시연 절차, 질문, 오류 대응을 포함한 교수자용 자료
- **실습 자료**: 시작 코드, 완성 예시, 데이터, 실행 명령과 검증 절차
- **평가 자료**: 4개 종합과제 안내서·루브릭과 수시·기말평가 출제 기준

15주 초판(교재·슬라이드·실습·예제·평가 문서와 비공개 대본·해답)은 작성을 마쳤다.
현재 개편 결과와 남은 실습실 검증·평가 운영 준비는 10절에 정리했다.

## 3. 폴더 구조

초안의 `materials/` 챕터 단위 구조 대신, 다른 과목과 같은 **주차 폴더 구조**를 채택했다.
학생용 교재·슬라이드·실습·예제·평가 문서는 공개 저장소에, 강의 대본과 실습 해답은 비공개 저장소의 같은 주차 폴더에 둔다.

```text
open_source_ai/
├─ README.md                 # 진입점
├─ materials_plan.md         # 이 문서
├─ ta_setup_guide.md         # 조교 설치 목록
└─ weeks/
   ├─ README.md              # 운영 기준·주차 목록·검증용 기본값
   └─ weekNN_slug/
      ├─ README.md           # 학습 질문·목표·3블록 흐름·완료 기준
      ├─ slides.md           # Marp 원고 (20분 × 3)
      ├─ lab.md              # 실습 문제 (30분 × 3)
      ├─ walkthrough.md      # 1·3·4·7·10·12주차
      ├─ examples/           # uv 프로젝트·템플릿
      └─ 평가 문서            # 4·8·9·12·15주차

(비공개) teaching_materials_private/open_source_ai/weeks/weekNN_slug/
      ├─ lecture_script.md   # 20분 × 3 강의 대본
      └─ lab_solution.md     # 실습 해답
```

콘텐츠 ID `C{챕터}-W{주차}`는 주차 폴더 이름(`weekNN_*`)으로 대체한다.

## 5. 주차별 자료 구성 표준

각 주차는 아래 항목을 한 세트로 작성한다.

### 학생용 교재

1. 학습목표 3~5개
2. 선수지식과 핵심 용어
3. 개념 설명과 구조도
4. 단계별 실습
5. 실행 결과와 검증 방법
6. 자주 발생하는 오류와 해결 단서
7. 확인문제와 자기점검
8. 다음 주차 또는 종합과제 연결
9. 출처, 버전, 라이선스

### 교수자용 강의 교안

1. 수업 전 준비사항과 환경 점검
2. 구간별 시간 배분
3. 반드시 설명할 핵심 메시지
4. 라이브 코딩·시연 스크립트
5. 학생 질문과 토론 프롬프트
6. 중간 이해도 확인 지점
7. GPU·네트워크 장애 시 대체 진행안
8. 과제 안내 및 다음 시간 예고

### 실습 자료

- Windows·NVIDIA RTX 4070 환경을 기본 검증 대상으로 한다.
- GPU를 사용할 수 없을 때 실행 가능한 소형 모델 또는 CPU 대체 경로를 둔다.
- 설치 명령, 의존성 버전, 예상 실행시간과 VRAM 사용량을 기록한다.
- API 키와 비밀정보는 예제에 포함하지 않고 `.env.example` 형식만 제공한다.
- 학생용 시작본과 해설·완성본을 분리한다.

## 8. 품질 검수 기준

- [ ] 15개 주차가 각각 하나의 콘텐츠 ID로 색인되어 있다.
- [ ] 교재와 교안이 동일 내용을 중복 서술하지 않고 상호 참조한다.
- [ ] 4개 과제가 4·8·12·15주차에만 연결되어 있다.
- [ ] 명령과 코드는 깨끗한 Windows 환경에서 처음부터 재현된다.
- [ ] RTX 4070 실습의 모델 크기, 실행시간과 VRAM 기준이 현실적이다.
- [ ] 외부 코드·모델·데이터에 출처, 버전과 라이선스가 기록되어 있다.
- [ ] 링크와 화면 캡처는 제작 시점의 공식 문서를 기준으로 최신성을 확인했다.
- [ ] 실패 사례와 GPU·네트워크 장애 대체안이 교수자 교안에 포함되어 있다.
- [ ] 학생용 시작본에 정답, 토큰, 개인정보와 비밀정보가 포함되지 않는다.
- [ ] 평가 루브릭의 항목과 배점 합계가 수업계획서와 일치한다.

## 9. 다음 작업 시작점

15주 초판은 [`weeks/README.md`](weeks/README.md)에서 시작한다. 개강 전에 남은 작업은 다음과 같다.

1. 환경 기준표에서 Python·uv·Ollama·PyTorch·CUDA·모델 ID·양자화 값을 확정한다.
2. 기준 PC(RTX 4070)에서 각 주차 `examples/`의 `uv lock`을 생성해 커밋하고, 4·6·7·10·11·12주차의 실행시간·VRAM 실측값을 README 기록 칸에 채운다.
3. 8주차 실기평가의 비공개 패킷(문항·fixture·정답)과 15주차 기말 검증 패킷을 비공개 저장소에 작성한다.
4. 강의 대본을 낭독 리허설해 20분 분량을 조정하고, 학교 운영 문서에 실제 배점·마감·분반 정보를 연결한다.

## 10. 10~15주차 개편안 (2026-11-12)

### 시뮬레이터 제어와 성능 평가를 연결한다

10~13주차는 작은 모델이 사용자의 요청을 함수 호출로 바꾸어 시뮬레이터를 제어하는 수업으로 재작성한다.
4주차의 툴 호출, 7주차의 파인튜닝, 9주차의 Streamlit을 다시 사용한다.
14주차에는 대학 소개 챗봇의 과제·보고서 규칙과 공개 평가 문제를 안내하고,
15주차에는 제출한 프로그램을 비공개 문제로 평가한다.
이번 공개 적용 과제는 사용자 지시에 따라 원광대학교 소개 챗봇으로 작성한다.
실제 강좌 배점·마감·학생 자료와 비공개 정답은 학교 운영 문서에 둔다.

| 주차 | 1교시 | 2교시 | 3교시 | 수업에서 확인할 결과 |
|---:|---|---|---|---|
| 10 | Python 함수로 시뮬레이터 제어 | Ollama 툴 호출에 같은 함수 연결 | 고정 16문항으로 제어 확인 | 자연어 입력 → 함수·인자 → 실제 LED 상태 |
| 11 | 초소형 툴 호출 모델로 교체 | Ollama·Needle 정확도와 시간 비교 | 도구 설명을 바꾸어 제어 실험 | 크기와 속도만으로 모델을 고를 수 없는 이유 |
| 12 | 명령과 정답 호출로 학습 데이터 구성 | 짧은 파인튜닝·저장 | 복원 후 학습 전후 비교 | 보지 않은 표현에서 호출과 인자가 맞는지 확인 |
| 13 | 제어 성공률을 계산하는 평가 | 오호출·인자 오류를 찾아 개선 | Streamlit에서 제어·결과 확인 | 개선 전후 수치와 시뮬레이터 상태를 함께 설명 |
| 14 | 대학 소개 챗봇 과제·보고서 규칙 | 공개 평가 실행과 실패 분석 | RAG·프롬프트 등 한 요소 개선 | 같은 평가로 변경 효과 확인 |
| 15 | 제출 버전·환경 확인 | 챗봇의 비공개 성능 평가 | 개발 보고서 검토 | 기존 발표·레포트 항목을 각각 성능·개발 내용으로 평가 |

교시마다 설명·시연 20분, 실습 30분, 휴식 10분을 유지한다.
모델 설치와 다운로드는 수업 전에 끝내고, 필수 실습에서는 한 모델만 학습한다.
기존 10~13주차 프로젝트 제안·데이터 평가·서비스 배포·CI 원고는 [선택 자료](specials/project_delivery/README.md)에 보존한다. 이전 14주차 릴리스 원고는 Git 이력에 남는다.
실행 안내·의존성 고정·출처·라이선스 기록은 새 프로젝트에도 포함한다.

### 시뮬레이터는 기존 도구를 재사용한다

대상은 [`tools/bleuno-sim`](../tools/bleuno-sim/README.md)이다.
자연어 요청을 `turn_on(index)`, `turn_off(index)`, `set_brightness(index, value)`,
`read_environment()` 같은 짧은 함수로 연결한다. 이 함수들은 공용 제어 코드에 구현했다.
실제 시뮬레이터 명령은 TCP의 `on`, `off`, `pwm`, `dht11`이다.

LED 제어는 TCP 연결을 유지한 채 실행한다. 연결하거나 끊을 때 LED가 초기화되므로
함수 호출마다 새 연결을 만들지 않는다. HTTP `GET /state`는 결과 확인에,
`POST /set`은 평가할 온습도 조건을 만드는 데 쓴다.
센서 값을 바꾸는 평가 도구와 모델에 제공할 제어 함수를 구분한다.

LED 번호 0~3과 밝기 0~255를 함수에서 검사하고, 등록된 함수만 실행한다.
시뮬레이터의 `ok` 응답만으로 성공을 판단하지 않는다. 범위 밖 LED 번호에도 `ok`가 올 수 있으므로
실제 상태와 목표 상태를 대조한다. 모호한 요청이나 지원하지 않는 요청에서 임의로 실행하지 않는지도 평가한다.

### 모델 후보와 검증 순서

| 후보 | 수업에서 맡길 역할 | 확인한 범위와 남은 검증 |
|---|---|---|
| 기존 Ollama 모델 | 4주차와 같은 방식의 기준 구현 | `qwen3.5:2b` 도구 호출·반복 입력·실제 LED 제어 확인 |
| Needle 3 | 함수와 인자 출력, 작은 제어용 모델의 파인튜닝 | `cactus-compute 4.2.0`으로 Mac CPU 추론·학습·저장·복원 확인. Windows·수업 GPU 환경 검증은 별도 |
| Kev-0.8B | 미리 정한 행동 중 하나를 고르는 결정 모델 비교 | 공식 카드가 일반 툴 호출 판단과 영어 외 언어를 권장 범위에서 제외한다. 제어용 데이터로 학습·평가한 뒤 채택 여부를 정한다 |
| 사용자 언급 모델 `lyya` | 정확한 모델 확인 후 결정 | 정확한 이름이 확인되지 않아 필수 실습에 넣지 않음 |

Needle을 필수 실습 모델로 사용한다. Kev는 역할·입출력·사용 범위를 비교하는 선택 자료로 둔다.
모든 후보를 학생이 각각 설치·학습하게 하지 않는다.
학생은 제공된 작은 데이터의 표현·인자·호출하지 않는 예를 고치며,
교수자가 준비한 데이터 전체를 처음부터 작성하게 하지 않는다.
짧은 학습으로 성능이 반드시 올라간다고 가정하지 않는다.

2026-11-12 공식 문서 확인 기준이다. 다음 링크의 안내와 실제 수업 PC 실행 결과는 구분한다.

- [Needle 3 공식 소개](https://cactuscompute.com/needle): 함수 호출과 구조화 출력.
- [Needle 로컬 파인튜닝 안내](https://cactuscompute.com/blog/finetuning-needle): JAX 기반 LoRA 학습·내보내기. 로컬 학습본은 기본 배포본과 양자화 조건이 다르고 confidence가 없으므로, 속도 비교에 조건을 적고 동일한 신뢰도 임곗값을 적용하지 않는다.
- [Kev-0.8B 모델 카드](https://huggingface.co/jaredpalmer/kev-0.8b): 선택지별 확률을 출력하는 0.8B 결정 모델과 사용 범위.

제어 평가에서는 함수 선택 정확도, 인자 정확도, 최종 상태 성공률,
호출하면 안 되는 요청의 오호출률을 나누어 기록한다.
모델 준비 시간과 준비 후 요청 처리 시간을 분리하고, 같은 PC·입력·도구 목록에서
중앙값과 느린 요청의 시간(p95)을 비교한다. 함수 선택이 틀린 빠른 응답도 실패로 센다.
학습 전후 비교는 같은 기본 모델·입력·출력 조건을 사용한다.

### 대학 소개 챗봇은 기준을 공개하고 최종 문항을 분리한다

학생은 RAG, 파인튜닝, 프롬프트, 검색·분류 알고리즘을 자유롭게 조합한다.
모든 기법을 썼는지가 아니라 같은 조건에서 질문을 얼마나 정확하게 해결했는지 평가한다.

공식 대학 자료의 기준일과 문서 ID를 고정해 학생에게 제공한다.
답할 수 있는 정보의 범위, 답이 없는 경우의 처리, 허용 모델·외부 API·인터넷 사용,
평가 PC·시간 제한·제출 방식도 과제 안내 때 공개한다.
공용 평가 함수는 질문을 받아 답변과 출처 문서 ID를 돌려주는 형태로 단순화하고,
Streamlit 화면과 별도로 호출할 수 있게 한다.

공개 연습 20문항을 제공하고 비공개 최종 40문항 초안을 별도로 작성했다.
두 평가셋 모두 단일 문서 사실 확인, 여러 근거 연결, 자료에 없는 정보·잘못된 전제의 처리를 포함한다.
비공개 문제도 공개한 자료와 난이도 범위에서 출제한다.
공개 문장을 조금 바꾼 문제에만 의존하지 않고, 질문 의도·표현·정보 조합을 검토해 나눈다.
학생은 공개 문제와 직접 만든 문제로 반복 개선하고, 비공개 정답과 개별 결과는 제출 버전 확정 전까지 제공하지 않는다.

평가 항목·산식·부분점수 기준은 전부 공개한다. 질문별로 필요한 사실과 허용 표현,
틀리면 안 되는 사실, 근거 문서를 정해 둔다.
정답 문장과 문자열이 같은지만 검사하거나 LLM 평가 점수 하나로 최종 점수를 정하지 않는다.
사실·출처 대조를 자동화하고, 의미가 같지만 자동 판정이 갈리는 답변은 원자료로 재검토한다.
전부 답변을 거절하는 프로그램이 유리해지지 않도록 답할 수 있는 문제와 없는 문제를 나누어 집계한다.

성능 점수는 비공개 평가를 중심으로 산출하고 공개 점수는 개선용으로 사용한다.
2026-11-12 후속 지시로 **기존 발표 점수는 AI 성능 평가로 대체하고 레포트 점수는 개발 보고서로 별도 평가**한다.
기존 발표·레포트 성적 비율은 유지한다. 앞서 제안한 성능 80%·보고서 20% 통합안은 사용하지 않는다.
성능에는 사실 정확성·근거의 적합성·답변 불가 처리의 정확성을 반영하고,
보고서에는 기준 구현, 바꾼 요소, 전후 수치, 실패 사례, 선택 이유를 요구한다.
응답 시간은 먼저 공통 제한과 관찰 지표로 두고 학생 PC 성능으로 점수를 나누지 않는다.
실제 성적 환산 방식과 학습 과정 평가에 적용할 학교 공통 원칙은 학교 운영 문서에서 함께 확정한다.

비공개 문항·정답·채점용 근거는 학교 비공개 저장소에만 둔다.
제출 버전과 평가셋을 고정한 뒤 같은 환경에서 평가하고, 평가 문항의 오류를 정정하면
모든 제출물에 같은 정정을 적용한다. 이 개편안에는 실제 비공개 문항이나 정답을 포함하지 않는다.

### 재작성 순서와 완료 조건

1. 시뮬레이터와 기존 Ollama 모델을 연결해 입력·제어·다음 입력·종료를 확인한다.
2. Needle의 한국어 호출, 짧은 학습, 저장·복원, 학습 전후 결과를 수업 PC에서 검증한다. 설치나 학습이 수업 시간을 넘으면 예제 범위를 줄이고 준비된 학습본으로 비교하는 경로를 둔다.
3. 검증한 모델과 입력 범위로 10~13주차 README·실습지·슬라이드·따라하기·예제를 재작성한다. 예제 구조는 5주차 규격의 주차별 uv 프로젝트 하나를 따른다.
4. 공통 자료 범위·평가 함수·공개 문제를 먼저 만들고 14주차 과제 안내와 15주차 평가를 맞춘다. 학교별 비공개 평가셋은 별도 보관한다.
5. 12·15주차 종합과제, 주차 색인, 설치 안내, 한영 슬라이드와 비공개 강의 대본·해설을 새 흐름에 맞춘다. 14주차 안내를 별도 종합과제로 중복 집계하지 않는다.

14~15주차에는 기말과제 안내·보고서 양식·두 평가 기준과 한영 슬라이드를 작성하고,
공식 출처 요약 5개, 공개 질문·정답 20문항, 같은 채점 함수를 재사용하는 공개 도구를 제공한다.
10~13주차는 주차별 단일 uv 프로젝트와 `tools/bleuno-control` 공용 코드로 구성한다.
Mac M1 Max CPU에서 48개 예제·4 epochs·batch 4의 학습·저장에 약 339.4초가 걸렸다.
같은 20층·4비트 조건의 미학습 16문항 제어 성공률은 기본 9/16, 학습 후 10/16이었다.
실행 가능한 예제의 기준값이며 성능 향상을 보장하지 않는다. 한국어 실패·오호출·형식 오류 분석을 실습에 포함한다.
학교 실습실의 Windows·GPU 실행과 실제 운영 환경·배점·마감 확정은 남아 있다.
비공개 최종 40문항은 학교 비공개 폴더에 보관했다. 공개 자료 범위·문항 중복·허용 표현·채점 산식의 합성 검증을 마쳤다.
최종 출제 검토와 학생 프로그램의 격리 실행 검증은 별도로 진행한다. 실제 학생 성적은 산출하지 않았다.
