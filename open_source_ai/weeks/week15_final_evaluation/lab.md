# 15주차 실습 — 원광대 소개 챗봇 평가와 개발 레포트

14주차의 프로젝트·공개 평가 결과를 이어 사용한다. 과제와 제출 규칙은 [과제 안내](../week14_chatbot_project/assignment_brief.md), 입출력과 채점 규칙은 [평가 명세](../week14_chatbot_project/evaluation_spec.md), 실행법은 [공개 평가 도구 안내](../week14_chatbot_project/examples/README.md)를 따른다. 개발 내용은 [레포트 양식](../week14_chatbot_project/report_template.md)에 정리한다.

## 프로젝트 준비

기존 프로젝트의 코드·자료·실험 기록을 보존한다. 처음 시작하는 경우에는 [공개 평가 도구 안내의 프로젝트 준비](../week14_chatbot_project/examples/README.md)에 따라 Python 3.12를 지정해 uv 패키지 프로젝트를 만들고, `.python-version`, `pyproject.toml`, `src/` 구조를 확인한다. 교시마다 새 프로젝트를 만들거나 평가 도구를 복사하지 않는다. 모델·의존성 다운로드는 수업 전에 준비한다.

발표 리허설이나 릴리스 검증 도구 대신 공개 평가 도구를 사용한다. 최종평가에 쓸 제출본의 확정 시점과 제출 방법은 과제 정본과 학교 운영 공지를 따른다.

## 1교시 실습 — 공개 결과와 제출본 확인

설명·시연 20분에는 평가 결과의 사실 답변, 근거 문서, 답변 불가, 형식 오류를 구분해 읽는다. 다음 30분은 아래 순서로 진행한다.

| 시간 | 활동 | 기록 |
|---|---|---|
| 0~5분 | 제출할 코드·자료·모델과 평가 도구의 버전을 확인 | 제출본과 환경 정보 |
| 5~15분 | 정본의 명령으로 공개 평가 실행 | 문항별 출력과 점수 |
| 15~25분 | 오답·근거 오류·답변 불가 처리·형식 오류를 구분 | 실제 출력, 예상과 다른 부분, 확인한 원인 |
| 25~30분 | 레포트의 전후 비교가 같은 조건인지 확인 | 바꾼 요소와 유지한 조건 |

평가 함수는 질문을 받아 짧은 사실 목록, 근거 문서 ID 목록, 답변 불가 여부를 반환한다. 키 이름과 타입, 정규화·허용 별칭은 [평가 명세](../week14_chatbot_project/evaluation_spec.md)에서 확인한다. 자연스러운 긴 설명이나 화면 캡처만으로 평가용 반환값을 대신하지 않는다.

### 확인할 내용

- 답할 수 있는 질문에서 필요한 사실과 해당 사실의 근거 문서 ID가 함께 나오는지 본다.
- 자료로 답할 수 없는 질문에서 답변 불가를 표시하고 답과 근거 목록을 비우는지 본다.
- 오류가 있다면 프로그램의 실제 반환값과 평가 결과를 나란히 읽는다. 원인을 확인하지 못한 경우에는 추정과 다음 확인 방법을 구분해 적는다.
- 공개 점수가 올라도 비공개 성능이 보장되는 것은 아니다. 개선 이유를 질문·검색 결과·답변의 변화로 설명한다.

평가가 끝난 뒤 10분 휴식한다. 오류 사례 개수를 채우기 위해 없는 실패를 만들어 적지 않는다.

## 2교시 실습 — 비공개 최종평가와 구현 설명

설명·시연 20분에는 최종 제출본의 평가 절차를 확인한다. 학생은 공개 규칙을 알고 준비하며, 평가자는 같은 규격의 비공개 문항을 같은 환경에서 실행한다. 평가 중 문항·정답을 학생용 자료나 공개 저장소에 복사하지 않는다.

| 시간 | 학생 활동 | 평가자 확인 |
|---|---|---|
| 0~10분 | 제출본과 실행 안내가 일치하는지 확인 | 제출본·도구·평가셋·환경 기록 |
| 10~25분 | 공개 실험 기록을 보며 구현 흐름과 선택 이유 정리 | 비공개 평가 실행과 문항별 원출력 보존 |
| 25~30분 | 확인하지 못한 동작과 남은 한계 표시 | 실행 장애·판정 오류 여부 확인 |

학생은 질문이 들어온 뒤 자료 선택, 답 생성, 근거 연결, 답변 불가 판단이 어디서 이루어지는지 자신의 구현으로 설명한다. 사용하지 않은 기법을 추가할 필요는 없다. RAG·파인튜닝·프롬프트·검색 중 특정 방법을 썼다는 사실 자체는 가점 조건이 아니다.

응답 시간은 보고용으로 기록한다. 공개 도구는 문항당 30초 제한을 적용하며, 환경·준비 시간·초과 시 처리는 [평가 명세](../week14_chatbot_project/evaluation_spec.md)를 따른다. 학생 PC의 속도나 발표 시간으로 성능 점수를 나누지 않는다.

평가자가 확인할 자동 판정 오류와 환경 장애는 구현 오류와 구분한다. 확정 제출본은 보존하고, 비공개 결과에 맞춰 코드를 바꾼 뒤 원래 제출본처럼 취급하지 않는다. 실행이 끝나지 않았거나 원인을 확인하지 못했으면 그 상태를 기록한다. 이후 10분 휴식한다.

## 3교시 실습 — 개발 레포트와 제출 확인

설명·시연 20분에는 [개발 레포트 루브릭](assignment_rubric.md)을 읽는다. 다음 30분에는 [레포트 양식](../week14_chatbot_project/report_template.md)의 각 설명을 실제 코드·공개 실험 기록과 대조한다.

| 시간 | 활동 | 확인할 근거 |
|---|---|---|
| 0~8분 | 목적·설계와 구현 설명 점검 | 대상 질문, 선택 이유, 주요 처리 흐름 |
| 8~20분 | 개선 실험과 결과 해석 점검 | 기준 구현, 바꾼 요소, 같은 조건의 전후 결과, 오류 관찰 |
| 20~26분 | 한계·재현·출처 점검 | 남은 문제, 실행 절차, 자료·모델·코드·AI 도구 사용 내역 |
| 26~30분 | 프로그램과 레포트 제출 정보 대조 | 과제 정본의 제출 항목, 제출본 일치 |

성능이 개선되지 않은 실험도 원인 관찰과 다음 검증 방법을 구체적으로 설명한다. 실패나 미완성을 숨기지 않고, 실행하지 않은 결과를 성공으로 적지 않는다. 레포트는 글 길이나 화면 수가 아니라 구현 이해와 실제 시도·수정·검증의 근거로 평가한다. 실습 뒤 10분 휴식한다.

## 제출 전 확인

- [ ] 프로그램의 실행법과 반환 형식을 과제·평가 정본과 대조했다.
- [ ] 공개 연습 점수와 비공개 최종평가를 구분했다.
- [ ] 레포트의 수치·화면·설명이 제출본 및 실제 실험과 일치한다.
- [ ] AI 도구를 사용했다면 적용한 부분과 직접 이해·수정·검증한 부분을 적었다.
- [ ] 공개 자료에 비공개 문항·정답, 토큰, 학생 개인정보가 포함되지 않았다.
- [ ] 과제 정본의 방법으로 프로그램과 레포트를 제출했다.

발표 영상, 정해진 길이의 구두 발표, 릴리스 태그, CI 결과, 동료 리뷰 기록을 추가 필수 제출물로 요구하지 않는다.
