# 1교시 · 설명 20분
## 최종 평가 준비

---

## 0–3분 · 발표 점수와 레포트 점수

| 성적 항목 | 이번 주 확인할 근거 |
|---|---|
| 발표 점수 | 제출한 챗봇의 비공개 문제 AI 성능 평가 점수 |
| 레포트 점수 | 개발정리 보고서의 구현·변경·검증 설명 |

기존 발표·레포트 배점을 각각 적용한다.
발표 말솜씨·발표 시간은 채점하지 않는다.
학교 배점·마감·제출 경로는 확정 공지를 따른다. 이 자료에서 정하지 않는다.

---

## 3–7분 · 같은 도구와 비공개 문항

14주차의 [평가 명세](../week14_chatbot_project/evaluation_spec.md)를 그대로 적용한다.

- API: `student_bot.answer(question)`
- 반환값: `answers`·`sources`·`abstain`
- 문서·모델·생성 조건·평가기·정규화 규칙 고정
- 최종 평가 문항과 정답은 비공개로 관리

`uv run evaluate`는 공개 연습 평가의 별칭이다.
학생용 명령을 실행했다고 비공개 최종 평가가 완료되는 것은 아니다.

---

## 7–11분 · 제출본과 실행 조건 확인

평가자가 실행할 파일과 보고서에 적은 파일이 같아야 한다.

| 확인 항목 | 남길 근거 |
|---|---|
| 코드 | 제출본 식별 정보와 `student_bot.answer`의 변경 위치 |
| 프로젝트 | Python 3.12, `pyproject.toml`, `uv.lock` |
| 평가 조건 | 배포 문서·평가기·모델·생성 설정의 기준 버전 |
| 실행 | 같은 입력의 반환값과 오류 여부 |

최종 평가 중에는 제출본을 바꾸지 않는다. 환경 문제는 담당자에게 기록해 알린다.

---

## 11–15분 · 기존 프로젝트의 재현

처음 만든 구조를 다시 확인한다. 기존 폴더에 재초기화하지 않는다.

```sh
uv init --package --python 3.12 --vcs none wku-bot
```

이번 주에도 14주차 `examples/`의 같은 프로젝트를 사용한다.
`.python-version`·`src/`·`pyproject.toml`·`uv.lock`을 대조한다.
명령은 `[project.scripts]`에서 `main()`으로 연결되고 `uv_build`로 설치한다.
실행은 `uv sync --frozen`, scripts 변경 뒤에는 `uv sync`를 사용한다.

---

## 15–18분 · 최종 평가 전 공개 점검

같은 프로젝트에서 실행한다.

```sh
uv sync --frozen
uv run ex03
uv run ex02
```

연속 질문·빈 입력·종료와 반환값 형식을 확인한다.
공개 평가 결과를 14주차 기록과 비교하고 제출본 식별 정보를 적는다.
학생 PC 속도는 성적 항목이 아니다. 응답시간과 환경은 보고서에 기록한다.

---

## 18–20분 · 1교시 실습 인계

[14주차 실행 안내](../week14_chatbot_project/examples/README.md)를 이어 쓴다.

1. 제출할 코드와 환경 파일을 확인한다.
2. 공개 평가를 다시 실행하고 결과와 제출본을 연결한다.
3. 실행 오류가 있으면 명령·메시지·발생 단계를 기록한다.

실습 30분 후 휴식 10분. 다음 교시에 같은 제출본을 최종 평가한다.

# 2교시 · 설명 20분
## 비공개 성능 평가

---

## 0–3분 · 비공개 평가의 진행

평가자는 확정한 제출본에 같은 평가기를 적용한다.

1. 코드와 고정 환경을 확인한다.
2. 비공개 문항을 `student_bot.answer`에 한 문항씩 전달한다.
3. 반환 형식·사실·근거·답변 보류를 같은 규칙으로 채점한다.
4. 문항별 점수와 전체 평균, 실행 상태를 보관한다.

문제와 정답을 학생 코드나 공개 교재에 복사하지 않는다.
실행 절차 설명은 가능하며 발표 말솜씨·시간의 채점은 없다.

---

## 3–7분 · 최종 평가의 고정 조건

| 고정 항목 | 적용 원칙 |
|---|---|
| 입력·근거 자료 | 같은 평가셋 버전과 다섯 요약 문서 |
| 실행 | 같은 평가기·모델·생성 조건·평가 환경 |
| 판정 | 같은 별칭·NFKC·공백 정규화·시간 제한 |
| 집계 | 모든 문항의 산술평균, 0점 문항 포함 |

평가자는 모든 제출본에 같은 조건을 적용한다.
학생 PC 성능에는 점수를 주지 않는다. 응답시간은 기록만 한다.

---

## 7–11분 · 문항 점수의 재확인

| 문항·상태 | 점수 |
|---|---|
| `fact`·`composite` | 80 × 사실 F1 + 20 × 근거 F1 |
| 사실 F1이 0 | 근거 점수도 0 |
| `unknown` | 보류 `true` + 답·근거 빈 배열이면 100, 그 외 0 |
| 형식·실행 오류·30초 초과 | 해당 문항 0 |

F1은 정답 집합과 반환 집합의 일치 정도다. 등록 별칭·정규화를 적용한다.
80/20은 문항 성능의 내부 비율이며 레포트와 합치는 비율이 아니다.

---

## 11–15분 · 오류 기록과 평가 결과의 구분

- 형식 오류·시간 초과: 해당 문항 0점을 포함해 기록
- 사실·근거·보류 오류: 평가기가 계산한 결과를 그대로 기록
- 설치·실행 환경 장애: 발생 단계와 메시지를 담당자에게 전달

환경 장애와 챗봇의 오답을 섞어 임의로 점수를 바꾸지 않는다.
재실행이 필요하면 담당자가 같은 기준으로 처리하고 원인을 남긴다.
학생이 비공개 정답을 보고 제출본을 고치는 절차는 제공하지 않는다.

---

## 15–18분 · 성능 결과의 확인

결과에는 제출본 식별 정보, 평가 조건, 문항별 결과와 전체 평균이 연결된다.

공개 연습 점수와 비공개 최종 점수를 구분해 적는다.
공개에서 잘 맞았다는 이유로 비공개 점수를 대신하지 않는다.
응답시간은 환경과 함께 보고하며 별도 속도 가산점은 없다.

평가자가 공개한 결과만 보고서에 적는다.
비공개 문제·정답은 공개 저장소나 보고서 예시에 넣지 않는다.

---

## 18–20분 · 2교시 실습 인계

1. 확정한 제출본으로 담당자의 비공개 평가 절차에 참여한다.
2. 평가 완료·진행 중·환경 장애 중 실제 상태를 기록한다.
3. 제공된 결과가 자신의 제출본과 일치하는지 확인한다.

대기 중에는 공개 실험 기록과 보고서를 정리한다.
완료하지 않은 평가의 점수를 예상해서 적지 않는다.
실습 30분 후 휴식 10분.

## 0–3분 · 보고서의 구성

[보고서 양식](../week14_chatbot_project/report_template.md)과 [평가 기준](assignment_rubric.md)을 대조한다.

| 보고서 평가 항목 | 지표 배점 | 확인 근거 |
|---|---:|---|
| 목적·설계 | 25 | 질문·자료 범위와 선택 이유 |
| 구현 이해 | 25 | 처리 흐름과 직접 확인한 코드 |
| 개선 실험 | 30 | 기준·변경·같은 조건의 전후 결과 |
| 한계·재현·출처 | 20 | 남은 문제, 실행법, 자료·AI 사용 |

보고서 자체의 100점 지표다. 학교 레포트 배점은 기존 기준을 따른다.
성능 점수와 별도 평가하며 글 길이나 발표 말솜씨는 기준이 아니다.

---

## 3–7분 · 변경과 수치를 연결한다

| 변경 요소 | 수정 전 | 수정 후 | 근거 |
|---|---|---|---|
| 직접 바꾼 처리 | 실제 측정값 | 실제 측정값 | 같은 공개 평가의 출력 |

기준 구현, 바꾼 파일·함수, 바꾼 이유를 먼저 적는다.
전체 평균뿐 아니라 영향을 받은 문항과 유형별 결과를 함께 읽는다.
평가셋·문서·모델·생성 조건을 고정했는지 밝힌다.
측정하지 않은 칸은 ‘미측정’으로 두고 이유를 쓴다.

---

## 7–11분 · 실패와 선택 이유

공개 문항 한 건의 질문·실제 반환값·정답 근거를 나란히 놓는다.

“정확도가 낮다” 대신 빠진 사실이나 잘못 붙인 문서 ID를 짚는다.
원인을 확인한 부분과 추정한 부분을 나누고 다음 확인 방법을 적는다.

변경을 채택한 이유, 되돌린 이유, 시도하지 못한 이유를 설명한다.
수치가 오르지 않았어도 실제 시도와 검증을 기록한다.
공개 실패 사례로 설명하며 비공개 정답을 보고서에 옮기지 않는다.

---

## 11–15분 · 재현·출처·AI 사용 기록

- 재현: 제출본, Python 3.12, 의존성, 실행 명령과 실제 결과
- 출처: 배포 문서 ID와 공식 URL, 추가로 참고한 자료
- AI 사용: 도구명, 도움받은 파일·범위, 수정·검증한 내용

AI가 파일을 직접 생성·수정한 경우도 사용 내역에 적는다.
AI 사용 자체보다 본인이 설명하고 확인한 작업을 구분한다.
사용하지 않았다면 그렇게 적는다. 비밀키·개인정보는 넣지 않는다.

---

| 개발정리 보고서 | 기준 구현·변경·수치·실패·이유·재현·출처·AI 사용 |
