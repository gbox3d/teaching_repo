# 개발 레포트 루브릭 — 0~100 지표

원광대 소개 챗봇을 개발한 목적·설계·구현 이해·개선 실험을 별도로 평가한다. 기존 레포트 항목에 적용하며, 기존 발표 항목을 대체하는 [AI 성능 지표](presentation_rubric.md)와 합산 비율을 새로 정하지 않는다. 실제 성적 환산은 학교의 기존 레포트 배점을 따른다.

과제 범위와 제출 방법은 [과제 안내](../week14_chatbot_project/assignment_brief.md), 작성 양식은 [개발 레포트 양식](../week14_chatbot_project/report_template.md)을 따른다. 실험 수치는 [평가 명세](../week14_chatbot_project/evaluation_spec.md)와 [공개 평가 도구](../week14_chatbot_project/examples/README.md)를 기준으로 읽는다.

## 평가 항목

| 항목 | 배점 | 충분히 갖춘 근거 | 부족한 경우 확인할 부분 |
|---|---:|---|---|
| 목적·설계 | 25 | 원광대 소개 챗봇의 대상 질문과 자료 범위, 답변·근거·답변 불가 처리 방침을 설명하고 구현 방식의 선택 이유를 연결한다 | 목표가 실제 구현과 다른지, 선택 이유 없이 도구 이름만 나열했는지 |
| 구현 이해 | 25 | 질문에서 자료 선택·답 생성·근거 반환까지의 흐름과 주요 코드의 역할을 자신의 구현으로 설명한다. 직접 확인·수정한 부분을 코드 위치나 실행 기록과 연결한다 | 결과 화면만 있고 동작 이유가 없는지, 설명이 코드와 다른지, 가져온 코드를 이해했다는 근거가 있는지 |
| 개선 실험 | 30 | 기준 구현과 바꾼 요소를 밝히고 같은 조건의 전후 결과를 비교한다. 사실·근거·답변 불가·형식 오류를 구분해 관찰하고 결과의 원인과 남은 질문을 설명한다 | 조건이 달라 비교가 어려운지, 수치만 있고 원인 관찰이 없는지, 실제 결과와 해석이 다른지 |
| 한계·재현·출처 | 20 | 남은 한계와 확인하지 못한 부분, 재실행에 필요한 환경·절차, 자료·모델·참고 코드의 출처와 이용 조건을 적는다. AI 도구 사용 시 적용 범위와 직접 검증한 내용을 구분한다 | 검증하지 않은 동작을 단정했는지, 실행 단계가 빠졌는지, 출처·활용 범위가 불명확한지 |
| 합계 | 100 | 각 항목의 확인 근거에 따라 합산한다 | |

## 판단 기준

각 항목은 실제 확인한 근거에 따라 0점부터 해당 배점까지 평가한다. 항목 만점은 요구 내용과 정확한 설명을 갖추고 고쳐야 할 오류·필수 누락이 없을 때 부여한다. 일부만 확인되면 해당 부분을 인정하고, 남은 누락·오류의 위치와 중요성을 근거로 부분점수를 정한다. 확인할 근거가 없을 때에는 그 사유를 기록한다.

레포트 전체 만점도 요구 내용과 정확한 설명을 모두 갖춘 경우에만 부여한다. 성능 자체가 낮거나 개선 실험에서 점수가 오르지 않았다는 이유만으로 레포트 점수를 낮추지 않는다. 비교 조건, 실제 시도, 오류 관찰, 수정·검증, 구체적인 질문과 해석이 평가 근거다. 반대로 성능 점수가 높거나 완성 결과만 있다는 이유만으로 구현 이해와 실험 설명을 인정하지 않는다.

짧아도 정확한 설명은 인정하며 본문·코드 주석·첨부 설명을 함께 읽는다. 글 길이, 맞춤법, 화면 수, 모델 크기, 질문 수, 특정 개발 기법의 사용 여부로 점수를 정하지 않는다. 실패 사례나 추가 실험의 개수를 채우도록 과제 밖 요구를 덧붙이지 않는다.

## 일관성과 학습 과정 확인

- 같은 성취·누락·오류에는 같은 기준을 적용한다. 같은 원인을 여러 항목에서 중복 감점하지 않는다.
- 교재·예제의 공통 설명과 학생이 추가로 연결한 이해·선택·관찰을 구분한다. 예제 사용이나 AI 도구 사용 자체를 감점 사유로 삼지 않는다.
- AI가 생성한 결과를 사용한 사실과 제출물 전체를 수정 없이 옮긴 사실을 구분한다. 문체·유사도만으로 사용이나 무이해를 단정하지 않는다.
- 오답·미완성이어도 성의 있는 시도·질문·검증을 인정한다. 공통 채점 원칙의 기본점수와 학습 노력 기준은 학교 성적 처리에서 적용하며, 이 0~100 지표에 5·6·7점을 임의로 비례 환산하지 않는다.
- 미제출은 제출 후 미완성과 구분한다. 자동 평가 점수나 레포트 합계만으로 검토 없이 최종 성적을 확정하지 않는다.

## 피드백과 평가 기록

피드백에는 제출물에서 확인한 행동과 그 점수의 이유를 구체적으로 적는다. 감점할 때는 부족한 위치, 왜 필요한지, 어떻게 수정하고 확인할지를 설명한다. 학생의 질문에는 개념·예시·다음 확인 방법으로 답한다. 만점에는 확인한 성취와 만점 근거를 쓰고, 없는 부족을 만들어 덧붙이지 않는다.

| 기록 항목 | 내용 |
|---|---|
| 평가 대상 | 제출본과 레포트 식별 정보 |
| 목적·설계 | /25, 원문·코드·첨부 위치, 확인한 설명, 남은 부족 |
| 구현 이해 | /25, 실제 처리 흐름과 학생 설명의 대조 |
| 개선 실험 | /30, 전후 조건·수치·관찰·질문과 해석 |
| 한계·재현·출처 | /20, 재현 정보·한계·출처·AI 활용 범위 |
| 레포트 지표 | /100, 항목 합계와 점수 근거 |
| 학생 피드백 | 확인한 성취, 감점 이유와 보완·확인 방법, 질문 답변 |
| 학교 성적 처리 | 기존 레포트 배점, 공통 채점 원칙 적용 근거, 확인자 |

학생 식별정보와 평가 기록은 학교의 비공개 보관 위치에서 관리한다.
