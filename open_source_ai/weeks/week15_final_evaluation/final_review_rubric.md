# 기말 최종평가 — 성능·개발 레포트 확인 절차

원광대 소개 챗봇의 최종평가는 두 축으로 기록한다. 기존 발표 항목은 AI 성능으로 대체하고, 기존 레포트 항목은 개발 레포트로 별도 평가한다. 이 문서는 평가 결과를 확인하는 절차이며 세 번째 점수나 추가 기말 배점을 만들지 않는다.

14주차에 규칙·공개 평가셋·공개 도구를 안내하고, 15주차에 같은 규격의 비공개 최종평가를 진행한다. 평가 함수와 문항·도구가 정본과 일치하는지 확인한 뒤 평가를 시작한다. 예전 릴리스 검증 도구나 CI 결과로 챗봇 성능 평가를 대신하지 않는다.

## 평가 절차

1. 과제 정본에 따라 제출 프로그램과 레포트를 확인한다. 제출본, 자료·모델, 실행 방법, 제출 시점을 기록하고 미제출과 제출 후 실행 실패를 구분한다.
2. 평가 명세의 도구·평가셋·환경·제한을 확인한다. 모든 제출물에 같은 조건을 적용하고 평가 환경 장애는 별도로 기록한다.
3. 확정 제출본을 비공개 평가셋으로 실행한다. 원출력, 문항별 판정·점수, 전체 평균, 응답 시간을 보존한다. 비공개 정답과 문항은 공개 자료에 넣지 않는다.
4. 형식 오류, 정답·별칭·근거 오류, 도구 오류와 환경 장애를 구분해 검토한다. 정정이 필요하면 같은 영향을 받는 제출물 전체에 적용하고 변경 전후를 보존한다.
5. 레포트의 본문·코드 주석·첨부·학생 질문을 읽고 실제 구현 및 공개 실험 기록과 대조한다. 목적·설계 25, 구현 이해 25, 개선 실험 30, 한계·재현·출처 20으로 근거를 기록한다.
6. 비슷한 성취·누락·오류를 제출물끼리 비교한다. 공통 교재와 예제를 제외한 유사 부분은 근거를 남기되 유사도·문체만으로 표절이나 AI 전재를 단정하지 않는다.
7. 성능 지표와 레포트 지표를 각각 기록하고 학교의 기존 발표·레포트 배점 및 공통 채점 원칙에 맞춰 성적을 검토한다. 학교의 승인·저장 절차를 따른다.

## 성적 환산과 피드백

두 축은 각각 0~100 지표다. 학교 수업계획서의 기존 발표·레포트 비율을 각각 유지한다. 사실 문항의 답·근거 80·20 배점은 문항 내부 산식이며 성적 항목 비율과 구분한다.

자동 계산값의 산술 확인, 원자료 읽기, 점수와 피드백의 일관성 검토, 유사 제출 검토, 학교 성적 저장 확인은 별개다. 자동 평가 통과만으로 학습 이해나 최종 성적 검토가 끝났다고 판단하지 않는다. 공통 채점 원칙의 기본점수와 노력·질문 기준을 이 지표에 임의로 비례 환산하지 않는다.

낮은 성능과 성의 있는 학습 과정은 함께 존재할 수 있다. 레포트에서는 실제 시도·오류 관찰·수정·질문·검증을 인정한다. 반대로 높은 성능만으로 정확한 구현 설명이 있다고 추정하지 않는다. 레포트 만점은 요구 내용과 정확한 설명을 모두 갖추고 실제로 고쳐야 할 사항이 없을 때 부여한다.

피드백에는 확인한 성취, 해당 점수의 근거, 질문의 답, 부족한 부분의 수정·확인 방법을 적는다. 만점 피드백에는 없는 보완점을 덧붙이지 않는다. 발표 시간·말솜씨·릴리스 태그·CI 통과 여부를 점수 조건으로 되살리지 않는다.

## 평가 기록

| 항목 | 기록할 내용 |
|---|---|
| 대상 | 과목·과제·학생 또는 팀, 제출본·레포트 식별 정보 |
| 적용 기준 | 과제·평가 명세·도구·평가셋의 버전과 실행 환경 |
| AI 성능 | 비공개 전체 문항 평균 /100, 문항별 근거, 보고용 응답 시간 |
| 개발 레포트 | 목적·설계 /25, 구현 이해 /25, 개선 실험 /30, 한계·재현·출처 /20, 합계 /100 |
| 원자료 검토 | 읽은 본문·첨부·코드 설명·질문, 확인 방법과 확인하지 못한 부분 |
| 일관성·유사성 검토 | 비교 대상·공통 자료 제외 범위·확인 근거·판단 한계 |
| 정정 | 사유, 영향 범위, 수정 전후 결과, 재평가 기록 |
| 성적 환산 | 학교의 기존 발표·레포트 배점, 공통 원칙 적용 근거, 승인·저장 확인 |
| 피드백 | 학생에게 전달할 문안과 근거 |

평가 기록과 비공개 문항·정답은 학교의 비공개 보관 위치에 남긴다. 공개 저장소에는 규칙·공개 도구·공개 평가 자료만 둔다.
