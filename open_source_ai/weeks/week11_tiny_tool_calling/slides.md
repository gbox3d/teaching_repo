# 1교시 · 설명 20분
## Needle3 도구 호출

---

## 0–3분 · 호출 제안 모델 교체

10주차의 제어 함수·검증·상태 조회를 유지한다.
호출을 제안하는 모델만 Needle3로 바꾼다.

같은 입력으로 차이를 관찰한다.
초소형 모델의 품질·속도를 미리 보장하지 않는다.

---

## 3–6분 · Needle3와 호출 출력

Needle3는 도구 호출을 제안하는 초소형 모델이다.
수업 패키지는 `cactus-compute==4.2.0`이다.

`complete()`가 `function_calls`를 반환한다.
이 수업은 기준 2bit 엔진을 사용한다.

[공식 Python 문서](https://cactuscompute.com/blog/needle-python-docs)

---

## 6–9분 · Python 프로젝트와 실행 준비

Python 3.12, 한 `examples/` 프로젝트, `ex01`~`ex03`.
`main()`·scripts·`uv_build`, 변경 뒤 `uv sync`.

전체 clone에서 주차 `shared`가 `bleuno_control`을 import한다.
모델과 패키지 다운로드는 수업 전에 마친다.

시뮬레이터는 별도 터미널에서 유지한다.

---

## 9–12분 · 도구 목록과 문항 독립

```python
agent = Cactus(tools=tools, auto_date=False)
agent.reset()
result = agent.complete(text)
```

`tools`는 네 함수의 명세 목록이다.
`reset()`은 모델 이력 초기화다. LED 복원은 별도다.

---

## 12–15분 · 호출 검증과 실제 상태

`function_calls`의 이름·인수를 Python에서 검사한다.
검증을 통과하면 네 함수 중 해당 함수를 실행한다.

`run()` 자동 호출은 사용하지 않는다.
TCP 8266 연결 유지, `hello`·이벤트 행 제외.
HTTP 8080의 `GET /state`로 실제 결과를 읽는다.

---

## 15–18분 · 빈 호출과 confidence

빈 호출은 실행할 함수가 없다는 뜻이다.
입력에 따라 올바른 거부 또는 호출 누락이다.

`confidence`는 모델의 신뢰도 출력이다.
정답 비율·상태 일치는 별도로 측정한다.

높은 신뢰도만으로 성공을 판정하지 않는다.

---

## 18–20분 · 1교시 실습 인계

`uv run ex01`에서 영어·한글 명령을 입력한다.
LED 켜기·밝기·끄기·온습도를 관찰한다.

없는 기능과 정상 기능의 빈 호출을 구분한다.
실제 제안·검증·상태를 기록한다.

실습 30분, 휴식 10분.

# 2교시 · 설명 20분
## 결정 모델과 같은 입력 비교

---

## 0–3분 · Kev의 영어 선택지 판단

Kev-0.8B는 영어 상태와 주어진 선택지를 읽는다.
선택지별 확률을 반환하는 결정 모델이다.

예: 제시된 요청을 LED 제어·센서 조회·기타로 분류.
이 예는 출력 형식 설명이며 실행 결과가 아니다.

[Kev 공식 카드](https://huggingface.co/jaredpalmer/kev-0.8b)

---

## 3–6분 · 선택 판단과 일반 도구 호출

| 비교 | Needle 도구 호출 | Kev 결정 모델 |
|---|---|---|
| 출력 | 함수 이름과 인수 | 주어진 선택지의 확률 |
| 실습 | 직접 실행·평가 | 공식 카드 선택 소개 |

Kev 카드는 영어 외 언어·도구 호출 라우팅을 범위 밖으로 둔다.
이번 주 성능표에는 Kev 실측값을 넣지 않는다.

---

## 6–9분 · 같은 16문항의 비교

`uv run ex02`: Ollama `qwen3.5:2b`와 Needle3.

공용 평가셋: 한글 8·영어 8.
호출 10·무호출 6.

입력·도구·기대값을 유지한다.
모델 하나에만 추가 힌트를 주지 않는다.

---

## 9–12분 · 초기 조건과 추론 시간

LED는 매 문항 `[0, 64, 128, 255]`로 복원한다.
Needle는 `reset()`으로 문항을 독립시킨다.

예열 1회는 점수·시간에서 제외한다.
모델 준비 시간은 별도로 기록한다.
추론 구간의 median·p95를 비교한다.

---

## 12–15분 · 오류를 나누는 평가 항목

함수 선택 정확도.
이름·인수·순서의 전체 호출 완전 일치.
완전 일치와 실제 상태의 제어 성공률.
무호출 문항 오호출률.

언어별 문항과 실패 근거도 함께 읽는다.

---

## 15–18분 · 실측 결과 해석

| 모델 | 성공 | 오호출 | median | p95 |
|---|---|---|---|---|
| Ollama | 9/16 | 4/6 | 296.2ms | 658.2ms |
| Needle3 | 10/16 | 1/6 | 60.6ms | 179.9ms |

M1 Max, CPU 학습 종료 후, 출력 한도 256토큰. 준비·예열 제외.
p95는 16개 중 최댓값이다. 한글 실패도 남긴 단일 실행 관찰이다.
[상세 조건·오류·언어별 결과](lab.md#수업-준비-실측)

---

## 18–20분 · 2교시 실습 인계

`uv run ex02`로 두 모델을 평가한다.

문항별 제안·상태와 다섯 평가 항목을 기록한다.
차이가 난 입력의 근거를 설명한다.
Kev의 선택 판단과 일반 도구 호출을 구분한다.

실습 30분, 휴식 10분.

# 3교시 · 설명 20분
## 도구 설명 변경

---

## 0–3분 · 도구 설명과 모델 가중치

도구 설명은 모델 입력의 일부다.
설명을 바꾸어도 모델 가중치를 학습하지는 않는다.

이번 교시는 같은 Needle3에 설명만 바꾼다.
함수·인수·Python 검증은 유지한다.

---

## 3–6분 · DESCRIPTIONS의 한 항목

`ex03_descriptions`의 `DESCRIPTIONS`를 읽는다.

영어 기능 설명을 같은 뜻의 한국어로 바꾼다.
또는 번호·밝기 범위를 명시한다.
한 번에 한 조건만 바꾼다.

입력 언어까지 동시에 바꾸지 않는다.

---

## 6–10분 · 새 인스턴스로 재실행

기준 설명에서 `uv run ex03`을 실행하고 기록한다.
종료한 뒤 설명을 수정하고 같은 명령으로 시작한다.

도구 명세를 바꾸면 새 `Cactus(...)`가 필요하다.
`reset()`은 기존 도구 정의를 교체하지 않는다.

각 입력의 제안과 실제 상태를 대조한다.

---

## 10–14분 · 정상 요청과 무호출 요청 재검사

같은 정상 입력에서 이름·인수·상태를 비교한다.
범위 밖 번호·밝기, 센서 쓰기 요청도 확인한다.

불리언 거부와 네 함수 제한은 유지한다.
모델에게 `POST /set`을 제공하지 않는다.

바꾼 설명이 다른 문항을 망가뜨렸는지도 읽는다.

---

## 14–17분 · 변경 근거와 관찰 기록

수정한 설명 원문과 수정 이유.
같은 입력의 변경 전후 호출·실제 상태.
개선·악화·변화 없음의 근거.

정답을 바꾸거나 불리한 문항을 빼지 않는다.
confidence를 실측 정확도로 옮기지 않는다.

---

## 17–20분 · 3교시 실습 인계

`uv run ex03`에서 기준 결과를 먼저 남긴다.
`DESCRIPTIONS` 한 항목을 수정하고 재실행한다.

정상·무호출 입력을 같은 조건으로 비교한다.
설명 수정과 가중치 학습의 차이를 적는다.

실습 30분, 휴식 10분.
