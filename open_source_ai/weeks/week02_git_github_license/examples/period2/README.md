# 2교시 — 짝 저장소에 제안하고 리뷰 받기

[실습지 2교시](../../lab.md#2교시-실습--짝-저장소에-제안하고-리뷰-받기)의 **Issue·PR 양식**이다.
[.github](.github/)를 개인 저장소의 `.github`에 넣는다. 기존 파일이 있으면 내용을 먼저 비교한다.

| 단계 | 파일 | 확인 |
|---|---|---|
| 준비·Issue | [.github/ISSUE_TEMPLATE/proposal.md](.github/ISSUE_TEMPLATE/proposal.md) | 새 Issue에 제안 양식 |
| 문제 1 · PR | [.github/PULL_REQUEST_TEMPLATE.md](.github/PULL_REQUEST_TEMPLATE.md) | 관련 Issue·확인 방법 |
| 확장 | [CONTRIBUTING_sample.md](CONTRIBUTING_sample.md) | 팀의 기여 절차 초안 |

개인 저장소에서 템플릿을 commit·push한 뒤 Issue→Fork→branch→PR→리뷰 순서를 따른다.
Python 명령은 없다. 완료 증거는 실습지의 Issue·PR URL과 리뷰·수정 기록이다.
네트워크가 없으면 파일·브랜치·리뷰 문장까지 준비하고 GitHub 작업은 연결 후 진행한다.

## 실습 시간표

| 단계 | 시간 | 활동 |
|---|---:|---|
| 문제·예상 | 0–4분 | 짝 정하기, 템플릿 설치·push, 저장소 URL 교환 |
| Issue·Fork | 4–10분 | 짝 저장소에 Issue 등록, fork, fork clone |
| 브랜치·PR | 10–17분 | branch, README 수정, push, 템플릿 채운 PR |
| 리뷰·수정 | 17–25분 | 짝 PR에 코멘트·수정 요청, 내 PR 수정 push, merge |
| 검증·기록 | 25–30분 | URL 2개 기록, 상태 문장 |

시간은 설명·시연 20분 뒤 시작하는 **실습 30분 기준**이다. 휴식 10분은 별도다.
