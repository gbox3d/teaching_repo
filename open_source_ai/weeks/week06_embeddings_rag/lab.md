# 6주차 실습 — 신화 50편으로 만드는 검색과 RAG

## 준비

Python 버전과 패키지 구조를 먼저 확인한다. 4·5주차와 같은 구조를 Python 3.12로 직접 만든다.

```powershell
New-Item -ItemType Directory -Force "C:\classwork" | Out-Null
Set-Location C:\classwork
uv init --package --python 3.12 --vcs none my-rag
Set-Location my-rag
uv add langchain-ollama
uv run my-rag
```

`Hello from my-rag!`가 나오면 성공이다. `.python-version`, `pyproject.toml`의 `[project.scripts]`·`[build-system]`, `src/my_rag/__init__.py`의 `main()`을 열어 본다. `uv add`가 `dependencies`에 패키지를 적어 넣은 것도 확인한다. 교재 예제는 이 구조에 명령 여섯 개와 `shared` 패키지를 더한 것이다.

교재의 `examples` 전체를 개인 실습 폴더에 복사하고 그 루트에서 명령을 실행한다. 세 교시는 같은 프로젝트를 이어 쓴다.

```powershell
$src = "<교재 저장소>\open_source_ai\weeks\week06_embeddings_rag\examples"
$dst = "C:\classwork\week06"
Copy-Item -Recurse $src $dst
Set-Location $dst
uv sync
ollama list
```

`ollama list`에 `qwen3.5:2b`와 `bge-m3`가 모두 있어야 한다. 없으면 수업 전에 `ollama pull bge-m3`로 받는다. scripts를 수정하면 `uv sync`를 다시 실행한다. 바꿔 보는 값은 모두 각 파일 맨 위의 대문자 상수다. 명령행 옵션은 없다.

## 1교시 실습 — 임베딩과 신화 검색

| 시간 | 활동 |
|---|---|
| 0–5분 | 프로젝트와 두 모델 확인, `uv run ex01` |
| 5–12분 | 내 문장 세 개의 유사도 보기 |
| 12–22분 | `uv run ex02`로 신화 검색, `TOP_K` 변경 |
| 22–30분 | 표현을 바꾼 질문 비교와 기록 |

1. `uv run ex01`을 실행한다. 첫 줄의 숫자 개수(1024)와 앞 다섯 숫자를 적는다. `헤라는 결혼의 여신이다.`를 입력하고 다섯 기준 문장의 유사도 순서를 본다. 신화 문장 세 개가 위에, 점심·파이썬 문장이 아래에 오는지 확인한다.
2. `오늘 저녁 메뉴는 라면이다.`, `변수는 값을 담는 상자다.`를 차례로 입력하고 1위 문장이 각각 무엇인지 적는다. 빈 줄을 입력해 건너뛰는지 확인하고 `/bye`로 종료한다.
3. [ex01](examples/src/ex01_embed/__init__.py)의 `SENTENCES`에 자기 문장 하나를 추가하고 다시 실행한다. 추가한 문장을 그대로 입력하면 1위는 자기 자신(1.000)이고, 그 아래 순서가 새 문장과 가까운 순서다. 어느 문장이 2위인지 적는다.
4. `uv run ex02`를 실행한다. 신화 50편을 저장하는 데 몇 초 걸린다. `메두사를 죽인 영웅은 누구야?`를 입력하고 세 결과의 제목과 점수를 적는다. 1위가 페르세우스 글이 아니어도 세 편 모두 메두사와 관련 있는지 본다.
5. `겨울이 생긴 이유를 설명하는 신화는?`을 입력한다. 1위 점수가 0.5 아래이고 제목이 엉뚱할 것이다. 같은 내용을 `페르세포네가 석류 씨를 먹어서 생긴 일은?`으로 바꿔 입력하고 1위와 점수를 비교한다. 검색은 질문의 표현과 가까운 글을 찾는다는 점을 한 문장으로 적는다.
6. 종료 후 [ex02](examples/src/ex02_search/__init__.py)의 `TOP_K`를 1로 바꿔 다시 실행하고, 같은 질문에서 무엇이 사라졌는지 적는다. 원래 값 3으로 되돌린다.

완료 조건: 벡터 길이와 유사도 순서를 실제 값으로 기록하고, 표현을 바꾼 두 질문의 1위 차이를 설명한다.

## 2교시 실습 — 자료를 넣어 답하기

| 시간 | 활동 |
|---|---|
| 0–10분 | `uv run ex03`으로 자료 없는 답과 자료 넣은 답 비교 |
| 10–20분 | `uv run ex04`에서 출처 확인, 자료에 없는 질문 |
| 20–27분 | `RULES` 한 줄 바꿔 다시 실행 |
| 27–30분 | 기록 |

1. `uv run ex03`을 실행하고 `헤라클레스의 열두 과업 중 다섯 번째는 무엇이야?`를 입력한다. `자료 없이>` 답과 `자료 넣고>` 답을 모두 적고, [myths.md](examples/src/shared/data/myths.md)의 「헤라클레스의 열두 과업」을 열어 어느 답이 맞는지 확인한다.
2. `메두사를 죽인 영웅은 누구야?`와 자기가 고른 신화 질문 하나를 더 입력한다. 자료 넣은 답에 찾은 자료 세 편 중 질문과 무관한 글의 내용이 섞여 들어갔는지 본다. `/bye`로 종료한다.
3. `uv run ex04`를 실행하고 `아탈란테와의 경주에서 히포메네스는 무엇을 던졌어?`, `로마는 기원전 몇 년에 세워졌어?`를 입력한다. 답과 `[출처]` 줄의 1위 제목·점수를 적는다.
4. `토르의 망치 이름은 무엇이야?`와 `해리 포터의 지팡이는 어떤 나무로 만들었어?`를 입력한다. 답이 `자료에 없습니다.`인지, `[출처]` 점수가 3번보다 낮은지 비교한다. 자료에 없는 질문도 검색은 항상 세 편을 돌려준다는 점을 적는다.
5. 종료 후 [ex04](examples/src/ex04_rag_chat/__init__.py)의 `RULES`에서 `자료에 답이 없을 때만 "자료에 없습니다."라고 답한다.` 문장을 지우고 4번 질문을 다시 한다. 질문마다 모델이 답을 지어내는지, 다른 말로 없다고 하는지 실제 답을 기록한 뒤 원래 문장을 되돌린다.
6. `week06_note.md`에 자료 없는 답과 넣은 답의 차이, 거부 규칙을 뺐을 때의 차이를 각각 한 문장으로 적는다. 모델은 그대로이고 프롬프트에 넣은 자료만 달라졌다는 점을 포함한다.

완료 조건: 같은 질문의 두 답을 자료 파일과 대조해 비교하고, 자료에 없는 질문의 거부와 출처 점수를 기록한다.

## 3교시 실습 — 긴 글 나누기와 내 문서 도우미

| 시간 | 활동 |
|---|---|
| 0–10분 | `uv run ex05`, `CHUNK_SIZE` 150·1000 비교 |
| 10–18분 | `uv run ex06`으로 두 파일에 질문 |
| 18–27분 | 내 글을 자료 폴더에 넣고 질문 |
| 27–30분 | 기록 |

1. `uv run ex05`를 실행한다. 첫 줄의 글자 수와 조각 수(300자 기준 19개)를 적고, 조각 2의 끝과 조각 3의 시작이 겹치는 것을 화면에서 확인한다. `아이올로스가 준 선물은 무엇이었어?`를 입력해 어느 조각이 1위인지 본다.
2. 종료 후 [ex05](examples/src/ex05_chunk/__init__.py)의 `CHUNK_SIZE`를 150으로, 다음에는 1000으로 바꿔 같은 질문을 반복한다. `CHUNK_OVERLAP`은 50 그대로 둔다. 세 크기의 조각 수와 1위 조각 번호·점수를 표로 적고, 조각이 아주 작거나 아주 클 때 1위 점수가 어떻게 되는지 한 문장으로 적는다. 원래 값 300으로 되돌린다.
3. `uv run ex06`을 실행한다. 파일별 조각 수(`myths.md` 45개, `odyssey.md` 12개)를 적고 `오디세우스는 칼립소의 섬에 몇 년 있었어?`를 입력한다. `[출처]`에 두 파일이 섞여 나오는지 본다.
4. `나우시카는 누구야?`를 입력한다. 나우시카 이야기는 `odyssey.md#7` 조각에 있다(조각 500자 기준). 나우시카는 파이아케스 왕 알키노오스의 딸이다. 답이 틀렸거나 `자료에 없습니다.`이면 `[출처]`에 `odyssey.md#7`이 있는지 본다. 없으면 검색이 놓친 것이고, 있으면 모델이 놓친 것이다. 어느 쪽인지 적는다.
5. 메모장으로 자기 글 한 편(수업 노트, 동아리 규칙, 좋아하는 작품 줄거리 등 열 문장 이상)을 직접 쓴다. [다른 이름으로 저장]에서 파일 형식은 `모든 파일(*.*)`, 인코딩은 `UTF-8`을 고르고 `src/shared/data/` 안에 `my_note.md`처럼 `.md`로 저장한다. 실제 이름·연락처·계정 정보는 넣지 않는다. 책·웹의 문장을 옮긴 글은 자기 PC에서만 시험한다. 다시 실행해 파일별 조각 수에 내 파일이 나오는지 확인하고, 그 글에 대해 두 가지를 질문한다.
6. `week06_note.md`에 조각 크기 비교표, 내 글의 파일명과 질문·답·출처를 적고 개인 저장소에 커밋한다. 직접 쓴 글이 아니면 원문 출처(책·사이트 이름)를 적고 그 글 파일은 커밋하지 않는다.

완료 조건: 조각 크기 세 가지의 조각 수와 검색 결과를 비교하고, 자기 글에 대한 질문의 답과 출처를 기록한다.

선택 확장:

- `ex04`의 `RULES`를 `너는 그리스·로마 신화 안내자다. 아래 자료만 근거로 한국어로 답한다. 자료에 없는 내용은 지어내지 말고 "자료에 없습니다."라고만 답한다.`로 바꾸고 2교시 3번 질문을 다시 한다. 답이 자료에 있는데도 거부하는지 보고, 금지를 세게 쓴 규칙이 작은 모델에 어떤 영향을 주는지 적는다.
- `ex04`에 5주차 `ex03`의 `history`를 더해 앞 질문을 이어서 묻는 도우미로 바꾼다.
- `[출처]` 1위 점수가 0.45 아래이면 모델을 부르지 않고 `자료에 없습니다.`를 바로 출력하도록 고치고, 어떤 질문에서 잘못 거부되는지 본다.
