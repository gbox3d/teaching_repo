# 1교시 · 설명 20분
## 임베딩으로 글을 찾는다

---

## 0–2분 · 모델은 배운 것만 안다

4주차 모델에게 물었다. `메두사를 죽인 영웅은 누구야?`

> 메두사를 죽인 영웅은 … 두 가지 버전이 있습니다. 첫 번째는 헤라 … 두 번째는 아테나 …
> (qwen3.5:2b, 자료 없이, 답 줄임)

작은 모델은 모르는 것을 자신 있게 지어낸다.
이번 주에는 **답이 적힌 글을 찾아서 프롬프트에 넣어 준다.** 모델은 그대로다.

---

## 2–4분 · 임베딩: 문장을 숫자로

```python
embeddings = create_embeddings()   # shared: bge-m3
vector = embeddings.embed_query("제우스는 하늘에서 번개를 던진다.")
len(vector)      # 1024
vector[:5]       # [0.004, 0.041, -0.052, -0.021, -0.016]
```

문장 하나가 숫자 1024개가 된다. 이 숫자 묶음이 **임베딩**(벡터)이다.
뜻이 비슷한 문장은 비슷한 숫자 묶음이 된다.

---

## 4–6분 · 유사도: 가까운 정도를 숫자 하나로

| 기준 문장 | `헤라는 결혼의 여신이다.`와의 유사도 |
|---|---:|
| 하데스는 죽은 자들의 세계를 지배한다. | 0.493 |
| 제우스는 하늘에서 번개를 던진다. | 0.488 |
| 포세이돈은 바다와 지진을 다스린다. | 0.427 |
| 파이썬 리스트는 대괄호로 만든다. | 0.350 |
| 학생 식당의 오늘 점심은 김치찌개다. | 0.273 |

코사인 유사도는 두 벡터의 방향이 같은 정도다. 1에 가까우면 뜻이 비슷하다.
단어가 하나도 겹치지 않아도 신화 문장끼리 더 가깝다.

---

## 6–8분 · 이번 주의 두 모델

| 모델 | 하는 일 | 크기 |
|---|---|---|
| `qwen3.5:2b` | 질문을 읽고 답을 **생성**한다 (4·5주차) | 약 2.7 GB |
| `bge-m3` | 글을 **벡터로만** 바꾼다. 답을 만들지 않는다 | 약 1.2 GB |

```python
from langchain_ollama import OllamaEmbeddings
embeddings = OllamaEmbeddings(model="bge-m3")
```

같은 Ollama 서버에서 두 모델을 쓴다. 벡터는 같은 임베딩 모델로 만든 것끼리만 비교한다.
자료 여러 개는 `embed_documents(목록)`, 질문 하나는 `embed_query(문장)`로 바꾼다.

---

## 8–10분 · 벡터 저장소: 넣고, 찾는다

```python
store = InMemoryVectorStore(embeddings)
store.add_texts(texts, metadatas)                 # 글마다 벡터를 만들어 보관
store.similarity_search_with_score(question, k=3) # 질문과 가까운 글 3개
```

글 50편을 한 번 벡터로 바꿔 두면, 질문 하나를 벡터로 바꿔 가장 가까운 글을 꺼낸다.
점수는 ex01과 같은 코사인 유사도다. 확률이나 퍼센트가 아니다.
이번 주 규모는 메모리에 두면 충분하다. 벡터 데이터베이스 서버는 글이 수만 편일 때 필요해진다.

---

## 10–13분 · 자료: 그리스·로마 신화 50편

```text
## 페르세우스와 메두사의 머리
페르세우스는 황금 비로 변한 제우스와 다나에 사이에서 태어났다. ...
```

`src/shared/data/myths.md`의 `## 제목` 하나가 검색 단위 한 편이다. `load_myths()`가 (제목, 본문) 50쌍으로 읽는다.

신화의 줄거리는 누구나 다시 쓸 수 있어 수업용 요약을 새로 썼다. 번역서의 문장이나 소설처럼 저작권이 있는 글은 넣지 않는다.
작은 모델이 세부를 자주 틀리는 영역이어서 자료의 효과가 눈에 보인다.

# 2교시 · 설명 20분
## 찾은 자료를 넣어 답한다

---

## 0–3분 · 자료 없이 물으면

```text
나> 헤라클레스의 열두 과업 중 다섯 번째는 무엇이야?
자료 없이> 헤라클레스의 열두 과업 중 다섯 번째 과업은 **아테네城的 벽을 쌓기**입니다. ...
자료 넣고> 헤라클레스의 열두 과업 중 다섯 번째 과업은 아우게이아스 왕의 외양간을 하루에 청소하는 것이었습니다.
찾은 자료: 헤라클레스의 열두 과업, 헤라클레스의 탄생, 헤르메스
```

같은 모델, 같은 질문이다. 달라진 것은 프롬프트에 넣은 자료 세 편뿐이다. 자료 없는 답에는 한자까지 섞였다.

---

## 3–6분 · RAG: 검색해서 넣고 생성한다

```text
질문 ─▶ 임베딩 ─▶ 저장소에서 가까운 글 3편 ─▶ [자료 + 질문] ─▶ 모델 ─▶ 답
                       (1교시)                    (2교시)
```

Retrieval(검색) Augmented(증강) Generation(생성). 검색한 글로 보강해서 생성한다.
모델을 다시 학습시키지 않는다. 글을 바꾸면 답도 바뀐다. 출처는 검색 단계에서 이미 안다.

---

## 6–9분 · 자료가 들어갈 자리

```python
prompt = ChatPromptTemplate.from_messages([
    ("system", RULES),
    ("human", "자료:\n{context}\n\n질문: {question}"),
])
chain = prompt | create_model() | StrOutputParser()
```

5주차 연결 그대로다. `{context}`에 찾은 글 세 편을, `{question}`에 질문을 넣는다.

```python
context = "\n\n".join(doc.page_content for doc in docs)
chain.invoke({"context": context, "question": question})
```

## 9–12분 · 규칙 한 줄과 출처

```python
RULES = ("너는 그리스·로마 신화 안내자다. 자료에서 질문의 답을 찾아 한국어로 짧게 답한다. "
         "자료에 답이 없을 때만 \"자료에 없습니다.\"라고 답한다.")
```

```text
AI> 히포메네스는 아탈란테가 앞설 때마다 **황금 사과**를 하나씩 던졌다.
[출처] 아탈란테의 경주 0.60 / 아킬레우스의 발뒤꿈치 0.49 / 헤라클레스의 열두 과업 0.49
```

출처는 모델이 쓰는 것이 아니라 **프로그램이 검색 결과에서 붙인다.** `**`는 모델이 굵게 쓰려고 붙인 마크다운 기호다.
점수와 상관없이 세 편 모두 모델에게 들어간다. 무관한 글의 내용이 답에 섞일 수 있으니 1위 글과 대조한다.

# 3교시 · 설명 20분
## 긴 글을 나누고, 내 문서로

---

## 0–3분 · 글이 길면 조각으로 나눈다

신화 자료는 편마다 한 덩어리였다. 실제 문서는 제목 없이 길게 이어진다.

- 통째로 넣으면 질문과 무관한 부분까지 들어가 답이 흐려지고 토큰을 낭비한다
- 벡터 하나가 긴 글 전체를 대표하면 검색 점수도 뭉개진다
- 그래서 **조각**(청크)으로 나눠 조각마다 벡터를 만든다

오늘 글: 오디세우스의 귀향 약 3,900자 (`odyssey.md`)

---

## 3–6분 · 조각 크기와 겹침

```python
splitter = RecursiveCharacterTextSplitter(chunk_size=300, chunk_overlap=50)
chunks = splitter.split_text(text)
```

문단 → 줄 → 띄어쓰기 순서로 경계를 찾아 `chunk_size`자 이내로 자른다.
`chunk_overlap`은 문단 중간에서 자를 때 앞 조각의 끝을 최대 50자까지 다음 조각에 다시 넣는다. 문단 경계에서 나뉜 조각은 겹치지 않는다.

| `CHUNK_SIZE` (겹침 50) | 150 | 300 | 600 | 1000 |
|---|---:|---:|---:|---:|
| 조각 수 | 39 | 19 | 10 | 5 |
| 아이올로스 질문 1위 점수 | 0.566 | 0.583 | 0.583 | 0.532 |

---

## 6–9분 · 시연: 조각이 잘린 자리

```text
글자 3905개를 최대 300자 조각 19개로 나눴습니다.
  조각 2 (298자): 다음에 닿은 섬은 … 아무 일도 없는 줄 알고 돌아갔다. 아침에 거인이 양을
  조각 3 (182자): 나를 해쳤다"고 외치자 그들은 아무 일도 없는 줄 알고 … 해 달라고 빌었다.
나> 아이올로스가 준 선물은 무엇이었어?
  0.583  조각 4: 바람의 신 아이올로스는 오디세우스를 한 달 동안 대접한 뒤 ...
```

조각 2는 문장 중간에서 끝나고, 조각 3은 조각 2의 끝 47자를 다시 담고 시작한다(`아무 일도 없는 줄 알고`). 조각 0·1·2 사이는 문단 경계라 겹치지 않는다.
너무 작으면 문맥이 끊기고(150자 0.566), 너무 크면 무관한 내용이 섞여 점수가 흐려진다(1000자 0.532).

## 9–12분 · 내 문서 도우미: 1·2교시의 조합

```python
for path in sorted(DATA_DIR.glob("*.md")):
    chunks = splitter.split_text(path.read_text(encoding="utf-8"))
    store.add_texts(chunks, [{"source": f"{path.name}#{n}"} for n in range(len(chunks))])
```

폴더의 `.md`를 모두 읽어 조각으로 나눠 저장한다. 출처는 `파일명#조각번호`다.
그 뒤는 2교시와 같다. 검색 → 자료와 질문 → 모델 → 답과 `[출처]`.

`[출처]`에 답이 든 조각이 없으면 **검색 실패**, 있는데 틀리면 **모델의 한계**다.
