# 11주차 · Needle3 도구 호출과 모델 비교

10주차의 제어 함수와 검증 절차를 유지하고 호출을 제안하는 모델을 바꾼다. Needle3로 자연어 명령을 입력한 뒤, 같은 평가셋에서 Ollama와 호출 정확도·시간을 비교한다. 마지막에는 도구 설명 하나를 바꾸고 같은 입력의 결과를 다시 확인한다.

## 목표와 교시별 결과

| 교시 | 설명·시연 20분 | 실습 30분 | 실행 |
|---|---|---|---|
| 1 | Needle3와 호출 제안 읽기 | 반복 입력으로 LED·온습도 확인 | `uv run ex01` |
| 2 | Kev와 출력 목적 구분, 공정한 비교 | 같은 평가셋의 Ollama·Needle 비교 | `uv run ex02` |
| 3 | 도구 설명 변경과 재검증 | 설명 변경 전후에 같은 명령 입력 | `uv run ex03` |

각 교시는 설명·시연 20분, 실습 30분, 휴식 10분이다. Kev는 선택 소개이며 실제 실행기를 설치하거나 성능표에 추가할 필요는 없다.

## 준비와 구조

Python 3.12와 `cactus-compute==4.2.0`을 사용한다. 수업 전에 패키지와 모델 다운로드를 마친다. Ollama 비교에는 10주차의 `qwen3.5:2b`를 사용한다. 지원 환경과 설치 결과는 실제 PC에서 확인한다.

[실습지](lab.md)에서 Python 버전을 지정한 프로젝트 생성 구조를 확인한 뒤, `teaching_repo` 전체를 clone한 상태에서 주차의 `examples/`로 이동한다. 한 uv 프로젝트의 `main()` 세 개를 `[project.scripts]`에 연결한다. `uv_build`가 패키지를 설치하며 scripts 수정 뒤에는 `uv sync`가 필요하다.

주차 `shared`가 공용 `bleuno_control`을 import하고, `[tool.uv.sources]`의 상대 path가 `tools/bleuno-control`을 가리킨다. 교시별로 프로젝트·자료·통신 코드를 복사하지 않는다. 비교할 모델 설정과 도구 설명은 소스의 상수에서 읽는다.

## Needle의 반환과 실행 순서

`Cactus(tools=list, auto_date=False)`에 네 제어 함수의 명세를 넣는다. `complete()`의 `function_calls`에서 이름과 인수를 읽고, Python에서 검증한 뒤 실행한다. `run()`의 자동 실행 경로는 사용하지 않는다.

`reset()`은 문항 사이의 모델 대화 상태를 비운다. 시뮬레이터 LED 초기화와는 별개다. 터미널이 입력을 반복해서 받는 것만으로 이전 문맥을 기억한다고 설명하지 않는다. 빈 입력은 건너뛰며 `/bye`로 종료한다.

공식 반환 형식의 `confidence`는 해당 호출에 관한 모델의 신뢰도 출력이다. 현재 수업 래퍼는 호출 목록만 전달하므로 대화 화면에 신뢰도 값은 표시하지 않는다. 실제 입력의 정답 비율이나 LED 제어 성공률은 평가셋과 `GET /state`로 따로 계산한다. 빈 호출 목록은 실행할 함수가 없다는 뜻이며, 올바른 거부인지 호출 누락인지는 입력과 함께 판단한다.

## 장치 검증과 비교 범위

시뮬레이터는 저장소 루트의 별도 터미널에서 실행한다.

```powershell
uv run --python 3.12 tools/bleuno-sim/sim.py --bind 127.0.0.1
```

창 없는 검증에는 `--no-window`를 추가한다. TCP 8266 연결을 유지하고, HTTP 8080의 `GET /state`에서 실제 상태를 확인한다. `hello`·이벤트 행을 명령 응답으로 세지 않는다.

모델에는 `turn_on(index)`, `turn_off(index)`, `set_brightness(index, value)`, `read_environment()`만 제공한다. LED 번호는 정수 0~3, 밝기는 정수 0~255이며 불리언은 거부한다. 센서 값을 바꾸는 `POST /set`은 도구 목록에 넣지 않는다.

Kev-0.8B는 주어진 영어 상태와 선택지를 읽고 선택지별 확률을 반환하는 결정 모델이다. 일반적인 함수 이름·인수 생성과 구분한다. 공식 카드는 영어 외 언어와 도구 호출 라우팅을 적용 범위 밖으로 적고 있으므로, 이 실습의 Needle 대체 실행기로 다루지 않는다. [Kev 공식 카드](https://huggingface.co/jaredpalmer/kev-0.8b)

모델에 선언한 함수 이름은 호출 규약이다. 실제 실행은 공용 `Board.execute()`가 이름·인수를 검증한 뒤 TCP 명령으로 바꾼다. `tools.json`의 같은 명세를 두 모델이 사용한다.

## 수업 준비 실측

Mac M1 Max에서 CPU 학습을 종료한 뒤 같은 16문항을 한 번씩 실행한 결과다. 같은 PC·초기 LED·도구 명세를 사용했고 모델별 출력 한도는 256토큰이다. 예열 1회와 모델 준비는 제외하고 추론 구간만 측정했다.

| 모델 | 제어 성공 | 무호출 오호출 | 오류 | 한글 성공 | 영어 성공 | median | p95 |
|---|---|---|---|---|---|---|---|
| Ollama `qwen3.5:2b` | 9/16 (56.25%) | 4/6 | 1 | 2/8 | 7/8 | 296.2ms | 658.2ms |
| Needle3 배포본 | 10/16 (62.5%) | 1/6 | 3 | 3/8 | 7/8 | 60.6ms | 179.9ms |

오류도 분모에 포함했다. 이 평가기의 p95는 16개 관찰값 중 최댓값이다. 두 모델의 반환 형식은 다르지만 실행기에 전달하는 호출 목록 계약은 같다. 한글 실패·보류를 포함한 단일 실행의 관찰이며 다른 입력·장치의 성능을 보장하지 않는다. 실습에서는 이 숫자를 복사해 제출하지 않고 자신의 입력·실측 결과를 남긴다.
