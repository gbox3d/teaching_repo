## 0–3분 · 모델은 데이터를 닮는다

```text
수집 ──▶ 정제 ──▶ 중복 제거 ──▶ 개인정보 점검 ──▶ 분할 ──▶ 데이터 카드
raw.jsonl   빈 값·정규화   정확·근사      마스킹/삭제     train/val/test
48건
```

- 10주차 어댑터는 `sample_sft.jsonl` 50여 건을 **그대로** 배웠다
- 데이터에 전화번호가 있으면 모델은 전화번호를 외운다
- 같은 질문이 학습과 평가에 같이 있으면 점수는 부풀어 오른다

**질문:** 팀원이 보낸 48건에서 먼저 무엇을 의심해야 하는가?

## 3–6분 · 정제: 무엇을 지울 것인가

| 검사 | 기준 | 예제에서 |
|---|---|---|
| 필수 필드 | id·instruction·output이 비어 있지 않음 | q040 output 빈 값 |
| 정규화 | NFKC, 연속 공백 하나로 | `uv sync 와  uv sync` |
| 정확 중복 | instruction 소문자·공백·문장부호 제거 키 | q009 = q003, q021 = q014 |
| 근사 중복 | instruction+output 문자 2-gram Jaccard ≥ 0.8 | q033 ≈ q027 (0.94) |

- 임계값은 **데이터를 보고 정한다** — 0.95면 q033이 살아남는다
- 지운 것은 이유와 함께 `clean_report.json`에 남긴다

## 6–9분 · 분할과 누수

```text
44건 ─ train_test_split(seed 42) ─▶  train 20  │  val 4  │  test 20
                                      학습        조정       봉인
```

- train은 가중치를 바꾸고, val은 하이퍼파라미터를 고르고, test는 **한 번만** 본다
- 누수: 같은 질문이 두 split에 있으면 test 점수는 외운 것 — `leak_check`가 정규화 키로 찾는다
- seed를 기록해야 같은 split이 다시 나온다

**질문:** 중복 제거를 분할 **뒤에** 하면 무엇이 잘못되는가?

## 9–12분 · 개인정보·저작권·편향

| 유형 | 정규식이 찾는 모양 | 예제 값(가짜) |
|---|---|---|
| PHONE | `010-####-####` 형태의 휴대전화 | q012 output |
| EMAIL | `이름@도메인.tld` | q025 instruction |
| RRN | `######-#######`, 7번째 자리 1~4 | q038 output |

- 정규식은 **문맥을 모른다**: 설명용 예시 번호(q038)도 잡고(오탐), 모양이 다른 번호는 놓친다(미탐)
- 검출 목록을 사람이 다시 읽고 판단을 **데이터 카드에 적는다**
- 저작권: 출처·라이선스 없는 문서는 학습에 쓰지 않는다 · 편향: `source` 열 분포를 센다

# 2교시 · 설명 20분
## 기준선과 지표 — 무엇으로 좋아졌다고 말하는가

---

## 0–3분 · "좋아졌다"에는 기준선이 필요하다

```text
run-001.md : 어댑터 적용 후 형식 준수 5/5          ← 기준선은? 문항은 어디서?
이번 주     : base 0/20 → lora 17/20 (test, greedy, seed 42, 같은 system)
```

- 기준선(baseline): 학습하지 않은 모델의 **제로샷** 점수
- 비교에서 고정할 것: 같은 test split, 같은 system 프롬프트, greedy, seed, `max_new_tokens`
- 하나라도 다르면 "좋아졌다"가 아니라 "달라졌다"

**질문:** 10주차 `eval_prompts.json` 5개로 낸 5/5는 무엇이 문제였는가?

---

## 3–6분 · 분류 지표: 혼동행렬에서 시작한다

```text
              예측 1     예측 0
정답 1        TP         FN
정답 0        FP         TN

accuracy = (TP+TN)/전체   precision = TP/(TP+FP)   recall = TP/(TP+FN)
F1 = 2·P·R/(P+R)
```

- "형식 준수 여부"처럼 **예/아니오 판정**을 채점할 때 쓴다
- 14:6으로 불균형하면 전부 1이라 해도 accuracy 0.7 — F1이 낮은 이유
- `metrics.py --demo`: accuracy 0.8, precision 0.857, recall 0.857

---

## 6–10분 · 생성 지표: 각각 무엇을 놓치는가

| 지표 | 계산 | 놓치는 것 |
|---|---|---|
| 정확 일치 | 정규화 후 문자열 동일 | 표현만 달라도 0 |
| 키워드 포함 | 정답 키워드 중 포함 비율 | 키워드만 넣은 엉터리 답 |
| 유사도 | 문자 2-gram Jaccard | 의미가 반대여도 높을 수 있음 |
| 형식 준수 | 핵심:/이유:/다음 할 일: 세 줄, 400자 | **내용이 틀려도 통과** |
| 한글 비율·반복 | 문자 통계 | 짧은 영어 명령어 |

- 지표는 **증상 탐지기**다. 판결은 사람이 한다(3교시)
- 정답이 하나가 아닌 생성 과제에서 정확 일치는 거의 0 — 놀라지 않는다

---

## 10–13분 · LLM에게 채점을 맡기면

- LLM-as-judge: 판정 프롬프트로 다른 모델이 점수를 매긴다 — 빠르고 싸다
- 알려진 편향: **긴 답·자신감 있는 답·자기 계열 모델**을 선호, 순서 효과
- 쓰려면: 사람이 표본 20건을 먼저 채점해 **일치율**을 적고, 루브릭을 프롬프트에 그대로 넣는다
- 이 수업의 기본: 자동 지표(증상) + 사람 채점(판결). LLM 판정은 확장 문제

**질문:** 판정 모델이 "형식이 완벽하다"며 2점을 줬다. 무엇을 확인해야 하는가?

---

## 13–15분 · 벤치마크 오염: 시험 문제를 미리 본 모델

```text
10주차 sample_sft.jsonl : "torch.no_grad는 언제 쓰나요?"   ← LoRA 학습에 씀
11주차 test.jsonl q023  : "torch.no_grad는 언제 쓰나요?"   ← 같은 질문
```

- 공개 벤치마크 점수가 높은 이유가 "학습 데이터에 시험지가 들어 있어서"인 경우가 있다
- `split.py --against 학습파일.jsonl`: test 문항과 학습 질문의 유사도를 재서 겹치는 id를 보고한다
- 겹친 문항을 `evaluate.py --exclude`로 빼고 다시 계산한 점수가 일반화 점수에 가깝다
- test는 분할 직후 봉인 — 하이퍼파라미터는 **val**로만 고른다

## 0–3분 · 숫자가 말하지 않는 것

```text
q043 "CHANGELOG는 커밋 로그를 복사하면 되나요?"
lora: 핵심: 커밋 로그를 그대로 복사하면 된다.
      이유: 커밋 메시지가 곧 변경 내역이기 때문이다.
      다음 할 일: `git log --changelog` 명령으로 CHANGELOG.md를 자동 생성한다.
자동 지표: 형식 O · 키워드 0/2 · 유사도 0.31
```

- 형식은 완벽하고 말투도 배웠다. 그런데 **없는 명령**을 알려 준다
- 형식 준수율 0.85는 "말투를 배웠다"의 증거이지 "맞는 말을 한다"의 증거가 아니다

**질문:** 이 답을 서비스로 내보내면 사용자는 무엇을 하게 되는가?

## 3–6분 · 오류 유형 분류표

| 코드 | 유형 | 신호 | 샘플 id |
|---|---|---|---|
| H | 환각 | 없는 명령·틀린 사실, 키워드 0 | q043 |
| F | 형식 위반 | 머리말 누락, 줄 수, 400자 초과 | q031, q027 |

| L | 언어 혼합 | 한글 비율 하락, 외국어 문장 | q035 |

- 한 출력에 여러 코드가 붙을 수 있다 — 전부 적는다

## 6–9분 · 3단계 루브릭과 채점 일관성

| 점수 | 뜻 | 판단 순서 |
|---:|---|---|
| 0 | 부적합 | 틀린 정보·무관·거부·반복·빈 출력 중 하나라도 있으면 |
| 1 | 부분 | 내용은 맞지만 형식 위반·누락·군더더기 중 하나 |
| 2 | 적합 | 내용 맞고 형식 지키고 틀린 정보 없음 |

- 판단은 **0부터** 검사한다: 틀린 정보가 있으면 형식이 완벽해도 0
- 채점 전에 짝과 "틀린 정보"·"누락"의 기준을 한 문장씩 합의한다
- 같은 5건을 따로 채점해 **일치율**을 적는다 — 3/5 이하이면 기준을 고치고 다시 한다

**질문:** 자동 지표 열을 보면서 채점하면 무엇이 달라지는가?

## 9–12분 · 유해 출력과 개인정보 유출 점검

```text
학습 데이터(마스킹 후): "다음 할 일: 그래도 안 되면 조교에게 [PHONE]로 연락한다."

점검 1  출력에 [PHONE]·[EMAIL]·[RRN] 토큰이 그대로 나오는가   → 마스킹 흔적을 배운 것
점검 2  "조교 연락처 알려줘"에 번호 형태를 지어내는가          → 환각 + 안전 (H, S)
점검 3  마스킹 전 데이터로 학습했다면 실제 번호가 나오는가      → 즉시 폐기·재학습
```

- 정규식 검사를 **출력에도** 돌린다(`pii_check.py`의 패턴 재사용)
- 유도 질문 2~3개를 test와 별도로 두고 매 run마다 같은 질문을 던진다
- 문제가 나오면 데이터 카드의 「한계」와 실패 분석의 「안전 점검」에 적는다

## 12–15분 · 개선 루프: 실패 분석에서 run-002로

```text
평가(run-001) ──▶ 실패 분석: 유형별 건수 + 사례 3개(증상·원인 가설·근거·개선안)
     ▲                                    │
     └── 재평가(같은 test) ◀── 재학습(run-002) ◀── 한 가지만 바꾼다
```

- 원인 가설은 네 곳 중 하나: **데이터**(없음·모순·형식 불일치) / **학습 설정**(epoch·lr) / **디코딩**(길이·반복) / **프롬프트**
- 근거 찾기: 기준선도 틀리면 데이터에 지식이 없는 것, 기준선은 맞는데 LoRA가 틀리면 학습이 망가뜨린 것
- 성공 기준을 **숫자로** 미리 적는다: "사례 1~3이 2점, 형식 준수율 0.85→0.95, 반복 0건"
