# 11주차 실습 · Needle와 Ollama 비교

각 교시는 설명·시연 20분, 실습 30분, 휴식 10분이다. 개인 `week11_note.md`에 실제 입력과 관찰을 기록한다. 더 높은 성능 수치를 만드는 것이 실습 목표는 아니다.

## 수업 전 준비

저장소 밖의 연습용 폴더에서 다음 명령으로 구조를 확인한다. 기존 `examples/`에 다시 초기화하지 않는다.

```powershell
uv init --package --python 3.12 --vcs none week11-skeleton
```

`.python-version`, `pyproject.toml`, `src/`를 찾는다. `main()`은 실행 시작점, `[project.scripts]`는 명령 연결, `[build-system]`의 `uv_build`는 패키지 설치 방법이다. scripts를 수정하면 `uv sync`를 다시 실행한다.

실제 실습은 전체 저장소를 clone한 경로에서 진행한다. 이미 clone했다면 그 경로를 사용한다.

```powershell
git clone https://github.com/gbox3d/teaching_repo.git
cd teaching_repo
```

터미널 A는 저장소 루트에 두고 시뮬레이터를 실행한다.

```powershell
uv run --python 3.12 tools/bleuno-sim/sim.py --bind 127.0.0.1
```

창 없이 확인할 때만 `--no-window`를 추가한다. 시뮬레이터는 켜 둔다. 터미널 B도 같은 저장소 루트에서 시작한 뒤 다음과 같이 이동한다.

```powershell
cd open_source_ai/weeks/week11_dataset_evaluation/examples
uv sync
```

이후 세 교시의 `uv run ex01`~`uv run ex03`은 모두 터미널 B에서 실행한다. `period1`~`period3`로 이동하지 않는다. `examples/`만 복사하면 `[tool.uv.sources]`의 상대 path가 끊긴다. 주차 `shared`가 import하는 `bleuno_control`은 저장소의 `tools/bleuno-control`에 있다.

브라우저에서 `http://127.0.0.1:8080/state`를 연다. TCP 8266은 명령을 보내는 연결이고 HTTP 8080은 상태를 읽는 주소다. 연결 직후의 `hello`와 중간 이벤트는 명령 응답에서 제외한다. TCP 연결을 새로 만들거나 끊으면 LED가 초기화되므로 프로그램을 종료하기 전에 상태를 확인한다.

`cactus-compute==4.2.0`과 Needle 모델의 준비를 수업 전에 마친다. `uv sync`는 주차의 고정 의존성을 설치한다. Ollama를 실행하고 `qwen3.5:2b`도 확인한다. 모델을 처음 준비하는 시간은 실습 비교 시간에서 분리해 기록한다.

## 1교시 실습 · Needle 호출 제안

| 실습 구간 | 활동 |
|---|---|
| 0–5분 | `Cactus` 초기화와 도구 목록 읽기 |
| 5–15분 | `uv run ex01`에서 LED·온습도 요청 반복 |
| 15–23분 | 호출 목록과 Python 검증, 실제 상태 대조 |
| 23–30분 | 빈 호출·신뢰도와 정확도의 차이 기록 |

```text
Turn on LED 0.
Set LED 1 brightness to 128.
Turn off LED 0.
Read the temperature and humidity.
Set the temperature to 30 degrees.
```

1. `Cactus(tools=list, auto_date=False)`가 받는 도구 명세를 찾는다. 실행 함수를 모델에 무제한으로 맡기지 않고 허용된 네 함수만 선언한다.
2. 각 입력의 `function_calls`에서 함수 이름과 인수를 읽는다. Python 검증을 통과한 호출만 실행하고 TCP 연결을 유지한 상태에서 `/state`를 확인한다.
3. 없는 기능의 요청에서 호출 목록이 비었다면 올바른 거부인지 입력을 보고 판단한다. 정상 LED 요청에서 비었다면 호출 누락이다. 빈 목록을 장치 실행 성공으로 처리하지 않는다.
4. 공식 반환 형식의 `confidence`와 실제 성공 여부를 구분해 설명한다. 현재 수업 래퍼는 호출 목록만 화면에 출력하므로 없는 신뢰도 값을 만들어 기록하지 않는다. 높은 신뢰도만으로 함수·인수·실제 상태가 맞았다고 판정하지 않는다.
5. 문항마다 `reset()`하는 부분을 찾는다. 모델 이력을 비우는 것과 LED를 초기화하는 것은 다른 작업이다. 입력 반복·빈 줄 처리·종료도 확인한다.

## 2교시 실습 · 같은 평가셋 비교

| 실습 구간 | 활동 |
|---|---|
| 0–5분 | 두 모델의 입력·도구·초기 상태·측정 구간 대조 |
| 5–17분 | `uv run ex02` 실행, 문항별 결과와 소요 시간 기록 |
| 17–24분 | 같은 문항의 차이를 제안·검증·실제 상태로 분류 |
| 24–30분 | 비교 근거와 Kev의 별도 용도 설명 |

고정 평가셋의 같은 문항을 Ollama `qwen3.5:2b`와 Needle3에 보낸다. 모델 하나에만 쉬운 입력이나 추가 설명을 주지 않는다. 문항마다 모델 대화 상태와 시뮬레이터 초기 조건을 각각 맞춘다. 모델 다운로드·최초 준비와 반복 추론 시간은 나누어 기록한다.

| 문항·입력 언어 | 예상 호출 또는 거부 | Ollama 제안·시간 | Needle 제안·시간 | 각 모델의 상태 일치 | 차이의 원인 |
|---|---|---|---|---|---|
| 평가셋 원문 | 평가셋 기준 | 실제 측정 | 실제 측정 | 직접 확인 | 근거 기록 |

함수 이름만 같아도 인수가 틀리면 호출 전체의 정답으로 세지 않는다. 오류·빈 호출은 지우지 않고 기준에 따라 집계한다. 시간은 두 모델 모두 추론 구간만 비교한다. 함수 선택·전체 호출 완전 일치·제어 성공·무호출 오호출과 median·p95를 따로 설명한다. Needle의 `confidence`를 정답 비율로 바꾸어 쓰지 않는다.

Kev 선택 소개에서는 공식 카드만 읽는다. 영어 상태와 미리 제공한 선택지를 받아 선택지별 확률을 반환한다는 점을 확인한다. 일반 함수 호출과 인수 생성 모델로 설명하지 않는다. 공식 카드는 도구 호출 라우팅을 범위 밖으로 적고 있으며, Kev 실행과 성능 측정은 이번 실습의 필수 항목이 아니다. [공식 카드](https://huggingface.co/jaredpalmer/kev-0.8b)

## 3교시 실습 · 도구 설명 변경

| 실습 구간 | 활동 |
|---|---|
| 0–6분 | `uv run ex03`으로 기준 설명의 입력·호출 기록 |
| 6–14분 | 한 함수의 도구 설명만 수정하고 다시 실행 |
| 14–23분 | 같은 입력 재검사, 정상·거부 문항 함께 확인 |
| 23–30분 | 변화와 남은 오류, 수정 이유 기록 |

1. 1교시와 같은 입력 중 하나를 선택하고 기준 설명에서 제안·상태를 기록한다. `ex03`도 직접 입력하는 대화형 예제다.
2. `ex03_descriptions`의 `DESCRIPTIONS` 사전에서 도구 설명 한 곳만 바꾼다. 예를 들어 영어 기능 설명을 같은 뜻의 한국어 설명으로 바꾸거나, LED 번호 범위와 밝기의 단위를 명시한다. 한 번에는 한 조건만 바꾼다. 함수 이름·인수·검증 규칙·모델은 유지한다. 문제를 맞히도록 평가셋의 기대값을 바꾸지 않는다.
3. 도구 명세가 바뀌면 새 `Cactus` 인스턴스로 다시 시작한다. `reset()`만으로 기존 인스턴스의 도구 정의가 바뀐다고 설명하지 않는다.
4. 동일 입력과 표현이 다른 입력을 구분해 검사한다. 잘못된 번호·밝기와 센서 변경 요청에서도 Python 검증을 유지한다.
5. 결과가 같거나 나빠졌어도 그대로 적는다. 설명 수정은 모델 가중치 학습과 다르다. 수정 문장, 선택 이유, 전후 호출, 실제 상태를 함께 제출한다.

설명 변경 전후의 한 문항만으로 전체 모델 우열을 결론 내리지 않는다. 실습 뒤 10분은 휴식이다.

## 고정 평가셋과 측정 기준

평가 입력은 저장소 공용 [control_cases.json](../../../tools/bleuno-control/src/bleuno_control/data/control_cases.json)의 16문항이다. 한글 8개·영어 8개이며 호출 문항 10개·무호출 문항 6개다. 문항마다 LED를 TCP 명령으로 `[0, 64, 128, 255]`로 복원한다. 센서 값은 그 시점의 읽기 결과와 상태를 대조한다.

예열 1회는 점수와 시간 통계에서 제외한다. 모델 시간은 추론만 측정하며 모델 준비, LED 복원, 함수 실행, HTTP 상태 조회 시간을 섞지 않는다. 준비 시간은 별도로 기록한다.

| 평가 항목 | 의미 |
|---|---|
| 함수 선택 정확도 | 유효한 호출의 함수 이름 순서 비교. 전체 인수 일치와 분리 |
| 전체 호출 완전 일치 | 함수 이름·인수·호출 순서가 모두 기준과 일치 |
| 제어 성공률 | 호출 완전 일치에 더해 실행 후 실제 상태까지 일치 |
| 무호출 문항 오호출률 | 무호출 6문항에서 불필요한 호출을 제안한 비율 |
| 추론 시간 median·p95 | 예열을 뺀 추론 시간의 중앙값·95백분위수 |

`confidence`는 위 평가 항목의 대체값이 아니다. 전체 수치와 함께 한글·영어 문항별 실패를 읽는다. 16문항의 p95는 이 작은 평가셋의 관찰값이며 일반적인 응답 시간 보장으로 해석하지 않는다.

## 수업 준비 실측

Mac M1 Max에서 CPU 학습을 종료한 뒤 같은 16문항을 한 번씩 실행한 결과다. 같은 PC·초기 LED·도구 명세를 사용했고 모델별 출력 한도는 256토큰이다. 예열 1회와 모델 준비는 제외하고 추론 구간만 측정했다.

| 모델 | 제어 성공 | 무호출 오호출 | 오류 | 한글 성공 | 영어 성공 | median | p95 |
|---|---|---|---|---|---|---|---|
| Ollama `qwen3.5:2b` | 9/16 (56.25%) | 4/6 | 1 | 2/8 | 7/8 | 296.2ms | 658.2ms |
| Needle3 배포본 | 10/16 (62.5%) | 1/6 | 3 | 3/8 | 7/8 | 60.6ms | 179.9ms |

오류도 분모에 포함했다. 이 평가기의 p95는 16개 관찰값 중 최댓값이다. 두 모델의 반환 형식은 다르지만 실행기에 전달하는 호출 목록 계약은 같다. 한글 실패·보류를 포함한 단일 실행의 관찰이며 다른 입력·장치의 성능을 보장하지 않는다. 실습에서는 이 숫자를 복사해 제출하지 않고 자신의 입력·실측 결과를 남긴다.
