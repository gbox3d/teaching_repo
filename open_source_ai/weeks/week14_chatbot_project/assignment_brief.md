# 기말과제 — 원광대학교 소개 챗봇과 개발 보고서

## 평가 항목

| 기존 성적 항목 | 이번 기말과제에서 평가할 것 |
|---|---|
| 발표 점수 | 제출한 챗봇의 비공개 평가셋 AI 성능 점수 |
| 레포트 점수 | 개발한 내용·선택 이유·실험 과정을 정리한 보고서 |

기존 발표·레포트의 성적 반영 비율을 각각 유지한다.
발표 말솜씨, 발표 시간, 슬라이드 꾸밈은 점수 항목에서 제외한다.
실행 확인이나 질문 응답이 있더라도 별도 발표 점수를 더하지 않는다.
실제 배점·마감·개인 또는 팀 제출 방식은 해당 강좌 공지를 따른다.

## 만들 프로그램

원광대학교를 소개하는 질문에 공통 참고 자료를 근거로 답하는 챗봇을 만든다.
자료에 없으면 답을 지어내지 않고 답변 불가로 처리한다.
터미널 또는 Streamlit에서 사용할 수 있어야 하며,
평가 도구는 화면을 조작하지 않고 `student_bot.answer(question)`을 호출한다.

RAG, 파인튜닝, 프롬프트, 검색·분류 알고리즘을 자유롭게 조합한다.
여러 기법을 썼다는 이유로 가산하지 않는다.
공개 모델과 자료의 출처를 적고, 선택한 모델의 설치·복원 방법을 제공한다.

## 공개 자료와 비공개 평가

14주차에 다음을 제공한다.

- 기준일을 붙인 [공통 참고 자료](examples/src/shared/data/corpus.json)와 [출처 안내](examples/src/shared/data/README.md)
- [공개 질문 20문항](examples/src/shared/data/public_questions.json)과 [정답·허용 표현](examples/src/shared/data/public_answers.json)
- [평가 도구 소스](examples/src/shared/evaluation.py)와 [규격·산식](evaluation_spec.md)
- 실행 가능한 [기준 챗봇](examples/src/student_bot/__init__.py)과 [보고서 양식](report_template.md)

공개 문제로 반복 실험하고 직접 만든 질문으로도 점검한다.
공개 점수는 개발용이다. 최종 발표 항목은 같은 규격의 비공개 문제로 평가한다.
비공개 문제도 공개된 참고 자료·질문 유형·시간 제한 안에서 출제한다.
문항 수와 유형 비율은 최종 평가 전에 공지하며, 학습용 문제와 최종 정답을 섞지 않는다.

공개 질문 파일을 읽어 문장별 정답을 반환하거나, 평가 도구·정답을 바꾸어 점수를 높이지 않는다.
평가 때만 다른 모델·검색 경로를 사용하는 것도 허용하지 않는다.
참고 자료를 검색 색인이나 학습 데이터로 바꾸고, 공개 실패 사례를 보고 일반적인 규칙을 개선하는 것은 허용한다.

## 제출물

1. 챗봇 소스와 실행 안내: `pyproject.toml`, `uv.lock`, Python 버전, 모델 ID·revision, 필요한 어댑터와 검색 자료, `answer(question)` 연결 방법.
2. 제출 버전: 저장소 URL과 commit ID, 또는 동일 버전을 담은 소스 압축 파일.
3. 개발 보고서: [양식](report_template.md)에 따라 구현 내용, 변경 이유, 전후 평가, 실패 사례, 출처와 AI 도구 사용 내역을 작성한다.
4. 공개 평가 결과: 전체 문항의 답변·점수·오류가 보이는 터미널 기록과 실행 조건. 보고서의 수치가 이 기록과 맞아야 한다.

한 번의 실행 화면만으로 개발 내용을 설명한 것으로 보지 않는다.
별도 발표 영상, GitHub Release, CI 구성, PR 개수는 이번 과제의 필수 제출물이 아니다.

## 최종 평가 절차

제출 마감의 버전을 고정하고 동일한 평가 환경에서 프로그램을 준비한다.
모델 로딩과 준비 요청 뒤, 질문만 프로그램에 전달하고 답을 받아 교수자 측에서 채점한다.
정답·문항 유형·문항 ID를 챗봇의 입력에 넣지 않는다.
실패·시간 초과 문항을 빼고 평균 내지 않는다.

발표 항목의 만점이 P점이고 비공개 성능 지표가 S/100이면 해당 항목은 `P × S / 100`이다.
레포트는 [보고서 평가 기준](../week15_final_evaluation/assignment_rubric.md)으로 별도 평가한다.
이 성능 지표를 일반 실습과제의 5·6·7점 기준에 임의로 적용하지 않는다.

평가 PC 사양·허용 모델 크기·외부 API 허용 여부·네트워크 조건·마감은 강좌 공지에서 확정한다.
공개 기준 예제는 로컬 Ollama를 사용하며 유료 API 키가 필요 없다.
교수자 환경 문제는 학생 프로그램의 실패와 구분해 기록하고 같은 조건으로 재평가한다.
