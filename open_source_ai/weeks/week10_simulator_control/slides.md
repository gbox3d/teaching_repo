# 1교시 · 설명 20분
## Python 직접 제어

---

## 0–3분 · 제어 함수를 분리하는 이유

수동 입력과 자연어 입력은 표현이 다르다.
LED를 켜는 동작과 검증 기준은 같다.

제어 함수를 한곳에 두면 입력 방식을 바꿔도 재사용한다.
오늘은 Python 직접 제어부터 시작한다.

---

## 3–6분 · 네 함수와 허용 범위

| 함수 | 입력 |
|---|---|
| `turn_on(index)` / `turn_off(index)` | 정수 0~3 |
| `set_brightness(index, value)` | 번호 0~3, 밝기 정수 0~255 |
| `read_environment()` | 인수 없음 |

번호·밝기의 `True`·`False`는 거부한다.

---

## 6–9분 · 한 프로젝트와 공용 라이브러리

Python 3.12로 `uv init --package --python 3.12 --vcs none`.
실습은 `teaching_repo` 전체 clone에서 진행한다.

`main()`을 scripts가 `ex01`~`ex03`으로 연결한다.
`uv_build`로 설치하고 scripts 수정 뒤 `uv sync`한다.

주차 `shared`가 상대 path 의존성 `bleuno_control`을 import한다.

---

## 9–12분 · 시뮬레이터와 두 통신 경로

저장소 루트의 별도 터미널:

```powershell
uv run --python 3.12 tools/bleuno-sim/sim.py --bind 127.0.0.1
```

TCP 8266: 명령 전송. HTTP 8080: `GET /state`.
창 없는 검증에는 `--no-window`를 추가한다.

---

## 12–15분 · 연결 유지와 이벤트 구분

연결 직후 `hello` 이벤트가 먼저 온다.
중간 이벤트 행도 명령 응답에서 건너뛴다.

제어 중에는 같은 TCP 연결을 유지한다.
새 연결·연결 종료는 LED를 초기화한다.

상태 확인은 프로그램을 종료하기 전에 한다.

---

## 15–18분 · 수동 명령과 실제 상태

`uv run ex01`에서 화면의 수동 명령 형식을 따른다.

0번 켜기, 1번 밝기 128, 0번 끄기, 온습도 읽기.
매번 `http://127.0.0.1:8080/state`를 새로 조회한다.

함수 인수, 명령 응답, 실제 상태를 나란히 기록한다.

---

## 18–20분 · 1교시 실습 인계

[실습지](lab.md)의 수동 제어를 수행한다.

경계값과 범위 밖 입력을 비교한다.
빈 입력·다음 입력·종료를 확인한다.
함수 분리 이유와 종료 전 상태를 기록한다.

실습 30분, 휴식 10분.

# 2교시 · 설명 20분
## Ollama 도구 호출

---

## 0–3분 · 자연어 요청과 호출 제안

“0번 LED를 켜 줘.”

모델은 `turn_on`과 `index=0`을 제안한다.
Python이 인수를 검증하고 허용된 함수를 실행한다.
실행 뒤 실제 상태를 읽는다.

제안만으로 장치가 바뀌지는 않는다.

---

## 3–6분 · 도구 명세의 이름과 인수

모델에 함수의 이름·설명·인수 형식을 제공한다.

`index`: LED 번호 0~3.
`value`: 밝기 정수 0~255.

네 제어 함수만 선언한다.
센서 값을 바꾸는 `POST /set`은 제공하지 않는다.

---

## 6–9분 · Ollama의 같은 모델 연결

모델은 `qwen3.5:2b`를 사용한다.
`models.ollama_predict`에서 도구 호출을 요청한다.

`uv run ex02`

출력의 함수 이름과 인수를 먼저 읽는다.
실제 상태까지 대조한 뒤 다음 입력을 한다.

---

## 9–12분 · Python의 실행 전 검사

허용된 함수 이름인지 검사한다.
필수 인수의 누락과 추가 인수를 검사한다.
정수·범위를 확인하고 불리언을 거부한다.

검증을 통과한 호출만 실행한다.
모델의 제안 오류와 실행 차단을 따로 기록한다.

---

## 12–15분 · 거부 요청과 상태 관찰

`Turn on LED 4.`
`Set the temperature to 30 degrees.`

없는 번호와 없는 기능을 요청한다.
제안·Python 검증·실제 상태를 구분한다.

실행을 막았어도 잘못된 제안은 오류로 남긴다.

---

## 15–18분 · 반복 입력과 대화 이력

응답 뒤 다음 입력을 받는다. 빈 줄은 건너뛴다.
입력을 반복하는 것과 이전 문맥을 보내는 것은 다르다.

“그것을 꺼 줘”와 “0번 LED를 꺼 줘”를 구분한다.
검증 문항은 앞 문항의 대화에 의존하지 않는다.

장치 연결 유지와 모델 이력도 별개다.

---

## 18–20분 · 2교시 실습 인계

`uv run ex02`에서 직접 입력한다.

정상 요청·범위 밖 요청·없는 기능을 비교한다.
한글과 영어 입력의 반환을 실제로 기록한다.
성공 문장과 상태 일치를 구분한다.

실습 30분, 휴식 10분.

# 3교시 · 설명 20분
## 같은 입력 반복 검증

---

## 0–3분 · 고정된 16문항

공용 `control_cases.json`을 사용한다.

한글 8문항, 영어 8문항.
호출 10문항, 무호출 6문항.

같은 입력·기대값을 유지한다.
출력에 맞춰 정답을 바꾸지 않는다.

---

## 3–6분 · 초기 상태와 예열

매 문항 LED를 TCP로 `[0, 64, 128, 255]`에 복원한다.
모델 문항도 독립적으로 처리한다.

예열 1회는 점수·시간에서 제외한다.
모델 준비 시간은 따로 기록한다.

센서 읽기는 현재 실제 상태와 대조한다.

---

## 6–10분 · 선택·완전 일치·제어 성공

함수 선택: 어떤 함수를 골랐는가.
완전 일치: 이름·인수·호출 순서까지 맞는가.
제어 성공: 완전 일치하고 실제 상태도 맞는가.

무호출 오호출률: 무호출 6문항에서 호출을 제안한 비율.
검증이 막은 오호출도 기록한다.

---

## 10–14분 · 추론 시간의 median과 p95

모델 추론 구간만 측정한다.
LED 복원·함수 실행·HTTP 조회는 제외한다.

median은 중앙값, p95는 95백분위수다.
예열·준비 시간은 별도로 다룬다.

숫자는 실제 측정 뒤 기록한다.

---

## 14–17분 · 평가 실행과 실패 재현

`uv run ex03`: 같은 모델의 고정 평가.
`uv run ex02`: 틀린 입력을 직접 다시 넣는 대화.

제안 오류, 검증 차단, 통신 오류, 상태 불일치를 구분한다.
같은 입력을 반복해 결과 차이를 남긴다.

오류 문항을 지우고 집계하지 않는다.

---

## 17–20분 · 3교시 실습 인계

같은 16문항을 두 번 실행한다.
정확도 항목과 추론 median·p95를 나누어 적는다.

틀린 입력 하나를 `ex02`에서 재현한다.
모두 맞으면 한 문항의 호출·상태 근거를 설명한다.

실습 30분, 휴식 10분.
