# 10주차 따라하기

준비와 실습 시간표는 [실습지](lab.md)를 따른다. `teaching_repo` 전체를 clone하고 두 터미널을 사용한다. A는 저장소 루트의 시뮬레이터, B는 `open_source_ai/weeks/week10_simulator_control/examples`의 실행 명령이다.

## 준비 확인

터미널 A에서 `uv run --python 3.12 tools/bleuno-sim/sim.py --bind 127.0.0.1`을 실행한다. 창 없이 확인할 때는 `--no-window`를 추가한다. 터미널 B에서 `uv sync`를 실행하고 Ollama의 `qwen3.5:2b`가 준비됐는지 확인한다. 브라우저에서는 `http://127.0.0.1:8080/state`를 연다.

## 1교시 · 수동 명령

`uv run ex01`을 실행한다. `on 0`, `pwm 1 128`, `off 0`, `sensor`를 차례로 입력한다. 종료는 `/bye`다. 매번 `/state`를 새로 고침한다. 빈 줄은 명령을 보내지 않아야 한다. 번호 4와 밝기 256을 요청했을 때 상태가 바뀌지 않는지 확인한다.

`ex01_manual`이 입력을 네 제어 함수로 연결하는 부분과 `shared`의 `bleuno_control` import를 읽는다. 연결 직후 `hello`와 중간 이벤트를 제외하는 이유를 설명한다. 종료 전에 상태를 기록하고 종료 뒤 LED 초기화와 비교한다.

## 2교시 · 자연어 명령

`uv run ex02`에서 `Turn on LED 0.`과 `0번 LED를 켜 줘.`를 각각 입력한다. `Set LED 1 brightness to 128.`과 온습도 읽기도 입력한다. 모델 제안의 함수 이름과 인수, Python 검증, 실제 상태를 나란히 적는다. `Set the temperature to 30 degrees.`는 없는 기능 요청이다. 모델이 호출을 잘못 만들더라도 센서 쓰기 기능을 추가하지 않는다.

실제 동작을 확인하기 전에 모델의 완료 문장을 성공 증거로 쓰지 않는다. 다음 입력이 계속 가능한지 확인한 뒤 `/bye`로 끝낸다.

## 3교시 · 고정 평가

`uv run ex03`을 실행한다. `ex03_check`는 `load_cases`로 공용 16문항을 읽고 `evaluation.evaluate`로 평가한다. LED 복원값은 `[0, 64, 128, 255]`이고 예열 1회는 점수·시간에서 제외한다. 추론 median·p95에 모델 준비나 장치 제어 시간이 섞이지 않는지 읽는다.

같은 명령을 다시 실행해 문항별 차이를 기록한다. 함수 선택, 전체 호출 완전 일치, 제어 성공률, 무호출 오호출률을 구분한다. 틀린 입력을 직접 다시 넣으려면 `uv run ex02`를 실행한다. 결과가 모두 같아도 실제 근거를 적고 일반적인 성능 보장으로 확대하지 않는다.

## 막혔을 때

| 증상 | 확인 순서 |
|---|---|
| 공용 라이브러리를 찾지 못함 | 전체 clone 여부, `tools/bleuno-control`, 상대 source path, `uv sync` |
| 명령을 찾지 못함 | `examples/` 위치, scripts 연결, `uv sync` |
| TCP 연결 실패 | 터미널 A 실행 상태, 127.0.0.1:8266 |
| 상태 페이지 접속 실패 | 시뮬레이터 실행 상태, 127.0.0.1:8080/state |
| LED가 모두 꺼짐 | 새 연결·해제 여부, 종료 전 상태를 읽었는지 |
| 모델 호출 실패 | Ollama 실행 상태와 `ollama list`, 모델 이름 |
| 답은 성공인데 상태가 다름 | 제안·인수·검증·응답·실제 상태 순서로 대조 |
