# 4차 종합과제 루브릭 — 100점 상대 배점

이 루브릭은 공개 가능한 공통 기준이다. 배점은 100점 상대 배점이며, 학교 적용 시 실제 비율·마감은 학교 운영 문서가 정한다. 평가자는 [assignment_brief.md](assignment_brief.md)의 필수 산출물을 [examples/reviewer_checklist.md](examples/reviewer_checklist.md) 절차로 깨끗한 PC에서 확인한다.

## 배점 표

|---|---:|---|
| 릴리스 완결성(실행·재현·태그) | 25 | 처음 보는 PC에서 `git clone` → `uv sync --frozen` → README 절차 → `uv run pytest -q`가 개입 없이 통과한다. 릴리스 태그가 제출 commit을 가리킨다. 모델 ID·용량·캐시 방법과 GPU 없는 대체 경로가 README에 있다 |

## 수준별 판단

### 완전 충족

평가자가 README만으로 재현했고, 문서·수치·태그·이력이 서로 모순되지 않는다. 팀원 각자의 기여가 저장소 이력에서 확인된다. 한계와 실패 사례가 실제 평가 결과와 일치한다.

### 부분 충족

핵심 흐름은 실행되지만 한 단계 이상에서 평가자의 개입(문서에 없는 명령, 환경변수 추측)이 필요했다. 문서 중 일부가 실제 상태와 다르거나, 팀원 일부의 기여 증거가 없거나, 평가 수치는 있으나 문항 수·출처가 없다.

### 미충족

`uv sync --frozen`이 실패하고 원인이 릴리스 결함이거나, 태그가 없거나, LICENSE 또는 `SOURCES.md`가 없거나, 실행 증거가 재현 불가능한 캡처뿐이다. 본인 구현임을 확인할 수 없는 경우도 포함한다.

## 감점 적용 원칙

- 같은 원인(예: `uv.lock` 누락)이 여러 항목에 걸치면 릴리스 완결성에서만 감점하고 다른 항목에는 기록만 남긴다.
- 항목별 최대 배점을 넘겨 감점하지 않는다.
- 환경 문제(모델 미캐시·네트워크·포트 충돌)로 인한 실패는 감점하지 않고 기록한다. 단, README에 모델 ID·용량·대체 경로가 없으면 릴리스 완결성에서 감점한다.
- 실제 비밀 또는 개인정보가 저장소·이력·영상에 있으면 보안 항목을 0점으로 하고 즉시 제거·토큰 회전을 요구한다. 부정행위 판단과는 분리한다.
- 라이선스가 없는 자원을 사용한 경우 라이선스·출처 항목을 0점으로 한다.
- 제출 뒤 태그를 옮기거나 이력을 다시 쓴 경우 제출 시점의 commit id를 기준으로 채점하고 그 사실을 기록한다.
- 팀 점수와 별개로 개인 기여 증거가 없는 팀원은 협업 근거 항목을 개인별로 조정한다.
