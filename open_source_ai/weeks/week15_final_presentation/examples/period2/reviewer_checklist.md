## 검증 단계

| 단계 | 명령·행동 | 기대 결과 | 결과 | 근거 |
|---|---|---|---|---|
| 0. 기준본 확인 | 저장소 URL·릴리스 태그·commit id 기록 | 태그가 제출 commit을 가리킴 | | |
| 1. clone | `git clone <URL> .\review\team-b` → `git checkout v0.1.0` | 오류 없이 checkout, `git status` clean | | |
| 2. 동기화 | `uv sync --frozen` | lock 기준으로 설치 성공 | | |
| 3. 실행 | README 재현 절차대로 핵심 기능 1개 실행 | README의 예시와 같은 형태의 출력 | | |
| 4. 테스트 | `uv run pytest -q` | 전부 통과, 또는 README에 알려진 실패가 명시됨 | | |
| 5. 문서 | README·LICENSE·CONTRIBUTING·CHANGELOG·SOURCES 존재와 내용 | 설치·실행·한계·라이선스·출처 절이 있음 | | |
| 6. 라이선스·출처 | LICENSE ↔ `SOURCES.md`의 모델·데이터·의존성 라이선스 | 호환되고 SPDX ID·URL이 있음 | | |
| 7. 비밀·개인정보 | `verify_release.py` 비밀 패턴, `.env` 추적 여부, `git log -p` 검색 | 추적된 비밀·개인정보 없음 | | |
| 8. 평가·한계 | 평가 결과 파일과 한계·오류 사례 | 수치·실패 사례가 문서와 일치 | | |
| 9. 협업 근거 | `git shortlog -sn --no-merges HEAD`, PR·Issue·Review | 팀원별 commit·PR·리뷰 1개 이상 | | |

## 실패 분류

| 유형 | 예 | 처리 |
|---|---|---|
| 환경 문제(우발) | 모델 미캐시, 포트 충돌, 네트워크·프록시 | 재시도 1회 뒤 "환경"으로 기록. 릴리스 결함이 아님 |
| 릴리스 결함 | `uv.lock` 누락·불일치, README에 없는 단계, 테스트 실패, 태그 없음, 비밀 커밋 | Issue로 보고 |
| 설계 한계 | 모델 품질·속도, 범위 밖 기능 | 한계 항목에 명시되어 있는지만 확인 |
