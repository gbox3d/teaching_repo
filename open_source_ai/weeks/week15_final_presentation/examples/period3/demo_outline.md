# 시연 3분 + 질의 2분 개요

팀: team-a · 발표 기준본: 태그 `v0.1.0` · commit `abc1234` · 발표자: student01 · 기록 담당: student02

기준본은 릴리스 태그가 가리키는 commit이다. 발표 직전에 `git status`가 clean이고 `git describe --tags`가 기준 태그인지 확인한다.

## 시연 3분

| 시간 | 화면·동작 | 말할 핵심 | 증거 |
|---:|---|---|---|
| 0:00–0:30 | 저장소 README 첫 화면, `git describe --tags` 출력 | 문제·사용자·한 줄 가치 | 저장소 URL, 릴리스 태그 |
| 0:30–1:45 | 터미널 또는 UI에서 핵심 흐름 1개를 실제로 실행 | 입력 → 출력, 출처·모델 표시, 오류 처리 1개 | 실행 출력, `outputs/` 기록 |
| 1:45–2:20 | 평가 결과 수치 1개와 실패 사례 1개 | 좋아진 것과 못 한 것을 같은 무게로 | `outputs/eval-*.json`, `FAILURE_ANALYSIS.md` |
| 2:20–3:00 | README 재현 절차 3줄, 열린 Issue 목록 | 누가 어떻게 재현·기여하는가, 다음 단계 | README, Issues |

시연 명령은 순서대로 한 파일에 적어 두고 복사해 실행한다. 저장소 열기·서버 켜기·모델 로드는 발표 전에 끝낸다.

## 장애 대체(fallback)

| 상황 | 대체 |
|---|---|
| Ollama 서버 미기동 | `ollama serve` 재시작 1회. 실패하면 사전 저장한 `outputs/` 결과로 같은 흐름을 설명 |
| GPU 인식 실패 | CPU 대체 모델(`OLLAMA_MODEL=qwen3:0.6b`)로 같은 흐름 실행. 속도 차이를 한계로 말함 |
| 네트워크 실패 | 로컬 clone본에서 실행. GitHub 화면은 사전 캡처 |
| 시연 도중 중단 | 화면 녹화의 해당 시점부터 재생. 기록 담당이 중단 원인을 적음 |

## 화면 점검

- [ ] 터미널 글꼴을 키웠고 프롬프트에 개인 경로·계정명이 보이지 않는다.
- [ ] `.env`·토큰·개인정보가 화면에 나오지 않는다.
- [ ] 시연 명령 파일과 fallback 자료(`outputs/`, 녹화)가 발표 PC에 있다.
- [ ] 리허설 측정값: 시연 ____분 ____초 / 실제 실행 구간 ____초
