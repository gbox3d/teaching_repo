# 최종 발표 루브릭 — 시연·질의응답 100점

15주차 1교시 최종 발표(팀당 시연 3분 + 질의 2분)의 평가 기준이다. 배점은 100점 상대 배점이며, 학교 적용 시 실제 비율·발표 순서·확장 시간은 학교 운영 문서가 정한다. 9주차 제안 발표 루브릭과 짝을 이루며, 이번에는 "계획"이 아니라 "재현 가능한 결과"를 본다.

## 배점 표

| 항목 | 배점 | 완전 충족 기준 |
|---|---:|---|
| 문제·사용자 전달 | 15 | 시작 30초 안에 문제·사용자·한 줄 가치가 나온다. 제안서의 Must와 릴리스의 실제 범위 차이를 숨기지 않는다 |
| 시연 | 30 | 릴리스 태그 기준본(`git describe --tags`)에서 핵심 기능 1개를 실제로 실행한다. 출력에 출처·모델 표시가 보이고, 오류 처리 1개(Ollama 미기동·잘못된 입력 등)를 보여 준다 |
| 평가 결과·한계의 정직성 | 15 | 기준선 대비 수치 1개(문항 수·평가셋 출처 포함)와 실패 사례 1개를 같은 무게로 말한다. "다 된다"는 표현이 없다 |
| 재현·다음 단계 | 10 | README 재현 절차 3줄과 열린 Issue를 보이고, 누가 어떻게 재현·기여할 수 있는지와 다음 조치를 말한다 |
| 시간·구성 | 10 | 시연 3분 이내, 문제 → 시연 → 한계 → 다음 순서, 화면에 토큰·`.env`·개인 경로·실명이 없다. 장애 시 fallback으로 시간 안에 마친다 |
| 질의응답 | 20 | 질문을 다시 말하고 → 현재 사실(파일·commit·수치) → 선택 이유 → 한계·다음 조치 순으로 답한다. 모르면 모른다고 말하고 확인 방법을 말한다. 팀원 각자 최소 1개 질문에 답한다 |
| 합계 | 100 | |

## 수준별 판단

### 완전 충족

기준본에서 실제 실행이 있었고, 수치와 실패 사례가 저장소 파일과 일치하며, 질의에 근거 파일을 가리키며 답했다. 시간 안에 마쳤다.

### 부분 충족

실행은 있었으나 태그 밖이거나 캡처·녹화로 대체했고 장애 원인 기록이 없다. 한계를 말했지만 수치가 없다. 질의에 사실 대신 의견으로 답했다. 시간을 30초 이상 넘겼다.

### 미충족

실행 없이 설명만 했거나, 기준본을 확인할 수 없거나, 질의에 답하지 않았다. 화면에 실제 비밀·개인정보가 노출된 경우도 포함한다.

## 감점 적용 원칙

- 장애(Ollama·GPU·네트워크)가 나도 `demo_outline.md`의 fallback으로 시간 안에 마치고 기록 담당이 원인을 적었으면 시연 항목에서 감점하지 않는다. 리허설 부족으로 인한 중단(서버를 안 켬, 모델을 안 로드함)은 시간·구성에서 감점한다.
- 발표 결과와 저장소 검증 결과는 별개다. 시연이 실패해도 저장소가 재현되면 기말평가 루브릭에서는 감점하지 않고, 반대로 시연이 좋아도 저장소가 재현되지 않으면 이 루브릭에서 시연 항목을 부분 충족으로 본다.
- 팀 발표이지만 질의응답은 개인별로 기록할 수 있다. 답하지 않은 팀원은 질의응답 항목을 개인별로 조정한다.
- 화면에 실제 비밀·개인정보가 노출되면 시간·구성 항목을 0점으로 하고 즉시 제거·토큰 회전을 요구한다. 부정행위 판단과는 분리한다.
- 항목별 최대 배점을 넘겨 감점하지 않는다.
- 팀 수가 많아 발표가 학교 시간표에 따라 확장·분할되어도 팀당 시간과 기준은 같게 적용한다.
