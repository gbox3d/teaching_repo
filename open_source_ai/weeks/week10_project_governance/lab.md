# 10주차 실습 · 함수 호출과 실제 상태 확인

각 교시는 설명·시연 20분, 아래 실습 30분, 휴식 10분이다. 설치와 모델 다운로드는 수업 전에 마친다. 실습 기록은 개인 `week10_note.md`에 적으며 결과 JSON 저장 프로그램은 만들지 않는다.

## 수업 전 준비

저장소 밖의 연습용 폴더에서 다음 명령으로 구조를 확인한다. 기존 `examples/`에 다시 초기화하지 않는다.

```powershell
uv init --package --python 3.12 --vcs none week10-skeleton
```

`.python-version`, `pyproject.toml`, `src/`를 찾는다. `main()`은 실행 시작점, `[project.scripts]`는 명령 연결, `[build-system]`의 `uv_build`는 패키지 설치 방법이다. scripts를 수정하면 `uv sync`를 다시 실행한다.

실제 실습은 전체 저장소를 clone한 경로에서 진행한다. 이미 clone했다면 그 경로를 사용한다.

```powershell
git clone https://github.com/gbox3d/teaching_repo.git
cd teaching_repo
```

터미널 A는 저장소 루트에 두고 시뮬레이터를 실행한다.

```powershell
uv run --python 3.12 tools/bleuno-sim/sim.py --bind 127.0.0.1
```

창 없이 확인할 때만 `--no-window`를 추가한다. 시뮬레이터는 켜 둔다. 터미널 B도 같은 저장소 루트에서 시작한 뒤 다음과 같이 이동한다.

```powershell
cd open_source_ai/weeks/week10_project_governance/examples
uv sync
```

이후 세 교시의 `uv run ex01`~`uv run ex03`은 모두 터미널 B에서 실행한다. `period1`~`period3`로 이동하지 않는다. `examples/`만 복사하면 `[tool.uv.sources]`의 상대 path가 끊긴다. 주차 `shared`가 import하는 `bleuno_control`은 저장소의 `tools/bleuno-control`에 있다.

브라우저에서 `http://127.0.0.1:8080/state`를 연다. TCP 8266은 명령을 보내는 연결이고 HTTP 8080은 상태를 읽는 주소다. 연결 직후의 `hello`와 중간 이벤트는 명령 응답에서 제외한다. TCP 연결을 새로 만들거나 끊으면 LED가 초기화되므로 프로그램을 종료하기 전에 상태를 확인한다.

Ollama를 실행하고 `ollama list`에서 `qwen3.5:2b`를 확인한다. 모델이 없을 때는 수업 전에 `ollama pull qwen3.5:2b`로 준비한다.

## 1교시 실습 · Python 직접 제어

| 실습 구간 | 활동 |
|---|---|
| 0–5분 | 입력 안내와 네 함수의 인수 확인, 실행 전 상태 예상 |
| 5–15분 | `uv run ex01`에서 LED 켜기·밝기 변경·끄기·온습도 읽기 |
| 15–23분 | 번호·밝기의 경계값과 잘못된 입력 비교 |
| 23–30분 | 연결을 유지하며 상태를 기록하고 함수 분리 이유 설명 |

1. `uv run ex01`을 실행한다. `on 0`, `pwm 1 128`, `off 0`, `sensor`를 차례로 입력한다. 각각 0번 LED 켜기, 1번 LED 밝기 128, 0번 LED 끄기, 온습도 읽기다.
2. 각 명령 뒤 `GET /state`를 새로 조회한다. 켜기는 해당 값 255, 끄기는 0, 밝기 변경은 요청한 값인지 비교한다. 다른 LED가 바뀌었는지도 확인한다.
3. LED 번호 0·3과 밝기 0·255는 허용 범위다. 번호 4, 밝기 256은 거부해야 한다. Python의 `bool`은 정수 검사에 포함될 수 있으므로 `True`·`False`를 별도로 거부하는 코드를 찾는다. 수동 입력기가 불리언을 숫자로 읽지 못하는 것과 공용 함수가 불리언을 거부하는 것을 구분한다.
4. 온습도 출력과 `/state`의 현재 값을 비교한다. 창의 센서 슬라이더를 움직였다면 다시 읽는다. 센서를 읽는 함수에는 값을 바꾸는 인수가 없다.
5. 빈 줄 뒤에도 입력을 계속 받는지 확인하고 `/bye`로 끝낸다. 종료 전과 종료 뒤 LED 상태가 다른 이유를 적는다.

기록 항목: 입력, 실행한 함수·인수, 응답, 실제 상태, 예상과 다른 점. 같은 제어 함수를 수동 입력과 모델 입력에서 재사용하면 검증 기준을 한곳에서 유지할 수 있다는 점을 자기 말로 설명한다.

## 2교시 실습 · Ollama 호출 제안

| 실습 구간 | 활동 |
|---|---|
| 0–5분 | `uv run ex02` 실행, 도구 이름·인수 예상 |
| 5–15분 | 자연어 명령을 반복 입력하고 호출 제안·상태 대조 |
| 15–23분 | 범위 밖 입력과 없는 기능을 요청해 처리 확인 |
| 23–30분 | 실패 한 건 재현 또는 성공 근거 설명 |

다음은 요청할 입력이다. 실제 응답을 미리 정해진 결과처럼 기록하지 않는다.

```text
Turn on LED 0.
Set LED 1 brightness to 128.
Turn off LED 0.
Read the temperature and humidity.
Turn on LED 4.
Set the temperature to 30 degrees.
```

각 유효 입력 뒤 다음 질문을 받는지 확인한다. 위 영어 입력과 같은 의미의 한국어 입력도 비교한다. 고정 평가셋에는 한글 8문항과 영어 8문항이 함께 들어 있다. 직접 추가한 입력은 고정 평가셋 점수와 구분한다.

도구 목록은 네 함수뿐이다. Python은 함수 이름, 인수 이름·개수, 정수 여부와 범위를 검사한다. LED 4나 센서 쓰기 요청이 들어와도 허용 범위를 넓히지 않는다. 모델이 잘못된 호출을 제안했지만 Python이 막았다면 “호출 선택 실패·실행 차단”으로 구분한다.

완료 기준은 말로 “켰다”고 답한 사실이 아니라 호출 제안과 실제 상태를 연결한 설명이다. 명령이 끝나도 제어 프로그램을 종료하지 않고 `/state`를 확인한다.

## 3교시 실습 · 같은 입력 반복 검증

| 실습 구간 | 활동 |
|---|---|
| 0–5분 | 고정 평가셋의 입력·예상 호출·거부 항목 읽기 |
| 5–15분 | `uv run ex03`을 실행해 문항별 결과와 시간 확인 |
| 15–23분 | 같은 평가셋을 다시 실행하고 차이 비교 |
| 23–30분 | 틀린 문항을 `ex02`에서 재현하고 기록 정리 |

모델은 2교시와 같은 `qwen3.5:2b`다. 테스트 입력과 기대값을 실행 결과에 맞춰 고치지 않는다. 각 문항의 초기 상태를 맞추고 이전 대화가 다음 문항에 섞이지 않게 하는 부분을 코드에서 확인한다.

다음 표를 실제 출력으로 채운다. 첫 준비·다운로드 시간은 반복 호출 시간과 분리한다. 모델 시간은 추론 구간만 기록한다. 실제 제어·상태 확인 시간과 모델 준비 시간은 섞지 않는다.

| 실행·문항 | 예상 함수·인수 또는 거부 | 실제 제안 | Python 검증 | 실제 상태 일치 | 측정 구간·시간 |
|---|---|---|---|---|---|
| 첫 실행 | 직접 기록 | 직접 기록 | 직접 기록 | 직접 기록 | 직접 측정 |
| 같은 입력 재실행 | 같은 기준 | 직접 기록 | 직접 기록 | 직접 기록 | 직접 측정 |

함수 선택과 전체 호출 완전 일치를 구분한다. 이름·인수·순서가 모두 맞아야 완전 일치다. 실제 상태와 무호출 문항의 오호출도 별도로 집계한다. 통신·모델 오류로 수행하지 못한 문항은 이유를 남기고 성공에 포함하지 않는다.

모두 맞았다면 입력 하나의 함수·인수·상태를 연결해 설명한다. 실패가 있다면 함수 선택, 인수, 검증, 연결, 상태 관찰 중 어느 단계인지 나누고 다음 확인 방법을 적는다. 실습 뒤 10분은 휴식이다.

## 고정 평가셋과 측정 기준

평가 입력은 저장소 공용 [control_cases.json](../../../tools/bleuno-control/src/bleuno_control/data/control_cases.json)의 16문항이다. 한글 8개·영어 8개이며 호출 문항 10개·무호출 문항 6개다. 문항마다 LED를 TCP 명령으로 `[0, 64, 128, 255]`로 복원한다. 센서 값은 그 시점의 읽기 결과와 상태를 대조한다.

예열 1회는 점수와 시간 통계에서 제외한다. 모델 시간은 추론만 측정하며 모델 준비, LED 복원, 함수 실행, HTTP 상태 조회 시간을 섞지 않는다. 준비 시간은 별도로 기록한다.

| 평가 항목 | 의미 |
|---|---|
| 함수 선택 정확도 | 유효한 호출의 함수 이름 순서 비교. 전체 인수 일치와 분리 |
| 전체 호출 완전 일치 | 함수 이름·인수·호출 순서가 모두 기준과 일치 |
| 제어 성공률 | 호출 완전 일치에 더해 실행 후 실제 상태까지 일치 |
| 무호출 문항 오호출률 | 무호출 6문항에서 불필요한 호출을 제안한 비율 |
| 추론 시간 median·p95 | 예열을 뺀 추론 시간의 중앙값·95백분위수 |

`confidence`는 위 평가 항목의 대체값이 아니다. 전체 수치와 함께 한글·영어 문항별 실패를 읽는다. 16문항의 p95는 이 작은 평가셋의 관찰값이며 일반적인 응답 시간 보장으로 해석하지 않는다.
