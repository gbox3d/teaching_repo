# 1교시 · 설명 20분
## 첫 화면과 입력 위젯

---

## 0–3분 · 터미널 기능을 화면으로 연결한다

Ollama → LangChain → RAG → LoRA에서 확인한 기능을 사용자가 입력할 수 있는 화면으로 연결한다.

8주차 평가 뒤 이번 주에는 앱 하나를 직접 완성한다.

---

## 3–6분 · 패키지에서 앱을 실행한다

Python 3.12로 uv 패키지 프로젝트를 확인한다. main은 시작 함수, scripts는 명령 연결, build-system은 설치 방법이다.

`uv run ex01`이 Streamlit을 실행한다. 루트에서 실행하고 Ctrl+C로 종료한다.

---

## 6–9분 · 입력과 출력을 놓는다

```python
name = st.text_input("수업용 이름")
if st.button("인사 출력"):
    st.write(f"{name}님, 안녕하세요.")
```

값을 입력하고 버튼을 눌러 출력을 확인한다.

---

## 9–12분 · 위젯을 바꾸면 재실행된다

버튼·입력 이벤트에서 스크립트가 다시 실행된다. 터미널의 while 입력 반복과 다른 실행 방식이다.

소스를 저장해 화면이 갱신되는지도 확인한다.

---

## 12–16분 · 첫 앱을 직접 바꾼다

제목과 인사 문장 한 개를 바꾼다. 화면의 어느 부분이 어떤 코드인지 짚는다.

입력값·버튼·출력이 연결되면 첫 단계는 완료다.

---

# 2교시 · 설명 20분
## 기억하며 대화하는 앱

---

## 0–3분 · 기존 로컬 모델을 사용한다

5주차 ChatOllama와 같은 서버·모델을 쓴다. API 키가 새로 필요하지 않다.

연결 설정은 shared의 OLLAMA_MODEL·OLLAMA_HOST다.

---

## 3–6분 · 채팅 입력과 말풍선

st.chat_input은 질문을 받고 st.chat_message는 사용자·AI 메시지를 구분해 보여 준다.

웹 앱에 while True 입력 루프를 넣지 않는다.

---

## 6–9분 · 재실행 사이에 상태를 보존한다

session_state.messages에 메시지를 넣고 다음 실행에서 다시 그린다.

화면 상태 보존과 모델에 과거 메시지를 보내는 일을 모두 확인한다.

---

## 9–12분 · 도착한 답을 바로 출력한다

st.write_stream에 문자열 조각을 전달한다. 완성한 답은 메시지 목록에도 남긴다.

재실행이 무조건 중복 호출을 만들지 않도록 질문이 들어온 경우에만 호출한다.

---

## 12–16분 · 대화를 지워 비교한다

색을 알려 준 뒤 다시 묻는다. 대화 지우기를 누르고 화면 메시지가 없어지는지 확인한다.

새 세션을 장기 저장소와 혼동하지 않는다.

---

# 3교시 · 설명 20분
## 내 문서에 질문하는 앱

---

## 0–3분 · 작은 문서부터 사용한다

기본 자료는 가상 도서관 안내다. 다른 문서는 UTF-8 txt로 업로드한다.

빈 줄로 나눈 문단을 검색 단위로 쓴다.

---

## 3–6분 · 임베딩과 검색을 재사용한다

6주차처럼 문단과 질문을 임베딩하고 코사인 유사도로 가까운 문단을 찾는다.

질문에는 query:, 문단에는 passage:를 붙이는 모델이다.

---

## 6–9분 · 반복 계산을 줄인다

cache_resource로 모델을, cache_data로 같은 문단의 임베딩을 재사용한다.

모델 다운로드와 설치는 수업 전에 마친다.

---

## 9–12분 · 답과 검색 근거를 함께 보여 준다

검색 문단을 펼쳐 답의 문단 번호와 대조한다. 높은 점수는 정답 확률이 아니다.

자료 밖 질문에는 찾을 수 없다고 답하는지도 확인한다.

---

## 12–16분 · 완성한 앱의 선택 확장

얼굴·이미지 임베딩 비교, 음성 입력·출력, 약 1B급 소형 모델 비교 중 하나를 고른다.

모든 확장을 필수로 추가하지 않는다. 입력 → 모델 → 출력이 보이는 시연으로 소개한다.

---
