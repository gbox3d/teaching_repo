# 7주차 — 내 답변 예시로 배우는 LoRA

4·5주차에는 Ollama 모델과 대화했고, 6주차에는 신화 자료를 검색해 질문에 넣었다. 이번에는 신화 안내자의 답변 예시를 직접 수정해 작은 모델을 학습시킨다. 학습한 결과를 저장하고 다시 불러와 대화하는 것까지 이어 간다.

학습할 0.5B 모델은 세 줄로 답하라는 지시를 받아도 형식 없이 한두 문장으로 답했다(교재 검증 PC, 실습에서 직접 확인한다). 그래서 지시 대신 원하는 형식의 답변 예시를 보여 주며 학습시킨다. 각자 정한 항목 이름이 학습 뒤 답변에 나오는지로 학습 효과를 확인한다. 짧은 학습으로 바뀌는 것은 형식이며, 사실에 맞는 답은 6주차 RAG처럼 자료를 넣는 방법으로 얻는다.

## 실행과 학습의 차이

| 지금까지 한 일 | 이번에 추가하는 일 |
|---|---|
| Ollama가 실행하는 모델에 질문을 보낸다 | Python에서 모델을 불러와 학습할 부분을 붙인다 |
| 프롬프트로 지시하거나 RAG로 자료를 넣는다 | 질문·답변 예시로 LoRA 어댑터를 학습한다 |
| 모델의 가중치는 바뀌지 않는다 | 학습한 어댑터를 저장하고 기본 모델과 함께 불러온다 |

Transformers는 모델과 토크나이저를 불러오고 실행하는 라이브러리다. PEFT는 기본 모델에 LoRA를 붙인다. `Trainer`는 학습 반복을 맡는다. 도구 이름을 먼저 외우지 않고, 기존 대화 예제에 학습 기능이 필요한 이유부터 확인한다. PyTorch 특강은 선수 과목이 아니다.

## 학습 모델과 준비

첫 대화는 4·5주차의 `qwen3.5:2b`를 그대로 쓴다. 학습은 시간을 줄이기 위해 `Qwen/Qwen2.5-0.5B-Instruct`를 쓴다. 서로 다른 모델의 답변 차이를 학습 효과로 비교하지 않는다. 학습 전후 비교는 `ex04`에서 **같은 0.5B 모델의 어댑터를 끄고 켜며** 수행한다.

Python 3.12와 uv를 사용한다. 모델 다운로드와 `uv sync --locked`, `uv run prepare`는 수업 전에 마친다. GPU에서는 CUDA 또는 Apple Silicon의 MPS를 자동 선택하고, 둘 다 없으면 CPU를 쓴다. 실제 소요 시간은 기준 PC에서 먼저 확인한다. CPU가 느리면 `STEPS = 3`으로 저장·복원 경로를 확인하고, 강의자가 제공한 같은 모델의 어댑터로 비교를 이어 간다. 이 경우 직접 학습한 것과 배포본을 사용한 것을 기록에 구분한다.

NVIDIA GPU로 학습하려면 CUDA를 지원하는 PyTorch 빌드를 설치해야 한다. [예제 TOML](examples/pyproject.toml)에는 CUDA 저장소와 `torch`의 출처 설정이 이미 들어 있다. [CUDA용 PyTorch 설치 설정](examples/README.md#cuda용-pytorch-설치-설정)에서 `cu128`·`explicit`·`marker`의 의미, 잠금 파일 갱신 순서, GPU 사용 확인 방법을 확인한다. [슬라이드의 수업 전 준비](slides.md#수업-전-준비--cuda용-pytorch)에서도 같은 내용을 다룬다. Ollama가 GPU를 쓰는 것만으로 Python의 CUDA 준비가 확인되지는 않는다.

- [ ] `experiments/run-001.md`에 데이터 변경, 실제 설정, loss 관찰, 전후 답변, 한계를 적었다.

loss 감소나 특정 답변 출현을 통과 조건으로 삼지 않는다. 짧은 학습에서 변화가 없거나 답변이 나빠져도 실제 관찰을 설명하면 된다. 이번 주 별도 제출은 없으며, 기록은 이후 평가·앱 실습에 이어 쓴다. 가중치와 가상환경은 개인 Git 저장소에 올리지 않는다.
