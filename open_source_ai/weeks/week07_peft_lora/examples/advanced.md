# 선택 심화 — LoRA 내부와 답변 범위

기본 실습의 저장·복원·전후 비교를 마친 뒤 읽는다. 아래 활동은 필수 완료 조건이 아니다.

## rank와 학습 파라미터

LoRA는 원래 가중치 W를 고정하고 작은 행렬 A와 B로 만든 변화를 더한다.

```text
y = W x + (alpha / r) B A x
A: (r, in) / B: (out, r)
추가 파라미터 수: r × (in + out)
```

이 예제는 `q_proj`, `v_proj`에만 붙이고 `alpha = 2 × RANK`로 둔다. 이는 수업의 고정 설정이며 모든 모델의 최적 설정은 아니다. `RANK`를 4 또는 16으로 바꿀 때는 다른 조건을 유지하고 공용 `ADAPTER_DIR`도 새 이름으로 바꾼다. `print_trainable_parameters()`의 수와 같은 질문의 답을 비교한다. rank가 크다고 항상 답이 나아지지 않는다.

## 메모리 관찰

원래 가중치, 학습하는 부분의 그래디언트·옵티마이저 상태, 중간 계산값이 메모리를 쓴다. LoRA는 학습할 파라미터 수를 줄여도 기본 모델을 메모리에 불러와야 한다. 길이와 배치도 메모리에 영향을 준다.

기본 코드는 CPU·CUDA·MPS에서 같은 저장·복원 흐름을 보여 주기 위해 float32를 쓴다. 작은 어댑터 파일의 크기만으로 필요한 VRAM을 계산하지 않는다. GPU 도구나 작업 관리자로 관찰하고 실제 사용량과 예측을 구분한다. bf16·QLoRA 설정은 별도 확장이다.

## 답변만 학습하는 마스킹

[shared/training.py](src/shared/training.py)의 `training_examples()`를 읽는다. 동일한 chat template로 질문까지의 토큰과 정답까지의 토큰을 만든다.

```text
입력: [system] [질문] [assistant 시작] [정답] [끝 토큰]
라벨: [-100 … 질문 부분은 제외 …] [정답] [끝 토큰]
```

`-100`은 loss 계산에서 제외하는 값이다. 질문을 정답으로 채점하지 않고 제공한 답변 부분을 학습한다. 패딩 라벨도 같은 값으로 가린다. 길이가 넘으면 조용히 답변을 잘라 버리지 않고 오류로 알려 준다. 다른 모델의 템플릿으로 변경할 때는 질문 접두부와 정답의 경계가 맞는지 다시 확인한다.

## 병합과 실행기 변경

`merge_and_unload()`는 학습한 변화를 기본 가중치에 합친다. 어댑터를 붙인 모델과 병합 모델은 같은 변화를 담지만 계산 정밀도에 따라 출력 차이가 생길 수 있다. Ollama의 양자화·템플릿·생성 설정까지 달라지면 전후 비교 조건이 더 바뀐다. 학습 효과는 `ex04`, 배포 동작은 Ollama 실행으로 나눠 확인한다.

## 추가로 생각해 볼 일: 자료에 없는 질문과 답변 거절

이번 실습에서 답변 형식을 배웠다고 해서 학습 자료에 없는 질문을 자동으로 거절하지는 않는다. LoRA는 기본 모델의 가중치를 고정하고 학습한 변화를 더한다. 기본 모델의 기존 지식을 지우거나, 답해도 되는 사실 목록을 따로 만드는 방식이 아니다. [PEFT의 LoRA 설명](https://huggingface.co/docs/peft/main/en/conceptual_guides/lora)

현재 `answer()`에는 질문과 system 지시만 들어간다. 학습에 쓴 24건을 다시 검색하거나 질문의 범위를 검사하지 않는다. 따라서 “학습 자료에 있을 때만 답하세요”라는 지시만으로 자료 포함 여부를 정확히 판별하기는 어렵다. 학습 질문과 표현이 달라도 자료로 답할 수 있는 경우와, 같은 신화 주제라도 자료에 근거가 없는 경우를 구분해야 한다.

### 답변을 제한하는 방법과 한계

RAG를 반드시 붙여야 하는 것은 아니다. 서비스에서 허용할 답변을 먼저 정한 뒤 방법을 선택한다. 다음은 확장 방향이며 이번 주 예제에 구현된 기능은 아니다.

| 방법 | 추가할 것 | 남는 한계 |
|---|---|---|
| 프롬프트 지시 | 답할 주제와 거절 문구를 system 지시에 명시 | 지시를 어길 수 있다. 주제를 지정해도 학습 자료에 있는 사실인지는 알 수 없다. |
| 거절 예시를 함께 학습 | 정상 질문·답변과 범위 밖 질문·거절 답변을 섞어 LoRA 학습 | 거절을 학습시키는 방법이지만 모든 새 질문에서 지킨다는 보장은 없다. 정상 질문까지 거절할 수 있다. |
| RAG와 생성 전 코드 검사 | 허용 자료를 검색하고, 정한 근거 기준을 통과한 경우에만 모델 호출 | 검색 점수가 높아도 답의 근거가 없을 수 있다. 생성한 답이 자료 밖 내용을 덧붙일 수도 있다. |
| 생성 후 근거 검사 | 답변의 주장과 출처를 대조하고, 근거가 부족한 답변은 보류 | 검사 모델도 틀릴 수 있고 실행 시간과 비용이 늘어난다. |
| 허용 질문·항목과 고정 답변 | 허용한 질문 종류를 코드로 확인하고 등록된 답변만 반환 | 새 표현과 복합 질문 대응이 제한된다. 인물 이름만 허용하고 나머지를 자유롭게 생성하면 내용 제한이 되지 않는다. |

LoRA와 RAG를 함께 쓴다면 LoRA에는 답변 형식·말투·거절 행동을 학습시키고, RAG에는 답의 근거를 맡기는 구성을 생각할 수 있다. [6주차 RAG](../../week06_embeddings_rag/README.md)에서 배운 검색 다음에 검사 단계를 두는 것이다. [Hugging Face RAG 예제](https://huggingface.co/learn/cookbook/en/advanced_rag)도 검색 자료를 넣고, 그 자료에서 답을 얻을 수 없으면 답하지 않도록 지시한다. 이 지시 자체가 코드의 차단 조건은 아니다.

```text
질문 → 허용 자료 검색 → 정한 근거 기준 검사
                       ├─ 미달: 모델을 호출하지 않고 고정 거절 문구 반환
                       └─ 통과: 검색 자료와 질문으로 답변 생성
```

이 구성은 기준에 미달한 질문의 생성을 코드로 막는다. 다만 검색 유사도는 “질문과 글이 비슷한 정도”이며, 답할 근거가 충분하다는 판정과 같지 않다. 기준을 높이면 근거 없는 답이 줄어들 수 있지만 답할 수 있는 질문도 놓칠 수 있다. 승인한 내용만 출력해야 한다면 자유 생성보다 등록된 답변을 그대로 반환하는 구성을 검토한다.

### 비교할 질문과 기록

먼저 답변 근거를 [현재 24건의 질문·답변](src/shared/data/sample_sft.jsonl)으로 제한한다고 정한다. 아래는 그 기준의 질문 예시이며 실제 모델의 실행 결과가 아니다. 자료 내용을 바꾸면 기대 행동도 다시 정한다.

| 질문 유형 | 질문 예시 | 기대 행동 |
|---|---|---|
| 자료로 답할 수 있는 다른 표현 | “제우스를 상징하는 물건을 알려 줘.” | 자료의 번개 설명으로 답한다. 학습 질문과 글자가 다르다는 이유로 거절하지 않는다. |
| 주제는 같지만 근거 없음 | “제우스 신전을 짓는 데 정확히 얼마가 들었어?” | 자료에 건축비가 없음을 알리고 숫자를 만들지 않는다. |
| 주제 밖 | “프린터의 와이파이를 설정하는 방법은?” | 정한 범위 밖임을 알린다. |
| 틀린 전제가 있는 질문 | “제우스의 대표 상징은 삼지창이지?” | 질문에 동의하지 않고 자료에 따라 번개라고 정정한다. |

기본 비교는 `ex04`에서 위 질문을 입력하고 어댑터를 껐을 때와 켰을 때의 답을 기록하는 것으로 충분하다. 거절 기능 구현이나 추가 학습은 필수 과제가 아니다. 확장 실험에서는 프롬프트, 거절 학습 데이터, 검색 검사 중 한 조건만 바꾸고 같은 질문으로 비교한다. 거절 학습에 쓴 문장을 평가 질문에 그대로 재사용하지 않는다.

기록에는 실제 답변과 자료의 근거, 근거 없이 답한 횟수, 답할 수 있는데도 거절한 횟수를 남긴다. “신화 질문에만 답하기”와 “이 자료에 근거가 있는 질문에만 답하기” 중 어느 요구를 구현했는지, 거절을 늘렸을 때 정상 질문을 얼마나 놓쳤는지 설명한다. 몇 개의 질문을 통과한 결과를 모든 질문의 거절 보장으로 해석하지 않는다.
