# 1교시 · 설명 20분
## 기말과제와 챗봇 실행

---

## 0–3분 · 기말과제의 두 성적 항목

원광대학교 소개 챗봇을 만들고, 같은 도구로 성능을 확인한다.

| 성적 항목 | 평가 근거 |
|---|---|
| 발표 점수 | 15주차 비공개 문제의 AI 성능 평가 점수 |
| 레포트 점수 | 별도로 제출하는 개발정리 보고서 |

기존 발표·레포트 배점을 각각 적용한다.
발표 말솜씨·발표 시간은 채점하지 않는다. 학교 배점·마감은 추후 공지한다.

## 3–7분 · 공식 요약 문서 다섯 개

| 문서 ID | 공식 요약의 주제 |
|---|---|
| `wku-location` | 위치·주소·연락처 |
| `wku-values` | 교훈·교육목표·건학정신 |
| `wku-symbols` | 교색·교조·교목·교화 |
| `wku-history` | 초기 연혁 |

평가 범위는 이 다섯 요약이다. 문서 밖 정보는 추측하지 않는다.

---

## 7–11분 · 입력 하나와 반환값 세 개

`student_bot.answer(question)`은 질문 문자열을 받아 사전을 반환한다.
도시와 교조를 함께 물은 예:

```python
{"answers": ["익산시", "봉황"],
 "sources": ["wku-location", "wku-symbols"], "abstain": False}
```

`answers`에는 사실 하나씩 짧게, `sources`에는 URL 대신 문서 ID를 넣는다.
`abstain`은 불리언이다. JSON에서는 `false`이며 문자열 `"false"`는 오류다.
평가 호출은 질문마다 독립적이다. [평가 규격](evaluation_spec.md)

---

## 11–15분 · 터미널에서 질문을 이어서 입력한다

14주차의 `examples/` 폴더에서 실행한다.

```sh
uv sync
uv run ex01
```

질문 입력, 응답 확인, 다음 질문 입력을 반복한다.
빈 입력은 건너뛰고 `/bye` 또는 Ctrl+C로 종료한다.
반복 입력은 대화 이력 유지와 다르다. 평가 함수는 질문 하나씩 처리한다.

## 15–18분 · 하나의 Python 3.12 프로젝트

프로젝트를 처음 만드는 명령과 생성된 구조를 확인한다.

```sh
uv init --package --python 3.12 --vcs none wku-bot
```

수업에서는 이미 제공한 `examples/` 프로젝트 하나를 계속 쓴다.
`.python-version`·`pyproject.toml`·`src/`·`uv.lock`을 확인한다.
`main()`은 명령의 시작점, `uv_build`는 패키지 설치 도구다.
`[project.scripts]`를 바꾸면 `uv sync`를 다시 실행한다.

# 2교시 · 설명 20분
## 공개 평가 규칙과 기준 점수

---

## 0–3분 · 공개 연습 문항 20개

| 유형 | 문항 수 | 확인 대상 |
|---|---:|---|
| `fact` | 12 | 질문이 요구한 사실과 근거 |
| `composite` | 4 | 함께 묻는 사실들의 누락·불필요한 추가 |
| `unknown` | 4 | 제공 문서로 답할 수 없을 때 보류 |

공개 평가셋과 평가 도구를 함께 제공한다. 공개 정답은 연습용이다.
15주차에는 같은 도구·조건으로 비공개 문항을 평가한다.
비공개 문제와 정답은 수업 교재에 넣지 않는다.

---

## 3–7분 · 사실 집합 F1의 계산

정답 사실 집합을 G, 반환한 사실 집합을 P라고 한다.

```text
사실 F1 = 2 × 맞게 반환한 사실 수 / (P의 크기 + G의 크기)
정답 {A, B}, 반환 {A}        : 2 × 1 / (1 + 2) = 2/3
정답 {A, B}, 반환 {A, B, C}  : 2 × 2 / (3 + 2) = 4/5
```

빠진 사실과 불필요한 사실을 함께 반영한다. 순서·중복은 점수를 늘리지 않는다.
NFKC·대소문자·공백·끝 마침표 정규화와 허용 별칭(`aliases`)을 적용한다.
임의의 비슷한 표현이 모두 정답이 되는 것은 아니다.

---

## 7–11분 · 근거 점수와 문항 점수

`fact`와 `composite`는 같은 계산식을 사용한다.

```text
문항 점수 = 80 × 사실 집합 F1 + 20 × 근거 집합 F1
사실 F1이 0이면 근거 점수도 0
```

근거 F1은 정답 문서 ID 집합과 반환 문서 ID 집합을 비교한다.
정답 사실 둘 중 하나만 맞고 근거가 모두 맞으면 약 73.33점이다.

**80/20은 성능지표 내부 비율이다.** 보고서 점수와 합치는 비율이 아니다.

---

## 11–15분 · 답변 보류와 0점 조건

문서로 답할 수 없는 `unknown` 문항의 만점 반환값:

```python
{"answers": [], "sources": [], "abstain": True}
```

`abstain=true`와 두 빈 배열을 모두 만족하면 100점, 그 외에는 0점이다.
형식·실행 오류와 문항당 30초 제한 초과는 0점이다. 준비 요청은 제외한다.
전체 점수는 모든 문항 점수의 평균이며 0점 문항도 포함한다.
학생 PC 성능에는 점수를 주지 않는다. 응답시간은 보고만 한다.

---

## 15–18분 · 공개 평가 실행

같은 `examples/` 폴더에서 실행한다.


수정 전의 전체 평균과 유형별 결과, 실패 문항을 기록한다.
[평가 명세](evaluation_spec.md)의 계산식과 출력 한 행을 나란히 읽는다.

## 18–20분 · 2교시 실습 인계

1. 공개 20문항을 실행하고 수정 전 기준 점수를 기록한다.

# 3교시 · 설명 20분
## 한 가지 개선과 보고서 기록

---

## 0–3분 · 같은 답변 함수의 개선

```text
ex01  터미널 챗봇 ─┐
ex02  공개 평가   ─┼─ student_bot.answer(question)
ex03  개선 확인   ─┘
```

`ex03`은 같은 함수를 연속 입력으로 확인하는 챗봇이다.
`src/student_bot/__init__.py`의 `TOP_K`나 프롬프트 한 요소를 수정한다.
공개 문항 번호별 답을 외우기보다 질문과 문서를 연결하는 처리를 고친다.

---

## 3–7분 · 한 번에 한 가지 변경

| 관찰한 실패 | 시도할 변경 |
|---|---|
| 함께 물은 사실 하나가 빠짐 | 질문이 요구한 사실을 각각 수집 |
| 관련 없는 문서까지 근거에 포함 | 실제 답을 뒷받침한 문서만 반환 |
| 문서에 없는 내용을 답함 | 근거가 없으면 답변 보류 |

실패 하나를 선택하고 변경 위치와 예상 효과를 먼저 적는다.
모델·평가 조건은 고정한다. 새 UI나 새 프레임워크는 필수 작업이 아니다.

---

## 7–11분 · 개선 챗봇과 재평가

```sh
uv run ex03
uv run ex02
```

`ex03`에서 수정 대상 질문과 다른 질문을 연속으로 입력한다.
빈 입력·종료와 세 반환 필드가 유지되는지 확인한다.
그다음 같은 공개 20문항 전체를 다시 평가한다.
전체 평균과 유형별 변화, 새로 틀린 문항을 수정 전과 비교한다.

---

## 11–15분 · 비교 조건과 실패 기록

전후 비교에서 문서·문항·평가기·모델·생성 조건을 고정한다.
변경한 답변 처리와 변경하지 않은 조건을 함께 적는다.

| 기록 | 쓸 내용 |
|---|---|
| 전후 수치 | 실제 전체 평균, 유형별 결과, 응답시간 |
| 실패 | 질문, 실제 반환값, 누락·오류와 근거 |
| 선택 이유 | 채택한 변경과 포기한 대안의 이유 |

점수가 내려가거나 그대로여도 관찰과 이유를 기록한다. 수치를 만들지 않는다.

- 전후 수치·실패·선택 이유: 실제 평가 출력과 연결
