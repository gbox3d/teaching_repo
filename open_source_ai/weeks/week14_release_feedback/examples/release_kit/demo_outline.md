# 3분 시연 구성과 리허설 기록

15주차 최종 발표는 팀당 **시연 3분 + 질의 2분**이다. 아래를 복사해 팀 저장소 `docs/demo_outline.md` 로 쓰고, 리허설마다 시간을 적는다.

## 구성

| 구간 | 시간 | 말할 것 | 화면 |
|---|---:|---|---|
| 문제 | 0:00–0:30 | 누구의 어떤 상황, 기존 해법이 안 되는 이유 한 문장 | README 첫 화면 |
| 시연 | 0:30–2:00 | 실행 명령 → 입력 1개 → 출력 1개 → 출처·근거가 보이는 곳 | 터미널 또는 UI (미리 켜 둠) |
| 한계 | 2:00–2:30 | 안 되는 것 2개, 조건(VRAM·모델·데이터 라이선스) | README 「제한」 절 |
| 다음 | 2:30–3:00 | 받은 피드백 1건과 v0.1.1 계획, 기여 방법 | Issue 목록 또는 `DECISIONS.md` |

원칙:

- 서비스·모델은 시연 전에 켜 두고 응답 1회를 미리 받아 둔다(첫 요청은 느리다).
- 시연 구간은 입력 1개·출력 1개로 제한한다. 설명을 줄이지 말고 화면 전환을 줄인다.
- 3분 30초를 넘기면 시연 구간에서 줄인다.

## 실패 대비

| 상황 | 대신 보여 줄 것 | 파일 경로 |
|---|---|---|
| Ollama 응답 없음·모델 로드 실패 | 사전 실행 출력 JSON | (예: `outputs/demo-chat.json`) |
| 서비스가 뜨지 않음 | CLI 경로로 같은 입력 | (예: `uv run python -m PACKAGE_NAME chat "..."`) |
| 네트워크 없음 | 로컬 README·릴리스 노트 파일 | (예: `outputs/release-notes-v0.1.0.md`) |

## 예상 질문 5개와 답의 근거

| 질문 | 답 뼈대 | 근거 파일 |
|---|---|---|
| 왜 이 모델인가 | VRAM·라이선스·평가 수치 | `SOURCES.md`, `experiments/run-*.md` |
| 데이터는 어디서 왔는가 | 이름·라이선스·변경 내용 | `SOURCES.md`, `DATA_CARD.md` |
| 재현에 얼마나 걸리는가 | 교차 재현 기록의 초 | `docs/repro/repro-log-*.md` |
| 무엇이 안 되는가 | 제한 2개와 실패 사례 | README 「제한」, `FAILURE_ANALYSIS.md` |
| 기여하려면 | Issue 양식·라벨·PR 규칙 | `CONTRIBUTING.md`, 열린 Issue |

답의 근거가 저장소 안의 파일이면 좋은 답이다. 파일을 열어 보여 주는 데 10초를 넘기지 않게 경로를 외워 둔다.
