# 분류(triage) 라벨과 결정 기록

받은 Issue 를 **다음에 누가 무엇을 할지**가 보이게 분류한다. 라벨은 GitHub 저장소 → Issues → Labels 에서 만든다.

## 라벨 5개

| 라벨 | 색(권장) | 뜻 | 붙이는 기준 |
|---|---|---|---|
| `bug` | `d73a4a` | 문서대로 했는데 다르게 동작 | 재현 명령·출력이 있고, 우리 PC 에서도 재현됨 |
| `docs` | `0075ca` | 코드는 맞고 README 가 틀리거나 부족 | 명령을 고치지 않고 문서만 고치면 해결 |
| `enhancement` | `a2eeef` | 새 기능·개선 제안 | 현재 동작은 정상, 범위 판단 필요 |
| `question` | `d876e3` | 사용법 질문 | 답이 docs 수정으로 이어질 수 있음 |
| `needs-repro` | `e4e669` | 재현 정보 부족 | 환경·명령·출력 중 하나라도 없음 |

GitHub 기본 라벨 중 `bug`·`enhancement`·`question` 은 이미 있을 수 있다. 색만 확인하고 `docs`·`needs-repro` 를 추가한다.
`gh` CLI 를 쓰는 팀은 `gh label create docs --color 0075ca --description "문서 수정"` 형태로 만들 수 있다(선택).

## 분류 절차

1. 읽는다. 제목만 보고 라벨을 붙이지 않는다.
2. 라벨 1~2개를 붙인다. 정보가 부족하면 결정하지 말고 `needs-repro` 만 붙인다.
3. 재현을 시도한다(10분 이내). 결과를 코멘트에 적는다.
4. 결정한다: 수용 / 보류 / 거절. 근거를 함께 적는다.
5. `DECISIONS.md` 에 한 줄 추가한다. 수용이면 반영 예정 버전(`v0.1.1`)을 적는다.

## 응답 문장 예시

```text
[재현 성공·수용]
보고 감사합니다. 같은 명령으로 재현했습니다 — uv.lock 이 .gitignore 에 잘못 들어가 있었습니다.
lock 파일을 커밋하고 v0.1.1 에 반영하겠습니다. 이 Issue 는 패치 릴리스 후 닫습니다.

[재현 실패·정보 요청]
확인 감사합니다. 저희 환경(Windows, RTX 4070)에서는 같은 단계가 통과해서 차이를 찾고 있습니다.
`uv run python --version` 출력과 오류 시점의 전체 출력을 붙여 주시면 다시 시도하겠습니다. (needs-repro)

[보류·범위 밖]
제안 감사합니다. GPU 없는 PC 지원은 이번 학기 범위(v0.1.x)에는 넣지 않기로 했습니다.
소형 모델로 우회하는 방법을 README 제한 절에 적어 두고, 다음 버전 후보로 DECISIONS.md 에 남깁니다.
```

- 사람이 아니라 동작에 대해 말한다. 기한을 약속하지 않는다.
- "제 PC 에서는 됩니다"로 끝내지 않는다. 차이를 찾을 정보를 요청한다.

## 결정 기록 양식 (`DECISIONS.md`)

```markdown
# 피드백 반영 결정

| Issue | 요약 | 라벨 | 결정 | 근거 | 반영 |
|---|---|---|---|---|---|
| #3 | `uv sync --frozen` 실패 | bug | 수용 | uv.lock 미커밋, 재현됨 | v0.1.1 |
| #4 | GPU 없이 실행 지원 | enhancement | 보류 | 이번 학기 범위 밖, 소형 모델 우회 안내로 대체 | 미정 |
| #5 | 예시 입력이 README 와 다름 | docs | 수용 | 예시 절 갱신 누락 | v0.1.1 |
```

수용·보류·거절 모두 기록한다. 이 표가 4차 종합과제의 「피드백 반영 근거」다.
