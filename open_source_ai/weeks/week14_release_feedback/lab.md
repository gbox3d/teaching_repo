# 14주차 실습 — 챗봇 평가와 개선 기록

이번 주 결과는 기말과제에 이어 쓴다. 별도 주간 과제는 추가하지 않는다.
각 교시는 설명 20분 뒤 아래 실습 30분을 진행하고 10분 쉰다.

## 준비

[예제 준비 안내](examples/README.md)에 따라 `examples/`에서 `uv sync`를 실행한다.
Ollama 모델은 수업 전에 다운로드한다. 교시마다 프로젝트를 복사하거나 환경을 다시 만들지 않는다.
실제 바꿀 파일은 `src/student_bot/__init__.py`이고, 평가 규격과 정답은 수정하지 않는다.

## 1교시 — 질문과 응답 확인

| 시간 | 활동 |
|---|---|
| 0~5분 | [기말과제](assignment_brief.md)의 발표 대체 점수와 보고서 점수를 구분 |
| 5~15분 | `uv run ex01` 실행, 소재 도시·교목·자료에 없는 질문 입력 |
| 15~25분 | `answers`, `sources`, `abstain`을 자료와 대조 |
| 25~30분 | 빈 입력을 확인하고 종료, 답이 틀린 질문 하나 기록 |

같은 프로그램에서 다음 질문을 계속 입력한다.
반복 입력과 이전 대화를 기억하는 기능은 구분한다. 기준 예제는 질문마다 독립적으로 답한다.
답변 불가일 때 추측한 숫자나 출처를 반환하지 않는지 확인한다.

## 2교시 — 공개 평가 실행

| 시간 | 활동 |
|---|---|
| 0~5분 | [평가 규격](evaluation_spec.md)에서 문항 수·산식·제한 확인 |
| 5~18분 | `uv run ex02`로 공개 20문항 실행 |
| 18~25분 | 실패 문항의 실제 답·정답·출처·형식 오류 비교 |
| 25~30분 | 전체 점수와 유형별 점수, 실패 원인 기록 |

문항을 실행하지 못했는데 건수를 줄여 평균 내지 않는다.
Ollama 미기동이나 모델 미설치는 먼저 해결하고 전체 평가를 다시 실행한다.
정답 사실 2개 중 1개를 맞히면 왜 부분점수가 나오는지 산식으로 확인한다.
관계없는 답과 출처를 여러 개 반환하면 점수가 어떻게 바뀌는지도 설명한다.

## 3교시 — 한 요소 개선과 보고서

| 시간 | 활동 |
|---|---|
| 0~5분 | 실패 한 종류를 고르고 바꿀 요소 하나 결정 |
| 5~15분 | `TOP_K` 또는 프롬프트를 수정하고 `uv run ex03`으로 대화 확인 |
| 15~25분 | `uv run ex02`로 같은 공개 평가 재실행 |
| 25~30분 | [보고서 양식](report_template.md)에 전후 수치·이유·남은 실패 기록 |

검색 자료가 없었던 경우와 자료를 주었는데 답을 잘못 만든 경우를 구분한다.
점수가 오르지 않아도 결과를 숨기지 말고 원인과 다음 확인을 적는다.
여유가 있으면 새 표현의 질문을 직접 만들어 공개 문장에만 맞춘 개선인지 확인한다.

## 완료 확인

챗봇의 대화와 공개 평가가 같은 `answer(question)`을 사용하는지 확인한다.
수정 전후 코드와 실행 조건, 전체 평가 결과를 보존한다.
다음 주에는 제출 버전을 고정해 비공개 성능 평가와 개발 보고서 평가를 각각 받는다.
