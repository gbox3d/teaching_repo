# 14주차 — 기말 챗봇 과제와 공개 성능 평가

원광대학교 소개 챗봇을 만들고, 공개 평가 문제로 개선한 뒤 개발 내용을 보고서로 정리한다.
기존 발표 점수는 AI 성능 평가 점수로 대체한다. 레포트 점수는 개발 보고서로 따로 평가한다.
두 항목의 기존 성적 반영 비율은 유지한다.

## 학습 목표

- 질문을 받아 답과 출처를 반환하는 챗봇을 평가 도구에 연결한다.
- 공개 문제의 점수와 실패 답변을 읽고 개선할 부분을 고른다.
- 같은 문제·모델·조건에서 변경 전후를 비교한다.
- 구현한 내용과 선택 이유를 코드·실험 결과에 연결해 설명한다.

## 수업 흐름

| 교시 | 설명·시연 20분 | 실습 30분 | 확인할 결과 |
|---|---|---|---|
| 1 | 기말과제 규칙, 사실 답변·출처·답변 불가 | 기준 챗봇 실행과 반환값 확인 | 직접 질문 → 답변 → 다음 질문 → 종료 |
| 2 | 공개 문제·정답·채점 산식, 오류 읽기 | 공개 20문항 평가와 실패 분류 | 점수, 잘못된 답, 빠진 근거 |
| 3 | 한 요소씩 개선하고 보고서 쓰기 | 프롬프트나 검색을 수정하고 재평가 | 변경 전후 수치와 이유 |

각 교시는 설명·시연 20분, 실습 30분, 휴식 10분이다.
이번 주 실습은 기말과제의 준비이며 별도 종합과제를 추가하지 않는다.

## 선행 내용과 범위

4주차 Ollama, 6주차 RAG, 7주차 파인튜닝, 9주차 Streamlit에서 배운 내용을 선택해서 활용한다.
RAG·파인튜닝·프롬프트·검색 알고리즘을 모두 구현할 필요는 없다.
평가 함수와 화면은 같은 지식·모델·검색 구현을 사용하며, 공개 문제의 답을 문항별로 하드코딩하지 않는다.

교수자가 제공한 참고 자료의 범위에서 답한다. 학교의 실제 서비스나 최신 학사 안내를 대신하는 챗봇으로 배포하지 않는다.
학생 이름·학번·성적 같은 개인 자료는 필요하지 않다.

## 완료 기준

- [ ] 터미널에서 두 질문 이상을 입력하고 종료했다.
- [ ] 공개 평가 20문항이 빠짐없이 처리되는지 확인했다.
- [ ] 실패 문항을 검색 실패, 사실 오류, 출처 오류, 답변 불가 처리, 형식 오류로 구분했다.
- [ ] 한 요소를 바꾸고 같은 공개 평가를 다시 실행했다.
- [ ] 바꾼 내용과 전후 결과, 개선되지 않은 사례를 보고서에 적었다.

## 다음 주 연결

15주차에는 제출한 버전을 고정해 비공개 문항으로 AI 성능을 평가한다.
공개 문제는 개발용이며 발표 점수를 직접 결정하지 않는다.
개발 보고서는 성능 점수와 별도로 평가한다.
기존 폴더 이름은 링크 호환을 위해 유지했다. 이전 릴리스 발표 수업의 코드는 Git 이력에서 확인할 수 있다.
