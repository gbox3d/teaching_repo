# 12주차 Needle3 툴 콜링 LoRA

명령을 함수 호출로 바꾸는 작은 제어 모델을 학습하고 저장·복원한다. 4주차 Ollama 대화의 입력 반복과 7주차 LoRA 학습을 이어 쓰며, 9주차 Streamlit 화면은 13주차 제어 앱에서 다시 연결한다. 이번 주는 명령·정답 호출 데이터, 학습 산출물, 같은 미학습 문항의 전후 비교를 다룬다.

## 학습 목표

- 명령에서 함수와 인자 값을 찾고, 잘못된 정답 호출을 고친 이유를 설명한다.
- Needle 3가 제안한 호출과 프로그램이 실제 실행한 동작을 구분한다.
- LoRA 학습 설정을 바꾸고 `adapter.safetensors`와 `tuned.cact`의 역할을 설명한다.
- 새 프로세스에서 학습한 모델을 복원하고 같은 미학습 문항으로 학습 전후를 비교한다.
- loss 변화, 함수 선택, 인자 정확성, 실제 상태 확인을 나누어 해석한다.

## 세 교시의 흐름

| 교시 | 설명·시연 20분 | 실습 30분 | 남길 근거 |
|---|---|---|---|
| 1교시 | 명령·정답 호출 데이터, 도구 계약, Needle 대화 | 데이터를 점검·수정하고 `uv run ex01`로 대화 | 수정 전후 행, 수정 이유, 기본 모델의 호출 관찰 |
| 2교시 | LoRA 학습, 길이 제한, loss, 저장 | `uv run ex02`로 짧은 로컬 학습·내보내기 | 실제 설정·loss 관찰, 두 산출물의 저장 위치 |
| 3교시 | 새 프로세스 복원, 동일 조건 비교, 종합과제 | `uv run ex03`로 동일 미학습 문항 비교 | 문항별 전후 호출, 오류 원인과 검증 방법 |

교시마다 설명·시연 20분, 실습 30분, 휴식 10분을 쓴다. 30분 실습의 세부 시간은 [실습지](lab.md)가 정본이다.

## 준비와 실행

Python 3.12와 uv를 사용한다. 수업 전 강의자가 엔진, 기본 `.cact`, 학습용 기본 체크포인트, 의존성을 준비한다. 최초 엔진·모델·체크포인트 다운로드와 환경 준비는 수업 전에 마친다. 의존성은 `cactus-compute[train]==4.2.0`이며 공식 cactus 학습·내보내기 컴포넌트를 사용한다. Metal·CUDA 선택은 강의자가 확인한 환경에 맞춘다. Mac arm64 CPU 실측은 아래 표에서 확인한다. 수업 전 자신의 환경에서 실행을 점검한다.

처음 받는 경우 개인 작업 위치에서 저장소 전체를 clone한다. 이미 clone했다면 기존 작업을 보존하고 그 저장소를 사용한다.

```powershell
git clone https://github.com/gbox3d/teaching_repo.git
Set-Location teaching_repo/open_source_ai/weeks/week12_control_lora/examples
uv sync
uv run ex01
```

`tools/bleuno-control`의 `src/bleuno_control`을 로컬 의존성으로 사용하므로 `examples/`만 복사하면 안 된다. 세 교시는 같은 `examples/` 프로젝트에서 이어 간다. `period1`~`period3`은 읽을 소스와 실행 순서를 알려 주는 문서 폴더다.

대화에서는 한 명령을 입력하고 호출 제안을 읽은 뒤 다음 명령을 입력한다. 빈 입력은 건너뛰고 `/bye`로 종료한다. 입력창이 반복되는 것과 앞 대화를 기억하는 것은 다르다. 문맥 유지에는 이력 전달이 필요하다. 이번 주 제공 예제는 모델을 재사용하되 입력마다 이력을 초기화하므로 각 명령을 독립적으로 해석한다.

실행 명령과 실제 소스는 [예제 안내](examples/README.md)에 연결했다. 시뮬레이터의 TCP 제어·HTTP 상태 조회를 수업 전에 준비하고, 실패하면 [따라하기](walkthrough.md)의 확인 위치를 읽는다.

## 함수 호출 계약

| 함수 | 허용 인자 | 의미 |
|---|---|---|
| `turn_on(index)` | 정수 `index`, 0~3 | 해당 LED 켜기 |
| `turn_off(index)` | 정수 `index`, 0~3 | 해당 LED 끄기 |
| `set_brightness(index, value)` | 정수 `index`, 0~3. 정수 `value`, 0~255 | 해당 LED 밝기 지정 |
| `read_environment()` | 없음 | 센서값 조회 |

모델은 호출을 제안한다. 실행기는 함수 허용 목록, 인자 이름·타입·범위를 검사한 뒤 실행하고, `GET /state`로 실제 상태를 확인한다. 형식에 맞는 `turn_off(index=2)`도 사용자가 켜 달라고 했다면 의도 오류다. 센서 숫자는 `read_environment()`의 반환값에서 읽는다.

TCP 연결은 대화·세션 동안 한 번 유지한다. 연결을 해제하면 LED가 초기화된다. 같은 조건을 비교할 때는 LED 초기 상태와 대화 이력을 맞춘다. 이 실행 경계는 13주차 시뮬레이터 평가에도 그대로 적용한다.

## 산출물과 비교 조건

| 대상 | 역할 |
|---|---|
| `models/checkpoints/needle3.safetensors` | LoRA 학습과 내보내기에 필요한 기본 체크포인트 |
| `models/adapter.safetensors` | 학습으로 얻은 LoRA 변화량 |
| `models/baseline_adapter.safetensors` | B=0인 비교용 어댑터, 기본 가중치 유지 |
| `models/baseline.cact` | 기본 가중치의 비교용 4bit·20L 추론 파일 |
| `models/tuned.cact` | 변화량을 기본 가중치에 병합하고 토크나이저를 묶은 4bit·20L 추론 파일 |

`weights=`에는 내보낸 `.cact`를 지정한다. 어댑터 파일을 바로 지정하지 않는다. 학습 전후 비교는 기본 4bit·20L와 학습 4bit·20L를 사용한다. 일반 배포 기본값인 2bit 모델과 비교하면 양자화 차이가 섞인다. 로컬 LoRA의 `confidence`는 `None`일 수 있으므로 기본 모델의 점수와 같은 기준으로 비교하지 않는다.

학습 원본은 `examples/src/shared/data/train_examples.jsonl`의 48행이며 공용 스키마는 `models/training_input.jsonl`을 만들 때 합친다. 초기값은 `EPOCHS=4`, `BATCH_SIZE=4`, `MAX_LEN=1024`, `LEARNING_RATE=1e-4`이며 데이터·실행 환경에 맞춰 조정할 수 있다.

평가는 같은 16문항(한국어 8·영어 8, 호출 10·무호출 6)을 사용한다. 학습 문장과 문자열이 다르다는 검사만으로 의미 독립성을 확정하지 않는다. 매 문항 LED를 `[0, 64, 128, 255]`로 복원하고 함수 정확도·호출 완전일치·실제 상태 성공·오호출률·median·p95를 읽는다. 실제 지표 단위와 해석은 [실습지](lab.md)를 따른다.

## 기준 PC의 학습·복원 실측

2026-11-13 교재 준비 과정에서 측정한 단일 PC 1회 실측이다. Mac arm64 CPU, JAX 0.12.0.1, cactus-compute 4.2.0을 사용했다. 학습·저장 뒤 새 프로세스에서 두 모델을 복원하고 같은 조건으로 실제 제어를 평가했다.

48개 중 학습 42개·검증 6개를 사용했고 4 epochs·batch 4로 44 steps를 수행했다. 실제 최장 예제는 305토큰, 패딩 길이는 512였다. `MAX_LEN=1024` 이하이며 자동 잘림은 없었다. 준비·최초 다운로드를 포함한 전체 시간은 339.4초(약 5분 39초)다. 순수 학습 시간이나 학생 PC·Windows·GPU의 보장 시간으로 해석하지 않는다. 사전 다운로드 준비는 유지한다.

`baseline.cact`와 `tuned.cact`는 각각 63.44 MB이며 B=0 비교 어댑터가 기본 가중치를 바꾸지 않는 것을 확인했다. 파일 크기가 같다는 사실은 정확도 개선의 근거가 아니다. 학습용 검증 6개와 평가셋의 무호출 6문항은 다른 집합이다.

| 관찰 지표 | 기본 4bit·20L | 학습 4bit·20L |
|---|---:|---:|
| 실제 제어 성공 | 9/16 (56.25%) | 10/16 (62.5%) |
| 무호출 문항의 오호출률 | 1/6 | 0/6 |
| 영어 문항 성공 | 7/8 | 7/8 |
| 한국어 문항 성공 | 2/8 | 3/8 |
| 오류 문항(256토큰 예산 소진) | 1 | 1 |
| median | 68.5 ms | 69.6 ms |
| p95 | 206.8 ms | 236.9 ms |

각 모델의 오류 1문항도 전체 분모 16에 포함한다. 이 16문항의 p95는 정렬 뒤 `ceil(0.95×16)`번째 값이므로 최댓값이다. 준비·학습 전체 시간과 평가 지연은 별도 측정이다. 작은 평가에서 한 문항이 바뀐 결과이므로 일반 성능 향상을 보장하지 않는다. 남은 실패와 오호출을 데이터·도구 설명 개선의 출발점으로 사용한다. 함수 정확도·호출 완전일치 수치는 자신의 평가 출력에서 별도로 읽는다.

## 완료 기준

- [ ] 48개 학습 데이터의 정답 호출과 수정 이유를 명령 속 근거로 설명했다.
- [ ] `ex01`에서 여러 입력과 종료를 관찰하고 문맥 유지 여부를 구분했다.
- [ ] `EPOCHS`, `BATCH_SIZE`, `MAX_LEN`, `LEARNING_RATE`의 실제 값을 기록했다.
- [ ] 모든 렌더링 예제의 토큰 길이를 검사하고 `MAX_LEN` 초과 시 학습을 중단하는 기준을 확인했다.
- [ ] 어댑터 저장과 `.cact` 내보내기의 결과를 각각 확인했다.
- [ ] 학습 프로세스를 끝내고 `ex03`의 새 프로세스에서 복원을 확인했다.
- [ ] 같은 미학습 문항·도구·생성 조건·초기 상태로 전후를 비교했다.
- [ ] loss 감소와 미학습 문항 성공을 별도로 판단하고, 미확인 단계는 구분했다.

## 공식 근거와 수업 설계

[Fine-tuning Needle](https://cactuscompute.com/blog/finetuning-needle)은 로컬 LoRA, 학습 데이터, 길이 제한, loss 해석과 `.cact` 내보내기의 근거다. [Needle Python Docs](https://cactuscompute.com/blog/needle-python-docs)는 호출 응답, 대화 이력, `weights=`의 근거다. 네 제어 함수와 세 교시 구성, `ex01`~`ex03`은 이 수업의 설계다. 공식 API 설명과 위 기준 PC 실측의 출처·범위를 구분한다.
