# 12주차 실습 Needle3 데이터 수정·LoRA·복원 비교

## 준비와 공통 기준

Python 3.12, uv, 저장소 전체 clone, 수업 전 준비한 엔진·기본 모델·학습용 체크포인트를 사용한다. 실제 실행 위치는 `teaching_repo/open_source_ai/weeks/week12_control_lora/examples`다. 세 교시는 프로젝트 하나에서 이어 간다. `tools/bleuno-control`의 `src/bleuno_control` 로컬 의존성이 있으므로 주차 폴더만 따로 복사하지 않는다.

```powershell
Set-Location teaching_repo/open_source_ai/weeks/week12_control_lora/examples
uv sync
```

의존성은 `cactus-compute[train]==4.2.0`이다. Metal·CUDA는 강의자가 확인한 환경을 사용한다. Mac arm64 CPU 실측은 이 실습지의 실측 절에서 확인한다. 다른 환경의 실행 시간을 보장하지 않는다. 설치·다운로드·엔진 준비는 수업 전에 마친다.

명령은 `uv run ex01`, `uv run ex02`, `uv run ex03`이다. 바꿀 값은 해당 패키지의 모듈 맨 위 대문자 상수에서 수정한다. 패키지는 `src/ex01_data/`, `src/ex02_train/`, `src/ex03_restore/`이며 각 `__init__.py`의 `main()`을 `[project.scripts]`에 연결한다. [예제 안내](examples/README.md)에서 실제 소스·데이터·산출물 경로를 읽는다.

## 별도 경로에서 uv 패키지 구조 확인

배포 예제 밖의 개인 연습 경로에서 한 번만 실행한다. 이 프로젝트에 모델 실습 파일을 옮기지 않는다.

```powershell
uv init --package --python 3.12 --vcs none week12-package-check
Set-Location week12-package-check
Get-ChildItem -Force
Get-Content .python-version, pyproject.toml
Get-ChildItem src
```

`.python-version`은 Python 버전, `pyproject.toml`은 의존성·명령·빌드 설정, `src/`는 패키지 위치를 보여 준다. `main()`은 명령 진입 함수다. `[project.scripts]`는 명령 이름과 `<패키지>:main`을 연결한다. `[build-system]`의 `uv_build`는 `src/` 패키지를 빌드·설치하는 방법을 정한다. scripts를 고쳤다면 `uv sync`를 다시 실행해 설치된 명령을 갱신한다. 구조 확인 후 원래 주차의 `examples/`로 돌아간다. 교시마다 새 프로젝트를 만들지 않는다.

### 문제 1 명령과 정답 호출 점검

다음은 함수 계약을 읽는 예이며 모델의 실제 출력이 아니다.

| 명령 | 기대 호출 | 명령 속 근거 |
|---|---|---|
| LED 2를 켜 줘 | `turn_on(index=2)` | 켜기, LED 2 |
| LED 2를 꺼 줘 | `turn_off(index=2)` | 끄기, LED 2 |
| LED 1의 밝기를 80으로 맞춰 줘 | `set_brightness(index=1, value=80)` | LED 1, 밝기 80 |
| 지금 센서값을 읽어 줘 | `read_environment()` | 환경 센서 조회 |
| 오늘 읽을 소설을 추천해 줘 | 빈 호출 `[]` | 등록한 제어 도구와 무관함 |

`index`는 정수 0~3, `value`는 정수 0~255다. LED 2를 index 1로 바꾸거나 밝기 80을 80%로 해석하지 않는다. 인자가 빠진 명령에는 임의 숫자를 채우지 말고 부족한 정보를 기록한다.

`src/shared/data/train_examples.jsonl`의 48개 `query`, `answers`, `reasoning`을 읽는다. 도구 스키마는 공용에 한 번 두며 원본 행에 반복하지 않는다. `ex02`가 스키마를 합쳐 `models/training_input.jsonl`을 만든다. `answers`는 정확한 함수 이름과 인자의 목록이다. `reasoning`에는 인자 값을 명령의 어느 표현에서 가져왔는지 짧게 적을 수 있다. 공식 형식은 JSONL 한 줄에 객체 하나다.

1. 함수 선택, 인자 이름·타입·범위, 명령에 없는 값, 호출 순서를 점검한다.
2. 틀린 행은 고치고 수정 전후와 이유를 적는다. 오류가 없으면 직접 바꾼 명령과 그에 맞춘 정답 호출을 연결해 설명한다.
3. `answers: []`인 도구 밖 명령도 확인한다. 모든 명령에 함수를 부르게 만드는 데이터를 피한다.
4. 학습에 쓸 문항과 3교시까지 따로 둘 미학습 문항을 구분한다. 비교 문항의 정답을 학습 데이터에 넣지 않는다.

### 문제 2 기본 모델과 대화

```powershell
uv run ex01
```

명령을 입력하고 `function_calls`의 이름·인자를 읽은 뒤 다음 명령을 입력한다. 빈 입력은 건너뛰고 `/bye`로 종료한다. Needle은 제어 도구 호출을 제안하며 일반 챗봇의 자유 답변을 기대하지 않는다. 도구 밖 입력의 빈 호출도 관찰 대상으로 남긴다.

독립 명령을 이어 입력한 경우와 “그 LED를 꺼 줘”처럼 앞 문맥이 필요한 입력을 비교한다. 반복문만 있어도 입력은 반복되지만, 문맥은 이력 전달이 있어야 이어진다. 제공 예제는 모델을 재사용하되 질문마다 `reset()`해 독립 명령으로 처리한다. 따라서 “그 LED”만 입력하면 앞 명령의 대상이 자동 유지된다고 가정하지 않는다. LED 번호를 다시 적어 비교하고 관찰을 남긴다.

`ex01` 기본 대화는 일반 배포 기본 모델을 관찰하는 단계다. 4bit·20L로 조건을 맞춘 LoRA 전후 비교는 `ex03`의 `baseline.cact`와 `tuned.cact`로 수행한다. 모델 제안은 곧 실행 성공을 뜻하지 않는다. 실행기는 허용 함수, 인자 이름·타입·범위를 확인해야 한다. 형식에 맞아도 명령의 켜기·끄기 의도가 다를 수 있다. 수업 전 시뮬레이터가 준비되어 있어야 한다. `ex01`은 TCP로 제어를 실행하고 HTTP `GET /state`로 확인하므로 두 연결 지점을 함께 준비한다. 함수 반환과 실제 상태를 대조한다. 센서값은 `read_environment()` 반환에서 읽는다.

### 문제 1 상수와 길이 제한 확인

`[project.scripts]`에서 `ex02`가 가리키는 패키지를 찾아 모듈 맨 위 상수를 읽는다. 한 번의 비교에서는 변경한 설정과 이유를 분명히 남긴다.

| 상수 | 의미 | 확인할 내용 |
|---|---|---|
| `EPOCHS` | 데이터를 반복해 학습하는 횟수 | 실제 값과 반복 수 선택 이유 |
| `BATCH_SIZE` | 한 학습 단계에서 묶는 예제 수 | 실제 값, 메모리·단계 수와의 관계 |
| `MAX_LEN` | 학습 전 길이 검사의 허용 한도 | 모든 렌더링 예제의 최장 토큰 길이가 한도 이하인지 |
| `LEARNING_RATE` | 업데이트 크기를 조절하는 값 | 실제 값과 변경 여부 |

초기값은 `EPOCHS=4`, `BATCH_SIZE=4`, `MAX_LEN=1024`, `LEARNING_RATE=1e-4`다. 실측에 사용한 시작값이며 다른 환경의 완료 시간이나 성능을 보장하지 않는다.

명령만 짧다고 전체 예제도 짧은 것은 아니다. 제공 코드는 스키마·reasoning·정답 호출을 포함한 모든 렌더링 예제의 최장 토큰 길이를 학습 전에 검사한다. `MAX_LEN`을 넘으면 중단하므로 초과한 예제를 잘라 학습하는 설정으로 설명하지 않는다. 데이터 길이를 줄이거나 한도를 검토한 뒤 다시 검사한다. 미학습 비교 문항은 이 조정에 섞지 않는다.

### 문제 2 학습과 내보내기

```powershell
uv run ex02
```

1. 공식 cactus 컴포넌트가 읽은 데이터와 실제 학습 설정을 확인한다.
2. 학습 loss와 제공되는 검증 loss의 변화를 기록한다. 측정하지 않은 시간·메모리·성공률은 빈칸 또는 미측정으로 둔다.
3. `models/adapter.safetensors` 저장과 `models/tuned.cact` 내보내기 결과를 각각 확인한다. 기본 비교용 B=0 어댑터인 `models/baseline_adapter.safetensors`와 `models/baseline.cact`도 확인한다. 기본 체크포인트는 `models/checkpoints/needle3.safetensors`다. 실패한 단계가 있으면 적는다.
4. 공용 제공 함수가 복잡한 내보내기를 담당한다. 학생은 데이터와 상수를 고친다. 어댑터가 있어도 내보내기가 실패하면 추론 파일이 완성된 것으로 처리하지 않는다.

기본 체크포인트는 학습의 원본이고 어댑터는 LoRA 변화량이다. 내보내기는 원본과 변화량을 병합하고 양자화·토크나이저를 묶어 추론용 `.cact`를 만든다. `weights=`에는 이 `.cact`를 사용한다. 기본 체크포인트와 어댑터를 `.cact`로 이름만 바꾸어 쓰지 않는다.

### 2교시 완료 조건과 힌트

- [ ] 네 상수의 실제 값과 데이터 수정 내용을 기록했다.
- [ ] 모든 예제의 최장 토큰 길이를 검사하고 `MAX_LEN` 초과 시 중단하는 기준을 확인했다.
- [ ] loss 관찰과 미학습 문항 성공 여부를 구분했다.
- [ ] 두 산출물의 실제 존재와 저장 위치를 확인하거나 실패 지점을 표시했다.

loss가 내려가면 학습 목표에 맞는 경향을 관찰한 것이다. 미학습 명령의 함수·인자가 맞는지는 3교시에서 별도로 확인한다. 검증 loss가 오르는데 학습 loss만 내려가면 과적합 가능성을 검토한다. 메모리 오류나 JAX 백엔드 문제는 상수·환경·오류 원문을 남기고 강의자에게 질문한다. 오류가 발생한 환경과 상수를 기록하고 수업 전 점검한 환경과 대조한다.

50–60분은 휴식이다. 산출물과 실제 경로를 보존하고 학습 프로세스 종료 상태를 확인한다.

### 문제 1 새 프로세스에서 복원

학습 명령이 끝났는지 확인한다. 학습 중인 메모리 속 모델을 그대로 호출하는 것으로 복원을 대신하지 않는다. 같은 프로젝트에서 새 명령을 실행한다.

```powershell
uv run ex03
```

`ex03`는 `models/baseline.cact`, `models/tuned.cact`를 차례로 읽어 평가한다. 내보낸 파일과 설정을 대조한다. 이 명령은 16문항을 자동으로 순회하며 대화 입력을 기다리는 명령이 아니다. 파일 존재만으로 로드 성공을 판단하지 말고 호출이 가능한지 확인한다. 엔진과 내보내기 패키지의 버전이 맞지 않으면 로드가 실패할 수 있다. 다른 버전의 `.cact`를 임의로 섞지 않는다.

### 문제 2 동일 미학습 문항으로 비교

기본 4bit·20L와 학습 4bit·20L를 비교한다. 일반 배포 기본 2bit 모델과 비교하면 양자화 차이까지 결과에 섞인다. 모델 외 조건은 같은 문항·도구 정의·생성 설정·대화 이력 초기화로 맞춘다. 제공 평가셋은 16문항(한국어 8·영어 8, 호출 10·무호출 6)이다. 학습 48개와 문자열이 겹치지 않는지 `ex01`이 검사한다. 문자열이 다르다는 사실만으로 의미 독립성까지 증명하지는 못한다. 학생이 문항을 추가하면 학습과의 의미·표현 중복도 검토한다.

시뮬레이터의 LED를 매 문항 `[0, 64, 128, 255]`로 복원하고 `GET /state`로 확인한다. TCP 연결은 대화·세션 동안 한 번 유지한다. 입력마다 재연결하면 연결 해제에 따른 LED 초기화가 상태를 바꾼다. 독립 문항의 모델 이력 초기화와 TCP 연결 해제는 서로 다른 작업이다.

| 미학습 문항 | 기대 호출·근거 | 학습 전 실제 호출 | 학습 후 실제 호출 | 판정·원인 가설 |
|---|---|---|---|---|
| 실제 문항 |  |  |  |  |

호출 형식, 함수 선택, 인자 이름·타입·값을 차례로 비교한다. 허용 목록·인자 검사 뒤 호출을 실행하고 함수 반환과 `GET /state`를 근거로 실제 제어 성공을 판정한다. `read_environment()`는 반환된 센서값을 읽으며 모델이 만든 숫자를 측정값으로 쓰지 않는다. 로컬 학습 모델의 `confidence=None`은 호출이 전부 틀렸다는 뜻이 아니며 기본 모델 점수와 같은 임계값으로 비교하지 않는다.

평가 출력에서 함수 정확도, 호출 완전일치(호출 목록 순서·인자 값 포함), 실제 상태 성공, 오호출률, median·p95를 읽는다. 호출 완전일치는 함수·인자 이름·값의 대응과 함수 호출 목록의 순서를 비교하며 JSON 딕셔너리 키의 나열 순서는 평가하지 않는다. 현재 공용 코드는 지연을 초 단위로 표시한다. 오호출률의 분모는 무호출 문항이며, median·p95에는 실패 문항도 포함한다. 자신의 결과를 기록할 때는 출력의 초 단위를 ms로 바꾸었는지 표시한다. 기준 실측과 자기 측정을 구분한다.

### 문제 3 차이의 원인 설명

다음 위치 중 실제로 관찰한 문제를 골라 근거와 다음 확인 방법을 적는다.

- 호출 이름이 다름: 켜기·끄기 등 명령의 동사와 정답 호출·도구 설명을 대조한다.
- 함수는 맞고 값이 다름: index·밝기의 근거 표현, 데이터의 값 분포와 길이 초과을 점검한다.
- 호출 형식·범위가 틀림: 허용 목록·인자 검사와 거절 여부를 확인한다.
- 호출은 맞고 상태가 다름: 연결·실행 결과·초기 상태를 확인한다.
- 학습 전후가 같거나 악화됨: 데이터·설정·평가 조건과 loss를 함께 읽고 학습 성공을 과장하지 않는다.

미학습 비교 문항을 그대로 학습에 추가하면 그 문항은 다음 비교의 미학습 문항이 아니다. 개선 학습은 별도 학습 예제를 고친 뒤 12주차 절차를 다시 따르고, 새 비교에는 학습에 쓰지 않은 문항을 둔다.

## 기준 PC 실측과 자기 결과 비교

다음은 2026-11-13 교재 준비 과정에서 측정한 Mac arm64 CPU 1회 실측이다. JAX 0.12.0.1, cactus-compute 4.2.0에서 학습·저장과 새 프로세스 복원·실제 제어를 확인했다. 학생은 자신의 실행 조건과 결과를 별도로 적는다.

학습 원본 48개 중 학습 42·검증 6개, 4 epochs·batch 4·44 steps를 사용했다. 최장 실제 길이는 305토큰, 패딩은 512이며 `MAX_LEN=1024`를 넘지 않아 자동 잘림이 없었다. 준비·최초 다운로드를 포함한 전체 339.4초(약 5분 39초)를 순수 학습 시간으로 적지 않는다. 두 4bit·20L 파일은 각각 63.44 MB이고 B=0 비교 어댑터를 확인했다. 검증 6개와 평가의 무호출 6문항을 구분한다.

| 관찰 지표 | baseline | tuned | 자기 결과 |
|---|---:|---:|---|
| 실제 제어 성공 | 9/16 (56.25%) | 10/16 (62.5%) |  |
| 무호출 오호출률 | 1/6 | 0/6 |  |
| 영어 성공 | 7/8 | 7/8 |  |
| 한국어 성공 | 2/8 | 3/8 |  |
| 256토큰 예산 소진 오류 | 1 | 1 |  |
| median | 68.5 ms | 69.6 ms |  |
| p95 | 206.8 ms | 236.9 ms |  |

오류 문항도 전체 16개 분모에 포함한다. 이 표의 p95는 `ceil(0.95×16)`번째 값으로 최댓값이다. 지연 출력의 초 단위를 ms로 바꾸면 환산 사실을 적는다. 제공되지 않은 함수 정확도·호출 완전일치 값은 추정하지 않는다. 한 문항의 성공 변화와 남은 실패를 분석하며 일반 성능 향상이나 다른 PC의 실행 시간을 보장하지 않는다.
