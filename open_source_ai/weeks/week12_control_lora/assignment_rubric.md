# 3차 종합과제 정성 루브릭

[과제 안내](assignment_brief.md)의 요구 결과와 설명을 함께 평가한다. 실제 만점·반영 비율·마감은 학교 운영 문서가 정한다. 이 문서는 항목별 새 배점이나 임의 환산 비율을 만들지 않는다.

## 평가 근거

| 항목 | 요구 결과와 정확한 설명을 갖춘 상태 | 확인·보완할 부분 |
|---|---|---|
| 데이터 이해 | 명령에서 함수·인자를 도출하고 수정 전후·수정 이유를 설명한다. 미학습 문항을 분리한다 | 정답 호출만 제시하거나, 근거 없는 인자를 넣거나, 평가 문항을 학습에 섞는다 |
| 학습 관찰 | 실제 상수 값과 길이 초과 사전 검사, loss 관찰을 남기고 각 설정의 역할을 설명한다 | 실행 화면만 제시하거나 정답 호출 길이 검사·loss 해석에 오류가 남는다 |
| 저장과 복원 | 기본 체크포인트·어댑터·`.cact`의 역할을 구분하고 새 프로세스 복원을 확인한다 | 저장과 내보내기를 혼동하거나 메모리 속 모델만 다시 호출한다 |
| 공정한 비교 | 기본·학습 4bit·20L의 같은 미학습 문항·도구·생성 조건·초기 상태를 맞추고 결과를 설명한다 | 양자화·깊이·문항·이력이 달라 학습 효과를 분리할 수 없다 |
| 실행 경계와 원인 분석 | 호출 제안과 실행을 나누고 허용 목록·인자 검사·상태 확인을 설명한다. 함수 선택·인자·환경 오류를 근거로 구분한다 | 형식이 맞으면 의도도 맞다고 보거나 모델이 만든 센서 숫자를 실제 값으로 쓴다 |
| 해결 노력과 질문 | 실제 시도, 오류 관찰, 수정, 검증, 구체적인 질문이 연결된다 | 인사·다짐·도구 이름만으로 학습 과정이 드러나지 않는다 |

짧아도 정확한 설명을 인정한다. 결과가 개선되지 않은 사실 자체로 일괄 감점하지 않는다. 개선 여부의 해석과 검증, 남은 오류·누락을 판단한다. 과제 밖 심화 기능이나 특정 도구, 글 길이·파일 수·질문 수를 새 조건으로 붙이지 않는다.

## 점수 판단의 공통 원칙

제출한 과제는 기본 5점에서 시작한다. 정답·완성 결과만 있고 본인 이해를 보여 주는 설명이 없으면 6점이다. 오답·미완성이어도 성의 있는 답변이나 구체적인 질문이 확인되면 7점 이상이다. 질문하며 해결하려는 노력이 보이면 최소 6점을 보장하며, 이미 성의 7점 기준을 충족한 제출을 6점으로 낮추지 않는다. 미제출에 기본점수를 적용하지 않는다. 실제 만점을 확인하고 지정한 5·6·7점을 다른 배점으로 임의 비례 환산하지 않는다.

7~9점은 확인한 과정과 설명의 충실도, 남은 오류·누락에 근거해 구분한다. 만점은 요구 결과와 정확한 설명을 모두 갖추고 실제로 고쳐야 할 사항이 없을 때만 부여한다. 필수 설명이 빠졌거나 개념·원인·결과를 고쳐야 하는데 선택 조언으로 바꾸어 만점을 유지하지 않는다.

환경 문제로 완료하지 못했더라도 확인한 시도·오류·질문을 인정한다. 실패 기록만으로 저장·복원 성공을 인정하지는 않는다. 실제 결과와 노력의 근거를 각각 적는다.

## 검토와 피드백 절차

학생 본문·코드 주석·첨부·질문을 함께 읽고, 공통 교재와 같은 주석을 학생 고유 설명으로 중복 인정하지 않는다. 같은 과제의 같은 성취·오류·누락에는 같은 기준을 적용한다.

유사 제출은 공통 예제를 제외한 일치 구간·파일 해시 등의 근거를 확인한다. 같은 정답, 같은 화면, 문체나 유사도 수치만으로 표절·AI 사용을 확정하지 않는다. AI 사용은 사용 확인·그대로 전재 확인·확인 불가를 구분하며, 사용 자체에 새 감점 규칙을 붙이지 않는다. 결과만 전재하고 이해 근거가 없을 때는 기존 결과만 제출 기준을 적용한다.

감점 피드백은 부족하거나 틀린 위치, 그 이유, 수정·확인 방법 순서로 적고 학생의 질문에 직접 답한다. 만점 피드백은 확인한 성취와 만점 근거를 쓴다. 실제 부족이 없는데 습관적으로 보완점을 붙이지 않는다.
