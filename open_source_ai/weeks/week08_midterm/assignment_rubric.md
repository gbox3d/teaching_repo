|---|---:|---|

## 수준별 판단

### 완전 충족

채점자가 README만 보고 새 폴더에서 같은 hit rate를 얻는다. 라이선스 표의 모든 항목에 출처 URL과 SPDX가 있고 판단 문단이 표와 일치한다. 실패 사례가 실제 `outputs/` 기록으로 확인된다.

### 부분 충족

파이프라인은 동작하지만 출처 표시가 일부 빠지거나, 평가셋이 10문항 미만이거나, 재현 절차에 README에 없는 조작이 한두 개 필요하다. 라이선스 표에 항목은 있으나 SPDX·URL이 빠진 경우도 여기에 든다.

### 미충족

새 폴더에서 실행되지 않거나, 출처 없는 답만 나오거나, 라이선스 분석이 사용 항목과 무관하거나, 본인 기여를 확인할 수 없다.

## 감점 적용 원칙

- 기술 이름을 나열했지만 선택 근거·라이선스·검증이 없으면 완전 충족이 아니다.
- 실행 화면만 있고 재현 절차와 commit이 없으면 해당 항목 점수를 대체하지 않는다.
- 문서 수가 많아도 출처 표시와 "모른다" 경로가 없으면 RAG 구조 점수가 낮다.
- 같은 원인(예: lock 파일 누락)으로 여러 항목이 실패하면 재현성에서만 감점하고 기록에 남긴다.
- 실제 토큰·개인정보·무단 문서를 공개한 경우 보안 항목을 미충족으로 보고, 라이선스 항목에도 반영한다.
- GPU 없이 CPU 대체 모델로 측정한 결과는 감점 사유가 아니다. README에 환경이 적혀 있으면 정상으로 본다.
