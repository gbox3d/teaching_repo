# 수시 실기평가 채점표 — 100점

이 rubric은 공개 가능한 공통 기준이다. 100점 상대 배점이며, 학교 적용 시 실제 비율·문항별 배점 매핑은 시험 전에 학교 운영 문서로 고지한다. 실제 정답과 비공개 testcase는 포함하지 않는다.

| 영역 | 배점 | 충족 기준 |
|---|---:|---|
| 재현·실행 | 15 | 지정 starter를 `uv sync`·`uv run`으로 실행 가능하게 복구, `.gitignore`·`.env.example` 정비, `outputs/` 기록 생성 |
| Git·협업 | 15 | 의미 있는 commit, 브랜치·충돌·PR 상황 판단의 명령 순서와 영역 설명, 비밀 파일 분리와 이력 잔존 판단 |
| 라이선스·출처 | 15 | 판별 문항의 판단과 근거, SPDX 표기, 출처 기록 항목(이름·버전·라이선스·용도·변경) |
| 로컬 AI API | 25 | 요청 JSON 구성(`stream`·`think`·`options` 명시), 지정 기능 추가, 연결 실패·모델 없음의 구분 처리, 응답 메타 기록 |
| HF 활용 | 15 | pipeline 결과·경고 메시지 해석, device·dtype 판단, 모델 카드 기준 용도·제한 판단 |
| 검증·설명 | 15 | 정상·실패 경로 증거, `outputs/` 기록과 코드의 일치, 원인·근거를 적은 짧은 설명 |
| 합계 | 100 | |

## 수준별 공통 판단

### 완전 충족

요구한 경로를 독립적으로 재현할 수 있고, 관련 없는 파일·설정에 부작용이 없다. 실행 결과가 `outputs/`에 남아 있고 코드·답안·commit이 일치한다. 판별·해석 문항은 판단에 근거가 붙어 있다.

### 부분 충족

핵심 구조 또는 일부 경로가 동작하지만 특정 입력·실패 경로·설정에서 실패한다. 시도 흔적만이 아니라 실행 가능한 부분 결과가 있어야 한다. 판별 문항은 판단은 맞지만 근거가 없거나, 근거는 맞지만 결론이 어긋난 경우다.

### 미충족

실행되지 않거나 요구사항과 무관한 결과이며, 채점 가능한 파일·commit이 없거나 본인 구현임을 확인할 수 없다.

## 감점 적용 원칙

- 같은 원인으로 여러 증상이 생긴 경우 중복 감점 여부를 기록한다.
- 문항별 최대 배점을 넘겨 감점하지 않는다.
- 메시지 문구의 미세한 차이와 예외 미처리를 같은 수준으로 취급하지 않는다.
- 모델 이름·주소의 하드코딩은 "동작하지만 재현성 원칙 위반"으로 기록하고 해당 영역에서만 감점한다.
- `.env`·`.venv`·`outputs/`·모델 파일이 commit에 포함된 경우 재현·실행 영역에서 감점하고, 실제 토큰이 포함된 경우 별도로 기록한다.
- GPU 장애로 CPU 대체 모델을 쓴 것은 감점 사유가 아니다. 답안에 기록되어 있으면 정상 경로로 본다.
- 제출 장애는 학생 구현 오류와 시스템 장애를 기록상 구분한다.
