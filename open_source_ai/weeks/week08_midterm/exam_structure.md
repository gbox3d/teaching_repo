# 수시 실기평가 구조

이 문서는 공개 가능한 공통 구조다. 실제 시험 문항, starter의 고유 값, fixture, 정답과 학생별 정보는 별도 비공개 공간에서 관리한다. 학교 적용 시 실제 비율·마감·시험 시간은 학교 운영 문서가 정한다.

## 평가 범위

| 영역 | 확인 역량 |
|---|---|
| uv 사용법·재현성 | `uv init --package`로 표준 양식 프로젝트 만들기와 `[project.scripts]`로 `uv run hello`, `pyproject.toml` 오류 복구, `uv add`가 바꾸는 파일, `pyproject.toml`과 `uv.lock`의 관계, `uv sync --locked`·`--frozen`, `uv run`이 하는 일, `.venv` 미커밋 |
| 프로젝트 관리법 | src 레이아웃, `[project.scripts]`·`[build-system]` 엔트리포인트, `uv init --package`, stdout·stderr 분리와 README 실행 절차, `.env`·`.env.example`과 설정 계층, 비밀값 가리기, ignore 규칙 |
| Git 개념·사용법 | working tree·staging area·repository·원격 네 영역, `git status` 읽기, add·commit·push 순서와 영역, GitHub에 올리기(`remote add`·`push -u`), 충돌 표시와 해결 순서, 비밀 파일 분리 |
| Ollama 사용법·응용 | `list`·`show`·`run`·`ps`가 알려 주는 것, 메시지 역할과 기억, `options`·`think`, 실패 메시지 구분, 툴 콜링 세 단계와 실행 주체, 함수 추가 실기, Modelfile |
| 검증·설명 | 정상·실패 경로 재현, `outputs/`와 `[함수 실행]` 줄 같은 실행 기록, 원인과 근거를 적은 짧은 설명 |

모의 실기 A·B는 위 다섯 영역, 곧 1~4주차 내용으로 구성한다. 라이선스 판별, Hugging Face pipeline 해석, 임베딩·RAG(5~7주차)의 포함 여부와 깊이는 학기별 실제 시험 공지에서 명시한다.

## 권장 운영

| 블록 | 설명·시연 20분 | 실습 30분 |
|---|---|---|
| 1교시 | 구조·범위·규정, 모의 문제 읽는 법 | 공개 동형 모의 실기 A(프로젝트 복구 + 판별 문항) |
| 2교시 | 로컬 AI 진단 포인트, 채점표 읽는 법 | 공개 동형 모의 실기 B(클라이언트 기능 추가 + 결과 해석) |
| 3교시 | 환경 점검·제출 경로·장애 대체 안내, 2차 과제 최종 점검 | 개인 실기평가(비공개 패킷) |

3교시 실기평가는 기관 시간표에 따라 30분을 넘겨 확장될 수 있다. 확장 시 총 평가 시간과 안내 시간을 분리해 학교 운영 문서에 사전 공지한다. 분반 시간표상 실기가 다른 슬롯에 있으면 3교시 실습은 2차 종합과제 최종 점검으로 대체한다.

## 시험 패킷

실제 학기에는 다음을 비공개로 준비한다.

1. 요구사항 문서와 정확한 완료 조건(요구사항 → 완료 조건 → 검증 순서 형식)
2. 동일 commit 또는 release tag의 starter(깨진 uv 프로젝트, 4주차 `period3` 툴 콜링 프로젝트 등)
3. 읽기 문항용 샘플(`git status` 출력, `pyproject.toml` 조각, Modelfile 등)
4. 사전 캐시 모델 목록(`OLLAMA_MODEL`, CPU 대체 모델)과 캐시 확인 절차
5. 제출 경로·파일명·마감 시각
6. 네트워크·참고 자료·AI 도구 허용 범위
7. 장애 발생 시 대체 제출 절차와 장애 기록 양식
8. 비공개 채점 테스트와 정답 기준

## 학생 산출물

- 지정 source 파일(복구된 `pyproject.toml`, 수정한 클라이언트 스크립트 등)
- 실행 기록(`outputs/report.json`, 새 함수를 부른 `[함수 실행]` 줄을 포함한 터미널 출력)
- 마지막 commit id
- 요구한 정상·실패 경로의 실행 결과
- 개념·읽기 문항 답안(판단 + 근거 + 영역 표기나 확인할 명령)
- 시험 규정에서 요구한 짧은 설명

## 시작 전 감독 체크

- 모든 PC에서 starter가 같은 방식으로 열리고 `uv sync`가 캐시로 해결된다.
- Ollama 서버가 떠 있고 사전 캐시 모델이 `ollama list`에 보인다.
- GPU 없는 PC의 CPU 대체 모델이 캐시되어 있다.
- starter에 답안 또는 이전 학생 정보가 없다.
- `.env` 커밋 상황을 재현하는 스크립트가 각 PC에서 동작한다.
- 제출 시스템에 테스트 파일을 업로드·재다운로드했다.
- 장애 기록 시각과 대체 제출 창구가 준비됐다.

## 공정성 경계

- 문구·환경·제출 장애는 모든 학생에게 같은 수준으로 안내한다.
- 구현 로직이나 정답에 해당하는 개별 힌트는 제공하지 않는다.
- AI 도구를 허용하는 경우 허용 범위·표기 방식·구두 확인 절차를 시험 전에 공지한다.
- 추가 시간·대체 평가는 대학 규정과 공식 기록을 따른다.
- 학생 코드·점수·개인정보는 공개 저장소에 올리지 않는다.

## 공개 저장소 제외 항목

- 실제 문제의 고유 값과 숨은 경계 조건
- 모범 답안과 부분 답안
- 채점 자동화의 비공개 testcase
- 수험생 명단, 제출 URL, 점수와 이의신청 기록
