# 2차 종합과제 — 라이선스 분석과 RAG 미니프로젝트

## 목적

5~7주에 누적한 공개 자원 분석과 임베딩·검색·생성 실습을 하나의 저장소로 묶어, **다른 사람이 clone해서 같은 결과를 재현할 수 있는** 출처 있는 RAG 답변기를 만든다. 모델·데이터·문서를 어떤 조건으로 썼는지 근거를 남기고, 답변기의 품질을 평가셋으로 측정해 실패 사례까지 기록한다. 배점·마감은 학교 운영 문서가 정한다.

## 대상 범위

| 주차 | 가져오는 것 |
|---|---|
| 2주차 | `LICENSE`, `license_matrix.md`(확장 대상) |
| 5주차 | `model_cards.md`, `SOURCES.md`, 캐시 보고, pipeline 실행 기록 |
| 6주차 | 임베딩 추출·유사도 계산, 실험 기록(`runlog`) 습관 |
| 7주차 | `mini_rag/` 파이프라인(chunk → embed → search → answer), `evalset.json`, `eval.py` |

## 필수 산출물

1. **라이선스·출처 분석 보고**
   - `model_cards.md`: 사용·검토한 모델 3개 이상. 라이선스·SPDX 식별자·의도된 용도·금지 용도·학습 데이터 공개 여부·한계.
   - `SOURCES.md`: 실제로 쓴 모델(생성 1개·임베딩 1개 이상)과 데이터·문서 출처. 이름·revision 또는 버전·라이선스·용도·변경 내용.
   - `license_matrix.md` 확장: 의존 패키지·모델·데이터·RAG 문서를 한 표에. 항목·라이선스·SPDX·상업적 이용·재배포 조건·출처 URL.
   - 종합 판단 1문단: 내 저장소의 `LICENSE`와 위 항목 사이에 충돌이 없는지, 있다면 어떻게 처리했는지.
2. **RAG 미니프로젝트**
   - `docs/`에 자기 문서 10개 이상(자체 작성 또는 라이선스가 허용하는 문서, 개인정보 없음).
   - `chunk → embed → search → answer` 파이프라인. 답에 출처(파일명·chunk id)를 표시한다.
   - 컨텍스트에 없는 질문에는 "모른다"로 답하는 경로.
   - 모델·주소는 환경변수 + 기본값(`OLLAMA_HOST`, `OLLAMA_MODEL`, `HF_EMBED_MODEL` 등)으로 읽는다. 요청 JSON에 `stream`·`think`·`options`를 명시한다.
3. **평가와 실패 분석**
   - `evalset.json` 10문항(질문·정답 키워드·정답 출처).
   - `eval.py` 실행 결과: retrieval hit rate·출처 일치율. `outputs/`에 JSON으로 남기고 README에 표로 옮긴다.
   - 실패 사례 2개: 증상·원인 가설·시도한 개선·결과.
4. **재현 절차**
   - README: clone → `uv sync --frozen` → 실행 명령 → 예상 출력. 사전 캐시가 필요한 모델 목록과 용량.
   - `pyproject.toml`, `uv.lock`, `.env.example`, `.gitignore`.
5. **개인 기여 증거**(아래 절)

## 제출 형식

- 저장소 URL(공개 또는 강의자에게 접근 권한 부여)
- 최종 commit id(`git log -1 --format=%H`)
- README의 재현 절차. 채점자는 이 절차만으로 깨끗한 폴더에서 실행한다.
- 제출 방식과 경로는 학교 운영 문서를 따른다.

## 개인 기여 증거

팀(2~3인)으로 제출하더라도 개인별로 다음이 확인되어야 한다.

- 본인 이름의 commit 5개 이상(의미 있는 단위, "update"·"fix" 한 단어 메시지 제외)
- 본인이 만든 Issue 1개 이상, 본인이 올린 PR 1개 이상, 본인이 남긴 Review 코멘트 1개 이상
- README 또는 `CONTRIBUTORS.md`에 역할 분담 표

개인 제출이면 Issue·PR·Review는 본인 저장소 안에서 브랜치 → PR → merge를 쓴 근거로 대신한다.

## 제출 전 검사

- [ ] 새 폴더에 clone해 README의 명령만으로 `eval.py`까지 실행했다.
- [ ] 8주차 예제의 `examples/assignment_check.ps1`에서 FAIL이 없다.
- [ ] `git ls-files`에 `.env`, `.venv/`, `outputs/`, 모델 파일이 없다.
- [ ] `SOURCES.md`·`license_matrix.md`의 모든 항목에 라이선스와 출처 URL이 있다.
- [ ] `docs/`·`evalset.json`·`outputs/`에 실제 이름·연락처·계정 정보가 없다.
- [ ] 출처 표시가 붙은 답 2건과 "모른다" 답 1건을 README 예시에 넣었다.
- [ ] 실패 사례 2개에 원인 가설과 시도 결과가 있다.
- [ ] 최종 commit id가 README 재현 절차를 검증한 시점의 것이다.

## 금지 사항

- 실제 토큰·비밀번호·개인정보를 어떤 파일·commit 이력에도 넣지 않는다. 이미 들어갔다면 토큰을 회전하고 이력 처리 내용을 README에 적는다.
- 라이선스가 없거나 재배포를 금지하는 문서·데이터를 `docs/`에 넣지 않는다.
- 재현할 수 없는 캡처만으로 결과를 대신하지 않는다. 캡처를 넣더라도 같은 결과를 만드는 명령과 파일을 함께 둔다.
- 모델 가중치·대용량 캐시를 저장소에 커밋하지 않는다.
- AI 도구를 썼다면 README에 사용 범위를 적고, 생성된 코드·문장을 직접 검증·수정한 내용을 남긴다.
