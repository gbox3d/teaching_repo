# 9주차 2교시 — 팀 제안서 초안

팀 제안서 작성에 쓰는 **양식과 VRAM 추정 참조 도구**다. 1교시 조사 도구·양식도 누적되어 있지만 이번 시간에는 제안서와 후보 비교에 집중한다.

기준: [실습지의 2교시](../../lab.md#2교시-실습--팀-제안서-초안). 아래 시간은 실습 30분의 구간이며, 설명 20분·휴식 10분은 기존 시간표를 따른다.

## 시간과 파일 대응

| 시간 | 실습 단계 | 읽거나 실행할 파일 |
|---|---|---|
| 0–5분 | 문제 후보 2개·선택 | `proposal_template.md` |
| 5–13분 | 사용자·Must 3개 | 개인 `proposal.md` |
| 13–21분 | 모델·데이터 후보 | `vram_estimate.py`, 제안서 후보 표 |
| 21–25분 | 위험 2개 | 제안서 위험 표 |
| 25–30분 | 완료조건 점검·저장 | `proposal.md` |

## 이전 산출물과 시작 위치

1교시 `governance_survey.md`의 규칙 3개와 4·5·7주차 모델·데이터 근거를 이어받는다. `period2`를 `C:\classwork\week09\period2`에 복사한다. 팀 제안서는 이 폴더에서 작성 후 3교시 팀 저장소로 옮긴다.

## 실행 순서

복사·`.env` 생성·이전 산출물 전달은 **새 실습 폴더에서 최초 1회만** 한다. 이미 작업 중이면 이 명령들을 생략하고 실행 위치 확인부터 이어간다. 기존 개인 코드·설정·결과를 덮어쓰지 않는다. 새 period의 누적 코드와 개인 변경은 비교하여 필요한 수정만 옮긴다.

```powershell
Set-Location C:\classwork\week09\period2
if (-not (Test-Path proposal.md)) { Copy-Item proposal_template.md proposal.md }
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
uv sync
uv run python vram_estimate.py --candidate "qwen3:8b,8.2B,4" --candidate "qwen3:0.6b,0.6B,4" --ctx 8192
```

## 예상 출력과 완료 확인

`outputs/vram-*.md`에 두 후보의 가중치·KV·여유·합계·12 GB 판정이 나온다. 이는 추정값이며 실측값과 구분한다. 제안서에는 Must 3개, 모델 2개, 위험 2개의 확인 방법·근거·담당을 채운다.

## 대체 경로

계산은 GPU·모델 다운로드 없이 가능하다. KV 구조를 주지 않으면 가중치 중심 추정이며 구조 값의 출처는 모델 카드에서 확인한다. 잘못된 후보 형식의 오류도 관찰한다.

실측 결과·답안은 개인 실습 폴더에 기록한다. 실제 비밀정보와 환경 폴더를 공개하지 않는다. 학기 기준이 정해지면 기준 PC에서 생성·검증한 lock을 배포하며, 현재 원본에는 lock을 넣지 않았다.
