# 제안 발표 채점표 — 100점 상대 배점

9주차 팀 프로젝트 제안 발표(팀당 3분 + 질의)의 공개 기준이다. 배점은 100점 기준의 **상대 배점**이며, 학교 적용 시 실제 반영 비율·발표 시각·마감은 학교 운영 문서가 정한다. 발표와 `docs/proposal.md`는 같은 범위를 설명해야 하며, 둘이 다르면 문서를 기준으로 낮은 쪽을 적용한다.

## 배점표

| 항목 | 배점 | 충족 기준 | 보는 곳 |
|---|---:|---|---|
| 문제·사용자 명확성 | 20 | 사용자·상황·문제·기존 해법·한계가 한 문장에 있고, 성공 신호가 측정 가능하다 | 제안서 1·2절, 발표 0:00–0:30 |
| 범위·기술 선정 근거 | 25 | Must 3개에 확인 방법이 있고, 모델 후보 2개의 선택 기준(라이선스·VRAM 추정/실측·재현 가능한 ID·품질 근거)이 수치와 URL로 제시된다 | 제안서 3·4·7절, 발표 0:30–1:15 |
| 라이선스·데이터 적법성 | 20 | 코드·모델·데이터·의존성 라이선스가 SPDX ID 또는 약관 이름으로 적혀 있고 호환 판단이 있다. 데이터 확보 방법·라이선스·개인정보 점검이 있다 | 제안서 5·6절 |
| 마일스톤·역할 현실성 | 20 | 12주차·15주차 고정 일정과 맞는 마일스톤 3개, 닫히는 조건이 산출물로 적혀 있고, Issue 8~10개가 담당·완료 조건과 함께 저장소에 있다. 위험 2개에 신호·완화·담당이 있다 | 제안서 8·9·10절, 팀 저장소 Issues, 발표 1:15–3:00 |

| 합계 | 100 | | |

## 수준별 판단

### 완전 충족

항목이 요구하는 요소가 모두 있고, 근거(수치·URL·저장소 링크)를 따라가면 같은 판단에 이른다. 발표에서 말한 것과 문서가 일치한다.

### 부분 충족

핵심 요소는 있으나 근거가 빠졌거나(예: 라이선스 이름은 있지만 URL이 없음, VRAM은 추정만 있고 실측 계획이 없음), 일부가 문서와 발표에서 다르다. 시도 흔적이 아니라 확인 가능한 부분 결과가 있어야 한다.

### 미충족

요소가 없거나 검증할 수 없다(예: "오픈소스"라고만 적힌 라이선스, "나중에 구한다"는 데이터, 닫히는 조건 없는 마일스톤, 저장소에 Issue가 없음). 발표를 했더라도 문서가 없으면 해당 항목은 미충족이다.

## 감점 적용 원칙

- 항목별 배점을 넘겨 감점하지 않는다. 같은 원인이 여러 항목에 영향을 주면 어느 항목에서 반영했는지 기록한다.
- 기술 이름을 나열했지만 선택 기준·수치·URL이 없으면 "범위·기술 선정 근거"를 완전 충족으로 보지 않는다.
- 라이선스가 없거나 약관을 확인하지 않은 모델·데이터를 후보로 둔 경우 "라이선스·데이터 적법성"은 미충족이다.
- 실명·학번·연락처·토큰이 제안서나 저장소에 있으면 관련 항목(적법성·현실성)에서 감점하고 즉시 제거를 요청한다.
- 3분을 30초 이상 넘기면 "시간·질의응답"에서 감점한다. 남는 시간은 감점하지 않는다.
- 팀 과제이므로 팀 점수를 기본으로 하되, 개인 기여 증거(Issue 담당·발표 역할)가 없는 팀원은 "마일스톤·역할 현실성"과 "시간·질의응답"을 개인별로 낮게 판단할 수 있다.
