# 1차 종합과제 루브릭 — 100점 상대 배점

## 적용 원칙

- 아래 배점은 100점 기준의 상대 배점이다. 학교 적용 시 실제 성적 비율·마감은 학교 운영 문서가 정한다.
- 채점은 제출된 commit id를 새 폴더에 `git clone`해서 README의 재현 절차대로 실행하며 진행한다. 실행되지 않으면 문서 점수가 실행 점수를 대체하지 않는다.
- 팀 제출은 팀 점수를 기본으로 하되, 개인 기여 증거가 최소 기준에 미치지 못한 사람은 항목 2(협업 근거)를 개인별로 판정한다.

합계 100점.

## 수준별 판단

| 항목 | 완전 충족 | 부분 충족 | 미충족 |
|---|---|---|---|
| 1. 재현성 | 깨끗한 폴더에서 README대로 실행됨 | `uv sync`는 되나 실행 명령이 README와 다르거나 수동 조치 1~2개가 필요함 | lock 없음, 재현 절차 없음, 또는 실행 실패 |
| 2. 협업 근거 | Issue·PR·Review 최소 개수와 리뷰 반영 흔적이 모두 확인됨 | 개수는 맞으나 리뷰 코멘트가 형식적이거나 PR이 리뷰 없이 merge됨 | URL이 없거나 열리지 않음 |
| 3. 라이선스·출처 | LICENSE·이유·출처 표가 모두 있음 | LICENSE는 있으나 이유 또는 가져온 코드 출처가 빠짐 | LICENSE 없음 또는 출처 없는 복사 코드 |
| 4. Ollama 활용 기능 | 세 기능이 모두 동작하고 `tool`에 직접 만든 함수가 있음 | 세 기능 중 하나가 빠지거나 동작하지 않음, 또는 `tool`에 예제 함수만 있음, 또는 `chat`이 기억하지 않음 | 모델 호출 자체가 실패하거나 두 기능 이상이 없음 |
| 5. 실습 기록 | 1~3절이 모두 채워지고 관찰마다 이유가 있으며 증거와 일치 | 일부 절이 비었거나, 결과만 있고 이유 설명이 없거나, 증거와 다름 | 보고서 없음 또는 실행 없이 적은 값 |
| 6. 보안·비밀 관리 | 파일·이력 모두 깨끗함 | `.env.example`이나 `.gitignore`가 불완전하나 실제 비밀은 없음 | 비밀·개인정보가 파일 또는 이력에 있음 |

부분 충족은 항목 배점의 절반 안팎(예: 배점 20이면 8~14점), 미충족은 그 아래(배점 20이면 0~6점) 범위에서 근거를 적어 판정한다.

## 감점 적용 원칙

- 실제 토큰·비밀번호·개인정보가 저장소 또는 이력에 있으면 항목 6은 0점이며, 제거와 토큰 회전 사실을 README에 적은 경우에만 다른 항목을 정상 채점한다.
- `evidence/`의 실행 화면과 보고서 내용이 맞지 않으면 항목 5를 부분 충족 이하로 본다. 실행 없이 적은 값으로 판단되면 미충족이다.
- 모델 가중치 파일을 커밋한 경우 항목 1에서 재현성 감점(용량·라이선스·clone 실패)을 적용한다.
- 캡처만 있고 명령·commit이 없는 산출물은 해당 항목의 증거로 인정하지 않는다.
- 제출한 commit id와 저장소 HEAD가 다르면 제출한 commit id 기준으로만 채점한다.
- 지각·마감은 학교 운영 문서가 정한다. 이 문서는 감점 비율을 정하지 않는다.
