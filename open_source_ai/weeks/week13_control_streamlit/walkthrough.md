# 13주차 따라하기: 제어 평가에서 Streamlit까지

문제와 실습 시간 배분은 [실습지](lab.md)가 기준이다. 이 문서는 실행 위치, 관찰 순서와 종료 방법을 설명한다. 소스와 교시별 실행 위치는 [예제 안내](examples/README.md)에서 확인한다.

## 1. 전체 저장소와 환경 준비

`teaching_repo` 전체를 clone한 폴더를 연다. 로컬 의존성 `tools/bleuno-control`과 주차 `examples/`의 상대 위치를 유지한다. Python 3.12를 사용하고, 새 구조 생성 연습은 실습지의 별도 경로에서 한 번만 한다.

```sh
# teaching_repo 루트에서
cd open_source_ai/weeks/week13_control_streamlit/examples
uv sync
```

`pyproject.toml`의 scripts가 [ex01_evaluate](examples/src/ex01_evaluate/__init__.py), [ex02_improve](examples/src/ex02_improve/__init__.py), [ex03_app](examples/src/ex03_app/__init__.py)의 `main()`에 연결되는지 읽는다. `uv_build`는 패키지를 설치하며 scripts는 실행 명령을 만든다. scripts를 고쳤다면 `uv sync`를 다시 실행한다.

바꿀 값은 모듈 위 대문자 상수에서 수정한다. 엔진과 모델은 수업 전에 준비한다. [shared/__init__.py](examples/src/shared/__init__.py)의 `MODELS_DIR`은 12주차 `examples/models/`를 가리키므로 모델 복사는 필요 없다.

## 2. 12주차 산출물 구별

| 자료 | 역할 | 이번 주 사용 |
|---|---|---|
| `models/checkpoints/needle3.safetensors` | LoRA 학습의 바탕 가중치 | 재학습 때 12주 절차에서 사용 |
| `adapter.safetensors` | LoRA로 학습한 변화량 | `.cact`와 구분해 보존 |
| `tuned.cact` | 어댑터 병합·내보내기 결과 | 학습 모델의 추론 가중치 |
| `models/baseline_adapter.safetensors` | B=0으로 기본 가중치를 바꾸지 않는 어댑터 | 기본 모델 내보내기에 사용 |
| `models/baseline.cact` | 기본 4bit·20층 비교 기준 | 학습 4bit·20층 `models/tuned.cact`와 비교 |

표의 경로는 모두 12주차 `examples/` 기준이다. 학습 원본은 12주차 `src/shared/data/train_examples.jsonl`의 48개 `query`·`answers`·`reasoning`이다. 공용 도구 스키마를 합쳐 만든 `models/training_input.jsonl`은 학습 입력이며 평가 결과 파일이 아니다. 복잡한 내보내기는 제공 함수가 담당한다. 학생은 데이터와 상수를 수정한다.

공식 `Cactus(weights=...)`는 `.cact`를 받는다. 어댑터 파일을 대신 넣지 않는다. 패키지·엔진과 맞지 않는 이전 `.cact`는 같은 버전으로 다시 내보내는 절차를 확인한다. 기본 배포 2bit와 로컬 LoRA 4bit의 차이를 학습 효과에 섞지 않는다.

## 3. 시뮬레이터 연결 확인

수업용 시뮬레이터를 먼저 실행한다. 공용 [Board](../../../tools/bleuno-control/src/bleuno_control/__init__.py)의 기본 주소는 TCP `127.0.0.1:8266`, HTTP `http://127.0.0.1:8080`이다. 명령 실행 전 초기 LED 상태를 정하고, `GET /state`가 실제로 돌려준 값으로 준비 상태를 확인한다.

한 대화나 평가 세션은 TCP 연결 하나를 유지한다. `turn_on(index)`, `turn_off(index)`, `set_brightness(index, value)`, `read_environment()`만 허용한다. 인덱스는 정수 0~3, 밝기는 정수 0~255다. 인자 이름이 다르거나 값이 잘못되면 실행하지 않는다. 호출 목록 전체를 검사한 뒤 실행해 뒤쪽 오류로 앞쪽 호출만 실행되는 일을 막는다.

## 4. 학습 전후 평가

```sh
uv run ex01
```

대화 입력 없이 공용 `control_cases.json`의 16문항을 자동 평가한다. 한국어 8·영어 8, 호출 10·무호출 6이다. 학습 원본 48개와 정확 문자열 중복은 없지만 의미 독립성까지 보장하지 않는다. 실행 전에 같은 문항·순서, 도구 정의, 생성 조건을 확인한다. 기본·학습 모델의 양자화와 층 수를 4bit·20층으로 맞춘다. 각 문항은 대화 이력을 초기화한 상태에서 시작한다. 매 문항과 모델 전환 전에 LED 초기 상태 `[0, 64, 128, 255]`를 복원하고 조회한다.

예상 호출과 실제 제안의 함수·인자를 대조한다. 실행한 뒤에는 함수 반환과 `GET /state`를 읽는다. LED가 우연히 이미 원하는 상태였다고 성공으로 처리하지 않는다. 호출까지 정답과 맞는지 함께 본다. 센서 문항은 그 시점의 함수 반환을 확인하며 서로 다른 시점의 온도·습도가 같아야 한다고 요구하지 않는다.

문항별 기록은 요청, 예상 호출, 모델 제안, 검증 결과, 함수 반환, 실제 상태, 오류다. 성공률을 계산하면 전체 문항 수와 성공 수를 함께 쓴다. 호출 없는 정답 문항의 불필요한 호출은 그 문항들만 분모로 따로 센다. 함수 정확도·호출 완전일치·실제 제어 성공·오호출률·median·p95를 구분한다. 시간은 측정 구간을 적고 실측값만 사용한다. 교재 준비 과정의 단일 실측은 [실측 표](README.md#수업-준비-환경의-단일-실측)를 참고한다.

## 5. 수정 요청을 반복 입력

```sh
uv run ex02
```

원래 요청의 실패를 재현하고 함수 선택과 인자 오류를 나눈다. 예를 들어 끄기 요청에 켜기 함수를 제안하면 함수 선택 오류이며, 끄기 함수의 LED 번호만 다르면 인자 오류다. 모호한 요청에서 값을 추측했다면 요청을 분명히 다시 입력해 변화도 관찰한다.

요청 수정 전후에는 시작 상태를 다시 맞춘다. 원문과 수정문, 바뀐 조건과 결과를 나란히 적는다. 반복 입력은 가중치 학습이 아니다. 현재 predictor는 요청마다 `reset()`하므로 독립 요청이다. “그 LED”처럼 번호가 빠진 요청을 이전 문맥에서 추측하지 않는다.

빈 입력은 건너뛰고 `/bye`로 마친다. 정상 종료 뒤 TCP 해제와 LED 초기화를 확인한다.

## 6. 데이터·설명 개선

실패 원인을 요청의 모호함, 도구 설명, 학습 데이터, 실행·연결 중 어디에서 고칠지 정한다. 수정한 요청의 성공을 원래 평가 점수에 덮어쓰지 않는다. 같은 평가 문항을 반복 보며 수정하면 그 문항은 개발 자료가 되므로 새 미학습 평가 문항이 필요하다.

`examples/src/ex02_improve/__init__.py` 위 `DESCRIPTIONS = {}`에 도구별 설명을 넣어 변경 전후를 비교한다. LoRA 전후 비교와 따로 기록하며 LoRA 비교에는 같은 설명을 쓴다.

학습 데이터는 별도 개발 예를 수정한다. 평가 원문·정답을 복사하지 않는다. 관련 없는 요청에 호출하지 않는 예, 동작이 반대인 예, 값이 다른 예의 필요성을 원인과 연결해 설명한다. 재학습은 [12주차](../week12_control_lora/README.md)에서 `EPOCHS`, `BATCH_SIZE`, `MAX_LEN`, `LEARNING_RATE`를 확인하고 학습·저장·새 프로세스 복원 순서로 진행한다. 시작값은 `EPOCHS=4`, `BATCH_SIZE=4`, `MAX_LEN=1024`, `LEARNING_RATE=1e-4`이며 데이터와 실측에 따라 조정한다. 학습 전 최장 토큰을 검사해 `MAX_LEN`을 넘으면 중단하고 자동으로 자르지 않는다. loss만으로 개선을 선언하지 않는다.

## 7. Streamlit UI 확인

```sh
uv run ex03
```

`http://127.0.0.1:8501`을 직접 연다. “시뮬레이터 연결”을 누르고 밝기와 LED 번호가 명확한 요청을 “제어 요청”에 입력하고 “요청 실행”으로 제출한다. 화면에서 사용자 입력, 호출 제안, 검증 결과, 함수 반환과 실제 LED 상태를 읽는다. 센서 요청은 실제 반환값과 표시가 같은지 확인한다.

모델 준비는 `st.cache_resource`를 사용한다. TCP 연결은 세션에 두고 재실행 때 재사용한다. 공용 predictor는 `Lock` 안에서 `reset()`과 `complete()`를 함께 처리한다. 한 PC에서 제어 창 하나를 사용한다. 같은 경로에 새 모델을 저장했다면 서버를 재시작한다. UI는 공용 기본 도구 설명을 쓰며 `ex02`의 변경을 자동으로 가져오지 않는다. 입력 없이 화면만 재실행했을 때 같은 호출을 다시 실행하거나 연결을 다시 만들면 수정 대상이다. 확인 근거가 없으면 중복 방지나 세션 격리가 검증되었다고 기록하지 않는다.

## 8. 연결 해제와 기록

UI의 “연결 해제”로 명시적으로 연결을 해제하고 LED 초기화를 확인한다. 그 뒤 터미널에서 `Ctrl+C`로 서버를 종료한다. 탭을 닫는 것만으로 소켓 정리를 보장하지 않는다.

학습 전후 비교 조건, 오류 분석과 수정 이유, UI에서 확인한 동작을 남긴다. 실행하지 못한 항목은 준비 실패·모델 실패·통신 실패·브라우저 미확인 중 실제 상황으로 적는다. 제출 형식과 일정은 강좌 안내를 따른다.

## 근거 자료

[Needle Python Docs](https://cactuscompute.com/blog/needle-python-docs)는 호출 응답, `reset()`, `weights`와 대화 객체 재사용의 근거다. [Fine-tuning Needle](https://cactuscompute.com/blog/finetuning-needle)은 로컬 4bit 학습·내보내기, 어댑터와 `.cact`, loss 해석의 근거다. 시뮬레이터 검증과 Streamlit 운영 절차는 이 수업에서 정한다.

## 재학습 후 앱 재시작

12주차에서 같은 `tuned.cact` 경로를 재학습해 덮어썼다면, 화면에서 연결을 해제하고 앱 서버 터미널에서 `Ctrl+C`를 누른 뒤 `uv run ex03`로 다시 시작한다. 브라우저 새로고침만으로 캐시된 가중치는 갱신되지 않는다.
