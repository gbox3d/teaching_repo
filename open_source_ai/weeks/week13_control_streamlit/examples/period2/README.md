[실습 문제와 시간표](../../lab.md#2교시-실습-오류-분석과-수정-대화) · [예제 색인](../README.md)

## 실행 위치와 명령

1교시와 같은 `examples/`에서 실행한다. 이 폴더로 이동하거나 프로젝트를 다시 만들지 않는다.

```sh
uv run ex02
```

[ex02_improve](../src/ex02_improve/__init__.py)는 12주차 `examples/models/tuned.cact`를 복사 없이 읽는다. 한 대화 동안 TCP 연결을 유지한다. 원래 요청을 재현한 뒤 의도가 분명한 요청을 다시 입력하고 호출·상태 변화를 확인한다. 빈 입력은 건너뛰고 `/bye`로 종료한다.

## 오류 분류와 수정

| 관찰 | 분류 | 확인할 위치 |
|---|---|---|
| 끄기 요청에 `turn_on` 제안 | 함수 선택 오류 | 요청의 동작과 학습 데이터의 정답 함수 |
| 함수는 맞지만 다른 LED·밝기 | 인자 오류 | 요청의 값, 인자 근거, 도구 설명 |
| 범위를 벗어난 값·문자열 숫자 | 검증 실패 | 실행 전 타입·범위 검사 |
| 호출은 맞지만 상태 조회 실패 | 연결·실행 오류 | TCP 연결, 함수 반환, `GET /state` |
| 모호한 요청에 임의 제어 | 불필요한 호출 | 호출 없는 학습 예와 모호한 요청 처리 |

검증 실패와 의도 오류를 구분한다. 유효한 다른 LED를 켠 호출은 형식 검사만으로 막을 수 없다. 수정 요청의 성공을 원래 평가 문항의 성공으로 바꿔 쓰지 않는다.

요청 재입력은 모델 가중치를 바꾸지 않는다. 현재 공용 predictor는 요청마다 `reset()`하므로 독립 요청이다. “그 LED”의 번호를 이전 문맥에서 추측하지 않는다. 반복 입력만으로 이전 요청을 기억한다고 설명하지 않는다.

## 학습 개선과 연결 해제

`ex02_improve` 위의 `DESCRIPTIONS = {}`에 함수 이름과 바꿀 설명을 넣고 같은 `uv run ex02`를 다시 실행한다. 요청 재입력과 설명 변경 전후 실험을 구분한다. LoRA 전후 비교에는 같은 도구 설명을 사용한다. UI에는 이 변경이 자동 전달되지 않는다.

학습 데이터의 수정안을 고를 때 원인·수정 내용·재확인 방법을 적는다. 평가 문항의 원문과 정답을 학습에 넣지 않고, 별도 개발 예로 수정한다. 재학습은 [12주차](../../../week12_control_lora/README.md)의 학습·저장·복원 절차를 따른다.

종료 후 연결을 해제하고 LED 초기화를 확인한다. 3교시에는 오류 분석에서 정한 입력·호출·반환·상태 항목을 화면에 표시한다. 실행한 관찰과 수정 계획을 구분해 기록한다.
