# 3차 종합과제 루브릭 — PEFT/LoRA 실험 기록과 AI 서비스 베타

100점 상대 배점이다. 학교 적용 시 실제 비율·마감은 학교 운영 문서가 정한다. 대상 산출물은 [3차 종합과제 안내](assignment_brief.md)를 따른다.

## 배점 표

| 항목 | 배점 | 완전 충족 기준 |
|---|---:|---|

## 수준별 판단

각 항목은 완전(배점 전부)·부분(배점의 절반)·미충족(0점) 세 수준으로 판단한다. 부분과 완전 사이의 세부 조정은 아래 기준의 충족 개수로 한다.

| 항목 | 완전 | 부분 | 미충족 |
|---|---|---|---|
| 실험 기록의 재현성 | 2회 기록 모두 필수 항목이 완비되고 차이 변수·이유가 명확 | 기록은 2회지만 seed·데이터 버전·VRAM 중 일부가 빠졌거나 차이 변수 설명이 없음 | 기록이 1회 이하이거나 설정만 있고 결과·실패가 없음 |
| 데이터·평가의 타당성 | 데이터 카드·분리된 평가셋·비교표·실패 분석 3건이 모두 있고 수치의 출처가 추적됨 | 비교표는 있으나 평가셋 분리가 불명확하거나 실패 분석이 1~2건 | 데이터 카드가 없거나 평가 수치의 근거 파일이 없음 |
| 서비스 기능·오류 처리 | 정상·422·원인별 5xx·UI 오류 표시가 모두 재현되고 점검 JSON이 있음 | 정상 경로는 되지만 실패가 500 하나로 뭉쳐 있거나 UI에 오류 상태가 없음 | 앱 서버가 뜨지 않거나 `/chat`이 모델 서버와 연결되지 않음 |
| 재현 절차 | 채점자가 README만으로 10분 안에 `/health` ok까지 도달 | 절차는 있으나 전제(모델 pull 등)나 확인 명령이 빠져 채점자가 추측해야 함 | 절차가 없거나 따라 해도 실행되지 않음 |
| 협업 근거 | 모든 팀원이 최소 기준을 넘고 기여 표가 이력과 일치 | 일부 팀원이 최소 기준 미달이거나 표와 이력이 다름 | 한 명의 계정에 이력이 몰려 있거나 PR·Review가 없음 |
| 보안·라이선스 | 비밀 없음, 라이선스 모두 기재, 충돌 없음 | 라이선스 일부 누락 또는 조건 검토 없음 | 비밀·개인정보가 이력에 있거나 라이선스 불명 자원을 사용 |

## 감점 적용 원칙

- 기술 이름을 나열했지만 실행·검증·근거 파일이 없으면 완전 충족이 아니다.
- 캡처만 있고 JSON·로그·commit이 없으면 해당 항목을 부분 이하로 본다.
- 재현 절차가 실패하면 「재현 절차」는 미충족이고, 「서비스 기능·오류 처리」는 채점자 환경에서 실행 가능한 범위만 인정한다.
- 실제 토큰·비밀번호·개인정보가 이력에 있으면 「보안·라이선스」를 0으로 하고, 회전·삭제 조치가 기록되어 있으면 부분으로 되돌린다.
- 팀 점수는 같아도 「협업 근거」는 개인별로 판단한다. 개인 기여가 없는 팀원은 이 항목을 0으로 한다.
- 제출 commit id 이후의 변경은 어떤 항목에도 반영하지 않는다.
- 선택 항목(스트리밍, Docker 경로)은 없어도 감점하지 않으며, 있으면 「서비스 기능」·「재현 절차」의 완전 충족 판단에 유리하게 본다.
