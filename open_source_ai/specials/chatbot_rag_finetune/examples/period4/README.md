# 특강 4교시: 추론 버그 잡기

실행 위치는 이 폴더가 아니라 `examples/` 루트다. 3교시에 등록한 자기 모델을 쓰고, 1~3교시 기록표의 자기 모델 `mine` 줄을 비교 기준으로 삼는다.

읽을 파일은 [ex07_inspect](../src/ex07_inspect/__init__.py), [rag_bot](../src/rag_bot/__init__.py), [추론 버그 잡기](../debugging.md)다. `ex07`은 봇 코드를 바꾸지 않고, 봇이 `answer(question)`을 한 번 실행하는 동안 Ollama에 보낸 요청과 받은 응답을 여섯 구역으로 보여 준다. 증상별로 확인할 값과 고칠 곳, 버그 심기 표 전체는 [추론 버그 잡기](../debugging.md)에 있다.

## 목표

- `ex04`에서 실패한 문항 하나를 `ex07`에 같은 질문으로 넣어 재현하고, [5]의 status와 [6]의 증상을 `ex04`의 실패 종류와 맞춰 본다.
- 기준 봇(14주차 `student_bot`)과 3교시에 등록한 자기 모델(`rag_bot`의 `MODEL`)을 같은 질문으로 점검해 요청과 모델 설정이 어디서 다른지 찾는다.
- 버그를 하나씩 넣기 전에 결과를 예상해 적고, `ex07`과 `ex04`로 관찰한 뒤 넣기 전 상태로 되돌린다.

## 준비

수업 전에 3교시 명령을 마쳐 자기 모델을 Ollama에 등록해 둔다. `examples/`에서 확인한다.

```powershell
ollama list
```

`ollama list`에 3교시에 등록한 이름(예: `wku-lora`)과 `qwen3.5:2b`, `bge-m3`가 있어야 한다. 3교시에 등록하지 못했으면 수업 전 준비에서 등록한 학습 전 모델 `wku-base`를 자기 모델 자리에 쓴다. `ex07`은 봇의 `answer()`를 실제로 부르므로 Ollama가 실행 중이어야 한다.

`ex07`에서 바꿔 볼 값은 파일 맨 위 상수다. 전체 목록은 [추론 버그 잡기](../debugging.md#ex07-추론-점검)에 있다.

| 상수 | 기본값 | 이 교시에서 둘 값 |
|---|---|---|
| `BOT` | `"student_bot"` | 1·3단계는 `"rag_bot"`, 2단계는 `"student_bot"` |
| `SHOW_PROMPT` | `True` | `False`. [2]의 messages가 역할과 글자 수만 나와 출력이 짧아진다. 보낸 문서를 읽어야 할 때만 `True`로 바꾼다 |

`rag_bot`의 `MODEL`은 자기 모델 이름으로 둔다. 3교시 끝에 `"wku-base"`로 바꿔 두었으면 자기 모델로 되돌린다. 봇 파일이나 `ex07`의 상수를 고치면 `ex07`을 `/bye`로 끝내고 다시 실행한다. 실행 중에는 처음 불러온 봇 모듈을 계속 쓴다.

## 30분 실습

| 시간 | 활동 |
|---|---|
| 0~7분 | 1. 실패한 문항 하나를 `ex07`로 재현 |
| 7~12분 | 2. 같은 질문을 기준 봇으로 점검해 두 출력 비교 |
| 12~27분 | 3. 버그 심기 1~3: 넣기 전 상태와 기준값 기록, 버그마다 예상 → 넣기 → `ex07`·`ex04` 관찰 → 되돌리기 |
| 27~30분 | 4. 기록 |

시간이 모자라면 `ex04`는 버그 하나에서만 실행하고, 하지 못한 버그는 과제 기간에 골라서 한다(선택). 버그 1은 수업에서 끝까지 한다.

### 1. 실패한 문항을 ex07로 재현

3교시에 자기 모델을 잰 `ex04` 출력에서 실패한 문항 하나를 고른다. 3교시 표에 적어 둔 `id`가 있으면 그 문항을 고르고, 질문 원문은 문항 파일에서 복사한다. 실패한 문항은 점수 줄과 `응답` 줄 사이에 `질문` 줄이 있다. 출력이 남아 있지 않으면 3교시와 같은 설정(`BOT = "rag_bot"`, `rag_bot`의 `MODEL`은 자기 모델, `QUESTION_SET`은 그 문항이 든 세트)으로 `uv run ex04`를 한 번 더 실행한다.

[ex07](../src/ex07_inspect/__init__.py) 맨 위 상수를 다음처럼 바꾸고 실행한다.

```python
BOT = "rag_bot"
SHOW_PROMPT = False
```

```powershell
uv run ex07
```

`질문>`에 `질문` 줄의 문장을 그대로 넣는다. 앞의 `질문` 낱말은 빼고 문장만 넣는다. `ex04`는 160자(`RESPONSE_WIDTH`)보다 긴 질문을 `...`로 잘라 보이므로, 잘렸으면 문항 파일에서 원문을 복사한다. 채점기는 문항마다 질문 하나만 보내므로 앞 질문에 기대지 않고 그 질문 하나로 재현한다.

[5]의 status가 `ex04`의 status와 같은지 보고, [6]의 문제 줄을 위에서부터 읽어 근거 값을 [2]~[5]에서 찾는다. status가 `ok`인데 점수가 낮았으면 형식은 맞고 답의 내용이 틀린 것이다. 이때 [6]에는 문제 줄이 없을 수 있으므로 [5]의 반환값을 정답과 비교하고, 검색된 문서(`ex05`)와 `SYSTEM_PROMPT`를 본다. 첫 질문의 [6]에 '모델 새로 적재'가 나오면 `ex07`을 켠 뒤 모델을 올린 시간이다. 채점기는 이 시간을 준비 질문으로 뺀다.

증상별로 확인할 값과 고칠 곳은 [증상 표](../debugging.md#증상별-확인할-값과-고칠-곳)에 있다. 확인을 마치면 `/bye`로 끝낸다.

### 2. 같은 질문을 기준 봇으로 점검

기준 봇은 14주차 `student_bot`이다. 낱말 겹침 검색과 `qwen3.5:2b`를 쓰고, `rag_bot`과 응답 계약·시스템 지시·요청 본문의 값이 같다. `ex07`의 `BOT`을 `"student_bot"`으로 바꾸고 다시 실행해 1단계와 같은 질문을 넣는다.

두 출력을 나란히 놓고 다른 곳을 적는다.

- [2]의 모델 정보: capabilities, Modelfile 기본값, 템플릿 출처
- [3]의 임베딩 호출
- [5]의 반환값, status, 적재를 뺀 시간
- [6]의 문제 줄과 끝의 참고 줄

두 봇은 검색 방법과 모델이 함께 다르다. 반환값이 다르면 `SHOW_PROMPT = True`로 [2]의 messages 전문을 보고 모델이 받은 문서가 같았는지 먼저 본다. 참고 줄은 요청 options가 덮어쓰지 않아 모델의 Modelfile 값이 그대로 쓰이는 PARAMETER이고, `ex07`은 이 값을 문제로 판정하지 않는다. 읽는 법은 [Modelfile 기본값](../debugging.md#modelfile-기본값)에 있다.

### 3. 버그 심기

[버그 심기 실습](../debugging.md#버그-심기-실습) 표의 1~3번을 하나씩 넣는다. 버그는 `rag_bot`에만 넣고 14주차 `student_bot`은 고치지 않는다. 수업에서는 질문 A(원광대학교를 상징하는 새는 무엇인가요?) 하나만 넣는다.

1. 넣기 전 상태를 기록한다. `git diff -- src/rag_bot/__init__.py`를 실행해 출력을 [4교시 실습](../../lab.md#4교시--추론-버그-잡기)의 넣기 전 `git diff` 표에 적는다. 2·3교시에 바꾼 상수(`TOP_K`, `MIN_SCORE`, `MODEL`)가 있으면 그 줄이 나온다.
2. `ex07`의 `BOT`을 `"rag_bot"`으로 되돌리고 버그 없이 실행해 질문 A를 넣는다. [2]의 capabilities, prompt_eval_count, eval_count와 [5]의 status, [6]에 나온 줄을 기준값으로 적는다.
3. 버그마다 다음 순서로 한다.
   - 예상 칸을 먼저 채운다. [6]에 새로 나올 증상, [5]의 status, `ex04` 실패 종류 표에서 잃은 점수가 가장 클 줄이다.
   - 버그 하나를 넣고 `ex07`을 다시 실행해 질문 A를 넣는다. [6]에 새로 나온 줄과 [5]의 status를 관찰 칸에 적는다.
   - [ex04](../src/ex04_my_eval/__init__.py)를 `BOT = "rag_bot"`, `QUESTION_SET = "mine"`으로 한 번 실행해 전체 평균과 실패 종류 표를 본다.
   - 바꾼 곳을 넣기 전 값으로 되돌리고 `git diff -- src/rag_bot/__init__.py`의 출력이 1번의 기록과 같은지 확인한다.

| 버그 | 넣는 곳(`src/rag_bot/__init__.py`) | 바꾸는 값 |
|---|---|---|
| 1. 생각 모드 켜기 | `answer()` 요청의 `"think": False` | `"think": True` |
| 2. 출력 한도 줄이기 | `answer()` 요청 options의 `"num_predict": 512` | 2번에서 적은 질문 A의 eval_count를 2로 나눈 정수 |
| 3. 없는 모델 이름 | `MODEL` | 지금 이름에서 한 글자를 틀리게 바꾼 값(예: `"wku-lora"`의 하이픈을 밑줄로) |

예상은 2번의 기준값과 [증상 표](../debugging.md#증상별-확인할-값과-고칠-곳)를 보고 정한다. 같은 버그라도 `MODEL`이 가리키는 모델에 따라 결과가 다를 수 있다. 기준값에서도 [6]에 줄이 나올 수 있으므로 버그를 넣은 뒤에는 기준값에 없던 줄을 찾는다. `ex07`을 다시 켠 첫 질문에서 모델을 다시 올리면 버그와 상관없이 '모델 새로 적재'가 나올 수 있다.

### 4. 기록

1단계 문항의 [6] 증상(문제 줄이 없으면 '없음'), 확인한 값, 고칠 곳과 2단계에서 찾은 두 봇의 차이를 [4교시 실습](../../lab.md#4교시--추론-버그-잡기)의 표에 적는다. 버그 심기의 예상과 관찰도 같은 곳에 적고, `git diff -- src/rag_bot/__init__.py` 출력이 3단계 1번의 기록과 같은지 마지막으로 한 번 더 본다.

수업에서 하지 못한 버그(4~9)는 과제 기간에 [추론 버그 잡기](../debugging.md)에서 골라서 한다(선택). 학습한 모델의 답이 이상할 때도 같은 문서의 순서로 원인을 좁힌다.

## 과제 폴더에서 ex07 쓰기

과제 챗봇은 14주차 예제를 복사한 개인 과제 폴더에서 고친다. `ex07`은 14주차 `shared`만 쓰므로 `src/ex07_inspect` 폴더를 과제 폴더의 `src/`에 복사하고, `pyproject.toml`의 `[project.scripts]`에 `ex07` 줄을, `module-name` 목록 끝에 `"ex07_inspect"`를 더한 뒤 `uv sync`를 다시 실행하면 자기 `student_bot`을 점검할 수 있다. 고친 뒤의 표 모양과 주의할 점은 [추론 버그 잡기의 과제 폴더에서 ex07 쓰기](../debugging.md#과제-폴더에서-ex07-쓰기)에 있다. 과제 폴더에는 `rag_bot`이 없으므로 `BOT = "student_bot"`을 그대로 둔다.
