# 특강 1교시: 내 평가 문항과 실패 분류

실행 위치는 이 폴더가 아니라 `examples/` 루트다. 이 교시에서 더한 문항과 기록표는 2~4교시에도 이어 쓴다.

읽을 파일은 [ex04_my_eval](../src/ex04_my_eval/__init__.py), [lab_shared](../src/lab_shared/__init__.py), [문항 작성 규칙](../src/lab_shared/data/README.md)이다. 채점은 14주차 [채점기](../../../../weeks/week14_chatbot_project/examples/src/shared/evaluation.py)의 `evaluate`가 하고, 산식은 [평가 규격](../../../../weeks/week14_chatbot_project/evaluation_spec.md)을 따른다. `ex04`는 채점 전에 문항 내용을 검사하고, 채점 뒤에 잃은 점수를 실패 종류별로 모은다.

## 목표

- 14주차 `ex02`와 같은 채점기로 공개 20문항과 내 문항을 잰다.
- 문항마다 잃은 점수를 실패 종류로 나누고, 전체 평균을 가장 많이 깎은 종류를 찾는다.
- 다음 교시에 고칠 것 하나와, 고친 뒤 비교할 점수를 정한다.

## 준비

수업 전에 `examples/`에서 한 번 실행한다.

```powershell
uv sync
ollama list
```

`ollama list`에 `qwen3.5:2b`가 없으면 수업 전에 `ollama pull qwen3.5:2b`로 내려받는다. 평가하는 동안 Ollama가 실행 중이어야 한다. 이 프로젝트는 14주차 예제 폴더를 상대 경로로 쓰므로 저장소 전체를 clone한 위치에서 실행한다.

`ex04`에서 바꿔 볼 값은 파일 맨 위 상수다.

| 상수 | 기본값 | 역할 |
|---|---|---|
| `BOT` | `"student_bot"` | 잴 봇 모듈. `student_bot`은 14주차 공식 워커로 재고, 다른 이름은 `lab_shared.worker`가 그 모듈의 `answer(question)` 함수를 부른다(없으면 문항마다 실행 오류). `"rag_bot"`은 2교시에 쓴다(`bge-m3` 필요) |
| `QUESTION_SET` | `"mine"` | `"public"`은 14주차 공개 20문항, `"mine"`은 내 문항, `"train"`은 3교시 학습 문항 |
| `OLLAMA_HOST` | `"http://127.0.0.1:11434"` | 평가 뒤 올라가 있는 모델과 Ollama 버전을 조회하는 주소. 채점에는 쓰지 않는다 |
| `RESPONSE_WIDTH` | `160` | 문항별 응답·오류와 실패한 문항의 질문을 보여 줄 최대 글자 수 |

## 30분 실습

| 시간 | 활동 |
|---|---|
| 0~7분 | 1. 공개 20문항으로 `ex04`와 `ex02`를 실행하고 점수 대조 |
| 7~15분 | 2. 내 문항 더하기, 3. 내 문항으로 실행 |
| 15~20분 | 4. 실패 종류 표 읽기 |
| 20~25분 | 5. 고칠 감점 하나 고르기, 6. 같은 설정으로 다시 실행 |
| 25~30분 | 7. 기록표 채우기 |

### 1. 공개 20문항으로 채점 맞추기

[ex04](../src/ex04_my_eval/__init__.py) 맨 위 상수를 다음처럼 바꾼다.

```python
BOT = "student_bot"
QUESTION_SET = "public"
```

```powershell
uv run ex04
uv run ex02
```

`ex02`는 이 프로젝트에 함께 설치된 14주차 공개 평가 명령이다. 두 명령은 같은 채점기, 같은 문항, 같은 봇을 쓴다. 범주별 평균과 전체 평균이 같은지 본다. 점수는 응답만으로 정해지므로 점수가 다르면 응답이 달라진 문항이 있다. 문항별 출력에서 그 문항을 찾는다. 평가 중에 Ctrl+C를 누르면 워커를 정리하고 점수 없이 끝난다. Windows에서는 진행 중인 문항이 끝나거나 제한 시간(문항 30초, 모델 준비 120초)을 넘긴 뒤에 중단된다.

### 2. 내 문항 더하기

[문항 작성 규칙](../src/lab_shared/data/README.md)을 따라 `src/lab_shared/data/my_questions.json`과 `my_answers.json`에 문항을 몇 개 더한다. 두 파일은 14주차 공개 질문·정답과 형식이 같고 `id`로 짝을 맞춘다.

`ex04`는 평가 전에 14주차 `validate_dataset`으로 형식을 보고 이어서 내용을 검사한다. 형식이 틀리면 `평가 시작 오류`로 멈춘다. 내용 검사 메시지에는 문항 `id`가 붙는다.

| 내용 검사 | 결과 |
|---|---|
| 근거 문서 ID가 `corpus.json`에 없음 | 오류 |
| 공개 문항과 같은 질문 | 오류 |
| 세트 안에서 같은 질문 | 오류 |
| 사실의 어떤 별칭도 근거 문서 본문에 없음 | 경고 |
| `composite`인데 사실이 하나 | 경고 |

질문이 같은지는 14주차 채점과 같은 정규화로 판단하므로 공백과 대소문자 차이는 무시한다. 다만 `https://` 같은 주소가 든 질문은 문장 안의 공백 차이를 구분한다. 오류가 하나라도 있으면 평가를 시작하지 않는다. 경고는 표시만 하고 평가를 진행한다. 경고가 나오면 근거 문서 원문과 대조해 정답이나 근거 문서 ID를 고칠지 정한다.

### 3. 내 문항으로 실행

`QUESTION_SET = "mine"`으로 바꾸고 `uv run ex04`를 실행한다. 문항마다 `id`, 범주, 점수, `status`, 실패 종류와 잃은 점수가 한 줄에 나오고 다음 줄에 응답이 나온다. 실패한 문항은 두 줄 사이에 `질문` 줄이 더 나온다. 시간 초과·실행 오류·형식 오류는 응답 아래 `오류` 줄에 원인이 나온다. 질문·응답·오류가 `RESPONSE_WIDTH`보다 길면 잘라서 보여 준다.

문항별 출력이 끝나면 `모델 준비 N회: ok, ...` 줄이 먼저 나온다. N은 워커를 시작하거나 다시 시작한 횟수다. 채점기는 첫 문항 앞에서 워커를 시작하고, 시간 초과나 실행 오류가 난 문항 뒤에는 워커를 끝냈다가 다음 문항 앞에서 다시 시작한다. 시작할 때마다 준비 질문을 한 번 보내며, 쉼표로 나열한 값이 준비 결과(`ok`, `timeout`, `error`, `invalid_response`)다. 준비 질문은 점수에 들지 않는다. N이 1보다 크면 평가 중에 워커가 다시 시작된 것이다.

### 4. 실패 종류 표 읽기

평가가 끝나면 범주별 평균과 전체 평균 뒤에 실패 종류 표가 나온다. 문항마다 잃은 점수(100 − 점수)를 아래 종류에 넣는다. 표는 14주차 채점 결과의 `status`, `subscores`, 정답, 응답만 읽고 다시 채점하지 않는다.

| 종류 | 해당 문항 | 넣는 점수 |
|---|---|---|
| 시간 초과 | `status=timeout`. 문항 30초나 모델 준비 120초를 넘김 | 100 |
| 실행 오류 | `status=error`. 봇 예외, Ollama 연결 실패, 워커 종료 | 100 |
| 형식 오류 | `status=invalid_response`. 응답 계약(세 키, 값의 형식·길이)을 어김 | 100 |
| 답변 불가인데 답함 | 정답이 답변 불가인데 100점이 아님 | 100 |
| 답할 수 있는데 거절 | 정답이 있는데 응답이 `abstain=true` | 100 |
| 사실 누락·불필요한 답 | 답변 F1이 1보다 낮음 | 80 − `answer_points` |
| 출처 누락·불필요한 출처 | 출처 F1이 1보다 낮음 | 20 − `source_points` |

맞힌 사실이 없으면 채점 규칙상 출처 점수도 0이므로 그 문항의 100점을 모두 '사실 누락·불필요한 답'에 넣는다. 출처 F1의 분모에는 문항에 필요한 문서가 모두 들어간다. 그래서 빠뜨린 사실에만 필요한 문서가 있으면 맞힌 사실의 출처를 바르게 적어도 출처 쪽 감점이 함께 생기고, 한 문항이 사실과 출처 두 줄에 함께 든다.

'전체 평균에서 빠진 점수'는 잃은 점수 합을 전체 문항 수로 나눈 값이다. 일곱 줄을 더하면 100에서 전체 평균을 뺀 값과 같고, 표 아래 줄이 `빠진 점수 합 + 전체 평균 = 100`으로 이 관계를 보여 준다. 표 아래의 합은 반올림하기 전의 값을 더한 것이고 표의 각 줄은 소수 둘째 자리로 반올림한 값이므로, 화면에 보이는 일곱 줄을 손으로 더하면 표 아래 합과 0.01~0.03 다를 수 있다. 표는 Markdown 형식이므로 보고서에 그대로 붙일 수 있다.

### 5. 고칠 감점 하나 고르기

'전체 평균에서 빠진 점수'가 가장 큰 종류 하나를 고른다. 그 종류에 든 문항의 질문과 응답을 읽고 원인 가설을 하나 적는다. 근거 문서가 모델에 가지 않았는지, 문서는 갔는데 답을 잘못 뽑았는지, 형식을 어겼는지를 나눠 본다. 근거 문서가 검색 결과에 들었는지는 2교시 `ex05`로 확인한다. 바꿀 것 하나(상수, 프롬프트 문장, 학습 문항)와 바뀌면 줄어야 할 종류·문항 `id`를 적는다. 검색은 2교시, 학습은 3교시 예제로 고친다.

가장 큰 종류가 형식 오류, 시간 초과, 실행 오류 가운데 하나이면 답의 내용을 채점하기 전에 0점이 된 것이다. 이때는 그 문항의 `질문` 줄에 나온 문장을 `uv run ex07`(4교시 추론 점검)의 `질문>`에 그대로 넣어 봇이 Ollama에 보낸 요청과 받은 응답을 본다. `ex07`의 `BOT`도 `ex04`와 같은 봇으로 둔다. 증상별로 확인할 값과 고칠 곳은 [추론 버그 잡기](../debugging.md)에 있다.

### 6. 같은 설정으로 다시 실행

아무것도 바꾸지 않고 `uv run ex04`를 한 번 더 실행한다. 두 실행의 문항별 점수와 전체 평균을 비교한다. 차이가 있으면 그만큼은 설정을 바꾸지 않아도 생기는 변동이다. 설정을 바꾼 뒤의 차이가 이 변동보다 크지 않으면 개선으로 보지 않는다. Ollama는 기본으로 5분 동안 요청이 없는 모델을 내린다. 두 실행 사이에 5분 넘게 쉬면 모델을 다시 올리므로 설정이 같아도 응답이 달라질 수 있다.

### 7. 기록표 채우기

실행할 때마다 한 줄씩 적는다. 값은 `ex04` 출력 끝의 '기록할 값'에서 옮긴다.

| 날짜 | BOT | 문항 세트 | 바꾼 상수 | 전체 | fact | composite | unknown | 모델·digest | Ollama 버전 |
|---|---|---|---|---:|---:|---:|---:|---|---|
| | `student_bot` | `public` | 없음(기준) | | | | | | |
| | `student_bot` | `mine` | 없음(기준) | | | | | | |

- 같은 설정으로 `public`과 `mine`을 모두 실행해 두 줄을 나란히 적는다.
- 공개 점수와 내 문항 점수가 함께 오른 변경만 채택한다. 한쪽만 오른 변경은 채택하지 않는다. 공개 20문항에만 맞춘 변경은 처음 보는 질문에서 점수를 올리지 못할 수 있고, 최종 성능은 같은 형식의 비공개 문항으로 잰다.
- '평가 뒤 올라가 있는 모델' 줄은 조회한 순간 Ollama에 올라가 있는 모델마다 하나씩 나온다. 앞선 실행이나 다른 프로그램이 올린 모델도 섞일 수 있으므로 `BOT`이 쓰는 모델(봇 파일의 `MODEL`, `rag_bot`은 `EMBED_MODEL`도)의 줄만 옮긴다. 처음 값으로는 `student_bot`이 `qwen3.5:2b`, `rag_bot`이 `qwen3.5:2b`와 `bge-m3`를 쓴다. 태그를 생략한 `bge-m3`는 `bge-m3:latest`로 나온다.
- 모델은 이름과 digest 앞 12자리를 함께 적는다. 같은 태그라도 digest가 다르면 다른 빌드다.

## 터미널 출력을 파일로 남기기

```powershell
[Console]::OutputEncoding = [Text.Encoding]::UTF8; uv run ex04 | Tee-Object -FilePath ex04_mine_1.log
```

출력이 화면에 그대로 보이고 같은 내용이 파일에 남는다. 앞부분은 PowerShell이 프로그램의 UTF-8 출력을 UTF-8로 읽게 한다. 콘솔 코드 페이지가 한국어 Windows 기본값인 949이면 이 설정 없이 화면과 파일의 한글이 깨진다. 파일 이름에는 문항 세트와 회차를 넣는다. 저장소의 `.gitignore`가 `*.log`를 제외하므로 이 파일은 커밋 대상에 오르지 않는다. 워커와 봇이 표준 오류로 내는 메시지는 화면에만 나온다. `uv run ex02`의 전체 출력도 같은 방법으로 남긴다.

## 과제 폴더로 옮기기

기말과제 챗봇은 14주차 예제를 복사한 개인 과제 폴더에서 고친다. 그 폴더에서 `ex04`로 자기 봇을 재려면 다음 순서로 옮긴다.

1. 이 특강의 `src/lab_shared`(`data/` 포함)와 `src/ex04_my_eval`을 과제 폴더의 `src/` 아래에 복사한다.
2. 과제 폴더의 `pyproject.toml`에 이미 있는 두 표를 고친다. `[project.scripts]`의 기존 줄 아래에 `ex04` 줄을 더하고, `[tool.uv.build-backend]`의 `module-name` 목록 끝에 `"lab_shared"`와 `"ex04_my_eval"`을 더한다. 14주차 예제를 그대로 복사한 폴더라면 고친 뒤 두 표는 아래 모양이다(사이의 `[build-system]`은 그대로 둔다). 이 블록을 파일 끝에 통째로 붙이면 같은 표가 두 번 생겨 TOML 오류가 난다.

   ```toml
   [project.scripts]
   ex01 = "ex01_chat:main"
   ex02 = "ex02_evaluate:main"
   ex03 = "ex03_improve:main"
   evaluate = "ex02_evaluate:main"
   ex04 = "ex04_my_eval:main"  # 더한 줄

   [tool.uv.build-backend]
   # 목록 끝의 "lab_shared", "ex04_my_eval"을 더했다
   module-name = ["shared", "student_bot", "ex01_chat", "ex02_evaluate", "ex03_improve", "lab_shared", "ex04_my_eval"]
   ```

3. `uv sync`를 다시 실행한 뒤 `uv run ex04`를 실행한다.

`main()`은 명령의 시작점이고 `[project.scripts]`는 `ex04`라는 이름을 `ex04_my_eval:main`에 연결한다. `[build-system]`의 `uv_build`가 `module-name`에 적은 패키지로 프로젝트를 설치하므로, scripts와 `module-name`을 고친 뒤에는 `uv sync`를 다시 해야 `ex04` 명령이 생긴다. `BOT = "student_bot"`이면 과제 폴더의 `student_bot`을 14주차 공식 워커로 잰다. `rag_bot`은 이 특강 폴더에만 있으므로 과제 폴더에서는 `BOT`을 바꾸지 않는다.
