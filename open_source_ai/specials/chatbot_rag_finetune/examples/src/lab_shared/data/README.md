# 내 평가 문항과 학습 문항 예시(v0)

특강 예제가 읽는 문항 예시다. 기말 챗봇을 고칠 때 쓸 내 평가 문항과 학습 문항을 만드는 방법을 보여 준다. v0은 14주차 [참고 자료 corpus.json](../../../../../../weeks/week14_chatbot_project/examples/src/shared/data/corpus.json)의 문서 5개만 근거로 쓴다. 학습 문항은 일부만 공개한 예시이고, 학습 데이터를 늘려 채우는 일은 학생이 한다. 참고 자료가 늘면 이 자료를 v1로 바꾸고 아래 수치와 목록도 고친다.

## 파일과 역할

| 파일 | 역할 | 문항 수 |
|---|---|---|
| `my_questions.json`, `my_answers.json` | 내 평가 문항. `ex04`가 공개 20문항과 같은 채점기로 재고, `ex05`가 근거 문서를 검색했는지 확인한다 | 20(fact 12, composite 4, unknown 4) |
| `train_questions.json`, `train_answers.json` | 학습 문항. `ex06`이 챗봇이 실제로 보낼 대화에 정답 JSON을 붙여 학습 예시로 바꾼다 | 40(fact 24, composite 5, unknown 11) |

특강 프로젝트에서는 이 네 파일을 직접 고치고, 과제 폴더로 옮길 때는 `data/`가 든 `lab_shared` 폴더를 통째로 복사한다([1교시 안내](../../../period1/README.md#과제-폴더로-옮기기)).

예제는 `lab_shared.load_set("mine")`과 `load_set("train")`으로 이 파일을 읽는다. 평가용과 학습용을 나누어 내 평가 점수가 학습으로 부풀지 않게 한다. 학습한 질문으로 다시 재면 모델이 질문과 답을 외워 점수가 오르고, 그 점수로는 처음 보는 질문으로 치르는 비공개 시험에서 나아졌는지 판단할 수 없다. 그래서 내 평가 문항과 공개 20문항은 학습에 넣지 않는다. `ex06`도 학습 문항 가운데 공개·내 평가 문항과 같은 질문이 있으면 학습 예시를 만들지 않고 멈춘다.

## 형식

14주차 공개 평가 세트와 같고, 정본은 14주차 [평가 명세](../../../../../../weeks/week14_chatbot_project/evaluation_spec.md#사실과-출처-점수)다. 질문 파일의 항목은 `id`, `category`, `question`이고 정답 파일의 항목은 `id`, `expected`, `sources`, `abstain`, `fact_sources`다. 두 파일은 `id`로 짝을 맞춘다.

```json
{"id": "mine-16", "category": "composite", "question": "신입생 퀴즈에 원광초급대학 설립 연도와 원광대학교 교색을 문제로 내려 합니다. 두 정답을 알려 주세요."}
```

```json
{"id": "mine-16", "expected": [["1951", "1951년"], ["황금색", "금색"]], "sources": ["wku-history", "wku-symbols"], "abstain": false, "fact_sources": ["wku-history", "wku-symbols"]}
```

`expected`에는 사실마다 별칭 그룹을 하나씩 둔다. 채점기는 응답을 정규화한 값이 그룹 안의 별칭 하나와 같으면 그 사실을 맞힌 것으로 본다. `fact_sources[i]`는 `expected[i]`의 근거 문서 ID이고, 한 문서가 여러 사실의 근거이면 같은 ID를 되풀이한다. `sources`에는 그 ID를 처음 나온 순서대로 한 번씩 적는다. `ex06`은 그룹마다 첫 별칭을 모델이 그대로 출력할 학습 답으로 쓴다. unknown 문항은 `expected`, `sources`, `fact_sources`가 모두 빈 배열이고 `abstain`이 `true`다.

## 작성 순서

1. 사실 고르기. `corpus.json` 본문을 끝까지 읽고 답 한 칸에 들어갈 값을 문서별로 모두 적는다. 내 평가에는 공개 문항이 묻지 않는 사실을 먼저 쓴다.
2. 질문 쓰기. 학생이 실제로 물을 법한 문장으로 쓰고 '연도만', '각각' 같은 답 모양 지시를 섞는다. 잘못된 전제를 바로잡는 질문(mine-06)도 fact에 넣는다. composite는 서로 다른 문서의 사실 2~3개를 함께 묻는다. unknown은 실시간·개인 정보처럼 참고 자료 밖의 질문과, 익숙한 주제지만 참고 자료에 없는 세부를 묻는 질문을 섞는다. unknown의 주제는 아래 [작성 규칙](#작성-규칙)대로 고른다.
3. 별칭 적기. 첫 별칭은 문서 본문에 그대로 나오는 짧은 값이고, 흔한 다른 표기를 뒤에 둔다. 연도는 숫자만 쓴 값을 앞에, '년'을 붙인 값을 뒤에 둔다(`["1951", "1951년"]`, 14주차 공개 정답과 같은 순서). URL은 끝 슬래시나 스킴을 뺀 표기를, 전화번호는 하이픈을 빼거나 괄호·점으로 나눈 표기를 뒤에 둔다. 채점기가 단어 사이 공백을 무시하므로 공백만 다른 별칭은 넣지 않는다.
4. 근거 문서 적기. 사실마다 `fact_sources`에 문서 ID를 같은 순서로 적고 `sources`를 맞춘다.
5. 검사 실행. 아래 [검사](#검사)의 시험 9개가 모두 통과해야 한다.

## 작성 규칙

- 공개 20문항과 비공개 평가 문항을 넣지 않는다. 공개 문항에서 조사나 낱말 몇 개만 바꾼 문장도 쓰지 않는다. 시험은 공개 문항과 문장 유사도가 0.85 이상인 질문을 실패로 본다.
- 내 평가 문항과 학습 문항의 질문을 겹치지 않는다. 같은지는 14주차 채점기의 `normalize`(NFKC, casefold, 공백 무시)로 판정한다.
- unknown은 내 평가와 학습이 묻는 주제도 겹치지 않게 한다. 학습에서 거절을 배운 주제를 내 평가에서 다시 물으면 unknown 점수가 부푼다.
- 학습용 unknown도 공개 17~20번 주제를 피한다. 같은 주제의 거절을 학습하면 공개 점수가 학습으로 부풀어, 공개 점수로 개선 여부를 판단할 수 없다. 피할 범위는 학교 식당의 식단(17), 교색·교조·교목·교화 네 상징물에서 자료에 없는 세부(18), 중앙도서관에서 자료에 없는 세부(19·20)다.
- 피할 것은 주제다. 실시간 정보, 개인 정보, 익숙한 주제에서 자료에 없는 세부 같은 질문 유형은 겹쳐도 된다. 비공개 문제도 공개된 참고 자료와 질문 유형 안에서 출제하기 때문이다([과제 안내](../../../../../../weeks/week14_chatbot_project/assignment_brief.md#공개-자료와-비공개-평가)). mine-17(내 장학금)과 train-30·34(내 성적·수강 신청)는 유형이 같고 주제가 달라 함께 둔다.
- 별칭은 문서 표기에서 시작한다. 옛 이름 `전라북도`처럼 지금은 틀린 표기는 별칭에 넣지 않는다.

## v0의 한계

문서 5개에서 답으로 쓸 수 있는 사실을 30개로 셌다. 답 한 칸에 들어가는 값 하나를 사실 하나로 세므로 교육목표 세 가지는 사실 3개다. 공개 20문항이 그중 15개를 묻는다. 내 평가의 known 16문항은 사실 18개를 묻고, 그중 15개는 공개 문항이 묻지 않는 사실이다. 광역자치단체, 교육목표 세 가지, 건학정신(원불교·과학·도학·전인교육), 원광초급대학·원광대학 설립 연도, 대학원 석사과정 설치 연도, 종합대학교 승격 날짜, 공식 홈페이지·웹정보서비스 주소, WAFFLE-i의 서비스 종류가 여기에 든다.

학습의 known 29문항은 사실 25개를 묻는다. 공개 문항이 묻는 사실 15개를 모두 포함하고, 내 평가 사실 18개 중 13개도 다른 문장으로 다시 묻는다. 문서가 5개뿐이라 학습 문항 29개를 쓰려면 같은 사실을 되풀이해 물을 수밖에 없다.

이 학습 예시는 공개 문항이 묻는 사실도 쓴다. 그래서 이 예시로 학습한 모델의 공개 점수에는 같은 사실을 외운 효과가 들어 있다. 학생이 참고 자료 전체를 학습 데이터로 바꾸는 것은 과제 규칙이 허용하고([과제 안내](../../../../../../weeks/week14_chatbot_project/assignment_brief.md#공개-자료와-비공개-평가)), 비공개 평가도 참고 자료의 사실을 다른 문장으로 묻는다. 그래서 학습 뒤의 공개·내 평가 점수는 '학습한 사실을 처음 보는 문장으로 물었을 때'의 점수로 읽는다.

학습에 없는 사실 5개(과학, 도학, 전인교육, `1971년 12월 31일`, 학습 플랫폼)는 내 평가에만 있다. 이 사실을 묻는 mine-04, mine-05, mine-09, mine-12의 점수를 학습 전후로 따로 보면 학습이 처음 보는 사실에도 통하는지 가늠할 수 있다. 네 문항뿐이므로 경향만 본다. unknown은 내 평가와 학습이 서로 다른 주제를 묻고, 학습 unknown은 공개 17~20번 주제도 묻지 않는다.

학생이 학습 데이터를 늘릴 때도 위 작성 규칙과 아래 검사를 그대로 따르고, 문항 수가 바뀌면 시험 파일의 상수를 고친다.

참고 자료가 늘면 v1로 바꾼다. 문서가 충분하면 학습용 사실과 평가용 사실을 문서 단위로 나누고, 아래 목록과 대조해 unknown 문항이 여전히 답할 수 없는 질문인지 다시 확인한다.

## 참고 자료에 넣으면 안 되는 사실

아래 사실이 참고 자료에 들어가면 해당 unknown 문항이 답할 수 있는 질문이 되어 정답(답변 불가)이 맞지 않게 된다. 참고 자료를 늘릴 때 이 사실은 넣지 않는다. 꼭 넣어야 하면 그 문항을 다른 unknown 문항으로 바꾸고 이 표를 고친다.

| 문항 | 넣으면 안 되는 사실 |
|---|---|
| mine-17 | 학생 개인별 장학금 |
| mine-18 | 개교기념일 날짜 |
| mine-19 | 다음 학년도 신입생 모집 인원 |
| mine-20 | 대학원 박사과정 설치 연도 |
| train-30 | 학생 개인 성적 |
| train-31 | 올해 축제 초대 가수 |
| train-32 | 셔틀버스 실시간 위치 |
| train-33 | 날씨 |
| train-34 | 학생 개인 수강 신청 내역 |
| train-35 | 교가 작곡자 |
| train-36 | 대표 팩스 번호 |
| train-37 | 유일학림 설립자 |
| train-38 | 캠퍼스 면적 |
| train-39 | 단과대학 수 |
| train-40 | 웹정보서비스 정기 점검 시간 |

14주차 공개 17~20번이 묻는 학생식당 식단, 교목 지정 연도, 열람실 실시간 좌석 수, 중앙도서관 개관 연도도 같은 이유로 넣지 않는다.

이 표는 공통 참고 자료를 고칠 때 대조하는 목록이다. 학생이 자기 봇의 검색 자료에 공통 참고 자료 밖의 사실을 더하면, 그 사실을 묻는 답변 불가 문항에 답하게 되어 점수를 잃을 수 있다. 답변 불가 여부는 공통 참고 자료로 답할 수 있는지로 정한다([출처 안내](../../../../../../weeks/week14_chatbot_project/examples/src/shared/data/README.md)).

## 검사

특강 `examples/` 폴더에서 실행한다. Ollama가 필요 없다.

```powershell
uv run python -B -m unittest tests.test_my_data -v
```

[시험 파일](../../../tests/test_my_data.py)에는 시험이 9개 있고 모두 통과해야 한다. 출력 끝에 `Ran 9 tests`와 `OK`가 나온다. 실패하면 문항 id를 함께 보여 준다. 질문과 정답의 id 짝이 맞지 않으면 짝 없는 id를, JSON 파일을 읽지 못하면 파일 이름을 보여 준다. 문항 수를 바꾸면 시험 파일 맨 위의 `MY_COUNTS`, `TRAIN_TOTAL`, `TRAIN_UNKNOWN_MIN`, `TRAIN_UNKNOWN_MAX`도 고친다. 공개 문항과의 유사도 기준은 같은 곳의 `SIMILARITY_LIMIT`(0.85)이다.

시험 9개는 다음을 확인한다.

- 14주차 채점기의 `validate_dataset`을 통과한다.
- known 문항에 `fact_sources`가 있고 그 문서 ID가 참고 자료에 있다.
- 사실마다 별칭 하나 이상이 근거 문서 본문에 있고 첫 별칭도 본문에 있다. 둘 다 NFKC·casefold를 적용하고 공백을 지워 비교한다.
- 공개 20문항과 같은 질문이 없다.
- 공개 20문항과 문장 유사도가 `SIMILARITY_LIMIT`보다 낮다. 두 질문을 14주차 `normalize`로 바꾼 뒤 `difflib.SequenceMatcher`의 `ratio()`로 잰다. v0 예시 60문항의 최댓값은 train-08과 public-08 사이의 0.72이고, 두 질문은 서로 다른 사실을 묻는다. 짧은 질문은 낱말 하나만 바꿔도 기준을 넘는다. public-08에서 '교화'만 '교조'로 바꾼 문장은 0.94다.
- 내 평가와 학습 사이, 그리고 한 파일 안에 같은 질문이 없다.
- 내 평가는 20문항(fact 12, composite 4, unknown 4)이고, 학습은 40문항이며 그중 unknown이 10~12문항이다.
- unknown 문항의 정답이 비어 있다.
- `ex06`이 학습 답으로 쓰는 첫 별칭과 `fact_sources`가 14주차 채점기에서 100점을 받는다.

다음 셋은 시험이 잡지 못하므로 근거 문서 본문, 공개 문항과 직접 대조한다.

- 별칭이 그 질문이 묻는 사실인지. 원광대학 설립 연도를 묻는 문항의 정답에 같은 문서의 `1951`을 적어도 통과한다.
- 첫 별칭이 본문 표기를 그대로 쓴 값인지. `익산시` 대신 그 일부인 `익산`을 앞에 두어도 통과한다.
- 문장을 조금만 바꾼 질문인지. 어순이나 낱말 몇 개를 바꿔 유사도가 0.85 밑으로 내려가면 통과한다.
