# C04: 11주는 저장을 익히고 SPA 구현은 선택 특강으로 분리한다

작성: 독립 기획자 C04, 2026-11-18. 대상: 강의자의 웹프로그래밍 입문 수업. 이 문서는 구현 계획이며 실행 검증 완료 보고서가 아니다.

## 결정 기록

- 결정: 정규 과정은 세 페이지를 유지한다. 11주 2차시 강의에 상태 비교 시연 8분을 넣고, 해시 SPA 직접 구현은 11주 이후 선택 특강으로 편성한다.
- 근거: SPA의 화면 이동은 메모리 수명을 연장할 수 있지만 새로고침 이후 데이터 보존을 해결하지 않는다. 문자열 저장·JSON·폼 복원을 처음 배우는 주에 주소 해석·초기 진입·탐색까지 직접 작성하게 하면 서로 다른 원인을 동시에 디버깅해야 한다.
- 대안: 10주 전환은 배열·DOM 반복 생성과 겹친다. 12~14주 전환은 HTTP 요청·응답·편집 권한 실습을 줄인다. 9주 전환은 README·발표와 충돌한다. 정규 전체 전환보다 같은 화면의 상태 차이를 짧게 관찰하는 편이 현재 목표에 맞는다.
- 재검토: 초보 학생 리허설에서 11주 저장 실습을 도움말 2회 이하로 25분 안에 마친 학생이 80% 이상이고, 별도 SPA 실습도 30분 안에 끝나는지 확인한 뒤 다음 학기 편성을 다시 판단한다. 이는 제안한 기준이며 측정 결과가 아니다.

## 시간과 학생 부담

일반 차시는 모두 강의·시연 60분, 실습 30분이다. 강의 중 장문 동시 타이핑은 배정하지 않는다. 실습 기본값은 시작 확인 4분, 수정 16분, 오류·동작 확인 7분, 증거 저장 3분이다.

## 메모리·저장·주소를 구분하는 SPA 계약

11주 8분 시연은 같은 입력을 MPA와 제공 SPA에서 바꾸기 2분, 화면 왕복 2분, 새로고침과 명시적 불러오기 3분, 결과 예측 1분이다. 라우터 코드는 설명·타이핑·시험 범위에 넣지 않는다. MPA의 뒤로 가기에는 브라우저의 페이지 복원 영향이 있으므로 메모리 소멸의 증거로 단정하지 않고 새로고침·새 탭 진입을 따로 확인한다. 비교용 시연본은 초기 입력 비우기를 명시해 브라우저의 폼 값 복원을 저장 기능으로 오해하지 않게 한다.

| 상태·조작 | 비교 시연 및 선택 특강에서 보장할 동작 |
|---|---|
| 화면 주소 | `index.html#home`, `#about`, `#guestbook`; 빈 해시는 홈, 알 수 없는 해시는 주소를 유지한 안내 화면과 홈 링크 |
| 메뉴·탐색 | 해시 링크와 hashchange로 section.hidden·현재 메뉴·제목을 함께 갱신한다. 최초 실행 때도 같은 함수를 한 번 호출한다 |
| 직접 URL·새로고침 | 새 탭의 `#guestbook`과 새로고침 모두 방명록을 연다. 화면 선택을 localStorage에 저장하지 않는다 |
| 뒤로·앞으로 | 이동한 해시와 현재 section이 일치한다. 알 수 없는 해시도 안내 화면으로 복귀한다 |
| 화면만 전환 | 기존 DOM을 재생성하지 않아 입력·메모리 배열·목록을 유지한다. 전환 자체는 저장 호출을 하지 않는다 |
| 새로고침 | 메모리 배열과 DOM 상태를 다시 초기화한다. 저장한 값만 별도 읽기 코드로 복원한다. ex06은 불러오기 버튼, 특강 목록은 초기 읽기로 복원한다 |
| 저장 범위 | 같은 origin의 저장 공간을 공유한다. `week11-ex06-entry`, `web-week11-guestbook-v1`, `spa-state-guestbook-v1`처럼 키를 분리하며 localhost·포트·HTTPS 변경 시 자동 이전되지 않는다 |
| 서버 상태 | REST 확장 단계에서만 GET으로 복원한다. localStorage의 이전 글과 서버 응답을 자동 합치지 않는다. 편집 키는 런타임 메모리에만 두고 새로고침 뒤 다시 입력한다 |
| Pages·접근성 | `/web-spa-state/` 아래 상대 CSS/JS/그림 요청을 검사한다. section id 중복 금지, 현재 메뉴 aria-current, 제목·Tab 탐색·숨은 영역의 포커스를 확인한다 |

저장 공간의 기준과 지속성은 [MDN localStorage](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage), 해시 이벤트 조건은 [MDN hashchange](https://developer.mozilla.org/en-US/docs/Web/API/Window/hashchange_event)로 확인했다. pushState/replaceState가 hashchange를 발생시킨다고 설명하지 않는다.
선택 특강은 `specials/spa_state/`를 신설해 01_mpa→02_hash_memory→03_storage→04_rest 순서로 만든다. 04는 14주 이후 단계이며 `.http`를 동봉한다. 각 단계 통과 후 다음으로 진행하고 차시 수를 제한하지 않는다. 정규 P07~P14 주소는 그대로 두며 특강의 옛 about.html·guestbook.html에는 새 해시 주소 안내 링크를 둔다. [GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)의 프로젝트 경로를 유지하며 가상 `/guestbook` 경로는 채택하지 않는다.

## 평가 정합과 수정 순서

중간은 1~7주 학생 작성 범위만 출제한다. 제공 submit·trim·focus·form.reset 코드를 처음부터 작성시키지 않는다. 9주는 문서 전달과 시연을 평가하며 폼 구현 능력으로 점수를 주지 않는다. 기말 저장 문항은 ex04~06 범위와 제공 틀의 호출·필드 수정, REST 문항은 실제로 수정한 요청·본문·대상 id·재조회 구간만 출제한다. SPA·ex07·배열 심화는 정규 점수에서 제외한다.
실기 서버 장애 시 강의자 로컬 API와 동일 요청 파일로 전환한다. 사전 전환 검사도 실패하면 공통 시간을 중단하고 문항을 재실시한다. 서버 접속 실패를 학생 구현 오류로 감점하지 않는다. Pages 지연은 로컬 결과와 commit 증거를 인정하고 다음 수업에서 공개 주소를 확인한다.

1. 인계 담당: 10→11→12의 README·lab 설명을 먼저 일치시키고 P11의 저장 키·초기 복구를 보정한다. 일반 키 충돌·잘못된 JSON·타입 불일치에서 해당 키만 지우고 다시 시작할 수 있게 한다.
2. 기초 담당: 1~6주 모든 README/slides/walkthrough/lab/examples를 조사하되 4·5주 필수 축소와 준비 시간을 먼저 반영한다. 3주의 다음 저장소 주소를 web-week04로 고친다.
3. 화면 담당: 7→9→10→11→12→13→14 완성본의 CDN·클래스·id·추가 CSS 경로를 비교한다. CDN은 `https://cdnjs.cloudflare.com/ajax/libs/w3-css/4.1.0/w3.min.css`, 추가 스타일은 `shared/examples.css` 원칙으로 맞춘다. 독립 배포본 PNN에는 공용 CSS의 배포 사본을 `shared/examples.css`에 포함해 저장소 바깥 상대 경로에 의존하지 않게 한다.
4. REST 담당: 12주 예제 앞에 접속/about→help 폴더를 추가하고 모든 요청 예제에 실행 가능한 .http를 둔다. baseUrl·공개 apikey·book_id 설정, Send Request, 예상 200/201/204·본문을 쓴다. 편집 키는 로컬 환경값/입력으로 받고 추적 파일에는 넣지 않는다. book_id는 구분값이며 권한이 아니다.
5. 평가·특강 담당: 8·9·15주 문제은행·rubric·project_brief와 SPA 선택 자료를 갱신한다. 14주 수정·삭제를 유지하고 기존 레포트 경로는 별도 과제 안내로 남긴다.
6. 통합 담당: 과목 README·weeks/specials 색인, 전체 한글/영문 슬라이드·실습 설명·예제 README·walkthrough 코드 일치를 검사한다. 주차별 읽은 파일 목록과 필수/시연/선택 분류를 남긴 뒤 사이트 빌드·링크 검사를 수행한다.

## 자체 검증과 남는 한계

기획 단계에서는 대표 코드·문서와 30차시 합계를 대조했다. 브라우저 실행과 초보 학생 소요 시간은 아직 검증하지 않았다. 선정 후 다음 리허설을 실제 결과와 함께 기록한다.

| 리허설 | 통과 조건·예상 실패 대응 |
|---|---|
| 6→7→9→10 | 제공 시작본으로 글 2개·375px·배열 3개 중 가운데 삭제를 재현한다. id 변경이나 CSS 누락은 인계 파일에서 수정한다 |
| 11주 30분 | ex04의 빈 문자열/null, ex05 JSON, ex06 저장→새로고침→불러오기→지우기를 순서대로 수행한다. 자동 복원으로 오해하면 버튼 단계부터 다시 확인한다 |
| origin·복구 | 동일 origin 다른 폴더에서 키 충돌이 없고 포트 변경 뒤 이전 값이 보이지 않는다. 잘못된 JSON 복구가 다른 예제의 저장값을 지우지 않는다 |
| SPA 시연·특강 | 직접 주소·새로고침·뒤/앞·잘못된 해시·키보드 이동을 localhost와 Pages에서 각각 실행한다. 화면 이동 유지와 재로딩 복원을 따로 기록한다 |
| 12→14 | about/help→GET, 빈 배열, Offline→복구, POST 연속 클릭, 지정 id의 PATCH/DELETE, 잘못된 키, 204 빈 본문을 확인한다. 성공 상태만 보지 않고 GET 결과를 대조한다 |
| 시간·시험 | 초보 학생의 시작본·수정 목록·도움말 횟수·실제 경과 시간을 기록한다. 30분을 넘으면 필수 수정량을 먼저 줄이고, 시험 시작본으로 같은 범위를 다시 수행한다 |

이 안의 약점은 정규 수강생이 SPA를 직접 완성하지 않는다는 점이다. 8분 비교로 라우팅 구현 능력을 평가할 수 없다. 12~14주도 제공 코드 의존이 남으므로 수정 위치와 제공 부분을 명시한 채점표가 필요하다. 특강 자료 한 세트의 추가 유지 비용, 수업 전후 20분 준비 부담, 공용 API와 CDN 연결 조건은 실제 운영 리허설에서 확인해야 한다.
