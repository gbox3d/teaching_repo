# 7주 W3.CSS 방명록 조사와 실행 기록

2026-11-18, 강의자의 수업의 C01 구현 범위에서 조사했다. 기존 W3.CSS 개편과 60분 강의·30분 실습 흐름을 유지했다. 이번 담당 작업은 준비·인계·제공 코드 범위의 명시, 6주 홈 CSS 인계, 이메일 기본 검사 설명과 긴 출력 줄바꿈 보완이다. 기존 개편으로 이미 바뀐 예제 구성·원고를 이번 담당이 새로 작성했다고 계산하지 않는다.

## 차시별 운영

| 차시 | 강의·시연 60분 | 학생 실습 30분 | 확인 결과 |
|---|---|---|---|
| 7-1 | CDN 10, ex01 15, ex02 15, ex03 15, 안내 5 | CDN 5, 입력·버튼 10, 메뉴·카드 10, 확인 5 | CDN 200, 클릭·미리보기, 375/1280px 메뉴 배치 |

각 차시 첫 10분의 앞 5분을 파일·서버 확인에 포함하고, 마지막 5분에는 실습·다음 수업을 안내한다고 원고 6종에 맞췄다. 기존 구간을 늘리거나 60+30 합계를 바꾸지 않았다. 다운로드·저장소 생성은 사전 준비이고 push·Pages 확인은 수업 뒤 작업이다.

학생 필수는 1일차 ex02·ex03의 지정 클래스 한 곳씩과 2일차 CDN·매핑 클래스·색상 한 곳 변경이다. ex01 색상 변경은 강의자 시연·학생 선택으로 구분했다. ex04·ex05의 JS 비교는 강의자 시연이며 제공 폼 JS 재작성, 보조 CSS 구현, 새 JS 기능은 필수가 아니다. 30분 안에 초보 학생이 실제로 마치는지는 아직 관찰하지 않았다.

## 수정 내용과 근거

6주 최종 `styles.css`를 그대로 받아 홈 제목의 단어 단위 줄바꿈, 입력의 border-box, 다크 모드 h1·h2·메뉴 색 `#a7c5ff`, footer 색 `#c8d4eb`를 이어 썼다. `index.html`, `app.js`, `about.html`, `styles.css`, `images/profile.png`는 6주 완성본과 SHA-256이 일치했다.

이메일 값이 JS에서 쓰이지 않더라도 `type="email"`의 브라우저 검사는 실행된다. `abc`가 submit 전에 거절되고, 빈 이메일 또는 `student01@example.com`은 허용됨을 실행했다. 이 차이를 README·실습·따라하기·예제 안내·한영 슬라이드에 설명했다. JS의 이름·메시지 빈값 처리나 기존 ID는 변경하지 않았다.

공백 없는 ASCII 120자를 입력했을 때 ex02·ex03·ex04·ex05·완성 방명록 전후의 문서 폭이 375px에서 1246~1297px, 일부 1280px 화면에서도 최대 1601px로 늘었다. 총괄이 공통 `shared/examples.css`에 추가한 `.example-output { overflow-wrap: anywhere; }`를 사용하여 보완했다. 해당 5개 폴더에 공통 CSS 배포 사본을 두고 출력 요소에 클래스와 상대 링크를 연결했다. 모든 사본의 SHA-256은 원본과 일치한다. W3.CSS 자체는 계속 고정 CDN에서만 읽는다.

클래스 매핑은 목록의 `card`만 `w3-ul`로 바꾸고 제공 `example-output`은 유지한다고 고쳤다. `shared/` 폴더의 복사·인계도 설명했다. 12주에 이미 사용하는 보조 CSS 배포 방식과 같고 새 의존성이나 JS 기능은 넣지 않았다.

9주에는 7주 웹 파일을 유지하며 README·캡처·제공 SVG만 추가하고, 시험 답안을 출발점으로 사용하지 않는다고 명시했다. 11주 예고도 필수 폼 한 건 저장·복원과 제공 전체 저장 방명록을 구분했다.

## Chrome 실행 결과

로컬 서버 `http://localhost:8111/`의 과목 하위 경로에서 Playwright의 설치된 Chrome 채널을 headless로 실행했다. 10개 HTML을 375×960과 1280×960에서 모두 열었다. 20개 실행 화면을 캡처해 직접 확인했다. 자산·CDN 요청과 JS 오류를 별도로 수집했으며 예제 코드의 pageerror와 실패한 자산 요청은 0건이었다. CDN을 사용하는 화면은 지정 주소의 200 응답을 확인했다.

`web-week07` 전체 9개 파일을 임시 폴더에 독립 복사해 `file://`로도 실행했다. CDN·`shared/examples.css`·프로필·홈/소개/방명록 이동이 동작했고, 375px에서 ASCII 120자가 줄바꿈되었다. 이는 교재의 파일 직접 열기 대체 절차 검증이다. 외부 GitHub Pages에 새 배포를 수행한 것은 아니다.

로컬 검증 자료는 `%TEMP%/week07-audit/`의 `results.json`, `long-results.json`, 20개 화면 PNG, `portable-long-375.png`에 있다. 실행 스크립트는 `%TEMP%/week07-{baseline,browser,static,portable}.mjs`다. 임시 자료이며 배포 교재에 포함하지 않았다.

## 정적 검사와 인계

상대 파일 링크 93건을 검사해 누락 0건이었다. 단편 앵커는 해당 원고 제목·HTML ID와 대조했다. 7개 JS는 모두 `node --check`를 통과했다. UI 문구 검사와 한국어 문서 검사도 0건이었다. 전체 HTML·JS 코드 전문을 복제한 원고는 없으며, CDN·버튼·입력·script 발췌와 매핑표는 실제 속성·파일 경로와 대조했다. 한영 슬라이드는 기존 18장씩을 유지했다.

`ex02/app.js`와 `ex03/app.js`, `ex04/app.js`·`ex05/app.js`·완성 `guestbook.js`는 각각 해시가 일치한다. 페이지마다 동작 JS 하나를 유지한다. `guestbook-form`, `name`, `message`, `notice`, `list`와 이메일 ID·라벨 연결은 변환 전후 동일하다.

9주 초기 검사에서는 홈 HTML·CSS 차이와 프로필 누락이 있었고 방명록 HTML·JS는 기존에 동일했다. 이번 보완 후 9주 담당에게 `web-week07` 전체 9개 파일과 `shared/`, 긴 출력·다크 모드 보완을 직접 인계했다. 9주 동기화 후 최종 동일성 검증은 9주 담당·총괄의 기록을 따른다.

전체 저장소 빌드, 렌더된 슬라이드 배치 검사, 다른 주차와의 통합 검사는 총괄 담당이다. 공개 Pages 게시, 초보 학생 30분 실측, 구현에 참여하지 않은 심사자의 평가는 여기서 실행했다고 기록하지 않는다. 커밋·푸시는 하지 않았다.
