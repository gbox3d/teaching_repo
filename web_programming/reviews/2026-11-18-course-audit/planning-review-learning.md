# 학습·차시 운영 독립 심사

대상: 강의자의 웹프로그래밍 수업 구성 C01~C09. 심사자: learning. 기획 1차 심사, 2026-11-18.

결정: 이 심사에서는 C01을 권고한다. 30차시의 학생 수정과 확인 시간을 가장 구체적으로 나누고, 11주 필수 폼 복원과 제공 방명록, 12주 읽기 전환, 기말 작성 범위를 연결했다. 9개 안 모두 이 심사에서 8점 이상이며 확인된 필수조건 위반은 없다. 이는 계획의 적합성 판정이다. 다른 심사자의 점수와 구현 결과까지 통과했다는 뜻은 아니다.

대안: C04는 11주의 상태 비교와 저장 복원을 구분하고 수정 파일 수를 제한한 점에서 근접한 대안이다. C02의 정규 SPA도 필요한 선수 지식과 주소 동작을 갖춘 안이다. 다만 9주 첫 실습의 개인 콘텐츠 이식·문서 작성·라우팅·검증 시간을 더 세분해야 한다.

재검토: 승자안의 시작 파일과 학생 수정표를 만든 뒤 이 보고서의 구현 전 조건을 다시 대조한다. 실제 학생 소요 시간은 이후 초보자 리허설과 수업 운영에서 측정한다. 아직 존재하지 않는 개편 예제의 실행 성공이나 학생 수행 시간을 이번 점수의 근거로 사용하지 않았다.

## 심사 범위와 기준

[brief.md](brief.md)의 7개 항목과 배점을 그대로 사용했다. C01~C09를 모두 읽었으며 다른 심사 보고서·점수는 읽지 않았다. 공통 사실·기준 문서인 [director.md](director.md)는 읽었다. 실제 교재·코드·평가 자료는 읽기만 했으며 이 보고서와 JSON 외에는 작성하지 않았다.

모든 안의 30차시 표, 강의·실습 구분, 직접 작성량, 제공 코드, 주차 인계, SPA 주소·상태 계약, 시험·발표 운영을 비교했다. 분량은 줄 수만으로 평가하지 않았다. 파일 준비, 두 예제 사이 이동, 개념 판단, 정상·실패 결과 확인, 증거 저장이 같은 30분 안에 들어가는지 보았다. 강의 중 학생이 제공 예제를 조작하는 관찰 활동은 독립 구현과 구분했다.

## C01: 수정량과 평가 범위의 연결이 가장 구체적이다

[C01](proposal-C01.md)은 27개 일반 차시와 세 평가 예외의 합계를 맞췄다. 4·5주를 값·조건·함수의 지정 부분으로 줄이고 10주에는 직접 append 제거, push, showList, splice의 작성 위치를 구분했다. 11주 ex06만 완료한 학생에게 제공 W11을 주고 12주 읽기 화면으로 바꾸는 흐름도 명확하다. 기말 저장 문제를 폼 복원으로 바꾸고, 수정·삭제 문제는 한 메서드 작성으로 좁힌 것이 수업 중 작성량과 맞는다.

남은 결함은 9주와 제공 기능의 변경량이다. 9-1은 두 장 캡처·코드 인용을 10분, SVG 글자 수정·미리보기를 5분에 넣는데, 기존 rubric의 기능 설명과 배운 내용 작성 시간은 따로 보이지 않는다. 31명 이상 대안의 ‘전원 짧은 코드 설명’도 개인 시간·최대 인원이 없다. 13·14주 파일 통합과 런타임 공개 설정 패널은 새 제공 기능이므로 단순 문서 편집 이상의 비용이 든다. C01이 이메일을 3주 입력 예제로 설명해도 실제 7주 폼에는 이메일이 남아 있으므로 제거·유지 시점을 인계표에서 확정해야 한다.

구현 전에는 9주 필수 README 틀을 채점표 다섯 항목과 대조하고, 31명 이상 운영을 수치로 고정해야 한다. 통합 JS에서 중복 선언·이벤트·초기 요청이 없고 설정 입력 전후의 동작이 분명한 시작본을 먼저 만든다. 이후 초보자 리허설은 9주와 12주 첫 설정의 실소요를 확인한다. SPA 특강의 주소·탐색·상태 계약은 충분하며 특강 선택 자체는 감점하지 않았다.

## C02: 정규 SPA의 범위는 적절하나 9주 실습이 촘촘하다

[C02](proposal-C02.md)은 6주의 classList·함수·이벤트를 재사용하고 두 화면으로 제한한다. 실제 홈의 count·countBox와 후속 방명록 식별자 충돌을 짚고 강의자 시작본에서 해결하도록 했다. 초기 호출·hashchange·직접 주소·잘못된 hash·새로고침·뒤로/앞으로·메모리 상태·Pages 경로가 일관된다. SPA 코드 암기를 시험에 추가하지 않는 경계도 명시했다.

9-1의 README 8분, 라우팅 14분, 동작 확인 8분은 합계가 맞지만 준비·증거 저장의 별도 몫이 없다. 본문에서 학생이 옮긴다고 한 자기 제목·소개·색상은 이 표에 배정되지 않았다. 메뉴 두 개, 분기, classList, 이벤트 등록, 최초 실행을 처음 연결하면서 문서까지 작성하므로 ‘몇 줄’만으로 14분을 보장할 수 없다. SPA 전환은 소개를 홈 카드로 합치므로 기존 세 페이지 이동 점수도 실제 두 화면 동작으로 다시 정의해야 한다. 9~14주 외곽·옛 주소·시험 시작본까지 바뀌는 비용은 다른 안보다 크다.

구현 전에는 9주 시작본에 개인 콘텐츠 이식까지 포함한 변경표와 분 단위 실습표를 만든다. README 배점과 새 두 화면 탐색 점수를 명시한다. 제안한 초보자 5명·4명 완료 기준은 향후 채택 리허설 기준이며 이번 기획 심사에서 이미 통과한 것으로 보지 않았다. 이 조건을 실제로 확인하기 전 정규 전환을 확정하지 않는 제안 자체는 타당하다.

## C03: 목록 학습은 보존하지만 비교 활동의 시간 여유가 작다

[C03](proposal-C03.md)은 배열·반복·DOM 생성의 선수 순서를 유지하고, 정규 SPA를 코드 작성이 아닌 조작 비교로 한정했다. ex08이 이후 주 시작본에 섞이지 않으며 showList와 showPage를 구분했다. 11주 ex06만 마친 학생의 12주 시작도 별도 상황으로 검토했다.

10-2는 준비 3분, 수정 17분, 비교 5분, 확인·캡처 5분이다. 수정은 여섯 곳 이내지만 추가·삭제·개수 연결과 별도 ex08 열기, 글 두 개 입력, 왕복, 새로고침까지 들어간다. 목록 오류가 한 번 나면 비교 또는 증거 시간이 줄어드는 구조다. 계획은 비교 5분을 보강으로 돌리는 대안을 두었으므로 재현 불가능으로 판정하지는 않았다. 31명 이상 발표 대안은 개인 1분 확인의 전환 시간·최대 인원이 없다. 13·14주 기능 파일은 유지하면서 공통 단일 JS 지침의 예외를 명시적으로 확정하지 않았다.

구현 전에는 10주 필수 목록의 완료 기준을 SPA 관찰과 분리하고 비교를 생략해도 제출·평가가 동일함을 안내한다. 대규모 발표 상한과 REST 파일 예외를 확정한다. 실제 초보자 측정은 17분 수정 구간의 적합성을 검증할 후속 작업이다.

## C04: 저장과 화면 수명을 구분하고 기존 코드 변경을 줄인다

[C04](proposal-C04.md)은 각 차시의 수정량을 상한으로 제시하고 13·14주 한 차시에 한 동작 파일만 편집하도록 한다. 11주 시연 8분도 문자열 10·JSON 12·폼 12·origin 8·비교 8·복구 5·인계 5분으로 기존 강의 안에서 재배분했다. ex06의 명시적 불러오기와 특강의 초기 복원, 브라우저 뒤로 가기 복원을 구분한 점이 좋다. 발표의 32명 상한과 초과 시 병행 활동도 계산 가능하다.

1~10주 대부분은 공통 4+16+7+3분 틀에 의존한다. 2-1의 새 저장소·remote·push·Pages, 4-1의 비교 두 개와 사이트 CSS 여덟 값 변경은 일반적인 세 줄 수정과 난도가 다르므로 차시별 보정이 필요하다. 9주 필수 네 구역에는 기존 rubric의 코드 인용·배운 내용·두 장 캡처를 얼마나 줄일지와 대체 배점이 완전히 고정되지 않았다. ‘평가 정합’의 방향은 분명하지만 구체적인 시험 시작본 목록은 다음 단계로 남아 있다.

구현 전에는 2-1·4-1·9-1의 활동별 시간과 9주 채점표를 확정한다. REST의 기존 파일 분리를 유지하므로 구현 비용은 C01·C02·C09보다 작다. 비교 시연이 저장 설명을 압박하는지는 이후 학생 리허설에서 확인하고 8분을 줄일 수 있다.

## C05: 저장 분산안의 객체 배열 연결을 보완해야 한다

[C05](proposal-C05.md)은 문자열 저장을 11-1로 옮기고 11-2를 JSON·폼에 쓴다. 12주 전용 시작본으로 11주 전체 방명록 구현을 요구하지 않으며, 12·13주 비교에서 REST 요청과 SPA 구성을 별개로 관찰하게 한다. 발표는 30명 상한과 초과 영상 채점 부담을 계산했다.

실제 ex05는 객체 배열을 JSON으로 저장하고 복원한 객체의 필드를 표시한다. 그런데 C05의 11-1은 객체·점 표기 후 문자열 저장이며 ex02·ex03을 시연·선택 중 어디에 둘지, ex05를 단일 객체로 바꿀지 정하지 않았다. 12주 학생이 표시 문장을 수정할 때도 객체 배열 접근이 필요하다. 저장 실습 분산의 이점은 있지만 선수 지식 연결이 C08의 명시적 객체 배열 시연보다 덜 구체적이다. 9주 문서 축소 뒤 SVG 배점을 무엇으로 옮기는지도 미정이다. 비교 자료 두 쌍과 최종 CRUD 특강은 각각 다른 시점의 데이터·입력 상태를 관리해야 한다.

구현 전에는 ex02·ex03의 지위와 ex05 자료형을 고정하고 12주 학생이 읽을 `items[i].name`의 최초 학습 위치를 표에 추가한다. 9주 배점과 비교본별 데이터 초기값도 정한다. 12주 15분 비교는 관찰 활동이며 학생 구현으로 부풀려 평가하지 않는다는 경계는 유지할 수 있다.

## C06: 14주 직접 검증을 우선하지만 필수 회귀 시간을 더 밝혀야 한다

[C06](proposal-C06.md)은 11-2와 14주 실습을 분 단위로 쪼개고 14주 PATCH·DELETE를 학생 작성으로 남긴다. 기존 다중 파일과 로드 순서를 보존하며 SPA는 같은 CRUD의 상태 비교로 제한했다. 새로고침 시 편집 키와 서버 데이터의 수명을 나누고 화면 밖에서 완료한 요청의 처리까지 계획했다.

14-2에는 PATCH 수정 12분, 수정·삭제·새로고침 회귀 확인 8분, 캡처·업로드 6분을 배정했다. 지정 글의 수정·삭제뿐 아니라 틀린 키와 서버 상태를 대조하는 활동을 누가 어떤 순서로 수행할지가 여전히 필요하다. 4주 이후 새 저장소·Pages를 실습 마지막 5분에 ‘시작’하고 미완료 시 10분을 밖으로 넘기는 방식은 수업 종료 시 상태가 학생마다 달라질 수 있다. 초보자 검증의 중심은 7·11·12·14주라서 4·5·9주 축소안의 확인이 상대적으로 약하다.

구현 전에는 14주 정상·틀린 키 확인을 두 차시에 나눠 빠짐없이 배치하고 업로드의 수업 내 완료 범위와 수업 밖 범위를 고정한다. 초보자 측정에는 9주 README도 넣어야 한다. SPA 8분을 줄일 때 수정·삭제 검증을 보존한다는 우선순위는 타당하다.

## C07: 정규·방학 연결은 명확하나 12주 폼 상태를 확정해야 한다

[C07](proposal-C07.md)은 정규 수강생과 특강 참여자의 출발점을 분리하고 방학 첫 단계에 F14 재현 진단을 둔다. 9주에는 기존 폼 동작을 관찰하고 14주 뒤에는 서버 상태를 다룬다는 시연본의 차이도 명시했다. 28명 현장 발표 상한과 전원 영상 전환은 수용 인원을 숨기지 않는다.

12주에는 ‘입력 폼과 표시 함수를 유지한 채 데이터 출처만 교체’하고 13주에 submit 틀을 추가한다고 한다. 기존 폼 submit을 12주에서 제거·비활성화할지, 연습 입력을 막을지의 사용자 동작 계약은 없다. 이 결정을 미루면 12주 읽기 전용의 결과와 남아 있는 로컬 입력 동작이 혼동될 수 있다. 9주 코드 인용은 필수로 유지하지만 실습표의 주소·기능 표·캡처·설명에 그 작성 부담이 뚜렷하지 않다. 15주 저장 문제를 실제 ex06 수준으로 바꾸는 지정 경로도 C01·C02·C08보다 덜 구체적이다.

구현 전에는 12주 폼·기존 submit·저장 호출의 활성 여부를 표로 확정하고 13주 복구 부분을 표시한다. 9주 README와 15주 저장 문제의 시작본·할 일·채점 기준을 함께 고친다. 이는 계획의 빈칸이며 실제로 중복 POST가 발생했다고 판정한 것은 아니다.

## C08: 평가 설계는 구체적이나 일부 사실 근거와 시간표를 수정해야 한다

[C08](proposal-C08.md)은 9주 SVG 0.5점을 코드 출처 표시로 옮기고, 발표·구술·전환을 합쳐 26명 상한을 계산했다. 11주 ex04를 앞당기면서 ex02·ex03은 객체 배열 시연으로 남겨 선수 지식의 연결을 설명했다. 기말 다섯 문항을 8~10분으로 줄이는 계획도 직접 작성 범위와 연결된다.

현재 [기말 rubric](../../weeks/week15_final_exam/rubric.md)은 이미 ‘14주 레포트·발표 배점은 이 기말 채점표와 무관하다’고 명시한다. 이를 낡은 평가 문구로 보고 제거할 필요는 없다. 9주 표의 발표 78분 구성과 N>26의 대체 표는 각각 성립하지만 대체 표가 우선함을 학기 문서에서 분명히 해야 한다. 9-1에는 원래 다섯 항목과 동작 뒤 캡처 두 장을 남기면서 18분 수정·5분 오류 확인을 공통 적용한다. 문서 입력과 실제 동작 캡처의 하위 시간이 빠져 있다. 객체 배열을 시연으로 낮춘 만큼 12주 학생 필드 수정이 그 시연을 전제로 한다는 확인도 필요하다.

구현 전에는 사실 근거를 바로잡고 9주 캡처 두 장·코드 인용·배운 내용의 작성 시간을 따로 배정한다. 객체 배열의 학생 과제는 짧은 필드 읽기 확인으로 검증한다. 형식 검사·예외 처리를 제공한다는 이유로 학생이 모든 복원 코드를 이해했다고 평가해서는 안 된다.

## C09: 입력 검사와 저장 순서를 개선하지만 변경 지점이 넓다

[C09](proposal-C09.md)은 6주에 value·조건·안내를 직접 작성하고 7주 요소 생성은 제공 코드로 남긴다. 10주 배열·for와 DOM 조립을 분리하고, 11주 문자열 저장을 먼저 익힌 뒤 객체·JSON·폼으로 연결한다. 발표는 30명, 대체 방식은 50명 상한을 밝혔고 실습 검증을 빼서 시간을 맞추지 않도록 했다.

11-2에는 객체·점 표기 15분, JSON 15분, 폼 20분, 실패 10분이 들어간다. 실제 ex05의 객체 배열 표시를 어느 부분까지 제공하고 어느 부분을 설명할지 지정하지 않으면 다음 주 객체 목록 읽기로 넘어갈 때 새 개념이 한꺼번에 남는다. 6주 classList·함수 재사용을 선택으로 옮기므로 기존 6주 예제·제출·9주 홈 동작을 함께 바꿔야 한다. ‘8주 은행에서 다크 모드 의무 제거’라고 했지만 실제 w06 문항은 클릭·문장·횟수이며 다크 모드는 요구하지 않는다. 새 입력 검사 문항의 추가는 기존 문항 교체와 별개로 설계해야 한다. 13·14주 한 파일 통합도 주차 간 학생 수정 위치를 다시 잡는 작업이다.

구현 전에는 6주 필수/선택 예제와 중간 문항을 실제 파일 기준으로 매핑하고, 11주 ex05 제공 범위와 12주 객체 배열 표시 설명을 확정한다. C11을 폼 임시저장 시연본으로 바꾸는 경우 기존 완성본·walkthrough·12주 안내도 함께 바꿔야 한다. 이런 변경량을 고려해 실행 가능성 점수를 제한했다.

## 구현 전 조건과 향후 측정을 분리한다

지금 구현에 착수하기 전에 확정할 것은 학생이 받는 시작 파일, 직접 수정 위치, 제공 코드, 예제 분류, 자료형, 폼 활성 상태, 배포 묶음의 공용 CSS 경로, 평가 문항의 작성 범위다. 이는 파일과 계획만으로 확인할 수 있다. 발표 인원 N에 맞는 시간표와 영상 채점 부담도 학기 운영값으로 먼저 정한다.

시작본이 만들어진 뒤에는 강의자 또는 개발자가 복사·실행·주소·통신·실패 복구·문서 링크를 검증한다. 그 수행 시간은 숙련자 기록으로 남긴다. 공식 공개 API CRUD나 Pages에서 검증하지 않은 항목은 미완료로 표시한다.

초보 학생의 25분·30분 완료율, 도움 요청 횟수, 객체 배열 이해, README 작성 시간은 이후 학생 리허설이나 실제 수업에서 측정한다. 이 심사는 그 미래 자료를 꾸며 점수에 넣지 않았으며, 학생 실측을 지금 반드시 제출해야 하는 blocker로 바꾸지도 않았다. 선정안 구현이 끝나면 별도 독립 평가자 세 명의 최종 심사를 받아야 한다.
