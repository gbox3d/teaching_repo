# C01 구현 작업 지시서

## 공통 작업

[선정 결과](winner.md)와 [C01 상세안](proposal-C01.md)을 따른다. 각 주차 담당자는 자신의 주차 안의 모든 원고·예제·자산을 조사하고 실제 결함을 고친다. README·lab·walkthrough·examples 안내·한영 슬라이드의 시간표와 학생 활동을 맞춘다. 수업 시간 변경은 C01의 해당 차시 행을 기준으로 하고, 필수·시연·선택 예제를 구분한다.

학생 화면에는 제목·입력·버튼·결과와 짧은 상태만 둔다. 긴 설명은 README로 옮긴다. 1~6주 CSS 학습 예제는 자체 CSS를 유지한다. 7주 이후 방명록은 cdnjs W3.CSS 4.1.0을 사용한다. 기존 파일명과 주차 덱 ID는 유지한다.

예제는 직접 실행하고 문서의 기대 결과와 비교한다. 실제 실행하지 못한 외부 서비스·학생 실측은 실행했다고 기록하지 않는다. 노드 구문 검사만으로 동작 검증을 대신하지 않는다. 기존 시험의 빈 구현 부분은 학생 문제이므로 해답을 공개 파일에 채우지 않는다.

## 시간과 준비

일반 27차시는 60분 강의·시연과 30분 학생 실습이다. 8·15주 2차시와 9주 발표만 예외다. 3주부터 파일 배부와 새 저장소 준비는 사전 준비로, 업로드는 수업 뒤 정리로 분리한다. 강의 첫 5분에 준비 상태를 확인한다. Git 자체를 배우는 1~2주는 수업 안에서 수행한다.

11주 실습 캡처는 localhost에서 저장·복원한 결과를 인정한다. 다른 일반 주차도 30분 안의 동작 확인과 캡처를 우선하고 공개 업로드는 정리 단계로 안내한다. 12~14주 로컬 API 리허설과 실제 공용 서버의 브라우저 간 공유 확인을 구분한다.

## 주차 인계와 예외

- 7주 제공 JS·폼 ID·W3.CSS 전후 비교를 유지하고 9주 완성 웹 파일은 같은 내용으로 인계한다.
- 9주 Markdown 필수는 제목·목록·링크·그림·코드·표와 제공 SVG의 글자 변경이다. 직접 도형 좌표 작성과 Mermaid는 선택이다. 발표 75분은 30명까지 2분 시연+30초 전환으로 운영한다. 31명 이상은 사전 2분 시연 제출과 표본 시연·짧은 개인 설명으로 바꾸고 분반 인원에 맞는 시간 계산을 안내한다.
- 10주는 문자열 배열·고전 for·showList·splice만 필수로 두고 고급 배열은 특강으로 연결한다.
- 11주 ex04 문자열→ex05 JSON→ex06 폼 저장을 유지한다. ex07 탭 동기화는 참고이며 ex08 이후를 다시 만들지 않는다. 제공 방명록은 주차별 저장 키, 손상 JSON 안내, 해당 키만 삭제하는 복구를 갖춘다.
- 12주 ex01 about→ex02 help→ex03 GET, ex04 목록·ex05 HTTP 오류·ex06 통신 오류 순서다. 각 REST 예제에 README·requests.http를 둔다. 11주 객체 배열 방명록을 학생이 전부 구현했다고 쓰지 않는다. 로컬 저장본과 서버 조회본을 구분한다.
- 13·14주 완성 방명록의 동작은 guestbook.js 하나에 모으고 GET·POST·PATCH·DELETE 구역을 구분한다. 설정은 별도 제공 파일로 두어도 된다. 모든 준비 뒤 최초 GET을 실행하고 14주 지연 로딩 오류를 재현 조건과 함께 검증한다.
- 기말 w11은 폼 한 객체의 저장·불러오기·해당 키 삭제로 맞춘다. w14는 PATCH 또는 DELETE 한 요청 구현을 기본으로 하고 재조회·나머지 요청 틀은 제공한다. 기말 영역·총점과 정규 실습 범위의 정합성을 유지한다.

## API 설정 계약

12주 담당자가 제공 설정 패널과 파일의 기준을 먼저 만든다. 기본값은 로컬 연습용 URL·가상 공개 키·student01이다. 공용 API 주소·공개 키·book_id는 실행 중 입력하며 메모리에만 둔다. 새로고침 후 다시 입력하는 절차를 README에 적는다. .http는 같은 폴더의 .env 또는 요청 prompt를 사용한다. 실제 편집 키·서버 비밀 키를 추적 파일에 넣지 않는다.

설정 UI의 복잡도를 줄이고 기존 DOM·폼 API를 사용한다. 학생은 요청 URL·헤더·본문·응답 처리를 수정하며 설정 패널 재구현은 평가하지 않는다. 13·14주 담당자는 12주의 기준 파일과 설정 이름을 이어 쓴다. 공통 설정 요소를 추가하면서 각 예제의 독립 실행 경로를 깨뜨리지 않는다.

## SPA 특강 계약

`specials/hash_spa`는 MPA 비교→두 화면 전환→세 화면·hash 탐색→14주 CRUD 통합 순서의 폴더로 나눈다. 빈 hash는 홈, 알 수 없는 hash는 안내·홈 링크, 현재 메뉴는 aria-current로 표시한다. 화면을 숨겨도 DOM과 입력은 유지하고 이벤트는 한 번만 등록한다. 직접 진입·새로고침·뒤로·앞으로·키보드 포커스를 확인한다.

합치기 전 홈의 count 관련 ID·변수에 home 접두어를 붙여 방명록과 충돌하지 않게 한다. 기존 화면의 실제 HTML 경로는 MPA 비교본으로 보존한다. hash 경로에는 별도 서버 라우터가 필요하지 않으며 루트 아닌 프로젝트 하위 경로에서도 실행한다. REST 단계에는 .http를 둔다. 새 특강을 빌드 색인에 추가하는 일은 총괄 담당이다.
