[완성본](../../weeks/week07_form_input/examples/day2/web-week07/guestbook.html)의 `guestbook.js`는 그대로 사용한다. 13분 매핑 활동이 실제 초보 학생에게 충분한지는 별도 수업 관찰이 필요하다.

Node.js 정적 서버 `http://localhost:8111/`에서 별도 Chrome headless 컨텍스트를 사용했다. 7주 타임라인·변환 전 방명록·변환 후 방명록·9주 방명록을 각각 375px와 1280px로 실행해 8경우를 확인했다.

7주 ex04·ex05·완성본 JS는 현재도 동일하다. 작성자·시각·본문을 만드는 `createPost`와 `list.prepend(li)`를 공통으로 사용하므로 CSS 변환 전후의 동작이 달라지지 않는다. W3.CSS는 고정 cdnjs 4.1.0을 사용하며 별도 CSS에는 피드 배치 규칙이 있다. 추가 CSS를 공통 원본과 항상 같은 사본이라고 설명하지도 않는다.

## 8~10주와 기말 문제은행 인계

### 7→8: CSS 시험 범위를 유지한다

[중간 w07 문제](../../weeks/week08_midterm/examples/w07_form_line/README.md)는 CDN·클래스 적용만 평가하고 폼 JS를 제공한다. 현재 시험용 폼은 피드의 축약 비교 예제로서 작성 시각·최신순 생성 기능을 구현하는 문제는 아니다. 이 차이는 시험의 필수 범위를 늘리지 않는다. [채점표](../../weeks/week08_midterm/rubric.md)의 A4+B4+C5+D3+E4=20도 유지된다.

### 7→9: 현재 타임라인을 그대로 사용한다

7주와 [9주 완성본](../../weeks/week09_readme_presentation/examples/day2/web-week09/)의 홈 HTML·소개 HTML·홈 JS·방명록 HTML·방명록 JS·styles.css·프로필·shared/examples.css 8개가 SHA-256으로 일치한다. 이전 기준본의 결과를 재사용하지 않고 현재 파일로 다시 비교했다.

9주 README 예시는 새 글이 맨 위에 표시되고 작성자·작성 시각 아래에서 본문을 읽는다고 설명한다. 실제 동작과 캡처가 같다. 9주의 60+30 README 실습과 5+75+10 발표 운영, SVG 글자만 필수인 범위는 그대로다.

### 9→10: 배열 인덱스와 줄 순서를 비교하는 제공 틀로 전환한다

초기에는 문서가 방명록의 단순 확장처럼 설명했으나 실제 10주 화면은 작성 시각 없는 문자열을 등록순으로 표시했다. 현재 [9주 다음 수업 안내](../../weeks/week09_readme_presentation/README.md)와 [10주 README](../../weeks/week10_array_list/README.md), [실습지](../../weeks/week10_array_list/lab.md), [따라하기](../../weeks/week10_array_list/walkthrough.md), [예제 안내](../../weeks/week10_array_list/examples/README.md), 양쪽 한영 슬라이드에 전환을 명시했다.

10주 폴더 전체를 먼저 배부하고 학생의 홈·소개·기존 이미지 등을 옮긴다. 방명록 HTML·JS·보조 CSS는 10주 제공 파일을 사용한다. 따라서 등록 시 바꿀 `append` 세 줄은 **9주 createPost/prepend 코드가 아니라 10주 guestbook.start.js의 세 줄**이라는 점이 명확해졌다. 학생은 등록 2줄과 삭제 2줄만 작성한다.

10주 실제 완성본에 세 글을 입력했다. 등록순 student01→student02→student03, 가운데 삭제 뒤 student01·student03, `2개` 표시를 확인했다. 작성 시각 요소는 없으며 첫 줄과 `items[0]`를 대응한다. 375px 가로 넘침·pageerror도 없었다.

11주는 객체 저장, 12~14주는 서버 ID 내림차순 목록을 다룬다. 이 주차들에 7주 피드 DOM이 있다고 판정하지 않는다. 이번 연결 방식은 7~9주 CSS 응용 화면, 10주 문자열 배열 제공 틀, 이후 객체·REST 과정으로 구분된다. 최신 과목 [AGENTS](../../AGENTS.md)와 [README](../../README.md)에도 이 구분이 반영되었다.

### 15주 w09: 현재 9주 화면과 캡처로 맞췄다

초기 확인에서는 [기말 w09 배부본](../../weeks/week15_final_exam/examples/w09_readme_links/README.md)의 방명록 HTML·JS·CSS가 구형 목록이었다. 수정 뒤 방명록 HTML·JS·보조 CSS·홈 캡처·방명록 캡처 5개가 현재 9주 파일과 SHA-256으로 일치함을 확인했다.

기말 배부 경로의 실제 방명록도 375px에서 실행해 새 글이 맨 위, time 요소 2개, 가로 넘침·pageerror 없음까지 확인했다. 문제 설명도 최신순·작성자·시각·새로고침 초기화로 바뀌었다. 학생 과제는 기존처럼 제공 화면을 읽고 README의 제목·목록·링크를 채우는 범위이며, 새 타임라인 JS 작성이나 캡처 제작을 추가하지 않는다.

## 재현 기록과 한계

7주 현재 목록은 40파일(문서12·HTML11·JS8·CSS7·PNG2)이다. 한영 슬라이드는 각각 18장을 유지한다. 7주 문서 12개의 로컬·저장소 파일 링크 109개에서 누락 0건을 확인했다. 외부 사이트의 생존 여부나 모든 fragment를 검사한 수치는 아니다.

검사 스크립트와 실행 자료는 Windows 임시 폴더에 두었다.

- `followup-inventory.mjs`, `followup-handoff.mjs`: 파일·덱 수, 현재 주차 간 해시 비교
- `followup-learning-links.mjs`: 문서 대상 파일 검사
- `followup-learning-browser.mjs`, `followup-learning-browser.json`: 7·9주 8경우 실행
- `followup-week10-browser.mjs`: 등록순·가운데 삭제 확인
- `followup-week15-browser.mjs`: 기말 제공본·캡처 동일성 및 실제 실행
- `followup-timeline-375.png`, `followup-guestbook-375.png`: 직접 열어 본 실행 캡처

`padding-block` 비교는 브라우저에 임시 스타일을 적용했으며 교재 CSS를 저장·변경하지 않았다. 7주 방명록 JS의 현재 SHA-256은 `135eafc7ea892e73e21e8e3ab0f671b7cc03419cbe5374825a4e5a16b056b578`이다.

학생 수행 시간, GitHub Pages 새 게시, 공용 API 쓰기, 다른 기기 공유는 이번 재심사에서 측정하지 않았다. 전체 빌드·덱 레이아웃·자동 시험을 이 심사자가 다시 수행한 것으로 표시하지 않는다. 위 점수는 명시한 현재 변경 범위의 학습·문서 평가다.
