# 11주 구현·검증 기록

2026-11-18에 C01의 11-1·11-2와 구현 작업 지시서를 적용했다. 변경 범위는 `weeks/week11_object_localstorage/`와 이 보고서다. 커밋·푸시는 하지 않았다.

## 수업 범위와 시간

두 차시 모두 강의·시연 60분과 실습 30분을 유지했다. 파일 배부와 서버 준비는 수업 전, 공개 업로드는 수업 후로 구분했다.

| 차시 | 강의·시연 | 학생 실습 | 필수 결과 |
|---|---|---|---|
| 11-1 | 실행 확인 10, 객체 15, 객체 배열 15, 목록 필드 15, 안내 5분 | ex01 속성 8, ex02 인덱스 8, ex03 표시 필드 9, 결과 확인 5분 | 객체 필드와 인덱스 구별 |
| 11-2 | 문자열 10, JSON 15, 폼 복원 15, 저장 범위 10, 검증 5, 안내 5분 | ex04 8, ex05 8, ex06 11, 캡처 3분 | ex06 저장·새로고침·불러오기·키 삭제와 복원 화면 |

전체 객체 배열 방명록은 강의자 제공 시연본이며 12주 인계 자료다. 학생의 필수 산출물은 ex06 폼 복원이다. 오류 처리·형식 검사·복구 코드는 제공 범위로 명시했다. ex07은 참고이며 고급 배열은 별도 특강이다. ex08 이후 예제는 만들지 않았다.

## 저장 시연본 수정과 인계

기존 초기화는 `JSON.parse(localStorage.getItem('guestbook')) || []`여서 손상 JSON이 있으면 이벤트 연결 전에 실행이 중단됐다. `week11-guestbook-items` 키와 제공 `loadList()`로 바꾸고, JSON 및 배열 필드가 올바르지 않으면 안내를 표시하도록 했다. 전체 지우기는 이 키 하나만 지우며 기본 실습 키와 이전 `guestbook` 키를 보존한다. `localStorage.clear()`는 사용하지 않았다.

11주 필수 실습에 새 복구 기능 구현을 추가하지 않았다. 제공 초기화·복구 설명은 README·따라하기·한영 슬라이드에 짧게 남겼다. 초기화 뒤에는 이름·메시지를 다시 입력한다.

수정한 `guestbook.html`·`guestbook.js`의 브라우저 확인 후 총괄에 인계했다. 12주 담당이 이를 `guestbook.local.html`·`guestbook.local.js`로 보관했다는 통지를 받았다. 이후 두 인계 파일은 추가로 변경하지 않았다. 12주 서버 조회본과 로컬 보관본의 구분, 로컬 데이터의 자동 이관·삭제 없음, 다른 origin에서는 재입력이 필요함을 원고에 적었다.

## 실제 브라우저 검증

2026-11-18에 `http://localhost:8111`에서 Playwright의 설치된 Chrome을 headless로 실행했다. 별도 브라우저 컨텍스트에서 검사하여 사용자 기존 저장 데이터는 변경하지 않았다. 테스트용 보존 키와 이전 키는 그 컨텍스트 안에서 만들었다.

| 대상 | 실행한 조작 | 관찰 결과 |
|---|---|---|
| ex01 | 이름 입력·이름 적용, 없는 속성 표시 | 입력 이름과 `undefined`가 화면에 표시됨 |
| ex02 | 원본 실행 후 JS 응답을 시험 중에만 인덱스 0→1로 교체 | 버튼 결과가 하늘→바다로 바뀜, 디스크 예제는 원본 유지 |
| ex03 | 두 목록 조회 | 각 2개, 첫 목록 `[object Object]`, 둘째 목록 이름·메시지·날짜 |
| ex04 | 문자열 저장·입력 변경·새로고침·불러오기, 빈 문자열 저장, 삭제·불러오기 | 저장 값 유지, 빈 문자열 `""`와 키 없음 `null` 구분, 다른 키 유지 |
| ex05 | JSON 저장·원문 조회·복원·새로고침, 빈 문자열·`{`·`[null]`·`{}` 주입, 삭제 | 두 필드 목록 복원, JSON 오류와 형식 오류 안내, 해당 키만 삭제 |
| ex06 | 저장·입력 변경·불러오기·새로고침·불러오기·삭제, 빈 입력, 손상 값·잘못된 형식 | 자동 복원 없이 버튼으로 복원, 삭제 후 값 없음, 오류 때 현재 입력 유지 |
| ex06 접근성 | 이름 라벨 클릭과 키보드 입력 | 이름 칸에 포커스가 이동하고 입력됨 |
| origin | 같은 컨텍스트에서 `127.0.0.1:8111` 열기 | localhost에서 저장한 키가 보이지 않음 |
| ex07 | 같은 origin 두 탭에서 저장·삭제 | 다른 탭에 반영, 값을 바꾼 탭에는 storage 이벤트 결과 없음 |
| 제공 방명록 | 손상 JSON·객체·null 행·날짜 없는 행, 안내·전체 지우기 | 화면과 버튼 유지, 대상 키만 삭제, 다른 키와 이전 `guestbook` 보존 |
| 제공 방명록 | 빈 입력, 한글 글 3개, 가운데 삭제, 새로고침, 전체 지우기 | 입력 거절·3→2→0개 정상, 삭제 결과 유지 |
| 텍스트 출력 | `<b>태그 그대로</b>` 저장·표시 | 문자열 그대로 표시되고 b 요소가 생성되지 않음 |
| 홈 | 인사 바꾸기·다크 모드 | 클릭 2회와 dark 클래스 확인 |
| 전체 10 HTML | 375px·1280px 직접 주소 열기, 이미지 로딩 | 모두 HTTP 200, 가로 넘침 없음, 이미지 정상 |

브라우저 pageerror 0건, requestfailed 0건이다. ex06 복원 화면과 제공 방명록의 375px 캡처를 직접 열어 입력·결과·버튼 배치를 확인했다. 공개 Pages 배포나 실제 학생의 수행 시간을 검증한 결과로 해석하지 않는다.

## 원고·코드·문체 검사

- 주차 내부·외부로 이어지는 상대 파일·앵커 138개를 검사했고 끊어진 대상이 없었다. 외부 HTTP 링크의 전체 생존 검사는 수행하지 않았다.
- `walkthrough.md`의 `guestbook.html`·`guestbook.js` 전문을 실제 파일과 문자열 단위로 비교하여 일치함을 확인했다.
- 한영 슬라이드는 각각 기존 16장을 유지했다. ex01~ex06 순서, 실습 시간, ex06 캡처, 로컬 시연본·12주 인계, ex07·배열 특강의 제외 범위가 같다.
- 주차 JavaScript 9개에 `node --check`를 실행했다.
- `korean-copy-style`의 UI 문구 검사와 문서 검사에 주차 폴더 전체를 전달하여 종료 코드 0을 확인했다.

브라우저 검사 스크립트·결과 JSON·375px 검증 캡처는 Windows 임시 폴더의 `week11-check.mjs`, `week11-browser-results.json`, `week11-ex06-375.png`, `week11-guestbook-375.png`에 두었다. 기존 수업 캡처를 검증 캡처로 덮어쓰지 않았다.

## 남은 확인

초보 학생의 30분 수행 시간은 실측하지 않았다. 공개 사이트·다른 기기·공용 REST API는 11주 검증 범위가 아니다. 저장 제한·용량 초과와 모든 브라우저 조합은 별도로 시험하지 않았다. 전체 빌드·공통 테스트·슬라이드 렌더링 통합 검증과 독립 심사는 총괄 단계에서 수행한다.
