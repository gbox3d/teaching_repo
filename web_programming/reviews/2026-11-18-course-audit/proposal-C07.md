# C07: 정규 방명록 완성과 방학 SPA 연구를 잇는 2단계 수업

강의자의 수업 독립 기획안. 2026-11-18. 대표 원고와 예제를 확인한 계획이며 실행 검증 결과는 아니다. 경로는 `web_programming/` 기준이다.

## 결정 기록

결정: 정규 15주는 다중 페이지 방명록을 완성한다. 9주 1차시에 SPA 비교 시연 10분을 두고, 직접 전환은 기말 이후 선택 연결 특강에서 수행한다.
근거: 정규 과정의 도달점은 화면·이벤트·배열·저장·HTTP를 구분해 고치는 능력이다. SPA를 필수 구현하면 주소 처리와 화면 상태를 배우는 동안 기존 DOM·저장·REST 연습을 줄여야 한다.
대안: 11주 이후 정규 전환은 저장과 화면 이동의 관계를 바로 실험할 수 있지만, ex06만 마친 학생에게 배열 완성본과 라우팅을 동시에 해석하게 한다. 7주 전환은 폼 동작조차 제공 코드인 시점이므로 채택하지 않는다.
재검토: 다음 학기 정규 편입은 초보 학생이 방학 연결 특강의 전환 단계를 지원 없이 재현한 기록과, 정규에서 줄일 학습 목표를 확보한 뒤 판단한다.
두 단계는 같은 방명록을 사용한다. 특강 불참 학생도 정규 수업을 끝낼 수 있고, 참여 학생은 서버·화면 전환·상태 보존을 따로 실험한 뒤 결합한다.

## 일반 차시는 강의 60분과 실습 30분으로 운영한다

강의 60분은 이전 결과 확인 5분, 개념 20분, 예측과 시연 25분, 오류 관찰·실습 인계 10분이다. 학생의 긴 코드 입력을 강의 시간에 숨겨 넣지 않는다. 9주 1차시만 시연 중 10분을 SPA 비교에 쓴다.
실습 30분은 준비 확인 4분, 아래 표의 수정 17분, 실행·오류 수정 6분, 캡처·저장 3분이다. 차시마다 수정 파일 1~2개, 필수 동작 하나를 목표로 하고 완성 틀과 수정 위치를 배부한다.
3주 이후 다운로드·복사·새 저장소 생성은 주당 수업 전 10분, push·Pages 확인은 수업 후 10분의 예상 부담으로 별도 공지한다. 첫날 시작 파일이 없으면 준비된 복사본을 지급한다. 1·2주는 준비·배포 자체가 학습이므로 수업 안에 포함한다.
일반 제출은 주별 화면 1장이다. 1주 화면·Git 기록 2장, 2주 현행 4장, 8·15주 시험 제출, 9주 README·발표는 예외다. Pages 지연은 로컬 화면과 Commits 증거를 인정하고 다음 수업에서 확인한다.

## 시작 파일과 다음 주 인계

11주 F11의 저장 키는 주차·예제명을 포함하게 고치고 손상 JSON은 안내 후 빈 목록으로 시작하는 제공 코드를 둔다. ex06의 방어 코드와 try/catch는 11주 직접 작성 대상이 아니다. 12주는 로컬 글이 서버로 자동 이관되지 않으며, 입력 폼과 표시 함수를 유지한 채 데이터 출처만 교체한다.
13·14주는 기존 분리 파일을 유지한다. 공통 문서에 정규 예외를 명시하고 `config→guestbook→submit→actions→delete→edit`의 classic defer 순서를 제공한다. 학생은 해당 차시 파일만 고친다. projects.* 등 추가 기능은 필수 복사본에서 제외하고 선택 자료로 보존한다.

## SPA는 비교 시연 후 방학에 구현한다

9주 비교는 `specials/spa_bridge/examples/01_compare/`에 신규 제공한다. 7주 방명록과 같은 홈·소개·폼을 다중 페이지와 단일 문서로 나란히 실행해 메뉴 이동 때 Document 요청과 입력 유지가 달라지는 것을 보여 준다. 브라우저의 뒤로 이동 복원은 별도 현상이며 항상 초기화된다고 단정하지 않는다.
정규 10~14주는 이 시연 파일을 복사하지 않는다. 10주는 배열·목록, 11주는 저장, 12~14주는 REST가 필수 실습 시간을 사용한다. 시연 코드는 읽기 참고이며 라우팅 코드·SPA 용어·상태 비교는 시험에 넣지 않는다.
방학 첫 단계는 F14 재현 진단이다. REST가 막히면 12~14주 해당 예제를 보강하고, 배열 심화는 필요할 때 기존 array_advanced로 연결한다. 정규 미참여자도 같은 진단과 보강으로 진입한다.
전환은 `02_sections/`에서 세 문서를 index.html의 고유 id를 가진 section으로 합치고, `03_hash/`에서 `<a href="#home">`·`#about`·`#guestbook`을 연결한다. 별도 router.js는 함수·if·location.hash·hashchange·hidden만 사용한다.
초기 실행과 hashchange에서 같은 화면 선택 함수를 호출한다. 해시가 없거나 알 수 없으면 replaceState로 #home을 정규화한 뒤 함수를 직접 호출한다. replaceState가 hashchange를 일으킨다고 가정하지 않는다.
이동마다 주소·보이는 section·선택 메뉴의 aria-current·문서 제목을 맞춘다. 홈→소개→방명록→뒤로→앞으로를 검사하고, 해시 직접 주소와 새로고침도 같은 화면을 연다. 표시할 제목으로 초점을 옮기며 Tab·Enter로 메뉴와 폼을 검사한다.
Pages는 `/web-spa-study/#guestbook`을 사용한다. `/guestbook` 가상 경로와 History API 라우터는 연구 후속 주제로 미룬다. CSS·JS·그림은 저장소 경로 아래의 상대 주소로 요청한다. 기존 정규 3페이지 주소는 그대로 남기고 새 특강 주소를 README에서 연결한다.
`04_state/`에서 화면 이동은 section을 숨기기만 하므로 작성 중 입력·메모리 목록·편집 키를 유지한다. 새로고침은 메모리를 초기화하고 목록은 서버 GET으로 복원한다. 편집 키는 다시 입력하며 URL·localStorage에 저장하지 않는다.
초안 보존은 다음 실험에서 이름·메시지만 localStorage에 저장한다. 저장 키는 특강·예제별로 정하며 같은 사용자 Pages 도메인의 프로젝트 경로가 저장 공간을 격리하지 않음을 확인한다. localhost의 호스트·포트 또는 HTTPS로 바뀌면 데이터가 자동 이동하지 않는다.

## 시험과 방학 연구의 경계

8주·9주·15주 평가 위치와 학기 배점은 유지한다. 중간은 HTML·CSS·기초 JS·click과 W3.CSS 수정만 직접 작성하게 하고, 7주 submit 검사는 제공한다. 기말도 제공 fetch·오류 처리 틀에서 정규 실습 때 수정한 영역만 묻는다.
9주 README 필수는 제목·공개 링크·기능 표·캡처·코드 인용이다. SVG 직접 작성·Mermaid는 선택으로 옮겨 30분을 확보한다. SPA 설명은 README 점수에 요구하지 않으며 사이트 시연 기준도 다중 페이지로 유지한다.
발표는 2분 발표+30초 전환으로 70분에 28명까지 배정한다. 초과 분반은 모든 학생이 동일한 2분 영상을 비공개 제출하고 같은 루브릭으로 평가한다. 9주 2차시는 70분 동안 모둠별 상호 시연·피드백을 병행한다. 영상 준비 예상 15분과 강의자 검토 2N분을 사전 공지한다.
공용 API 장애는 검증한 로컬 연습 API로 전환하고 같은 .http·상태·본문으로 평가한다. 대체 서버 준비도 실패하면 해당 통신 문항을 재평가한다. 장애를 학생 코드 오류로 채점하지 않는다. 문제은행·시작 파일·루브릭·한영 시험 안내를 함께 바꾼다.
방학 spa_bridge는 차시 수를 제한하지 않는다. 이후 Supabase 구축·홈 IoT 상태 조회·지도 화면 전환·신시사이저 음원 지속 중 한 주제로 이어 간다. 모든 학생에게 모든 특강을 요구하지 않는다. 가설·고정/변경 조건·관찰·해석·재현 절차를 결과물로 남긴다.

## 구현 순서와 수정 책임

1. 통합 담당자가 공통 README·weeks 색인에서 60+30, 저장소 복사, 캡처 예외, JS 분리 예외를 먼저 확정한다. 기존 폴더 이름과 공개 링크는 보존한다.
2. 3~7주 담당자가 제한된 필수 예제·제공 코드 경계를 정하고 F7을 기준 화면으로 고정한다. 4주 나머지 비교 예제는 시연·선택, 5주 var·날짜·실행 시점 비교는 필수에서 분리한다.
3. 9~11주 담당자가 F7→F9→F10의 W3.CSS를 인계하고 ex06 제출과 F11 제공을 분리한다. 11주 고급 저장 ex07은 특강 참고 및 시험 제외 표시를 맞춘다.
4. 12~14주 담당자가 접속/about/help→CRUD의 단계 폴더와 실행 가능한 requests.http를 점검한다. baseUrl·공개 헤더·bookId 설정, Send Request, 200/201/204와 응답 형태를 README에 적는다. 편집 키는 REST Client 런타임 입력이나 추적 제외 로컬 환경에서만 받는다.
5. 평가 담당자가 8·9·15주 문제은행과 루브릭을 수정하고, 특강 담당자가 비교 시연과 spa_bridge를 제작한다. 서버 계정·SQL·SDK·로그인 구현은 정규 자료에 넣지 않는다. book_id는 구분값이며 권한 증명이 아니다.
6. 각 주 담당자는 README·slides.md·slides_en.md·walkthrough·lab·examples/README의 시간·링크·전체 코드 블록을 함께 맞춘다. 용어표의 한국어·English·中文을 유지하고 미수정 영문 슬라이드를 남기지 않는다. 전수 조사 목록과 실제 수정 파일은 구현 단계에 기록한다.

시연용 7주 버전과 연구용 14주 버전의 유지 비용이 생긴다. 화면·탐색 검사를 공통 항목으로 두고 각 자료에 출발 주차와 데이터 저장 위치를 적어 혼동을 막는다.
