# 웹프로그래밍 수업 구성 9안 비교 기준

## 목표

입문 학생이 HTML·CSS·JavaScript 기초를 익힌 뒤 방명록을 브라우저 저장과 공용 REST API로 확장한다. 7주차의 W3.CSS 변환 이후 화면과 코드가 끊기지 않도록 전체 차시의 예제와 학습자료를 조사·갱신한다. SPA 도입 위치와 분량도 다시 판단한다.

## 사용자 요구와 현재 상태

- 대상은 프로그래밍 경험이 거의 없는 대학생이다. 15주, 주 2회, 회당 90분이다. 사용자 수업 모델은 강의 60분과 실습 30분이다. 현재 자료에는 7·11주에 이 모델이 적용되어 있고 나머지 주차는 이전 시간표가 섞여 있다. 각 안에서 적용 범위를 명시한다.
- 7주차는 W3.CSS 소개와 기존 방명록의 변환을 다룬다. W3.CSS는 cdnjs의 버전 고정 CDN을 사용한다. HTML에 장황한 설명을 넣지 않는다.
- 12주에는 REST 호출을 배운다. 강의자가 공용 Supabase API를 준비하고 학생은 계정 없이 book_id 태그로 데이터를 구분한다. 수정·삭제에는 편집 키가 필요하다. 자격증명은 추적 파일에 기록하지 않는다.
- 13주는 저장, 14주는 수정·삭제 실습으로 개편 중이다. 14주를 레포트 검사주로 되돌리지 않는다. 레포트는 별도 과제다.
- 11주 저장 기초는 문자열 저장·불러오기·지우기, JSON 변환, 폼 저장 순서다. 배열 심화는 별도 보강 특강이다.
- 현재 8주 중간 실기, 9주 README·1차 발표, 15주 기말 실기로 편성되어 있다. 변경을 제안하면 목적·수업 손익·수정 범위를 명시한다.
- 특강은 분량 제한이 없는 방학 연구 수업용이다. 현재 배열 심화, Supabase 구축, 홈 IoT HTTP, 지도, 신시사이저가 있다.
- REST 예제에는 VS Code REST Client용 실행 가능한 .http 파일을 둔다. 접속/about/help 확인을 CRUD보다 먼저 다룬다.
- SPA는 도입 필요성과 시점부터 검토한다. 프레임워크·번들러를 전제하지 않는다. GitHub Pages에서 직접 주소·새로고침·뒤로/앞으로가 동작하는지 설명해야 한다.

## 기획자 작업

기획자 9명은 다른 안을 읽지 않고 저장소 원고와 예제를 확인해 독립안을 작성한다. 서로 다른 관점은 탐색의 출발점이며 특정 결론을 강제하지 않는다. 각 안에는 아래 내용을 포함한다.

1. 현행 자료에서 확인한 구체적인 문제와 유지할 내용, 파일 근거.
2. 15주 전체의 1·2차시 목표, 강의·실습 분량, 학생 결과물 표.
3. 방명록의 주차별 시작 파일과 다음 주로 넘길 파일·기능.
4. SPA 도입 위치와 구현 범위, 도입하지 않는 정규 차시의 이유.
5. 예제 폴더·시험·특강·한영 자료의 수정 범위와 구현 순서.
6. 초보 학생 관점의 검증 과정, 예상 실패 사례, 대안과 한계.

코드와 기존 교재는 수정하지 않는다. 담당 proposal-CNN.md만 작성한다. 다른 과목과 tools/wleno 등의 동시 작업은 범위 밖이다.

## 독립 심사

총괄 디렉터와 별도 심사자 2명이 모든 안을 심사한다. 총점은 각각 10점이다. 점수를 평균 내어 결함을 숨기지 않도록 세 명 모두 8점 이상인 안만 후보가 된다. 필수 조건 위반이나 실습을 재현할 수 없는 결함이 있으면 점수와 별개로 탈락 또는 보완이다.

| 항목 | 배점 | 확인 근거 |
|---|---:|---|
| 학습 순서와 선수 지식 | 2 | 처음 소개되는 개념과 실제 코드 사용 순서 |
| 차시 분량과 학생 활동 | 2 | 90분 안의 강의·실습, 구체적인 학생 수정 |
| SPA 도입 판단 | 1.5 | 필요성, 시점, 정적 호스팅·탐색 동작 |
| 기술 정확성 | 1.5 | W3.CSS·DOM·저장·REST·키 구분 |
| 재현과 검증 | 1 | 실행 절차·기대 결과·실패 확인 |
| 예제·교재·평가 일관성 | 1 | 한영 자료와 과제·시험 범위 연결 |
| 실행 가능성 | 1 | 유지할 파일, 변경량, 주차별 담당 범위 |

통과안의 세 심사 점수 평균으로 순위를 정한다. 동점이면 최저 심사 점수가 높은 안, 그다음 학생 구현 부담이 작은 안을 우선한다. 전부 미달이면 지적 사항을 반영해 다시 심사한다. 8점 미만 안을 통과시키지 않는다.

## 구현 후 통과 기준

선정안을 주차별 별도 에이전트가 구현한다. 예제와 차시별 조사 범위를 기록하고, 공통 빌드·테스트·브라우저 동작과 문서 링크를 검증한다. 구현에 직접 참여하지 않은 평가·관리 에이전트 3명이 최종 결과를 심사하여 각각 8/10 이상일 때 완료한다.
