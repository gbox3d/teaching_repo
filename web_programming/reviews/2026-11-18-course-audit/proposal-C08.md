# C08 수행평가와 프로젝트 인계 중심 수업안

강의자의 15주 수업은 방명록을 단계별로 확장하되, 9주를 자기 결과물을 다른 사람이 실행할 수 있게 설명하는 프로젝트 점검 주로 유지한다.
결정: 7주 W3.CSS, 8주 중간 실기, 9주 README·발표, 11주 저장 기초, 12주 REST 읽기, 13주 등록, 14주 수정·삭제, 15주 기말 실기의 순서를 유지한다.
근거: 9주 발표는 중간시험과 달리 여러 파일을 연결한 사이트의 실행·설명·전달 능력을 확인한다. 문서 장식과 새 기능의 개수가 이 목적을 대신하지 않도록 줄인다.
대안: 9주를 SPA 구현으로 바꾸면 화면 전환을 직접 배울 수 있지만 개인 코드와 제공 코드의 구분, 배포 확인, 프로젝트 설명 활동이 사라진다.
재검토: 9주 축소 실습과 11주 저장 실습을 초보 학생이 실제로 완료하는지 확인한 뒤 SPA 필수 편성을 다시 판단한다. 이 안에서는 비교 시연과 선택 특강으로 둔다.

## 9주 평가와 SPA의 범위

README는 공개 주소, 페이지 표, 기능과 직접 바꾼 코드, 동작 후 그림 두 장, 배운 내용의 다섯 항목을 유지한다. SVG·Mermaid 제작은 선택으로 돌려 문서 렌더링보다 실행 재현에 시간을 쓴다.
발표 5점은 공개 주소 1·페이지 이동 1·버튼/폼 시연 2·시간/구술 1을 유지한다. README 5점 중 SVG 0.5점을 제공 코드와 학생 수정 코드의 출처 표시 0.5점으로 옮긴다. 추가 기능은 가점하지 않는다.
발표는 1인 3분으로 26명까지 78분이다. N>26이면 전원 2분 시연 영상을 제출하고 마지막 20초에 본인 수정 코드와 파일을 설명한다. 수업은 준비 5·대표 8명 시연/구술 24·소그룹 재현 40·피드백 16·마감 5분으로 운영하며 채점자는 전원 영상을 같은 기준으로 본다.
영상 방식은 학생 준비 10~15분과 교원 검토 약 3N분을 수업 밖에 추가한다. 장비가 없으면 수업 PC에서 녹화할 시간을 별도로 배정한다. 짝 평가는 점수에 넣지 않으며 발표 방식·기한은 개강 때 인원에 맞춰 공지한다.
SPA 비교는 9주 첫 차시 강의 10분에 동일한 입력을 둔 다중 페이지와 제공 해시 예제를 실행한다. 문서 요청과 화면 전환, 주소와 상태의 차이를 관찰하며 학생 작성·평가 대상으로 넣지 않는다.
선택 특강 `specials/vanilla_spa/`를 신설해 11주 뒤 P11 복사본을 전환한다. 기존 세 HTML은 정규 과정에 남고 특강은 index.html의 세 section과 app.js로 옮긴다. 12~14주를 마친 뒤 REST 연결을 확장한다.
특강의 첫 단계는 `#home`·`#about`·`#guestbook`, `location.hash`, `hashchange`, `hidden`, 함수·if만 쓴다. 프레임워크·라우터 패키지·번들러·History API를 추가하지 않는다.
해시가 없으면 홈을 보이고, 알 수 없는 해시이면 `location.replace('#home')`으로 주소를 정정한 뒤 짧은 안내를 보인다. 메뉴·초기 실행·hashchange가 같은 표시 함수를 호출하며 표시 제목·현재 메뉴·aria-current를 함께 갱신한다.
직접 주소 `/web-spa/#guestbook`, 새 탭, 새로고침은 방명록을 열어야 한다. 뒤로/앞으로도 주소와 화면이 일치해야 한다. Pages의 실제 index.html과 상대 자산 경로를 사용하며 `/guestbook` 가상 경로는 만들지 않는다.
화면 전환은 DOM을 숨기기만 하므로 입력·배열을 유지한다. 새로고침은 메모리를 지우고 별도 저장 코드가 복원한다. 편집 키는 메모리에만 두며 새로고침 뒤 다시 입력한다. section id 중복·Tab 이동·제목 포커스를 검증한다.
정규 과정에서 SPA 구현을 제외하는 손실은 라우팅 구현 경험이다. 대신 저장·통신 실패·수정 권한을 반복 확인할 시간을 확보한다. 같은 Pages 도메인의 여러 저장소는 저장 공간을 공유할 수 있어 주차·예제별 key를 제공한다.

## 수정 순서와 검증 계획

1. 전체 색인·30차시 시간·제출 예외·파일 인계를 확정하고 4·5·9주 비교 예제에 필수/시연/선택을 표시한다. 날짜·서버 원리 확장은 5주 선택으로 둔다.
2. 7→9→10→11→12~14 완성본의 스타일·id·파일 로딩을 연결하고 학생 수정 표시와 제공 코드 범위를 맞춘다. 새 예제의 긴 설명은 HTML 대신 README에 둔다.
3. 모든 주차 README·slides.md·slides_en.md·walkthrough·lab·examples/README와 코드 부록을 대조한다. 영문 슬라이드도 시간·예제 번호·평가 범위를 함께 바꾸며 번역만 뒤로 미루지 않는다.
   특강 색인에는 SPA 선수 지식과 정규 시험 제외를 기록한다. 기존 배열 심화·Supabase·IoT·지도·신시사이저의 범위는 유지하며 SPA 특강도 완료 시간을 제한하지 않는다.
4. 8주 문제은행의 7주 문항은 CSS 변경만 평가한다. 15주 저장 문항은 ex06 수준으로, REST는 수업에서 채운 요청·필드 부분만 평가한다. 선택 배열·ex07·SVG·Mermaid·SPA는 시험에서 제외한다.
5. 기말 다섯 문항은 각각 8~10분 목표로 리허설해 60분 안의 재확인 시간을 확보한다. 서버 장애 때는 동일 계약의 강의자 로컬 서버로 전환하고 지연은 기록해 보충 시간을 준다. 실행 불가 부분은 별도 재평가한다.
6. REST 단계별 폴더마다 .http를 제공하고 about/help→GET→POST→PATCH/DELETE 순서를 유지한다. baseUrl·공개 헤더·로컬 값과 실제 비밀을 구분하며 편집 키는 프롬프트나 추적하지 않는 로컬 환경에서 받는다.
7. API는 교원이 준비하고 학생은 book_id로 데이터만 구분한다. 공개 API 키·book_id는 편집 권한이 아니다. 학생 계정·SQL·SDK·로그인 구현은 추가하지 않으며 캡처에 편집 키를 노출하지 않는다.
8. 초보 학생에게 시작 묶음을 배부해 7주 변환, 9주 README, 11주 ex06, 12주 GET, 14주 수정·삭제를 관찰한다. 준비·수정·오류·도움 요청·증거 저장 시간을 별도로 기록하고 30분 초과 활동을 줄인다.
9. 자동 검사는 링크·한영 예제 번호·시간 합계·W3 CDN·중복 id·비밀값 부재·코드 부록 일치를 확인한다. 실제 브라우저에서는 375px, 페이지 왕복, 새로고침, 직접 URL, Console·Network를 확인한다.
10. 실패 검증은 저장값 없음/빈 문자열/깨진 JSON, origin 변경, GET 빈 배열·Offline, POST 연속 클릭·입력 보존, 잘못된 편집 키, 가운데 ID 삭제, PATCH 재조회, DELETE 204 무파싱을 포함한다. SPA 탐색 검사는 별도 특강에서 수행한다.

이 안의 약점은 정규 SPA 작성 경험을 제공하지 못하고 주간 저장소 운영·영상 발표에 수업 밖 시간이 든다는 점이다. 초보 학생 리허설을 아직 하지 않아 18분 수정량은 가정이며, 실제 측정에서 실패하면 필수 수정 항목부터 줄인다.
14주는 두 차시 모두 수정·삭제 구현으로 유지한다. 별도 레포트 과제는 별도 안내·기한으로 운영하고 이 주차 실습 시간이나 기말 점수에 혼합하지 않는다. 현재 제출 범위는 이 기획안 한 파일이며 기존 교재·코드는 변경하지 않았다.
