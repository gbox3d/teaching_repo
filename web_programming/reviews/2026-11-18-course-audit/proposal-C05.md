# C05: REST의 데이터 갱신을 익힌 뒤 SPA를 비교한다

작성일: 2026-11-18. 대상: 강의자의 웹프로그래밍 15주 수업. 이 문서는 기획안이며 기존 교재·코드를 변경하거나 실행 검증한 기록이 아니다.

## 결정 기록

- 결정: 정규 결과물은 다중 페이지 방명록을 유지한다. 12주 2차시에 SPA 비교 15분, 13주 2차시에 POST와 연결하는 복습 5분을 넣는다. 전체 SPA 구현은 14주 이후 선택 특강으로 편성한다.
- 근거: 현재 방명록도 fetch 응답으로 목록만 바꾼다. REST는 데이터 요청 방식이고 SPA는 문서 이동 없이 화면을 전환하는 구성이라는 차이를 같은 방명록에서 관찰할 수 있다. 조회·등록·실패 복구를 배우는 시기에 탐색 구현까지 학생 과제로 추가하지 않는다.
- 대안: 13주에 전체 사이트를 해시 SPA로 전환하면 입력 상태 유지까지 직접 구현할 수 있으나 POST·대기·재조회와 동시에 배운다. 본안은 이 구현 경험을 특강으로 옮긴다.
- 재검토: 12주 조회와 13주 등록을 초보 학생이 각각 30분 안에 마친다는 리허설 근거가 생기면 다음 학기에 SPA 필수 구현을 다시 판단한다.

## SPA 비교와 선택 특강의 실행 계약

정규 비교 자료는 신설 `specials/vanilla_spa/examples/01-read/{mpa,spa}/`와 `02-post/{mpa,spa}/`를 사용한다. 원본은 이곳에서만 관리하고 배포 ZIP에는 `compare/mpa/`·`compare/spa/`로 묶어 해당 주 저장소에 포함한다. 학생은 비교 파일을 수정하지 않는다. 두 구현은 같은 API·book_id·목록 표시를 사용한다. 12주에는 새 문서를 여는 메뉴와 JSON만 받는 재조회, 해시로 화면을 바꾸는 메뉴를 Network의 document/fetch 요청에서 비교한다.
12주 비교 15분은 예상 3분·MPA 메뉴/GET 4분·SPA 메뉴/GET 4분·새로고침/뒤로/직접 주소 4분이다. 학생은 제공 예제를 조작하고 차이를 구두로 확인한다. 13주 5분에는 POST→GET이 두 구성 모두에서 동작함을 확인한다. 라우팅 코드 작성과 SPA 독립 구현 능력은 정규 평가에서 제외한다.

| 항목 | 제공 SPA 및 특강에서 보장할 동작 |
|---|---|
| 주소와 초기 화면 | `index.html#home`, `#about`, `#guestbook`만 사용한다. 해시가 없거나 알 수 없으면 `location.replace('#home')`로 정규화해 주소와 화면을 맞춘다 |
| 화면 전환 | 하나의 HTML에 id가 겹치지 않는 section 3개를 두고 hidden·if·짧은 함수로 전환한다. 링크의 해시와 hashchange를 사용하며 pushState·라우터 패키지는 도입하지 않는다 |
| 새 탭·새로고침 | `/web-week12/compare/spa/index.html#guestbook`을 직접 열면 방명록부터 표시한다. 13주는 저장소 경로만 바뀐다. HTML은 다시 읽고 목록은 서버에서 GET한다. `/guestbook` 가상 경로는 만들지 않는다 |
| 뒤로·앞으로 | 브라우저 탐색에 따라 해시·보이는 section·현재 메뉴가 일치한다. 같은 메뉴 재선택으로 불필요한 상태 변경을 만들지 않는다 |
| 화면 상태·데이터 | 메뉴만 바꾸면 입력과 로딩된 배열·목록을 유지한다. 메뉴마다 자동 GET을 하지 않으며 새로 불러오기 버튼으로 갱신한다. 새로고침하면 미전송 입력은 사라지고 서버 글만 다시 읽는다 |
| 저장과 접근성 | localStorage 복원은 별도 기능이다. 11주 값이 서버로 옮겨지지 않는다. 현재 메뉴·보이는 제목·키보드 이동·section id 중복을 검사한다 |
| Pages와 기존 주소 | 프로젝트 경로 아래 상대 자산 URL을 쓴다. 정규 index/about/guestbook.html 주소는 유지한다. 특강은 P14를 별도 폴더에 복사하고 이전 사이트에서 새 SPA 주소로 안내한다 |

선택 특강은 P14의 CRUD를 `03-crud/`로 옮겨 화면 분리→해시 전환→입력 유지→직접 주소·탐색 검증→REST 결합 순서로 진행한다. 분량 상한을 두지 않으며 정규 미참여 학생의 시작 파일·시험 범위에는 영향을 주지 않는다.

## REST 설정과 실패 처리

12주 개념 예제를 접속/about → help → GET 목록 순서의 폴더로 정리하고 각 폴더에 실행 가능한 `requests.http`를 둔다. 13·14주도 정보 확인→자기 글 조회→변경→재조회 순서를 유지한다. README에는 `humao.rest-client` 설치, baseUrl·필수 헤더 설정, 요청 위 **Send Request**, 예상 상태와 본문을 명시한다.
강의자는 공용 HTTPS API·CORS·연습 데이터·학생별 book_id를 준비한다. book_id는 구분값이다. 공개 API 설정과 서버 비밀 키, 런타임 편집 키를 구별한다. 추적 `.http`에는 로컬 가상값만 두고 실제 값은 로컬 환경값이나 입력 프롬프트에서 받는다. 편집 키는 화면의 password 입력과 `X-Edit-Key` 헤더에만 사용하고 URL·저장소·localStorage·캡처에 남기지 않는다.
about/help/GET은 200과 배열, 빈 목록은 `[]`, POST는 201과 생성한 글, PATCH는 200과 변경 배열, DELETE는 204와 빈 본문을 예상한다. 204에서 JSON 파싱을 하지 않는다. PATCH의 `[]`와 DELETE 뒤 같은 ID 재조회로 실제 변경을 판정한다.
13주는 대기 중 버튼 비활성화·실패 후 입력 보존을 제공한다. POST 성공 뒤 GET 실패를 저장 실패와 구분하고, 결과가 불명확하면 먼저 재조회한다. 응답이 없다는 이유로 바로 재전송하여 중복 글을 만들지 않는다. 다른 브라우저의 같은 book_id에서 같은 서버 ID를 확인한다.

## 평가와 자료 수정 순서

8주 중간, 9주 README·발표, 15주 기말은 유지한다. 9주 SVG 직접 편집과 Mermaid는 선택으로 옮기고 이미지를 제공한다. 발표 인원이 N명이면 총 15+2.5N분이며 N≤30에 해당한다. 초과 분반은 전원 2분 시연 영상을 사전 제출하고 당일에는 준비 10분·조별 상호 검토 60분·강의자 표본 확인 15분·총평 5분으로 전환한다. 전원의 영상에 같은 수행 항목을 채점하며 학생의 추가 촬영 부담과 강의자의 최소 2N분 영상 확인 부담을 사전 공지한다.
8주 은행의 7주 문항은 W3.CSS 클래스·id 보존만 직접 작성으로 평가한다. 1~6주 문항 범위는 유지한다. 15주는 ex06 수준 저장, 제공 틀의 GET/POST/PATCH/DELETE 지정 부분과 재조회 판정을 평가한다. 배열 심화·SPA 코드·SVG 제작·서버 구축은 제외한다. 서버 장애 시 공통 로컬 API와 같은 데이터로 전환하고 기기 간 공유 항목은 별도 확인한다.

1. 공통 운영 문서와 30차시 시간표를 먼저 고정하고 모든 예제를 필수·시연·선택으로 분류한다. 1~6주 담당은 해당 제한에 맞춰 시작 파일과 직접 수정 부분을 작성한다.
2. 7·9·10주 담당은 P07의 화면을 기준으로 CDN·id·폼·nav 인계를 정리한다. 9주 발표 규칙·rubric·project_brief, 8주 은행·rubric도 함께 수정한다.
3. 11주 담당은 ex04→05→06의 저장 순서와 별도 제출을 고정한다. ex07·배열 저장 심화는 선택 표시하고 저장 키를 예제/주차별로 구분한다. P11 참고본의 손상된 저장값 복구도 확인한다.
4. 12~14주 담당은 전용 시작 파일·API 설정·단계별 `.http`·학생 수정 표시를 만든다. 실제 JS 분리와 오류·재조회 설명을 맞춘 뒤 15주 은행을 갱신한다.
5. SPA 특강 담당은 두 비교 쌍과 CRUD 전환 단계를 작성한다. 주차 담당은 README·slides.md·slides_en.md·walkthrough·lab·examples 색인을 같은 범위로 갱신한다. 영문 덱에도 제공/직접 작성/선택과 시간표를 동일하게 반영한다.
6. 통합 담당은 과목·weeks·specials 색인, 다음 주 안내, 배포 링크·덱 빌드·예제 경로를 검사한다. 선정 후에는 주차별 모든 파일의 조사 목록과 미확인 범위를 기록하고 독립 심사자 3명의 8/10 이상 판정을 받는다.

현재 근거는 대표 파일의 정적 검토다. 전체 예제 실행, 공개 API 접속, 초보 학생 시간 측정은 수행하지 않았다. 본안은 정규 수업의 SPA 구현 능력을 보장하지 않으며 비교 예제 두 쌍과 특강의 유지 비용이 추가된다. 12주 비교만으로 문서와 데이터 요청을 구분하지 못하면 새 문법을 늘리지 않고 같은 비교를 13주 복습에 사용한다.
