# 기술·예제 연계 기획 심사

대상: 강의자의 웹프로그래밍 수업 C01~C09. 심사일: 2026-11-18. 심사자: technical. 단계: planning, 1차.

결정: 이 심사에서는 C01을 9.2점으로 추천한다. C09가 9.0점, C02·C04가 각각 8.8점이다. 9개 안 모두 기획 필수조건을 충족하며 이 심사의 8점 기준을 넘는다. 다른 심사자 점수를 읽지 않았으며 전체 후보 자격과 최종 순위는 세 심사 결과를 모아 판정해야 한다.

근거: C01은 실제 인계 파일, 제공 코드와 학생 작성 범위, REST 실패 판정, 기말 문제량을 함께 정한다. 정규 SPA를 선택하지 않은 사실은 가점 근거가 아니다. C02의 정규 SPA 계약도 기술적으로 성립한다.

대안: 입력 검사와 저장 기초의 직접 연습을 더 늘리려면 C09가 적합하다. 다만 6·7·11주, 중간 문제은행, 12주 시작본, 13~14주 파일 구성을 함께 바꾸는 비용이 든다.

재검토: 선정 후 시작본·수정 표시·초기화 계약을 확정하고 대표 차시를 리허설한다. 실제 학생 시간과 공개 배포를 아직 검증하지 않았다는 사실은 기획 탈락 사유로 삼지 않았다. 확인한 현행 코드 결함은 구현 완료 전에 고쳐야 한다.

## 14주 최초 조회 경쟁을 로컬 브라우저에서 재현했다

원인은 [guestbook.js](../../weeks/week14_project_presentation/examples/day2/web-week14/guestbook.js)의 마지막 `loadMessages()`다. 이 함수의 응답 처리는 나중에 읽는 [actions.js](../../weeks/week14_project_presentation/examples/day2/web-week14/actions.js)의 `createEditButtons()`를 호출한다. HTML의 defer 순서가 JS 실행 순서는 맞추지만, 먼저 시작한 비동기 요청의 완료를 모든 후속 script 준비 뒤로 미루지는 않는다.

리허설은 원본을 수정하지 않고 임시 HTTP 서버에서 실제 14주 HTML·JS를 읽었다. API는 브라우저 요청 가로채기로 일회용 글 한 개를 반환했다. CDN 요청은 중단해 외부 네트워크와 스타일을 이 검사에서 제외했다. 따라서 CDN 요청 실패 로그는 이 리허설의 의도한 조건이며 스타일 판정 결과가 아니다. 클라우드 변경 요청·실제 키·학생 데이터는 사용하지 않았다.

| 조건 | 기대 결과 | 관찰 결과 |
|---|---|---|
| 파일 지연 없음, 모의 GET 1행 | 목록 1개·불러오기 완료 | 기대대로 표시 |
| 동일 조건에서 actions.js 응답만 600ms 지연 | 목록 1개·불러오기 완료 | 목록 0개·불러오기 실패. Console에 `createEditButtons is not defined` |

같은 두 조건을 두 번 실행해 동일 결과를 확인했다. 오류는 `loadMessages()` 내부 catch에 잡히므로 pageerror가 비어 있어도 실패다. Console과 화면의 목록·상태를 함께 봐야 한다.

```powershell
node <임시 폴더>/course-audit-technical-20261118/week14-defer-race.mjs <저장소 루트>
```

해결 조건: 모든 의존 함수·DOM 참조를 준비한 뒤 최초 조회를 한 번 실행한다. 분리 파일을 유지하면 마지막 초기화 단계 또는 DOMContentLoaded에서 호출한다. 단일 JS로 합치는 안도 초기화 위치를 확인한다. 같은 600ms 지연 조건에서 목록 한 개와 완료 상태가 나오고, reload·POST 이후 목록·수정·삭제 기능이 유지되어야 한다.

이 결함은 현행 코드의 구현 전 선결 조건이다. 모든 분리안의 기획을 탈락시키는 blocker로 처리하지 않았다. 단일 파일과 분리 파일 모두 작은 초기화 수정으로 해결할 수 있으며 선정안 구현 후 반드시 동일 조건으로 다시 검증해야 한다.

## 구현 선결 조건과 향후 검증을 구분한다

| 시점 | 필요한 조치 |
