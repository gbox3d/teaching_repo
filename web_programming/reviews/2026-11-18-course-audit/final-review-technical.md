## 직접 실행한 검증

### 기존 통합 시험

독립적으로 저장소 루트에서 `npm test`를 실행해 종료 코드 0을 확인했다. 사이트 검사 후 덱 맞춤 3개, 정적 서버·방명록·IoT·HTTP 26개, 지도 25개가 통과했다. 합계는 54개다. 사이트 검사는 58개 덱·언어별 1175장과 내부 링크를 통과했다.

전체 빌드는 총괄이 수행한 산출물을 사용했다. 빌드를 동시에 실행하지 않았으며, 모든 슬라이드를 이 심사자가 다시 순회했다고 주장하지 않는다. 총괄의 42개 웹 덱·742장 검사와 수정 덱 재검사 기록은 보조 근거다.

### 임시 API와 실제 Chrome

Chrome 157.0.8103.38을 Playwright로 실행했다. 별도 임시 폴더의 `createGuestbookServer`와 임시 포트의 정적 서버를 사용했다. 생성된 임시 키는 메모리에서만 사용했고 결과에 출력하지 않았다. API·브라우저·임시 파일은 종료·정리했다.

### 정적 서버 비공개 경로

실제 강의자 파일 대신 임시 더미 파일로 새 서버를 실행했다. `/`는 200, `.env`·`.env.local`·`localfiles`·대문자 `LOCALFILES`·`.git`·인코딩한 `.local`은 403이었다. `.env.example`은 200이며 `/localfiles./dummy.txt`와 없는 파일은 404였다. 기존 8111 서버에 새 차단 코드가 적용됐다고 가정하지 않았다.

## 소스에서 확인한 계약

- [render-site.mjs](../../../scripts/render-site.mjs)는 Git 공개 파일 목록을 기반으로 HTML 예제와 같은 단원의 JS·CSS·JSON·이미지·`.http`·`.env.example`을 포함한다. `realpath` 이후 저장소 경계를 확인하며, 다른 예제 HTML 링크를 따라 필요한 자산을 추가한다.
- [check-site.mjs](../../../scripts/check-site.mjs)는 생성 결과에 비공개 경로·환경 파일·실제 config·Markdown 원고가 포함됐는지 검사한다. 실제 산출물 검사도 통과했다.
- [api-settings.js](../../shared/api-settings.js)는 설정을 메모리에 둔다. 13·14주 동작 파일은 DOM·상태·이벤트 등록 후 최초 조회를 실행한다. 설정 변경 버전과 요청 번호로 과거 응답의 화면 적용을 제한한다.
- [schema.sql](../../tools/guestbook-api/schema.sql)의 SELECT/INSERT 공개 정책과 PATCH/DELETE 편집 키 정책이 [학생 안내](../../tools/guestbook-api/student-guide.md)의 설명과 일치한다. `book_id` 필터를 로그인이나 읽기 권한 격리로 설명하지 않는다.
- 14주 방명록은 동작 파일 `guestbook.js` 하나와 제공 설정 파일을 사용한다. 변경 확인은 상태 번호만 보지 않고 같은 ID를 다시 읽는다.
- 15주의 w10 삽입·삭제 2개, w11 저장·복원·삭제 3개, w12 GET·w13 POST·w14 PATCH 각 1개 TODO가 남아 있다. w14 DELETE와 재조회는 제공 코드다. [기말 채점표](../../weeks/week15_final_exam/rubric.md)의 구현 15점과 URL·구술 5점, 총 20점과 일치한다.

## 결함과 재검증

| 등급 | 상태 | 근거 |
|---|---|---|
| blocking | 없음 | 실행·배포·시험 진행을 막는 결함을 발견하지 않았다. |
| major | 없음 | 정상 CRUD·설정 교체·키 제한·저장 복구·SPA 탐색의 필수 동작을 통과했다. |
| minor T01 | 수정 후 종결 | 11주 제공 방명록의 setItem 실패가 처리되지 않은 예외로 이어졌다. 12주 로컬 보관본에도 같은 코드가 있었다. |

T01은 `Storage.prototype.setItem`이 `QuotaExceededError`를 던지도록 주입해 재현했다. 수정 전에는 폼 제출 시 페이지 예외가 발생하고 안내가 비어 있었다. 총괄이 `saveList()`의 성공 여부 반환과 등록·삭제 실패 시 배열 복원을 추가했다. 11주 walkthrough의 코드 전문도 확인했다.

수정 후 두 화면 각각에서 실패 등록 시 폼·기존 2행·저장값 유지, 실패 삭제 시 2행 유지, 저장 기능 복구 후 정확히 3행 등록, 정상 삭제, 다른 키 유지가 통과했다. 두 화면 모두 처리되지 않은 예외는 0개였다. 새 해답이나 시험 구현은 추가하지 않았다.

## 확인하지 않은 범위

실제 GitHub Pages 게시, 운영 Supabase 쓰기와 정책 변경, VS Code REST Client 확장 UI의 직접 클릭, 실제 Kakao 인증·지도 응답, 소리의 청감, 학생 집단의 30분 실습 소요 시간은 이 심사 결과로 입증하지 않는다. 담당자 기록이나 소스 검사와 독립 실행을 구분해 기록했다. 이 제한을 정상 동작 실패나 이미 수행한 검증으로 바꾸어 표현하지 않았다.
