## SPA 결정

SPA 직접 구현은 14주 이후 선택 특강 `specials/hash_spa`에 둔다. W3.CSS로 만든 세 HTML 페이지를 한 HTML의 화면 구역으로 옮기고 `#home`, `#about`, `#guestbook`으로 전환한다. 직접 주소, 새로고침, 뒤로·앞으로, 입력 상태와 서버 데이터의 차이까지 확인한다.

정규 중간에 SPA를 넣는 C02도 검토했으나 C01이 학생의 직접 수정 범위, 11→12주 인계, 기말 저장·REST 문항을 더 구체적으로 연결했다. 정규 수업의 기존 페이지 구조를 유지하고 특강에서 전환 전후를 직접 비교한다. SPA 특강은 정규 시험에 출제하지 않는다.

## 구현에 반영할 심사 의견

- 필수 수정, 강의자 시연, 선택 연습을 모든 차시에서 구분한다. 기존 예제 수를 그대로 필수로 두고 시간표만 줄이지 않는다.
- 11주 필수 결과는 폼 저장·복원이다. 전체 저장 방명록은 제공 시연본이며 12주 시작 자료로 명시한다. 기말 저장 문제도 폼 저장 수준으로 맞춘다.
- 12~14주 설정 패널은 제공 코드로 두고 학생 작성 구역과 분리한다. 설정을 메모리에만 두는 데 따른 재입력 절차를 설명한다.
- 13·14주 방명록 동작 JS는 한 파일에 합치고 최초 조회를 초기화 뒤에 둔다. 14주 지연 로딩 실패를 같은 조건으로 재검증한다.
- 9주 README의 기능·배운 내용도 30분 활동에 포함한다. 발표 인원 상한과 31명 이상 운영을 명시한다.
- SPA의 빈 hash는 홈, 미등록 hash는 안내와 홈 링크로 처리한다. 합친 화면의 ID·전역 변수를 중복 없이 정리한다.
