# C09안: 입력·상태·저장·통신을 설명하고 수정하는 수업

작성일: 2026-11-18. 대상: 강의자의 웹프로그래밍 15주 수업. 독립 기획안이며 다른 제안서는 읽지 않았다.

## 결정과 도달 능력

결정: 기존 주차 번호는 유지하되 6주에 입력 검사, 11주 1차시에 문자열 저장을 앞세운다. SPA는 9주 비교 시연과 14주 이후 선택 특강으로 편성한다. 정규 완성본은 다중 페이지를 유지한다.
근거: 학생이 최종적으로 해야 할 일은 빈 입력을 막고, 배열에서 목록을 만들고, 저장 위치를 구분하고, 요청·응답·실제 데이터를 대조하는 것이다. 라우팅을 함께 작성하면 이 능력의 연습 시간이 줄어든다.
대안: 6주에 SPA를 작성하면 아직 폼을 다루지 못하고, 10주에 작성하면 배열·반복 연습이 줄며, 11~14주에 작성하면 저장·통신 실패의 원인을 분리하기 어렵다. 전체 전환의 이득보다 초보자의 판단 대상 증가가 크다.
재검토: 6·10·11·12·14주 초보자 리허설에서 필수 수정과 검증을 25분 이내에 마친 학생이 80% 이상이고, 저장 위치를 설명할 수 있을 때 정규 SPA 구현을 다음 학기에 검토한다.
성취 증거는 실행 화면과 학생의 코드 수정이다. 7주의 제공 목록 추가 코드, 11주의 방어 코드, 12~14주의 통신 틀을 처음부터 작성하는 능력으로 간주하지 않는다.

## 30차시 구성과 학생 산출물

일반 차시는 강의·시연 60분과 실습 30분이다. 강의에는 예측·실행·오류 비교를 넣고 학생의 장문 타이핑을 숨겨 배정하지 않는다. 실습은 준비 4분, 수정 17분, 검증 6분, 증거 저장 3분을 기준으로 한다.
4주 이후 주간 폴더·새 저장소 준비 10분과 업로드·정리 10분은 수업 전후 부담으로 별도 명시한다. 준비 실패자는 배포 가능한 전체 시작 묶음으로 즉시 실습하며, 로컬 완료 증거를 먼저 인정한다. 1·2주는 환경 준비를 차시 안에 포함한다.

6주 다크 모드·classList 확장은 선택으로 옮기며 필수 문제에서 뺀다. 5주 날짜 처리와 나머지 비교 예제, 4주의 나머지 예제는 시연·선택으로 표시한다. 10주 splice 삭제 콜백은 제공하고 인덱스와 결과만 설명하게 한다.
9주 발표 인원 N의 소요는 `5 + 2.5N + 10`분이다. 31명 이상이면 전원 2분 녹화와 수업 중 개인 1분 설명·확인으로 동일하게 바꾸어 `15 + 1.5N`분을 쓴다. 50명 초과는 별도 평가 분반이 필요하며 시간을 숨겨 편성하지 않는다.

## 방명록 인계와 파일 계약

`WNN`은 기존 `weeks/weekNN_<현행이름>/`, `CNN`은 `WNN/examples/day2/web-weekNN/` 전체 폴더다. 1~3주는 `WNN/examples/day2/`가 완성본이다. 아래 경로는 선정 후 만들거나 수정할 시작 묶음까지 포함한 계획이다.
각 차시 시작본은 해당 `examples/day1/` 또는 `day2/` 개념 폴더에 두고, 완성본은 CNN 하나만 유지한다. 학생 개인 수정은 다음 주에 복사하되, 실패한 기능은 배포된 CNN으로 교체할 수 있다.

7주 이후 CDN은 `https://cdnjs.cloudflare.com/ajax/libs/w3-css/4.1.0/w3.min.css`로 고정한다. 추가 CSS는 `shared/examples.css`에 두고 학생 배포 묶음에도 같은 상대 경로의 사본을 포함한다. 긴 설명은 README에만 둔다.
13·14주 기능 JS는 `guestbook.js` 한 파일로 합치고 기존 기능별 함수는 보존한다. `config.example.js`는 공개 설정 전용 예외로 먼저 로드한다. 이벤트 중복 등록을 제거하며, 학생은 차시별 표시된 함수 부분만 수정한다.
11주 필수는 폼 한 건 저장이다. C11의 시연 기능과 배열 전체 저장을 필수 제출로 섞지 않는다. 12주에는 기존 브라우저 목록이 서버로 자동 이전되지 않으며, GET 결과가 화면 목록의 기준이 된다고 명시한다.

## SPA 비교와 선택 특강의 동작 계약

9주 시연본은 `W09/examples/day1/spa_compare/`에 MPA와 SPA를 나란히 제공한다. 같은 이름·메시지 입력 후 메뉴 이동, 직접 주소, 새로고침을 비교한다. 브라우저 뒤로 가기의 캐시 복원을 SPA의 증거로 쓰지 않는다. 시연 내용은 중간·기말 필수 출제에서 제외한다.
선택 구현은 `specials/spa_guestbook/` 신설을 제안한다. 14주 완성본을 복사하여 MPA 관찰→해시 전환 작성→메모리/저장 비교→REST 실패 실험 순서로 진행한다. 참여하지 않아도 정규 차시의 파일·점수·선수 지식에 차이가 없다. 분량·차시 수 상한은 두지 않는다.
구현은 클래식 script, 고정 세 화면, `location.hash`, `hashchange`, `hidden`, if와 함수만 사용한다. SPA의 단일 `index.html`로 홈·소개·방명록을 합치되 정규 MPA 파일·주소는 그대로 남긴다. 특강 README에 두 공개 주소를 각각 적는다.
해시가 없으면 홈, `#home/#about/#guestbook`이면 해당 화면, 미등록 해시는 주소를 유지한 오류 화면과 홈 링크를 표시한다. 초기 실행과 hashchange에서 같은 표시 함수를 호출하며 주소·현재 메뉴·보이는 제목을 함께 갱신한다.
새 탭의 `/spa-guestbook/#guestbook`, 새로고침, 뒤로/앞으로가 같은 화면 규칙을 따른다. GitHub Pages에는 실제 `index.html`을 요청하고 해시는 클라이언트가 해석한다. `/guestbook` 가상 경로와 History API는 채택하지 않는다.
화면 전환은 section을 숨기기만 하므로 DOM 입력·메모리 배열·조회 목록을 유지한다. 새로고침하면 메모리·편집 키는 초기화한다. 폼 복원은 명시적 localStorage 코드가 있을 때만, 서버 목록 복원은 GET이 성공할 때만 일어난다. 편집 키는 저장하지 않는다.
section id는 `view-home`처럼 폼 id와 겹치지 않게 만든다. 메뉴는 a 요소, 현재 메뉴는 aria-current로 표시하고 전환 뒤 제목에 초점을 옮긴다. 키보드 Tab/Enter·숨긴 화면의 포커스·375px 표시를 검증한다.
프로젝트 하위 경로에서 CSS·JS·이미지 상대 주소를 확인한다. 같은 사용자 Pages 프로젝트들은 origin을 공유할 수 있으므로 저장 키에 과목·주차·예제명을 넣는다. localhost의 다른 포트와 HTTPS 배포 주소는 별도 저장 공간이다.

## 구현 순서와 평가·특강 정합성

1. 공통 담당이 기존 원고·예제·한영 슬라이드·검사 스크립트의 목록을 만들고 학생 작성/제공/선택 표시를 확정한다. 6주 입력 검사 이동, 11주 저장 순서, 4~15주 60+30 적용을 색인·공통 안내에 먼저 반영한다.
2. 1~6주 담당이 필수 예제를 줄이고 시작 묶음을 만든다. 7주 담당이 C06→C07 동작 동일성을 확인한다. 9·10주 담당은 C07을 복사해 W3 클래스·id·상대 자산을 이어받는다.
3. 11주 담당이 ex04→ex05→ex06을 재배치하고 누락/손상 JSON 처리를 제공한다. C11 시연본과 필수 ex06을 분리한다. 12~14주 담당은 `.http`와 브라우저 예제를 같은 순서·요청 규약으로 정렬한다.
4. REST 폴더는 접속·about/help, GET, POST, DELETE, PATCH를 진행 단계별로 둔다. 각 폴더에 실행 가능한 `.http`, 기본 URL·필수 헤더 설정, Send Request, 예상 상태·응답을 적는다. book_id는 구분값이고 편집 권한이 아니다.
5. 강의자는 공용 HTTPS Supabase API와 브라우저 CORS를 준비한다. 공개 설정·로컬 연습값·실제 비밀을 구분하고 편집 키는 요청 프롬프트/런타임 입력으로 받는다. 실제 키는 추적 파일·URL·캡처에서 제외한다.
6. 평가 담당은 8주 은행에서 다크 모드 의무를 빼고 6주에 작성한 입력 검사만 추가한다. 9주 rubric에서 SVG·Mermaid 의무를 빼고 실제 수정 설명을 채점한다. 15주 은행은 제공 함수·서버·정답을 분리하며 SPA·배열 심화는 제외한다.
7. 서버 장애 때 기말은 사전 검증한 동일 계약의 로컬 교사용 서버로 전환한다. 전환 자체는 채점하지 않으며 실패 시 통신 문항을 재평가한다. 14주는 두 차시 모두 수정·삭제 실습이고 레포트는 별도 과제다.
8. 문서 담당은 모든 변경 주차의 README·slides.md·slides_en.md·walkthrough·lab·examples 안내와 코드 블록을 맞춘다. 용어표와 날짜 폴더 링크, 시험 시작 파일, 특강 선수 지식을 함께 검사한다. 기존 Supabase·IoT·지도·신시사이저 특강은 유지한다.

## 검증 계획과 남은 약점

예정된 기술 검증은 3→4·6→7·7→9→10의 동일 입력, 새로고침 전후, W3 CDN 요청, Console 오류 0, 하위 Pages 주소의 자산 200이다. 11주는 빈 문자열·삭제·손상 JSON·origin 변경, 12주는 빈 배열·Offline→재시도, 13주는 연속 제출·실패 입력 보존, 14주는 잘못된 키·204·대상 ID 재조회까지 기록한다.
초보자 5명 이상에게 6·10·11·12·14주 시작 묶음을 주고 각 30분 수정 시간을 측정한다. 준비·수정·오류·검증 시간과 도움 요청을 따로 기록한다. 80% 미달이면 필수 수정 항목을 줄이고 제공 부분을 늘린 뒤 같은 성공 조건으로 재시험한다. 검증 단계를 삭제해 시간을 맞추지 않는다.
필수 리허설에는 11주 ex06만 마친 학생의 12주 시작, 누락 CSS, 잘못된 book_id, 틀린 편집 키, PATCH 성공 상태 후 실제 미변경을 넣는다. 캡처 한 장으로 증명할 수 없는 탐색·실패 복구는 강의자가 순서대로 재현한다.
약점은 매주 준비·정리 20분의 수업 밖 부담, 한 파일로 합친 14주 코드의 길이, 제공 코드가 많은 REST 학습의 한계다. 이를 줄이려고 전체 시작 묶음·함수별 수정 위치·직접 작성 부분만의 평가를 사용하지만 독립 앱 전체 구현 능력을 보장하지는 않는다.
현재 근거는 대표 원고와 코드 읽기다. 학생 리허설·실제 API·배포·SPA 탐색은 미검증 상태이며, 선정 후 모든 예제 조사와 독립 평가자 3명의 각 8/10 이상 판정을 완료 조건으로 삼는다.
