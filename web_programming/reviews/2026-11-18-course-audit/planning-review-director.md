## 안별 판단과 보완

### C01: 가장 구체적인 시간·인계·평가 연결

[제안](proposal-C01.md)의 30차시표는 강의와 학생 활동의 분 단위를 나누고, 필수·시연·선택을 구별한다. 11주 ex06만 이수한 학생에게 제공 W11을 넘기는 설명과 기말 저장 문제의 축소가 연결된다. SPA 특강은 직접 주소·탐색·DOM 수명까지 정의하며 정규 과정에서 배우지 못하는 범위도 인정한다.

보완: 실행 중 설정 입력 패널은 기존 페이지에 없던 기능이다. 공개 설정 입력과 편집 키 입력을 구분하고 새로고침마다 반복하는 횟수·시간을 시작본에 반영해야 한다. 단일 JS 조립 시 설정 파일 예외와 함수 수정 구역도 명시한다. 이 비용 때문에 실행 가능성은 만점을 주지 않았다.

### C02: 정규 SPA의 근거는 성립하지만 9주 여유가 작다

[제안](proposal-C02.md)은 6주 classList·함수를 재사용하고 홈·방명록 두 화면만 전환한다. 소개 통합, 전역 이름 충돌, 다크 모드 범위, 옛 주소 안내, 반복 전환의 중복 요청을 검토했다. 프레임워크가 없다는 것보다 실제 통합 위험을 찾은 점이 좋다.

보완: 9주 README 8분·라우팅 14분·탐색 8분은 총 30분이며 별도 오류 수정 여유가 작다. 라우팅의 학생 작성 줄과 제공 줄을 먼저 확정해야 한다. 9주부터 여러 JS를 쓰는 예외를 공통 규칙에 명시하고 공개 설정의 실제 공급 방식도 정한다. 학생 리허설은 학기 적용 여부를 결정할 현장 조건이다. 초보 참여자가 지금 없다는 이유로 시작본 구현까지 중단할 조건으로 삼지 않는다.

### C03: 변경 범위는 작지만 배열 실습을 17분으로 줄인다

[제안](proposal-C03.md)은 showList와 showPage를 구분하고 ex08을 이후 정규 인계에서 제외한다. 실패 시 SPA 학생 비교 5분을 배열 보강으로 돌리는 조정도 있다.

보완: 10주 2차시의 목록 작성 17분 안에 여섯 수정 지점과 삭제 원리를 확인할 수 있는지 검증해야 한다. 제공 W11의 손상 JSON 초기화 복구와 13~14주 다중 JS 예외가 구현 지시서에서 빠지지 않아야 한다. 이를 위해 배열 예제 자체를 더 짧은 것으로 대체할 필요는 없다.

### C04: 저장과 화면 이동의 구분 및 인계가 명확하다

[제안](proposal-C04.md)은 ex06의 명시적 불러오기, P11 제공본, 손상값 복구, 키 분리, REST 파일 분리 예외를 함께 다룬다. MPA 뒤로 가기의 브라우저 복원을 별도 현상으로 설명해 비교 시연의 오해를 줄인다.

보완: 11주 8분 시연을 넣으며 JSON·폼 설명을 각각 15분에서 12분으로 줄이는 비용이 있다. 학생에게 필요한 저장 순서 설명을 생략하지 않는지 확인한다. 1~2주 최초 계정·인증·환경 준비의 실제 작업 시간도 별도 기록한다. 나머지 변경량은 작고 담당 범위가 분명하다.

### C05: REST와 SPA의 차이는 선명하나 객체 배열 연결이 약하다

[제안](proposal-C05.md)은 같은 API를 쓰는 MPA·SPA로 document 요청, fetch 요청, 화면 전환을 비교한다. POST 성공 후 GET 실패를 구분하는 처리도 명확하다.

보완: 11주 1차시가 객체·점 표기와 문자열 저장으로 바뀌는데 객체 배열 학습의 위치가 드러나지 않는다. 12주 학생이 직접 응답 필드를 연결하기 전에 `items[i].name`을 읽는 시연·확인을 넣어야 한다. 12주 비교 15분이 GET 실패·재시도 설명을 압박하면 비교부터 줄이는 조건도 정한다.

### C06: CRUD 검증을 보존하며 전환을 분리한다

[제안](proposal-C06.md)은 14주 ID·키·204·재조회를 유지하고, 시연을 줄일 수 있게 설계했다. 특강의 요청 중 화면 이동, 입력·편집 키 수명, 화면 밖에서 끝난 요청의 처리까지 구체적이다.

보완: 14주 실습 30분에 업로드도 포함한다. 인증·배포 지연이 정상·틀린 키 재조회 시간을 잠식하지 않도록 업로드를 수업 뒤로 넘기는 조건을 명시한다. 제출 캡처를 빨리 만드는 것보다 실제 대상 ID 검증이 우선이다.

### C07: 방학 연결은 좋지만 12주 폼의 동작 계약이 부족하다

[제안](proposal-C07.md)은 기말 이후 진단·보강·선택 연구를 연결하고 미참여자의 정규 진도를 보존한다. 제공 코드와 직접 작성 범위도 구분한다.

보완: 모든 폼 ID와 입력 폼을 유지한 채 12주를 서버 읽기로 바꾼다고 한다. 이때 기존 submit 리스너·DOM 추가·localStorage 쓰기를 제거할지, 폼을 비활성화할지 명시해야 한다. 10주 첫날의 제공 showList와 둘째 날 직접 작성 부분, 기말 w11의 ex06 대응도 정확히 적는다. 이 미결정 때문에 기술·일관성 점수가 낮다.

### C08: 평가 설계가 구체적이며 근거 해석 한 곳을 고쳐야 한다

[제안](proposal-C08.md)은 README의 코드 출처, 발표 인원, 영상 채점 부담, 기말 문항당 시간을 다룬다. 학생이 제공 폼을 시연한 것을 전체 구현 능력으로 오인하지 않는다.

보완: 기말 rubric의 레포트 제외 문장을 결함 근거에서 뺀다. 11주 객체 배열을 시연으로 낮춘 뒤 12주 직접 필드 연결로 넘어갈 때 확인할 예제를 지정한다. 8주 연습의 두 문항·push 점검과 9주 README 두 화면 캡처가 30분 안에 들어가는지 세부 시간을 보완한다.

### C09: 직접 입력 검사 경험을 앞당기는 대신 교차 수정이 늘어난다

[제안](proposal-C09.md)은 6주 입력 검사, 11주 문자열 저장을 앞에 두어 제공 코드를 읽기 전에 짧은 직접 경험을 만든다. C11을 배열 전체 저장이 아닌 폼 임시저장 시연본으로 재정의하는 점도 일관된다.

보완: 3주 required 비교를 그대로 이어 쓰면 빈 값에서 브라우저 기본 검사가 submit 이벤트 자체를 막을 수 있다. 6주 JS 빈값 검사용 폼의 required 제거·novalidate 또는 비교 단계 중 하나를 명시한다. 현재 7주 방명록은 required가 없는 자체 검사 방식이다. 객체 배열 필드 읽기의 11→12 연결, 6~8주 문제은행 변경, 14주 184행 기능 코드 병합도 각각 담당 경계를 정한다.

## 구현 전 결정과 이후 검증의 구분

지금 결정할 것은 시작본의 학생 수정 구역, 11→12 데이터 출처와 폼 활성 상태, 단일/분리 JS 예외, 기말 저장 문항, SPA 주소·상태 계약이다. 위 보완은 이 항목을 구체화하기 위한 작업이며 모든 안을 탈락시키는 공통 장애가 아니다.

학생 시간 실측, 실제 공개 API의 권한·CORS, Pages 직접 URL·뒤로/앞으로는 구현 후 실제 환경에서 검증한다. 이번 심사에서는 수행하지 않았다. 소스 대조와 시간 산식만으로 통과했다고 기록하지 않는다. 선정안 구현 뒤에는 계획 심사와 별도로 독립 평가자 3명의 각 8/10 이상을 받아야 한다.
