# 1차 과제 rubric — 10점

## 발표 5점

| 항목 | 점수 | 기준 |
|---|---:|---|
| 문제·사용자·scope | 1 | 핵심 사용자의 문제와 Must가 명확함 |
| architecture 설명 | 1.5 | 실행 위치·data flow·신뢰 경계를 근거로 설명 |
| walking skeleton 시연 | 1.5 | URL에서 핵심 흐름과 상태를 재현 |
| 시간·응답 | 1 | 3분 내 핵심 전달, 질문에 설계 근거로 답변 |

## 보고서 5점

| 항목 | 점수 | 기준 |
|---|---:|---|
| 사용자 흐름·검증 | 1 | 이야기와 정상/경계 acceptance scenario |
| 데이터·권한 | 1.5 | entity, key, owner, 관계, 읽기/쓰기 범위 |
| architecture·상태 | 1.5 | 실제 범위와 일치하는 diagram, 여섯 상태 |
| 재현성·계획 | 1 | repository/URL/commit, 위험과 다음 단계 |

## 부분 점수 원칙

- 기술 이름을 나열했지만 선택 근거·화살표·검증이 없으면 완전 충족이 아니다.
- 실행 화면만 있고 설계와 재현 정보가 없으면 해당 문서 점수를 대체하지 않는다.
- 선택 기능이 많아도 Must 흐름이 실행되지 않으면 범위 관리 점수가 낮다.
- 실제 secret, 타인 개인정보, 무단 asset을 공개한 경우 관련 운영·보안 항목을 충족하지 못한 것으로 본다.
