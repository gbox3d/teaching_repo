# 9주차 실습 — README 1차판을 조립하고 2분 발표하기

1일차 실습도 코드를 새로 쓰는 것이 아니라 **값을 바꿔 보는 것**에서 시작한다.
비교 예제 3개(마크다운 `.md` 파일)를 이번 주 새 저장소 `web-week09` 의 `ex/` 폴더에 저장하고, 기호나 띄어쓰기 하나를 바꾼 뒤 렌더된 모양이 어떻게 달라지는지 본다. 결과는 VS Code 미리 보기와, 올린 뒤의 GitHub 저장소 화면에서 본다.
1일차 끝에 그 세 가지로 `web-week09` 맨 위의 `README.md` 1차판을 조립하고 화면 캡처 두 장을 넣는다. 사이트 파일(HTML·CSS·JavaScript)은 7주차 완성본 그대로 두고 고치지 않는다.
2일차 60분은 **발표**다. 이번 주는 주차별 실습 점수가 아니라 1차 과제 10점(발표 5 + 레포트 5)으로 본다.
`student01` 은 예시 아이디이므로 본인 아이디로 바꾼다.

파일을 받는 법과 미리 보기를 여는 법은 [따라하기 1일차](walkthrough.md#1일차)에 있다.
"바꿔 보기"는 **무엇이 달라질지 먼저 말해 보고** 원문을 고친 뒤 미리 보기로 확인한다. 확인했으면 원래대로 되돌리고 다음으로 간다.

1일차 예제는 모두 마크다운 파일이다. VS Code 에서 파일을 열고 **미리 보기를 옆에** 띄운다(**Ctrl+K** 를 누르고 손을 뗀 뒤 **V**, macOS **⌘+K** 다음 **V**). 왼쪽 원문을 고치면 오른쪽 미리 보기가 따라 바뀐다. 고친 뒤에는 저장(Ctrl+S)해 둔다.

### 5. 조립 — `README.md` 1차판 (`#` · `-` · `[보이는 글](주소)`)

이제 `ex/` 가 아니라 `web-week09` **맨 위**(`index.html` 옆)에 `README.md` 를 만든다. 지난주 파일에 `README.md` 가 있으면 내용을 모두 지우고 다시 쓴다. 저장소 맨 위의 `README.md` 가 GitHub 저장소 첫 화면에 보인다. 전문과 단계는 [따라하기 7단계](walkthrough.md#7-readme-1차판-조립하기)에 있다.

- 맨 위에 큰 제목 한 줄, 그 아래 작은 제목 다섯을 이 순서로 쓴다: `## 공개 주소` · `## 페이지` · `## 기능` · `## 화면` · `## 이번에 배운 것`.
- `## 공개 주소` 에는 **이번 주 내 공개 주소** `https://student01.github.io/web-week09/`(본인 아이디)를 쓴다.
- 문장은 내 사이트와 내가 한 것에 맞게 쓴다. `student01` 과 예시 문장을 그대로 두지 않는다.

| 조립할 줄 | 어느 ex 에서 본 것 |
|---|---|
| `# student01의 웹 연습장` (내 사이트 이름 한 줄) | ex01 1번 (`#` 하나와 띄어쓰기). 글자는 7주차 `index.html` 맨 위 `<h1>` 과 같게 |
| `웹프로그래밍 수업에서 한 주씩 늘려 가는 자기소개 사이트입니다.` (소개 한 문장) | ex02 2번 (기호 없는 줄은 문단이 된다) |
| `## 공개 주소` · `## 페이지` · `## 기능` · `## 화면` · `## 이번에 배운 것` | ex01 2번 (`#` 둘과 띄어쓰기) |
| `- [https://student01.github.io/web-week09/](https://student01.github.io/web-week09/)` (내 공개 주소 한 줄) | ex02 1번 (`- `) + ex03 1번 (인터넷 주소) |
| `- [홈 (index.html)](index.html) — 인사말, 소개, 취미 목록` 외 두 줄 | ex02 1번 + ex03 2번 (같은 저장소 안의 파일 이름) |
| `- 홈의 "인사 바꾸기"와 …` · `- 방명록에서 …` (기능 두 줄) | ex02 1번 |
| `- [홈 화면 캡처](screenshots/home.png)` · `- [방명록 화면 캡처](screenshots/guestbook.png)` | ex02 1번 + ex03 2번. `폴더/파일` 로 쓰는 경로는 3주차 `<img src="images/profile.png">` 와 같다 |
| `- HTML 뼈대와 nav로 세 페이지를 이어 놓는 법` 외 두 줄 (배운 것 세 줄) | ex02 1번 |
| 덩어리(제목·문단·목록) 사이의 빈 줄 | ex01~ex03 (형제 사이를 빈 줄로 나눴다) |

- 확인: 미리 보기를 옆에 띄운다. 큰 제목 한 줄, 소개 문장, 작은 제목 다섯과 그 아래 점이 붙은 목록이 보이고, 링크가 여섯 개(공개 주소 하나·페이지 셋·캡처 둘)면 된 것이다. `## 페이지`·`## 화면` 의 링크를 하나씩 눌러 그 파일이 열리는지 본다. 공개 주소 링크는 50–60분에 Pages 를 켠 뒤 누른다.
- 바꿔 보기: `## 기능` 두 줄 맨 앞의 `- ` 를 지운다. 미리 보기에서 어떻게 보이나? ex02 의 몇 번과 같은가? 확인했으면 되돌린다.
- 흔한 실수: `README.md` 를 `ex/` 안이나 다른 폴더에 만든다. 저장소 첫 화면에는 **맨 위**의 `README.md` 만 보인다. 이름이 `readme.txt` 처럼 다르면 마크다운으로 렌더되지 않는다.

짝과 번갈아 아래 순서를 한 번씩 말하면서 눌러 본다. 오늘은 내 PC 화면으로 하고, 2일차에는 공개 주소와 GitHub 화면으로 한다.

### 이번 주 저장소 만들어 올리기

GitHub 에서 **New repository** → 이름 `web-week09`, **Public**, README 는 추가하지 않는다(내 PC 에서 쓴 `README.md` 를 올린다). VS Code 터미널(현재 폴더 `web-week09`)에서 2주차에 배운 순서 그대로 친다.

```bash
git init
git add .
git commit -m "9주차 1일차"
git branch -M main
git remote add origin https://github.com/student01/web-week09.git
git push -u origin main
```

저장소 **Settings › Pages › Branch: main, /(root) › Save** 를 누른다. 저장소 화면 `https://github.com/student01/web-week09` 를 새로고침하면 파일 목록 아래에 README 가 렌더되어 보인다. 이 화면이 **제출 캡처 1장**이다.
`ex` 폴더에서 `ex01_heading.md` 를 눌러 렌더된 모양을 보고, 위쪽 **Code** 를 눌러 원문과 비교한다. 1~3분 뒤 `https://student01.github.io/web-week09/` 를 열어 세 페이지·버튼·폼과 README 의 공개 주소 링크를 확인한다. 공용 PC면 자격 증명을 지우고 나간다.

- 방명록은 비워 둔 상태로 시작한다. 발표 중에 직접 한 줄 남기고, 이름을 비워 안내 문장까지 보인다.
- 코드 파일은 띄우지 않는다. 구술 질문("이 버튼을 누르면 어느 파일이 실행됩니까?")을 받으면 그때 연다.
- "남긴 글이 새로고침하면 사라지나요?"에는 "아직 화면에만 있습니다(세 곳 중 ①)"라고 답한다.
- 잘 안 되는 기능이 있으면 **되는 것부터** 보여 주고 남은 시간에 말한다.

### 8. 듣는 동안

- [채점표](rubric.md)를 보며 듣는다. 다음 차례 두 사람은 탭 세 개를 미리 열어 둔다.
- 남의 발표 중에 자기 파일을 고치지 않는다. 고칠 것은 55–60분 끝 루틴에서 고친다.

## 막혔을 때

| 증상 | 확인할 것 |
|---|---|
| 공개 주소에 방금 push한 내용이 안 보인다 | Pages 반영은 보통 1~3분 걸린다. 5분 안에 안 보이면 로컬 화면 캡처와 GitHub **Commits** 탭 캡처를 같은 점수로 인정한다. 발표 때도 같다 |
| push 가 거부되거나 로그인 창이 안 뜬다 | [2주차 막혔을 때](../week02_github_pages/lab.md#막혔을-때) 표를 본다 |
| 미리 보기가 안 열리거나 원문만 보인다 | 파일 이름이 `.md` 로 끝나는지 본다(`ex01_heading.md.txt` 면 이름을 고친다). 미리 보기는 **Ctrl+K** 다음 **V**(옆에 열기)다. 그래도 안 되면 **Ctrl+Shift+V**(macOS **⌘+Shift+V**)로 같은 자리에 연다 |
| `#제목` 이 제목이 아니라 글자로 보인다 | `#` 뒤에 띄어쓰기가 없다. `# 제목` 으로 고친다(ex01 3번) |
| 기능 두 줄이 점 없이 한 문단으로 이어져 보인다 | 줄 맨 앞에 `- ` 가 없다(ex02 2번) |
| 링크가 `[보이는 글] (주소)` 글자 그대로 보인다 | `]` 와 `(` 사이의 띄어쓰기를 지운다(ex03 3번) |
| 저장소 첫 화면에 README 가 안 보인다 | 파일이 저장소 **맨 위**에 있고 이름이 `README.md` 인지, push 했는지 본다. 폴더 안의 README 는 그 폴더를 열어야 보인다 |
| README 의 캡처 링크를 누르면 404 | `screenshots/` 폴더가 올라갔는지(저장소 화면에 폴더가 보이는지), 링크의 폴더·파일 이름이 대소문자까지 같은지 본다. GitHub 화면의 파일 이름을 복사해 넣는다 |
| README 의 공개 주소 링크가 옛 사이트나 404 를 연다 | 소괄호 안이 이번 주 주소 `https://student01.github.io/web-week09/`(본인 아이디)인지 본다 |
| 공개 주소 `…/web-week09/` 가 404 다 | ① 저장소 이름이 `web-week09` 인지 ② **Settings › Pages** 가 켜져 있는지 ③ `index.html` 이 저장소 맨 위에 있는지 본다 |
| 발표 중 버튼이나 폼이 동작하지 않는다 | Console 첫 빨간 줄을 읽고 [6주차](../week06_dom_crud/lab.md#막혔을-때)·[7주차](../week07_async_modules/lab.md#막혔을-때) 막혔을 때 표를 본다. 발표에서는 되는 것부터 보여 준다 |
| 방명록에 남긴 글이 새로고침하면 사라진다 | 정상이다. 지금 글은 ① 화면에만 있다. 새로고침해도 남게 하는 것은 11주차다 |
| 2분을 넘긴다 | 말하면서 누른다. 첫 소개를 한 문장으로 줄인다 |

한 번에 한 곳만 고치고 다시 확인한다. 해결되지 않으면 미리 보기나 Console 화면을 그대로 보여 주고 도움을 받는다.

## 제출 — 캡처 한 장과 발표

**캡처 1장**: `https://github.com/<아이디>/web-week09` 저장소 첫 화면. README 5항목과 캡처 2장이 함께 보이게 찍는다.
캡처 2장은 `## 화면` 아래의 링크 두 줄로 보이면 된다. 그림이 펼쳐져 보이지 않아도 된다.

발표는 2일차 수업 시간에 한다. 채점 기준은 [채점표](rubric.md), 과제 범위는 [1차 과제 안내](project_brief.md)에 있다.
캡처에 실명·학번·실제 이메일이 보이지 않게 한다. 제출 위치와 마감은 수업 공지를 따른다.
1일차 `ex/` 실험 파일은 확인용이며 따로 제출하지 않는다.

## 먼저 끝났다면

- README 에 `## 다음에 해 볼 것` 절을 하나 더 두고, 10~12주에 넣고 싶은 기능을 `- ` 두 줄로 쓴다.
- 다크 모드를 켠 홈 화면을 `screenshots/dark.png` 로 한 장 더 찍고, `## 화면` 에 링크 한 줄을 더한다.
- ex01: 10행의 `#` 를 하나씩 늘려 `######`(여섯 개)까지 바꿔 본다. 일곱 개(`#######`)면 어떻게 보이나?
- 짝과 공개 주소로 2분 연습을 한 번 더 하고, 넘친 구간을 한 문장 줄인다.

추가 과제는 선택 사항이며 채점하지 않는다.
