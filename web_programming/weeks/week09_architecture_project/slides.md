## 1일차 · 0–6분 — 2분 발표는 이렇게 합니다

```text
0:00–0:20  공개 주소를 열고 한 줄 소개
0:20–0:50  nav로 세 페이지 이동 (홈 → 내 정보 → 방명록)
0:50–1:30  버튼 한 번, 폼 한 번 (빈값 안내까지)
1:30–2:00  GitHub Commits 탭과 README
```

- 코드는 띄우지 않습니다. **공개 주소에서 동작하는 화면**을 보여 줍니다.
- 발표 전에 탭 세 개를 미리 열어 둡니다. 주소를 치는 시간도 2분에 들어갑니다.
- 로그인 화면·개인 정보가 보이는 탭은 닫고 시작합니다.

---

## 1일차 · 6–12분 — 데이터가 가는 세 곳

```text
① 화면                 지금까지 배운 곳. 새로고침하면 사라진다
② 브라우저 저장소      내 브라우저에만 남는다        → 11주차
③ 인터넷 서버          여러 사람이 함께 본다         → 선택 특강
```

- 오늘 방명록의 글은 **①**에 있습니다. 새로고침하면 `아직 남긴 글이 없습니다.`로 돌아갑니다.
- 11주차에 **②**를 배우면 내 PC에서 새로고침해도 남습니다. 다른 사람에게는 보이지 않습니다.
- 남이 쓴 글까지 함께 보이게 하려면 **③**이 필요합니다. 이 과목의 필수 범위는 아닙니다.
- 발표에서 "이건 아직 ①입니다"라고 말할 수 있으면 충분합니다.

---

## 1일차 · 12–22분 ① — 기능 브랜치를 만들어 합치기

```bash
git switch -c readme
git add .
git commit -m "README 1차판과 화면 캡처 2장"
git push -u origin readme
```

```text
Switched to a new branch 'readme'
 * [new branch]      readme -> readme
```

- 2주차 `about`, 3주차 `guestbook`, 6주차 `dark-mode`와 같은 순서입니다.
- 처음 올리는 브랜치라 `-u`를 붙입니다. `--set-upstream-to`는 `git push -u`가 대신합니다.
- 이 시점의 공개 페이지는 그대로입니다. Pages는 `main`만 배포합니다.

---

## 1일차 · 12–22분 ② — 합친 브랜치 지우기

```bash
git switch main
git merge readme
git push
git branch -d readme
git push origin --delete readme
```

```text
Fast-forward
Deleted branch readme (was 1f74687).
 - [deleted]         readme
```

- `branch -d`는 **내 PC**, `push origin --delete`는 **GitHub**입니다. 두 곳을 따로 지웁니다.
- 아직 push하지 않은 브랜치를 merge 전에 지우려 하면 `error: the branch 'readme' is not fully merged`가 납니다. 이미 push한 브랜치면 경고만 내고 지워지므로 merge를 먼저 합니다.
- 지운 뒤에도 commit은 main에 남습니다. 지우는 것은 이름표뿐입니다.

## 1일차 · 22–26분 — 좋은 시작·피할 시작

좋은 시작:

> `student01`의 웹 연습장입니다. 세 페이지가 있고, 방명록에 한 줄을 남길 수 있습니다.

피할 시작:

> HTML도 했고 CSS도 했고 자바스크립트도 했습니다. 어… 이게 안 되네요.

- 첫 20초에 **무엇을 만들었는지** 한 문장으로 말합니다.
- 만들지 못한 것을 먼저 말하지 않습니다. 되는 것부터 보여 줍니다.
- 미리 한 번 소리 내어 읽어 보면 20초가 얼마나 짧은지 알게 됩니다.

## 1일차 · 26–30분 — README 1차판과 실습 인계

[1일차 실습](lab.md#1일차--readme-1차판과-브랜치-한-바퀴-60분) · [따라하기](walkthrough.md#1일차)
실습 페이지: https://github.com/gbox3d/teaching_repo/tree/main/web_programming/weeks/week09_architecture_project

```text
# 제목        ## 공개 주소     ## 페이지(3개)
## 기능(2줄)  ## 화면(캡처 2장)  ## 이번에 배운 것(3줄)
```

- 레포트는 따로 내는 문서가 아니라 저장소 첫 화면의 `README.md` 한 장입니다.
- 쓰는 마크다운은 `#`·`-`·`[보이는 글](https://주소)` 셋뿐입니다.
- 발표 차례와 시각은 인원이 확정된 뒤 공지합니다.

**설명 합계: 6+6+10+4+4 = 30분**

## 2일차 · 0–6분 — 오늘 순서와 준비

```text
탭 1  https://student01.github.io/my-web/
탭 2  https://github.com/student01/my-web          ← README가 보이는 첫 화면
탭 3  https://github.com/student01/my-web/commits  ← Commits 탭
```

- 자기 차례 **두 사람 앞**에서 탭 세 개를 열어 둡니다.
- 방명록은 **비워 둔 상태**로 시작합니다. 발표 중에 직접 한 줄 남깁니다.
- 다크 모드를 쓴다면 시작 전에 꺼 둡니다. 첫 화면이 밝아야 글씨가 잘 보입니다.

## 2일차 · 6–12분 — 채점표 10점

| 발표 5 | 점수 |
|---|---:|
| 공개 주소가 열린다 | 1 |
| nav로 세 페이지를 오간다 | 1 |
| 버튼·폼이 화면을 바꾼다 | 2 |
| 2분을 지킨다 | 1 |

레포트 5 = README **5항목 각 1점**(공개 주소 / 페이지 / 기능 / 화면 / 배운 것).

자세한 기준은 [채점표](rubric.md)에 있습니다.

## 2일차 · 12–18분 — 2분 시연 한 번 보기

```text
"student01의 웹 연습장입니다. 세 페이지가 있습니다."   (0:20)
홈 → 내 정보 → 방명록 → 홈                              (0:50)
[인사 바꾸기] 클릭 → 문장과 클릭 횟수가 바뀜             (1:10)
방명록에 이름·메시지 → [남기기] → 한 줄 표시             (1:30)
이름을 비우고 [남기기] → 안내 문장                       (1:40)
Commits 탭 → README                                     (2:00)
```

- 말하면서 누릅니다. 누르고 나서 설명하면 시간이 두 배로 듭니다.
- 빈값 안내까지 보여 주면 폼 점수 2점이 한 번에 채워집니다.

## 2일차 · 18–24분 — 공개 주소가 안 열리면

| 일어난 일 | 할 일 |
|---|---|
| Pages가 5분 넘게 옛 화면 | 로컬 화면과 **Commits** 탭을 같은 점수로 인정 |
| 공개 주소가 404 | 저장소 `main`에 `index.html`이 있는지 먼저 확인 |
| 인터넷이 끊김 | 차례를 뒤로 미루고 뒤 순서에 다시 발표 |
| 버튼이 동작하지 않음 | 되는 것부터 보여 주고 남은 시간에 원인을 말한다 |

혼자 고치려고 발표 시간을 쓰지 않습니다. 손을 들어 알립니다.
