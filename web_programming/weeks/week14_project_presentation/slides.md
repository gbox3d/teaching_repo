# 최종 프로젝트 발표

9주차에는 세 페이지를 **2분** 동안 보여 주었습니다.
그 뒤 목록·저장·JSON 카드가 늘었고 페이지는 네 개가 되었습니다.

```text
발표 3분   공개 주소 → 네 페이지 → 버튼 → 폼 안내 → 목록 → 새로고침 → 카드 → Commits
레포트     저장소 README.md 최종판
```

배점은 **20점**입니다. 발표 12 + 레포트 8.

## 1일차 · 0–5분 — 발표 순서와 3분 규칙

```text
0:00  공개 주소를 열고 한 줄 소개      1:15  글을 남기고 한 줄 삭제
0:20  nav로 네 페이지                  1:45  새로고침 — 목록이 남아 있다
0:40  [다크 모드] 클릭                 2:05  프로젝트 카드
0:55  빈 칸으로 [남기기] → 안내        2:35  Commits 탭과 README
```

- 여덟 가지입니다. 하나에 20~30초씩입니다.
- 코드는 띄우지 않습니다. **공개 주소에서 동작하는 화면**만 보여 줍니다.
- 탭을 미리 열어 둡니다. 주소를 치는 시간도 3분에 들어갑니다.
- 9주차보다 1분 늘었습니다. 늘어난 1분이 목록·저장·카드입니다.

## 1일차 · 5–12분 — 채점표 20점 (발표 12 · 레포트 8)

| 발표 12 | 점수 | 레포트 8 | 점수 |
|---|---:|---|---:|
| URL·페이지 이동 | 2 | URL·한 줄 소개 | 1 |
| 클릭 이벤트·폼 안내 | 3 | 기능 목록 5개 | 2 |
| 목록 추가·삭제·새로고침 유지 | 3 | 캡처 3장 | 2 |
| JSON 카드 | 2 | 사용 기술·`git log` | 1 |
| 시간·설명(구술 포함) | 2 | 어려움과 해결 3줄 | 2 |

레포트는 저장소 `README.md` 한 장입니다. 13주차에 쓴 최종판이 그대로 레포트입니다.
자세한 기준은 [채점표](rubric.md)에 있습니다.

## 1일차 · 12–18분 — 3분 시연 흐름 표 8줄

[3분 시연 흐름 표](examples/demo_outline.md)를 종이에 옮겨 적고 **말할 것** 칸만 본인 문장으로 바꿉니다.

| 시간 | 화면·동작 | 말할 것 |
|---|---|---|
| 0:40–0:55 | **[다크 모드]** | "버튼을 누르면 배경색이 바뀌고 클릭 횟수가 오릅니다." |
| 1:45–2:05 | 새로고침 | "목록이 그대로입니다. 브라우저에 저장되기 때문입니다." |

- 여덟 줄의 **순서를 홈 화면 목록으로도 적어 둡니다.** 오늘 실습에서 넣습니다.
- 그러면 발표 중에 다음에 할 일을 화면에서 볼 수 있습니다.
- 새로고침은 실제로 누릅니다. 말로만 하면 점수가 되지 않습니다.

## 1일차 · 18–24분 — 공개 주소가 안 열릴 때

| 일어난 일 | 할 일 |
|---|---|
| 조교 전수 확인(발표 전날) | 제출 URL을 모두 열어 본다. 안 열리는 학생에게 미리 알린다 |
| 내 화면은 열리는데 남은 안 열린다 | **새 시크릿 창**에서 연다. 저장소가 Private이면 여기서 막힌다 |
| 시크릿 창에서도 안 열린다 | 로컬 시연으로 바꾼다. **같은 배점**을 받는다 |
| Pages가 옛 화면 | 반영은 1~3분. 5분 넘으면 **Commits** 탭을 함께 보인다 |

로컬 시연은 Live Server(**Go Live**) 또는 `python3 -m http.server 8000`입니다.
발표 시간에 혼자 고치지 않습니다. 손을 들면 됩니다.

## 1일차 · 24–27분 — 좋은 시작·피할 시작

좋은 시작:

> `student01`의 웹 연습장입니다. 네 페이지가 있고, 방명록에 남긴 글이 새로고침해도 남습니다.

피할 시작:

> 어… 목록이 원래 되는데요. 다시 해 볼게요. JSON이 안 불러와져서…

- 첫 20초에 **무엇을 만들었는지** 한 문장으로 말합니다.
- 안 되는 것부터 말하지 않습니다. 되는 것을 먼저 보여 줍니다.
- 한 번 소리 내어 읽어 보면 20초가 얼마나 짧은지 알게 됩니다.

[1일차 실습](lab.md#1일차--최종-통합과-3분-리허설-60분) · [따라하기](walkthrough.md#1일차)

# 2일차 — 3분 발표

`90분 전체가 발표입니다`

```text
0–5분    안내
5–68분   발표 3분 × 21명
68–80분  총평과 15주차 예고
80–90분  지연 여유
```

설명 30 + 실습 60으로 나누지 않습니다. 인원이 다르면 차례와 시각을 다시 공지합니다.

---

## 2일차 · 0–2분 — 오늘 순서와 준비

```text
탭 1  https://student01.github.io/my-web/            ← 시크릿 창으로 연다
탭 2  https://github.com/student01/my-web            ← README가 보이는 첫 화면
탭 3  https://github.com/student01/my-web/commits    ← Commits 탭
```

- 자기 차례 **두 사람 앞**에서 탭 세 개를 열어 둡니다.
- 방명록은 **글 두세 줄이 있는 상태**로 시작합니다. 발표 중에 한 줄 더 남기고 하나를 지웁니다.
- 다크 모드는 꺼 두고 시작합니다. 0:40에 눌러서 바뀌는 것을 보여 줍니다.

---

## 2일차 · 2–4분 — 채점표와 구술 1문항

- 발표 12점: URL·이동 2 / 클릭·폼 안내 3 / 목록·삭제·새로고침 3 / JSON 카드 2 / 시간·설명 2
- 레포트 8점: 채점자가 저장소 첫 화면의 `README.md`만 엽니다.
- 구술은 **한 문항**입니다. 예: "이 버튼을 누르면 어느 함수가 실행됩니까?"

답이 바로 안 나와도 감점은 시간·설명 2점 안에서만 봅니다.
점수를 가장 많이 잃는 자리는 둘입니다. **새로고침을 건너뛰는 것**, **캡처가 동작 전 화면인 것**.

---

## 2일차 · 4–5분 — 공개 주소가 안 열리면

| 증상 | 할 일 |
|---|---|
| 시크릿 창에서 404 | 저장소 `main`에 `index.html`이 있는지 본다 |
| 옛 화면 | **Commits** 탭을 함께 보인다. 5분 넘으면 로컬 시연 |
| 카드가 안 그려진다 | 파일을 더블클릭해 연 것이다. 공개 주소로 다시 연다 |
| 목록이 비어 있다 | 내 PC 화면과 공개 주소는 저장되는 곳이 다르다. 그 자리에서 한 줄 남긴다 |

혼자 고치려고 발표 시간을 쓰지 않습니다. 손을 들어 알립니다.

## 2일차 · 5–29분 — 발표 시작 (1~8번)

[2일차 실습](lab.md#2일차--3분-발표-60분) · [따라하기](walkthrough.md#2일차)
실습 페이지: https://github.com/gbox3d/teaching_repo/tree/main/web_programming/weeks/week14_project_presentation

- 1번부터 3분씩 시작합니다. 1:45와 2:35에 신호를 한 번씩 줍니다.
- 다음 차례 두 사람은 탭 세 개를 열어 둡니다.
- 듣는 사람도 채점표를 보며 듣고, 끝나면 박수 한 번 칩니다.
- 남의 발표 중에 자기 코드를 고치지 않습니다.

**설명 합계: 2+2+1 = 5분** — 나머지 85분은 발표(5–68)와 총평(68–80), 지연 여유(80–90)다

## 다음 주 미리 보기

15주차는 **기말 개인 실기**입니다.

범위는 2~13주이고, 오늘 발표한 `my-web`이 아니라 **새 저장소**의 시험 폴더에서 혼자 만듭니다.
1일차에 저장소를 만들고 Pages를 켜고 리허설을 하며, 2일차 60분이 본시험입니다.
구현 15 + 시연 5이고, 시연 5는 채점자가 제출한 공개 주소를 직접 여는 것과 구술 한 문항입니다.
