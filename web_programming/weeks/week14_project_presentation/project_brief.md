# 2차 과제 — 내 사이트 3분 발표와 README 최종판

개인 과제다. 새로 만드는 프로젝트가 아니라 **3~13주에 만든 `my-web`을 그대로** 발표한다.
제출 방식과 마감은 수업 공지를 따른다. 배점은 20점(발표 12 + 레포트 8)이며 채점 기준은 [채점표](rubric.md)에 있다.
배점 비중은 강의자 승인 전이므로 **안**이다. 확정되면 수업 공지로 알린다.

## 과제 범위

9주차 1차 과제에서 발표한 것에 10~13주에 만든 기능이 더해진 것이다. 8주차 `my-web/exam/` 폴더는 이번 과제와 관계가 없다.

| 갖춰야 할 것 | 어디서 만들었나 | 발표에서 |
|---|---|---|
| 공개 주소 `https://<아이디>.github.io/my-web/` | 2주차 | 첫 20초에 연다 |
| 네 페이지 `index.html`·`about.html`·`guestbook.html`·`projects.html`과 nav | 3·12주차 | 오가며 보여 준다 |
| `styles.css` — 색·박스·`display: flex`·`@media` 1개(375px 대응) | 4주차 | 화면으로 보인다 |
| 클릭 이벤트 1개 — 문장·배경색이 바뀌고 횟수가 오른다 | 5·6주차 | 눌러서 보여 준다 |
| 폼 입력과 빈값 안내 | 7주차 | 칸을 비우고 눌러 본다 |
| 방명록 목록 추가·삭제 | 10주차 | 남기고 한 줄 지운다 |
| 새로고침해도 목록이 남는 저장 | 11주차 | 실제로 새로고침한다 |
| `data/projects.json`을 불러온 카드 세 장 | 12주차 | 프로젝트 페이지를 연다 |
| 저장소 `README.md` 최종판과 `screenshots/` 캡처 3장 | 13·14주차 | 마지막 25초 |

본인 기능 1개를 더 넣어도 된다(선택). 발표 소재로 쓸 수 있지만 **가산점은 없다.**
기능을 더 넣다가 위 표의 동작이 멈추면 그 항목에서 점수를 잃는다.

## 레포트 = 저장소 README.md 한 장

별도 보고서 파일(docx·pdf)은 받지 않는다. 채점자는 공개 주소와 저장소 첫 화면만 연다.

```text
# 사이트 이름
## 공개 주소        Pages 주소 링크와 한 줄 소개
## 페이지           네 페이지와 한 줄 설명
## 기능             기능 5개
## 화면             screenshots/ 캡처 3장 (![그림] 문법)
## 사용 기술        HTML·CSS·JavaScript·GitHub Pages
## 어려움과 해결    3줄
## 만든 과정        git log --oneline 다섯 줄 이상
```

- 13주차에 쓴 최종판이 그대로 레포트다. 14주차에는 홈 설명 한 줄과 commit 한 줄만 더한다.
- 캡처 세 장은 **동작한 뒤의 화면**으로 찍는다(버튼을 누른 홈, 글이 쌓인 방명록, 카드 세 장).
- 캡처는 **공개 주소에서** 찍는다. 파일을 더블클릭해 연 화면은 목록이 다르고 카드가 그려지지 않는다.
- 예시는 [examples/day1/README.md](examples/day1/README.md)에 있다. 그대로 베끼지 말고 본인 사이트 내용으로 바꾼다.

## 3분 발표 순서

[3분 시연 흐름 표](examples/demo_outline.md)의 여덟 줄이 그대로 발표 순서다.

| 시간 | 보여 줄 것 |
|---|---|
| 0:00–0:20 | 공개 주소를 열고 사이트 이름·한 줄 소개 |
| 0:20–0:40 | nav로 네 페이지 이동 |
| 0:40–0:55 | 홈에서 버튼 한 번(다크 모드 또는 인사 바꾸기) |
| 0:55–1:15 | 칸을 비우고 **[남기기]** → 빈값 안내 |
| 1:15–1:45 | 글을 남기고 한 줄 **[삭제]** |
| 1:45–2:05 | 새로고침 — 목록이 남아 있다 |
| 2:05–2:35 | 프로젝트 카드 세 장 |
| 2:35–3:00 | GitHub **Commits** 탭과 README |

구술 질문은 한 문항이다. 예: "이 버튼을 누르면 어느 함수가 실행됩니까?"

## 제출물

1. **발표 3분** — 2일차 수업 시간
2. **공개 주소** `https://<아이디>.github.io/my-web/`
3. **저장소 주소** `https://github.com/<아이디>/my-web`
4. **캡처 1장** — 저장소 첫 화면(README 최종판과 캡처 3장이 보이게)

## 제출 전 확인

- [ ] **새 시크릿 창**에서 공개 주소를 열어 네 페이지가 모두 열린다.
- [ ] 버튼·폼·목록·삭제·새로고침·카드가 공개 주소에서 동작한다.
- [ ] 발표할 창의 방명록에 글 두세 줄이 미리 남아 있다.
- [ ] 저장소 첫 화면에 README가 보이고 그림 세 장이 깨지지 않는다.
- [ ] `git status`가 clean이고 마지막 commit이 push되어 있다.
- [ ] 저장소·공개 페이지·캡처에 실명·학번·전화번호·실제 이메일이 없다.
- [ ] 3분 안에 끝나는지 한 번 재 보았다.

## 장애가 났을 때

발표는 **공개 주소**가 기본이다. 조교가 발표 전날 제출 URL을 모두 열어 확인한다.

1. 내 화면은 열리는데 남의 화면에서 안 열리면 **새 시크릿 창**으로 연다.
2. 시크릿 창에서도 안 열리면 **로컬 시연**으로 바꾼다. Live Server(**Go Live**) 또는 `python3 -m http.server 8000`이며 **같은 배점**을 받는다.
3. Pages 반영이 5분 넘게 늦으면 로컬 화면과 GitHub **Commits** 탭을 같은 점수로 인정한다.
4. 발표 중 인터넷이 끊기면 차례를 뒤로 미루고 뒤 순서에 다시 발표한다.
5. 기능 하나가 동작하지 않으면 그 줄을 지우고 되는 것부터 보여 준다. 남은 시간에 원인을 말하면 시간 점수는 유지된다.
