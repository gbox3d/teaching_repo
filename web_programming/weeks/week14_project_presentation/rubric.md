# 2차 과제 채점표 — 20점

채점 대상은 학생이 제출한 **공개 주소**와 **저장소 첫 화면(README)**, 그리고 2일차 3분 발표다.
채점자는 발표 중에 이 두 가지만 연다. 코드 파일은 구술 질문에 답할 때만 연다.
배점 비중은 강의자 승인 전이므로 **안**이다. 확정되면 수업 공지로 알린다.

## 발표 12점

| 항목 | 배점 | 충족 기준 |
|---|---:|---|
| URL·페이지 이동 | 2 | 공개 주소가 채점자 화면에서 열리고(1), nav로 네 페이지를 오가며 404가 없다(1) |
| 클릭 이벤트·폼 안내 | 3 | 버튼으로 문장·배경색이 바뀌고 횟수가 오른다(1). 칸을 비우고 누르면 안내가 보인다(1). 글을 넣고 누르면 저장된다(1) |
| 목록 추가·삭제·새로고침 유지 | 3 | 목록에 한 줄이 쌓인다(1). 한 줄을 지우면 그 줄만 빠진다(1). **실제로 새로고침해** 목록이 남는 것을 보인다(1) |
| JSON 카드 | 2 | 프로젝트 페이지에 카드가 그려지고(1), 그 데이터가 `data/projects.json`에서 온다고 말한다(1) |
| 시간·설명(구술 포함) | 2 | 3분 안에 여덟 가지를 마친다(1). 구술 한 문항에 답한다(1). 3분 20초까지는 감점하지 않는다 |

## 레포트 8점 — 저장소 `README.md`

| 항목 | 배점 | 충족 기준 |
|---|---:|---|
| URL·한 줄 소개 | 1 | Pages 주소가 링크로 있고 눌러서 열린다. 사이트가 무엇인지 한 줄이 있다 |
| 기능 목록 5개 | 2 | 기능이 다섯 줄로 있고 각 줄이 실제 동작과 맞다. 네 줄 이하면 1점 |
| 캡처 3장 | 2 | `screenshots/`의 세 장이 그림으로 보이고 **동작한 뒤** 화면이다. 깨진 그림이 있으면 1점 |
| 사용 기술·`git log --oneline` 이력 | 1 | 쓴 기술이 적혀 있고 commit 이력이 다섯 줄 이상 붙어 있다 |
| 어려움과 해결 3줄 | 2 | 세 줄이 있고 본인이 실제로 겪은 것이다. 두 줄이면 1점 |

제목(`# 사이트 이름`)은 항목이 모두 있는지 볼 때 함께 확인하며 따로 배점하지 않는다.

## 수준별 판단

### 완전 충족

채점자의 브라우저에서 공개 주소가 그대로 열리고, 여덟 가지가 모두 재현되며, README 다섯 항목이 본인 사이트의 내용이다.

### 부분 충족

- 기능 하나가 멈췄지만 나머지가 동작한다 → 그 항목만 감점한다.
- 새로고침을 말로만 하고 누르지 않았다 → 새로고침 유지 1점을 주지 않는다.
- 캡처를 파일 더블클릭 화면으로 찍어 목록이 비어 있거나 카드가 없다 → 캡처 2점 중 1점.
- README 항목이 있으나 내용이 예시 그대로다(`student01`이 남아 있다) → 해당 항목 절반.

### 미충족

공개 주소가 열리지 않고 대체 증거(시크릿 창·로컬 시연·**Commits** 탭)도 없거나, README가 저장소에 없다.

## 감점 적용 원칙

- 원인이 하나인데 증상이 여럿이면 한 번만 감점하고 그렇게 기록한다.
- 항목별 최대 배점을 넘겨 깎지 않는다.
- 색이 예쁘지 않은 것과 기능이 동작하지 않는 것을 같은 수준으로 보지 않는다.
- 본인 기능 1개(선택)는 가점하지 않는다. 그 때문에 필수 동작이 멈추면 해당 항목에서만 감점한다.
- Pages 반영 지연으로 공개 주소가 늦게 뜨는 경우는 감점하지 않는다. 로컬 화면과 **Commits** 탭으로 확인한다.
- 시크릿 창에서 열리지 않아 로컬 시연으로 바꾼 경우 **배점은 같다.** 바꾸는 데 쓴 시간은 시간 점수에 넣지 않는다.
- 발표 순서가 밀려 생긴 지연은 시간 점수에 넣지 않는다.
- 8주차 `exam/` 폴더의 내용은 이번 과제에서 채점하지 않는다.
