# 14주차 — 최종 프로젝트 발표

## 주간 목표

- 공개 URL에서 핵심 사용자 시나리오를 짧고 재현 가능하게 시연한다.
- Auth·schema·RLS·오류 UX의 설계 판단을 증거와 함께 설명한다.
- 지정된 실패·권한 시나리오와 작은 현장 수정에 대응한다.
- release tag, 보고서와 실행 결과의 일치를 확인한다.

## 1일차 — 발표 설계와 rehearsal

| 구간 | 내용 |
|---|---|
| 설명·시연 30분 | 문제-사용자-기능-권한-실패-회고의 5분 발표 구조 |
| 직접 해결 60분 | 화면 녹화, 시간 측정 rehearsal, 무작위 시나리오와 질의 대응 |

## 2일차 — 평가 발표

| 구간 | 내용 |
|---|---|
| 설명·안내 30분 | 루브릭·순서·장애 대응 재확인, 대표 오류 미니 클리닉 |
| 시연·질의 60분 | 분반 인원에 맞춘 현장 발표 또는 사전 영상+지정 시연 |

## 완료 기준

- 마감 release tag와 제출 SHA가 일치한다.
- 비로그인·소유자·타 사용자·network 실패 중 지정 시나리오를 재현한다.
- SQL policy와 UI 버튼 숨김의 차이를 설명한다.
- 보고서의 기능·테스트·출처가 실제 제출본과 일치한다.

## 발표 시간 원칙

- 20명 이하: 6분 시연 + 2분 질의
- 21~30명: 4분 시연 + 1분 질의
- 30명 초과: 사전 영상 전원 채점 + 지정 현장 시연 또는 별도 세션
