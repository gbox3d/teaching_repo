# 14주차 실습: 글 하나 수정·삭제

양일 강의·시연 60분 뒤 30분 실습이다. 파일 배부·새 web-week14 저장소 준비는 수업 전, 공개 업로드는 수업 뒤에 진행한다. 설정·키·초기화·실패 복구·응답 순서 보호는 제공 코드를 쓴다.

## 1일차 실습

| 실습 시간 | 할 일 | 확인 |
|---|---|---|
| 0–5분 | 자기 글 ID와 .http의 about → help → 목록 → 대상 GET 확인 | 배열 인덱스가 아닌 서버 ID |
| 5–17분 | 제공 guestbook.js의 DELETE 대상 URL·method·헤더 3곳 수정 | id·book_id와 X-Edit-Key |
| 17–30분 | 자기 글 세 개 중 가운데 글 삭제, 남은 글에 틀린 키로 삭제 시도, 재조회 | 정답 키는 대상만 사라지고 틀린 키는 원본 유지 |

DELETE 204 뒤 response.json()을 호출하지 않는다. 같은 ID의 GET이 빈 배열인지 확인한다. 재조회와 확인창은 제공 코드다. ex01 배열 비교와 ex02 실행은 강의자 시연에서 확인하며, 실습 중 예제 전체를 다시 입력하지 않는다.

## 2일차 실습

| 실습 시간 | 할 일 | 확인 |
|---|---|---|
| 0–12분 | PATCH 대상 URL·JSON 본문·같은 ID 재조회 3곳 수정 | id·book_id는 변경 본문에 없음 |
| 12–25분 | 세 글 수정·가운데 삭제·틀린 키 실패 후 올바른 키 재시도 | PATCH 응답 1행과 GET 메시지 일치 |
| 25–30분 | 편집 키 지우기, 수정 결과와 Network GET 캡처 | 키와 개인정보 없는 화면 |

기존 글→폼 연결과 편집 키 입력은 제공한다. 수정 전후에 같은 ID를 읽는다. PATCH 200 []는 수정 완료가 아니다. 새로고침해도 서버 글과 처음 넣은 공개 키는 남고 편집 키만 다시 입력한다.

## 막혔을 때

| 상황 | 확인·복구 |
|---|---|
| Failed to fetch | config.example.js 주소·네트워크·CORS 확인 후 조회 재시도 |
| DELETE 204인데 글이 남음 | 편집 키와 ID를 확인하고 같은 ID GET |
| PATCH 200 [] | 대상·키 확인, 원본 조회 뒤 다시 시도 |
| 편집 키를 넣지 않음 | 요청이 전송되지 않음, 실행 중 키 입력 |
| HTTP 401 조회·저장 실패 | 공개 키 창을 취소했거나 빈 칸이면 새로고침, 편집 키 등 다른 값을 넣었으면 [공개 키 지우기] 뒤 배부받은 공개 키 입력 |
| 글이 student01 방명록에 저장됨 | config.example.js의 BOOK_ID를 배정받은 번호로 바꾸고 새로고침 |
| 쓰기 응답 중 통신 끊김 | 중복 쓰기 전에 GET으로 실제 저장 상태 확인 |
| Pages 반영 지연 | localhost 결과 먼저 캡처하고 수업 뒤 공개 URL 재확인 |

## 제출: 캡처 한 장

수정한 글·남은 목록·주소창·PATCH 또는 DELETE 뒤 GET을 담는다. 편집 키의 [키 지우기]를 누르고, Network의 요청 헤더·공개 키 입력 창·REST Client 키 입력 화면은 캡처하지 않는다. localhost 결과도 실습 확인으로 인정한다. Pages·다른 기기 확인은 수업 뒤 별도 확인이며 그 브라우저에서 처음 묻는 창에 공개 키를 넣는다. 레포트 검사는 없다.

## 선택 확인

ex04에서 같은 ID를 직접 GET하거나 새로고침한 뒤 다시 읽어 결과를 확인한다. 다른 브라우저에서는 처음 묻는 창에 공개 키를 넣은 뒤 조회한다. 다른 사람의 글이나 키를 시험하지 않는다.
