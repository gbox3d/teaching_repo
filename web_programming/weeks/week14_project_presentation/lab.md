# 14주차 실습 — 비교 예제로 확인하고 발표 준비하기

이번 주 실습도 **값을 바꿔 보는 것**으로 시작한다.
비교 예제 3개(파일 여섯 개)를 이번 주 새 저장소 `web-week14` 의 `ex/` 폴더에 저장하고, 값이나 여는 방법을 바꾼 뒤 결과가 어떻게 달라지는지 본다.
이어서 지난주 완성본에 홈의 발표 순서 목록, 내 정보 표의 공개 주소 행, README 세 곳을 조립한다. 2일차가 발표라서 **조립과 올리기를 모두 1일차에 끝낸다.** 그래서 저장소도 50분이 아니라 31분에 만든다. 그래야 수업 안에 조교가 공개 주소를 확인하고, 리허설도 공개 주소로 할 수 있다.
결과는 화면, **F12 › Console**, **F12 › Elements**, 그리고 서버를 띄운 터미널에서 본다. `student01` 은 예시 아이디이므로 본인 아이디로 바꾼다.

파일을 받는 법과 서버로 여는 법은 [따라하기 1일차](walkthrough.md#1일차)에 있다.
"바꿔 보기"는 **무엇이 달라질지 먼저 말해 보고** 저장 → 새로고침으로 확인한다. 확인했으면 원래대로 되돌리고 다음으로 간다.

이번 주 예제는 화면이 서로 달라서 고르기 페이지가 없다. 파일마다 `.html` 을 연다. `.js`·`.json` 은 같은 `ex/` 폴더에서 `.html` 이 불러온다.
ex02·ex03 은 서버로 열 때와 두 번 눌러 열 때를 비교한다. 서버는 2번 문항 첫머리에서 띄운다.

### 1. ex01 순서 목록 (`ol` · `ul` · `li`)

[examples/day1/ex01_order_list.html](examples/day1/ex01_order_list.html) 을 `ex/ex01_order_list.html` 로 저장하고 두 번 눌러 연다.

- 바꿔 보기: 1번 목록의 24행과 25행(첫째 줄과 둘째 줄)을 통째로 맞바꾼다. 번호는 어떻게 붙나? 파일에 번호를 쓴 곳이 있나?
- 바꿔 보기: 23행 `<ol>` 과 29행 `</ol>` 을 `<ul>` 과 `</ul>` 로 바꾼다. 번호 대신 무엇이 붙나? 상자 색은 왜 2번과 같아지나? (`<style>` 의 `ul { … }` 규칙이 태그 이름으로 고른다. 4주차) 확인했으면 되돌린다.
- 바꿔 보기: 29행 `</ol>` 한 줄을 지운다. 2번 제목과 2번 목록은 어디에 들어가나? **F12 › Elements** 에서 `<ol>` 을 펼쳐 본다. 확인했으면 되돌린다.
- 흔한 실수: 번호를 글로 직접 쓴다(`<li>1. 위 메뉴로 네 페이지를 오갑니다.</li>`). `<ol>` 이 붙인 번호와 겹쳐 `1. 1. 위 메뉴로…` 처럼 두 번 보인다. 번호는 `<ol>` 에 맡긴다.

### 2. ex02 로컬 시연은 서버로 (`fetch` · `node server.mjs`)

[examples/day1/ex02_server.html](examples/day1/ex02_server.html) · [ex02_server.js](examples/day1/ex02_server.js) · [ex02_message.json](examples/day1/ex02_message.json) 세 파일을 `ex/` 에 저장한다.
이어서 터미널(현재 폴더 `web-week14`)에서 `node server.mjs` 를 띄운다. 서버는 조립 확인이 끝날 때까지 띄워 둔다.

- 바꿔 보기: 주소창에 `http://localhost:8000/ex/ex02_server.html` 을 친다(1번, 서버로 열기). 화면 글자와 Console 의 번호는? 터미널에 새로 찍힌 요청 줄은 무엇인가?
- 바꿔 보기: 같은 `ex02_server.html` 을 두 번 눌러 연다(2번). 주소창은 무엇으로 시작하나? 화면 글자와 Console 의 번호는? 빨간 줄은 무엇이라고 하나?
- 바꿔 보기: 서버로 연 탭에서 `.js` 8행의 `'ex02_message.json'` 을 `'ex02_massage.json'` 으로 바꾸고 새로고침한다. 화면 글자는 두 번 눌러 열었을 때와 같은가? 그렇다면 둘을 무엇으로 구별하나? 터미널에서 `404 GET /ex/ex02_massage.json` 줄을 찾는다. 확인했으면 되돌린다.
- 흔한 실수: 공개 주소가 안 열려 로컬 시연으로 바꿀 때 `index.html` 을 두 번 눌러 연다. 프로젝트 페이지에 카드가 나오지 않는다. 로컬 시연은 꼭 `node server.mjs` 로 연다.

### 3. ex03 새로고침해도 남는 것 (`localStorage` · 시크릿 창)

[examples/day1/ex03_storage.html](examples/day1/ex03_storage.html) 과 [ex03_storage.js](examples/day1/ex03_storage.js) 를 `ex/` 에 저장하고 `ex03_storage.html` 을 두 번 눌러 연다.

- 바꿔 보기: **눌러 보기**를 세 번 누르고 새로고침한다. 1번과 2번은 각각 몇인가? `+ 1` 하는 줄은 둘이 같은데 왜 다른가?
- 바꿔 보기: 9행을 `let countSaved = 0;` 으로 바꾸고 새로고침한다. 2번은 몇인가? **F12 › Application › Local storage** 에서 `ex03-count` 값은 그대로인가? 이 상태에서 한 번 누르면 저장된 값은 몇이 되나? 확인했으면 되돌린다.
- 바꿔 보기: 같은 파일을 서버 주소 `http://localhost:8000/ex/ex03_storage.html` 로 연다. 2번은 몇에서 시작하나? 두 번 눌러 연 탭을 새로고침하면 그쪽 수는 그대로인가?
- 바꿔 보기: 서버 주소를 복사해 **새 시크릿 창**(Ctrl+Shift+N, macOS ⌘+Shift+N)에 붙여 연다. 2번은? 시크릿 창을 모두 닫았다가 다시 열면?
- 흔한 실수: 발표 전에 일반 창에서 방명록 글을 남겨 두고 발표는 시크릿 창으로 한다. 목록이 비어 있다. 글은 **발표할 그 창**에서 남긴다.

### 4. 조립 — 홈 목록, 공개 주소 행, README (`h2` · `ol` · `tr` · `td`)

이제 `ex/` 가 아니라 `web-week14` 맨 위의 `index.html`·`about.html`·`README.md` 를 연다. 전문과 단계는 [따라하기 5~10단계](walkthrough.md#5-조립표)에 있다.

- `index.html` 의 `<div class="card" id="count">클릭 0회</div>` 바로 아래에 제목 한 줄과 번호 목록(일곱 줄)을 넣는다. 다섯 줄의 순서가 곧 발표 순서다. [3분 시연 흐름 표](demo_outline.md)의 둘째~일곱째 줄과 같은 차례로 두고, 빈값 안내와 남기기·삭제는 한 줄로 묶는다.
- `about.html` 표의 `관심 분야` 행 아래에 행 하나(네 줄)를 넣는다. 주소는 **내 공개 주소** `https://student01.github.io/web-week14/`(본인 아이디)다.
- `README.md` 는 새로 쓰지 않고 세 곳만 고친다. `## 공개 주소` 의 주소를 내 `web-week14` 공개 주소로 바꾸고, `## 페이지` 의 홈 줄에 `할 수 있는 것 목록` 을 넣고, `## 만든 과정` 맨 아래(13주차 줄 다음)에 이번 주에 한 일을 `- 14주차: …` 한 줄로 더한다. 만든 과정은 주차마다 한 줄이라 9주차부터 14주차까지 여섯 줄이 된다. 빠진 주가 있으면 그 주 실습에서 한 일을 떠올려 한 줄로 채운다.

| 조립할 줄 | 어느 ex 에서 본 것 |
|---|---|
| `index.html` 의 `<h2>이 사이트에서 할 수 있는 것</h2>` | 13주차 완성본 `index.html` 의 `<h2>취미</h2>` 와 같은 모양. 제목 글만 다르다 |
| `index.html` 의 `<ol class="card">` 와 `</ol>` | ex01 1번 `<ol>` + 13주차 완성본 `<ul class="card">` 의 `class="card"`(흰 상자, 4주차) |
| `<li>위 메뉴로 네 페이지를 오갑니다.</li>` 등 다섯 줄 | ex01 1번의 다섯 줄. 차례는 3분 시연 흐름 표의 둘째~일곱째 줄 |
| `about.html` 의 `<tr>` · `<td>공개 주소</td>` · `<td>https://student01.github.io/web-week14/</td>` · `</tr>` | 13주차 완성본 `about.html` 의 `관심 분야` 행과 같은 모양. 주소는 곧 만들 이번 주 저장소의 공개 주소 |
| `README.md` 의 `## 공개 주소` 링크 한 줄 | 13주차 완성본 `README.md` 7행. 대괄호 안 보이는 글과 소괄호 안 주소 두 곳을 이번 주 주소로 바꾼다 |
| `README.md` 의 `- [홈 (index.html)](index.html) — 인사말, 할 수 있는 것 목록, 소개, 취미 목록` | 13주차 완성본 `README.md` 11행에 ex01 목록 이름을 넣은 것 |
| `README.md` 의 `## 만든 과정` 맨 아래 한 줄(`- 14주차: …`) | 13주차 완성본 `README.md` 의 같은 절 줄 모양(`- 13주차: …`). 내용은 이번 주에 한 일(홈 목록·공개 주소 행) |

- 확인: 저장하고 서버 주소 `http://localhost:8000/` 을 새로고침한다. 홈의 `클릭 0회` 아래에 `이 사이트에서 할 수 있는 것` 과 1~5 번호가 붙은 다섯 줄이 흰 카드에 들어가 보이고(번호는 카드 왼쪽 테두리에 걸쳐 보인다. 13주차 취미 목록의 점과 같은 자리다), 내 정보 표가 다섯 행(머리 행 포함)이면 된 것이다.
- 바꿔 보기: **다크 모드**를 눌러 본다. 목록 카드도 어두워지나? 왜 그런가? (6주차 `body.dark .card` 규칙. 목록에도 `class="card"` 가 붙어 있다.)
- 바꿔 보기: 서버 주소에서 3분 시연 일곱 가지를 한 번 해 본다(여덟째 Commits 탭과 README 는 31분에 올린 뒤 5·6번에서). 로컬 시연 연습이다. 방명록에 보이는 글은 공개 주소에서 남긴 글과 같은가? 왜 그런가? (ex03)
- 흔한 실수: `</ol>` 을 빠뜨린다. 소개·그림·취미까지 목록 카드 안에 들어간다(ex01 셋째 바꿔 보기).

### 이번 주 저장소 만들어 올리기

GitHub 에서 **New repository** → 이름 `web-week14`, **Public**, README 는 추가하지 않는다(지난주 `README.md` 를 이미 넣었다). 서버를 띄운 터미널은 두고, VS Code 에서 **새 터미널**(현재 폴더 `web-week14`)을 하나 더 열어 2주차에 배운 순서 그대로 친다.

```bash
git init
git add .
git commit -m "14주차 1일차"
git branch -M main
git remote add origin https://github.com/student01/web-week14.git
git push -u origin main
```

저장소 **Settings › Pages › Branch: main, /(root) › Save** → 1~3분 뒤 `https://student01.github.io/web-week14/` 를 연다. 홈에 번호 목록이 보이면 된 것이다.
저장소 첫 화면에는 파일 목록 아래에 `README.md` 가 문서로 보인다. 이 화면이 레포트이고 오늘 캡처할 화면이다.

### 5. 공개 주소에서 확인하고 그림 다시 찍기 (시크릿 창 · `screenshots/home.png` · README)

- 공개 주소를 **새 시크릿 창**으로 열어 [3분 시연 흐름 표](demo_outline.md)의 여덟 줄을 한 번씩 해 본다. 로그인하지 않은 창이라 채점자가 보는 화면과 같다.
- 시크릿 창의 방명록은 비어 있다(ex03). 한 줄 남겨 쌓이는지만 본다. 시크릿 창을 닫으면 지워지므로 발표용 두세 줄은 2일차 발표 직전에 발표할 창에서 남긴다([따라하기 17단계](walkthrough.md#17-발표-전-탭-세-개-준비하기)).
- 홈에서 **인사 바꾸기**를 한 번 누르고, 13주차와 같은 방법으로 홈 화면을 찍어 `screenshots/home.png` 에 덮어쓴다. `guestbook.png`·`projects.png` 는 그대로 둔다.
- 저장소 첫 화면을 새로고침해 README 를 본다. 공개 주소 링크를 누르면 내 사이트가 열리고, 홈 줄에 `할 수 있는 것 목록` 이 있고, `## 만든 과정` 이 9주차부터 14주차까지 여섯 줄이면 된 것이다([따라하기 14단계](walkthrough.md#14-저장소-첫-화면에서-readme-확인하기)). 다시 찍은 `home.png` 는 55분 끝 루틴에서 올라간다.
- 흔한 실수: README 의 그림 이름을 대소문자만 바꿔 적는다(`screenshots/Home.png`). 내 PC 미리보기에서는 보여도 GitHub 에서는 깨진다. `screenshots/` 폴더의 파일 이름을 그대로 복사해 넣는다.

### 6. 조교 확인과 3분 리허설

조교는 38분부터 순회하며 먼저 끝낸 사람부터 두 가지만 본다. **새 시크릿 창에서 열리는 공개 주소**와 **저장소 첫 화면의 README 와 그림 세 장**이다. 확인받은 사람부터 짝과 리허설한다. [따라하기 15단계](walkthrough.md#15-3분-리허설)를 본다.

- [3분 시연 흐름 표](demo_outline.md)를 옆에 두고 짝과 번갈아 3분을 재며 한 번씩 해 본다. 듣는 짝은 점수를 매기지 않는다. 넘긴 시간과 빠뜨린 줄만 적어 준다.
- 3분을 넘기면 첫 소개와 카드 설명을 줄인다. 빈값 안내와 새로고침 줄은 줄이지 않는다. 채점표 점수가 걸린 자리다.
- 구술 연습: 짝이 홈의 버튼 하나를 가리키면 **F12 › Elements** 에서 그 버튼의 `id` 를 읽고, `app.js` 에서 그 `id` 로 찾은 줄과 `addEventListener` 안에서 부르는 함수를 말한다.

## 2일차 — 3분 발표 (60분)

2일차는 설명과 실습으로 나누지 않고 90분 전체가 발표다. 하루 흐름은 아래와 같다(21명 기준). 실제 차례와 시각은 수업 공지를 따른다.

```text
0–5분     안내 — 오늘 차례, 탭 세 개, 채점표와 구술 한 문항, 공개 주소가 안 열릴 때
5–68분    발표 3분 × 21명
68–80분   총평과 15주차 기말 예고
80–90분   지연 여유 · 끝 루틴
```

아래 시간표는 안내와 앞 차례 발표가 끝난 **30분부터의 60분**이다. 인원이 다르면 `5 + 3 × 인원 ≤ 85` 로 다시 계산해 공지한다.

| 시간 | 할 일 |
|---|---|
| 0–38분 | 이어서 발표(21명 기준 9~21번, 3분씩). 다음 차례 두 사람은 탭 세 개(공개 주소·저장소 첫 화면·Commits 탭)를 열고, 발표할 탭의 방명록에 글 두세 줄을 남겨 둔다. 발표는 공개 주소로 하므로 내 폴더가 없어도 된다. 로컬 시연으로 바꿀 때만 폴더가 필요하다(7번 끝 줄) |
| 38–50분 | 총평과 15주차 기말 실기 예고 |
| 50–60분 | 지연 여유. 끝 루틴: README 를 고쳤으면 `web-week14` 폴더를 열고(같은 PC에 없으면 `git clone https://github.com/student01/web-week14.git` 뒤 **File › Open Folder**) `git add .` → `git commit -m "14주차 2일차"` → `git push`. 공용 PC면 자격 증명 삭제 |

### 7. 발표 순서 (3분)

[따라하기 2일차](walkthrough.md#2일차)와 [3분 시연 흐름 표](demo_outline.md)를 본다.

| 시간 | 보여 줄 것 | 말할 것 |
|---|---|---|
| 0:00 | 공개 주소를 연다 | 사이트 이름과 한 줄 소개 |
| 0:20 | nav 로 네 페이지 | 어떤 페이지가 있는지, 표의 공개 주소 |
| 0:40 | 홈에서 **[다크 모드]** | 무엇이 바뀌는지, 클릭 횟수 |
| 0:55 | 칸을 비우고 **[남기기]** | 빈값 안내 |
| 1:15 | 글을 남기고 한 줄 **[삭제]** | 목록이 쌓이고 그 줄만 지워진다 |
| 1:45 | 새로고침 | 목록이 그대로 남는다 |
| 2:05 | 프로젝트 페이지 | 카드가 `data/projects.json` 에서 온다 |
| 2:35 | **Commits** 탭과 README | README 맨 아래의 만든 과정, 이번 주에 올린 기록 |

- 말하면서 누른다. 누르고 나서 설명하면 3분을 넘긴다.
- 코드 파일은 띄우지 않는다. 구술 질문을 받으면 그때 연다.
- 잘 안 되는 기능이 있으면 그 줄을 건너뛰고 되는 것부터 보여 준다.
- 공개 주소가 안 열리면 손을 든다. 새 시크릿 창 → 로컬 시연(`node server.mjs`) 순서로 바꾸며 **같은 배점**이다. 로컬 주소의 방명록은 공개 주소와 저장 칸이 따로다. 비어 있으면 먼저 두세 줄 남긴다(ex03).
- 발표하는 PC 에 내 폴더가 없으면 `git clone https://github.com/student01/web-week14.git` 으로 받고 그 폴더에서 `node server.mjs` 를 띄운다. Node 가 없는 PC 면 손을 들어 조교 PC 에서 같은 순서로 연다(로컬 화면과 **Commits** 탭도 같은 배점).

### 8. 듣는 동안

- 채점표를 보며 듣는다. 다음 차례 두 사람은 탭 세 개를 미리 열어 둔다.
- 남의 발표 중에 자기 코드를 고치지 않는다. 수정은 50–60분 끝 루틴에서 한다.
- 발표가 끝나면 박수 한 번.

## 막혔을 때

| 증상 | 확인할 것 |
|---|---|
| 공개 주소에 방금 push한 내용이 안 보인다 | Pages 반영은 보통 1~3분 걸린다. 5분 안에 안 보이면 로컬 화면 캡처와 GitHub **Commits** 탭 캡처를 같은 점수로 인정한다. 발표 중이면 로컬 시연으로 바꾸고 배점은 같다 |
| push 가 거부되거나 로그인 창이 안 뜬다 | [2주차 막혔을 때](../week02_github_pages/lab.md#막혔을-때) 표를 본다 |
| 새 시크릿 창에서 공개 주소가 404 다 | 저장소가 Private 이거나 맨 위에 `index.html` 이 없다. **Settings › Pages** 에 `Your site is live at` 이 있는지, 주소의 아이디·저장소 이름 `web-week14`·끝의 `/` 를 본다 |
| 두 번 눌러 연 페이지에서 ex02 글이나 프로젝트 카드가 안 나온다 | Console 에 `Access to fetch at 'file:///…' from origin 'null' has been blocked by CORS policy` 로 시작하는 빨간 줄이 있다. 두 번 눌러 연 `file://` 페이지에서는 `fetch` 가 파일을 읽지 못한다. `node server.mjs` 로 연다(ex02) |
| 서버로 열었는데도 `읽지 못했습니다.` 나 `프로젝트를 불러오지 못했습니다.` 가 나온다 | 서버 터미널에서 `404 GET /…` 줄을 찾는다. 파일 이름의 철자·대소문자, 폴더 이름(`data/`)을 본다(ex02 셋째 바꿔 보기) |
| 서버 주소에서는 카드가 나오는데 공개 주소에서는 안 나온다 | `projects.js` 의 주소가 `data/projects.json` 인지 본다. 앞에 `/` 를 붙이면 공개 주소에서는 `https://student01.github.io/data/projects.json` 을 찾아 404 가 난다. `data/` 폴더가 저장소에 올라갔는지도 본다 |
| 로컬 시연 중 `사이트에 연결할 수 없음` · `ERR_CONNECTION_REFUSED` 화면이 나온다 | 서버를 띄운 터미널을 닫았거나 Ctrl+C 로 멈췄다. 그 폴더에서 다시 `node server.mjs` 를 띄운다 |
| 시크릿 창이나 로컬 주소에서 방명록이 비어 있다 | 정상이다. 저장 칸은 주소 앞부분마다 따로이고, 시크릿 창은 일반 창과 따로다(ex03). 발표할 그 창에서 두세 줄 남겨 둔다 |
| 로컬 주소나 공개 주소의 방명록에 지난주에 남긴 글이 보인다 | 정상이다. `http://localhost:8000` 은 5주부터 쓴 주소이고, `web-week13` 과 `web-week14` 의 공개 주소는 앞부분 `https://student01.github.io` 가 같다. 같은 주소 앞부분은 저장 칸(키 `guestbook`)을 함께 쓴다(11주). 발표 전에 **전체 지우기**로 비우고 두세 줄 남긴다 |
| 홈의 소개·그림·취미까지 목록 카드 안에 들어간다 | `</ol>` 을 빠뜨렸다(ex01 셋째 바꿔 보기). **Elements** 에서 `<ol class="card">` 를 펼쳐 어디까지 들어갔는지 본다 |
| 목록 번호가 `1. 1. 위 메뉴로…` 처럼 두 번 보인다 | `<li>` 안에 번호를 직접 썼다. 번호는 `<ol>` 이 붙인다(ex01 흔한 실수) |
| 내 정보 표의 공개 주소 행이 한 칸뿐이다 | `<tr>` 안에 `<td>` 가 두 개인지 본다. 위 `관심 분야` 행과 줄 수를 맞춘다 |
| README 의 그림이 깨지거나 글자 링크로만 보인다 | `screenshots/` 안 파일 이름과 README 에 적은 이름의 대소문자를 맞춘다. 그림 문법 앞의 `!` 가 빠지면 그림 대신 글자 링크가 된다 |
| 저장소 첫 화면에 README 가 안 보인다 | 파일이 저장소 **맨 위**에 있고 이름이 `README.md` 인지 본다. `ex/` 같은 폴더 안의 파일은 첫 화면에 보이지 않는다 |
| 발표 중 인터넷이 끊겼다 | 손을 들어 차례를 뒤로 미루고 뒤 순서에 다시 발표한다. 시간 점수는 그대로다 |

한 번에 한 곳만 고치고 다시 확인한다. 해결되지 않으면 Console 이나 터미널 화면을 그대로 보여 주고 도움을 받는다.

## 제출 — 캡처 한 장과 발표

**캡처 1장**: `https://github.com/<아이디>/web-week14` 저장소 첫 화면. README 최종판과 캡처 3장이 함께 보이게 찍는다.

발표는 2일차 수업 시간에 한다. 채점 기준은 [채점표](rubric.md), 과제 범위는 [2차 과제 안내](project_brief.md)에 있다.
1일차 `ex/` 실험 파일은 확인용이며 따로 제출하지 않는다.
캡처에 실명·학번·실제 이메일이 보이지 않게 한다. 제출 위치와 마감은 수업 공지를 따른다.

## 먼저 끝났다면

- [3분 시연 흐름 표](demo_outline.md)의 **말할 것** 칸 여덟 개를 모두 본인 문장으로 바꿔 적어 본다.
- 홈의 다섯 줄 목록을 본인 사이트 문장으로 다시 쓰고, 발표 순서와 어긋나지 않는지 확인한다.
- `data/projects.json` 에 네 번째 카드를 더해 본다. 키 네 개(`title`·`description`·`image`·`link`)를 모두 넣고 쉼표 자리를 본다. 서버 주소와 공개 주소에서 카드가 네 장이 되는지 확인한다.
- 방명록을 **전체 지우기**로 비우고 발표용 문장 두세 줄을 남기는 연습을 한다. 시크릿 창이면 닫을 때 지워지므로 2일차 발표 직전에 발표할 창에서 한 번 더 한다.
- 3분을 두 번 더 재 본다. 두 번 모두 2분 50초 안에 끝나면 본 발표에서 여유가 생긴다.

추가 과제는 선택 사항이며 채점하지 않는다.
