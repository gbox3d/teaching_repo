# 14주차 실습: 글 하나 수정·삭제

양일 강의·시연 60분 뒤 30분 실습이다. 파일 배부·새 web-week14 저장소 준비는 수업 전, 공개 업로드는 수업 뒤에 진행한다. 설정·초기화·실패 복구·응답 순서 보호는 제공 코드를 쓴다.

## 1일차 실습

| 실습 시간 | 할 일 | 확인 |
|---|---|---|
| 0–5분 | 자기 글 ID와 .http의 about → help → 목록 → 대상 GET 확인 | 배열 인덱스가 아닌 서버 ID |
| 5–17분 | 제공 guestbook.js의 DELETE 대상 URL·method·헤더 3곳 수정 | id·book_id와 apikey |
| 17–30분 | 목록 가운데 글의 삭제 버튼을 누르고 같은 ID를 다시 조회 | 삭제한 글은 빈 배열, 나머지 두 글은 목록에 남음 |

DELETE 204 뒤 response.json()을 호출하지 않는다. 같은 ID의 GET이 빈 배열인지 확인한다. 재조회와 확인창은 제공 코드다. ex01 배열 비교와 ex02 실행은 강의자 시연에서 확인하며, 실습 중 예제 전체를 다시 입력하지 않는다.

## 2일차 실습

| 실습 시간 | 할 일 | 확인 |
|---|---|---|
| 0–12분 | PATCH 대상 URL·JSON 본문·같은 ID 재조회 3곳 수정 | id·book_id는 변경 본문에 없음 |
| 12–25분 | 글 한 건 수정·재조회 후 그 글 삭제, 삭제된 ID의 PATCH 응답 비교 | PATCH 응답 1행과 GET 메시지 일치 |
| 25–30분 | 수정 결과와 Network GET 캡처 | 키와 개인정보 없는 화면 |

목록의 글을 수정 폼으로 불러오는 코드는 제공한다. 수정 전후에 같은 ID를 읽는다. PATCH 200 []는 수정 완료가 아니다. 새로고침한 뒤 다시 조회하면 수정된 메시지가 보인다.

## 막혔을 때

| 상황 | 확인·복구 |
|---|---|
| Failed to fetch | config.example.js 주소·네트워크·CORS 확인 후 조회 재시도 |
| DELETE 204인데 글이 남음 | 태그와 ID를 확인하고 같은 ID GET |
| PATCH 200 [] | 대상 태그·글 번호 확인, 원본 조회 뒤 다시 시도 |
| HTTP 401 조회·저장 실패 | 공개 키 창을 취소했거나 빈 칸이면 새로고침, 잘못된 공개 키를 넣었으면 [공개 키 지우기] 뒤 배부받은 공개 키 입력 |
| 글이 student01 방명록에 저장됨 | config.example.js의 BOOK_ID를 배정받은 번호로 바꾸고 새로고침 |
| 쓰기 응답 중 통신 끊김 | 중복 쓰기 전에 GET으로 실제 저장 상태 확인 |
| Pages 반영 지연 | localhost 결과 먼저 캡처하고 수업 뒤 공개 URL 재확인 |

## 제출: 캡처 한 장

수정한 글·남은 목록·주소창·PATCH 또는 DELETE 뒤 GET을 담는다. Network에서 같은 글 번호에 대한 응답을 캡처한다. localhost 결과도 실습 확인으로 인정한다. Pages·다른 기기 확인은 수업 뒤 별도 확인이며 그 브라우저에서 처음 묻는 창에 공개 키를 넣는다. 레포트 검사는 없다.

## 선택 확인

ex04에서 같은 ID를 직접 GET하거나 새로고침한 뒤 다시 읽어 결과를 확인한다. 다른 브라우저에서는 처음 묻는 창에 공개 키를 넣은 뒤 조회한다. 직접 작성한 연습 글로 실습한다.
