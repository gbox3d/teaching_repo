# 14주차 실습 — 마지막 손질과 3분 발표

실습 페이지: https://github.com/gbox3d/teaching_repo/tree/main/web_programming/weeks/week14_project_presentation

1일차에는 3~13주에 만든 `my-web`을 발표할 수 있는 상태로 마무리한다. 고치는 파일은 `index.html`·`about.html`·`README.md` 셋뿐이다.
**2일차 90분 전체가 발표다.** 모든 단계와 전체 코드는 [따라하기](walkthrough.md)에 있다. `student01`은 예시 아이디이므로 본인 아이디로 바꾼다.

**확인과 캡처는 공개 주소에서 한다.** 방명록 목록은 파일을 더블클릭해 연 화면과 공개 주소가 서로 다른 곳에 저장되고,
프로젝트 카드는 더블클릭해 연 화면에서는 그려지지 않는다. 고칠 때마다 push하고 공개 주소를 새로고침한다.

## 1일차 — 최종 통합과 3분 리허설 (60분)

| 시간 | 할 일 |
|---|---|
| 0–5분 | 같은 PC면 `git pull`, 다른 PC면 `git clone https://github.com/<아이디>/my-web.git` |
| 5–35분 | 홈에 할 수 있는 것 목록 → 내 정보 표에 공개 주소 행 → `README.md` 최종판 마무리 → `screenshots/home.png` 다시 찍기 |
| 35–55분 | 조교 1:1로 공개 주소와 README를 확인받고, 짝과 3분 리허설을 한다 |
| 55–60분 | 끝 루틴: `git add .` → `git commit` → `git push` → 공개 주소 새로고침 → 저장소 첫 화면 **캡처 1장** → 공용 PC면 자격 증명 삭제 |

### 1. 시작 루틴과 네 페이지 점검 (`git pull` · 시크릿 창)

받아온 뒤 공개 주소를 **새 시크릿 창**으로 열어 본다. 채점자가 보는 화면과 같다.
[따라하기 1~2단계](walkthrough.md#1-저장소-열고-시작-루틴)를 본다.

| 확인할 것 | 어디서 |
|---|---|
| nav 네 개가 서로 오간다 | 네 페이지 모두 |
| 버튼으로 문장·배경색이 바뀌고 `클릭 N회`가 오른다 | `index.html` |
| 입학 연도를 넣으면 `n년차`가 나온다 | `about.html` |
| 칸을 비우면 안내, 넣으면 목록에 쌓이고 삭제된다 | `guestbook.html` |
| 새로고침해도 목록이 남아 있다 | `guestbook.html` |
| 카드 세 장이 그려진다 | `projects.html` |

- 시크릿 창에서 목록이 비어 있는 것은 정상이다. 저장된 글을 함께 쓰지 않는다. 그 자리에서 두세 줄 남겨 둔다.
- 동작하지 않는 것이 있으면 [따라하기의 이번 주에 고치지 않는 파일](walkthrough.md#이번-주에-고치지-않는-파일)에서 한 줄씩 비교한다.
- 오늘은 새 기능을 만들지 않는다. 되는 것을 발표할 수 있게 만드는 날이다.

### 2. 홈에 할 수 있는 것 목록 넣기 (`h2` · `ol` · `li`)

`index.html`의 `클릭 0회` 줄 아래에 제목 하나와 번호 목록 다섯 줄을 넣는다.
[따라하기 3단계](walkthrough.md#3-홈에-할-수-있는-것-목록-넣기)를 본다.

- 다섯 줄의 **순서가 곧 발표 순서**다. [3분 시연 흐름 표](examples/demo_outline.md)의 **둘째 줄부터 일곱째 줄**과 같게 둔다.
- 0:55 빈값 안내와 1:15 남기기·삭제는 "방명록에 글을 남기고 지웁니다" 한 줄로 묶는다. 그래서 여섯 줄이 다섯 줄이 된다.
- `<ol>`은 번호, `<ul>`은 점이다. 취미 목록은 `<ul>` 그대로 둔다.
- `class="card"`를 붙여야 흰 상자 안에 들어간다.
- 문장을 본인 사이트에 맞게 고쳐도 된다. 줄 수와 순서만 지킨다.

### 3. 내 정보 표에 공개 주소 넣기 (`tr` · `td`)

`about.html` 표의 `관심 분야` 행 아래에 행 하나를 더한다. [따라하기 4단계](walkthrough.md#4-내-정보-표에-공개-주소-한-줄-넣기)를 본다.

- 한 행은 `<tr>`이고 그 안에 `<td>` 두 개다. 3주차에 만든 표에 행 하나를 더하는 것뿐이다.
- 주소는 글자로 적는다. 링크로 만들지 않아도 된다.
- `student01`을 본인 아이디로 바꾼다. 그대로 두면 예시를 베낀 것으로 본다.

### 4. README 최종판 마무리 (`git log --oneline`)

13주차에 쓴 `README.md`에서 두 곳만 고친다. 새로 쓰지 않는다. [따라하기 5단계](walkthrough.md#5-readme-최종판-마무리하기)를 본다.

1. `## 페이지`의 홈 설명에 `할 수 있는 것 목록`을 넣는다.
2. `## 만든 과정 (git log --oneline)` 맨 위에 오늘 commit 한 줄을 더한다.
3. 홈이 바뀌었으므로 `screenshots/home.png`를 공개 주소에서 다시 찍어 덮어쓴다. `guestbook.png`·`projects.png`는 그대로 둔다.

- commit 앞의 일곱 글자는 PC마다 다르다. 6번 push 뒤 `git log --oneline`에서 본인 값을 옮겨 적는다.
- `home.png`는 **[인사 바꾸기]**를 한 번 누른 뒤 찍는다. `클릭 0회`인 캡처는 눌러 보지 않은 것으로 보인다.
- 이 파일이 레포트 8점이다. 별도 보고서 파일은 내지 않는다.

### 5. 조교 확인과 3분 리허설

조교는 두 가지만 본다. **시크릿 창에서 열리는 공개 주소**와 **저장소 첫 화면의 README**다.
[따라하기 7단계](walkthrough.md#7-3분-리허설-해-보기)를 본다.

- [3분 시연 흐름 표](examples/demo_outline.md)를 옆에 두고 짝과 번갈아 3분을 재며 한 번씩 해 본다.
- 듣는 짝은 점수를 매기지 않는다. 넘긴 시간과 빠뜨린 줄만 적어 준다.
- 3분을 넘기면 첫 소개와 카드 설명을 줄인다. 새로고침 줄은 줄이지 않는다.

### 6. 오늘 확인할 것

- [ ] 공개 주소가 시크릿 창에서 열리고 네 페이지를 오갈 수 있다.
- [ ] 홈에 할 수 있는 것 다섯 줄이 보이고 내 정보 표에 공개 주소 행이 있다.
- [ ] 저장소 첫 화면에 README 최종판과 캡처 3장이 보인다.
- [ ] `git status`가 clean이고 마지막 commit이 push되어 있다.
- [ ] 저장소 첫 화면을 캡처 1장으로 저장했다.
- [ ] 3분 안에 여덟 줄을 끝내 보았다.

## 2일차 — 3분 발표 (60분)

2일차는 90분 전체가 발표다. 아래 60분 시간표는 **90분 중 뒤 60분**(30분~90분)이다.
앞 30분에는 안내 5분과 1~8번 발표(5–29분)가 들어간다.

| 시간 | 할 일 |
|---|---|
| 0–5분 | 9번 마무리와 10번 발표. 다음 차례 두 사람은 탭 세 개(공개 주소·저장소 첫 화면·Commits 탭)를 열어 둔다. 같은 PC면 `git pull`로 마지막 commit이 올라갔는지 확인한다 |
| 5–38분 | **발표 11~21번** (3분 × 11) — 공개 주소에서 여덟 가지를 순서대로 보여 준다 |
| 38–50분 | 총평과 15주차 기말 실기 예고 |
| 50–60분 | 지연 여유. 끝 루틴: README를 고쳤으면 `git add .` → `git commit` → `git push`, 공용 PC면 자격 증명 삭제 |

21명 기준이다. 인원이 다르면 `5 + 3N ≤ 85`로 다시 계산하며 **실제 차례와 시각은 수업 공지를 따른다.**

### 1. 발표 순서 (3분)

[따라하기 9단계](walkthrough.md#9-3분-시연-순서대로-해-보기)와 [3분 시연 흐름 표](examples/demo_outline.md)를 본다.

| 시간 | 보여 줄 것 | 말할 것 |
|---|---|---|
| 0:00 | 공개 주소를 연다 | 사이트 이름과 한 줄 소개 |
| 0:20 | nav로 네 페이지 | 어떤 페이지가 있는지, 표의 공개 주소 |
| 0:40 | 홈에서 **[다크 모드]** | 무엇이 바뀌는지, 클릭 횟수 |
| 0:55 | 칸을 비우고 **[남기기]** | 빈값 안내 |
| 1:15 | 글을 남기고 한 줄 **[삭제]** | 목록이 쌓이고 지워진다 |
| 1:45 | 새로고침 | 목록이 그대로 남는다 |
| 2:05 | 프로젝트 페이지 | 카드가 JSON 파일에서 온다 |
| 2:35 | **Commits** 탭과 README | 몇 번에 걸쳐 만들었는지 |

- 말하면서 누른다. 누르고 나서 설명하면 3분을 넘긴다.
- 코드 파일은 띄우지 않는다. 구술 질문을 받으면 그때 연다.
- 잘 안 되는 기능이 있으면 그 줄을 지우고 **되는 것부터** 보여 준다.

### 2. 듣는 동안

- 채점표를 보며 듣는다. 다음 차례 두 사람은 탭 세 개를 미리 열어 둔다.
- 남의 발표 중에 자기 코드를 고치지 않는다. 수정은 50–60분 끝 루틴에서 한다.
- 발표가 끝나면 박수 한 번.

## 막혔을 때

| 증상 | 확인할 것 |
|---|---|
| 공개 주소에 방금 push한 내용이 안 보인다 | Pages 반영은 보통 1~3분 걸린다. 5분 안에 안 보이면 로컬 화면 캡처와 GitHub **Commits** 탭 캡처를 같은 점수로 인정한다. 다음 수업 시작 5분에 다시 확인해도 된다. `git status`에 `Your branch is ahead`가 있으면 push를 안 한 것이다 |
| `git pull`이 `error: Your local changes to the following files would be overwritten by merge:` / `	README.md` / `Please commit your changes or stash them before you merge.` / `Aborting`으로 멈춘다 | 집이나 다른 PC에서 고친 것과 지금 폴더에서 고친 것이 겹쳤다. 먼저 `git add .` → `git commit`을 하고 다시 `git pull`을 한다 |
| `git push`가 `! [rejected]        main -> main (fetch first)` / `error: failed to push some refs to '…'` / `hint: Updates were rejected because the remote contains work that you do not have locally` | GitHub에 내가 받지 않은 commit이 있다. `git pull`을 먼저 하고 다시 `git push` 한다 |
| `git status`가 `Your branch is behind 'origin/main' by 1 commit, and can be fast-forwarded.` / `nothing to commit, working tree clean` | 고친 것을 저장하지 않았거나 이미 commit했고, GitHub 쪽이 더 앞서 있다. VS Code 탭 제목의 ● 표시를 보고 `git pull`을 한다 |
| 시크릿 창에서 공개 주소가 404 | 저장소가 Private이거나 `main`에 `index.html`이 없다. **Settings › Pages**에 `Your site is live at`이 있는지, 주소의 아이디·저장소 이름·끝의 `/`를 본다 |
| 시크릿 창에서 방명록 목록이 비어 있다 | 정상이다. 창마다 저장된 글을 따로 쓴다. 발표할 창에서 미리 두세 줄 남겨 둔다 |
| 파일을 더블클릭해 열었더니 프로젝트 카드가 안 보인다 | Console에 `Access to fetch at 'file:///…/data/projects.json' from origin 'null' has been blocked by CORS policy: Cross origin requests are only supported for protocol schemes: chrome, chrome-extension, chrome-untrusted, data, http, https, isolated-app.`가 나온다. 공개 주소에서 열면 된다 |
| 프로젝트 카드가 공개 주소에서도 안 보인다 | `projects.js`의 주소가 `data/projects.json`인지 본다. 앞에 `/`를 붙이면 404가 난다. `data/` 폴더가 push됐는지 저장소 화면에서 확인한다 |
| README의 그림 세 장이 깨져 보인다 | `screenshots/` 안 파일 이름과 README에 적은 이름의 대소문자가 다르다. GitHub에서 폴더를 열어 이름을 그대로 복사해 넣는다. 그림 문법 앞의 `!`가 빠지면 그림 대신 글자 링크가 된다 |
| 저장소 첫 화면에 README가 안 보인다 | 파일이 저장소 **맨 위**에 있고 이름이 `README.md`인지 본다. 폴더 안의 파일은 첫 화면에 보이지 않는다 |
| 홈에 목록이 안 보인다 | `<ol>`을 `</main>` 밖에 넣었거나 `</ol>`을 빠뜨렸다. F12 **Elements**에서 `<ol class="card">`가 `<main>` 안에 있는지 본다 |
| 내 정보 표에 행이 겹쳐 보인다 | `<tr>` 안에 `<td>`가 두 개인지, `</tr>`을 닫았는지 본다 |
| 발표 중 인터넷이 끊겼다 | 차례를 뒤로 미루고 뒤 순서에 다시 발표한다. 시간 점수는 그대로다 |

한 번에 한 곳만 고치고 다시 확인한다. 해결되지 않으면 터미널이나 Console 화면을 그대로 보여 주고 도움을 받는다.

## 제출 — 캡처 한 장과 발표

**캡처 1장**: `https://github.com/<아이디>/my-web` 저장소 첫 화면. README 최종판과 캡처 3장이 함께 보이게 찍는다.

발표는 2일차 수업 시간에 한다. 채점 기준은 [채점표](rubric.md), 과제 범위는 [2차 과제 안내](project_brief.md)에 있다.
캡처에 실명·학번·실제 이메일이 보이지 않게 한다. 제출 위치와 마감은 수업 공지를 따른다.

## 먼저 끝났다면

- [3분 시연 흐름 표](examples/demo_outline.md)의 **말할 것** 칸을 여덟 줄 모두 본인 문장으로 바꿔 적어 본다.
- 홈의 다섯 줄 목록을 본인 사이트 문장으로 다시 쓰고, 발표 순서와 어긋나지 않는지 확인한다.
- `data/projects.json`에 네 번째 카드를 더해 본다. 카드가 네 장이 되는지 공개 주소에서 확인한다.
- 방명록을 **전체 지우기**로 비운 뒤 발표용 문장 두세 줄을 다시 남겨 둔다.
- 3분을 두 번 더 재 본다. 두 번 모두 2분 50초 안에 끝나면 본 발표에서 여유가 생긴다.

추가 과제는 선택 사항이며 채점하지 않는다.
