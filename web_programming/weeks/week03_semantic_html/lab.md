# 3주차 실습 — 세 페이지 자기소개 사이트

실습 페이지: https://github.com/gbox3d/teaching_repo/tree/main/web_programming/weeks/week03_semantic_html

각 차시는 강의·시연 60분 뒤 학생 실습 30분이다. [사전 준비](README.md#사전-준비)를 마친 `my-web`의 `main`에서 작업한다. 파일 다운로드·저장소 준비는 수업 전, 공개 업로드는 수업 뒤다. [따라하기](walkthrough.md)의 전체 코드 작성은 강의자 시연·복습용이며 30분에 모두 다시 입력하지 않는다.

## 1차시 실습 30분

| 시간 | 필수 작업 | 확인 |
|---|---|---|
| 0–5분 | 준비된 `index.html`을 열고 `header`·`nav`·`main`·`footer`를 찾는다 | 제공 홈 뼈대가 열린다 |
| 5–20분 | `h1`·소개 문단·그림의 `alt`·취미 목록을 자기 내용으로 바꾼다 | 수업용 별칭·문단·그림·목록 |
| 20–25분 | 메뉴의 `index.html`·`about.html` 두 링크를 확인하고 소개에서 돌아온다 | 왕복 이동 |
| 25–30분 | 저장·새로고침 뒤 그림과 글을 확인한다 | 로컬 홈 화면 |

### 필수 수정

`h1`과 소개 문단은 수업용 별칭으로, 취미 `li`는 자기 내용으로 바꾼다. `alt`에는 그림 내용을 설명한다. 제공 그림을 그대로 쓰면 예를 들어 `student01을 나타내는 사람 모양 그림`으로 쓴다. 실제 프로필 사진은 필요하지 않다.

`img`의 경로는 `images/profile.png`, 홈 메뉴의 두 경로는 `index.html`·`about.html`이다. 그림이 안 보이면 폴더와 파일 이름을 확인한다. 이름만 같은 다른 파일을 열고 있지 않은지도 확인한다.

이 단계의 홈에는 CSS·JS 연결이 없다. `about.html`만 지난주 카드 모양인 것은 정상이다. 보존한 `styles.css`·`app.js`는 학생 수정 대상이 아니다.

### 강의자 시연과 선택 연습

강의자는 빈 본문에 구조를 만들고 링크 경로 오류를 비교한다. 일찍 마친 학생은 취미 목록을 `ul`에서 `ol`로 바꿔 번호를 확인한 뒤 되돌린다. 반응형 CSS나 JavaScript는 추가하지 않는다.

## 2차시 실습 30분

수업 전에 제공 `about.html`·`guestbook.html`과 홈의 방명록 메뉴 한 줄을 준비한다. 1차시에 쓴 자기소개 내용은 유지한다.

| 시간 | 필수 작업 | 확인 |
|---|---|---|
| 0–5분 | 표의 아이디·관심 분야 두 행을 바꾼다 | 2열 4행 유지 |
| 5–20분 | 이름·이메일·메시지의 `label for`와 입력 `id` 세 쌍을 연결하고 눌러 확인한다 | 세 이름표의 포커스 이동 |
| 20–25분 | 세 페이지에서 메뉴 링크를 확인한다 | 홈·내 정보·방명록 이동 |
| 25–30분 | 방명록 화면과 주소창을 캡처한다 | 제출용 한 장 |

### 표 두 행 변경

첫 행의 `th` 두 칸과 가상 이메일 행은 그대로 두고 아이디·관심 분야의 `td` 내용만 고친다. 표에 선이 없는 것은 정상이다. 선과 여백은 4주차에 CSS로 다룬다.

### label과 입력 연결

제공 완성본의 세 `label`에서 `for` 값만 잠시 비운 다음, 아래 표를 보고 다시 입력한다. 입력의 `id`도 대조한다. 연결이 없는 상태와 연결한 상태에서 이름표를 눌러 포커스를 비교한다.

| 표시 글자 | label의 for | 입력의 id | 입력 종류 |
|---|---|---|---|
| 이름 | `name` | `name` | `input type="text"` |
| 이메일 | `email` | `email` | `input type="email"` |
| 메시지 | `message` | `message` | `textarea rows="4"` |

세 쌍을 완성한 뒤 이메일에 `abc`를 넣고 **남기기**를 누른다. 브라우저가 제출을 막는지 확인한다. 이메일을 지우거나 가상 주소로 바꾼 뒤 누르면 현재 페이지를 다시 열며 입력값이 초기화된다. 글 목록은 추가되지 않는다. 이 기본 동작은 [정적 폼 설명](README.md#정적-폼의-동작)에 있다.

### 세 페이지 이동

각 페이지의 메뉴에서 홈·내 정보·방명록을 눌러 본다. 세 페이지에 세 링크씩 있으므로 총 아홉 경로를 확인한다. `guestbook.html`의 철자와 대소문자를 맞춘다.

### 강의자 시연과 선택 연습

강의자는 표·폼 전체 조립, 이메일 기본 검사, 잘못된 `for`와 `id`를 비교한다. 일찍 마친 학생은 표에 가상 정보 한 행을 추가해도 된다. 입력값을 화면에 추가하거나 저장하는 코드는 이번 주 과제가 아니다.

## 제출 — 캡처 한 장

로컬 `guestbook.html`에서 메뉴·세 입력 칸·남기기 버튼과 주소창이 보이게 캡처 한 장을 제출한다. 로컬 파일 주소와 수업용 로컬 서버 주소 모두 인정한다. 제목·표·링크 확인은 실습 중 함께 확인하며 별도 캡처를 요구하지 않는다.

## 수업 뒤 정리

수업 뒤 배운 순서로 `git add .` → `git commit -m "3주 HTML 실습"` → `git push`를 반복한다. `https://<아이디>.github.io/my-web/guestbook.html`에서 결과를 확인한다. 새 브랜치를 만들거나 merge하는 실습은 없다. 공개 반영·계정 문제는 다음 차시 첫 5분에 확인한다.

## 막혔을 때

| 증상 | 확인 |
|---|---|
| 그림 대신 alt 글자만 보인다 | `images/profile.png`의 위치와 철자 |
| 링크가 열리지 않는다 | 같은 폴더인지, 파일 이름·대소문자가 일치하는지 |
| 이름표를 눌러도 입력으로 이동하지 않는다 | `for`와 `id`의 세 쌍을 비교 |
| 잘못된 이메일 때문에 제출이 막힌다 | `type="email"`의 기본 검사. 빈 값 또는 가상 이메일로 다시 관찰 |
| 정상 이메일로 제출하니 입력이 사라진다 | 기본 제출이 현재 페이지를 다시 연 결과. 아직 저장 기능은 없음 |
| 홈은 기본 모양인데 1차시 소개만 카드다 | 1차시 소개에만 보존 CSS 연결이 남아 있음 |
| 공개 화면에 수정이 보이지 않는다 | 먼저 로컬 캡처로 제출. 수업 뒤 저장·commit·push와 Pages 반영 확인 |
