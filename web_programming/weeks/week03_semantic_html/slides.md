# 시맨틱 HTML과 form

2주차의 `my-web` 홈·소개에 정적 방명록을 더한다.
제공 HTML에서 자기 내용과 입력 연결을 수정한다.

```text
my-web/
  index.html      ← 자기소개
  about.html      ← 내 정보 표
  guestbook.html  ← 정적 방명록 폼
  images/profile.png
  styles.css  app.js  ← 보존 파일
```

홈은 CSS·JS 연결을 해제한다. 1차시 소개에만 지난주 CSS가 남고,
2차시가 끝나면 세 페이지 모두 연결하지 않는다.

---

# 1차시 — 시맨틱 구조와 자기소개

`강의·시연 60분 → 학생 실습 30분`

- 강의: 준비 5, 구조 15, 제목·문단 10, 링크·이미지 15, 목록 10, 안내 5
- 필수: 제공 뼈대 열기 5, 제목·문단·alt·취미 15, 링크 2개 5, 확인 5
- 제공: HTML·그림·지난주 CSS·JS. 전체 파일 배부는 수업 전이다.
- 시연: 빈 문서에서 뼈대 조립과 경로 오류 비교
- 선택: 취미 목록의 `ul`·`ol` 비교

---

## 1차시 · 0–5분 — 준비 상태 확인

수업 전에 `my-web`의 `main`과 제공 day1 파일을 준비한다.

- 같은 PC의 `git pull`, 다른 PC의 `git clone`은 2주차 복습이다.
- 첫 5분에는 파일이 열리는지 확인한다. Raw 다운로드를 시작하지 않는다.
- 홈은 제공 뼈대, 소개·CSS·JS는 지난주 결과다.
- 그림 `images/profile.png`가 준비되어 있는지 확인한다.

수업 뒤 배운 `add`·`commit`·`push`로 업로드한다.
이번 주에 새 브랜치 명령은 배우지 않는다.

---

## 1차시 · 5–20분 — header·nav·main·footer

```html
<body>
  <header>
    <h1>student01의 웹 연습장</h1>
    <nav><a href="about.html">내 정보</a></nav>
  </header>
  <main>… 이 페이지의 본문 …</main>
  <footer>… 마무리 한 줄 …</footer>
</body>
```

`header`는 소개, `nav`는 메뉴, `main`은 본문, `footer`는 마무리다.
제공 예제에서는 `nav`를 `header` 안에 둔다. `main`은 하나다.
강의자가 뼈대를 조립하고 학생은 제공 파일에서 각 부분을 찾는다.

---

## 1차시 · 20–30분 — 제목과 문단

```html
<h1>student01의 웹 연습장</h1>
<h2>소개</h2>
<p>웹프로그래밍을 배우는 <strong>student01</strong>입니다.</p>
<h3>이번 학기 목표</h3>
```

- 예제의 `h1`은 페이지 제목 하나, `h2`는 소개·취미의 제목이다.
- `h3`는 `h2` 안의 더 작은 묶음에 쓴다. 강의 비교 코드에서 관찰한다.
- `p`는 문단, `strong`은 문단 안에서 중요한 말이다.
- 필수 수정은 제목과 소개 문단의 수업용 별칭·내용이다.

글자 크기와 배치는 4주차 CSS에서 다룬다.

---

## 1차시 · 30–45분 — 상대 링크와 그림

```html
<a href="about.html">내 정보</a>
<img src="images/profile.png" alt="student01의 프로필 그림" width="160">
```

- 같은 폴더의 파일은 파일 이름으로 연결한다.
- 그림은 미리 받은 `images/profile.png`를 사용한다.
- `alt`는 그림 내용을 설명하며, 그림을 보지 못할 때도 의미를 전한다.
- 경로 오류는 강의자가 시연하고 정상 경로로 복원한다.

실습에서는 `alt`를 고치고 홈·소개 두 링크와 돌아오기를 확인한다.

---

## 1차시 · 45–55분 — ul·ol·li

```html
<ul>
  <li>사진 찍기</li>
  <li>보드게임</li>
  <li>저녁 산책</li>
</ul>
```

`ul`은 순서 없는 목록, `ol`은 순서 있는 목록이다.
이 예제의 목록 항목 `li`는 목록 안에 둔다.

필수는 제공 취미 항목을 자기 내용으로 바꾸는 일이다.
선택 연습에서는 `ul`을 `ol`로 바꿔 번호를 보고 되돌린다.

# 2차시 — 표와 정적 방명록 폼

`강의·시연 60분 → 학생 실습 30분`

- 강의: 준비 5, table 10, form·label 20, 입력·submit 15, 링크 5, 안내 5
- 필수: 표 2행 5, label/입력 3쌍 15, 3페이지 이동 5, 캡처 5
- 제공: 소개·방명록 HTML과 홈의 방명록 메뉴 한 줄
- 시연: 표·폼 조립과 이메일 기본 검사
- 선택: 표에 가상 정보 한 행 추가

사전 배부 파일을 사용하며 `main`에서 HTML만 수정한다.

---

## 2차시 · 0–15분 — 준비 5분과 표 10분

처음 5분에 세 HTML과 메뉴·그림이 준비되어 있는지 확인한다.

```html
<table>
  <tr><th>항목</th><th>내용</th></tr>
  <tr><td>아이디</td><td>student01</td></tr>
</table>
```

- `tr`은 행, `th`는 제목 칸, `td`는 내용 칸이다.
- 제공 표는 제목 행을 포함해 2열 4행이다.
- 필수 수정은 아이디·관심 분야 두 행의 내용이다.
- 가상 이메일 행은 유지한다. 표의 선은 4주차에 CSS로 만든다.

---

## 2차시 · 15–35분 — form과 label 연결

```html
<form>
  <label for="name">이름</label>
  <input id="name" type="text">
  <label for="message">메시지</label>
  <textarea id="message" rows="4"></textarea>
</form>
```

`label for`와 입력 `id`가 같으면 이름표를 눌러 입력으로 이동한다.
실습에서는 세 `for` 값을 잠시 비운 뒤 다시 입력해 차이를 확인한다.
이름 `name`, 이메일 `email`, 메시지 `message`의 세 쌍을 유지한다.

---

## 2차시 · 35–50분 — 입력 종류와 기본 제출

```html
<input id="email" type="email">
<button type="submit">남기기</button>
```

- 이름은 한 줄 `text`, 이메일은 `email`, 메시지는 여러 줄 `textarea`다.
- `abc` 이메일은 브라우저가 제출을 막는다. JavaScript 검사가 아니다.
- `required`가 없어 빈 입력은 허용된다.
- 빈 이메일·정상 형식은 현재 페이지로 기본 GET 제출하며 입력이 초기화된다.
- 주소 끝에 `?`가 붙을 수 있다. 글 추가·저장은 아직 없다.

입력에 `name` 속성이 없어 값이 쿼리에 담기지 않는다.
5주차부터 JS 문법을 배우고, 방명록 글 추가는 7주차에 한다.

---

## 2차시 · 50–55분 — 세 페이지의 왕복 링크

```html
<nav>
  <a href="index.html">홈</a>
  <a href="about.html">내 정보</a>
  <a href="guestbook.html">방명록</a>
</nav>
```

세 페이지에서 같은 세 링크를 확인한다. 모두 아홉 경로다.
파일 이름의 철자와 대소문자를 맞춘다.

홈의 메뉴만 늘리고 1차시에 수정한 자기소개 내용은 보존한다.
브랜치 생성·merge는 이번 주 실습에 넣지 않는다.
