# 중간 개인 실기

1~7주 실습에서 **실제로 제출한 것**을 한 문제씩 모은 **문제 은행**으로 연습하고, 2일차에 같은 문제를 값만 바꿔 시험을 봅니다.

```text
1일차  문제 은행 연습 60분 — 수업에서 나간 범위의 문제를 차례로
2일차  중간 실기 — 은행 문제를 값만 바꿔 낸다 (시간·문항 수는 분반 공지)
```

- 시험 문제는 은행 문제와 **문장·할 일·확인하는 방법이 같고**, 값만 다릅니다.
- 해답은 공개하지 않습니다. 문제마다 **"확인할 것"** 과 **힌트**가 있습니다.
- 수업에서 한 실습을 다시 하는 수준입니다. 배점은 **20점**, 주차별 실습 점수가 아닙니다.

## 1일차 · 8–16분 — 문제 하나 읽는 법: w04_box_style

[w04_box_style 문제 문장](examples/w04_box_style/README.md) — 절은 여섯, 모든 문제가 같은 순서다

```text
시작 파일      받는 파일과 지금 상태. "고치지 않는다" 파일은 그대로 둔다
할 일          고칠 파일과 자리, 쓸 값. 적힌 순서대로 한다
확인할 것      화면·F12 로 스스로 맞춰 보는 목록. 해답 대신이다
힌트           막혔을 때 읽는다. 시험의 설명 물음이 이 내용이다
이 문제의 값   시험에서 바뀌는 값. w04 는 300 · black · lightgreen · 4px solid gold …
받기와 올리기  web-week08/w04_box_style/ 에 Raw 로 받는다
```

- 확인할 것 예: 배경 `black`, 글자 `lightgreen`, 테두리 `4px solid gold`, 세 줄이 가로·세로 가운데.
- 값은 표에서 **복사해 붙여 넣습니다.** 한 글자만 달라도 확인할 것이 맞지 않습니다.

**문장·할 일·확인할 것은 시험에서도 그대로다. "이 문제의 값" 표만 바뀐다.**

## 1일차 · 16–24분 — 확인하는 법: 열기와 F12

두 번 눌러 열기(`file://`) 또는 [server.mjs](../../tools/static-server/server.mjs) → `node server.mjs` → `http://localhost:8000/<문제 id>/`

```text
Console      빨간 줄(Uncaught) · console.log · 식 쳐 보기 document.querySelectorAll('li').length
Network      파일마다 Status 200 / 404 — 서버·공개 주소에서만 보인다
Elements     태그·id·href, Styles 의 값, 맨 아래 상자 그림(padding·border·내용 크기)
```

- "확인할 것"마다 볼 곳이 적혀 있습니다. 그곳을 열고 글자 하나까지 맞춰 봅니다.
- 상자 문제(w04·w05)는 Elements 의 상자 그림과 화면 위치로, 버튼·폼 문제(w06·w07)는 눌러 보고 Console 로 봅니다.
- Node 가 없는 PC 는 두 번 눌러 엽니다. 그때는 Status 번호만 보이지 않습니다.

**확인할 것은 화면과 F12 로 보는 결과다. 결과가 같으면 코드 모양은 달라도 된다.**

# 2일차 — 중간 실기

`30분 설명·시연 → 시험(공지한 시간)`

1. 시험 규칙 — 분반 공지가 정한다
2. 문제 읽는 순서 — 값이 어디가 다른지 표시
3. 답안에 넣을 것 — 코드·캡처·설명
4. 제출과 끝내기 전

---

## 2일차 · 0–8분 — 시험 규칙: 분반 공지가 정한다

```text
문항   은행 문제를 값만 바꿔 2~4문제      시간   30~60분 (시작·끝 시각은 공지)
범위   수업에서 나간 주차까지            제출   LMS 답안 칸 또는 저장소 web-week08/exam/
```

- 볼 수 있는 것(교재 사이트·본인 파일·MDN)과 AI 도구 허용 여부는 공지를 따릅니다.
- 문제끼리 이어지지 않습니다. **한 문제에 오래 막히면 다음 문제로 갑니다.**
- 다 못 했어도 쓴 코드·캡처·시도한 것(오류 메시지)을 냅니다. 부분 점수가 있습니다.
- 질문은 문장의 뜻·파일 위치·제출 방법·장애만 받습니다. 코드가 맞는지는 답하지 않습니다.

**규칙은 공지 한 장에 다 있다. 시작 전에 다시 읽는다.**

---

## 2일차 · 8–16분 — 문제 읽는 순서: 값이 어디가 다른지

```text
은행 w04    상자 300×300 · black · lightgreen · 4px solid gold · padding 8
시험 문제   상자 320×200 · navy  · yellow     · 3px dashed white · padding 12   ← 값만 다르다
```

1. 문제를 끝까지 읽고, "이 문제의 값"에서 은행과 다른 값에 표시합니다.
2. 시작 파일이 있으면 1일차처럼 받아 문제 폴더에 둡니다.
3. 할 일을 위에서부터 한 덩어리씩 → 저장 → 새로고침 → Console.
4. "확인할 것"을 하나씩 맞춥니다. 맞지 않으면 그 항목이 가리키는 할 일로 돌아갑니다.

**3분 안에 읽기를 끝내고, 값은 복사해 붙인다.**

---

## 2일차 · 16–24분 — 답안에 넣을 것: 코드·캡처·설명

[채점표](rubric.md) — 결과(확인할 것) 약 60% · 실행 증거(캡처) 약 20% · 설명 약 20%

```text
① 코드    고친 파일 전체, 또는 고친 부분이 분명한 코드
② 캡처    요구한 상태의 브라우저 화면 — 주소창이 보이게. F12 항목은 그 패널까지
③ 설명    문제가 묻는 물음에 자기 말로 1~2문장 (힌트에 있는 내용 수준)
```

- 채점은 "확인할 것"으로 봅니다. 완전 충족 · 부분 충족(맞은 만큼) · 미충족.
- 원인이 하나면 한 번만 깎습니다. 실행 결과가 없어도 시도·설명은 점수가 있습니다.
- 설명 예: "row 방향에서 `justify-content` 는 가로, `align-items` 는 세로를 맡는다."

**코드 모양이 아니라 결과·캡처·설명을 본다.**

## 2일차 · 24–30분 — 제출과 끝내기 전

[2일차 실습](lab.md#2일차--중간-실기-공지한-시간) · [따라하기](walkthrough.md#2일차) · [실습 페이지](https://github.com/gbox3d/teaching_repo/tree/main/web_programming/weeks/week08_midterm)

```text
끝나기 5분 전   문제마다 코드 → 캡처 → 설명이 있는지 본다
LMS 방식       답안 칸에 그 순서로 붙여 넣고 제출
저장소 방식     git add . → git commit -m "중간 실기 끝" → git push → 공개 주소·저장소 주소·Commits 탭 캡처
```

- 저장하지 않은 파일은 올라가지 않습니다. 캡처에 실명·학번·실제 이메일이 보이지 않게 합니다.
- Pages 가 늦으면 로컬 화면 캡처로 냅니다. 감점하지 않습니다.
- 공용 PC 면 자격 증명을 지우고 나갑니다.

**설명 합계: 8+8+8+6 = 30분**

## 제출하기

2일차 시험이 끝나면 분반 공지가 정한 곳에 냅니다. [제출](lab.md#제출)

```text
LMS 답안 칸     문제마다 코드 · 캡처 · 설명
저장소 방식     ① 공개 주소 https://student01.github.io/web-week08/exam/
               ② 저장소 주소 https://github.com/student01/web-week08
               ③ Commits 탭 캡처 1장 — 맨 위 commit 의 번호와 시각
```

1일차 연습 폴더는 제출하지 않습니다. 점수에 들어가지 않습니다.
캡처에 실명·학번·실제 이메일이 보이지 않게 합니다. 제출 기한은 공지한 시각입니다.
