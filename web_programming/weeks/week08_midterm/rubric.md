# 중간 개인 실기 채점표 — 20점 (안)

배점은 강의계획 비중 재배분 승인 전까지 **안**이다. 확정 배점은 시험 전에 공지한다.
채점 대상은 제출한 공개 URL과 `my-web/exam/` 폴더의 세 파일이다.

| 영역 | 배점 | 충족 기준 |
|---|---:|---|
| Pages 배포·commit 2개 이상 | 3 | `https://<아이디>.github.io/my-web/exam/`이 열리고, `exam/`에 세 파일이 있으며, `exam/`에 남은 commit이 2개 이상이다(starter를 넣은 첫 commit `중간 실기 시작` + 마지막 commit `중간 실기`) |
| HTML 구조 | 4 | 뼈대(`header`·`nav`·`main`·`footer`), 문제가 요구한 목록·표, `label for`와 `input id`가 연결된 폼 |
| CSS | 4 | 문제가 지정한 선택자·색·박스·`display: flex`·`@media` 중 요구된 것이 화면에 나타난다 |
| DOM 이벤트 | 5 | 버튼 클릭으로 `textContent`가 바뀌고, `classList`로 모양이 바뀐다 |
| 폼 입력·빈값 안내 | 3 | 제출하면 입력한 값이 화면에 보이고, 비우고 제출하면 안내가 보이며 값이 표시되지 않는다 |
| Console 오류 없음 | 1 | 페이지를 열고 요구 동작을 한 번씩 했을 때 `Uncaught`로 시작하는 빨간 줄이 없다. CSS·이미지를 못 찾은 404 한 줄(`Failed to load resource`)은 요구 동작이 정상이면 감점하지 않는다 |
| 합계 | 20 | |

## 수준별 판단

### 완전 충족

요구한 화면과 동작이 채점자의 브라우저에서 그대로 재현된다. 다른 기능을 건드리지 않고, Console에 빨간 줄이 없으며,
제출한 commit SHA의 파일과 공개 주소의 화면이 같다.

### 부분 충족

화면은 만들어졌지만 특정 입력이나 특정 폭에서 동작하지 않는다. 예를 들어 버튼은 동작하는데 빈값 안내가 없거나,
`@media`를 썼는데 375px에서 바뀌지 않는다. 실행되는 부분 결과가 있어야 부분 점수를 준다.

### 미충족

열리지 않거나, 요구와 무관한 결과이거나, 채점할 파일·URL이 없다.

- **실행 실패 제출의 5점 floor**: 구현 시도 흔적(`exam/` 폴더의 세 파일과 commit 1개 이상)이 있으면 5점을 준다.
  적용 여부는 강의자 결정 사항이며, 적용하면 15주 기말에도 같은 규칙을 쓴다.

## 감점 적용 원칙

- 원인이 하나인데 증상이 여럿이면 한 번만 감점하고 그렇게 기록한다.
- 영역별 최대 배점을 넘겨 깎지 않는다.
- 색이 예쁘지 않은 것과 기능이 동작하지 않는 것을 같은 수준으로 보지 않는다.
- 범위 밖 기능(배열 목록·`localStorage`·`fetch`·모듈)은 가점하지 않는다. 그 때문에 요구 동작이 멈추면 해당 영역에서만 감점한다.
- Pages 반영 지연으로 공개 주소가 늦게 뜨는 경우는 감점하지 않는다. 로컬 화면 캡처와 commit SHA로 확인한다.
- 제출 장애는 학생의 구현 오류와 구분해 기록한다.
