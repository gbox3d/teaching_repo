# 중간 개인 실기 채점표 — 20점 (안)

배점은 강의계획 비중 재배분 승인 전까지 **안**이다. 확정 배점은 시험 전에 공지한다.
채점 대상은 제출한 공개 주소 `https://<아이디>.github.io/web-week08/exam/` 와 저장소 `web-week08` 의 `exam` 폴더다. 1일차 연습 폴더는 채점하지 않는다.
제출본은 마감(시험 60분이 끝나는 시각) 전 마지막 commit 을 공개 주소에서 연 화면이다. 마감 뒤에 올린 commit 은 채점하지 않는다. 세 가지를 내는 곳과 기한은 수업 공지를 따른다.

| 영역 | 배점 | 충족 기준 |
|---|---:|---|
| 제출·공개 | 3 | 제출 세 가지(공개 주소·저장소 주소·GitHub **Commits** 탭 캡처)를 냈다. 공개 주소에서 목차가 열리고, 목차의 링크로 문제마다 첫 페이지가 열린다. 저장소 맨 위에 `exam` 폴더가 있고, 시험 시간에 올린 commit 이 두 번 이상(`중간 실기 시작` + `중간 실기 끝`)이다 |
| A HTML | 4 | 문제 A 의 "확인할 것"이 모두 맞는다 |
| B CSS | 4 | 문제 B 의 "확인할 것"이 모두 맞는다 |
| C JavaScript·DOM | 5 | 문제 C 의 "확인할 것"이 모두 맞는다 |
| D 폼 | 3 | 문제 D 의 "확인할 것"이 모두 맞는다 |
| Console 오류 없음 | 1 | 목차와 네 문제 페이지를 열고 요구 동작을 한 번씩 했을 때 `Uncaught` 로 시작하는 빨간 줄이 없다 |
| 합계 | 20 | |

영역마다 나올 수 있는 은행 문제는 [README 의 이번 주 범위](README.md#이번-주-범위)와 [문제 은행 목록](examples/README.md)에 있다.
시험 문제는 은행 문제와 같은 문제를 값만 바꾼 것이라 "확인할 것"의 항목도 은행 문제와 같은 모양이다.

## 채점하는 방법

- 채점자는 제출한 공개 주소의 목차에서 문제마다 페이지를 열고, 문제지(`exam/README.md`)의 "확인할 것"을 위에서부터 하나씩 해 본다.
- 결과로 본다. 화면 글자, 계산된 스타일(F12 › Elements › Computed), Console, Network 로 확인한다.
- 어떤 방법으로 썼는지(`var`·`getElementById`·`innerText` 등)는 채점하지 않는다. "확인할 것"의 결과가 같으면 정답이다.
- 강의자는 항목별 확인을 돕는 도구를 먼저 돌려 볼 수 있다. 최종 판정은 채점자가 화면으로 한다.
- Pages 반영이 늦어 공개 주소가 옛 화면이면 채점자가 다음 날 다시 연다.

## 수준별 판단

### 완전 충족

그 문제의 "확인할 것"이 모두 채점자의 브라우저에서 그대로 재현된다. 다른 기능을 건드리지 않고, Console 에 빨간 줄이 없으며,
공개 주소의 화면이 마감 전 마지막 commit 의 파일과 같다.

### 부분 충족

"확인할 것"의 일부 항목만 맞는다. 예를 들어 버튼은 동작하는데 횟수 문장이 틀리거나, 기준 폭을 썼는데 375px 에서 메뉴가 바뀌지 않는다.
실행되는 부분 결과가 있어야 부분 점수를 준다. 점수는 배점 안에서 맞은 만큼 준다. 실행되는 결과가 없는 코드는 부분 충족으로 보지 않는다.

### 미충족

열리지 않거나, 요구와 무관한 결과이거나, 채점할 파일·주소가 없다. 그 영역은 0점이다.

- **실행 실패 제출의 5점 하한(floor)**: 구현 시도 흔적이 있으면 최소 5점을 준다는 규칙이다.
  적용 여부는 강의자가 아직 정하지 않았다(**미정**). 적용하면 15주 기말에도 같은 규칙을 쓴다. 정해지면 수업 공지로 알린다.

## 감점 적용 원칙

- 원인이 하나인데 증상이 여럿이면 한 번만 감점하고 그렇게 기록한다.
- 영역별 최대 배점을 넘겨 깎지 않는다.
- 색이 예쁘지 않은 것과 기능이 동작하지 않는 것을 같은 수준으로 보지 않는다. 모양은 "확인할 것"에 적힌 값만 본다.
- 범위 밖 기능(배열 목록·`localStorage`·`fetch`·모듈·외부 라이브러리)은 가점하지 않는다. 그 때문에 요구 동작이 멈추면 해당 영역에서만 감점한다.
- Pages 반영 지연으로 공개 주소가 늦게 뜨는 경우는 감점하지 않는다. 채점자가 다음 날 다시 열고, 로컬 화면 캡처와 Commits 탭 캡처로도 확인한다.
- Console 1점은 `Uncaught` 로 시작하는 빨간 줄만 본다. 파일을 못 찾은 404 줄(`Failed to load resource`, `favicon.ico` 포함)은 이 1점에서 보지 않는다.
  파일 연결 자체를 묻는 문제(은행의 [w01_link_fix](examples/w01_link_fix/) 같은 문제)에서는 그 404 를 그 문제의 "확인할 것"으로, 그 문제 점수에서만 본다.
- 제출 장애(Pages 지연·자격 증명 충돌)는 학생의 구현 오류와 구분해 기록한다.
- 실명·학번·전화번호·실제 이메일이 공개 페이지나 캡처에 있으면 점수와 별개로 즉시 고치게 한다.

## Pages 반영 지연과 장애

| 상황 | 처리 |
|---|---|
| Pages 반영이 5분 넘게 늦다 | 감점하지 않는다. 채점자가 다음 날 공개 주소를 다시 연다. 로컬 화면 캡처와 Commits 탭 캡처도 인정한다 |
| 공용 PC의 자격 증명 충돌로 push 가 막힌다 | 자격 증명 관리자에서 `git:https://github.com` 을 지우고 다시 로그인한다. 그래도 막히면 손을 들고, 감독이 시각을 기록한 뒤 폴더를 압축해 제출한다 |
| 네트워크나 GitHub 가 끊겨 올릴 수 없다 | 손을 들어 감독이 시각을 기록한다. 폴더를 압축하고 서버로 연 화면 캡처와 함께 제출한다 |
| 개인 PC 고장 | 손을 들어 감독 확인을 받고, 예비 PC 에서 저장소를 내려받아 마지막으로 올린 것부터 이어 간다 |

## 채점 기록 양식

```text
응시 식별자:
채점 시각:
공개 주소:      https://<아이디>.github.io/web-week08/exam/
저장소 주소:    https://github.com/<아이디>/web-week08
맨 위 commit:   번호            시각            (Commits 탭 캡처, 마감 전인지)

제출·공개                    /3   근거:
A HTML            (문제 a)   /4   근거:
B CSS             (문제 b)   /4   근거:
C JavaScript·DOM  (문제 c)   /5   근거:
D 폼              (문제 d)   /3   근거:
Console 오류 없음            /1   근거:
합계                        /20

확인한 화면:
비고(장애·지연 기록):
```

근거에는 맞지 않은 "확인할 것" 항목과 그때 본 화면(글자·Console 줄)을 적는다.
