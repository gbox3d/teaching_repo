# 중간 개인 실기 채점표 — 20점

채점 대상은 분반 공지가 정한 제출물(LMS 답안 또는 저장소 `web-week08/exam/`)이다. 1일차 연습 폴더는 채점하지 않는다.
시험 문제는 은행 문제와 같은 문제를 값만 바꾼 것이라, 채점도 그 문제의 **"확인할 것"** 으로 한다. 어떤 방법으로 썼는지(`var`·`getElementById`·`innerText` 등)는 보지 않는다. 결과가 같으면 정답이다.

## 문제마다 보는 것

| 보는 것 | 비율 | 어떻게 본다 |
|---|---:|---|
| 결과(확인할 것) | 약 60% | 그 문제의 "확인할 것"이 제출한 코드·캡처에서 맞는지 항목마다 본다. 저장소 제출이면 채점자가 공개 주소를 열어 직접 해 본다 |
| 실행 증거(캡처) | 약 20% | 브라우저 화면(주소창 포함)이나 F12 화면이 요구한 상태를 보여 준다. 수업 과제의 캡처와 같다 |
| 설명 | 약 20% | 문제가 묻는 속성·명령의 뜻을 자기 말로 1~2문장 썼다. 힌트에 있는 내용 수준이면 된다. 한국어·영어 어느 쪽이든 내용으로 본다 |

문제가 2개면 문제당 10점이다. 문제가 4개면 영역 배점(A HTML 4 · B CSS 4 · C JavaScript·DOM 5 · D 폼 3)에 제출·Console 4점을 더해 20점이다. 어느 쪽인지는 분반 공지에 적는다.

## 수준별 판단

### 완전 충족

"확인할 것"이 모두 맞고, 캡처가 그 상태를 보여 주며, 설명이 정확하다. 다른 기능을 건드리지 않았고 Console 에 빨간 줄이 없다.

### 부분 충족

일부 항목만 맞는다. 예를 들어 상자 색·테두리는 맞는데 세로 가운데가 안 됐다, 버튼을 누르면 글자는 바뀌는데 횟수가 늘지 않는다, push 는 안 됐지만 commit 까지의 `git log` 와 오류 메시지를 적었다. 맞은 만큼 준다.
실행되는 결과가 하나도 없는 코드는 결과 점수는 없지만, 시도한 코드·오류 메시지·설명이 있으면 설명과 시도 점수는 받을 수 있다.

### 미충족

제출이 없거나 요구와 무관한 결과다. 그 문제는 0점이다.

## 감점 적용 원칙

- 원인이 하나인데 증상이 여럿이면 한 번만 감점하고 그렇게 기록한다. 예: `querySelector` 선택자 오타 하나로 글자와 횟수가 모두 안 바뀐 경우.
- 문제별 배점을 넘겨 깎지 않는다.
- 색이 예쁘지 않은 것과 기능이 동작하지 않는 것을 같은 수준으로 보지 않는다. 모양은 "확인할 것"에 적힌 값만 본다.
- 범위 밖 기능은 가점하지 않는다. 그 때문에 요구 동작이 멈추면 그 문제에서만 감점한다.
- Console 의 빨간 줄은 `Uncaught` 로 시작하는 줄만 본다. `favicon.ico` 404 는 보지 않는다.
- 제출 장애(Pages 지연·자격 증명 충돌·LMS 오류)는 학생의 구현 오류와 구분해 기록한다. Pages 지연으로 늦게 뜬 공개 주소는 채점자가 다음 날 다시 연다. 로컬 화면 캡처도 인정한다.
- 실명·학번·전화번호·실제 이메일이 공개 페이지나 캡처에 있으면 점수와 별개로 즉시 고치게 한다.

## 채점 기록 양식

```text
응시 식별자:
채점 시각:
제출 위치(LMS 답안 / 공개 주소 / 저장소):

문제 1 (은행 wNN)   결과   /   캡처   /   설명   /   소계   /
문제 2 (은행 wNN)   결과   /   캡처   /   설명   /   소계   /
(문제 3·4가 있으면 같은 줄을 더한다)
합계                                              /20

맞지 않은 "확인할 것" 항목과 그때 본 화면(글자·Console 줄):
비고(장애·지연 기록):
```

학생 코드·이름·학번·점수가 들어간 기록은 공개 저장소에 올리지 않는다.
