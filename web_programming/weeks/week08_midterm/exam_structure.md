# 중간 개인 실기 구조

이 문서는 공개해도 되는 시험 구조다. 시험에 내는 문제의 값과 해답은 공개하지 않는다.
시간·문항 수·볼 수 있는 것·제출 방법은 **분반 공지가 정한다.** 이 문서와 공지가 다르면 공지가 우선한다.

## 시험 문제 — 문제 은행에서, 값만 바꿔

- 1~7주 실습 제출을 한 문제씩으로 정리한 [문제 은행](examples/README.md)이 공개돼 있다. 문제마다 시작 파일·할 일·확인할 것·힌트·이 문제의 값이 있고, 해답은 공개하지 않는다.
- 시험 문제는 은행 문제와 **같은 문제를 값만 바꾼 것**이다. 문장·할 일·확인하는 방법은 같고, "이 문제의 값" 표의 값(글자·색·크기·위치·id·파일 이름·횟수 등)만 다르다. 은행에 보이는 값이 시험에 그대로 나오지 않는다.
- 범위는 1~7주 가운데 **수업에서 나간 주차까지**다. 어디까지인지는 분반 공지에 적는다.
- 문제끼리 이어지지 않는다. 한 문제를 못 풀어도 다른 문제는 풀 수 있다.
- 15주 기말도 같은 방식이다. 기말 은행은 1~14주 누적이라 이 일곱 문제도 들어 있고, 다시 나오면 8주와 다른 값으로 나온다.

## 시험 형식 — 분반 공지가 정한다

기본 틀은 아래와 같다. 분반마다 공지로 확정한다.

| 항목 | 기본 틀 | 공지에서 정하는 것 |
|---|---|---|
| 문항 | 은행 문제를 값만 바꿔 **2~4문제** | 몇 문제, 어느 영역 |
| 시간 | **30~60분** | 시작·끝 시각 |
| 답안 | 문제마다 ① 고친 코드(또는 파일) ② 실행 화면 캡처(브라우저·주소창, 필요하면 F12) ③ 문제가 묻는 설명 1~2문장(자기 말로) | 설명 물음의 수 |
| 제출 | LMS 답안 칸에 코드와 캡처를 붙여 넣기, 또는 저장소 `web-week08/exam/` 에 올려 공개 주소·저장소 주소·Commits 탭 캡처를 내기 | 둘 중 어느 쪽 |
| 볼 수 있는 것 | 교재 사이트, 본인 저장소·파일, MDN | AI 도구 허용 여부 등 |

- 설명 물음은 그 문제에서 쓴 속성·명령의 뜻을 묻는다. 예: `justify-content` 와 `align-items` 가 각각 어느 방향을 맡는지, `add`·`commit`·`push` 가 각각 무엇을 하는지, `file://` 과 `http://` 의 차이. 수업과 은행 문제의 힌트에 있는 내용이다.
- 실행 결과가 없어도 시도한 코드와 오류 메시지·설명을 적으면 부분 점수가 있다([채점표](rubric.md)).

## 운영

### 1일차 — 문제 은행으로 연습

- 설명 30분: 이번 주는 문제 은행과 시험(같은 문제·값만 바뀜·해답 비공개·확인할 것·힌트), 문제 하나 읽는 법(공개 문제 [w04_box_style](examples/w04_box_style/)), 확인하는 법(열기, F12 Console·Network·Elements), 오늘 순서.
- 연습 60분: 수업에서 나간 범위의 문제를 차례로 푼다. 문제마다 10분 안팎. [w02_push_repo](examples/w02_push_repo/) 로 GitHub 로그인과 push 를 미리 확인한다.
- 1일차 결과는 점수에 넣지 않는다.

### 2일차 — 중간 실기

- 설명 30분: 시험 규칙(분반 공지), 문제 읽는 순서(값이 어디가 다른지 표시), 답안에 넣을 것(코드·캡처·설명), 제출 방법, 장애가 났을 때.
- 시험: 공지한 시간. 한 문제에 오래 막히면 다음 문제로 간다. 다 못 했어도 쓴 코드와 캡처, 시도한 것을 낸다.
- 질문은 문장의 뜻·파일 위치·제출 방법·환경 장애만 받는다. 코드가 맞는지는 알려 주지 않는다.

## 시작 전 감독 체크

- 모든 PC 에서 VS Code 와 브라우저가 열리고 F12 가 뜬다. Node 가 없는 PC 는 두 번 눌러 연다.
- 저장소 제출 방식이면 1일차에 `web-week08` 을 만들고 push 가 되는지 확인했다.
- LMS 제출 방식이면 답안 칸에 캡처 붙이기가 되는지 시험 전에 확인했다.
- 앞 사람의 GitHub 로그인이 남아 있지 않다(자격 증명 삭제 확인).
- 장애 기록 시각과 대체 제출 창구가 준비됐다.

## 공정성

- 문제 문장의 뜻, 파일 위치, 제출 방법, 환경 장애는 모든 학생에게 같은 수준으로 안내한다.
- 구현 방법과 코드가 맞는지는 알려 주지 않는다.
- 추가 시간·대체 평가는 대학 규정과 공식 기록을 따른다.
- 학생 코드·점수·개인정보는 공개 저장소에 올리지 않는다.

## 공개 저장소에 두지 않는 것

- 시험에 내는 문제의 값, 해답과 부분 해답
- 수험생 명단, 제출 주소, 점수와 이의 신청 기록
