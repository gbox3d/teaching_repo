# 중간 개인 실기 구조

이 문서는 공개해도 되는 시험 구조다. 시험에 내는 문제의 값과 해답은 공개하지 않는다.
배점은 강의계획 비중 재배분 승인 전까지 **안**이다.

## 시험 문제 — 문제 은행에서 영역마다 한 문제

- 1~7주 실습 제출을 한 문제씩으로 정리한 [문제 은행](examples/README.md)이 공개돼 있다. 문제마다 시작 파일·할 일·확인할 것·이 문제의 값이 있고, 해답은 공개하지 않는다.
- 시험은 이 은행에서 영역(A~D)마다 한 문제씩, 모두 **네 문제**를 낸다.
- 시험 문제는 은행 문제와 **같은 문제를 값만 바꾼 것**이다. 문장·할 일·확인하는 방법은 같고, "이 문제의 값" 표의 값(이름·문장·색·크기·기준값·id·class·파일 이름·개수 등)만 다르다. 은행에 보이는 값이 시험에 그대로 나오지 않는다.
- 문제끼리 이어지지 않는다. 한 문제를 못 풀어도 다른 문제는 풀 수 있다.
- 15주 기말도 같은 방식이다. 기말 은행은 1~14주 누적이라 이 일곱 문제도 들어 있고, 다시 나오면 8주와 다른 값으로 나온다.

## 범위

범위는 1~7주다. 은행 문제는 문제마다 그 주에 배운 것만 쓰게 만들었고, 다른 주의 내용은 시작 파일에 들어 있다.

**출제하지 않는 것**: 배열로 목록 그리기(10주), `localStorage`(11주), `fetch`·JSON(12주), ES Module(`import`·`export`), 외부 라이브러리·CDN, 서버·데이터베이스.
범위 밖 기능을 써도 가점은 없다.

## 1·2일차 운영

### 1일차 — 문제 은행으로 연습

- 설명 30분: 이번 주는 문제 은행과 시험(같은 문제·값만 바뀜·해답 비공개·확인할 것), 문제 하나 읽는 법(공개 문제 w05_greeting_card), 확인하는 법(서버로 열기, F12 Console·Network·Elements, 기기 모드), 오늘 순서와 저장소 만들기·Pages.
- 연습 60분: **0–5 문제 고르기 · 5–20 첫 문제 · 20–35 둘째 문제 · 35–50 셋째 문제 · 50–60 저장소 `web-week08` 만들기 → 연습 폴더 올리기 → Pages 켜기 → 공개 주소에서 확인**.
- 1일차에 반드시 끝내는 것: **새 저장소 `web-week08` 만들기 → push → Pages 켜기**. 공용 PC 의 자격 증명 문제도 이날 겪고 끝낸다.
- 1일차 결과는 점수에 넣지 않는다.

### 2일차 — 중간 실기

- 설명 30분: 시험 규칙(볼 수 있는 것·범위·막히면 넘어가기·시간표), `exam` 폴더 받기·저장소 맨 위에 넣기·목차 열기·시작 올리기, 영역·배점·채점, 끝내기 전(마지막 올리기·공개 주소·Commits 탭 캡처).
- 시험 60분: **0–5 읽기 · 5–15 A · 15–27 B · 27–39 C · 39–50 D · 50–55 올리기 · 55–60 예비**.
- 예비 5분은 Pages 반영(1~3분)과 다시 로그인을 흡수한다.
- 볼 수 있는 것: 교재 사이트, 본인 저장소, MDN. 그 밖은 강의자 공지를 따른다.
- 한 문제에 5분 넘게 막히면 다음 문제로 간다.
- 시험 중에 저장소 만들기·Pages 켜기가 없다. 1일차에 만든 `web-week08` 에 `exam` 폴더를 넣기만 한다.
- 기관 시험 시간표가 다르면 총 평가 시간과 안내 시간을 나누어 미리 공지한다.

## 받는 것 — exam 폴더

시험 시작 때 강의자가 `exam` 폴더를 나눠 준다. 받는 곳은 강의자가 공지한다.

```text
exam/
  README.md      ← 문제 문장 넷 전체
  index.html     ← 목차. 문제마다 첫 페이지로 가는 링크
  a/  b/  c/  d/ ← 문제 폴더. 시작 파일만 있다
```

- 문제 문장은 `exam/README.md` 한 곳에 있다. 문제마다 은행 문제와 같은 네 절(시작 파일·할 일·확인할 것·이 문제의 값)이 있고, 그 문제의 폴더(`exam/a/` 등)와 권장 분이 적혀 있다.
- 문제 폴더에는 시작 파일만 있다. 문제마다 그 폴더 안의 파일만 고친다.
- 목차는 문제마다 첫 페이지로 이어진다. 첫 페이지가 `index.html` 이 아닌 문제도 목차의 링크로 열린다.

## 저장소와 올리기

- 저장소는 1일차에 만든 `web-week08` 하나다(매주 새 저장소 규칙). 2일차에는 새로 만들지 않는다.
- 받은 `exam` 폴더를 저장소 맨 위에 그대로 넣는다. `web-week08/exam/index.html` 이 된다.
- 시작하자마자 한 번 올린다(`중간 실기 시작`). 끝날 때 마지막으로 올린다(`중간 실기 끝`). 중간에 더 올려도 된다.
- 공개 주소는 `https://<아이디>.github.io/web-week08/exam/`(목차)다.

## 제출

1. 공개 주소 `https://<아이디>.github.io/web-week08/exam/`
2. 저장소 주소 `https://github.com/<아이디>/web-week08`
3. GitHub **Commits** 탭 캡처 1장 — 맨 위 commit 의 번호와 시각이 보이게

- 제출본은 마감 전 마지막 commit 을 공개 주소에서 연 화면이다. 마감 뒤에 올린 commit 은 채점하지 않는다. 채점은 `exam` 폴더만 본다.
- Pages 반영 지연은 감점하지 않는다. 채점자가 다음 날 다시 연다. 로컬 화면 캡처와 Commits 탭 캡처도 인정한다.
- 채점이 끝날 때까지 저장소를 지우거나 이름을 바꾸지 않는다.

## 시작 전 감독 체크

- 모든 PC 에서 `web-week08` 폴더가 열리고, `node server.mjs` 가 뜨거나(Node 가 없으면 두 번 눌러 열기) F12 가 열린다.
- 1일차에 저장소를 만들지 못한 학생은 시험 전에 만들고 Pages 를 켰다.
- 앞 사람의 GitHub 로그인이 남아 있지 않다(자격 증명 삭제 확인).
- 나눠 줄 `exam` 폴더에 답안이나 이전 학생의 파일이 없다. 파일 이름의 대소문자가 문제 문장과 같다. 공개 주소는 대소문자를 구분한다.
- 장애 기록 시각과 대체 제출 창구가 준비됐다.

## 공정성

- 문제 문장의 뜻, 파일 위치, 제출 방법, 환경 장애는 모든 학생에게 같은 수준으로 안내한다.
- 구현 방법과 코드가 맞는지는 알려 주지 않는다.
- 추가 시간·대체 평가는 대학 규정과 공식 기록을 따른다.
- 학생 코드·점수·개인정보는 공개 저장소에 올리지 않는다.

## 공개 저장소에 두지 않는 것

- 시험에 내는 문제와 값, 해답과 부분 해답
- 수험생 명단, 제출 주소, 점수와 이의 신청 기록
