# 8주차 실습 — 문제 은행으로 연습하고 중간 실기 보기

이번 주 실습은 새로 배우는 것이 아니라 **1~7주에 수업에서 한 것을 혼자 다시 만들어 보는 것**이다.
1일차에는 [문제 은행](examples/README.md)에서 수업에서 나간 범위의 문제를 차례로 풀고, 2일차에는 같은 문제를 값만 바꾼 중간 실기를 본다.
문제마다 해답 대신 **확인할 것**과 **힌트**가 있다. 화면과 F12(Console·Network·Elements)로 그 항목을 하나씩 맞춰 보는 것이 이번 주 실습이다.
받는 법·여는 법·올리는 법은 [따라하기](walkthrough.md)에 있다. `student01` 은 예시 아이디이므로 본인 아이디로 바꾼다.

| 5–15분 | [w01_first_page](examples/w01_first_page/) 첫 페이지 만들기 — 받기 → 열기 → 할 일 → "확인할 것" 맞추기 |
| 15–25분 | [w04_box_style](examples/w04_box_style/) 상자 꾸미기와 글자 가운데 |
| 25–35분 | [w05_box_position](examples/w05_box_position/) 틀 안의 상자를 지정 위치에 |
| 35–45분 | [w03_second_page](examples/w03_second_page/) 새 페이지와 링크로 오가기 |
| 45–55분 | [w02_push_repo](examples/w02_push_repo/) 고치고 올리기 — 저장소 `web-week08` 을 만들어 올린다. GitHub 로그인이 되는지 여기서 확인한다 |

문제마다 10분을 잡았다. 권장 분 안에 끝나는지 재 본다. 10분이 되면 남은 항목은 두고 다음 문제로 간다. 시험의 "막히면 넘어가기"를 미리 연습하는 것이다.

### 1. 문제 고르기

[은행 목록](examples/README.md)을 연다. 1~7주 실습 제출이 문제 일곱 개로 정리돼 있다. [따라하기 2단계](walkthrough.md#2-문제-하나-읽는-법-w04_box_style)를 본다.

- 영역은 넷이다. A HTML(w01·w02·w03), B CSS(w04·w05), C JavaScript·DOM(w06), D 폼(w07). 수업에서 나간 주차까지가 범위다. 어디까지인지는 분반 공지에 적혀 있다.
- 자신 없는 문제부터 고른다. 그 주 실습을 끝내지 못했거나 제출 캡처를 못 낸 주가 먼저다.
- 문제 문장 제목 아래 줄의 출처 링크로 그 주 실습지를 열어 둔다. 그 주에 같은 것을 다른 값으로 만든 과정이 있다.
- 시험 문제는 은행 문제와 같고 값만 다르다. 어느 문제가 나올지는 미리 알려 주지 않는다.

### 2. 문제 하나 풀기 (받기 · 열기 · 할 일 · 확인할 것)

[따라하기 2~5단계](walkthrough.md#2-문제-하나-읽는-법-w04_box_style)에 공개 문제 w04_box_style 로 같은 순서를 보였다.

- 받기: `web-week08` 안에 문제 id 와 같은 이름의 폴더를 만들고, 문제 폴더의 시작 파일을 **Raw** 로 받아 같은 이름으로 저장한다. 문제 문장 `README.md` 는 받지 않는다.
- 열기: 파일을 두 번 눌러 열거나, `web-week08` 맨 위에서 `node server.mjs` → `http://localhost:8000/<문제 id>/` 를 연다. Network 의 Status 번호를 보라는 항목만 서버가 필요하다.
- 할 일: "시작 파일" 표에서 고칠 파일과 고치지 않을 파일을 먼저 본다. 할 일을 위에서부터 한 덩어리씩 하고, 덩어리마다 저장 → 새로고침 → Console 을 본다.
- 확인할 것: 항목마다 화면이나 F12 로 직접 해 본다. 모두 맞으면 된 것이다. 맞지 않는 항목이 있으면 그 항목이 가리키는 할 일로 돌아간다. 막히면 **힌트**를 읽는다.
- 흔한 실수: 값을 손으로 옮겨 적다가 글자 하나·빈칸 하나·마침표 하나가 달라진다. 값은 문제 문장에서 **복사해 붙인다**.
- 흔한 실수: 할 일에 없는 것까지 고친다. "고치지 않는다"고 적힌 파일은 열어 보기만 한다.

### 3. 올리기 — w02_push_repo

GitHub 에서 **New repository** → 이름 `web-week08`, **Public**, README 는 추가하지 않는다. VS Code 터미널(현재 폴더 `web-week08`)에서 2주차에 배운 순서 그대로 친다. 서버가 떠 있는 터미널에서는 칠 수 없으니 **Terminal › New Terminal** 로 하나 더 연다.

```bash
git init
git add .
git commit -m "8주차 연습"
git branch -M main
git remote add origin https://github.com/student01/web-week08.git
git push -u origin main
```

그다음 w02 문제의 할 일대로 파일을 고쳐 `git add .` → `git commit -m "…"` → `git push` 를 한 번 더 한다. GitHub 저장소 화면에 폴더와 commit 메시지가 보이면 된 것이다.
**Settings › Pages › Branch: main, /(root) › Save** 를 켜 두면 1~3분 뒤 `https://student01.github.io/web-week08/<문제 id>/` 로 연습한 문제를 볼 수 있다. 공용 PC 면 자격 증명을 지우고 나간다.

### 오늘 확인할 것

- [ ] 수업에서 나간 범위의 문제를 풀어 "확인할 것"을 스스로 맞춰 봤고, 맞추지 못한 항목이 무엇인지 안다.
- [ ] 저장소 `web-week08` 이 있고 push 가 됐다(w02).
- [ ] 각 문제의 힌트에 있는 설명(예: `justify-content` 와 `align-items` 의 방향, `add`·`commit`·`push` 의 뜻)을 한 문장씩 말할 수 있다.

1일차 결과는 점수에 들어가지 않는다. **어디서 막혔는지 알고 가는 것**이 목적이다.

## 2일차 — 중간 실기 (공지한 시간)

| 시간 | 할 일 |
|---|---|
| 시작 전 | 분반 공지를 다시 읽는다. 시작·끝 시각, 문제 수, 볼 수 있는 것, 내는 곳. VS Code·브라우저를 켜 두고 저장소 제출이면 GitHub 로그인까지 해 둔다 |
| 0–3분 | 문제를 읽는다. 문제마다 "이 문제의 값"이 은행 문제와 어디가 다른지 표시한다. 아직 코드를 쓰지 않는다 |
| 3–50분 | 문제마다: 시작 파일 받기(있으면) → 열기 → 할 일 → 확인할 것 → 캡처 → 설명 1~2문장. 오래 막히면 다음 문제로 |
| 50–55분 | 답안 정리: 문제마다 코드·캡처·설명이 있는지 본다 |
| 55–60분 | 제출(공지한 곳에). 저장소 방식이면 마지막 올리기와 Commits 탭 캡처 |

위 표는 시험이 60분일 때의 배분이다. 공지가 30분이면 읽기 2분 · 풀기 25분 · 정리와 제출 3분처럼 비율대로 줄인다. 분 단위 순서는 [따라하기 2일차](walkthrough.md#2일차)에 있다.

### 시험 중 규칙

- 볼 수 있는 것과 AI 도구 허용 여부는 분반 공지를 따른다.
- 범위는 수업에서 나간 주차까지다. 범위 밖 기능은 가점이 없다. 그 때문에 요구 동작이 멈추면 그 문제에서 감점한다.
- 막히면 넘어가기: 한 문제에 오래 막히면 다음 문제로 간다. 문제끼리 이어지지 않는다. 넘긴 문제는 남는 시간에 돌아와 푼다.
- 다 못 했어도 쓴 코드와 캡처, 시도한 것(오류 메시지 포함)을 낸다. 실행되는 부분 결과와 설명은 부분 점수를 받는다([채점표](rubric.md)).
- 확인은 1일차와 같다. 저장 → 새로고침 → "확인할 것". 채점도 그 항목으로 하고, 어떤 방법으로 썼는지는 보지 않는다.
- 시험 중에는 문제 문장의 뜻·파일 위치·제출 방법·환경 장애만 안내한다. 코드가 맞는지는 알려 주지 않는다.
- 장애(서버·push·LMS)는 혼자 붙잡고 있지 않는다. 손을 들면 감독이 시각을 기록한다.

### 답안에 넣는 것

1. **코드**: 고친 파일 전체, 또는 고친 부분이 분명한 코드.
2. **캡처**: 요구한 상태의 브라우저 화면. 주소창이 함께 보이게 찍는다. F12 를 보라는 항목은 그 패널까지 보이게.
3. **설명**: 문제가 묻는 물음에 자기 말로 1~2문장.
4. 저장소 제출 방식이면 공개 주소 `https://student01.github.io/web-week08/exam/`·저장소 주소·GitHub **Commits** 탭 캡처.

## 막혔을 때

| 증상 | 확인할 것 |
|---|---|
| 저장한 파일 이름이 `index.html.txt` 처럼 `.txt` 로 끝난다 | 브라우저가 붙인 것이다. VS Code 탐색기에서 이름을 고친다 |
| 받은 문제를 열었더니 모양이 깨지거나 Console 에 404 줄이 있다 | 받은 파일 이름이나 폴더가 문제와 다르다. 이름 끝에 `.txt` 가 붙지 않았는지, 대소문자까지 같은지 본다 |
| 내 PC 에서는 열리는데 공개 주소에서는 404 다 | 파일 이름 대소문자가 다르다. 내 PC(Windows·macOS)는 가리지 않지만 GitHub 와 공개 주소는 가린다. 문제 문장의 파일 이름과 한 글자씩 맞춘다 |
| "확인할 것"의 Status 번호(`200`·`404`)가 안 보인다 | 두 번 눌러 연 `file://` 화면이다. `node server.mjs` 로 연 주소나 공개 주소에서 F12 › Network 를 연 채 새로고침한다 |
| 화면이 생각과 다른데 이유를 모르겠다 | **Console 을 먼저 연다.** 빨간 줄 오른쪽 `파일:줄` 로 간다. 그 문제의 힌트와 출처 주 실습지 "막혔을 때" 표를 본다 |
| 상자 안 글자가 가로만 가운데고 세로는 위에 붙어 있다 | `text-align: center` 만 썼다. `display: flex; flex-direction: column; justify-content: center; align-items: center;` 로 두 방향을 모은다 |
| 상자가 좌우는 맞는데 위아래가 틀리다 | row 방향에서 위아래는 `align-items` 다. `justify-content` 는 좌우만 바꾼다 |
| `Uncaught TypeError: Cannot read properties of null (reading 'addEventListener')` | `querySelector` 가 아무것도 못 찾았다. 선택자의 `#` 과 철자를 HTML 의 `id` 와 대소문자까지 비교한다. `script` 줄에 `defer` 가 없어도 같은 줄이 나온다 |
| `Uncaught TypeError: Assignment to constant variable.` | `const` 로 만든 변수에 다시 값을 넣었다. 횟수처럼 바뀌는 변수는 `let` 이다 |
| 버튼을 누르면 페이지가 다시 열리고 주소 끝에 `?` 가 붙는다 | 폼이 그대로 제출됐다. `submit` 이벤트 안에서 맨 먼저 `event.preventDefault()` 를 부른다. 그 줄까지 가기 전에 오류가 났는지 Console 도 본다 |
| commit 이나 push 가 거부되거나 로그인 창이 안 뜬다 | [2주차 막혔을 때](../week02_github_pages/lab.md#막혔을-때) 표를 본다. 시험 중이면 손을 들고, 오류 메시지를 답안에 적는다 |
| 공개 주소에 방금 push 한 내용이 안 보인다 | Pages 반영은 보통 1~3분 걸린다. 시험 시간 안에 안 보여도 감점하지 않는다. 로컬 화면 캡처와 Commits 탭 캡처도 인정한다 |
| `'node' is not recognized` / `command not found: node` | Node.js 가 없거나 설치 뒤 터미널을 새로 열지 않았다. 페이지를 두 번 눌러 연다 |
| `8000 번 포트를 이미 다른 프로그램이 쓰고 있습니다` | 다른 터미널에 서버가 떠 있다. 그 터미널에서 Ctrl+C 하거나 `node server.mjs . 8001` 로 띄우고 `http://localhost:8001/` 을 연다 |

한 번에 한 곳만 고치고 새로고침한다. 1일차에는 10분 넘게 같은 자리에 있으면 손을 든다. 시험 중에는 환경·제출 문제만 함께 본다.

## 제출

- **1일차**: 제출하지 않는다. 연습 폴더와 공개 주소는 본인 확인용이다.
- **2일차**: 분반 공지가 정한 곳(LMS 답안 칸 또는 저장소 `web-week08/exam/`)에 공지한 시각까지 낸다. 문제마다 코드·캡처·설명이 있어야 한다.
- 캡처에 실명·학번·실제 이메일이 보이지 않게 한다. 아이디는 보여도 된다.
- 저장소 제출 방식이면 채점이 끝날 때까지 저장소 `web-week08` 을 지우거나 이름을 바꾸지 않는다.

## 먼저 끝났다면

- 1일차: 푼 문제의 "이 문제의 값" 표에서 값 두세 개(글자·색·위치·id 등)를 스스로 바꿔 다시 풀고, "확인할 것"도 바뀐 값으로 맞춰 본다. 시험이 이 모양이다.
- 1일차: 각 문제의 힌트에 있는 설명을 힌트를 가린 채 한 문장씩 써 본다. 시험의 설명 물음이 이것이다.
- 2일차: 남는 시간에는 새 기능을 넣지 않는다. 문제마다 "확인할 것"을 다시 보고, 캡처와 설명이 빠지지 않았는지만 본다.

1일차 추가 연습은 채점하지 않는다.
