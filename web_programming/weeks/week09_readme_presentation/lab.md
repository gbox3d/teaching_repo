# 9주차 실습과 발표

7주차 웹 파일은 그대로 두고 README·캡처·도표만 추가한다. 강의는 60분, 필수 실습은 30분이다. 비교 예제 전체 수정과 SVG 좌표·Mermaid는 필수가 아니다. 이번 주는 1차 과제 10점(발표 5+README 5)으로 평가한다.

## 수업 전 준비

1. [7주차 완성 웹](../week07_form_input/examples/day2/web-week07/)의 HTML·JS·CSS와 images/·shared/를 새 web-week09 폴더에 복사한다. 8주 시험 파일은 쓰지 않는다.
2. [정적 서버](../../tools/static-server/server.mjs)를 같은 폴더에 두고 Node.js 24로 실행한다. 웹 주소는 http://localhost:8000/ 이다.
3. 새 GitHub 저장소 web-week09를 준비한다. 생성·업로드 명령은 [2주차 실습](../week02_github_pages/lab.md)을 따른다.
4. [README.start.md](examples/day2/web-week09/README.start.md)를 맨 위 README.md로 복사하고 [제공 SVG](examples/day1/ex10_site_map.svg)를 images/site-map.svg로 복사한다. 시작 틀의 TODO는 수업 중 채운다.

## 1일차 — README 작성 실습 (30분)

| 시간 | 필수 활동 | 확인 |
|---|---|---|
| 0–10분 | 사이트 제목·소개·공개 주소를 고치고 제공 페이지 표의 설명을 내 사이트와 맞춘다 | 제목 1개, 주소 1개, 세 페이지 링크 |
| 10–20분 | 홈과 방명록 캡처, app.js 코드 인용, 기능 두 줄과 배운 것 세 줄을 채운다 | 기능·배운 내용도 이 시간에 작성 |
| 20–25분 | 제공 SVG의 홈 글자를 첫 화면으로 고치고 미리 보기를 연다 | 좌표·도형은 수정하지 않음 |
| 25–30분 | 링크·캡처·코드·표를 확인하고 localhost 동작을 다시 본다 | README 다섯 항목과 캡처 두 장 |

### 캡처와 코드

- 홈에서 인사 바꾸기를 한 번 누른다. 인사 문장과 클릭 1회가 보이는 화면을 screenshots/home.png로 저장한다.
- 방명록에서 이름 student01과 첫 메시지를 넣고 남긴다. 폼은 비워지므로 이름과 두 번째 메시지를 다시 넣고 남긴다. 두 글이 보이는 화면을 screenshots/guestbook.png로 저장한다.
- 내 app.js에서 다크 모드 이벤트 함수를 복사해 시작 틀의 js 코드 블록에 붙인다. 기능 두 줄과 배운 것 세 줄도 실제 수행한 내용으로 쓴다.
- 필수 문법은 ex01·ex02·ex03·ex05·ex06·ex07을 참고한다. 제공 SVG의 글자 변경은 ex10이다. [전체 예제 설명](examples/README.md)에서 선택 자료와 구분한다.

### 확인 순서

1. VS Code에서 README.md를 열고 Ctrl+K 다음 V로 미리 보기를 연다.
2. 표의 index.html·about.html·guestbook.html 링크가 맞는지 확인한다.
3. 도표와 캡처 두 장이 보이고, 코드 블록이 닫혔는지 확인한다.
4. localhost에서 홈 버튼, 두 글 추가, 빈 이름·메시지 안내를 확인한다. 이메일을 입력했다면 올바른 형식이어야 한다. 이메일은 목록에 저장하지 않는다.
5. 새로고침하면 방명록 목록이 비워진다. 이 주의 글은 화면에만 있다.

### 이번 주 저장소 만들어 올리기

업로드는 수업 뒤에 한다. 준비한 저장소에 README·캡처·도표와 7주 파일 전체를 올리고 Pages를 확인한다. 명령은 [따라하기 9단계](walkthrough.md#9-이번-주-저장소-만들어-올리기)를 참고한다. 공개 반영이 끝나면 저장소 첫 화면을 캡처한다. 수업 중 증거는 VS Code 미리 보기와 localhost 캡처로 남길 수 있다.

## 2일차 — 발표 평가 (90분)

| 시간 | 활동 |
|---|---|
| 0–5분 | 순서·탭 세 개·장애 대체 방법 확인 |
| 5–80분 | 발표 75분. 30명까지 1인 시연 2분+전환 30초 |
| 80–90분 | 피드백·10주차 예고 |

31명 이상은 [발표 인원과 운영](project_brief.md#발표-인원과-운영)의 사전 영상 방식으로 바꾼다. 발표·README 배점은 같다. 발표 설명을 위한 별도 30분 강의는 없다. 시연 순서와 채점표는 1일차에 미리 안내한다.

### 발표

- 공개 주소·저장소 첫 화면·Commits 탭을 자기 차례 두 사람 전에 연다.
- [2분 순서](project_brief.md#2분-발표-순서)에 따라 버튼 한 번과 글 두 개를 직접 입력한다. 폼이 비워지므로 두 번째 글에도 이름을 넣는다.
- 마지막 10초에 짧은 구술 질문 하나에 답한다. 전환 30초에는 다음 발표자를 준비한다.
- 수정·업로드는 발표 뒤 수업 밖에서 한다. 듣는 동안에는 채점표를 보며 다음 주에 고칠 내용을 기록한다.

## 막혔을 때

| 증상 | 확인할 것 |
|---|---|
| 공개 주소에 방금 push한 내용이 안 보인다 | Pages 반영 시간은 달라진다. 5분 안에 안 보이면 로컬 화면 캡처와 GitHub **Commits** 탭 캡처를 같은 점수로 인정한다. 발표 때도 같다 |
| push 가 거부되거나 로그인 창이 안 뜬다 | [2주차 막혔을 때](../week02_github_pages/lab.md#막혔을-때) 표를 본다 |
| 미리 보기가 안 열리거나 원문만 보인다 | 파일 이름이 `.md` 로 끝나는지 본다(`ex01_heading.md.txt` 면 이름을 고친다). 미리 보기는 Ctrl+K 다음 V(옆에 열기)다. 그래도 안 되면 Ctrl+Shift+V(macOS ⌘+Shift+V)로 같은 자리에 연다 |
| `#제목` 이 제목이 아니라 글자로 보인다 | `#` 뒤에 띄어쓰기가 없다. `# 제목` 으로 고친다(ex01 3번) |
| 기능 두 줄이 점 없이 한 문단으로 이어져 보인다 | 줄 맨 앞에 `- ` 가 없다(ex02 2번) |
| 링크가 `[보이는 글] (주소)` 글자 그대로 보인다 | `]` 와 `(` 사이의 띄어쓰기를 지운다(ex03 3번) |
| `**[남기기]**를` 처럼 별이 글자로 보인다 | 닫는 별 앞이 문장 부호이고 뒤에 글자가 붙었다. 닫는 별 뒤를 한 칸 띄운다(ex04 5번) |
| 그림 자리에 깨진 표시와 글자만 보인다 | 경로가 틀렸다. 폴더·파일 이름을 대소문자까지 맞추고, 그 폴더가 저장소에 올라갔는지 본다(ex05 3번) |
| 코드 블록 뒤의 글이 전부 코드로 보인다 | 닫는 줄(백틱 세 개)이 없다(ex06) |
| 표가 `\|` 글자 그대로 보인다 | 머리글 바로 아래에 구분 줄이 있는지, 구분 줄의 칸 수가 머리글과 같은지 본다(ex07 2번) |
| 문서에 적은 `<svg>` 가 GitHub 에서 사라진다 | GitHub 은 문서 안의 `<svg>` 태그를 지운다. `.svg` 파일로 저장하고 `![글](파일.svg)` 로 넣는다(ex09) |
| SVG 그림이 깨져 나온다 | `.svg` 를 브라우저에서 열면 오류 줄과 위치가 보인다. `/>`·따옴표 짝을 본다(ex09) |
| 어두운 화면에서 SVG 글자가 안 보인다 | 맨 앞에 흰 배경 `<rect … fill="white"/>` 을 둔다(ex09) |
| VS Code 미리 보기에서 Mermaid 가 코드로 보인다 | 현재 기본 미리 보기는 Mermaid를 지원한다. 여는 줄의 mermaid 철자와 VS Code 버전을 확인하고 GitHub에서도 비교한다(ex11) |
| 저장소 첫 화면에 README 가 안 보인다 | 파일이 저장소 **맨 위**에 있고 이름이 `README.md` 인지, push 했는지 본다. 폴더 안의 README 는 그 폴더를 열어야 보인다 |
| README 의 캡처 그림이 GitHub 에서 깨진다 | `screenshots/` 폴더가 올라갔는지(저장소 화면에 폴더가 보이는지), 경로의 폴더·파일 이름이 대소문자까지 같은지 본다. GitHub 화면의 파일 이름을 복사해 넣는다 |
| README 의 공개 주소 링크가 옛 사이트나 404 를 연다 | 소괄호 안이 이번 주 주소 `https://student01.github.io/web-week09/`(본인 아이디)인지 본다 |
| 공개 주소 `…/web-week09/` 가 404 다 | ① 저장소 이름이 `web-week09` 인지 ② **Settings › Pages** 가 켜져 있는지 ③ `index.html` 이 저장소 맨 위에 있는지 본다 |
| 발표 중 버튼이나 폼이 동작하지 않는다 | Console 첫 빨간 줄을 읽고 [6주차](../week06_dom_events/lab.md#막혔을-때)·[7주차](../week07_form_input/lab.md#막혔을-때) 막혔을 때 표를 본다. 발표에서는 되는 것부터 보여 준다 |
| 방명록에 남긴 글이 새로고침하면 사라진다 | 정상이다. 지금 글은 화면에만 있다. 새로고침해도 남게 하는 것은 11주차다 |
| 2분을 넘긴다 | 말하면서 누른다. 첫 소개를 한 문장으로 줄인다 |

한 번에 한 곳만 고치고 다시 확인한다. 해결되지 않으면 미리 보기나 Console 화면을 그대로 보여 주고 도움을 받는다.

## 제출 — 캡처 한 장과 발표

**캡처 1장**: `https://github.com/<아이디>/web-week09` 저장소 첫 화면. README 5항목이 보이게 찍는다. 그림 때문에 길어서 한 화면에 안 들어오면 브라우저를 축소하거나(**Ctrl + `-`**) 나눠 찍어 한 파일로 낸다.

30명까지는 2일차 현장 발표, 31명 이상은 사전 영상과 현장 개인 설명으로 진행한다. 채점 기준은 [채점표](rubric.md), 과제 범위는 [1차 과제 안내](project_brief.md)에 있다.
캡처에 실명·학번·실제 이메일이 보이지 않게 한다. 제출 위치와 마감은 수업 공지를 따른다.
1일차 `ex/` 실험 파일은 확인용이며 따로 제출하지 않는다.
