# 9주차 실습 — 마크다운 기본 기능으로 README 1차판을 쓰고 2분 발표하기

1일차 실습은 **값을 바꿔 보는 것**에서 시작한다.
비교 예제 11개(마크다운 `.md` 파일과 SVG 파일)를 이번 주 새 저장소 `web-week09` 의 `ex/` 폴더에 저장하고, 기호나 숫자 하나를 바꾼 뒤 렌더된 모양이 어떻게 달라지는지 본다. 결과는 VS Code 미리 보기와, 올린 뒤의 GitHub 저장소 화면에서 본다.
1일차 끝에 그 기능들로 `web-week09` 맨 위의 `README.md` 1차판을 조립한다. 표·그림·소스 코드·SVG 도표가 들어간다. 사이트 파일(HTML·CSS·JavaScript)은 7주차 완성본 그대로 두고 고치지 않는다.
2일차 60분은 **발표**다. 이번 주는 주차별 실습 점수가 아니라 1차 과제 10점(발표 5 + 레포트 5)으로 본다.
`student01` 은 예시 아이디이므로 본인 아이디로 바꾼다.

파일을 받는 법과 미리 보기를 여는 법은 [따라하기 1일차](walkthrough.md#1일차)에 있다.
"바꿔 보기"는 **무엇이 달라질지 먼저 말해 보고** 원문을 고친 뒤 미리 보기로 확인한다. 확인했으면 원래대로 되돌리고 다음으로 간다.

## 1일차 — 마크다운 기본 기능과 README 1차판 (60분)

| 5–10분 | ex01 제목 · ex02 목록 |
| 10–13분 | ex03 링크 · ex04 강조 |

| 21–26분 | ex07 표 · ex08 인용과 구분선 |

1일차 예제는 마크다운 파일이다. VS Code 에서 파일을 열고 **미리 보기를 옆에** 띄운다(**Ctrl+K** 를 누르고 손을 뗀 뒤 **V**, macOS **⌘+K** 다음 **V**). 왼쪽 원문을 고치면 오른쪽 미리 보기가 따라 바뀐다. 고친 뒤에는 저장(Ctrl+S)해 둔다.
시간이 모자라면 바꿔 보기는 예제마다 첫 항목만 하고 넘어간다. 조립은 35분에 시작한다.

### 1. ex01 제목 (`#` · `##`)

[examples/day1/ex01_heading.md](examples/day1/ex01_heading.md) 를 `ex/ex01_heading.md` 로 저장하고 연다. 미리 보기를 옆에 띄운다.

- 바꿔 보기: 10행 `## 공개 주소` 를 `### 공개 주소` 로 바꾼다. 크기는 어떻게 되나? `#` 개수와 크기는 어떤 관계인가?
- 바꿔 보기: 14행 `#공개 주소` 를 `# 공개 주소` 로(샵 뒤에 한 칸) 바꾼다. 6행과 똑같은 제목이 되나?
- 흔한 실수: `#` 뒤 띄어쓰기를 빠뜨린다. 오류는 나지 않고 `#제목` 이 글자 그대로 보인다.

### 2. ex02 목록 (`-` · `1.` · 들여쓰기 · `- [ ]`)

[examples/day1/ex02_list.md](examples/day1/ex02_list.md) 를 `ex/ex02_list.md` 로 저장하고 연다.

- 바꿔 보기: 2번(12~14행) 세 줄 사이에 빈 줄을 하나씩 넣는다. 몇 줄로 보이나? 점은 붙나?
- 바꿔 보기: 4번의 `2. 내 정보` 를 `7. 내 정보` 로 바꾼다. 미리 보기의 번호는 어떻게 되나? 5번 안쪽 두 줄의 앞 칸을 지우면 어떻게 되나? 6번 `- [ ]` 를 `- [x]` 로 바꾼다.
- 흔한 실수: README 기능 두 줄을 `-` 없이 쓴다. 두 줄이 점 없이 한 문단으로 이어져 보인다.

### 3. ex03 링크 (`[보이는 글](주소)`)

[examples/day1/ex03_link.md](examples/day1/ex03_link.md) 를 `ex/ex03_link.md` 로 저장하고 연다. 2번이 ex01 을 가리키므로 ex01 이 같은 `ex/` 폴더에 있어야 한다.

- 바꿔 보기: 14행 `]` 와 `(` 사이의 띄어쓰기를 지운다. 링크가 되나?
- 바꿔 보기: 10행 소괄호 안을 `ex02_list.md` 로 바꾼다. 보이는 글은 그대로인데 누르면 어느 파일이 열리나?
- 흔한 실수: 소괄호 안 파일 이름의 대소문자를 틀린다(`Home.png`). GitHub 은 대소문자를 가린다. 내 PC 에서 열려도 올린 뒤 404 가 날 수 있으니 VS Code 탐색기에 보이는 이름을 글자 그대로 쓴다.

### 4. ex04 강조 (`**` · `*` · `~~`)

[examples/day1/ex04_emphasis.md](examples/day1/ex04_emphasis.md) 를 `ex/ex04_emphasis.md` 로 저장하고 연다.

- 바꿔 보기: 6행 `**세 페이지**` 의 닫는 별 둘을 지운다. 어떻게 보이나?
- 바꿔 보기: 4번은 별이 글자로 남았다. 5번과 어디가 다른가? 4번 `**[남기기]**를` 의 대괄호를 지워 `**남기기**를` 로 바꾸면 굵게 되나?
- 흔한 실수: 한글 조사 앞에서 별이 글자로 남는다. 닫는 별 앞이 문장 부호(`]`·`)`·`.`)이고 뒤에 글자가 바로 붙을 때다. 닫는 별 뒤를 한 칸 띄운다.

### 5. ex05 그림 (`![대신 읽을 글](경로)`)

[examples/day1/ex05_image.md](examples/day1/ex05_image.md) 를 `ex/ex05_image.md` 로, 그림 [examples/day1/images/profile.png](examples/day1/images/profile.png) 를 `ex/images/profile.png` 로 저장한다(`ex` 안에 `images` 폴더를 만든다). 그림은 **Raw** 대신 GitHub 화면의 내려받기 단추(**Download raw file**)로 받는다.

- 바꿔 보기: 1번 줄(6행) 맨 앞의 `!` 를 지운다. 2번과 같아지나?

- 흔한 실수: 경로를 틀리면 오류 없이 그림 자리에 깨진 표시와 대괄호 글자가 보인다(3번). 그래서 대괄호에 무엇인지 알려 주는 글을 쓴다.

### 6. ex06 소스 코드 (`` ` `` · ` ``` `)

[examples/day1/ex06_code.md](examples/day1/ex06_code.md) 를 `ex/ex06_code.md` 로 저장하고 연다.

- 바꿔 보기: 2번과 3번은 코드가 같다. 미리 보기에서 색이 어떻게 다른가? 3번 여는 줄의 `js` 를 `html` 로 바꾸면 색은 어떻게 되나?
- 바꿔 보기: 3번의 닫는 줄(백틱 세 개)을 지운다. 그 아래 4번 설명은 어떻게 보이나? 왜 그런가? 확인했으면 되돌린다.
- 흔한 실수: 백틱(`` ` ``, 키보드 왼쪽 위 숫자 1 옆)을 작은따옴표(`'`)로 친다. 코드 모양이 되지 않는다.

### 7. ex07 표 (`|` · `---` · `:`)

[examples/day1/ex07_table.md](examples/day1/ex07_table.md) 를 `ex/ex07_table.md` 로 저장하고 연다.

- 바꿔 보기: 1번 끝에 `| 내 정보 | about.html |` 한 줄을 더한다. 3번 구분 줄의 `:` 자리를 바꿔 칸 안 글자가 어디로 가는지 본다.
- 흔한 실수: 구분 줄의 칸 수가 머리글과 다르다(머리글 두 칸인데 `|---|` 한 칸). 표가 되지 않고 글자로 이어진다.

### 8. ex08 인용과 구분선 (`>` · `---`)

[examples/day1/ex08_quote_rule.md](examples/day1/ex08_quote_rule.md) 를 `ex/ex08_quote_rule.md` 로 저장하고 연다.

- 흔한 실수: 문단 바로 아래에 `---` 를 쓴다. 가로줄 대신 윗줄이 큰 글자 제목이 된다.

### 9. ex09 SVG 그림 (`<rect>` · `<line>` · `<text>`)

[examples/day1/ex09_svg.md](examples/day1/ex09_svg.md) 와 [examples/day1/ex09_shapes.svg](examples/day1/ex09_shapes.svg) 를 `ex/` 에 저장한다. `ex09_svg.md` 의 미리 보기를 띄우고, 옆에 `ex09_shapes.svg` 원문을 연다.

- 바꿔 보기: `.svg` 의 사각형 `fill="#e8f1ff"` 을 `fill="#ffe0e0"` 으로, `width="120"` 을 `width="200"` 으로 바꾸고 저장한다. 미리 보기 그림이 어떻게 바뀌나?
- 바꿔 보기: 글자 줄 `y="120"` 을 `y="40"` 으로 바꾼다. 글자는 어디로 가나? 숫자가 커지면 위로 가나 아래로 가나?
- 2번(문서 안에 바로 적은 `<svg>`)은 50–60분에 올린 뒤 GitHub 화면에서 본다. 1번은 보이고 2번은 보이지 않으면 맞다. 그래서 SVG 는 파일로 넣는다.
- 흔한 실수: `/>` 나 닫는 따옴표를 지운다. 고친 파일을 브라우저로 열면 오류가 보이고 문서에는 그림이 깨져 나온다.

### 10. ex10 SVG 도표

[examples/day1/ex10_diagram.md](examples/day1/ex10_diagram.md) 와 [examples/day1/ex10_site_map.svg](examples/day1/ex10_site_map.svg) 를 `ex/` 에 저장한다. 도형은 ex09 와 같은 사각형·선·글자뿐이다.

- 바꿔 보기: `.svg` 에서 글자 `홈 index.html` 을 `첫 화면 index.html` 로 바꾼다. 미리 보기에서 어떻게 보이나?
- 바꿔 보기: 맨 위 상자를 왼쪽으로 옮긴다. `x="180"` 을 `x="100"` 으로 바꾸면 글자와 선은 따라오나? 상자를 옮기려면 어느 숫자를 함께 바꿔야 하나?
- 흔한 실수: 글자가 상자보다 길어 삐져나온다. 상자의 `width` 를 늘리거나 `font-size` 를 줄인다.

### 11. ex11 Mermaid

[examples/day1/ex11_mermaid.md](examples/day1/ex11_mermaid.md) 를 `ex/ex11_mermaid.md` 로 저장한다. VS Code 기본 미리 보기에서는 1번도 코드로 보일 수 있다. 50–60분에 올린 뒤 GitHub 화면에서 도표를 본다.

- 바꿔 보기(시간이 남으면): 내 PC 에서 `about --> guestbook` 줄을 `guestbook --> home` 으로 바꾸고 다시 push 한다. GitHub 화면의 도표에서 선이 어떻게 바뀌나?
- ex10 과 비교한다. ex10 은 상자의 자리를 숫자로 직접 정했고, ex11 은 연결만 적었다. README 에는 둘 중 ex10 의 SVG 를 넣는다. 그림 파일이라 어디서나 같게 보이기 때문이다.
- 흔한 실수: 여는 줄의 `mermaid` 철자를 틀린다. 도표가 아니라 코드로 보인다(2번과 같다).

### 12. 조립 — `README.md` 1차판

이제 `ex/` 가 아니라 `web-week09` **맨 위**(`index.html` 옆)에 쓴다. 전문과 단계는 [따라하기 5단계](walkthrough.md#5-화면-두-장-캡처와-도표-파일)·[7단계](walkthrough.md#7-readme-1차판-조립하기)에 있다.

1. `screenshots` 폴더를 만들고 **동작한 뒤의 화면** 두 장을 캡처해 넣는다(Windows **Win+Shift+S**, macOS **⌘+Shift+4**).

| 캡처 | 할 일 | 저장 |
|---|---|---|
| 홈 | `index.html` 을 열고 **인사 바꾸기**를 한 번 누른다. `반갑습니다. 오늘도 좋은 하루 되세요.` 와 `클릭 1회` 가 보인다 | `screenshots/home.png` |
| 방명록 | `guestbook.html` 에서 이름 `student01`, 메시지 `첫 방명록입니다.` 로 **남기기**를 누르고, 메시지를 `두 번째 글입니다.` 로 바꿔 한 번 더 누른다. 목록에 `student01: 첫 방명록입니다.`·`student01: 두 번째 글입니다.` 두 줄이 보인다 | `screenshots/guestbook.png` |

2. `ex/ex10_site_map.svg` 를 복사해 `images/site-map.svg` 로 저장하고, 맨 위 주석 한 줄을 지운다. 글자는 내 사이트에 맞게 고친다.
3. 맨 위에 `README.md` 를 만든다. 큰 제목 한 줄, 그 아래 작은 제목 다섯을 이 순서로 쓴다: `## 공개 주소` · `## 페이지` · `## 기능` · `## 화면` · `## 이번에 배운 것`. 지난주 파일에 `README.md` 가 있으면 내용을 모두 지우고 다시 쓴다.

| 조립할 줄 | 어느 ex 에서 본 것 |
|---|---|
| `# student01의 웹 연습장` (내 사이트 이름 한 줄) | ex01 1번. 글자는 7주차 `index.html` 맨 위 `<h1>` 과 같게 |
| `… **자기소개 사이트**입니다.` (소개 한 문장) | ex02 2번(기호 없는 줄은 문단) + ex04 1번(굵게) |
| `## 공개 주소` 외 작은 제목 넷 | ex01 2번 |
| `- [https://student01.github.io/web-week09/](…)` | ex02 1번 + ex03 1번 |
| `## 페이지` 의 표 세 줄, 칸 안의 `[index.html](index.html)` | ex07 1번 + ex03 2번 |
| `![세 페이지가 … 사이트 구조](images/site-map.svg)` | ex10 + ex05 1번 |
| 기능 두 줄 · 배운 것 세 줄 | ex02 1번 |
| 문장 안의 코드와 `js` 코드 블록 | ex06 1번 · 3번. 코드는 내 `app.js` 에서 복사한다 |
| `![인사 바꾸기를 누른 홈 화면](screenshots/home.png)` · 방명록 한 줄 | ex05 1번 |

- 확인: 미리 보기를 옆에 띄운다. 큰 제목과 작은 제목 다섯, 표, 도표, 색이 입혀진 코드, 그림 두 장이 보이면 된 것이다. 표 안의 링크를 눌러 파일이 열리는지 본다.
- 바꿔 보기: 표의 구분 줄을 지운다. ex07 몇 번과 같아지나? 확인했으면 되돌린다.
- 흔한 실수: `README.md` 를 `ex/` 안에 만든다. 저장소 첫 화면에는 **맨 위**의 `README.md` 만 보인다. 이름이 `readme.txt` 처럼 다르면 마크다운으로 렌더되지 않는다. 그림 파일 이름은 영문 소문자로 한다.

### 이번 주 저장소 만들어 올리기

GitHub 에서 **New repository** → 이름 `web-week09`, **Public**, README 는 추가하지 않는다(내 PC 에서 쓴 `README.md` 를 올린다). VS Code 터미널(현재 폴더 `web-week09`)에서 2주차에 배운 순서 그대로 친다.

```bash
git init
git add .
git commit -m "9주차 1일차"
git branch -M main
git remote add origin https://github.com/student01/web-week09.git
git push -u origin main
```

저장소 **Settings › Pages › Branch: main, /(root) › Save** 를 누른다. 저장소 화면 `https://github.com/student01/web-week09` 를 새로고침하면 파일 목록 아래에 README 가 렌더되어 보인다. 이 화면이 **제출 캡처 1장**이다.
`ex` 폴더에서 `ex01_heading.md` 를 눌러 렌더된 모양을 보고, 위쪽 **Code** 를 눌러 원문과 비교한다. `ex09_svg.md`(1번만 그림이 보인다)와 `ex11_mermaid.md`(1번이 도표로 보인다)도 연다. 1~3분 뒤 `https://student01.github.io/web-week09/` 를 열어 세 페이지·버튼·폼과 README 의 공개 주소 링크를 확인한다. 공용 PC면 자격 증명을 지우고 나간다.

## 2일차 — 2분 발표 (60분)

| 시간 | 할 일 |
|---|---|
| 0–5분 | 발표 차례를 확인하고 탭 세 개(공개 주소·저장소 첫 화면·Commits 탭)를 연다. README 를 고칠 일이 있으면 같은 PC에 남은 `web-week09` 폴더를 연다. 없으면 `git clone https://github.com/student01/web-week09.git` 뒤 **File › Open Folder** |
| 5–47분 | **발표 2분 × 인원** — 공개 주소 → 세 페이지 → 버튼·폼 → README·Commits 탭 |
| 47–55분 | 총평과 10주차 예고 |
| 55–60분 | 끝 루틴: README 를 고쳤으면 `git add .` → `git commit -m "9주차 2일차"` → `git push` → 저장소 첫 화면 새로고침 → 공용 PC면 자격 증명 삭제 |

21명이면 발표에 42분이 든다. 인원에 따라 달라지며 **실제 차례와 시각은 수업 공지를 따른다.**

### 7. 발표 (2분)

[1차 과제 안내](project_brief.md#2분-발표-순서)의 순서를 공개 주소와 GitHub 화면으로 한다. [따라하기 11단계](walkthrough.md#11-2분-발표-순서대로)를 본다.

- 탭 1 `https://student01.github.io/web-week09/` · 탭 2 `https://github.com/student01/web-week09` · 탭 3 `https://github.com/student01/web-week09/commits`
- 방명록은 비워 둔 상태로 시작한다. 발표 중에 직접 두 줄 남겨 목록에 쌓이는 것을 보이고, 이름을 비워 안내 문장까지 보인다.
- 코드 파일은 띄우지 않는다. 구술 질문("이 버튼을 누르면 어느 파일이 실행됩니까?")을 받으면 그때 연다.
- "남긴 글이 새로고침하면 사라지나요?"에는 "아직 화면에만 있습니다. 남기는 것은 11주차에 합니다"라고 답한다.
- 잘 안 되는 기능이 있으면 **되는 것부터** 보여 주고 남은 시간에 말한다.

### 8. 듣는 동안

- [채점표](rubric.md)를 보며 듣는다. 다음 차례 두 사람은 탭 세 개를 미리 열어 둔다.
- 남의 발표 중에 자기 파일을 고치지 않는다. 고칠 것은 55–60분 끝 루틴에서 고친다.

## 막혔을 때

| 증상 | 확인할 것 |
|---|---|
| 공개 주소에 방금 push한 내용이 안 보인다 | Pages 반영은 보통 1~3분 걸린다. 5분 안에 안 보이면 로컬 화면 캡처와 GitHub **Commits** 탭 캡처를 같은 점수로 인정한다. 발표 때도 같다 |
| push 가 거부되거나 로그인 창이 안 뜬다 | [2주차 막혔을 때](../week02_github_pages/lab.md#막혔을-때) 표를 본다 |
| 미리 보기가 안 열리거나 원문만 보인다 | 파일 이름이 `.md` 로 끝나는지 본다(`ex01_heading.md.txt` 면 이름을 고친다). 미리 보기는 **Ctrl+K** 다음 **V**(옆에 열기)다. 그래도 안 되면 **Ctrl+Shift+V**(macOS **⌘+Shift+V**)로 같은 자리에 연다 |
| `#제목` 이 제목이 아니라 글자로 보인다 | `#` 뒤에 띄어쓰기가 없다. `# 제목` 으로 고친다(ex01 3번) |
| 기능 두 줄이 점 없이 한 문단으로 이어져 보인다 | 줄 맨 앞에 `- ` 가 없다(ex02 2번) |
| 링크가 `[보이는 글] (주소)` 글자 그대로 보인다 | `]` 와 `(` 사이의 띄어쓰기를 지운다(ex03 3번) |
| `**[남기기]**를` 처럼 별이 글자로 보인다 | 닫는 별 앞이 문장 부호이고 뒤에 글자가 붙었다. 닫는 별 뒤를 한 칸 띄운다(ex04 5번) |
| 그림 자리에 깨진 표시와 글자만 보인다 | 경로가 틀렸다. 폴더·파일 이름을 대소문자까지 맞추고, 그 폴더가 저장소에 올라갔는지 본다(ex05 3번) |
| 코드 블록 뒤의 글이 전부 코드로 보인다 | 닫는 줄(백틱 세 개)이 없다(ex06) |
| 표가 `\|` 글자 그대로 보인다 | 머리글 바로 아래에 구분 줄이 있는지, 구분 줄의 칸 수가 머리글과 같은지 본다(ex07 2번) |
| 문서에 적은 `<svg>` 가 GitHub 에서 사라진다 | GitHub 은 문서 안의 `<svg>` 태그를 지운다. `.svg` 파일로 저장하고 `![글](파일.svg)` 로 넣는다(ex09) |
| SVG 그림이 깨져 나온다 | `.svg` 를 브라우저에서 열면 오류 줄과 위치가 보인다. `/>`·따옴표 짝을 본다(ex09) |
| 어두운 화면에서 SVG 글자가 안 보인다 | 맨 앞에 흰 배경 `<rect … fill="white"/>` 을 둔다(ex09) |
| VS Code 미리 보기에서 Mermaid 가 코드로 보인다 | 기본 미리 보기에서는 그럴 수 있다. 올린 뒤 GitHub 화면에서 본다(ex11) |
| 저장소 첫 화면에 README 가 안 보인다 | 파일이 저장소 **맨 위**에 있고 이름이 `README.md` 인지, push 했는지 본다. 폴더 안의 README 는 그 폴더를 열어야 보인다 |
| README 의 캡처 그림이 GitHub 에서 깨진다 | `screenshots/` 폴더가 올라갔는지(저장소 화면에 폴더가 보이는지), 경로의 폴더·파일 이름이 대소문자까지 같은지 본다. GitHub 화면의 파일 이름을 복사해 넣는다 |
| README 의 공개 주소 링크가 옛 사이트나 404 를 연다 | 소괄호 안이 이번 주 주소 `https://student01.github.io/web-week09/`(본인 아이디)인지 본다 |
| 공개 주소 `…/web-week09/` 가 404 다 | ① 저장소 이름이 `web-week09` 인지 ② **Settings › Pages** 가 켜져 있는지 ③ `index.html` 이 저장소 맨 위에 있는지 본다 |
| 발표 중 버튼이나 폼이 동작하지 않는다 | Console 첫 빨간 줄을 읽고 [6주차](../week06_dom_events/lab.md#막혔을-때)·[7주차](../week07_form_input/lab.md#막혔을-때) 막혔을 때 표를 본다. 발표에서는 되는 것부터 보여 준다 |
| 방명록에 남긴 글이 새로고침하면 사라진다 | 정상이다. 지금 글은 화면에만 있다. 새로고침해도 남게 하는 것은 11주차다 |
| 2분을 넘긴다 | 말하면서 누른다. 첫 소개를 한 문장으로 줄인다 |

한 번에 한 곳만 고치고 다시 확인한다. 해결되지 않으면 미리 보기나 Console 화면을 그대로 보여 주고 도움을 받는다.

## 제출 — 캡처 한 장과 발표

**캡처 1장**: `https://github.com/<아이디>/web-week09` 저장소 첫 화면. README 5항목이 보이게 찍는다. 그림 때문에 길어서 한 화면에 안 들어오면 브라우저를 축소하거나(**Ctrl + `-`**) 나눠 찍어 한 파일로 낸다.

발표는 2일차 수업 시간에 한다. 채점 기준은 [채점표](rubric.md), 과제 범위는 [1차 과제 안내](project_brief.md)에 있다.
캡처에 실명·학번·실제 이메일이 보이지 않게 한다. 제출 위치와 마감은 수업 공지를 따른다.
1일차 `ex/` 실험 파일은 확인용이며 따로 제출하지 않는다.

## 먼저 끝났다면

- README 에 `## 다음에 해 볼 것` 절을 하나 더 두고, 10~12주에 넣고 싶은 기능을 점검표 `- [ ]` 두 줄로 쓴다.
- ex10 도표에 `styles.css` 상자를 하나 더 그려 세 페이지와 선으로 잇는다.
- `## 페이지` 의 도표를 ex11 의 Mermaid 로도 그려 GitHub 화면에서 SVG 와 비교한다.
- 다크 모드를 켠 홈 화면을 `screenshots/dark.png` 로 한 장 더 찍고, `## 화면` 에 그림 한 줄을 더한다.
- ex01: 10행의 `#` 를 하나씩 늘려 `######`(여섯 개)까지 바꿔 본다. 일곱 개(`#######`)면 어떻게 보이나?
- 짝과 공개 주소로 2분 연습을 한 번 더 하고, 넘친 구간을 한 문장 줄인다.

추가 과제는 선택 사항이며 채점하지 않는다.
