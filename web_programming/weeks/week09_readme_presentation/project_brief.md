# 1차 과제 — 내 사이트 2분 발표와 README

개인 과제다. 새로 만드는 프로젝트가 아니라 **3~7주에 만든 사이트(7주차 완성본)를 그대로** 이번 주 새 저장소 `web-week09` 에 넣어 발표한다.
제출 방식과 마감은 수업 공지를 따른다. 배점은 10점(발표 5 + 레포트 5)이며 채점 기준은 [채점표](rubric.md)에 있다.

## 과제 범위

발표 대상은 새 저장소 `web-week09` 에 넣은 내 사이트다. 8주차 중간 실기를 본 저장소 `web-week08`은 이번 과제와 관계가 없다.

| 갖춰야 할 것 | 어디서 만들었나 | 발표에서 |
|---|---|---|
| 공개 주소 `https://<아이디>.github.io/web-week09/` | 9주차 사전 준비·수업 뒤 업로드 | 첫 20초에 연다 |
| 세 페이지 `index.html`·`about.html`·`guestbook.html`과 nav | 3주차 | 오가며 보여 준다 |
| `styles.css` — 색·박스·`display: flex`·`@media` 1개 | 4주차 | 화면으로 보인다 |
| 버튼 클릭 기능 1개 — 문장이 바뀌고 횟수가 오른다 | 5·6주차 | 눌러서 보여 준다 |
| 폼 입력(남길 때마다 목록에 한 줄씩)과 빈값 안내 1개 | 7주차 | 두 번 남겨 목록에 쌓이는 것을 보이고, 비우고 눌러 본다 |
| 저장소 `README.md` 1차판 5항목, `screenshots/` 캡처 2장, `images/site-map.svg` 도표 | 9주차 | 마지막 20초 |

본인 기능 1개를 더 넣어도 된다(선택). 발표 소재로 쓸 수 있지만 **가산점은 없다.**
기능을 더 넣다가 위 표의 동작이 멈추면 그 항목에서 점수를 잃는다.

## 레포트 = 저장소 README.md 한 장

별도 보고서 파일(docx·pdf)은 받지 않는다. 채점자는 공개 주소와 저장소 첫 화면만 연다.

```text
# 사이트 이름
## 공개 주소        Pages 주소 링크
## 페이지           세 페이지 표(이름·파일 링크·설명)와 SVG 도표
## 기능             버튼 한 줄, 폼 한 줄, 내 코드 한 덩어리(코드 블록)
## 화면             screenshots/ 캡처 2장을 그림으로
## 이번에 배운 것   3줄
```

- 1일차에 본 기능을 쓴다: 제목 `#`, 목록 `-`, 링크 `[보이는 글](주소)`, 표 `|`, 그림 `![글](경로)`, 코드 블록. 같은 저장소 안의 파일은 소괄호에 파일 이름(경로, 예: `screenshots/home.png`)을 쓴다.
- 도표는 ex10 의 SVG 를 `images/site-map.svg` 로 저장해 내 사이트에 맞게 글자만 고쳐 넣는다. 도형 좌표 작성과 Mermaid는 선택이며 채점하지 않는다.
- 캡처 두 장은 **동작한 뒤의 화면**으로 찍는다(버튼을 누른 홈, 글 두 줄이 목록에 쌓인 방명록).
- 예시는 [examples/day2/web-week09/README.md](examples/day2/web-week09/README.md)에 있다. 그대로 베끼지 말고 본인 사이트 내용으로 바꾼다. 공개 주소는 이번 주 저장소 `web-week09` 의 주소이고, 예시의 `student01` 자리에 본인 아이디를 쓴다.

## 2분 발표 순서

| 시간 | 보여 줄 것 |
|---|---|
| 0:00–0:20 | 공개 주소를 열고 사이트 이름·한 줄 소개 |
| 0:20–0:50 | nav로 세 페이지 이동 |
| 0:50–1:30 | 버튼 한 번, 폼 두 번(목록에 두 줄) |
| 1:30–1:40 | 이름을 비우고 남기기 → 빈값 안내 |
| 1:40–1:50 | README 다섯 항목·Commits 탭 확인 |
| 1:50–2:00 | 짧은 구술 질문 하나 |

구술 질문은 한 문항이다. 예: "이 버튼을 누르면 어느 파일이 실행됩니까?"

## 발표 인원과 운영

2일차 90분은 안내 5분+발표 75분+피드백 10분이다. 인원과 운영 방식은 수업 전에 공지한다.

- 30명까지: 1인 시연 2분+전환 30초로 최대 75분이다. 구술 한 문항은 시연의 마지막 10초에 포함한다. 채점표의 20초 유예를 써도 전환 10초를 남겨 한 사람의 총 2분 30초를 넘기지 않는다.
- 31명 이상: 전원 같은 2분 시연 영상을 미리 제출한다. 강의자는 영상을 수업 전에 채점한다. 수업 중 표본 5명의 시연과 전환에 12분 30초를 배정한다. 전원 짧은 코드 설명에는 1인 최대 min(60, 3600/N)초를 전환 포함 배정한다(N은 인원). 나머지 시간은 질문·장애 보완에 쓴다. 예를 들어 40명은 표본 12분 30초+개인 설명 40분+질문 22분 30초=75분이다.
- 사전 영상도 공개 주소·세 페이지·버튼·폼·시간의 같은 5점 기준으로 평가한다. 표본으로 뽑히지 않아도 점수가 달라지지 않는다. README는 동일한 5점이다.

## 제출물

1. **발표 2분** — 30명까지 현장 시연, 31명 이상 사전 영상과 현장 개인 설명
2. **공개 주소** `https://<아이디>.github.io/web-week09/`
3. **저장소 주소** `https://github.com/<아이디>/web-week09`
4. **캡처 1장** — 저장소 첫 화면(README 5항목이 보이게, 길면 나눠 찍어 한 파일로)

## 제출 전 확인

- [ ] 새 시크릿 창에서 공개 주소를 열어 세 페이지가 모두 열린다.
- [ ] 버튼과 폼이 공개 주소에서 동작한다(내 PC의 `file://`이 아니라 공개 주소에서 확인한다).
- [ ] 저장소 첫 화면에 README가 보이고 표·코드 블록이 제 모양이며 도표와 캡처 두 장이 깨지지 않는다.
- [ ] 마지막으로 고친 것까지 push 했다. GitHub 저장소 화면에 `README.md` 와 `screenshots/`·`images/site-map.svg` 가 보인다.
- [ ] 저장소·공개 페이지·캡처에 실명·학번·전화번호·실제 이메일이 없다.
- [ ] 2분 안에 끝나는지 한 번 재 보았다.

## 장애가 났을 때

- 공개 주소 반영이 5분 넘게 늦으면 로컬 화면과 GitHub **Commits** 탭을 같은 점수로 인정한다.
- 발표 중 인터넷이 끊기면 차례를 뒤로 미루고 뒤 순서에 다시 발표한다.
- 기능 하나가 동작하지 않으면 되는 것부터 보여 준다. 남은 시간에 원인을 말하면 시간 점수는 유지된다.
