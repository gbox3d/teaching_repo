## 단계별 문제

1. ex01의 JSON 메시지를 바꾸고 글자와 배열을 Console에서 비교한다.
2. ex02에서 Network의 Request URL·Request Method·Status·Response를 찾아 GET 200을 확인한다.
3. ex03에서 limit을 1·2·5로 바꿔 응답 개수를 비교한다. 서버에 있는 글 수보다 많이 나오지는 않는다.
4. ex04의 li 표시 순서를 바꾼다. 서버 데이터를 바꾸지 않아도 화면 표현은 바뀐다.
5. ex05를 없는 끝점으로 바꾸고 status와 ok를 확인한 뒤 원래 주소로 되돌린다.
6. ex06에서 Network를 Offline으로 바꿔 실패 안내를 보고 No throttling으로 되돌린 뒤 재시도한다.

모든 코드는 [예제 설명](examples/README.md)에서 연다. 값 하나를 고친 뒤 결과를 확인하고 다음 값으로 넘어간다.

## 만들기

12주에는 guestbook.html을 서버 목록을 읽는 화면으로 바꾼다. 11주 localStorage 글을 옮기거나 지우지 않는다.

1. `config.example.js`에 강의자 안내값을 적는다. 예제마다 설정 파일이 있으므로 비교 예제의 값도 맞춘다.
2. [따라하기](walkthrough.md)의 만들기 순서로 파일을 작성한다. 홈·내 정보·공통 CSS는 지난주 파일을 이어 쓴다.
3. 새로 불러오기를 눌러 서버 목록과 화면이 일치하는지 확인한다.
4. 공용 HTTPS API가 설정되었다면 다른 브라우저·휴대폰에서 같은 공개 페이지를 연다. 로컬 API의 `127.0.0.1`은 기기마다 다르므로 다른 기기 공유 확인에 쓰지 않는다.

## 막혔을 때

| 증상 | 확인·조치 |
|---|---|
| Pages에 이전 화면이 보임 | 반영이 1~3분 늦을 수 있다. 5분 안에 안 보이면 로컬 화면과 Commits 탭을 제출하고 다음 수업에서 공개 URL을 확인한다 |
| `Failed to fetch` 또는 연결 실패 안내 | API가 실행 중인지, 주소가 맞는지, Network가 Offline인지 확인한다. CORS 허용은 강의자가 설정한다 |
| 401·403 응답 | 공개 API 키를 다시 확인한다. 서버 비밀 키나 편집 키로 임의 교체하지 않는다 |
| 빈 배열 `[]` | 요청 자체는 성공할 수 있다. BOOK_ID가 배부받은 번호인지와 서버에 글이 있는지 확인한다 |
| `Unexpected token` 등 JSON 오류 | Response가 JSON인지 확인한다. 정적 페이지 주소를 API 주소로 적지 않았는지 확인한다 |
| public HTTPS 페이지에서 로컬 API 사용 | 강의자가 제공한 HTTPS API로 바꾸거나 로컬 정적 서버로 실습한다 |

오류 문구는 브라우저와 서버에 따라 달라질 수 있다. Network의 실제 상태와 응답을 함께 확인한다.

## 제출물

서버 방명록 목록과 Network의 GET 200이 함께 보이는 화면을 캡처 한 장으로 제출한다. 코드와 비교 실험은 `web-week12` 저장소에 push한다.
공용 API가 아직 준비되지 않았다면 로컬 주소가 보이는 캡처를 인정하며 공유 검증 완료로 표시하지 않는다.

## 먼저 끝났다면

목록에서 메시지 앞에 서버 id를 표시하고 응답 배열과 대조한다. limit을 줄여 화면에 나온 개수를 확인한다.
