# 13주차 실습 — 페이지 점검하고 README 최종판 쓰기

실습 페이지: https://github.com/gbox3d/teaching_repo/tree/main/web_programming/weeks/week13_release_security

이번 주에는 새로 만드는 파일이 `about.js` 하나뿐이다. 나머지 시간은 지금까지 만든 네 페이지를 점검하고 고치는 데 쓴다.
2일차에는 저장소 `README.md`를 최종판으로 다시 쓴다. 이것이 14주차 레포트다.
모든 단계와 전체 코드는 [따라하기](walkthrough.md)에 있다. `student01`은 예시 아이디이므로 본인 아이디로 바꾼다.

**확인과 캡처는 공개 주소 `https://<아이디>.github.io/my-web/`에서만 한다.**
방명록에 남긴 글은 브라우저와 주소마다 따로 저장되고(11주차), 프로젝트 카드는 `file://`에서 읽히지 않는다(12주차).

## 1일차 — 페이지 점검하고 입학 연도 계산하기 (60분)

| 시간 | 할 일 |
|---|---|
| 0–5분 | 같은 PC면 `git pull`, 다른 PC면 `git clone https://github.com/<아이디>/my-web.git` |
| 5–18분 | `about.html`에 입학 연도 폼을 넣고 `about.js`로 몇 년차인지 계산한다 |
| 18–28분 | 방명록에 `<b>안녕</b>`을 남겨 글자 그대로 보이는지 확인한다 |
| 28–40분 | 네 페이지의 `img alt`·`label for`를 점검한다. 고칠 곳이 없으면 통과다. 이어서 카드 링크 글자 한 줄을 고친다 |
| 40–50분 | 링크 404 → Console 빨간 줄 → 기기 모드 375px 순서로 점검한다 |
| 50–55분 | 남은 점검을 마무리하고 고친 곳을 다시 새로고침한다 |
| 55–60분 | `git add .` → `git commit -m "…"` → `git push` → 공개 주소 새로고침 → 확인용 캡처 → 자격 증명 삭제 |

### 1. 입학 연도 폼 만들기 (`form` · `label for`)

`about.html`의 `head`에 `<script src="about.js" defer></script>`를 넣고, 표 아래에 입학 연도 폼을 만든다.
[따라하기 2단계](walkthrough.md#2-abouthtml에-입학-연도-폼-넣기)를 본다.

- `id`는 세 개다. 폼은 `year-form`, 입력 칸은 `year`, 결과가 보일 자리는 `year-result`.
- `label for="year"`의 값과 `input`의 `id`를 **글자까지 같게** 둔다. 이름표를 눌러 커서가 가면 맞다.
- 결과가 보일 `<p>`에는 `class="card"`를 붙인다. `styles.css`는 이번 주에 고치지 않는다.

### 2. `about.js`로 계산하기 (`Number` · `isNaN` · `getFullYear`)

`about.js`를 새로 만들고 제출 리스너 하나를 쓴다. [따라하기 3단계](walkthrough.md#3-aboutjs로-몇-년차인지-계산하기)를 본다.

- 순서는 7주차 방명록 폼과 같다: `event.preventDefault()` → `value.trim()` → 잘못된 입력이면 안내하고 `return` → 정상이면 화면에 쓰기.
- 숫자가 아닌지 묻는 조건은 `if (text === '' || isNaN(year))` 한 줄이다. 안내 문장은 `입학 연도를 숫자로 적어 주세요.`로 고정한다.
- 올해는 `new Date().getFullYear()`로 꺼낸다. 직접 `2026`이라고 적지 않는다.

### 3. 방명록 글자 확인하기 (`textContent`)

공개 주소의 `guestbook.html`에 이름 `student02`, 메시지 `<b>안녕</b>`으로 한 줄을 남긴다.
[따라하기 5단계](walkthrough.md#5-방명록에-b안녕b-남겨-보기)를 본다.

- 목록에 `<b>안녕</b>`이 **글자 그대로** 보이면 맞다. 굵은 글씨가 되면 `guestbook.js`의 `li.textContent` 줄을 확인한다.
- `innerHTML`은 `showList()` 첫 줄의 `list.innerHTML = ''`처럼 **비울 때만** 쓴다.
- 확인이 끝나면 **전체 지우기**로 비운다. 제출 캡처는 2일차 끝에 한 줄을 다시 남겨 찍는다.

### 4. `alt`·`label for`·링크 글자 점검하기

네 페이지를 차례로 열어 세 가지를 본다. [따라하기 6~7단계](walkthrough.md#6-그림의-alt와-폼의-label-점검하기)를 본다.

| 볼 것 | 확인 방법 |
|---|---|
| `img alt` | 그림마다 `alt`가 비어 있지 않은가 (`index.html`의 프로필 그림, `projects.js`가 만드는 카드 그림) |
| `label for` | 이름표 글자를 눌렀을 때 옆 입력 칸에 커서가 가는가 (입학 연도·이름·이메일·메시지) |
| 링크·버튼 글자 | 그 글자만 읽어도 어디로 가는지 알 수 있는가 |

- 3주차부터 `alt`와 `label for`를 넣어 왔으므로 대개 고칠 곳은 **새로 만든 폼 하나**뿐이다.
- 카드 링크는 세 장이 모두 `페이지 열기`였다. `projects.js` 한 줄을 `` `${projects[i].title} 열기` ``로 바꾼다.
- `projects.html`의 카드는 공개 주소에서만 보인다. push한 뒤 확인한다.

### 5. 링크·Console·375px 점검하기

순서를 바꾸지 않는다. 링크가 깨진 채로 Console을 보면 원인이 섞인다.

1. 네 페이지의 nav 링크 네 개를 **모두 눌러 본다.** 404가 없어야 한다.
2. 각 페이지에서 **F12 › Console**에 빨간 줄이 없는지 본다.
3. **F12 › 기기 모드**(휴대전화 아이콘) 폭 **375**에서 네 페이지를 본다. 가로로 밀리는 곳이 없어야 한다.

- 404는 파일 이름의 철자와 **대소문자**부터 본다. 공개 주소는 대소문자를 구분한다.
- 빨간 줄은 끝의 `파일:줄 번호`부터 읽는다. 대개 `id` 철자이거나 `script` 줄이다.
- 375에서 nav가 세로로 접히면 4주차 `@media`가 살아 있는 것이다. `styles.css`는 고치지 않는다.

### 6. 오늘 확인할 것

- [ ] 공개 주소 `/my-web/about.html`에서 `2023`을 적고 **계산하기**를 누르면 `…년차입니다.`가 보인다.
- [ ] 숫자가 아닌 글자를 적으면 `입학 연도를 숫자로 적어 주세요.`가 보인다.
- [ ] 방명록 목록에 `<b>안녕</b>`이 글자 그대로 보인다.
- [ ] 카드 세 장의 링크 글자가 서로 다르다.
- [ ] 네 페이지 링크가 모두 열리고 Console에 빨간 줄이 없으며 375px에서 가로로 밀리지 않는다.
- [ ] 기기 모드 375px에서 찍은 방명록 **확인용 캡처** 1장을 저장했다. 제출은 2일차 마지막에 한 번만 한다.

## 2일차 — README 최종판과 발표 준비 (60분)

| 시간 | 할 일 |
|---|---|
| 0–5분 | `git pull`. 어제 찍은 확인용 캡처와 공개 주소를 함께 열어 둔다 |
| 5–30분 | `screenshots/`에 그림 세 장을 넣고 `README.md` 최종판을 쓴다 |
| 30–40분 | push한 뒤 저장소 첫 화면에서 README와 그림 세 장을 확인하고 고친다 |
| 40–55분 | 짝과 3분 시연을 한 번씩 해 본다 |
| 55–60분 | `git add .` → `git commit -m "…"` → `git push` → 공개 주소 새로고침 → **375px 방명록 제출 캡처** → 자격 증명 삭제 |

### 1. 캡처 세 장 준비하기 (`screenshots/`)

공개 주소에서 홈·방명록·프로젝트 화면을 찍어 `screenshots/`에 넣는다. [따라하기 10단계](walkthrough.md#10-화면-캡처-세-장-넣기)를 본다.

- 파일 이름은 `home.png`·`guestbook.png`·`projects.png`로 통일한다. 한글·공백·대문자를 쓰지 않는다.
- 9주차에 찍은 두 장은 nav가 세 페이지였으므로 **새로 찍어 덮어쓴다**.
- 캡처에 실명·학번·전화번호·실제 이메일이 보이지 않게 한다.

### 2. `README.md` 최종판 쓰기 (마크다운 네 가지)

9주차 1차판을 지우고 일곱 절로 다시 쓴다. [따라하기 11단계](walkthrough.md#11-readmemd-최종판-쓰기)를 본다.

| 절 | 넣을 것 |
|---|---|
| 공개 주소 | `https://<아이디>.github.io/my-web/` |
| 페이지 | 네 페이지와 한 줄 설명 |
| 기능 | 다섯 줄 |
| 화면 | 캡처 세 장(그림은 링크 앞에 `!`) |
| 사용 기술 · 어려움과 해결 · 만든 과정 | 각각 세 줄 안팎 |

- 쓰는 기호는 네 가지다. 제목 `#`, 목록 `-`, 링크 `[보이는 글](https://주소)`, 그림(링크 앞에 `!`).
- 그림은 `!`로 시작한다. `!`가 없으면 그림 대신 링크가 된다.
- VS Code에서 **Open Preview**로 보면서 쓴다.

### 3. 만든 과정 붙이기 (`git log --oneline`)

터미널에서 `git log --oneline`을 실행해 최근 다섯 줄을 README 마지막 절에 옮겨 적는다.
[따라하기 12단계](walkthrough.md#12-commit-기록을-readme에-붙이기)를 본다.

- 앞의 일곱 글자는 PC마다 다르다. **본인 화면의 값**을 적는다.
- 목록에서 빠져나올 때는 `q`를 누른다.

### 4. 저장소 첫 화면에서 확인하기

push한 뒤 `https://github.com/<아이디>/my-web`을 새로고침한다. [따라하기 13단계](walkthrough.md#13-저장소-첫-화면에서-readme-확인하기)를 본다.

- 파일 목록 아래에 README가 문서로 보이고 그림 세 장이 모두 나와야 한다.
- 깨진 아이콘이 보이면 파일 이름의 대소문자, `screenshots/` 경로, 그림을 `git add .`로 올렸는지 순서대로 본다.
- **Settings › Pages**를 열어 Source가 `main` · `/(root)`인지만 확인한다. **바꾸지 않는다.**

### 5. 3분 시연 연습하기

짝과 한 번씩 시연한다. 말은 줄이고 화면을 누른다.

```text
공개 주소 열기 → nav로 페이지 이동 → 다크 모드 → 폼 빈값 안내
→ 방명록 추가·삭제 → 새로고침해도 남는 목록 → 프로젝트 카드 → Commits 탭
```

- 3분을 실제로 재어 본다. 넘치면 설명을 줄이고 화면을 더 빨리 넘긴다.
- 방명록에 남길 글은 미리 정해 둔다. 실명·이메일을 적지 않는다.

### 6. 오늘 확인할 것

- [ ] 저장소 첫 화면에 README 최종판이 보이고 그림 세 장이 깨지지 않는다.
- [ ] README의 공개 주소 링크를 눌렀을 때 내 페이지가 열린다.
- [ ] `만든 과정`에 본인 `git log --oneline` 다섯 줄이 있다.
- [ ] 3분 안에 시연을 마쳤다.
- [ ] 기기 모드 375px 공개 주소에서 방명록 **제출 캡처** 한 장을 찍어 저장했다.

## 막혔을 때

아래 문구는 실제로 재현해 본 Console·화면 문구다.

| 증상 | 확인할 것 |
|---|---|
| push했는데 공개 페이지가 그대로다 | **Pages 반영은 1~3분 늦다.** 5분 안에 안 보이면 로컬 화면 캡처와 GitHub **Commits** 탭 캡처를 같은 점수로 인정한다. 다음 수업 시작 5분에 Pages 확인을 해도 된다 |
| `Uncaught TypeError: Cannot read properties of null (reading 'addEventListener')` (`about.js:5`) | `#year-form`을 찾지 못했다. `about.html`의 `<form id="year-form">` 철자와 `about.js`의 `querySelector('#year-form')`를 맞춘다. `<script src="about.js" defer></script>`에 `defer`가 있는지도 본다 |
| `Uncaught TypeError: Cannot set properties of null (setting 'textContent')` (`about.js:16`) | `#year-result`를 찾지 못했다. 결과가 보일 `<p class="card" id="year-result">`의 `id` 철자를 본다 |
| **계산하기**를 눌렀더니 화면이 깜빡이고 주소창 끝에 `?`가 붙어 `about.html?`이 된다 | `event.preventDefault()`가 빠졌거나 `about.js`가 연결되지 않았다. 폼은 원래 눌리면 주소로 보내며 화면이 새로 열린다(3주차). `head`의 `script` 줄과 리스너 첫 줄을 본다 |
| 숫자를 적었는데 `입학 연도를 숫자로 적어 주세요.`가 나온다 | `2023년`처럼 글자가 섞여 있으면 `Number()`가 `NaN`이 된다. 숫자만 적는다 |
| `const years = thisYear - year + 1;`의 `year`를 `text`로 바꿔도 숫자만 적으면 `4년차`가 그대로 나온다 | 뺄셈이 글자를 숫자로 바꿔 주기 때문이다. 반대로 `const year = Number(text);` 줄 자체를 지우면 `2023`을 적어도 늘 `입학 연도를 숫자로 적어 주세요.`가 뜬다. `year`가 입력 칸을 가리키게 되기 때문이다 |
| 방명록 목록에서 `<b>안녕</b>`이 **굵게** 보인다 | 목록을 만드는 줄이 `li.innerHTML = …`이다. `li.textContent = …`로 바꾼다. `innerHTML`은 `list.innerHTML = ''`에만 남긴다 |
| 카드 링크 글자가 그대로 `페이지 열기`다 | `projects.js`를 고친 뒤 push하지 않았거나 Pages 반영 전이다. **Ctrl+F5**(macOS는 ⌘+Shift+R)로 새로고침한다 |
| 카드 링크에 `${projects[i].title} 열기`가 글자 그대로 보인다 | 템플릿 문자열의 백틱(`` ` ``)을 작은따옴표로 적었다. 오류는 나지 않는다. 따옴표를 백틱으로 바꾼다 |
| 링크를 눌렀더니 GitHub의 **404** 화면이 나온다 | 주소창의 파일 이름을 본다. 철자와 **대소문자**가 저장소의 파일 이름과 같아야 한다. `About.html`과 `about.html`은 다른 파일이다 |
| 그림이 깨져 보이거나 `about.js`가 동작하지 않는다 | **F12 › Network**에서 그 파일의 Status를 본다. **404**면 못 찾은 것이다. `images/`·`screenshots/` 안 파일 이름과 `src`에 적은 이름의 대소문자를 맞춘다 |
| 저장소 첫 화면의 README에서 그림만 깨진다 | `screenshots/home.png`와 `screenshots/Home.png`는 다른 파일이다. 파일 이름을 맞추고, 그림을 `git add .`로 올렸는지 저장소 `screenshots` 폴더에서 확인한다 |
| 방명록 목록이 강의자 화면과 다르다 | 정상이다. 방명록은 **내 브라우저, 내 주소**에만 저장된다(11주차). 다른 PC·다른 브라우저에서는 목록이 비어 있다 |
| 기기 모드 375px에서 가로 스크롤이 생긴다 | 표나 긴 글자가 원인인지 본다. `styles.css`는 이번 주에 고치지 않으므로 먼저 강의자에게 보여 준다 |
| `git push` 뒤 `Permission to student01/my-web.git denied to <다른 아이디>` | 공용 PC에 이전 사용자 로그인이 남아 있다. **자격 증명 관리자 › Windows 자격 증명**에서 `git:https://github.com`을 제거하고 다시 push한다 |

한 번에 한 곳만 고치고 다시 새로고침한다. 해결되지 않으면 Console 화면을 그대로 보여 주고 도움을 받는다.

제출 캡처는 **2일차 끝 루틴**(55–60분)에서 찍는다. [따라하기 15단계](walkthrough.md#15-제출-캡처-찍고-마무리하기)를 본다.
공개 주소 `https://<아이디>.github.io/my-web/guestbook.html`을 **F12 › 기기 모드 375px**로 열고 다음이 한 화면에 보이게 찍는다.
목록이 비어 있으면 이름 `student02`, 메시지 `<b>안녕</b>`으로 한 줄을 다시 남긴 뒤 찍는다.

1. 이름 `student02`, 메시지 `<b>안녕</b>`으로 남긴 한 줄이 **글자 그대로** 보인다
2. **F12 › Console**에 빨간 줄이 없다
3. 주소창(공개 주소가 보여야 한다)

완료 기준은 입력한 글이 태그가 아니라 글자로 보이고 Console이 깨끗한 것이다.
`about.html`의 `…년차입니다.` 화면은 1일차 확인용이며 제출물이 아니다.
캡처에 이메일·실명이 보이지 않게 한다. 제출 위치와 마감은 수업 공지를 따른다.

## 먼저 끝났다면

- 입학 연도에 올해보다 큰 수(예: `2030`)를 적어 보고 어떤 문장이 나오는지 본다. 안내를 하나 더 넣으려면 `if`를 어디에 넣어야 할지 생각해 본다.
- 방명록 이름 칸에 `<img src=x>`를 넣어 보고 목록에 어떻게 보이는지 확인한다. 글자 그대로 보이면 안전한 것이다.
- `projects.js`의 `image.alt`를 잠깐 지워 보고, DevTools **Elements**에서 `img` 태그가 어떻게 달라지는지 본다. 확인한 뒤 되돌린다.
- README에 여덟 번째 절 **앞으로 해 보고 싶은 것**을 두 줄로 더해 본다. 14주차 발표 마무리에 쓸 수 있다.
- 기기 모드에서 폭을 320으로 더 줄여 보고 어디가 먼저 깨지는지 본다. 고치지는 않는다.

추가 과제는 선택 사항이다.
