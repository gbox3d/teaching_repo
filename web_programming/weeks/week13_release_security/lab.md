# 13주차 실습 · POST와 저장 후 조회

파일 배부·새 저장소·서버 준비는 수업 전에 마친다. 각 차시는 강의·시연 60분 뒤 학생 실습 30분이다. 설정 패널·대기 상태·실패 처리·오래된 응답 방지는 제공 코드다.

## 1일차 실습

| 시간 | 필수 활동 |
|---|---|
| 0–10분 | ex02 `requests.http`에서 about·help를 Send Request로 확인하고 POST의 message 한 값을 바꿔 전송 |
| 10–20분 | 201 응답의 id를 읽고 이어지는 GET 200에서 같은 글 확인 |
| 20–30분 | ex03 또는 같은 `.http` 마지막 요청의 빈 메시지 400을 정상 문장의 201과 비교 |

`.env.example`을 복사한 `.env`의 API 주소·공개 키·방명록 번호와 `apikey`·`Content-Type`·`Prefer` 헤더를 확인한다. ex01 JSON 변환과 JS의 POST 전체는 강의자가 시연한다. 학생은 `.http` 요청의 message 값만 바꾸며 서버 설정을 새로 구현하지 않는다.

## 2일차 실습

| 시간 | 필수 활동 |
|---|---|
| 0–15분 | 제공 `guestbook.js`에서 학생 수정 1(폼 값), 2(JSON 본문), 3(loadMessages) 세 구역을 확인·변경 |
| 15–22분 | 별칭과 메시지 저장, 느린 연결 중복 클릭·Offline 실패 입력 보존 확인 |
| 22–30분 | 두 번째 브라우저에 같은 설정 적용, GET 확인, POST 201 → GET 200 캡처 |

`method: 'POST'`, 공개 키와 JSON 헤더를 읽고 본문의 `name`·`message`가 폼 입력과 일치하는지 확인한다. ex04~ex06을 전부 타이핑하지 않는다. GET·POST는 `guestbook.js` 안에 있고 `submit.js`를 별도로 연결하지 않는다.

## 확인 순서

1. 공백만 입력했을 때 안내가 나오고 POST가 없는지 확인한다.
2. 별칭과 `<b>연습</b>`를 저장하고 화면이 글자 그대로 표시하는지 본다.
3. Network의 속도를 낮춘 뒤 저장 중 버튼 비활성화를 확인한다. Offline에서는 입력이 남고 버튼이 다시 활성화되어야 한다.
4. No throttling으로 복구한다. 저장 응답을 못 받았다면 GET으로 먼저 확인한다. 저장이 확인된 글을 다시 POST하지 않는다.
5. 새로고침하면 로컬 설정으로 돌아간다. 공용 API를 쓰던 경우 설정을 다시 적용한 뒤 같은 글을 확인한다.

## 막혔을 때

| 증상 | 확인·조치 |
|---|---|
| 조회·저장 통신 실패 | API 실행·주소·Offline 상태 확인 |
| 401·403 | 공개 키 확인. 편집 키·서버 비밀 키로 바꾸지 않음 |
| POST 400 | book_id·이름·메시지·JSON 형식 확인 |
| POST 성공인데 조회 실패 | 저장 안내를 유지하고 새로 불러오기로 GET만 다시 실행 |
| 저장 응답 불명확 | 입력을 보존하고 GET·서버 목록으로 먼저 확인. 재POST를 자동 반복하지 않음 |
| 설정 변경 뒤 글이 다름 | API 주소와 방명록 번호 확인. 진행 중이던 이전 저장 결과는 이전 설정에서 GET |
| 새로고침 뒤 공용 글이 없음 | 공용 API 설정 재입력. 메모리 설정은 새로고침 시 초기화됨 |
| 다른 기기에서 localhost 실패 | 같은 PC의 로컬 연습과 구분하고 공용 HTTPS API로 확인 |

## 제출과 선택 연습

POST 201·GET 200과 저장한 글이 보이는 캡처를 제출한다. 로컬 API인지 공용 API인지 적는다. 같은 PC의 서로 다른 브라우저에서 확인한 결과와 다른 기기 공유 확인을 구분한다. 저장소 commit·push·Pages 확인은 수업 뒤에 한다.

선택 연습은 POST 성공 뒤 GET만 실패시키기, 설정을 바꾼 뒤 느린 이전 응답이 목록을 덮지 않는지 관찰하기다. 공개 API에서는 실패를 만들려고 반복 POST하지 않는다.
