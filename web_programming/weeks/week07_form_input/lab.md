# 7주차 CSS 응용 실습 · 모바일 피드와 방명록

1일차에는 W3.CSS로 메뉴를 꾸미고 트위터식 피드의 행 여백을 바꾼다. 2일차에는 본인 방명록에 같은 목록 모양을 적용하고 글 두 건을 등록한다. 제출물은 완성한 방명록의 375px 화면 한 장이다.

파일과 저장소는 [수업 전 준비](walkthrough.md#수업-전-준비)에서 마련한다. 매일 강의·시연 60분 중 첫 5분은 준비 상태 확인, 마지막 5분은 실습 안내에 쓴다. 이어지는 30분은 아래 표에 따라 진행한다. 폼 JavaScript는 제공 코드를 쓰고 push와 Pages 확인은 수업 뒤에 한다.

| 5–10분 | ex02의 버튼 색상 또는 입력창 테두리 변경 | 이름·메시지를 제출하면 미리보기가 표시됨 |

### ex01 CDN 연결과 색상

`examples/day1/ex01/before.html`과 `index.html`을 각각 연다. 두 화면에서 버튼을 눌러 같은 동작을 확인한다. 강의자는 `index.html`의 `w3-teal`을 `w3-blue`로 바꾸고 새로고침하여 색상 변화를 시연한다. 학생의 같은 변경은 선택이며 `id="button"`은 유지한다.

F12의 Network에서 **Disable cache**를 켜고 새로고침한 뒤 `w3.min.css`를 찾는다. 요청 주소가 `https://cdnjs.cloudflare.com/ajax/libs/w3-css/4.1.0/w3.min.css`이고 상태가 200인지 확인한다. 연결 실패 시 인터넷과 `<link>` 주소를 먼저 확인한다.

### ex02 입력창과 버튼

`examples/day1/ex02/index.html`에서 `w3-input w3-border`와 `w3-button`을 찾는다. 버튼의 색상 한 곳을 바꾸거나 입력창의 `w3-border`를 잠시 제거해 모양을 비교한다. 제거한 테두리는 비교 후 복구한다.

이름에 `student01`, 메시지에 `안녕하세요`를 넣고 제출한다. 결과에 입력값이 표시되고 입력 칸의 글자가 남아 있으면 정상이다. 이 예제는 입력 미리보기이며 방명록 목록 추가는 2일차에 확인한다.

### ex03 카드와 메뉴

`examples/day1/ex03/index.html`에서 `w3-card`, `w3-container`, `w3-bar`, `w3-mobile`을 찾는다. 메뉴 색상 한 곳 또는 카드의 여백 클래스를 바꾼다. F12의 기기 도구 모음에서 Responsive 폭을 375와 1280으로 바꿔 메뉴와 입력창을 비교한다.

`w3-mobile`은 600px 이하에서 해당 메뉴 항목을 블록으로 표시한다. 375px에서 메뉴가 세로로 보이고 입력창이 화면 안에 들어오는지 확인한다. 두 카드는 화면 폭과 관계없이 위아래로 놓인다.

### ex03b 모바일 피드의 행 간격

[수업 타임라인](examples/day1/ex03b_list/index.html)을 연다. `Tab`으로 **새 글 1개 보기**에 이동해 `Enter`를 누른다. 맨 위에 나타난 10:42 글에서 김민서 이름에 초점이 보인다. 아래 글과 비교해 이름 한 글자를 넣은 원, 작성자, 시각, 본문을 찾는다. HTML의 `ol` 안에는 글 하나가 `li` 하나로 들어간다.

예제 폴더의 `shared/examples.css`에서 `.post`의 `padding-block`을 `0.5rem`에서 `1rem`으로 바꾼다. 저장 후 새로고침하고 박준호의 글을 다시 본다. 글 위아래의 여백이 늘고 본문과 구분선 사이가 넓어진다. 폭을 375px와 1280px로 바꾸면서 이 글의 줄 수를 비교한다. [예제 설명](examples/day1/ex03b_list/README.md)

| 25–30분 | 주소와 글 두 건이 보이는 화면 캡처 | 제출용 실행 화면 한 장 |

### 변환 전후 비교

ex04와 ex05에 같은 이름·메시지를 입력한다. 두 화면 모두 빈값을 안내하고 정상 입력을 목록에 추가한다. VS Code에서 두 `app.js`를 비교하면 차이가 없다. HTML에서 바뀐 부분은 CDN 연결과 화면 구성·클래스다.

제공 JS에서 `submit` → `.value.trim()` → 빈값 검사와 `return` → 글 한 행 생성 → 목록 맨 앞에 삽입 → `reset`·`focus` 순서를 찾는다. 이 흐름은 후속 수업에서 다시 사용한다.

### 방명록 변환

수업 전에 `guestbook.before.html`을 복사해 둔 `web-week07/guestbook.html`에서 시작한다. 기존 `styles.css` 링크를 CDN으로 교체하고 입력·버튼·메뉴·카드를 꾸민다. 남긴 글 목록에도 피드용 클래스를 적용한다. 제목 또는 버튼 색상 한 곳은 본인이 선택한다. [클래스 매핑표](walkthrough.md#9-방명록-html-변환)

비교용 [ex05](examples/day2/ex05/index.html)와 별도 보관한 `guestbook.reference.html`은 대조용이다. 제공된 `guestbook.js`와 연결된 `id`는 유지한다. 홈과 소개 페이지는 기존 파일을 사용한다.

다음 순서로 확인한다.

1. 이름을 비우고 남기기를 누른다. 이름 안내가 나타나고 목록은 늘지 않는다.
2. 이름만 넣고 남기기를 누른다. 메시지 안내가 나타난다. 해당 칸에 입력하면 안내가 사라진다.
3. 이름 `student01`로 `안녕하세요`를 남기고 `student02`로 `반갑습니다`를 남긴다. 같은 주소에서 위쪽 행은 `student02`, 아래쪽 행은 `student01`이어야 한다. 각 행에서 작성자 아래에 해당 본문이 보이고 두 글 사이에 구분선이 있는지 확인한다.
4. 제출 후 입력이 비고 이름 칸에 커서가 오는지 확인한다.
5. 폭 375px에서 메뉴·입력·목록이 화면 안에 들어오는지 확인한다. Network의 CDN 요청과 Console도 확인한다.

이메일은 비워 두어도 된다. 입력한다면 `student01@example.com` 같은 예시 주소를 쓴다. `abc`처럼 이메일 형식이 아니면 브라우저가 먼저 제출을 막는다. JS 오류로 오해하지 않도록 이메일을 비우고 다시 확인한다.

## 제출 — 캡처 한 장

375px 실행 화면 한 장을 제출한다. 주소, W3.CSS 방명록, 등록한 글 두 건, 변경한 색상이 보이게 찍는다. 빈값 안내는 실습 중 확인하며 별도 캡처는 필요 없다. 공개 페이지 준비 전에는 localhost 실행 화면을 먼저 남기고, 수업 뒤 Pages 주소를 확인한다.

제출 저장소는 `web-week07`이다. push와 Pages 설정은 [수업 뒤 게시](walkthrough.md#수업-뒤-게시)에서 진행한다. 실명·학번·전화번호·실제 이메일은 사용하지 않는다.

## 막혔을 때

모양이 적용되지 않으면 CDN 주소와 Network 응답을 확인한다. 입력 결과가 나오지 않으면 `id`, JS 연결, Console 오류를 확인한다. 메뉴가 좁은 화면에서 세로로 바뀌지 않으면 각 메뉴 항목의 `w3-mobile`을 확인한다. 경로별 점검은 [문제 해결](walkthrough.md#문제-해결)에 있다.

## 먼저 마친 학생

375px와 1280px에서 같은 색상과 메뉴를 비교하고 긴 메시지를 입력해 본다. 제목과 버튼의 색상을 함께 맞춰도 된다. 애니메이션, 모달, 새 JavaScript 기능은 기본 과제에 포함하지 않는다.

완료한 웹 파일은 9주 README 수업의 시작 파일로 보관한다. 중간시험 답안으로 교체하지 않는다.
