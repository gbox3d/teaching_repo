# w14_readme_images — README 최종판과 그림 세 장

출처: [14주차 실습 제출](../../../week14_project_presentation/lab.md#제출--캡처-한-장과-발표) · 권장 9분 · 기말 A(화면(HTML·CSS·README))

14주차 README 최종판을 네 절로 줄여 다른 값으로 다시 쓴다. 이 폴더의 사이트를 소개하는 `README.md` 를 만들고, `screenshots/` 의 그림 세 장을 링크가 아니라 그림으로 넣는다. 그림 파일 이름은 대소문자까지 맞아야 GitHub 에서 깨지지 않는다.

## 시작 파일

| 파일 | 지금 상태 |
|---|---|
| `index.html` | 14주 사이트의 홈 페이지다. 인사말 카드, [인사 바꾸기]·[다크 모드] 버튼, 클릭 횟수, 소개가 있다. 고치지 않는다 |
| `styles.css`·`app.js`·`images/profile.png` | 홈 페이지의 CSS·JavaScript·프로필 그림이다. 고치지 않는다 |
| `screenshots/Home-Page.png` | 홈 화면을 찍은 그림이다 |
| `screenshots/Guest-Book.png` | 방명록 화면을 찍은 그림이다 |
| `screenshots/Project-List.png` | 프로젝트 화면을 찍은 그림이다 |
| `README.md` | 없다. 이 문제에서 새로 만든다 |

그림 세 장의 이름은 바꾸지 않는다.

## 할 일

이 문제 폴더 안(`index.html` 옆)에 `README.md` 를 만들어 아래 차례로 쓴다. 저장소에서 보면 `w14_readme_images/README.md` 다.
쓰는 기호는 제목 `#`·`##`, 목록 `-`, 링크 `[보이는 글](https://주소)`, 그림 네 가지다. 그림은 링크 앞에 `!` 를 붙이고, 대괄호 안이 설명 글, 소괄호 안이 경로다.

1. 첫 줄은 `#` 제목이고 글자는 `나의 웹 연습장` 이다.
2. 절 제목은 `##` 으로 넷이다. 차례: `공개 주소` → `기능` → `화면` → `어려움과 해결`. 다른 절은 넣지 않는다.
3. `공개 주소` 절에 목록 두 줄을 쓴다.
   - 첫 줄: 이 폴더의 공개 주소 링크. 주소는 `https://<아이디>.github.io/web-week15/w14_readme_images/` 다(올린 뒤 이 폴더의 `index.html` 이 열린다).
   - 둘째 줄: 이 사이트를 소개하는 문장 한 줄.
4. `기능` 절에 이 사이트에서 되는 일을 목록 5줄로 쓴다. 홈 페이지와 그림 세 장을 보고 쓴다.
5. `화면` 절에 그림 세 장을 아래 차례로 넣는다. 설명 글은 표의 글자대로 쓰고, 경로는 `screenshots/` 뒤에 파일 이름을 대소문자까지 똑같이 붙인다.

   | 차례 | 설명 글 | 파일 이름 |
   |---|---|---|
   | 1 | `홈 화면` | `Home-Page.png` |
   | 2 | `방명록 화면` | `Guest-Book.png` |
   | 3 | `프로젝트 화면` | `Project-List.png` |

6. `어려움과 해결` 절에 겪은 어려움과 해결을 목록 3줄로 쓴다. 한 줄에 어려움 하나와 그 해결을 함께 쓴다.

## 확인할 것

- [ ] 서버로 연 이 폴더 주소 뒤에 `README.md` 를 붙여 열면 404 가 아니라 쓴 글이 그대로 보인다.
- [ ] VS Code 에서 `README.md` 를 열고 **Open Preview** 를 누르면 맨 위에 큰 제목 하나가 보이고 글자는 `나의 웹 연습장` 이다.
- [ ] 절 제목이 `공개 주소` · `기능` · `화면` · `어려움과 해결` 넷뿐이고 이 차례다. `##` 이 글자로 보이는 줄이 없다.
- [ ] `공개 주소` 절은 목록 두 줄이다. 첫 줄은 누르면 열리는 링크이고 주소가 `https://<아이디>.github.io/` 로 시작한다. 둘째 줄은 소개 문장이다.
- [ ] `기능` 절은 목록 5줄, `어려움과 해결` 절은 목록 3줄이다.
- [ ] `화면` 절에 그림 세 장이 표의 차례대로 그림으로 보인다. 파란 글자 링크로 보이는 그림 줄이 없다.
- [ ] 그림 줄의 설명 글과 경로가 표와 글자 하나까지 같다. 내 PC 에서는 대소문자가 틀려도 그림이 보이므로 `screenshots/` 폴더의 파일 이름과 한 글자씩 맞춰 본다.
- [ ] 올린 뒤 공개 주소 끝에 `screenshots/Home-Page.png` 를 붙여 열면 그림이 나온다. 나머지 두 장도 같다(F12 › Network 에서 200).
- [ ] 올린 뒤 GitHub 저장소에서 이 폴더를 열면 파일 목록 아래에 README 가 문서로 보이고 그림 세 장이 깨지지 않는다.
- [ ] 이 폴더의 `index.html` 을 열면 F12 › Console 에 빨간 줄이 없다.

## 받기와 올리기

- 이번 주 저장소(`web-week15`) 맨 위에 [server.mjs](../../../../tools/static-server/server.mjs) 가 없으면 먼저 **Raw** 로 받아 둔다.
- 저장소 안에 `w14_readme_images/` 폴더를 만든다. 교재의 이 문제 폴더에 있는 시작 파일을 하나씩 열어 **Raw** 를 누르고 Ctrl+S(macOS ⌘+S)로 같은 이름으로 저장한다. 그림도 Raw 를 누르면 그림만 보이는 화면이 열리고, 거기서 같은 방법으로 저장한다. 하위 폴더(그림·데이터)는 GitHub 에서 그 폴더를 눌러 들어가 받고, 내 폴더에도 같은 이름으로 만든다. 저장한 이름 끝에 `.txt` 가 붙었으면 지운다. 이 `README.md`(지금 읽는 문제 문장)는 받지 않는다.
- 저장소 맨 위에서 `node server.mjs` 로 열면 주소는 `http://localhost:8000/w14_readme_images/` 이다. Node 가 없는 PC 는 두 번 눌러 연다.
- `node server.mjs` 로 연 주소나 공개 주소에서는 `favicon.ico` 404 한 줄이 Console·Network 에 보여도 괜찮다(빨간 줄로 세지 않는다). 공개 주소에서 새로고침하면 Status 가 `304` 로 보일 수 있다. 이미 받은 파일을 다시 쓴다는 뜻이다.
- 올린 뒤 공개 주소는 `https://student01.github.io/web-week15/w14_readme_images/`이다.
- 해답은 공개하지 않는다. 위 "확인할 것"이 모두 맞으면 된 것이다.
