# 기말 개인 실기 채점표 — 20점 (안)

배점은 강의계획 비중 승인 전까지 **안**이다. 확정 배점은 수업 공지를 따른다.
채점 대상은 제출한 공개 주소 `https://<아이디>.github.io/web-week15/exam/` 과 저장소 `web-week15` 의 `exam/` 폴더다. 1일차 연습 폴더는 채점하지 않는다.
시험은 [문제 은행](examples/README.md)에서 영역(A~E)마다 한 문제씩, 같은 문제를 값만 바꿔서 낸다. 이 문서에는 시험에 나온 문제와 값, 해답이 없다.

## 구현 15점

| 영역 | 배점 | 나올 수 있는 은행 문제 | 확인하는 것 |
|---|---:|---|---|
| A 화면(HTML·CSS·README) | 3 | `w01_link_fix` · `w02_about_page` · `w03_guestbook_form` · `w04_responsive_css` · `w09_readme_links` · `w14_readme_images` | 파일 연결과 요청 200, 새 페이지와 상대 링크, 폼 구조와 이름표, 폭에 따른 메뉴·카드 모양, README 의 제목·목록·링크·그림 |
| B DOM | 3 | `w05_greeting_card` · `w06_dark_mode` · `w13_text_safe` | 화면 글자와 class 가 바뀌는 것, 입력한 글이 글자 그대로 보이는 것 |
| C 폼·목록 | 4 | `w07_form_result` · `w10_list_delete` | 제출 결과 한 줄, 빈값 안내와 커서, 목록 추가·줄마다 삭제·개수 |
| D 저장(localStorage) | 2 | `w11_local_storage` | 새로고침해도 남는 목록, 저장 키와 값, 그 키만 지우기 |
| E 불러오기(fetch) | 3 | `w12_fetch_cards` | 상대 경로 요청과 200, 카드, 404·요청 실패 때 안내 문장과 `Uncaught` 없음 |
| 합계 | 15 | | |

- 영역마다 그 문제 문장의 **"확인할 것"** 항목으로 본다. 완전 충족은 "확인할 것"이 모두 맞는 것이다.
- 확인은 결과(화면 글자·계산된 스타일·Console·Network·저장 값)로 본다. 같은 결과를 내면 다른 방법(`var`·`getElementById`·`innerText` 등)으로 써도 정답이다.
- Console 빨간 줄은 문제마다 "확인할 것"의 한 항목으로 본다. 따로 점수를 두지 않는다.

## 시연 5점

| 항목 | 배점 | 완전 충족 |
|---|---:|---|
| URL 재현 | 3 | 채점자가 제출한 공개 주소 `https://<아이디>.github.io/web-week15/exam/` 을 새 시크릿 창으로 열고, 목차에서 다섯 문제를 차례로 열어 요구 동작이 그대로 된다 |
| 구술 | 2 | 시험 후반 30분에 강의자가 좌석을 돌며 1분씩 묻는다. 본인 코드에서 강의자가 가리킨 한 줄이 하는 일을 맞게 말한다 |

- 시연은 발표가 아니다. URL 재현은 채점자의 브라우저에서, 구술은 시험 중 좌석에서 본다. 구술에 쓴 1분은 그 학생의 마감에서 돌려준다.
- URL 재현은 새 시크릿 창으로 연다. 이전에 열었던 저장 칸(Local Storage)이 섞이지 않게 하기 위해서다.
- URL 재현은 공개 주소에서 목차와 다섯 문제가 열리고, 내 PC 에서 맞춘 결과가 공개 주소에서도 같은지(파일 이름 대소문자, `/` 로 시작하는 경로, 올리지 않은 파일 때문에 달라지지 않는지)를 본다. 구현에서 이미 틀린 항목은 여기서 다시 깎지 않는다. 일부 문제만 같게 열리면 그 문제 수에 비례해 준다(안).
- README 문제는 공개 주소의 그 문제 폴더 뒤에 `README.md` 를 붙여 열거나, GitHub 저장소의 그 폴더 화면으로 본다.
- 구술의 예: `event.preventDefault();` 를 가리키면 "폼을 제출할 때 페이지가 새로고침되지 않게 막는다."

## 수준별 판단

구현은 영역마다 그 문제의 "확인할 것"으로, 시연은 위 표의 "완전 충족" 칸으로 같은 세 수준을 본다.

| 수준 | 뜻 | 점수 |
|---|---|---|
| 완전 충족 | 요구한 것이 모두 맞는다(구현은 그 문제의 "확인할 것" 전부). 채점자의 브라우저에서 공개 주소로 그대로 재현된다 | 배점 전부 |
| 부분 충족 | 실행되는 부분 결과가 있다. "확인할 것" 가운데 일부만 맞는다. 예: 세 줄 추가는 되는데 삭제가 안 된다, 카드는 나오는데 파일이 없을 때 안내 문장이 없다 | 배점 안에서 맞은 만큼 |
| 미충족 | 열리지 않거나, 요구와 관계없는 결과이거나, 채점할 파일·주소가 없다 | 0 |

- 강의자는 채점 보조 도구로 항목별 통과를 먼저 보고, 최종 판정은 채점자가 화면으로 한다.
- 실행되는 결과가 없는 코드는 부분 충족으로 보지 않는다.

## 5점 하한 — 미정

"구현 시도 흔적이 있으면 구현 15점에서 최소 5점을 준다"는 규칙(5점 하한)은 **적용 여부를 강의자가 아직 정하지 않았다(미정).**
적용하면 8주 중간 실기와 같은 규칙으로 한다. 정해지면 수업 공지로 알린다.

## 감점 적용 원칙

- 원인이 하나인데 증상이 여러 개면 중복 감점하지 않고 한 항목에서만 깎는다. 그렇게 기록한다.
- 항목별 최대 배점을 넘겨 깎지 않는다.
- 화면이 덜 예쁜 것과 기능이 안 되는 것을 같은 수준으로 보지 않는다.
- 범위 밖 기능은 가점하지 않는다. 그 때문에 요구 동작이 멈추면 그 영역에서만 깎는다.
- 제출 장애(Pages 지연·자격 증명 충돌)는 학생의 구현 오류와 기록상 구분한다.
- 실명·학번·전화번호·실제 이메일이 공개 페이지나 캡처에 있으면 점수와 별개로 즉시 고치게 한다.

## Pages 반영 지연과 장애

| 상황 | 처리 |
|---|---|
| Pages 반영이 5분 넘게 늦다 | 감점하지 않는다. 채점자가 다음 날 공개 주소를 다시 연다. 로컬 화면 캡처와 Commits 탭 캡처도 인정한다 |
| 공용 PC의 자격 증명 충돌로 push 가 막힌다 | 자격 증명 관리자에서 `git:https://github.com` 을 지우고 다시 로그인한다. 그래도 막히면 손을 들고, 감독이 시각을 기록한 뒤 폴더를 압축해 제출한다 |
| 네트워크나 GitHub 가 끊겨 올릴 수 없다 | 손을 들어 감독이 시각을 기록한다. 폴더를 압축하고 서버로 연 화면 캡처와 함께 제출한다 |
| 개인 PC 고장 | 손을 들어 감독 확인을 받고, 예비 PC 에서 저장소를 내려받아 마지막으로 올린 것부터 이어 간다 |

## 제출 세 가지

1. 공개 주소 `https://<아이디>.github.io/web-week15/exam/`
2. 저장소 주소 `https://github.com/<아이디>/web-week15`
3. GitHub **Commits** 탭 캡처 1장 — 맨 위 commit 의 번호와 시각이 보이게

- 제출본은 **마감 전 마지막 commit 을 공개 주소에서 연 화면**이다. 마감 뒤에 올린 commit 은 채점하지 않는다. 마감은 시험 60분이 끝나는 시각이다(시험 시간 안에 구술을 받은 사람은 1분 뒤).
- 세 가지를 내는 곳과 내는 기한은 수업 공지를 따른다.
