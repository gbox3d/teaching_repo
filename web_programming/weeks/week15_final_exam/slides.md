# 기말 개인 실기

이번 주는 새 내용이 없습니다. 1~14주 실습 제출을 한 문제씩 정리한 **문제 은행**으로 연습하고 시험을 봅니다.

- 1일차: 은행에서 문제를 골라 풉니다. 해답 대신 **확인할 것**이 있습니다.
- 2일차: 기말 실기 60분. 영역 A~E 마다 한 문제를 **값만 바꿔서** 냅니다.
- 문제끼리 이어지지 않습니다. 한 문제에는 그 주에 배운 것만 씁니다.
- 이번 주 저장소는 `web-week15` 하나. 1일차 끝에 만들고 시험 폴더도 여기에 넣습니다.

[문제 은행 목록](examples/README.md) · 13문제 · 한 문제 권장 8~12분

## 1일차 · 0–8분 — 문제 은행과 시험: 같은 문제, 값만 바뀐다

| 영역 | 배점 | [은행 문제](examples/README.md) — 번호가 출처 주 |
|---|---:|---|
| A 화면(HTML·CSS·README) | 3 | w01 · w02 · w03 · w04 · w09 · w14 |
| B DOM | 3 | w05 · w06 · w13 |
| C 폼·목록 | 4 | w07 · w10 |
| D 저장(localStorage) | 2 | w11 |
| E 불러오기(fetch) | 3 | w12 |

- 시험은 영역마다 한 문제, **값만 바꿔서** 냅니다. 8주 문제(w01~w07)도 8주와 다른 값.
- 해답은 공개하지 않습니다. 맞았는지는 **확인할 것**으로 봅니다.

**값을 외우지 말고 할 일과 확인하는 법을 익힌다.**

## 1일차 · 8–16분 — 문제 하나 읽는 법: w12_fetch_cards

[examples/w12_fetch_cards/](examples/w12_fetch_cards/README.md) · 출처 12주 실습 제출 · E 불러오기(fetch) · 권장 9분

```text
시작 파일     app.js 의 loadCards() 속만 비어 있다. 나머지는 고치지 않는다
할 일         ① fetch ② 정상이 아니면 안내 ③ JSON → showCards ④ try / catch
확인할 것     카드 3장 · Network 200 · 빨간 줄 없음 · 파일이 없으면 안내 문장
이 문제의 값  data/html-docs.json · doc-list · 안내 문장 …   ← 시험에서 바뀐다
```

- 시작 파일에서 고칠 곳을 가르고, 할 일은 차례대로, 확인할 것은 위에서부터 하나씩.
- 값은 표에서 복사해 붙여 넣습니다. 시험 문제는 이 표의 값만 다릅니다.

**문제 문장은 늘 같은 절, 같은 차례다(끝은 받기와 올리기). 바뀌는 것은 값뿐이다.**

## 1일차 · 16–24분 — 확인하는 법: 서버로 열고 F12 로 본다

[server.mjs](../../tools/static-server/server.mjs) 를 `web-week15` 맨 위에 두고 `node server.mjs`

```text
http://localhost:8000/w12_fetch_cards/    ← 문제 폴더마다 이 모양의 주소
Console      빨간 줄(Uncaught)이 없는지, 찍힌 글자
Network      파일 요청이 200 인지, 404 는 없는지
Elements     글자·class·href, Computed 의 색·여백
Application  Local Storage 의 키와 저장된 값
기기 모드    Ctrl+Shift+M → 폭 375 에서 가로 넘침이 없는지
```

- `fetch` 문제(w12)는 `file://` 에서 막힙니다. 서버 주소나 공개 주소에서 봅니다.
- README 문제(w09·w14)는 **Open Preview** 와 올린 뒤 GitHub 화면에서 봅니다.

**맞았는지는 눈짐작이 아니라 화면 글자와 F12 의 값으로 본다.**

## 2일차 · 0–8분 — 시험 규칙과 시간표

| 시간 | 할 일 |
|---|---|
| 0–3분 | `exam` 넣기 → 시작 올리기 → `exam/README.md` 훑기 |
| 3–51분 | 문제 A~E. 한 문제에 5분 넘게 막히면 다음 문제로 |

- 볼 수 있는 것: 교재 사이트·본인 저장소·MDN. 그 밖은 강의자 공지를 따릅니다.
- 범위는 1~14주 실습 제출입니다. 범위 밖 기능은 가점하지 않습니다.
- 질문은 문제 문장의 뜻·파일 위치·제출 방법·장애만 받습니다.

**문제끼리 이어지지 않는다. 막히면 붙들지 말고 다음 문제로 간다.**

## 2일차 · 8–16분 — exam 폴더: 넣고, 열고, 바로 올린다

```text
web-week15/
  exam/              ← 시험 시작 때 받은 폴더. 이름 그대로 맨 위에
    README.md        ← 문제 다섯의 문장 전체
    index.html       ← 목차. 문제마다 여는 링크
    a/ b/ c/ d/ e/   ← 문제 폴더. 시작 파일만 들어 있다
  w12_fetch_cards/   ← 1일차 연습 폴더는 그대로 둔다
```

1. `node server.mjs` → `http://localhost:8000/exam/` 에서 목차를 엽니다.
2. 바로 올립니다: `git add .` → `git commit -m "기말 실기 시작"` → `git push`
3. 1~3분 뒤 `https://student01.github.io/web-week15/exam/` 에 목차가 보이면 됩니다.

**문제마다 그 문제 폴더(`exam/a/` …) 안의 파일만 고친다.**

## 2일차 · 16–24분 ① — 구현 15: "확인할 것"으로 본다

[채점표](rubric.md) · 20점(안) = 구현 15(A 3 · B 3 · C 4 · D 2 · E 3) + 시연 5

```text
완전 충족   확인할 것이 전부 맞는다
부분 충족   실행되는 부분 결과가 있다 — 일부 항목이 맞는다
미충족      열리지 않는다 · 문제와 관계없다 · 없다
```

- 원인 하나로 여러 항목이 틀리면 한 번만 깎고, 영역 배점보다 더 깎지 않습니다.
- "구현 시도 흔적이 있으면 최소 5점"은 적용 여부가 아직 정해지지 않았습니다.

**교재와 쓰는 방법이 달라도 확인할 것이 맞으면 맞다.**

## 2일차 · 16–24분 ② — 시연 5: URL 재현 3 · 구술 2

```text
URL 재현 3   채점자가 새 시크릿 창으로 …/web-week15/exam/ 을 연다
             → 목차에서 다섯 문제가 요구대로 되는지 본다
구술 2       시험 후반 30분, 강의자가 좌석을 돌며 한 사람에 1분
             → 내 코드에서 지정한 한 줄이 하는 일을 말한다
             → 구술에 쓴 1분은 마감 때 돌려준다
```

- 채점은 공개 주소에서 합니다. 내 PC 에서만 되는 것은 제출본이 아닙니다.
- Pages 반영이 늦은 것은 감점하지 않습니다. 채점자가 다음 날 다시 엽니다.

**구술은 외운 문장이 아니라 내 코드 한 줄을 읽는 것이다.**

[2일차 실습](lab.md#2일차--기말-실기-60분) · [따라하기](walkthrough.md#2일차) · [실습 페이지](https://github.com/gbox3d/teaching_repo/tree/main/web_programming/weeks/week15_final_exam)

**설명 합계: 8+8+8+6 = 30분**

## 제출하기

2일차 시험이 끝나면 **세 가지**를 냅니다.

```text
① 공개 주소    https://student01.github.io/web-week15/exam/
② 저장소 주소  https://github.com/student01/web-week15
③ 캡처 1장     Commits 탭 — 맨 위 commit 의 번호·시각과 주소창이 보이게
```

Pages 반영이 늦으면 로컬 화면 캡처와 Commits 탭 캡처도 인정합니다. 감점하지 않습니다.
1일차 연습 폴더는 확인용이며 따로 제출하지 않습니다.
캡처에 실명·학번·실제 이메일이 보이지 않게 합니다. 제출 위치와 기한은 수업 공지를 따릅니다. commit 마감은 시험이 끝나는 시각입니다.

15주차로 수업이 끝납니다. 다음 수업은 없습니다.

- `web-week15` 는 성적이 나올 때까지 지우지 않고, 마감 뒤에는 올리지 않습니다.

- 못 푼 은행 문제는 "이 문제의 값"을 스스로 바꿔 다시 풀어 봅니다. 기준은 확인할 것.
