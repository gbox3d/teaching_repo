# 15주차 실습 — 문제은행 연습과 기말 실기

## 1일차 실습

강의·시연 60분 뒤 학생 실습 30분이다. 파일·저장소·정적 서버·API는 수업 전 준비하며 강의 첫 5분에 확인한다.

| 시간 | 할 일 |
|---|---|
| 0–10분 | w11 폼 한 객체의 저장·복원·해당 키 삭제 |
| 10–22분 | w12·w13·w14 중 REST 한 문항의 요청 TODO |
| 22–30분 | 새로고침·재조회·오류 복구와 제출 경로 확인 |

두 문항만 필수다. 다른 문제는 선택 복습이다. REST 문항은 폴더의 `config.example.js`에서 `BOOK_ID`를 배정받은 방명록 번호로 바꾼다. 문항을 처음 열 때 공개 키를 묻는 창에 배부받은 공개 키를 입력한다. 같은 주소에서 연 다른 문항도 그 키를 함께 쓴다. 저장한 키와 서버 글은 새로고침해도 남는다. 1일차 commit·push·Pages 확인은 수업 뒤 진행한다.

## 2일차 시험

2일차는 안내 30분과 아래 시험 60분이다. 실제 시험 시간·허용 자료는 강의자 공지가 우선한다.

| 시간 | 할 일 |
|---|---|
| 0–3분 | 배부받은 `exam/` 목차와 A~E 문제·개인별 API 공간을 확인한다 |
| 3–43분 | A~E 한 문제씩 약 8분, 다섯 문제를 구현한다 |
| 43–55분 | 재조회·로컬 동작, commit·push와 공개 URL을 확인한다 |
| 55–60분 | 제출 세 가지와 재현 결과를 확인한다 |

구술은 후반부에 좌석에서 1분 진행하며 그 시간을 해당 학생 마감에 더한다. 강의자는 인원×1분과 이동 시간을 계산해 감독 인원을 사전에 정한다. 예를 들어 30명에게 20분 안에 진행하려면 최소 2명의 감독과 이동 여유가 필요하다. w14는 PATCH 또는 DELETE 하나만 작성한다. 응답 검사·다른 요청·재조회는 제공한다. 변경 문제는 강의자가 만든 시험 전용 글로 수행한다. 다른 학생의 시험 데이터를 읽거나 변경하지 않는다.

## 제출 — 주소 두 개와 캡처 한 장

1. 공개 주소 `https://<아이디>.github.io/web-week15/exam/`
2. 저장소 주소 `https://github.com/<아이디>/web-week15`
3. GitHub Commits 탭에서 마감 전 마지막 커밋이 보이는 캡처 한 장

1일차 연습은 별도 점수에 넣지 않는다.

## 막혔을 때

| 상황 | 처리 |
|---|---|
| Pages 반영이 5분 넘게 늦다 | 로컬 화면과 Commits 캡처를 제출한다. 감독이 시각을 기록하고 이후 공개 URL을 확인한다 |
| API가 응답하지 않는다 | 감독에게 알린다. 서버 장애 확인 후 동일 계약의 로컬 대체 서버를 배부하고 해당 시간을 보정한다. 학생은 `config.example.js`의 주소 한 줄을 바꾸고 [공개 키 지우기]를 누른 뒤 대체 서버의 공개 키를 입력한다 |
| 요청이 HTTP 401로 실패한다 | 공개 키를 입력하지 않았거나 틀렸다. 창을 취소했으면 새로고침해 다시 묻는 창에 입력한다. 잘못 넣었거나 연습 때 넣은 키가 남아 있으면 [공개 키 지우기]를 누르고 배부받은 키를 입력한다. 다른 브라우저·포트·Pages 주소에서는 처음 열 때 다시 묻는다 |
| 글이 자기 방명록이 아닌 student01 방명록에 저장된다 | `config.example.js`의 `BOOK_ID`를 배정받은 방명록 번호로 바꾸고 새로고침한다 |
| 204 뒤 JSON 오류 | DELETE 응답을 JSON으로 읽었는지 확인한다 |
| PATCH가 200인데 배열이 비었다 | 자기 BOOK_ID·대상 ID를 확인한다 |
| 공용 PC에서 push 거부 | GitHub 로그인 계정을 확인하고 강의자의 계정 정리 안내를 따른다 |

서버 장애 때문에 REST 문항을 임의로 localStorage 문제로 바꾸지 않는다. 대체 서버는 같은 요청·응답·권한과 초기 데이터를 갖춰야 한다. 대체 환경도 없으면 해당 영역 평가를 보류하고 재평가를 공지한다.

## 먼저 끝났다면

새 창에서 공개 주소를 열고 각 문항의 확인할 것을 다시 수행한다. 공개 주소에서 처음 열면 묻는 창에 공개 키를 입력한다. 자신의 코드 한 줄을 골라 요청과 응답에서 하는 일을 설명한다.
