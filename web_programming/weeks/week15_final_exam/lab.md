# 15주차 실습 — 문제은행 연습과 기말 실기

## 1일차 실습

| 시간 | 할 일 |
|---|---|
| 0–5분 | 새 `web-week15` 폴더와 정적 서버를 준비하고 자기 API 설정을 확인한다 |
| 5–18분 | 가장 어려웠던 영역의 문항 하나를 푼다 |
| 18–32분 | REST 문항 한 개를 푼다. GET으로 서버 결과까지 확인한다 |
| 32–45분 | 앞과 다른 영역의 문항 하나를 푼다 |
| 45–50분 | 세 문항의 확인할 것 중 남은 항목을 고친다 |
| 50–60분 | 저장소 생성·add·commit·push·Pages 등록, 공개 주소 확인 |

문항은 [은행 목록](examples/README.md)에서 선택한다. REST 문항의 `config.example.js`에는 공개 설정만 넣는다. 편집 키는 실행 화면에만 입력한다. 공개 URL 확인에는 공용 HTTPS API가 필요하다.

## 2일차 시험

각 일차의 설명은 30분, 아래 시험은 60분이다. 실제 시험 시간·허용 자료는 강의자 공지가 우선한다.

| 시간 | 할 일 |
|---|---|
| 0–3분 | 배부받은 `exam/` 목차와 A~E 문제·개인별 API 공간을 확인한다 |
| 3–51분 | 다섯 문제를 구현한다. 한 문제에 막히면 다음 문제로 이동한다 |
| 51–56분 | add·commit·push 후 공개 URL을 확인한다 |
| 56–60분 | 제출 세 가지와 편집 키 노출 여부를 확인한다 |

구술은 후반부에 좌석에서 1분 진행하며 그 시간을 해당 학생 마감에 더한다. PATCH·DELETE 문제는 강의자가 만든 시험 전용 글로 수행한다. 다른 학생의 시험 데이터를 읽거나 변경하지 않는다.

## 제출 — 주소 두 개와 캡처 한 장

1. 공개 주소 `https://<아이디>.github.io/web-week15/exam/`
2. 저장소 주소 `https://github.com/<아이디>/web-week15`
3. GitHub Commits 탭에서 마감 전 마지막 커밋이 보이는 캡처 한 장

편집 키는 제출하지 않는다. 채점자는 강의자 보관 키로 재현한다. 1일차 연습은 별도 점수에 넣지 않는다.

## 막혔을 때

| 상황 | 처리 |
|---|---|
| Pages 반영이 5분 넘게 늦다 | 로컬 화면과 Commits 캡처를 제출한다. 감독이 시각을 기록하고 이후 공개 URL을 확인한다 |
| API가 응답하지 않는다 | 감독에게 알린다. 서버 장애 확인 후 동일 계약의 로컬 대체 서버를 배부하고 해당 시간을 보정한다 |
| 204 뒤 JSON 오류 | DELETE 응답을 JSON으로 읽었는지 확인한다 |
| PATCH가 200인데 배열이 비었다 | 자기 BOOK_ID·대상 ID·편집 키를 확인한다 |
| 공용 PC에서 push 거부 | GitHub 로그인 계정을 확인하고 강의자의 계정 정리 안내를 따른다 |

서버 장애 때문에 REST 문항을 임의로 localStorage 문제로 바꾸지 않는다. 대체 서버는 같은 요청·응답·권한과 초기 데이터를 갖춰야 한다. 대체 환경도 없으면 해당 영역 평가를 보류하고 재평가를 공지한다.

## 먼저 끝났다면

새 창에서 공개 주소를 열고 각 문항의 확인할 것을 다시 수행한다. 편집 키 입력칸이 비었는지 확인한다. 자신의 코드 한 줄을 골라 요청과 응답에서 하는 일을 설명한다.
