## 1. 파일과 서버 준비

할 일: home_iot_http 폴더 전체를 VS Code로 연다. examples 안에 simulator, ex01~ex03, student, reference, automatic, automatic_student가 있는지 확인한다.
현재 폴더: home_iot_http

```bash
node examples/simulator/server.mjs
```

예상 결과: 터미널에 http://localhost:8014/ 주소가 나타난다. 브라우저에서 가상 거실이 열린다. 전등은 꺼짐, 팬은 정지, 온도는 24°C다.

## 2. GET과 PATCH

할 일: 대시보드에서 01 상태 읽기를 열고 조회한다. Network에서 GET /api/state와 응답을 찾는다. 이어 02 전등 제어를 열고 전등을 켠다.

예상 결과: GET은 상태 객체를 반환하고 PATCH는 전등의 on과 brightness를 바꾼다. 대시보드의 밝기와 응답 값이 같다.
ex02/app.js의 밝기 65를 20으로 바꾸고 저장·새로고침한 뒤 다시 켜면 밝기는 20%다.

## 3. 기초 제어 코드 작성

할 일: 03 온도와 선풍기를 연다. 대시보드에서 27°C와 29°C를 각각 적용하고 제어 버튼을 누른다. 이후 student/app.js의 TODO를 채운다.

예상 결과: ex03의 기본 기준 28°C에서 27°C는 정지, 29°C는 작동이다. student에서는 밝기 40%와 기준 27°C로 자신이 작성한 동작을 확인한다.
기초 예제는 클릭할 때 한 번만 검사한다. 온도만 바꿔서는 새 제어가 일어나지 않는다.

## 4. 자동 조회와 중지

할 일: 자동 제어 연구 화면을 연다. 다른 자동 제어 탭은 중지한다. 단일 기준 27.5°C, 간격 2000ms에서 시작한다.

예상 결과: GET이 반복된다. 현재 팬 상태와 판단 결과가 다를 때만 PATCH가 이어진다. 조회와 제어 횟수가 따로 표시된다.
중지를 누르면 새 요청이 멈춘다. 설정 칸은 중지한 상태에서 바꿀 수 있다. 간격을 500ms나 5000ms로 바꿔 입력 반영 지연을 비교한다.

## 5. 히스테리시스 비교

할 일: 자동 제어를 중지하고 팬을 정지한다. 온도 26°C를 적용한다. 단일 기준으로 시작한 뒤 26→27→28→27→28→29→28→27→26 순서로 값을 적용한다. 기록에 각 온도가 나타난 뒤 다음 값으로 넘어간다.

예상 결과: 27.5°C 경계를 오갈 때 팬 상태가 바뀐다. 기록을 다운로드한다.
중지 후 기록을 다운로드하고 자동 제어 화면을 새로고침해 누적 횟수를 비운다. 또는 실험 전후 횟수의 차를 기록한다.
팬 정지·26°C 초기 조건을 만든다. 히스테리시스, 하한 26°C, 상한 29°C로 같은 순서를 실행한다.

예상 결과: 팬이 꺼져 있으면 29°C에 도달할 때까지 꺼진 상태를 유지한다. 켜진 뒤에는 26°C에 도달할 때까지 켜진 상태를 유지한다. 같은 27°C에서도 이전 상태에 따라 결과가 다르다.
경계 근처를 더 살펴보려면 27.4°C와 27.6°C를 번갈아 적용한다. 온도 슬라이더는 0.1°C 단위이며 방향키로 조정할 수 있다.

## 6. 정책 함수 작성

할 일: 정책 작성 화면을 열고 automatic_student/policy.js의 TODO 3개를 채운다. 함수는 온도, 현재 팬 상태, 설정을 받아 true 또는 false를 반환한다.

예상 결과: TODO가 남아 null을 반환하면 실행기가 정책 미완성을 알리고 중지한다. 구현 후에는 기초 비교와 히스테리시스 실험을 같은 화면에서 반복할 수 있다.
HTTP와 재시도 코드는 automatic/runner.js에 있다. 정책 함수가 동작하면 runCycle의 GET·판단·PATCH·다음 예약 순서를 읽는다.

## 7. 서버 중단과 복구

할 일: 자동 제어를 시작하고 Network에서 Preserve log를 켠다. 서버 터미널에서 Ctrl+C로 종료한다. 브라우저 페이지는 새로고침하지 않는다.

예상 결과: 실패 기록과 다음 재시도 대기가 나타난다. 기본 2000ms 설정의 연속 실패는 4000·8000·10000ms 대기로 늘어난다.
같은 서버 시작 명령을 다시 실행한다. 다음 재시도에서 성공하면 정상 대기로 돌아간다. 서버 상태는 초기화되었으므로 온도를 다시 적용한다.

## 8. 기록과 종료

할 일: 자동 제어를 중지하고 관찰 기록 다운로드를 누른다. 가설과 변경 변수, 고정 조건, 관찰, 해석과 한계를 기록한다. 필요한 코드·화면·Network 자료를 함께 보관한다.

예상 결과: iot-observations.json에 최근 500건까지 저장된다. 화면에는 최근 30건만 보이고 대시보드는 최근 PATCH 12건만 보여 주므로 범위를 구분한다.
서버 종료 뒤에는 메모리 상태가 사라지고 작성한 코드·다운로드한 기록 파일은 남는다.
