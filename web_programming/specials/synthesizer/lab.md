# 신시사이저 연구 실습

정규 12주차 이후의 선택 특강입니다. 정규 시험·필수 과제에 포함하지 않습니다. 아래 60분은 첫 실습의 예시이며 방학 연구에서는 제한 없이 이어갑니다.

## 준비

[특강 안내](README.md)의 명령으로 서버를 열고 이어폰을 준비합니다. 브라우저 볼륨을 낮춰 시작합니다. JavaScript 클릭 이벤트·배열·객체·JSON·fetch를 알고 있다고 가정합니다. 실행 화면이 필요한 파일은 [예제 안내](examples/README.md), 독립 작업 폴더 구성은 [따라하기](walkthrough.md)에서 확인합니다.

## 실습 60분

| 예시 시간 | 작업 | 확인 결과 |
|---|---|---|
| 0~15분 | ex01·ex03·ex05에서 변수 하나씩 비교 | 변경 전후 수치, 예상과 청취·파형 관찰 |
| 15~25분 | ex07 호출/예약 시각 비교, ex08 체크 변경 | 109 BPM의 한 칸 계산과 수정한 16칸 배열 |
| 25~35분 | ex09와 requests.http 실행 | 200 JSON, 404 응답, 실패 후 재시도 |
| 35~50분 | build 폴더 복사, 제목·BPM·리듬 수정 | 자기 곡의 화면과 실제 재생 |
| 50~60분 | 오류 복구·재생/정지 반복·기록 | 바꾼 파일과 재현 절차 |

완료가 늦어지면 다음 연구 시간에 이어갑니다. ex10과 조합기는 이 표의 필수 분량에 끼워 넣지 않습니다.

## 연구 기록

자기 저장소 README에 다음 내용을 남깁니다.

- 실행 주소와 수정한 파일·함수
- 변경 전후 값, 변경 전에 예상한 결과
- 화면 관찰과 직접 청취한 결과를 나누어 기록
- JSON 404·문법 오류를 만들고 복구한 방법
- 재생·정지를 반복했을 때 소리와 화면이 멈추는지 확인

공개 자료에는 직접 만든 곡·멜로디 또는 사용 권한이 있는 자료를 사용합니다. 캡처만으로 청취 결과를 확인했다고 쓰지 않습니다.

## 막혔을 때

| 증상 | 확인 |
|---|---|
| 아무 동작도 없음 | `file://` 대신 HTTP 주소인지, Console의 모듈 404 여부 |
| `song.js` 404 | build 폴더 전체를 복사했는지 |
| 재생 버튼 비활성 | JSON 요청 상태·파싱 오류·멜로디 정수 범위 |
| 소리 없음 | 재생 버튼 클릭, 탭·OS 음량, AudioContext 상태, 악기 체크 |
| 수정한 소리가 그대로 | 기본값보다 호출 인수가 우선하는지, 새로고침했는지 |
| 참고 악보가 안 열림 | `score/`와 연주기 JSON의 서로 다른 형식 |
| BPM이 파일과 다름 | 연주기 슬라이더 범위 80~140 |

## 먼저 끝났다면

[ex10](examples/ex10_melody.html)에서 시작 칸·길이를 비교하고 직접 만든 멜로디를 입력합니다. [조합기](examples/build/compose.html)에서 마디 복제·이동·삭제·옮김 후 JSON으로 내보냅니다. 다시 열어 같은 곡이 복원되는지 확인합니다.

후속 연구로 키보드 입력, 다른 리듬 프리셋, 녹음, 참고 악보 형식 변환을 선택할 수 있습니다. 현재 예제에는 키보드 연주·녹음·참고 악보 자동 변환이 구현되어 있지 않습니다.
