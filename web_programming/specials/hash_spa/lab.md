# Hash SPA 실습지

14주 이후 선택 특강이다. 정규 시험 범위에 넣지 않으며 특강 시간·차시 수를 제한하지 않는다. 예제 파일과 로컬 서버는 수업 전에 준비한다. 01~03의 첫 60분은 설명·시연, 다음 30분은 학생 수정·관찰의 운영 예다. 04 통합과 REST 실패 실험은 별도 후속 시간에 진행한다.

## 01 MPA 비교

[01](examples/01_mpa/README.md)의 세 HTML을 각각 직접 연다. 홈 횟수를 바꾼 뒤 내 정보로 이동하여 Document 요청을 기록한다. 새로고침·뒤로·앞으로를 시험한다. 뒤로 가기 캐시 복원과 새 문서 로딩을 구분한다. 학생은 링크 목적지를 확인하고 강의자는 14주 MPA 파일을 대조한다.

## 02 두 화면 표시

[02](examples/02_two_screens/README.md)의 `showScreen`에서 표시할 section만 남기는 조건을 읽고 고친다. 홈 횟수를 2로 올리고 내 정보·홈을 오간다. 횟수·주소·Document 요청을 기록한다. 현재 메뉴·제목 포커스는 제공 코드를 사용한다.

## 03 주소 연결

[03](examples/03_hash_routes/README.md)에서 hash 읽기·표시 조건·이벤트 등록을 확인한다. 방명록에 별칭과 미전송 메시지를 입력한 뒤 홈·내 정보·방명록을 10회 오간다. 빈 hash, 세 경로 직접 주소, 없는 hash, 뒤로·앞으로, 키보드를 확인한다. 새로고침 전후 입력 차이도 기록한다.

## 04 REST 통합

[04](examples/04_rest_guestbook/README.md)의 요청을 about→help→GET 순서로 실행한다. 브라우저는 `config.example.js`의 `BOOK_ID`를 배정받은 번호로 바꾸고, 처음 열 때 묻는 창에 배부받은 공개 키를 넣어 준비한다. REST Client는 `.env`를 따로 읽으므로 `.env`도 준비한다. 학생은 03의 section과 14주 방명록을 합치는 위치 및 홈 `home-count`와 방명록 `count`의 구별을 확인한다. REST 함수와 `config.example.js`는 14주 제공본을 재사용한다.

세 글을 추가하고 가운데 글 하나를 선택하여 PATCH한 뒤 같은 ID의 메시지를 확인한다. 그 글을 DELETE하고 같은 ID의 GET 결과가 빈 배열인지 확인한다. 없는 글 번호, 통신 실패, 복구 후 재조회를 시험한다. 저장 결과가 불명확할 때 POST부터 다시 보내지 않는다.

화면 전환만으로 GET을 보내지 않는 기본 정책을 확인한다. 입력 중 이동하면 초안은 남는다. 새로고침하면 초안은 사라진다. 서버에 저장한 글과 localStorage의 공개 키는 남고 목록은 다시 조회된다. 로컬 API와 공용 서버의 검증 결과는 분리해 기록한다.

## 관찰 기록

| 조건 | 예상 | 실제 화면·요청 | 근거 |
|---|---|---|---|
| 실제 HTML 이동 | Document 요청 | 학생 기록 | Network |
| hash 이동 10회 | Document 요청 없음 | 학생 기록 | Network·입력값 |
| 홈 버튼 1회 | 횟수 1 증가 | 학생 기록 | 화면 |
| 하위 경로 직접 주소·새로고침 | 같은 section | 학생 기록 | 주소·화면 |
| POST·PATCH·DELETE | 서버 ID와 내용 변화 | 학생 기록 | 응답·대상 GET |
| 실패·복구 | 입력 유지·재조회 가능 | 학생 기록 | 화면·응답 |

캡처에는 변경 전후의 글 목록을 담는다. 결과물은 변경한 코드와 관찰 표이며 공개 업로드는 수업 뒤 진행한다. 선택 연구는 방명록 진입 시 재조회 정책이다. 기본 정책과 요청 횟수·초안 보존을 비교하고 중복 리스너가 생기지 않았는지 다시 확인한다.
