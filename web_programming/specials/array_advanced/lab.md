# 배열 심화 실습

입력과 결과를 예상한 뒤 버튼을 누르고 코드를 확인한다. 예제 5개를 차례로 사용하며 진행 시간과 차시 수를 고정하지 않는다. 정규 11주차 과제에 포함하지 않는다.

## 준비

저장소 루트에서 서버를 실행한다. [W3.CSS CDN](https://cdnjs.cloudflare.com/ajax/libs/w3-css/4.1.0/w3.min.css) 로딩에는 인터넷 연결이 필요하다.

```bash
node web_programming/tools/static-server/server.mjs web_programming 8111
```

첫 주소는 http://localhost:8111/specials/array_advanced/examples/01_insert_delete/ 이다. 다른 예제는 마지막 폴더명만 바꾼다. [예제 목록](examples/README.md)에서 이름을 확인한다.

## 1. 삽입·삭제와 반환값

사용 폴더: `01_insert_delete`. 각 행을 실행하기 전에 초기화를 누른다. 시작 배열은 `['사과', '바나나', '포도']`다.

| 입력과 버튼 | 먼저 예상할 것 |
|---|---|
| 값 귤 → push | 배열 끝과 반환값 |
| 값 귤 → unshift | 배열 앞과 반환값 |
| pop | 삭제한 값과 반환값 |
| shift | 삭제한 값과 반환값 |
| 값 귤, 위치 1 → splice 삽입 | 삽입 후 배열과 삭제 항목 배열 |
| 위치 1 → splice 삭제 | 남은 배열과 삭제 항목 배열 |

pop을 반복해 빈 배열로 만든 뒤 한 번 더 실행한다. 길이 0과 반환값 `undefined`를 확인한다. 위치를 빈 값·음수·범위 밖 값으로 바꿔 이 화면이 실행을 막는 조건도 확인한다.

도달 기준: 원본 배열을 바꾸는 동작과 반환하는 값을 구분한다. 삽입용 `splice`의 반환값이 `[]`인 이유를 설명한다.

## 2. 순회와 콜백

사용 폴더: `02_iteration`.

1. for...of 실행을 누르고 세 학생의 이름·점수를 확인한다.
2. forEach 실행을 누르고 목록과 반환값을 비교한다.
3. 버튼을 반복해서 누른다. 목록이 중복되지 않도록 비우는 줄을 찾는다.
4. `forEach(function (student) { ... })`에서 현재 항목을 받는 인수를 찾는다.

도달 기준: 화면 결과가 같아도 `for...of`는 반복문이고 `forEach`의 반환값은 `undefined`라는 차이를 설명한다. 현재 코드는 객체를 읽기만 하므로 원본이 유지됨을 확인한다.

## 3. filter로 조건 선택

사용 폴더: `03_filter`. 최소 점수를 70, 60, 100으로 바꾸어 각각 실행한다.

| 최소 점수 | 예상 인원 | 실제 인원 | 원본 변화 |
|---|---|---|---|
| 70 | 기록 | 기록 | 기록 |
| 60 | 기록 | 기록 | 기록 |
| 100 | 기록 | 기록 | 기록 |

결과가 없는 경우도 오류가 아니라 새 빈 배열 `[]`임을 확인한다. `return student.score >= minimum`의 `>=`를 `>`로 바꾸고 최소 점수 80에서 결과를 비교한다. 실험 후 원래 코드로 되돌린다.

도달 기준: 콜백의 참·거짓 반환값이 항목 선택을 결정하며 원본에서 항목을 삭제하지 않는다는 점을 설명한다.

## 4. map으로 새 객체 만들기

사용 폴더: `04_map`.

1. 가산점 5로 실행하고 결과 85·65·95와 원본 80·60·90을 비교한다.
2. 같은 버튼을 다시 누른다. 가산점이 누적되지 않는 이유를 찾는다.
3. 가산점을 10, 0, -5로 바꾸어 실행한다. 매번 원본 점수에서 계산되는지 확인한다.
4. `return { name: student.name, score: student.score + bonus }`에서 새 객체를 만드는 부분을 찾는다.

도달 기준: 새 배열과 새 객체를 구분한다. `student.score`에 직접 대입하지 않아 원본 점수가 유지된다는 점을 설명한다.

## 5. reduce의 누적 과정과 빈 배열

사용 폴더: `05_reduce`. 빈 배열 선택을 해제하고 합계 계산을 누른다.

| 단계 | 누적값 | 현재 점수 | 다음 값 |
|---|---|---|---|
| 1 | 예상 후 기록 | 80 | 예상 후 기록 |
| 2 | 예상 후 기록 | 60 | 예상 후 기록 |
| 3 | 예상 후 기록 | 90 | 예상 후 기록 |

합계 230, 콜백 호출 3회를 확인한다. 표의 행이 실제 콜백 안의 `steps.push()`로 기록되는지 코드를 확인한다.
빈 배열을 선택하고 다시 계산하면 합계 0, 호출 0회, 표 0행이다. 선택을 해제한 뒤 다시 계산하여 원본 학생 배열이 남아 있음을 확인한다.

도달 기준: `return next`가 다음 호출의 누적값이 되고 마지막 반환값이 합계가 된다는 점을 설명한다. 마지막 인수 `0`이 빈 배열에서도 결과를 만들게 하는 초깃값임을 확인한다.

## 객체 참조 비교

filter 결과 배열은 새 배열이지만 안쪽 학생 객체는 원본과 같은 객체다. map 예제는 새 객체를 만들어 반환하므로 원본 점수가 유지된다. 새 배열이라는 사실만으로 깊은 복사가 되었다고 판단하지 않는다.

코드에서 학생 객체의 필드를 직접 대입하는 줄이 있는지 확인한다. 이번 filter·map·reduce 예제는 원본 학생 객체를 수정하지 않는다. 중첩 객체의 깊은 복사는 이 수업 범위에 넣지 않는다.
