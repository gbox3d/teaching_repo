## 재사용 지침의 위치

편집·자막·게시의 재사용 절차는 **`lecture-video-editing` 스킬**에서 관리한다. 이 저장소에 그 내용을 복제하지 않는다.

- 소스 정본: `myAISkills` 저장소의 `codex/lecture-video-editing/SKILL.md`.
- 사용 위치: 현재 세션의 스킬 목록에서 `lecture-video-editing`을 찾는다. 기본 설치 경로는 `~/.codex/skills/lecture-video-editing/`이며 `CODEX_HOME` 설정이 있으면 실제 경로를 확인한다.
- 새 머신에 설치가 필요하면 `myAISkills/README.md`의 선택 설치 절차를 사용한다. 저장소 커밋과 홈 설치본 동기화는 별개다.
- 스킬에는 범용 검사기 `scripts/verify_delivery.py`와 전사·Shotcut·게시·재개/독립 평가 참고 문서가 있다. 요청에 필요한 참고 문서만 읽는다.

## 작업을 이어받는 순서

1. 사용자가 지정한 강의와 현재 저장소를 확인한다. 과거 Windows 절대 경로를 현재 경로로 가정하지 않는다.
2. 기존 산출물이 있으면 해당 폴더의 `WORK_STATE.json`·`DELIVERY.txt`·`publishing_plan.json`과 최신 검증 보고서를 읽는다. 오래된 로컬 검증의 ‘미게시’ 표시는 최신 종합 보고서와 구분한다.
3. 기록을 실제 파일·프로세스·사이트 상태와 대조하고 남은 단계만 수행한다. 게시만 남았거나 자막 한 문장만 수정하는 작업에 전체 전사·렌더·업로드를 반복하지 않는다.
4. 최종 MLT·타임라인·자막의 원천 데이터를 확인한다. 초기 생성기나 동기화 스크립트를 다시 실행하기 전에 읽고 쓰는 파일과 강의 전용 값을 확인한다.

로컬 자료가 없는 다른 머신에서는 없는 원본·정본·검증 결과를 추정하지 않는다. 스킬과 코드가 공유됐다는 사실은 강의 영상까지 복사됐다는 뜻이 아니다.

## 저장 위치와 공유 범위

| 자료 | 위치와 취급 |
|---|---|
| 공용 교재·예제 | 과목의 `weeks/`·`specials/`; Git 추적 |
| 재사용 편집 지침·범용 검사기 | `myAISkills/codex/lecture-video-editing/`; Git 추적 |
| 강의 원본 | 사용자가 지정한 위치; 읽기 전용으로 사용 |
| 편집 프로젝트·파생 미디어·자막·로그 | 이 저장소의 `output/<과목>/<강의>/`; `.gitignore`로 제외 |
| LMS 설정·게시 URL·화면 증거 | 대상 학교의 비공개 작업 배치; 학교 지침에서 위치 확인 |

기존 강의 작업은 `output/web_programming/week11_day1/`과 `output/android_programming/week12_day1/`에 보관했다. 이 경로들은 로컬 인수인계 단서이며 Git에 포함되지 않는다. 강의별 `scripts/`의 파일 이름·좌표·과제·경로는 범용 API가 아니다.

## 교재와 수업의 대응

수업 주차는 사용자와 실제 강좌 일정이 정한다. 교재는 번호만 맞추지 말고 녹화에 나온 코드·주제로 찾는다. 이번 Android 수업의 ListView·ArrayAdapter·항목 선택 내용은 [교재 예제 안내](../android_programming/weeks/week11_content_provider/examples/README.md)의 `day1/`에 대응한다. 수업 표시 주차가 다르다고 BLE/GATT 폴더로 바꾸지 않는다.

영상에서 생략한 확장 사항을 필수 제출 조건으로 추가하지 않는다. 과제는 강의에서 요구한 실행 결과와 본인의 설명을 중심으로 만들고, 이전 **같은 과목·대응 차시**의 실제 설정을 확인한다.

## 완료를 확인하는 근거

- 로컬 출력: 최종 MP4 사양, 전체 A/V 디코딩, 언어별 자막 추출 대조, 실제 최종 화면과 음성 싱크 표본. 검사 범위와 전 구간 청취·GUI 재열기 등 미검증 범위를 구분한다.
- 게시: 요청된 공개 상태, 각 수동 자막의 게시됨, 시청자 화면의 실제 언어 선택·표시, 실제 영상 주소.
- 공지·과제: 대상 강좌·주차, 생성된 주소, 목록에서 다시 연 본문·링크, 다시 연 과제 설정. 학생 역할 미리보기와 실제 학생 제출은 다른 검사다.
- 인수인계: 최신 종합 판정과 실제 근거를 연결하고 완료·대기·해결된 오류 이력을 구분한다. 이미 검증한 파일이 동일하면 기존 근거를 재사용하되 다른 파일에 점수를 옮기지 않는다.

커밋에는 공개 가능한 재사용 문서·구현만 포함한다. `git status --short`와 staged diff에서 영상·전사·인증 파일·LMS 증거가 들어가지 않았는지 확인한다. 커밋과 원격 push는 별개이며, 다른 머신은 커밋을 전달받고 필요한 스킬을 설치해야 사용할 수 있다.

## 문서와 지침의 독립 검토

사용자가 문서·지침의 독립 검토를 요청한 이번 기준은 두 평가를 분리하는 것이다. 작성에 참여하지 않은 담당자가 **문서 정합성**(구현·작업·근거와 일치)과 **지침 유용성**(범위·실행 가능성·재작업 방지)을 각각 10점 만점으로 평가한다.

각각 **7점 초과**여야 통과한다. 7점 이하면 반려 이유를 고치고 영향을 받는 항목을 재검토한다. 평가별 회차·점수·수정·근거를 기록하고, 어느 평가든 **5번째 반려**에 이르면 커밋을 멈추고 사용자와 논의한다. 검토자나 세션을 바꿔 횟수를 초기화하지 않는다. 이 반복 검토를 모든 단순 문서 수정의 자동 절차로 확대하지 않는다.
